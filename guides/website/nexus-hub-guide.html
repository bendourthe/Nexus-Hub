Installation

Paste the line for the target system. The installer copies the catalog into ~/.nexus-hub/, wires every assistant it detects, and preserves customized files. There is no download to unzip first.

Windows · paste into PowerShell
> irm https://raw.githubusercontent.com/bendourthe/Nexus-Hub/main/install.ps1 | iex
macOS / Linux · paste into Terminal
$ curl -fsSL https://raw.githubusercontent.com/bendourthe/Nexus-Hub/main/install.sh | bash
  1. 1

    Check that it installed. Run either command in the assistant:

    /skills list /commands

    The command cheatsheet appears.

  2. 2

    Restart the assistant.

    Hooks and rules load at startup, so they only take effect after a restart.

Skills, Hooks, and Governance

Skills that load themselves, hooks the model cannot talk past, and governance that holds output to written rules.

Self-Loading Skills

340 senior-level procedures. The agent triggers the right one from the task; three-tier loading keeps only a summary in context until one is needed.

Enforced Hooks

Where skills advise, hooks enforce. 36 scripts fire on tool events and block the action outright, whether or not the model remembered to be careful.

Project Governance

Write MUST and SHOULD norms with /constitution; every /plan checks against them and /spec clarifies a vague request before code is written.

Security Guardrails

Every agentic platform already asks permission before a risky action. That prompt is advisory to the model, and a model can be talked past it.

Nexus Hub registers 36 hooks on the platform's own tool events, 18 of them before an action runs, and they block the action whatever the prompt said: secret scanning on every write, confirmation on destructive git operations, a large-file guard, and a memory-store guard.

It is local-first. The reverse-engineer-first MCP policy keeps search, embeddings, scraping, and generation off third-party services, and this guide itself makes zero network calls.

Raw Prompting vs Nexus Hub

Nexus Hub does not replace the model. It wraps it in the structure, depth, and guardrails a senior engineer brings.

Without Nexus Hub → With Nexus Hub

  2. Reusable Procedures

    Skills load on demand; a command starts the same workflow each time.

  3. Enforcement

    Safety depends on the model remembering to be careful.

  4. Persistence

    The useful output lives in a chat transcript.

  5. Team Consistency

    Everyone invents their own prompt.

    One shared workflow, with a written definition of done.

AI-Assisted Development Concepts

What a model reads, what an agentic platform adds, and where a harness fits.

Tokens

Model Input Units

A model never sees words. It sees tokens: the small pieces text is cut into first. A token can be a whole word, part of one, a punctuation mark, or a space attached to the word after it.

This is the real cl100k_base split. Other models cut the same sentence differently, so there is no fixed words-to-tokens ratio. The count matters because it is what fills the working budget, and it is one factor in speed and in metered cost.

Images are split too. Every square above holds real pixels from the picture beside it. Nine is the number in this picture, chosen to be countable; it is not a literal token count.

Models

A model is a neural network whose connection strengths, called weights, were learned from data: a request goes in, a likely response comes out.

Training Steps

Step 1: Pre-training - the phase in which the model is fed a large corpus of data (text, images and code) to learn patterns and set the strength of the connections, the weights, within its neural network.

Step 2: Post-training - the phase in which the pre-trained model is fine-tuned using techniques such as reinforcement learning, where its responses to a variety of requests are scored so the weights are progressively adjusted to favor better results. Post-training can improve behavior and put some guardrails in place, but it does not guarantee correctness.

Model Class and Size

A model class is a named family a provider ships at one capability level. Its size is the scale of the network behind it: more layers and more connections give a model more room to represent a hard problem, and cost more to run. The four classes below are the same ladder every provider offers under different names.

Quick, simple tasksDeeper, harder work

Conceptual capacity, not disclosed model sizes or equal benchmark scores. Speed and usage vary by task.

Reasoning Effort Levels

The effort level sets how much work a model does on a question before it answers. The same request goes in at every level. A low level answers in one pass. A higher one spawns agents with missions of their own, each searching, running commands and checking its working, spawning sub-agents where a problem needs them, and trying again when a result comes back wrong. Nothing is written until every branch has reported in, so a higher level answers later and in more depth.

Prompt Engineering

Checkable Requests

The prompt is where the job is stated. The same request can be asked in a way nobody could grade, or in a way anyone could check. That difference is the whole skill.

A useful prompt states the Query, points at the Context, defines the Goal the answer has to reach, and asks for a usable Format. Miss one and the model has to guess, and it will guess confidently.

Vague Prompt

"Look at this contract."

  • No request: nothing says what looking at it should produce
  • No context: which contract, and which parts of it
  • No goal: nothing the answer can be checked against
  • No format: any shape is arguably correct, so none is wrong
Engineered Prompt

Summarise this contract and list every deadline. Use the signed PDF I attached, sections 4 to 9 only. Every dated obligation appears once, with its clause number. Return a table: date, obligation, clause, who owes it.

Request
the job, stated so it can be graded
Context
the material the job runs on
Goal
the finish line the answer must reach
Format
a shape the work can use

Every part is now checkable: the request can be graded, the context is named, the goal is explicit, and the format is stated. The answer can be checked against the contract, line by line.

Context Engineering

Task-Relevant Material

The prompt states the job. Context is the material the job runs on, and it is separate from the words of the request. It can be an image, a file or document, a project folder or workspace, or a codebase.

Context is optional, and it is not free. Everything attached shares one finite working budget measured in tokens, alongside the instructions, the conversation so far, and any tool results. Material can also be stale, duplicated, or simply too large to be worth its space.

So the skill is selection, not volume. Attaching the whole drive is not more helpful than attaching the two sections the question is about.

Engineered Prompt

Fix the checkout screen. Use checkout-layout.png to identify the issues and checkout-guidelines.pdf for the required design. Align Back and Place order, apply the correct button styles, and add Change delivery. Keep the rest unchanged. Use the supplied icons in assets/checkout/ instead of inventing icons.

Context Engineering Best Practices

Attach everything in the project
files the job never touches

The material the job names gets a sliver, and there is almost no room left to answer.

  • More tokens: the budget fills with material nobody asked about
  • Slower: every attached file has to be read before anything is answered
  • Costs more: metered work is charged on what was read, not on what was needed
  • Likelier to miss: the one line that mattered is a needle in a haystack
Attach what the job names
the screenshot, guidelines, and SVG assetsroom to answer

Same budget, spent on the material the job runs on.

  • Fewer tokens: only the material the job runs on is read
  • Faster: less to read before the first useful sentence
  • Costs less: the same answer for a fraction of the metered work
  • Likelier to land: the material that decides the answer is not buried

Harnesses

Safer, Reusable Work

The model is a brain: it knows a great deal, and on its own it has nothing holding that knowledge to the job. A harness is the casing built around it, and every agentic platform already ships a harness: the runtime loop that assembles the context, offers the tools, enforces the permissions, executes the actions and feeds the observations back. Nexus Hub is a second, specialised layer around that loop: its skills and commands load themselves, its approval gates carry a written definition of done, its artifacts chain forward from one step to the next, and its hooks fire only where the host exposes the registered event. It does not replace the model, and it does not replace the platform runtime.
