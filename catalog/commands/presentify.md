# /presentify Command

Turn existing documents into a single self-contained, offline, UNIQUE interactive website - not a static slide deck. One PowerPoint becomes a more interactive, more dynamic site that follows the same flow; one report (Word or PDF) becomes a navigable interactive site presenting it; several mixed documents compile into one attributed site. The output opens from a single file with zero external network requests, renders the source's real figures as INTERACTIVE charts (zoom, pan, filter series, adjust axes), carries a clear navigable structure, and uses a fresh, creative design every run that leads with uniqueness and interactivity rather than reusing one house look. When you do not name the corresponding flags, the command asks all four high-level design choices - design direction (style), output aspect & navigation, interactivity level, and imagery tier - TOGETHER in one batched round up front, immediately after the command is submitted and BEFORE any document is read; each choice you name on the command line (`--style` / `using the style <description>` / `--theme`, `--layout`, `--nav`, `--interactivity`, `--images`) binds and drops from the round, so a fully-specified run asks nothing. The command never pre-answers a choice from a recalled memory or a saved preference - only an explicit flag in this invocation, or the non-interactive fallback, skips a question. After the four choices are captured it reads the document and brainstorms concrete tokens for the chosen direction (three standard presets - Corporate & Professional, Creative & Expressive, Technical & Precise - plus a "surprise me" and an "other"), announces the committed direction in one line, and authors to it. If the round cannot be answered (a non-interactive run) the agent auto-picks by content (design -> surprise-me / creative, aspect -> full-width for a deck / standard for a report with `scroll` navigation, interactivity -> balanced or restrained, imagery -> procedural Tier 1) and never blocks. Use `--theme` to pin an exact palette or brand. The imagery default and every non-interactive run stay fully offline: procedural (Tier 1) visuals are original inline SVG / CSS, and the opt-in stock / AI tiers require explicit consent for any build-time network use.

This is a thin entry point over the `document-to-interactive-html` skill. The full method (extract -> design -> author the interactive site -> verify), the per-format coverage, and the offline / anti-slop discipline live in that skill; this command resolves inputs and options, then delegates.

## Usage

```
/presentify <file-or-folder...> [using the style <description> | --style <description>] [--theme <name-or-path>] [--layout <full|standard|portrait|description>] [--nav <scroll|slides>] [--images <none|stock|ai|both>] [--interactivity <restrained|balanced|rich|cinematic>] [--verbosity <distilled|balanced|comprehensive>] [--qa-depth <light|standard|deep>] [--out <path>] [--mode <auto|deck|report|compile>]
```

- **Inputs** (required): one or more files - documents (`.pdf`, `.docx`, `.xlsx`, `.pptx`), source code and config, Markdown / plain text, CSV / TSV, standalone images - or a directory / repository. A directory is walked RECURSIVELY (ignoring VCS / dependency / build directories and lockfiles, honoring a root `.gitignore` best-effort, skipping binaries, capped by `--max-files` and `--max-text-bytes`). A single directory input builds a repository site (a synthesized overview, a navigable file tree, README / docs first, and source code grouped by top-level directory). Multiple inputs may mix formats freely.
- **`--style`** (optional): a style / color-scheme direction in plain words (e.g. `"dark, minimal"`, `"editorial, warm"`, `"high-contrast, playful"`, `"match brand #1a73e8"`). The natural-language form `using the style <description>` is equivalent. A named style binds the design and skips the menu below; the agent still brainstorms any axes the words leave open. Omit it and the command offers the design-direction menu instead.
- **`--theme`** (optional): for an exact palette/brand, a curated `theme-tokens` theme name or a path to a theme / brand-token JSON (a `brand-styling` `tokens.json`). Ask the user for brand tokens before inventing colors; do not guess a brand.
- **`--layout`** (optional): the output aspect / canvas - one of `full` (fills a 16:9 screen edge to edge), `standard` (a typical centered webpage column), `portrait` (a tall, narrow, reading- / mobile-oriented canvas), or a free-text description (the natural form `using the layout <description>` is equivalent). A named layout binds the canvas and skips the aspect menu below. Omit it and the command offers the aspect menu after the style choice; in a non-interactive run it auto-picks by content (a deck defaults to `full`, a report / repository to `standard`).
- **`--nav`** (optional): the navigation mode - how the reader moves through the output. One of `scroll` (the current scrolling website: scroll plus anchor navigation - the default and the non-interactive fallback) or `slides` (viewport-fitted slides advanced by keyboard, simulating a PowerPoint-style presentation: ArrowRight / ArrowDown / PageDown / Space go forward, ArrowLeft / ArrowUp / PageUp go back, Home / End jump to the first / last slide, swipe advances on touch, and a click on the on-screen next / previous zones advances too). The natural forms `using slide navigation` and `as slides` bind the same way. A named `--nav` binds the navigation half of the canvas question below and skips it; an unrecognized value (e.g. `--nav deck`) is rejected with a one-line usage note, after which the run asks the merged canvas question (interactive) or falls back to `scroll` (non-interactive) - it never blocks. `--nav slides` composes with any `--layout`: naming both is not an error, the slide stage simply adopts that aspect ratio (e.g. `--layout portrait --nav slides` gives portrait-ratio slides), and the combination is recorded in the design record. No pair of flags can deadlock the intake. Each output file is authored for exactly ONE mode - there is NO runtime scroll / slides toggle.
- **`--images`** (optional): what to ADD on top of the always-on procedural visual layer - one of `none` (the built-in procedural visuals only: original inline SVG / CSS, zero-outbound - NOT a bare page), `stock` (opt-in: real license-free, free-for-commercial-use stock images / video fetched and base64-embedded at build time), `ai` (opt-in: images generated by a LOCAL commercially-clean model), or `both` (stock preferred, local AI only where stock cannot serve). The natural form `using ... images` is equivalent (e.g. `using license-free stock images`). A named value binds and skips the additional-imagery question. **Legacy spellings still bind**: `procedural` -> `none`, and `auto` / `mix` -> `both`. One deliberate behavior change: the old `none` meant "no visuals at all", which no longer exists as a mode - procedural visuals are now the always-on baseline, so `none` means "nothing ADDED". When opting beyond procedural, real license-free stock is PREFERRED and AI is the last resort (used only when relevant stock cannot be found or you explicitly ask for AI). Stock VIDEO is Pexels-only and gated: it needs `--source pexels` and a free `PEXELS_API_KEY` plus build-time consent, and degrades to images-only (or Tier 1) with a one-line note when either is absent - it never blocks and never hotlinks. The stock and AI tiers are opt-in and, before any build-time fetch, require explicit confirmation of the network use; the default `procedural` and every non-interactive run stay fully offline.
- **`--interactivity`** (optional): the interactivity level - one of `restrained` (user-initiated only: hover readouts, click-toggle legends, expand / collapse, anchor nav; no scroll-triggered motion - the credible / journalistic-report end), `balanced` (adds scroll-triggered reveals, active-section nav, animated counters, image lightbox - the current minimum budget), or `rich` (adds scrollytelling: pinned / sticky graphics, full-bleed image-to-text transitions, parallax, a progress-driven timeline or before / after slider). A named level binds and skips the interactivity menu below. Every level honors the offline / no-CDN / reduced-motion guarantees. A fourth value, **`cinematic`** (v3.16.5, opt-in), builds a scroll-scrubbed stage in which scroll drives a continuous camera movement through the document's own sections. It is a SPECIALIZATION of `rich`, not a replacement: interactive charts stay interactive and the five-point interaction budget still applies in full. It carries a size / cost gate the other levels do not - clip count, projected base64 size impact, key requirements, and QA-depth cost are stated and confirmed BEFORE any asset is generated or embedded - because these assets are the largest thing the skill embeds and the output must stay one offline file. Hosted image / video generation is never used (the generation-as-service Hard-No); assets are user-supplied clips, procedural stills, consent-gated license-free stock, or LOCAL AI stills as posters. Under `prefers-reduced-motion: reduce` it degrades to stills-only and creates no video element at all. Separately, when you pick `rich`, the agent MAY propose scroll-scrub after extraction if the content genuinely suits a continuous fly-through - presented with its size estimate and confirmed by you, never silently auto-picked, and never in a non-interactive run. There is no separate cinematic command; it is a level of `/presentify`.
- **`--verbosity`** (optional): the coverage depth - how much of the source material survives onto the page. One of `distilled` (one narrative arc; only key findings, decisions, and conclusions survive), `balanced` (every major topic present, details summarized - the default and the non-interactive fallback), or `comprehensive` (full section-by-section coverage including appendix-grade material). A natural-language form binds the same way (e.g. "keep it comprehensive", "just the highlights" -> `distilled`). This is a CONTENT axis, deliberately named differently from `--qa-depth`: `--verbosity` decides how much content the page carries; `--qa-depth` decides how thoroughly the visual-QA loop inspects whatever was built - the two are independent. A named value binds and skips the round-2 coverage-depth question. An unrecognized value is rejected with a one-line usage note; the run then asks the round-2 question (interactive) or falls back to `balanced` (non-interactive) - it never blocks.
- **`--qa-depth`** (optional): bounds the post-generation iterative visual-QA loop (the skill's Step 9). `deep` (the default per the chosen ambition) runs the full per-segment fan-out (render, grade each segment against the rubric and its source, adversarially verify, synthesize fixes, re-render, iterate); `standard` runs the capped iterative loop; `light` runs a single grading pass for a cost-sensitive run. **All three still RENDER when a browser is available** - `--qa-depth` bounds how many iterations you pay for, not whether the page is ever looked at, so even `light` performs one real render. Only a host with no browser runs structural-only, and then the degradation is disclosed in the final report. Before the loop starts, `scripts/ensure_render_env.py` probes the environment and, if no browser is present, the run offers the one-time provisioning (`pip install playwright` + `playwright install chromium`) ONCE, up front; it never installs anything without that explicit consent, and declining degrades rather than blocks. A per-segment fan-out carries a 5-15x token multiplier, so the loop is scope-first (calibrate on one segment, confirm before scaling) and budget-guarded, and never hard-fails. See `[[ai-billing-safeguards]]`.
- **`--out`** (optional): the output `.html` path. Defaults to a `.html` alongside the inputs (or alongside the folder for a folder input).
- **`--mode`** (optional): overrides the auto-detected mode (below). Defaults to `auto`.

## Choosing the design (asked up front, in one round)

The intake runs in TWO rounds. **Round 1**: when the corresponding flags are not named, `/presentify` resolves ALL FOUR high-level design choices - design direction, output aspect & navigation, interactivity level, and additional imagery - TOGETHER in a single batched round, asked immediately after the command is submitted and BEFORE any document is read. **Round 2** runs after extraction and figure classification, and asks the choices that genuinely need the content: the color scheme and the coverage depth (verbosity). The color-scheme question offers three NAMED schemes derived from the extracted content (each with a 5-swatch preview and the content signal it keys off) plus **Other**; it is skipped entirely by a named `--theme`, a brand `tokens.json`, or a `--style` that already names colors - a pinned brand makes suggestions moot - and by any non-interactive run. The coverage-depth question states what extraction actually found (approximate page / section / topic counts) and offers **Distilled** / **Balanced** / **Comprehensive**, each with a content-derived size hint (an approximate section count for THIS source set); it is skipped by a named `--verbosity` (or its natural-language form), and a non-interactive run resolves it to `balanced`. The chosen scheme PINS the palette for the design roll while type voice, layout, motion, and the signature move still vary, so uniqueness is preserved within the palette rather than traded away for it. None of the four depends on the document's content, so they are gathered first rather than one menu at a time mid-run. Each choice named on the command line binds and drops from the round (`--style` / `using the style <description>` / `--theme`; `--layout` / `using the layout <description>`; `--nav` / `using slide navigation`; `--interactivity`; `--images` / `using ... images`); a fully-specified run asks nothing. The canvas question carries TWO bindable halves, so `--layout` and `--nav` drop it only together.

**No memory, no saved preference.** The ONLY things that skip one of the four questions are an explicit flag in THIS invocation and the non-interactive fallback below. `/presentify` does NOT pre-fill, infer, or skip a choice from a recalled memory (for example a `presentation-style-preference`), a saved preference, a prior run, or inferred context; if such a preference is present it is IGNORED for these four choices and the question is asked anyway. A recalled preference is not consent for this run. This covers the navigation half of the canvas question too: a remembered "prefers slides" never pre-answers navigation mode.

**1. Design direction (style):**

1. **Corporate & Professional** - polished, restrained, business-ready.
2. **Creative & Expressive** - bold, artistic, unexpected.
3. **Technical & Precise** - clean, structured, data-forward.
4. **Surprise me** - the agent invents a unique, creative, interactive direction for this run.
5. **Other** - describe your own style (the same as naming a `--style`).

A `--theme` or a `brand-styling` `tokens.json` pins an exact palette / brand; ask the user for brand tokens before inventing colors. After the round, the agent rolls a seeded design brief from the skill's entropy sampler (`scripts/design_seed.py` - preset-constrained axis pools plus a persisted run history that pushes each run away from the last three, so choosing the same preset twice still yields a different palette, type voice, and layout) and adapts it into concrete tokens for the chosen direction, announcing the committed direction (with the roll's seed) in one line before it builds. The document's character informs the design but does not dictate it: a finance report is not mechanically forced into a corporate look.

**2. Output aspect & navigation (the canvas):**

1. **Full-width scrolling site** - the site fills a 16:9 screen edge to edge, so opening it fullscreen occupies most of a typical widescreen display. Best for deck-like sources.
2. **Standard scrolling column** - a typical centered webpage column width. Best for reports and repositories.
3. **Portrait scrolling canvas** - a tall, narrow, reading- / mobile-oriented canvas. Best for long-form reading and phone-first delivery.
4. **Slide deck** - viewport-fitted slides advanced by keyboard arrows, on a 16:9 full-screen stage by default. Best when you want a PowerPoint-comparable presentation rather than a page to scroll.
5. **Other** - describe your own need (the same as naming a `--layout <description>`).

This single question resolves BOTH halves of the canvas, so Round 1 stays one four-question batch rather than growing a fifth question. Options 1-3 set `nav=scroll` with their existing aspect; option 4 sets `nav=slides` and pins the canvas to a viewport-fitted stage.

The two halves bind independently. A named `--layout` binds the aspect half, a named `--nav` binds the navigation half: when BOTH are named the question is skipped entirely, and when only ONE is named the question offers only the unresolved half (a run with `--nav slides` is asked only which aspect ratio the slide stage should use).

The aspect governs the CSS canvas (page width, section bands, grid columns) and composes with the per-element width discipline and the design tokens; it never overrides them. The navigation mode governs how the reader advances through that canvas.

**3. Interactivity level (how the output responds to the reader):**

1. **Restrained** - user-initiated only (hover readouts, click-toggle legends, expand / collapse, anchor nav); no scroll-triggered motion. The credible / journalistic-report end.
2. **Balanced** - adds scroll-triggered reveals, active-section nav, animated counters, and an image lightbox (the current minimum interaction budget).
3. **Rich** - adds scrollytelling: pinned / sticky graphics that update as prose scrolls past, full-bleed image-to-text transitions, parallax layers, and a progress-driven timeline or before / after slider.

**4. Imagery tier (which visuals the output carries):**

1. **Procedural (default)** - original visuals authored inline as SVG / CSS (color fields, gradient / mesh backgrounds, editorial dividers, generative textures, simple thematic illustrations). Fully offline, zero outbound, commercial-safe by construction (original work). This is the always-on default and the non-interactive fallback.
2. **License-free stock** - opt-in: fetch highly-relevant, real free-for-commercial-use images (and, gated, video) from openly-licensed sources at build time, verify each license, base64-embed them (so the output stays offline), and credit them. Stock VIDEO is Pexels-only and needs a `PEXELS_API_KEY` plus build-time consent; it degrades to images-only otherwise.
3. **Local AI-generated** - opt-in, and the LAST resort among the non-default tiers: generate original images with a LOCAL, commercially-clean model runtime (no hosted generation service is ever called), chosen only when relevant real stock cannot be found or you explicitly ask for AI.
4. **A mix** - a procedural base with real stock accents FIRST, and local AI only where stock cannot serve.

Priority when you opt beyond procedural: PREFER real license-free stock over AI-generated visuals - real stock is provably licensed and content-relevant, while AI output may not be copyrightable and reads as generic. Tier 1 procedural stays the default and the non-interactive fallback.

First-time stock video: stock images need no setup, but stock video needs a free Pexels key. The first time you pick video with no key configured, `/presentify` points you to run `nexus-hub setup-media` in your TERMINAL (a guided, hidden-input, one-time setup) and proceeds with images / procedural in the meantime, rather than asking you to paste a key into the chat. A stored key does not bypass consent - a build-time fetch still requires it.

The stock and AI tiers are OPT-IN and require explicit consent for any build-time network use, and that consent is captured UP FRONT: when you pick `stock`, `ai`, or `both` (and no flag pre-bound the choice), the command captures the build-time-network / generation consent as part of the same up-front batched round, not as a separate mid-run prompt. A consented run then proceeds to fetch and is EXPECTED to integrate relevant imagery into image-starved sections (a consented stock / both run that adds nothing is a bug, not a default). The consent gate stays load-bearing (the fetch helper performs no network without it, degrading with a recorded reason), and a recalled preference never pre-answers it; a non-interactive or headless run never fetches or generates and stays on Tier 1. If the round cannot be answered (a non-interactive run), the agent auto-picks by content - design -> surprise-me / creative; aspect -> full-width for a deck, standard for a report / repository; navigation -> `scroll` (always, for every content type - slide mode is never auto-picked); interactivity -> balanced for a deck / data story, restrained for a report; imagery -> procedural (Tier 1, offline); verbosity -> balanced - and records each (with its auto-pick note) in the output's design-record HTML comment. The resolved navigation mode is recorded there with its provenance (flag / asked / defaulted) like every other choice. A named `--style` / `--theme` / `--layout` / `--nav` / `--interactivity` / `--images` / `--verbosity` skips its respective question.

## Modes (auto-detected, overridable)

The mode is inferred from the inputs and can be forced with `--mode`:

- **`deck`** - a single `.pptx`: **preserve the flow**. Keep the source's content order, but render it as a navigable interactive site, more dynamic than the original. Do not re-sequence a deck the author already structured.
- **`report`** - a single `.docx` / `.pdf` / `.xlsx`: **present the source**. An overview, an intuitive section structure from the headings, and data surfaced as interactive charts. This is where structuring does the most work.
- **`compile`** - two or more files (any mix), or a folder: **compile the sources**. Each source becomes a labeled, attributed area of one site, optionally preceded by a synthesized overview that names all sources. Preserve per-source attribution; do not blend two sources into an indistinguishable middle.
- **`project` / repository** (a single directory input): a specialization of `compile` for a codebase or mixed folder. The extractor walks the tree recursively and emits a synthesized `overview` section plus a `tree`; the site leads with the overview and a navigable file tree, then README / docs, then source code grouped by top-level directory (rendered as offline-highlighted code sections), then data (CSV as interactive charts / tables) and standalone images. Use it to turn a whole repo into one navigable interactive site.

## Output

A single `.html` at `--out` (or alongside the inputs) - a navigable interactive website, not a slide deck. It is fully self-contained: all CSS and JS inline, images as base64, the source's real figures as interactive (zoom / pan / filter) charts built from inlined JS, and no external network requests. Confirm the output location with the user when it is ambiguous (for example, multiple input folders).

## Notes

- Output budget: everything produced in one reply, reasoning included, counts toward a single limit, so the delegated skill writes the page once in the output space and keeps its reasoning to understanding the inputs and settling structure; a complete draft composed as reasoning and then written again is what truncates a large page. Start at the documented default effort and raise it only where a quality gain has been measured. This governs the agent's own deliverable, not tool logs, so `## Output Minimization` still applies unchanged.
- Local-only and private by construction: parsing runs on local libraries (lazy-imported, with a `pip install` hint when one is missing), HTML generation is the agent's own work, and no document leaves the machine.
- When the flags are absent, the agent asks all four high-level design choices - style / direction, output aspect & navigation, interactivity level, and additional imagery - together in one batched round up front, before any document is read, then asks a SECOND round after extraction offering three content-derived color schemes plus Other AND the coverage-depth (verbosity) question with content-derived section counts; then it brainstorms concrete tokens for the chosen direction and announces the committed direction in one line before authoring. Each named flag (`--style` / `using the style <description>` / `--theme`, `--layout`, `--nav`, `--interactivity`, `--images`, `--verbosity`) binds and skips its question, and a recalled memory or saved preference never pre-answers one (only an explicit flag or the non-interactive fallback skips a question). Each run leads with creativity, interactivity, and uniqueness and deliberately differs from the default dark / monospace-label / amber-accent / card-grid look, so outputs do not all look alike; the document's character informs the design but does not dictate it.
- The layout uses the window width on purpose: the narrow reading measure applies to body prose only, so headings and hero text are not trapped in a half-width column while cards or charts sit at full width. The output aspect (`--layout` or the canvas menu) sets the canvas - full-width / standard / portrait / other - and the site holds a vertical-density discipline so sections are sized to content with no dead, half-empty screens. The navigation mode (`--nav` or the same menu) decides whether the reader scrolls that canvas or advances through it as viewport-fitted slides by keyboard arrow; `scroll` is the default and the non-interactive fallback, and each output file is authored for exactly one mode.
- Prominence is preserved: a visual that dominated its source (a large photo on a slide, the single figure on a page) stays a hero at native resolution rather than being flattened into a uniform thumbnail grid; only genuinely-secondary visuals are grouped.
- Imagery is tiered and offline-safe: the default is original procedural visuals (Tier 1, inline SVG / CSS, zero outbound, commercial-safe by construction); license-free stock (Tier 2) is opt-in and, for its build-time fetch, consent-gated; local AI-generated images (Tier 3) are opt-in and LOCAL-only (no hosted generation service is ever called - that would be generation-as-service), degrading to Tier 1 when no local model runtime is present. Every fetched or generated asset is base64-embedded so the output still opens offline with zero external requests. Interactivity is a chosen level (restrained / balanced / rich scrollytelling) via `--interactivity`, always reduced-motion-guarded.
- Supported inputs: documents (PDF / Word / Excel / PowerPoint, including scanned-PDF reading via local OCR + agent-vision fallback, PDF image and vector-figure extraction, and native PowerPoint / Word chart objects), source code and config, Markdown / plain text, CSV / TSV, standalone images, and whole directories / repositories (walked recursively). Out of scope: video / audio embedding. See the skill's `references/extraction-runbook.md`.
