# Code-Search Seeding for Application-Security Review

This procedure guides security-review hosts after surface inventory and before specialist adjudication. It uses the existing local code-search server, qualified graph identities, bounded disposable indexing, metadata-only receipts, and visible degraded fallback. Graph absence never establishes safety.

## Public capability contract

Begin each host run with public MCP initialization and tool listing. Record the profile and schemas by digest. The repository capability probe on 2026-09-08 verified these operations in the `standard` profile; `full` also contains them, while `minimal` does not expose every graph operation. Platform absence is `UNAVAILABLE`, including platforms without automatic code-search registration. Do not install a missing server implicitly.

| Operation | Required parameters | Additional graph parameter | Observable result |
|---|---|---|---|
| `code_node` | root, symbol | none | matching qualified nodes |
| `code_callers` | root, symbol | none | resolved seed count and direct caller edges |
| `code_callees` | root, symbol | none | resolved seed count and direct callee edges |
| `code_impact` | root, symbol | depth, default 2, advertised 1-6 | bounded-depth impact nodes |
| `code_context` | root, symbol | none | seed, callers, callees, siblings |
| `code_explore` | root, symbol | depth, default 2, advertised 1-6 | seed, callers, callees, impact |

All operations share the shipped response-format controls; use JSON for deterministic projection. Public `index_graph(root, force=false)` builds the existing local graph and reports file/node/edge counters. Public `get_indexing_status(root)` reports the separate chunk-index status; idle or a missing timestamp does not prove graph freshness. No public path operation, graph schema version, completeness marker, or freshness attestation is established by this probe. Record graph quality `unknown` unless independent evidence establishes it; `RAN` means terminal output only.

## Procedure

1. Consume the canonical surface inventory and its complete planned queue. Select entry seeds from observed route handlers, authentication boundaries, job handlers, and other in-scope application entry points. Select candidate sinks from observed query execution, subprocess calls, filesystem access, network requests, deserialization, authorization decisions, cookies, and error output. Missing entry/sink evidence is an incomplete seed inventory, not permission to guess symbols. Retain unsupported scope and every unmet owner obligation.
2. Use the sibling `_safe_artifact.py` owned temporary-root and contained-copy functions. Copy only explicitly authorized, inventory-bound source files; no target code/config is executed. Compute original content manifests before copying and after every indexing/query exercise with `_target_manifest.py`. Fail if any copied file or original identity changes. The existing `.nexus/code-index` may be created only inside that disposable root. Hash the index's contained regular files after indexing and after queries; if it changes unexpectedly, invalidate the receipt. Never hash a live changing SQLite file as stable evidence. Hold ownership until success/failure cleanup completes; an unverified cleanup is a failure.
3. Resolve a seed with `code_node`, preserving every returned candidate. Use its exact qualified identity for subsequent calls. An opaque symbol ID is `sha256:` plus the canonical JSON digest of the qualified identity; pair it with the canonical repository-relative path and bounded line region. Never emit the raw symbol string when it may contain source-controlled sensitive text. Keep parameters and original result bytes only in bounded process memory long enough to compute digests; emit no source, signature, docstring, configuration, prompt, command, environment value, absolute root, or secret-like value.
4. For each seed, request direct callers and callees; expand qualified edges breadth-first for at most two hops, 100 distinct nodes, 24 operations, and 60 seconds per operation. Use `code_impact` at depth 2 and context/explore as supporting views. These are host request/consumption ceilings, not a claimed server result-limit feature. Discard an over-budget response from adjudication, record truncation/timeout, and preserve the unmet obligation. No hidden retry is allowed. Match counts above one retain all qualified candidates and mark ambiguity until adjudication; zero matches retain the finding and mark `GRAPH_NO_RESULT`.
5. Before any stdout, log, fixture, or release evidence, call the pure sibling [`_graph_receipt.py`](../scripts/_graph_receipt.py) projector. It whitelists graph containers and emits only canonical relative locations, opaque qualified IDs, operation IDs, parameter/result/index digests, target/revision/scope/routing/run bindings, counters, duration, terminal reason, and ambiguity/truncation/fallback flags. It never runs a graph or reads a target. Raw errors become fixed reason codes. It rejects unsafe paths and invalid metadata rather than echoing them. Hash observation establishes content identity, not host execution provenance.
6. For unavailable, failed, partial, ambiguous, slow, or unknown-quality graph evidence, retain the graph obligation and use bounded [[direct-corpus-interaction]] only when the same target/boundary authorizes it. State a hypothesis, inspect the inventory-selected source region, trace exact qualified candidates, and verify each claim against a line. Keep the same two-hop/100-node/24-operation limits and receipt redaction boundary. Set fallback `direct-corpus`, graph quality `unknown` or the observed degraded state, and an explicit terminal graph reason. Do not invent unavailable graph operations, claim process assurance, or clear a finding on a no-result query.
7. Adjudicate through the routed specialist. Graph evidence can adjust confidence but cannot alone reject a finding, approve a patch, replace a scanner receipt, or serve as the independent verifier. Scanner, remediation, and verifier owners remain unchanged. Validate graph metadata with the closure-owned application-audit profile before downstream health/export/scoring.

## Receipt contract

The sibling projector/validator is the executable metadata shape. `availability` is `RAN`, `NOT_APPLICABLE`, `UNAVAILABLE`, `FAILED`, or `DECLINED`; non-run states require the matching fixed reason, no claimed result digest, zero result count, and no observed locations. A timeout is `UNAVAILABLE` with `GRAPH_TIMEOUT`. `quality` is separately `complete`, `partial`, `ambiguous`, or `unknown`. The projector never emits `complete`, since current public responses do not establish graph freshness. A separately supplied complete claim requires no ambiguity/truncation/fallback and a bound index digest; the profile still treats host execution as self-attested.

Bind every receipt to the same run fingerprint, target revision, target-root and scope fingerprints, and routing digest. The run fingerprint binds the content-manifest identity. An index digest is nullable only when unavailable; never substitute a timestamp or a different run's index. Keep separate receipts for conflicting query outputs, fail closure pending adjudication, and never silently select one. A failed operation fails aggregate health; unavailable, partial, ambiguous, fallback, and unknown-quality evidence remain degraded. Ordinary schema-v1/v2 records without the application-audit profile retain their previous behavior.
