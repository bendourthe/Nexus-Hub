# Retained handbook PowerPoint export

Use this runbook only when PowerPoint export of a retained interactive handbook is explicitly requested. The HTML skill owns the source-to-page-to-slide/state map and immutable figure definitions; this owner maps them into native PowerPoint content and verifies the actual package and playback. Routine documentation/release HTML refresh does not create a PPTX.

1. Load the retained storyboard, source coverage map, figure worksheets, brand assets, saved slide themes, slide-count ceiling and motion intent. Preserve every required unit and stable source identity. Record requested display aspect ratio or verified target dimensions; when neither is supplied, state the chosen default. One ratio cannot fill every physical screen without letterboxing, cropping or stretching.
2. Compose a headerless slide canvas. Keep section context in semantic slide content and navigation in the HTML controls. Place the authentic theme-appropriate mark/wordmark at the upper right only where measured content leaves clear space; omit it when occupied and avoid a duplicated cover lockup. Use the recovered header area to reflow the actual evidence.
3. Recompose complete directories, tables and interactive details into readable native slide content inside the existing logical-slide budget. Never use a cropped browser viewport, off-slide text, notes-only content or extra repair slides to claim complete coverage. If fit, visible coverage and the ceiling conflict, report that conflict before export; retain the HTML as the interactive deliverable.
4. Preserve charts as native series/marks and diagrams as editable elements wherever feasible. Map compatible process/comparison builds to automatic entrance effects with the recorded sequence or simultaneous comparison timing. A wipe over a screenshot of the entire figure is not native mark animation. State unsupported filters, scrolling and interactive behavior as format limitations.
5. Use full-bleed artwork matching the target aspect without baked-in bars, distortion or subject loss. Prefer a quick direct crossfade, approximately 0.2 seconds, without a fade-through-black. Preserve every saved light/dark theme assignment and motion intent; do not reroll style during export.
6. Open/render the actual PPTX in PowerPoint and inspect timed playback. Check all slides, all visible directory entries, chart/diagram geometry, automatic triggers, transitions, brand proportions, font embedding/substitution and target-display fit. Package structure alone does not prove playback. If PowerPoint rendering/playback is unavailable, record export parity as unverified.
7. Inspect package relationships for linked media, fonts and files. Embed required dependencies. Identify intentional outbound citation links separately from runtime dependencies. Copy only the final renamed PPTX into a temporary directory and render it again; likewise verify any final HTML renamed for sharing from its own single-file directory.
8. Deliver exact final filenames and a minimal share list. Separately identify private source documents, editable models, generator, brand assets, extraction/build records and QA evidence to retain. Repair the source/output map and rebuild commands after any rename; a standalone artifact does not establish that an old generator path still works. Do not delete working folders merely because exported files are self-contained.

Record the final PPTX hash, actual render/playback evidence, format limitations and any unresolved findings. Use `hallmark-design` for contextual composition and `anti-slop-editing` for prose; this reference owns native PowerPoint behavior and package verification rather than duplicating those rules.
