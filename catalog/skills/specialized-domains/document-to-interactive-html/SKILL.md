# Document to Interactive HTML

Turn existing documents into a single self-contained, offline, UNIQUE interactive website - not a static slide deck. The pipeline is compositional: a local extractor reads any mix of PDF / Word / Excel / PowerPoint into one normalized content model, and the agent then authors a bespoke interactive web experience from that model. The whole point is to move AWAY from PowerPoint-style static decks toward an engaging, dynamic interface: a clear, intuitive, navigable structure (sections, in-page navigation, scroll or routed views - whatever fits the content), real figures rendered as INTERACTIVE charts the reader can manipulate (zoom, pan, toggle series, adjust axis limits), intentional motion, and a design that is fresh each run. Nothing leaves the machine and the output has zero external dependencies.

A bundled deterministic builder (`scripts/build_presentation.py`) is available as an OPTIONAL plain baseline - a fast, reproducible, simple sectioned page - but it is not the goal and its output is intentionally minimal. The primary, default path is LLM-native authoring of a unique interactive site; reach for the builder only when a caller explicitly wants a quick deterministic draft to elevate.

This skill is the connector between Nexus-Hub's document-reading skills (`[[pptx-generation]]`, `[[docx-generation]]`, `[[xlsx-generation]]`, `[[pdf-document-generation]]`) and its self-contained-HTML design discipline (`[[html-output-conventions]]`, `[[hallmark-design]]`, `[[theme-tokens]]`, `[[brand-styling]]`). It does not reinvent either side; it wires ingestion to a unique interactive-website output.

## When to Use This Skill

Use this skill when:

- The user wants an existing PowerPoint turned into a more interactive, more dynamic website that follows the same flow.
- The user wants a report (Word or PDF) presented as a navigable interactive site: an overview, an intuitive section structure from the headings, data surfaced as interactive charts.
- The user has several documents (any mix of formats) and wants them compiled into one interactive site with per-source attribution.
- The user wants a spreadsheet's data shown as interactive, manipulable charts (zoom, filter, axis controls) inside a navigable site rather than a static export.
- The site must work offline, open from a single file, and contain no external requests (a confidential report, an air-gapped demo, an email attachment).

**Trigger phrases**: "presentify this", "turn this PowerPoint into an interactive website", "make an interactive site from these docs", "turn these documents into an interactive presentation", "convert this PDF/Word/Excel into an interactive website", "build an interactive site from this report", "compile these documents into one interactive site".

**When NOT to use**:

- Generating a brand-new document from scratch: use `[[pptx-generation]]`, `[[docx-generation]]`, `[[xlsx-generation]]`, or `[[pdf-document-generation]]`. This skill presents documents that already exist; it does not author source documents.
- A one-off static chart or a data export with no presentation flow.
- A plain HTML document (a README, a long-form article) that has no slide model or interactivity. Use `[[html-output-conventions]]` directly for non-presentation HTML.
- Video / audio EMBEDDED IN A SOURCE document is out of scope: the extractor does not carry media out of an input PDF / PPTX / DOCX into the output (see `references/extraction-runbook.md`). This is distinct from OUTPUT-side imagery - license-free stock VIDEO can appear in the generated site through the opt-in, consent-gated stock tier (Pexels-only, base64-embedded so the file stays offline; see "Tier 2 - license-free stock" in `references/interactive-features.md`). Scanned / image-only PDFs ARE supported via the extractor's two-tier local-OCR + agent-vision path.

## The Pipeline

The four high-level design choices are gathered up front in one batched round; then a local extraction stage, then LLM-native authoring. The contract is the normalized content model in `references/content-model.md`; nothing reads a source format directly after extraction, so the model is the single stable interface. Only the four CHOICES are hoisted to the front; the generative design-token brainstorm still runs after extraction, where it can see the content.

```

                        style/direction, output aspect & navigation
```

## Instructions

1. **Detect the inputs and the mode.** Inspect the input paths and pick the mode (auto-detected, overridable). In every mode the output is a navigable website, not a slide sequence:
    - One `.pptx` -> **preserve the flow**: keep the source's content order, but render it as an interactive site (sections + in-page navigation), better designed and more dynamic than the original.
    - One `.docx` / `.pdf` / `.xlsx` -> **present the source**: a clear landing/overview, an intuitive section structure from the headings, and data surfaced as interactive charts.
    - Two or more files (any mix), or a folder -> **compile the sources**: each source is a labeled, attributed area of the site, optionally preceded by a synthesized overview. Preserve per-source attribution.
2. **Resolve the design intake, ROUND 1 (up front, one batched round).** Resolve ALL FOUR high-level design choices - style / design direction, output aspect & navigation, interactivity level, and additional imagery - TOGETHER in a single batched question round, immediately after mode detection and BEFORE extraction. None of the four depends on the document's content (the only content-aware logic is the non-interactive fallback below), so they are asked first, in one round, not one menu at a time mid-pipeline; the interactive question surface accepts up to four questions at once. A SECOND round runs later, at the head of Step 5, for the design choices that genuinely cannot be made before the content is read: the color scheme and the coverage depth (verbosity).
    - **A named flag binds and drops from the batch.** A choice named on the command line in THIS invocation binds and is excluded from the questions: `--style` / the natural `using the style <description>` / `--theme`; `--layout` / `using the layout <description>`; `--nav <scroll|slides>` / the natural `using slide navigation` or `as slides`; `--interactivity`; `--images` / `using ... images`. A fully-specified run asks nothing.
    - **The canvas question has TWO bindable halves.** `--layout` binds the aspect half and `--nav` binds the navigation half. When BOTH are named the canvas question is skipped entirely; when only ONE is named the question offers only the UNRESOLVED half (given `--nav slides`, ask only which aspect ratio the slide stage uses). The two compose freely - `--layout portrait --nav slides` is not a conflict, it is portrait-ratio slides - so no pair of flags can deadlock the intake. An unrecognized `--nav` value (e.g. `--nav deck`) is rejected with a one-line usage note; the run then asks the canvas question (interactive) or falls back to `scroll` (non-interactive), and never blocks.
    - **`--images` spellings.** The current values are `none` / `stock` / `ai` / `both`. The pre-v3.16.5 spellings still bind, for backward compatibility: `procedural` -> `none` (procedural is now the always-on baseline, so "procedural only" IS "no additional imagery"), and `auto` / `mix` -> `both`. One behavior change is deliberate and worth stating rather than hiding: the old `none` meant "typography / layout / color only, no visuals at all", and that mode no longer exists - because the procedural layer is always on, `none` now means "the built-in procedural visuals and nothing added".
    - **NEVER pre-answer a choice from memory or inferred context.** The ONLY things that skip one of the four questions are an explicit flag in THIS invocation and the non-interactive fallback below. Do NOT pre-fill, infer, or skip any of the four from a recalled memory, a saved preference (for example a `presentation-style-preference` memory), a prior `/presentify` run, project or session context, or a "sensible default". If such a memory or preference is present in context, IGNORE it for these four choices and ask anyway - a recalled preference is not consent for THIS run.
    - **The four choices, asked together:**
        1. **Style / design direction** - five options: (1) Corporate & Professional (polished, restrained, business-ready); (2) Creative & Expressive (bold, artistic, unexpected); (3) Technical & Precise (clean, structured, data-forward); (4) Surprise me (let the agent invent a unique, creative direction for THIS run); (5) Other (the user describes their own style, equivalent to `--style`). A `[[theme-tokens]]` set or a `[[brand-styling]]` brand `tokens.json` also binds this choice; ask the user for brand tokens before inventing a brand's colors.
        2. **Output aspect & navigation (the canvas)** - ONE question resolving BOTH halves of the canvas, so the round stays at exactly four questions instead of growing a fifth. Five options: (1) **Full-width scrolling site** (fills a 16:9 screen edge to edge; best for deck-like sources); (2) **Standard scrolling column** (a centered webpage column; best for reports and repositories); (3) **Portrait scrolling canvas** (a tall, narrow reading- / mobile-oriented canvas); (4) **Slide deck** - viewport-fitted slides advanced by keyboard arrows on a 16:9 full-screen stage by default, for a PowerPoint-comparable presentation rather than a page to scroll; (5) **Other** (describe your own). Options 1-3 set `nav=scroll` with their existing aspect; option 4 sets `nav=slides` and pins the canvas to a viewport-fitted stage. The navigation mode governs how the reader ADVANCES (scroll plus anchor nav, versus keyboard-advanced slides: ArrowRight / ArrowDown / PageDown / Space forward, ArrowLeft / ArrowUp / PageUp back, Home / End to the first / last slide, swipe on touch, and a click on the on-screen next / previous zones); the aspect still governs the CSS canvas. Each output file is authored for exactly ONE mode - there is NO runtime scroll / slides toggle.
        3. **Interactivity level** - restrained (user-initiated only: hover readouts, click-toggle legends, expand / collapse, anchor nav; no scroll-triggered motion) / balanced (adds scroll-triggered reveals, active-section nav, animated counters, image lightbox - the current minimum budget) / rich (adds scrollytelling: pinned / sticky graphics, full-bleed transitions, parallax, a progress-driven timeline or before / after slider). **CINEMATIC (v3.16.5, opt-in, a fourth choice)** - a scroll-scrubbed stage where scroll drives a continuous camera movement through the document's own sections; it is a SPECIALIZATION of rich (charts stay interactive and the five-point budget still applies in full), it needs the size / cost gate before any asset is built, and it degrades to stills-only under `prefers-reduced-motion`. Offer it with that one-line description. Amendment for the `rich` answer: after extraction, when the content genuinely suits a continuous fly-through (a strong linear narrative, a journey / place / product structure), you MAY PROPOSE scroll-scrub as the run's signature scrollytelling pattern - present the size / cost estimate and get a yes or no. Under `rich` it is proposed-then-confirmed, NEVER silently auto-picked, and a headless / non-interactive run never selects it. The full protocol is `references/scroll-scrub.md`.
        4. **Additional imagery?** - Procedural visuals (original inline SVG / CSS: color fields, editorial devices, generative textures, thematic illustrations) are the ALWAYS-ON baseline every page gets, zero-outbound and commercial-safe by construction. They are no longer a menu choice, so this question asks only what to ADD on top of them. Exactly four options:
            1. **None** - no additional imagery. Say this explicitly when offering it: the page still gets the full procedural visual layer, so `None` means "the built-in visuals only", NOT a bare page. Fully offline; nothing is fetched or generated.
            2. **Stock images** - real license-free, free-for-commercial-use media, fetched at build time under explicit consent, license-verified, and base64-embedded so the output stays offline.
            3. **AI-generated images** - opt-in, a LOCAL commercially-clean model only. A hosted generation API is NEVER called.
            4. **Stock + AI** - stock PREFERRED, local AI only where stock cannot serve a placement.
            When the answer is anything but `None`, PREFER real license-free stock and MINIMIZE AI generation - local AI is the last resort, used only where relevant stock cannot be found for a placement or the user explicitly asked for AI. Options 2-4 are consent-gated for any build-time network use or local generation (captured in the same up-front round, per the consent bullet below); `None` stays fully offline. Stock VIDEO is offered under options 2 and 4 but is Pexels-only and gated (needs `--consent` AND a `PEXELS_API_KEY`); it degrades to images-only with a one-line note when either is absent.
    - **Capture build-time consent up front (stock / ai / both).** When the answer to the additional-imagery question is `stock`, `ai`, or `both`, capture the CONSENT for the build-time network use (the stock fetch) or local generation as part of (or immediately after) this same batched round, not as a separate mid-pipeline prompt. A consented `stock` / `both` run is EXPECTED to attempt integration in Step 6 (silence is a bug, not a default). Preserve every invariant: the `none` answer and every non-interactive run stay fully offline and never fetch; the consent gate stays load-bearing (`scripts/fetch_stock_media.py` performs NO network without `--consent`, and degrades with a recorded reason); a recalled memory or saved preference NEVER pre-answers the consent (only this run's explicit choice does). A non-consented or non-interactive run stays on Tier 1 with a one-line note.
    - **Non-interactive / headless fallback (behavior unchanged).** When the batch cannot be answered, do NOT block: apply the content-aware auto-picks - style -> surprise-me / creative; aspect -> full-width for a deck, standard for a report / repository / text-dominant source; navigation -> `scroll` (always, for every content type - slide mode is never auto-picked); interactivity -> balanced for a deck / data story, restrained for a report; additional imagery -> `None` (the procedural baseline only, fully offline) - and record each with its auto-pick note in the design-record comment. This headless auto-pick is the explicit no-interaction path; it is NOT "using a preference".
    - Record the four resolved choices (and whether each was auto-picked) in the design-record HTML comment. The canvas question records TWO values: the resolved aspect and the resolved `nav` mode, each with its provenance (`flag` / `asked` / `defaulted`). **Backward compatibility:** a design record carrying NO `nav` field (any page authored before this axis existed) means `nav=scroll` - treat its absence as the default, never as an error, so an older page re-entering the QA loop grades as a scrolling site. The GENERATIVE brainstorm for the chosen style direction (the seeded entropy roll and concrete-token commitment) happens AFTER extraction (Step 5), because it legitimately benefits from having seen the content; only the four choices are resolved here.
3. **Extract to the content model.** Run the local extractor:

    ```bash
    python scripts/extract_content.py <input...> -o model.json [--title "..."] [--max-image-bytes N]
    ```

    It dispatches by extension, lazy-imports each parser (so a missing library prints `pip install <lib>` and exits non-zero rather than crashing), carries images inline as base64 within a size budget, preserves source / section / block order, and merges multi-file input with a `sources` manifest. It also scans text blocks for SOURCE PLACEHOLDERS the author left unfilled (`xx`, `[insert ...]`, `[TBD]`-style tokens) and emits them in the model's `placeholders` list: surface every detected placeholder to the user in the Round 2 intake (they may know the real value), and when one ships, render it faithfully with a visible note - never invent the missing number. `chart` blocks carry the real data series (categories + values), so the charts you build use the source's actual numbers, never invented ones. Per-format coverage and the image budget are in `references/extraction-runbook.md`; the JSON shape is `references/content-model.md`.
    - **Base64 payloads stay out of context (BINARY).** The model file carries every image as a `data_uri` string, sometimes megabytes long. Never load those payloads into your own context: read the model through a projection that replaces each `data_uri` with its MIME type and byte length (for example `python -c "import json,sys; m=json.load(open(sys.argv[1])); [b.__setitem__('data_uri', b['data_uri'][:30]+'...('+str(len(b['data_uri']))+' chars)') for s in m.get('sections',[]) for b in s.get('blocks',[]) if 'data_uri' in b]; print(json.dumps(m, indent=1))" model.json`), refer to images by section and block index while authoring, and copy the URIs into the output programmatically (the builder does this; an authored page reads them from the model file with a script) rather than by pasting them through the conversation. The same rule applies on the way out: never read the generated `.html` back wholesale; Step 8 verifies it with `grep` and the bundled scripts, and Step 9 looks at screenshots. Base64 returned into model context is a documented safety-classifier false-positive trigger, and the offline guarantee is met by embedding, not by reading what was embedded (decision: `docs/releases/v4/v4.7/development/base64-context-decision.md`, 2026-09-05).

4. **Classify and reconstruct figures (MANDATORY whenever the model contains image blocks).** Run the `references/figure-reconstruction.md` protocol over the extracted model before any design work: render and classify every image block (`chart` / `map` / `diagram` / `table-image` / `photo` / `screenshot` / `decorative`); fill the read-the-figure worksheet for every data-bearing figure and pass the fidelity cross-checks; apply the confidence gate - `high`/`medium` figures become interactive `chart` blocks with `provenance: "reconstructed-from-image"`, a `confidence` tier, `source_image` for the view-original toggle, and the worksheet embedded as an adjacent HTML comment, while `low`-confidence figures ship as enhanced originals (pan/zoom lightbox with a stated reason), NEVER as fabricated charts; rebuild maps/diagrams as interactive SVG only when every label survives; verify scanned-page OCR text against the page image (ALL numeric content regardless of confidence) and transcribe gaps as `provenance: "agent-read"` blocks; then write classifications and new blocks back into the model JSON so authoring and coverage reconciliation work from one source of truth. Skip this step only when the model contains no image blocks.
5. **Design intake ROUND 2 (color scheme + coverage depth), then brainstorm concrete tokens (creativity-first).** Round 2 runs HERE, after extraction and figure classification and before the token brainstorm, because these are the design choices that need the content: a scheme can only be content-derived once there is content to derive it from, and a coverage-depth choice is only answerable once the agent can say what the sources actually contain. Ask both round-2 questions together in one batch, not one at a time.
    - **Propose THREE content-derived schemes plus Other.** Analyze the extracted model - subject domain, tone, era, and any brand colors already present in source figures or logos - and propose exactly three NAMED color schemes you judge relevant to this content and coherent with the Round 1 style choice. Each one carries a 5-swatch preview (base / surface / ink / accent / accent-2 hexes, rendered in the question's preview field) and ONE sentence on why it fits. A fourth option, **Other**, lets the user describe their own.
    - **Cite the content signal each scheme keys off.** This is what separates a content-derived scheme from a random palette, and it is the whole point of asking after extraction rather than before: name the signal ("the source's own chart series are blues and slate", "a 1970s field-report subject", "the deck's existing logo teal"). A scheme with no citable signal is not content-derived and should not be offered.
    - **Skips - do not ask when the answer is already fixed.** A named `--theme`, a brand `tokens.json` (`[[brand-styling]]`), or an explicit `--style` that already names colors makes suggestions moot: skip Round 2 entirely and say so in one line. A non-interactive run also skips it, and the entropy roll picks as it does today, recorded with its auto-pick note.
    - **Feed the choice to the roll as a CONSTRAINT, not a replacement.** Pass the chosen scheme to `scripts/design_seed.py --scheme-hint '<json>'` (or a path to that JSON). The sampler still rolls type voice, layout signature, motion personality, signature move, and spacing rhythm, and the history / anti-convergence logic is untouched - so two runs on the same pinned palette still differ on every other axis. Uniqueness is preserved WITHIN the pinned palette rather than traded away for it.
    - **Record it in the design record**: the three schemes offered, the content signal cited for each, which was chosen (or the Other description), and - when skipped - which skip applied.
    - **Ask the coverage depth (verbosity) in the same round.** This is the axis no round-1 choice covers: how much of the source material survives onto the page. Style shapes tone and register; verbosity decides survival. Make the question stem CONTENT-DERIVED: state what extraction found ("~40 pages across 6 major topics", "a 12-slide deck with 3 data figures") and offer exactly three options, each with a size hint derived from THIS source set (an approximate section count): **(a) Distilled** - one narrative arc; only key findings, decisions, and conclusions survive (~low-bound sections); **(b) Balanced** - every major topic present, per-topic detail summarized; **(c) Comprehensive** - full section-by-section coverage including appendix-grade material. When extraction yields too little content to characterize (a single tiny source), still ask, using the generic option descriptions without the counts.
    - **Verbosity skips and fallbacks.** A named `--verbosity <distilled|balanced|comprehensive>` (or its natural-language form: "keep it comprehensive", "just the highlights") binds the axis and skips the question - the flag is a PRESET, so when it is given the question is never asked, even in an interactive run. An unrecognized flag value is rejected with a one-line usage note, then the run asks the question (interactive) or resolves to `balanced` (non-interactive); it never blocks. A non-interactive run, or an unanswered prompt, resolves to `balanced` - the closest match to the pre-verbosity implicit behavior, so unattended runs do not change character. A recalled memory or saved preference NEVER pre-answers this choice, same as the round-1 four.
    - **Record the verbosity in the design record**: the resolved level, its provenance (`flag-preset` / `asked` / `defaulted`), and the derived section-count target for this run. The target is what Step 6's depth rules build to and what the visual-QA rubric's coverage-depth criterion grades against.
    - **Resolve the CONTENT BRIEF in the same round (what the page must accomplish), per `references/content-intent.md`.** The Round 1 four and the color / depth pair are all about FORM. None of them records what the artifact is FOR, which is why a page can pass every gate and still address the wrong reader. INFER these four fields from the request and the extracted source, and ask only what inference cannot settle - in ONE batched clarification, never four separate questions: (1) **`source_relationship`** (BINARY, default `standalone`) - one of `standalone` (the source informs the output and is never mentioned), `revision-aware`, `comparative`, or `faithful-adaptation`; default to `standalone` unless the user explicitly asked for critique, redlining, version comparison, or change commentary, and under `standalone` the visible output must not say "the original", "the prior draft", "what was right", "what was wrong", or "original preserved" unless the subject matter independently requires the words. (2) **`decision_to_enable`** - the one choice the reader must be able to make; when the request names options, the coverage list in the reference applies. (3) **`assumptions`** - the ledger, each classified `accepted` / `needs-verification` / `bounded` / `material-risk`; an `accepted` premise is part of the task contract, so no section heading or lead sentence may negate one, and challenging any assumption requires stated evidence plus the decision consequence. (4) **`scope_class`** (BINARY wherever an estimate is produced) - one of `working-demonstration`, `decision-grade-pilot`, `controlled-rollout`, or `reusable-platform`; every visible timeline names its class and at least three planning assumptions, and a bounded pilot NEVER inherits a reusable-platform estimate (agent speed changes the execution rate, not the target boundary). Record all four plus `exclusions` as the design record's `content_intent` block. Gate A grades this before authoring begins.
    Then brainstorm the concrete tokens that realize the Round 1 direction within that palette. The style / design direction was already chosen up front in Step 2 - do NOT re-ask it. Now that the content is extracted, brainstorm the concrete tokens that realize that direction. Do not jump straight to markup, and do not reuse a fixed house look (a recognizable style across runs is the templated "AI-generated" signature `[[hallmark-design]]` rejects); the goal each run is a UNIQUE, creative, interactive design, not a style mechanically derived from the document type.
    - **Roll the entropy brief, then adapt (mechanical variety first).** Using the direction chosen up front in Step 2, run `python scripts/design_seed.py --preset <choice> -o brief.json`: a seeded, history-aware sampler over curated axis pools (12 hue families with light and dark bases, moods, type voices, layout signatures, motion personalities, signature moves) that rejects any candidate sharing 2+ of {hue family, layout signature, type voice} with the last 3 committed runs - so two same-preset runs CANNOT converge to the same look. If no browser is available, ASK THE USER ONCE, up front, whether to run the one-time provisioning (`--install` runs `pip install playwright` + `playwright install chromium`; it NEVER installs without that flag).         **In slide mode (`nav=slides`) the capture set changes shape; scroll mode is unchanged.** The unit of evidence is the SLIDE, not the scroll band. Capture EACH slide at the four viewports (the 1366x768 leg is where the fit rule bites, per rubric criterion 12a). The interaction states become each slide's FRAGMENT SEQUENCE - first, one mid, and last state per slide - plus the lightbox and one chart interaction. The regression smoke-set becomes the title slide, one mid-deck slide, and one interactive chart slide. Wait for the transition to end, or emulate `prefers-reduced-motion: reduce` so transitions are instant cuts, and poll for a settled value rather than sleeping a fixed interval against an animation's duration. Deep-link one mid-deck slide (`#slide-<n>`) to confirm fragment state resolves rather than half-building.

Pass `{behavior: 'instant'}` explicitly and wait for the position to settle before capturing. A wrong diagnosis from a mid-scroll frame nearly shipped once.

Numbers end an argument a screenshot only starts - and they are what caught a 12.48px label that looked fine. Include the PAINTED-CANVAS probe for every JS-painted stage / chart canvas: its `clientWidth` is within a few px of its container's width AND a pixel sample is not uniformly blank after settle - a canvas squeezed or never drawn passes every static check and every console-error listener while rendering nothing (a CSS class collision once shrank the whole cinematic stage to a 10px strip with zero errors; only this probe class catches it deterministically). Run the deterministic STRUCTURAL checks with `scripts/visual_qa_score.py` and add the AGENT-VISION judgments from the screenshots. Optionally fan the per-segment grading out via the `assets/visual-qa-workflow.js` Dynamic-Workflow template when Dynamic Workflows are available.
    - **Decide imagery PLACEMENTS on the first iteration (consented runs only).** When the Round 1 answer was `stock`, `ai`, or `both` AND consent was given, the first grading pass also decides WHERE imagery helps, using the placement-role taxonomy in `references/interactive-features.md`: **hero / header**, **background** (with the mandatory scrim recipe, so overlaid text stays AA against a known color rather than against a per-pixel image), **contextual illustration**, or **gallery**. It runs HERE rather than before the loop because this is the first point at which the page can be SEEN - a section that looked starved in the content model may already read as full, and a band that looked fine may be visibly empty. For EVERY section produce one of two outcomes and never silence: a placement (role + one line on why THIS content benefits in THAT role), or an explicit `no image: <reason>`. Check each candidate's RELEVANCE before embedding - a generic techy stock photo beside a section about test coverage depicts a stock photo, not test coverage - re-query ONCE with tightened keywords, then drop the placement with its reason rather than embedding filler. Record every decision in the design record's `IMAGERY PLACEMENTS` block in the parseable form the reference specifies; `scripts/visual_qa_score.py` verifies that record against the page and fails a run whose record is missing, overclaims, or declines without a reason. A `none` / non-consented / non-interactive run emits NO placement pass at all - the procedural baseline is the whole design there, not a shortfall.
    - **Adversarially verify.** Before accepting a HIGH-severity finding, have an independent skeptic try to REFUTE it (default to refuted when uncertain), so the fix pass chases real defects only.
    - **Synthesize fixes and re-render - MANDATORY, not optional.** Apply ONLY the confirmed fixes, rebuild, and re-render. Findings-to-fix-to-re-render repeats until NO high-severity finding remains or the `--qa-depth` cap is hit. A run that reports findings without re-rendering has not run the loop; it has run one grading pass.
    - **Every re-render pass captures the REGRESSION SMOKE-SET, not just the changed section.** The fixed set - the hero at load, one divider (or band transition) mid-scroll, and one interactive chart - is captured on EVERY iteration and on every post-delivery edit, however unrelated the edit looks. Change-local rendering is how a map-pin CSS edit shipped a broken hero: the edited section verified clean while a class collision silently destroyed a section nobody re-looked at. The smoke-set costs three screenshots; the regression class it catches is exactly the one change-local verification structurally cannot.
    - **Capture PER-SECTION evidence, not only whole-page frames.** A full-page screenshot renders each section too small to judge typography: it establishes consistency and hides wrapping, heading balance, table density, and sticky spacing. Capture each top-level section at desktop AND mobile plus its meaningful interaction states, assemble contact sheets for fast whole-document review, and keep the native captures for detailed inspection. Every section appears in the evidence set, and every scrollytelling section carries at least one MID-state capture rather than only its initial state (verify each state the section's declared state table promises). This EXTENDS the regression smoke-set rather than replacing it: the smoke-set is the fixed three-shot guard on every iteration, the per-section set is the refinement evidence. Also record the STICKY-LAYER INVENTORY (which layers pin in which scroll context) in the design record and capture a mid-scroll frame for every scroll context containing sticky content, so no content is obscured at the top, middle, or bottom of its scroll range.
    - **Record the evidence trail.** Append to the output's design-record comment, per iteration: which viewports were captured, the findings raised, which were confirmed vs refuted, what changed in response, and (v3.16.7) the per-section density deltas with their content checksum. A reader must be able to tell what was actually looked at.
    - **`--qa-depth` bounds the cost, not the honesty.** `light` = a single grading pass but still ONE REAL RENDER when a browser is available; `standard` = the capped iterative loop (up to 3-4 passes); `deep` = the full per-segment fan-out. Only a browserless host may run structural-only. Scope-first + budget caution: a per-segment fan-out is a 5-15x token multiplier, so calibrate on ONE segment first and confirm before full-scale (cross-link `[[agent-orchestration-primitives]]` for whether a fan-out is warranted and `[[ai-billing-safeguards]]` for the hard caps).
    - **Robust either way (the degradation ladder).** WITH a browser, grade from screenshots (measure band widths and image boxes, compare overlays to the source, confirm integrated imagery). WITHOUT one - only after the provisioning offer was made and declined or failed - degrade to the STRUCTURAL subset (`scripts/visual_qa_score.py` plus a careful markup / computed-CSS read) and state the degradation in one line in the final report. Orthogonally, when Dynamic Workflows are absent the fan-out degrades to isolated subagents, then to a single sequential pass. NEVER hard-fail the run on a missing browser or a missing workflow runtime.

## Common Rationalizations

| Rationalization | Reality |
|---|---|
| "I'll output a slide deck / a slideshow of full-screen slides" | The deliverable is a unique interactive WEBSITE, not a static slide sequence. A one-screen-per-slide deck is exactly the PowerPoint experience this skill moves away from. Build a navigable site. |
| "A static SVG or a screenshot of the chart is good enough" | If a figure carries real data, render it as an INTERACTIVE chart (zoom, pan, toggle series, adjust axes) from inlined JS. A static image throws away the main advantage over the original PDF/PPTX. Static is a fallback only when interactivity is genuinely impossible. |
| "The figure is just a picture, I'll embed it as-is" | A data-bearing figure embedded as a static image throws away the skill's core promise. Classify every image block first per `references/figure-reconstruction.md`; charts and table-images get worksheets and the confidence gate. |
| "I can eyeball the bar heights, close enough" | Unaudited numbers are fabrication even when they look plausible. Fill the read-the-figure worksheet, run the fidelity cross-checks, and state the reading precision - or downgrade the confidence tier. |
| "The chart is blurry, so I'll approximate a nicer version" | Low confidence means the enhanced original (pan/zoom lightbox with a stated reason), never invented data. An honest image beats a doubtful chart. |
| "A tidy uniform thumbnail grid of the images looks cleaner" | A uniform grid erases the source's emphasis. A visual the author made dominant (`page_fraction >= 0.5`, or the sole visual of its section) must stay a hero - render it large / full-width, not a postage-stamp tile beside unrelated cards. Group only genuinely-secondary visuals, and show the native-resolution asset in the lightbox. See "Prominence preservation" in `references/interactive-features.md`. |
| "The content is mostly text, so a clean static page is appropriate" | The deliverable is an interactive site; the minimum interaction budget (scroll reveals, active nav, hover/focus affordances, lightboxes, a signature move) applies to text-heavy content EXACTLY because there are no charts to carry the dynamism. |
| "The user picked comprehensive, but the page flows better short" | The user explicitly chose coverage over brevity; cutting content overrides a recorded choice, which is the exact silent depth decision the verbosity axis exists to remove. Organize a long tail (collapsed regions, grouped appendices) instead of dropping it - and the same holds in reverse: padding a distilled page back out because it "looks thin" ignores the recorded choice too. |
| "Animations are risky, I'll skip motion entirely" | Reduced-motion users get stillness via the `prefers-reduced-motion` guard; everyone else gets intentional motion. Shipping the guarded state as the default for all users is a budget failure, not caution. |
| "I have good taste, I don't need the roll" | Taste converges: unseeded choices repeat the same palette and layout run after run - the exact "same preset, same look" failure the entropy roll exists to break. Roll `scripts/design_seed.py`, then adapt the brief; do not override it back to your prior. |
| "I'll reuse my usual template / house design" | A recognizable fixed look across runs is the templated 'AI-generated' signature `[[hallmark-design]]` rejects. Author a fresh, content-appropriate design each run; honor a caller-specified style when one is given. |
| "I'll start authoring with my usual clean look: dark bg, mono eyebrow labels, amber accent, card grid" | That is the exact default attractor `[[hallmark-design]]` flags as the 'AI-generated' signature, and it makes every run look the same. Brainstorm a fresh, creative direction first and commit to concrete tokens that diverge from it; reach for that look only when the chosen direction or `--style` genuinely calls for it. |
| "The user didn't name a style, so I'll just pick a design and start authoring" | When the flags are absent, ask the four-question design batch (style, output aspect, interactivity, imagery) UP FRONT - in one round, before any extraction - and resolve the choices; only take the content-aware fallback when the batch genuinely cannot be answered (a non-interactive run). Silently choosing for the user removes the choices this skill is meant to offer. |
| "I recall the user preferred style X (or a saved preference), so I'll use that and skip the question" | A recalled preference is NOT consent for THIS run. presentify ALWAYS asks the four choices unless the corresponding flag is named on this command line; a `presentation-style-preference` memory, a prior run, or inferred context never pre-answers one. Ask the batch - do not read a preference memory into the answer. The only non-asking paths are an explicit flag and the non-interactive fallback. |
| "This is a finance report, so it must get a corporate look" | Content character informs the design; it does not dictate it. The goal each run is a unique, creative, interactive result. Let the content shade palette and pacing, but do not mechanically map document type to a fixed style - that reintroduces the sameness the menu and the surprise-me option exist to break. |
| "The label does not fit, so I will rotate it" | Rotated label text is a readability defect, not a space-saving technique - a reader should never have to tilt their head to follow a diagram, and a reviewer reads it as broken on sight. Widen the `viewBox` or wrap onto a second line with `tspan`; both are free, since the SVG scales to its container regardless. Rotation is for a dense axis of many long category labels, never for a single annotation. |
| "Both the nav and the table header are sticky, which is convenient" | Two sticky layers in one scroll context stack up and the lower one covers the content it labels. Allow ONE sticky layer per scroll context, or offset the lower by the upper's height. Verify by scrolling, not by reading the CSS - this is invisible in markup and obvious in a screenshot. |
| "The anchor links work, I clicked one" | They scroll, which is not the same as working. Under a sticky nav an anchor jump lands the section heading UNDERNEATH the nav, so the reader arrives at a section whose title is hidden. One `scroll-margin-top` on the target fixes it; skipping it ships a navigation that appears to mis-target every section. |
| "A roughly-related stock photo is better than an empty section" | It is worse. A loosely-related image reads as padding, and once a reader learns that this page's images are filler they stop looking at ALL of them - including the ones that carry real information. Check relevance before embedding (does it depict the section's subject?), re-query once, then DECLINE with a recorded reason. A declined placement is a normal, frequent, correct outcome; filler is not. |
| "Text over the background image looks readable to me" | Over an image, "looks readable" varies per pixel and per photo, so it is not a check. Composite the mandated scrim (at or above ~82% of the base color) and verify the text against the SCRIM, which is a known color the contrast check can certify. Below roughly 75% the image shows through enough that no static check can certify anything, and the text has to move off the image. |
| "I integrated the images, the design record is just bookkeeping" | The record is what makes a SKIP distinguishable from a MISS. Without it nobody - including you on the next iteration - can tell whether a section has no image because it did not need one or because the pass forgot it. `visual_qa_score.py` therefore fails a consented run that embedded assets but wrote no placement block, and fails a record that claims more assets than the page contains. |
| "I'll call a hosted video model to generate the flight" | Hosted image / video generation is the MCP Registry Policy's generation-as-service Hard-No, and it applies to a vendor CLI exactly as it does to an API. A cinematic build uses user-supplied clips, Tier 1 procedural stills, consent-gated license-free stock, or LOCAL AI stills as posters - and it never prints a paid generation command for the user to run either. |
| "I'll ship the clips as sibling .mp4 files next to the HTML" | Then it is not a self-contained output, and the offline single-file guarantee is this skill's whole delivery contract. Clips load from `data:` URIs or Blob object URLs. If that makes the page too large, the answer is fewer or shorter clips - or stills-only - not a second file. |
| "The content is thin, so I'll invent a brand journey for the cinematic sections" | Cinematic is PRESENTATION over the sections the document already has. Inventing a narrative turns presentify into a different product - one that authors a new story rather than presenting an existing file - and that boundary is what keeps this a level of `/presentify` instead of a fork. Thin content is a reason to decline cinematic, not to fabricate. |
| "Cinematic suits this content, so I'll just build it under rich" | Under `rich` it is PROPOSED, priced, and confirmed - never silently selected. The size / cost gate exists because these assets are the largest thing this skill embeds, and a reader who asked for `rich` did not agree to a 15 MB file. Present the estimate and get a yes. |
| "The diagram looked right in my head / in the code" | Authored SVG coordinates are unchecked code. A curve whose midpoint you never computed can sit exactly under the label you thought was clear of it, and a hand-placed triangle you eyeballed into position detaches the first time a node moves. Run the numeric geometry self-check in `references/svg-diagram-quality.md` rule 5: evaluate the curve, confirm every coordinate is inside the viewBox, and confirm every marker reference resolves. |
| "A hand-drawn triangle is simpler than declaring a `<marker>`" | It is simpler to write once and broken thereafter. The triangle is an independent object that only happens to sit near the line's end; any change to the geometry leaves it behind, which is how a loop-back arrow shipped visibly in pieces. A marker is positioned BY the path, so it cannot detach - and one definition serves every connector. |
| "The pinned graphic is a bit tall, the reader can scroll to the rest" | They cannot: the container is `position: sticky`, so it does not scroll with the content. Anything past the bottom edge of the sticky slot is unreachable by any user action for the whole section. Cap it with `max-height` against the sticky offset and confirm every node is visible at once. |
| "The clamp() minimum only hits on tiny screens, so a small font is fine there" | The minimum IS the rendered size on the most common laptop widths. A `clamp(0.7rem, ...)` is still pinned at 11.2px at 1366px, which is where most readers are - not an edge case for phones. Check every floor at BOTH the clamp minimum and 1920px per `references/responsive-typography.md` rule 4. |
| "The type scale is fluid - I put the clamp() on `body`" | `rem` resolves against the ROOT element, not `body`, so a `clamp()` on `body` never reaches a `rem`-sized child: every one of them silently falls back to the 16px browser default and the scale is fluid in exactly one rule. This shipped an 11.2px footer heading under a correct-looking `body` declaration. Declare the scale ONCE as `:root` custom properties and reference step tokens. |
| "The `<code>` tokens use the mono family, so they already stand out" | One axis is not enough. A muted `<code>` that only changes family reads as prose at a glance - that is how a command name became invisible inside a margin note. Tokens need BOTH a color step (AA-checked) AND a family or weight change. |
| "I'll keep the page in one tidy centered column so the text stays readable" | The 45-85 character reading measure is for body PROSE only. Applied as a page-wide width it starves headings, hero text, and charts, and produces the broken look of a narrow text column beside full-width cards. Use the viewport width on purpose: per-element measures, with full-bleed and multi-column zones where they fit. |
| "The user chose full-width, but I'll keep one tidy centered column so it's safe" | At full-width a centered column with empty side margins is a DEFECT, not caution: it is the exact bug the full-width contract exists to catch (a page that only looks right at 200% browser zoom). Honor the "Output aspect (the canvas)" full-width contract: the shell spans the viewport via gutters, top-level bands are full-bleed, and the widest band reaches at least ~95% of a 1920px viewport. |
| "I'll just inline a CDN chart library (Chart.js, D3, Plotly) for interactivity" | A CDN reference breaks the offline guarantee and leaks a network request. Build interactivity from inlined vanilla JS with no external library. A CDN font or script is the same failure. |
| "I'll skip extraction and just eyeball the PDF / paste the slides" | Eyeballing loses tables, data series, speaker notes, and ordering, and is not reproducible. Run `scripts/extract_content.py` so the content model captures the structure the eye skips - and the real numbers your charts must use. |
| "The deterministic builder's output looks fine, I'll ship that" | `build_presentation.py` is an OPTIONAL plain draft (static SVG, fixed layout); it does not meet the interactive-website bar. It is a starting point to elevate, never the final deliverable. |
| "I'll embed the brand's web font via @import for the real look" | An `@import` of a font CDN is an external request that breaks offline. System font stacks only; a custom font must be base64-embedded as `@font-face`, never fetched. |
| "Multiple sources, I'll merge them into one smooth narrative" | Compiling sources requires per-source attribution: each source is a labeled, attributed area. Blending two sources into an indistinguishable middle loses the provenance the multi-file mode exists to preserve. |
| "A missing parser library means I should hardcode an import or vendor it" | Every parser is lazy-imported on purpose so one missing library never blocks the others. If extraction reports `pip install <lib>`, install it; do not move imports to module top level or bundle a parser. |
| "The page looks bare without photos, I need stock images" | Tier 1 procedural visuals plus editorial typography, layout, color, and restraint ARE the professional / journalistic look - most of that quality needs no external image at all. Author original SVG / CSS backgrounds, editorial devices, and thematic textures; reach for the stock / AI tiers only on explicit opt-in, never to rescue a page you have not yet designed. |
| "I'll just hotlink a stock image for speed" | A hotlinked image is an external network request that breaks the offline guarantee, and it records no license or attribution. Every non-procedural asset is fetched at BUILD time, base64-embedded into the output, and recorded in the credits with a free-for-commercial-use license. A `src="https://..."` on any visual is the same offline failure as a CDN font or script. |
| "Richer interactivity is always better, so I'll add scrollytelling everywhere" | RESTRAINED is the CREDIBLE default for a report or white paper, where scroll-driven motion reads as gimmicky; BALANCED fits a deck or data story; RICH scrollytelling is for a genuine narrative. Match the level to the content, and remember every effect must degrade to a static, linearly-readable form under `prefers-reduced-motion` - so rich motion is never load-bearing. |
| "The stock fetch is convenient, I'll just run it without asking for consent" | The Tier 2 outbound path is opt-in AND consent-gated by policy: run `fetch_stock_media.py` only with `--consent` after the user chose the `stock`/`ai` tier and confirmed the build-time network use. Without both, the default is offline (Tier 1). The helper enforces this - no `--consent` means no network - but the pipeline must not paper over the gate by always passing the flag. |
| "For AI images I'll just call a hosted image API (DALL-E / Midjourney / hosted SD), it's easier" | That is generation-as-service, a policy hard-no. Tier 3 is LOCAL generation only, via `generate_local_image.py` (diffusers + local weights, or a configured local CLI); the helper imports no hosted-API client and makes no network call. If no local runtime is present, degrade to Tier 1 - never reach for a hosted generation endpoint. |
| "One render pass is enough; I looked and it seems fine" | A single render-and-glance is the OLD Step 9, and it is exactly what let the four observed defects (non-full-width canvas, ballooned / cropped images, dropped map overlay, zero stock integration) reach production. Step 9 is an ITERATIVE loop: grade against the rubric, fix, re-render, and repeat until the page-level bar holds or the cap is hit. |
| "I'll grade the whole page at once instead of per segment" | Whole-page grading has a high miss rate: a ballooned image in one band or a dropped overlay in another hides in an overall "looks ok". The rubric is graded PER SEGMENT against each segment's SOURCE, then rolled up; that is why the four defects are caught. |
| "The per-segment fan-out is expensive, so I'll skip the verification step" | Scope-first calibration and the `--qa-depth` knob exist precisely to BOUND the fan-out cost, not to skip the gate. Calibrate on one segment, confirm, then scale; degrade to a single sequential pass or the structural scorer when the runtime is thin. Skipping verification ships the defects the loop exists to catch. See `[[ai-billing-safeguards]]`. |
| "No headless browser here, so I'll skip visual QA" | Degrading is the LAST resort, not the first. Run `scripts/ensure_render_env.py` and OFFER the one-time provisioning before you degrade at all - a missing browser is usually one consented command away, and the install is a per-host setup, not a per-run cost. Only after that offer is declined or fails does the loop fall back to the STRUCTURAL scorer plus a markup read (a "structural-only" pass), and then the degradation MUST be disclosed in the final report. It never SKIPS the gate. |
| "The structural checks all passed, so the page is visually fine" | The structural scorer certifies what a parser can see: declared sizes, declared colors, declared spacing, marker wiring. It cannot see what the page PAINTS. This repo's own history is the proof - three browser-dependent checks silently skipped for four minor versions, and five sub-AA accent colors passed the contrast check because a script assigned them at runtime. A structural pass with no render is a weaker gate, and it must be labelled "structural-only" rather than reported as a visual pass. |
| "I rendered once and the findings looked minor, so I'll report them and stop" | Findings-to-fix-to-re-render is mandatory until no HIGH-severity finding remains or the `--qa-depth` cap is hit. One grading pass is not the loop; it is the first iteration of it. Reporting a defect you could have fixed and re-verified hands the user work the loop exists to do. |
| "I only touched the map section, so I only need to re-render the map" | Change-local verification cannot see cross-component damage - a generic CSS class or a shared JS hook breaks a section nobody re-looks at, with zero console errors. Every re-render pass captures the regression smoke-set (hero at load, one divider mid-scroll, one chart), including post-delivery edits. |
| "`.pin` / `.card` / `.tip` are obvious names for this component" | Bare generic class names are how two components collide: a later feature's `.pin{width:14px}` once shrank the cinematic stage's `.pin` wrapper to a strip. Namespace every authored component's classes (`.map-pin`, not `.pin`). |
| "The series doesn't fit the axis, so I'll cap it at y-max" | A flat-topped bar drawn at the axis maximum reads as a real value - that is fabricated data, not layout pragmatism. Start mixed-scale context series hidden and auto-refit the axis on legend toggle so every drawn point is true. |
| "The scroll effect will reveal the title once the user scrolls" | The reader has not scrolled yet on first paint - a hero that loads at 25% opacity is a broken page, not anticipation. Scrub effects fade content OUT on the way out; the load-time state is fully legible. |
| "The source says 'xx subjects' - I'll estimate the real number from the other slides" | A placeholder the author left unfilled is not yours to fill. Detect it at extraction, ask the user in Round 2, and if it ships, render it faithfully with a visible note. |
| "The source is a draft, so a section on what it got right and wrong is useful" | Only if the reader has seen the draft. Under the `standalone` default they have not, so a critique section addresses someone who is not in the room and spends the reader's attention on an invisible document. Transformation and critique are different tasks; resolve `source_relationship` before authoring. |
| "Agents make this fast, so the timeline is short regardless of the target" | Agent speed changes the execution RATE, not the target boundary. A working demonstration, a decision-grade pilot, and a reusable platform differ by an order of magnitude, and the reader is choosing between them. Name the `scope_class` on every visible timeline, with at least three planning assumptions. |
| "The user's premise is a bit optimistic, I should open by flagging it" | An `accepted` premise is part of the task contract. Opening a section by rebutting a position the user never took argues with the reader instead of helping them, and it happened: a page led its regulatory section with "uploading documents is not enough" when the user's own premise already included extraction and verification. Build from the premise; challenge one only with evidence AND the decision consequence. |
| "Everyone understands an iceberg, it makes the cost point instantly" | It makes a visible-versus-hidden point, which is only the right point when that split IS the decision. When the reader is comparing three options across repeated criteria, an iceberg cannot show the comparison at all and a matrix can. Choose the visual by the decision shape, not by familiarity. |
| "Showing our method in the hero builds trust" | It spends the hero on the author's process rather than the reader's question. "Primary-source review" and "Original preserved" are production bookkeeping; every hero element must answer What is this, Why should I care, or What is the conclusion. Provenance belongs in the method section, the sources appendix, or the design record. |
| "Attribution has to be permanently visible to count" | It has to be REACHABLE, which is not the same thing. A permanent credit box competes with the title for the reader's first second; hover plus keyboard focus plus a touch route plus the credits section is fully accessible AND unobtrusive. Hover alone is the failure, not disclosure itself. |
| "The visual looks impressive, that is its job" | Its job is to make a relationship easier to understand than prose alone. An orbit diagram once rendered, sized, contrasted, and painted correctly while explaining nothing about the workflow it decorated - and passed every criterion, because they all grade execution. Apply the subtractive test: remove it, and if the section loses nothing, redesign or omit it. |
| "A narrower measure is always more readable" | The 45-85 character measure belongs to long-form prose, and applying it to display text produces the opposite of readability: a `32ch` cap once stranded a Highlights answer in 54% of its column, which reads as broken. Assign width by text ROLE, and let display text use its track. |
| "A full-viewport section looks intentional and premium" | On a short section it looks like a slide deck with an empty lower half, which is the format this skill exists to move away from. A universal `min-height: 82svh` passes the fluid-spacing check (it IS viewport-relative) while being exactly wrong. Height is earned by content or by a named interaction; if removing the rule only removes whitespace, it was never earned. |
| "The screenshots look fine, I do not need the numbers" | Screenshots reveal that a layout feels wrong; computed metrics explain why, and only the metrics locate it. "The hero looks cramped" became actionable as "the hero title uses 58% of its column across three lines". Line count, width utilization, orphan detection, and rectangle intersection cost one `page.evaluate()` and end an argument a screenshot only starts. |
| "The structural and behavioral checks are green, so QA passed" | Those are layers 3 and 4 of four. Layers 1 and 2 (content intent, semantic visual) ask whether the artifact serves its reader's decision, and a page can pass every technical gate while addressing the wrong audience with an oversized estimate - one did. A final pass requires all four layers, which is why the rule is binary. |

## Verification

Binary checklist - each item describes an observable artifact or state.

- [ ] The output `.html` exists at the requested path and opens in a browser.
- [ ] Opening it issues ZERO external network requests (DevTools network tab is empty, or `grep -Ei 'https?://|cdn' out.html` finds nothing outside comments).
- [ ] The output is a navigable WEBSITE (an overview plus section navigation that works), not a static one-screen-per-slide deck.
- [ ] Every figure with real data renders as an INTERACTIVE chart: zoom / pan, series toggle via the legend, and axis adjustment all respond - and the numbers match the source.
- [ ] Every image block in the model carries a `classification` (scanned-page blocks went through the transcription/verification pass instead), per `references/figure-reconstruction.md`.
- [ ] Every reconstructed chart has `provenance: "reconstructed-from-image"`, a `confidence` tier, an embedded worksheet comment, and a working view-original toggle; NO reconstructed chart exists whose numbers lack a worksheet.
- [ ] Low-confidence figures appear as enhanced originals (pan/zoom lightbox) with a one-line reason - never as reconstructed charts.
- [ ] All OCR-provenance numeric content was verified against the page image; content OCR missed was transcribed as `provenance: "agent-read"` blocks.
- [ ] The coverage reconciliation ran and is embedded as an HTML comment: every visual in the model's `coverage` manifest is accounted for as rendered, reconstructed, or skipped-with-reason - verdict ACCOUNTED with 0 unaccounted.
- [ ] Data fidelity holds: every chart in the output traces to `source-data` / `native-chart` provenance or to an embedded worksheet; no chart exists with neither.
- [ ] Visual provenance holds: every added visual carries provenance (Tier 1 = "original (generated)"; Tier 2 = source + URL + license + attribution; Tier 3 = model + license + the "AI-generated; may not be copyrightable" note) in an adjacent HTML comment, and every NON-ORIGINAL visual appears in the visible "Image credits" section with a free-for-commercial-use license and any required attribution; no visual lacks provenance. See "Visual provenance and credits" in `references/interactive-features.md`.
- [ ] For a Tier-2 (stock) run: every fetched asset is base64-embedded (no `src="https://..."` on any visual), verified as a free-for-commercial-use license, and credited; a run lacking the `stock`/`ai` choice AND explicit consent made NO network call (the helper degrades on missing `--consent`); and the assembled output greps clean for external references (zero external requests even with stock images).
- [ ] Integration gate (consented `stock` / `mix` / `ai`): the build-time consent was captured UP FRONT in the batched design round (Step 2), not as a separate mid-run prompt; and EACH image-starved section either received at least one relevant, license-verified asset OR carries a recorded per-section reason. A consented `stock` / `mix` run that integrated ZERO assets across all starved sections with NO recorded reason FAILS (silent zero-integration is the exact defect being fixed).
- [ ] For a Tier-3 (ai) run: every AI image carries the model + license + the "AI-generated; may not be copyrightable" caveat in its provenance and the credits section; the generation was LOCAL (no hosted-API call - `generate_local_image.py` imports no network / hosted-API client), the image is base64-embedded, and the output is offline; when no local runtime was present the run degraded to Tier 1.
- [ ] The minimum interaction budget passes, all five points observable: the section nav tracks the active section while scrolling; scroll reveals fire (or the equivalent scroll-responsive treatment responds); cards, images, and table rows respond to hover AND keyboard focus; every non-decorative image opens in the pan/zoom lightbox (Escape closes, focus returns); and the run's signature interaction works.
- [ ] No `data_uri` payload entered the agent's context: the model was inspected through the length-projection in Step 3 and the generated `.html` was verified by `grep` and the bundled scripts, never read back wholesale.
- [ ] The page was written once, in the output space; no complete draft of it was composed in reasoning first (the Step 6 output-budget rule).
- [ ] The interaction layer is within budget: ~60 KB or less of added inline JS (excluding chart controllers and base64 payloads), zero external requests, all motion guarded by `prefers-reduced-motion`.
- [ ] Every source section from the content model is represented; embedded images display from inline `data:` URIs.
- [ ] Prominence preserved: every visual dominant in its source (`page_fraction >= 0.5`, or the sole / primary visual of its section) renders as a hero (full-width band or wide column), NOT a uniform thumbnail; only genuinely-secondary visuals are grouped into a legible gallery; the lightbox shows the native-resolution `data_uri`, never an upscaled thumbnail.
- [ ] Spacing / density holds: no section is left half-empty; sparse sections are compacted or paired with a related element, not floated in whitespace.
- [ ] The output is built to the resolved output aspect (full-width / standard / portrait / other), and that aspect (with any content-aware auto-pick note) is recorded in the design-record HTML comment.
- [ ] The resolved imagery tier (procedural / stock / ai / auto / none) and interactivity level (restrained / balanced / rich), with any content-aware auto-pick note, are recorded in the design-record HTML comment.
- [ ] The resolved coverage-depth (verbosity) level, its provenance (`flag-preset` / `asked` / `defaulted`), and the derived section-count target are recorded in the design-record HTML comment, and the built page's section structure matches the recorded level (graded by the rubric's coverage-depth criterion).
- [ ] A Tier-1 (procedural / default) run made no fetch or generation: the output carries only inline SVG / CSS and base64 `data:` visuals, and grepping for external `http(s)` / `cdn` outside comments finds nothing (the default and every non-interactive run stay offline).
- [ ] The design is bespoke for this run (not a recognizable fixed template), leads with creativity / interactivity / uniqueness, and any caller-specified style or color scheme is applied.
- [ ] The four design choices (style, output aspect, interactivity, imagery) were resolved UP FRONT in a single batched round BEFORE extraction: when no flag was named, the five-option style menu (Corporate / Creative / Technical / surprise-me / other) plus the aspect / interactivity / imagery choices were offered together and resolved - or the content-aware fallback was used because the batch could not be answered; each named flag (`--style` / `--theme` / `--layout` / `--interactivity` / `--images`) bound and dropped its question.
- [ ] No recalled memory or saved preference pre-answered any of the four choices: with no flags AND a style / design-preference memory present in context, the four-question batch was still presented and the memory did NOT pre-fill or skip a choice (only an explicit flag or the non-interactive fallback skips a question).
- [ ] A design-direction record (named direction plus concrete color / font / spacing / motion tokens) is embedded as an HTML comment and was stated to the user, and it diverges from the default dark / mono-label / amber / card-grid attractor unless the chosen direction or `--style` called for it.
- [ ] The design record includes the entropy roll's seed and one-line brief summary, and the committed tokens match the brief's axes (hue family, base variant, type voice, layout signature, motion, signature move) - or the record states the no-Python manual-variation fallback was used.
- [ ] The run's brief was committed to the design history (`design_seed.py --commit`), so the history file gained an entry - or the fallback note explains why not.
- [ ] The layout uses the viewport width on purpose: headings and hero / display text are not trapped in the body reading measure, and the 45-85 character measure is scoped to long-form prose only.
- [ ] Motion is purposeful and `prefers-reduced-motion` is honored; the layout is responsive.
- [ ] At the RICH interactivity level, every scrollytelling effect (pinned / sticky graphics, image-to-text transitions, parallax, timeline, before/after slider) degrades to a static, linearly-readable form under `prefers-reduced-motion: reduce` - parallax is disabled entirely, not merely shortened - and no content is gated behind the scroll effect.
- [ ] In single-source mode the content order matches the source; in multi-source mode each source is a labeled, attributed area.
- [ ] The HTML is well-formed (tag balance) and ASCII-safe, and it clears the `[[hallmark-design]]` anti-slop gates.
- [ ] On a CINEMATIC run per `references/scroll-scrub.md`: the design record notes whether cinematic came from an explicit choice or a CONFIRMED rich-level proposal; the size / cost estimate was stated and a go / no-go obtained BEFORE any asset was generated or embedded; no hosted generation service was called and no vendor generation command was printed; every asset is embedded and the delivered `.html` makes zero network requests; and under `prefers-reduced-motion: reduce` NO video element is created, verified by emulating the preference rather than by reading the code.
- [ ] The render environment was PROBED before the Step 9 loop (`python scripts/ensure_render_env.py`), and if it reported a non-ready state the user was offered the one-time provisioning ONCE, up front - not silently skipped.
- [ ] The Step 9 loop RENDERED the output at 1920x1080, 1366x768, and 390x844 plus the interaction states (mid-scroll reveal, open lightbox, chart interaction, pinned-graphic mid-scroll), OR the final report carries the one-line degradation note stating that no browser was available and the grade is structural-only. One of those two is present - never neither.
- [ ] The evidence trail is in the design-record comment: per iteration, the viewports captured, the findings raised, which were confirmed vs refuted, and what changed.
- [ ] On a consented `stock` / `ai` / `both` run, the design record carries an `IMAGERY PLACEMENTS` block with one decision per section - each either a role plus a reason, or `none: <reason>` - and `scripts/visual_qa_score.py --expect-images <n>` reports no `imagery-integration` finding. On a `none` / non-consented / non-interactive run, no placement block is expected and none is required.
- [ ] Every authored inline SVG diagram holds `references/svg-diagram-quality.md`: `python scripts/visual_qa_score.py <out.html>` reports NO high-severity `svg-arrowhead`, `svg-viewport-fit`, or `svg-marker-integrity` finding, and the numeric geometry self-check passed (every coordinate inside the viewBox, every marker reference resolving, each dashed path's computed midpoint clear of its label's box, connector endpoints matching the joined boxes' edge expressions).
- [ ] The fluid-layout and readability contract holds per `references/responsive-typography.md`: `python scripts/visual_qa_score.py <out.html>` reports NO high-severity `fluid-spacing`, `font-floor`, `emphasis-token`, or `contrast` finding - no fixed macro spacing on a band or grid container, every font size clearing its 16 / 13 / 12px role floor at both the clamp minimum and 1920px, inline tokens distinct on both the color and the family/weight axis, and every ink / accent pair clearing WCAG AA on the surfaces it is used on.
- [ ] The iterative visual-QA loop (Step 9) ran and CONVERGED: the page was rendered and graded PER SEGMENT against `references/visual-qa-rubric.md`, high-severity findings were adversarially verified, fixes were synthesized and re-rendered, and the loop reached the page-level pass bar (no open high-severity finding) within the iteration / budget cap - or it recorded a bounded, explained non-pass. When no headless browser was available it degraded to the structural scorer + markup review with a one-line "structural-only" note (never a hard fail); when Dynamic Workflows were absent the fan-out degraded to subagents or a single sequential pass.
- [ ] Full-width band metric (Phase 1): at a full-width run, the widest top-level content band measured >= ~95% of a 1920px viewport with no global zoom (`scripts/visual_qa_score.py` full-width criterion passes).
- [ ] Image sizing (Phase 2): no hero exceeds ~80vh, no secondary balloons past a hero, no meaningful content is cropped, and no image band leaves dead space beyond the ceiling (caps present + rendered boxes within them).
- [ ] Annotation-overlay fidelity (Phase 3): every annotated source figure reproduced its regions + labels as a registered overlay over the base image (not a flat image beside a text list), OR a low-confidence figure correctly shipped the enhanced original + textual complement with no fabricated regions.
- [ ] Imagery-integration gate (Phase 4): a consented `stock` / `mix` / `ai` run integrated at least one relevant, license-verified asset into each image-starved section OR recorded a per-section reason; a consented run that integrated zero assets with no reason FAILS.
- [ ] No authored interactive component uses a bare generic class name: every component class carries its prefix (`.map-pin`-style), and no selector collision exists with the structural wrappers (`.stage`, `.pin`, section shells).
- [ ] Every re-render iteration (including post-delivery edits) captured the regression smoke-set - hero at load, one divider mid-scroll, one chart - and the painted-canvas probe passed for every JS-painted canvas (clientWidth ~ container width, non-blank pixel sample).
- [ ] No chart silently clamps a drawn value at its axis maximum: mixed-scale context series start hidden and legend toggles auto-refit the axis.
- [ ] The hero and every section's load-time state render fully legible before any scrolling (no scrub ramp starts content dimmed or invisible).
- [ ] Every source placeholder the extractor flagged (`placeholders` in the model) was surfaced to the user; any that ship render faithfully with a visible note, never a fabricated value.
- [ ] The design record carries a `content_intent` block with `source_relationship`, `decision_to_enable`, `assumptions` (each classified), `scope_class`, and `exclusions` - and Gate A ran against it BEFORE visual authoring.
- [ ] Under the `standalone` relationship, the visible output contains no "the original" / "the prior draft" / "what was right" / "what was wrong" / "original preserved" phrasing that the subject matter does not independently require, and no internal production metadata.
- [ ] No section heading or lead sentence negates an `accepted` assumption; any challenged assumption carries stated evidence and its decision consequence.
- [ ] Every visible timeline names its `scope_class` and at least three planning assumptions; no bounded pilot carries a reusable-platform estimate.
- [ ] Where the output compares a named subject with alternatives, a subject-capability summary PRECEDES the comparison, and a first-time reader can state the subject's role from it alone.
- [ ] The hero holds the content budget (at most one context label, title, framing question, and answer) and carries no production notes, preservation labels, or workflow history.
- [ ] Image credits are unobtrusive on load AND reachable by mouse, keyboard focus, and touch, and the full attribution appears in the credits section.
- [ ] A hybrid or multi-system recommendation ships responsibility lanes: one primary owner per activity, and a visible review point for every system-generated conclusion of regulatory or financial significance.
- [ ] Every major visual has a recorded `visual_contract` (question, message, encoding, states, trigger, fallback, evidence), survived the subtractive test, and passed Gate B before detailed styling; every scrollytelling section declares a state table and Step 9 verified each declared state.
- [ ] The composition probes ran at every required viewport: no desktop display heading above two lines without a recorded wrap plan, no display-text block under 70% of an otherwise empty track, no avoidable one-word orphan, no `content-height` section with a viewport-height minimum, and no text-graphic rectangle intersection where the regions must stay separate.
- [ ] Per-section desktop and mobile screenshots exist for every top-level section (plus a mid-state capture for every scrollytelling section), the sticky-layer inventory is recorded, and the evidence trail carries the per-section density deltas with a content checksum showing nothing was lost.
- [ ] All FOUR QA layers ran (content, semantic-visual, structural, behavioral). A page whose structural and behavioral layers alone are green does NOT receive a final pass.
- [ ] `make validate` passes (orphan-bundle audit clean, JSON integrity green).

"The site looks nice" is not a verification criterion. The verification is: does it open offline with no external requests, is it a navigable interactive website (not a deck), are the charts genuinely manipulable on real data, and does it clear the hallmark-design gates.

## Bundled Resources

The skill ships a Tier-3 bundle; load each file on demand rather than inlining it here.

- `scripts/extract_content.py` - the local, lazy-import multi-format extractor (PDF / Word / Excel / PowerPoint -> content-model JSON).
- `scripts/build_presentation.py` - the OPTIONAL deterministic baseline builder (content model + template + theme -> one self-contained plain `.html` with static inline SVG charts). A convenience draft to elevate, not the default path; the primary deliverable is the LLM-authored unique interactive site.
- `scripts/design_seed.py` - the seeded, history-aware design-entropy sampler (stdlib-only): rolls the per-run design brief from preset-constrained axis pools, rejects candidates too close to the last 3 committed runs, and appends used briefs to the persisted history via `--commit`.
- `scripts/fetch_stock_media.py` - the OPT-IN, consent-gated Tier-2 stock-media fetcher (lazy-import `requests`, stdlib `urllib` fallback): turns content-derived keywords into license-verified, base64-embedded assets plus a credits manifest from Openverse (default) / Wikimedia / Pexels. Makes NO network call without `--consent`; degrades to Tier 1 on any missing library / key / network error / zero results.
- `scripts/generate_local_image.py` - the OPT-IN, LOCAL-ONLY Tier-3 AI image generator (lazy-import `diffusers` + `torch`, or a configured local CLI via `NEXUS_LOCAL_IMAGE_CMD`): generates an image from a content-and-style prompt with a commercially-clean local model (FLUX.1 schnell / SDXL), base64-embeds it, and records model + license + the copyright caveat. Makes NO network call and imports no hosted-API client (forces offline mode before importing the runtime); degrades to Tier 1 when no local runtime / weights are present.
- `scripts/fit_map_projection.py` - the landmark-anchor projection fitter for the geo-pin overlay path (`references/figure-reconstruction.md` part 5, path 2b): fits a quadratic (or affine) lat/lon -> pixel transform from landmarks read off the map image, prints per-anchor residuals, and emits a paste-ready JS `projPct()`. Stdlib-only, no network.
- `scripts/visual_qa_score.py` - the deterministic STRUCTURAL scorer for the Step 9 visual-QA gate (stdlib-only, no network): scores a generated `.html` against the structural subset of `references/visual-qa-rubric.md` (full-width band, image caps, overlay well-formedness, imagery-integration count, offline / layout integrity) and returns per-criterion findings plus the binary page-level pass bar. The headless-optional structural-review path the loop degrades to when no browser or agent vision is available.
- `references/content-intent.md` - the content brief Step 5 resolves and Gate A grades (source relationship, decision to enable, the assumption ledger, the scope classes), the decision-brief authoring rules Step 6 holds (explain before comparing, Highlights that answer, decision-shaped comparison visuals, responsibility lanes, the hero budget, accessible credits, reader-centered competitor criteria), and the visual contracts plus scrollytelling state tables Gate B grades. The layer that decides whether the page was worth building, as distinct from whether it was built correctly.
- `references/content-model.md` - the normalized content-model schema; the stable contract between the extractor and the builder.
- `references/extraction-runbook.md` - per-format coverage, library + `pip install` lines, gotchas, the base64 image budget, determinism, the two-tier scanned-page OCR path, and the out-of-scope list.
- `references/figure-reconstruction.md` - the figure classification taxonomy, the read-the-figure worksheet, the fidelity cross-checks, the confidence gate, map/diagram rules, the model round-trip, and the scanned-page transcription/OCR-verification pass (Step 3).
- `references/interactive-features.md` - the interactive feature catalog, the full-width canvas contract, the image-sizing rules, the imagery tiers with the image-starved-section detection + integration gate, the theme-override path, and the enrichment pass tied to `[[hallmark-design]]` and the three input modes.
- `scripts/ensure_render_env.py` - probes the local headless-render environment the Step 9 loop needs (importable Playwright with a launchable chromium, then a local Chrome/Edge it can drive), exiting with a distinct code per state and printing the exact one-time provisioning commands. It NEVER installs without `--install`; its whole purpose is to make a degraded render environment EXPLICIT instead of silent.
- `references/scroll-scrub.md` - the OPT-IN cinematic protocol: when it applies, job fidelity (present the document, do not invent a brand), the size / cost gate, the asset boundary (no hosted generation, no sibling files), the seam and pacing rules, the stills-only fallback, and the accessibility floor.
- `assets/scroll-scrub-engine.js` - the zero-dependency scroll-scrub engine implementing that protocol: `data:` / Blob clip loading so the output stays one file, seam crossfade, per-section scroll + linger, mobile seek-coalescing, iOS priming, and a stills-only path that creates no video element under reduced motion. Adapt it; do not paste it.
- `references/slide-navigation.md` - the `nav=slides` authoring contract Step 6 builds to when the design record says slides: the 100svw x 100svh stage and safe-area sizing, the binary overflow-split rule (continuation slides, never an undeclared inner scrollbar), the full input map with the transition queue/fast-forward rule, idempotent fragment stepping, `#slide-<n>` deep links and history, the inert / live-region / focus accessibility contract, the no-JS stacked fallback and one-slide-per-page print rule, and the slide-mode expression of the five-point interaction budget.
- `references/responsive-typography.md` - the fluid-layout and readability contract Step 6 authors to: viewport-ratio macro spacing, viewport-serving wrapping, the tokenized fluid type scale, the hard rendered-size floors (16 / 13 / 12px), the two-axis emphasis-token rule, and the validated contrast floors.
- `references/svg-diagram-quality.md` - the authored-SVG integrity contract Step 6 holds: marker-based arrowheads that cannot detach, dash patterns clear of labels, connectors terminating on node edges, viewport-fit for pinned graphics, and the numeric geometry self-check.
- `references/visual-qa-rubric.md` - the per-segment grading rubric the Step 9 loop scores against (full-width, image-sizing, annotation-fidelity, imagery-integration, readability-layout), with the structural-vs-agent-vision split, the per-segment score schema, and the binary page-level pass bar.
- `assets/presentation-template.html` - the self-contained offline scaffold (all CSS/JS inline, no external requests) the builder populates.
- `assets/theme.json` - the default theme tokens the template reads, overridable via `[[theme-tokens]]` / `[[brand-styling]]`.
- `assets/visual-qa-workflow.js` - the Dynamic-Workflow TEMPLATE (adapt, do not run verbatim) that fans the per-segment visual-QA grading out (grade -> adversarially verify -> synthesize fixes -> re-render), carrying the three mandatory workflow rules (graceful degradation to subagents / a single agent and to the structural scorer; scope-first token caution; skill-native, no outbound call).
