# Continuous Learning

Teach the agent to harvest its own session for patterns: capture observations to a local JSONL, mint atomic instincts as YAML, and evolve clusters of instincts into draft skills or commands - all in-session, on demand, with no background process and no outbound network calls.

This is the local-only reverse-engineered subset of ECC's `continuous-learning-v2` pattern. See `docs/v2.2.0/comparison-ECC.md` Section 11 Bucket B (B4) and Section 13 ("Continuous-learning egress trap") for the policy framing. The capture half is the `learning-capture` hook; this skill is the analysis half.

## When to Use This Skill

Use when:

- The user explicitly asks to "learn from this session", "promote that to an instinct", or "draft a skill from these observations".
- The user has corrected the agent multiple times in the same direction (e.g., "no, don't run the tests inline, batch them") and the right next move is to record a durable rule.
- A multi-task session is wrapping up and there are patterns worth distilling before the context is lost.
- The user asks "what should we automate" or "what patterns are we seeing" in the recent work.

**When NOT to use:**

- Single-session todo tracking - use [[dev-progress-tracker]].
- One-off facts the user wants the agent to remember for one turn only - the agent's own working memory handles that.
- Any flow that wires a background observer model, uploads observations off-device, or shares them across projects. This is OUT OF SCOPE; see the Common Rationalizations table.

## Storage Layout

All artifacts are project-scoped and live under `.nexus/` relative to the git root (or cwd when not in a repo). Nothing crosses project boundaries.

| Path | Written by | Read by | Lifecycle |
|---|---|---|---|
| `.nexus/observations.jsonl` | `learning-capture` hook (Stop, UserPromptSubmit) | This skill, in-session | Auto-truncated at 1 MiB (keeps last half). |
| `.nexus/instincts/<slug>.yaml` | This skill | This skill + manual review | Persistent; user prunes manually. |
| `.nexus/instincts/_index.md` | This skill | Humans | Regenerated by this skill on demand. |
| Draft `SKILL.md` / command files | This skill | Maintainer for review | Land under `catalog/...` only after review. |

## Instructions

### 1. Observe (passive)

The `learning-capture` hook is already wired in `catalog/hooks/settings.json` for `UserPromptSubmit` and `Stop`. Each event appends one JSON line:

```json
{"ts":"2026-05-28T12:34:56Z","event":"UserPromptSubmit","tool":"","prompt_sample":"..."}
```

No agent action is required here. The hook silently no-ops when `NEXUS_LEARNING_CAPTURE=off` or `NEXUS_HOOK_PROFILE=minimal`.

### 2. Survey (on-demand, in-session)

When invoked, read `.nexus/observations.jsonl` (Read tool, or Bash `wc -l` + `tail` for size triage). Look for:

- **Repeated user corrections** in the same direction.
- **Tool-use patterns**: the same tool sequence appearing across multiple turns.
- **Pain-point prompts**: phrasing like "stop", "no", "actually", "instead", "you keep" that signals friction.

Report the top 3-5 candidate patterns to the user in one short paragraph each, with the supporting observation timestamps.

### 3. Mint an instinct

For each pattern the user confirms, create one atomic YAML file at `.nexus/instincts/<short-slug>.yaml`:

```yaml
slug: prefer-batched-test-runs
created: 2026-05-28
confidence: 0.6     # 0.0 (single observation) -- 1.0 (consistent across many sessions)
domains: [testing, workflow]
trigger: "user asks for tests + edits before"
behavior: "batch test runs after the last edit in a cluster, not inline per edit"
evidence:
  - "2026-05-28T11:02Z: user said 'just run them once at the end'"
  - "2026-05-28T11:45Z: user said 'why are you re-running pytest after every edit?'"
notes: |
  Confidence is moderate because the corrections came in one session.
  Re-evaluate after the next test-heavy session.
```

Rules:

- One finding per file. Compound instincts are split.
- `confidence` is the agent's honest estimate. Bump it on subsequent confirmations; do NOT silently inflate.
- `domains` are tags from a shared, free-form vocabulary (testing, security, git, planning, ...). Use existing tags when they fit.
- `evidence` cites concrete observations. No evidence -> the instinct is speculation, not an instinct.

### 4. Evolve into a draft skill or command

When several high-confidence instincts (>= 0.7) in the same domain cluster, propose a draft:

1. Search the catalog for an existing skill that already covers the pattern (use `search_skills` MCP or grep `data/SKILL_INDEX.md`). If one exists, propose extending it rather than creating a new one.
2. Otherwise, draft a new `SKILL.md` (or `catalog/commands/<name>.md`) following the AGENTS.md conventions: full `summary_l0`/`overview_l1`, When to Use (+ When NOT), Instructions, Common Rationalizations, binary Verification, Related Skills.
3. **Never** silently commit the draft. Surface it inline and ask the maintainer to review.

### 5. Index

After minting any instinct, regenerate `.nexus/instincts/_index.md` with one row per instinct: slug, confidence, domains, one-line summary. The index is the human's primary read surface.

### 6. Prune

The user prunes manually. This skill offers to mark an instinct `archived: true` (keep the file for history) when the user says "drop that one" or when an instinct contradicts a newer, higher-confidence one.

## Common Rationalizations

| Rationalization | Reality |
|---|---|
| "Running a background observer model would be more powerful - let me wire one up" | Out of scope and policy-prohibited. ECC's `continuous-learning-v2` upload-to-observer path is the exact pattern Nexus-Hub's MCP Registry Policy categorically rejects (generation-as-service / observation-as-service). The only acceptable observer in this skill is the agent itself, in-session, reading local JSONL. If the user explicitly asks for a background model anyway, escalate to AGENTS.md "MCP Registry Policy" rather than wiring it in. |
| "Capturing every prompt is a privacy risk" | The capture is project-scoped to `.nexus/` and the file is auto-truncated. Off-switch (`NEXUS_LEARNING_CAPTURE=off`) is documented in the hook header. The hook NEVER writes outside the project root. The user controls their own filesystem; this is no different from `git log` capturing commit metadata. |
| "I should mint an instinct from a single correction" | Speculation, not an instinct. The skill requires `evidence: []` to be populated with concrete observations. A single correction can be recorded as confidence 0.3 if it is clearly intentional, but lower-confidence instincts are reviewed and re-confirmed before they shape behavior. |
| "I can promote an instinct to a skill myself without showing the maintainer" | No. The skill's step 4 explicitly says surface the draft and ask. Skills are user-facing artifacts; an instinct that became a skill silently would bypass the curation bar that AGENTS.md defines. Drafts land in the working directory inline, never committed by the agent. |
| "Observations and instincts should sync across projects so I learn faster" | Cross-project sync is exactly the egress trap. Each project's `.nexus/` is its own. If the maintainer wants to promote a pattern globally, they do it explicitly by editing a real Nexus-Hub skill. |

## Verification

- [ ] Reading `.nexus/observations.jsonl` shows one JSON-per-line records with the four required fields (`ts`, `event`, `tool`, `prompt_sample`).
- [ ] Every minted instinct YAML has `slug`, `created`, `confidence`, `domains`, `trigger`, `behavior`, and `evidence` (with at least one entry).
- [ ] `confidence` is a number in `[0.0, 1.0]`.
- [ ] No background process, daemon, or network call is created or proposed at any step.
- [ ] No `.nexus/` file is written outside the project root.
- [ ] When a draft skill is produced, it is shown to the maintainer for review, not committed automatically.
- [ ] `.nexus/instincts/_index.md` matches the YAML files in the same directory (no drift).
