Incident report: 2026-05-27 retrieval latency spike

Summary

Hybrid retrieval p95 latency rose from 120ms to 1.4s for roughly 35 minutes. No data loss. Cause was an unbounded BM25 candidate set after a corpus import.

Timeline

14:02 import of 40k chunks completes. 14:05 latency alert fires. 14:22 candidate cap deployed. 14:40 p95 back to baseline.

Root cause

The FTS5 pre-filter cap was bypassed on the cold-index path, so the dense re-rank scored the full corpus.

Actions

Apply the candidate cap on every path; add a regression test asserting the cap; alert on candidate-set size, not just latency.
