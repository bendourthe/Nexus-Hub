# Known Gaps -- v3.2.0

**Status**: v3.2.0 has two sub-plans. (1) `adoption-teach` -- all 3 of 3 phases complete on `feat/adoption-teach`, merged into `develop` (merge `8523281`): core `session-teach-back` skill + modes/depth-levels/checklist + cross-links. (2) `adoption-headroom` -- Phases 1-3 of 7 complete on `feat/adoption-headroom` (branched off the post-teach `develop` merge `8523281`). **Phase 1** (Foundation + SmartCrusher): scaffolded `extensions/nexus-context-compressor` (no-op `compress` pipeline + `CompressResult` metrics + an offline-safe tiktoken/stdlib token counter), implemented the deterministic SmartCrusher JSON-array dedup (global-uniqueness + adjacent-change scoring, stable SHA-256 CCR markers `<<ccr:HASH N_rows>>`), and registered the package copy + editable-install block in both installers (no MCP registration yet -- deferred to Phase 4). **Phase 2** (CCR reversible store): added the `ccr/` subpackage -- a shared marker codec (`ccr/marker.py`, single source of truth for the `<<ccr:HASH N_rows>>` grammar so producer and consumer cannot drift), a local SQLite `CCRStore` (`ccr/store.py`, content-addressed, idempotent `put`, WAL, oldest-first `prune` eviction) wired into SmartCrusher via optional dependency injection (`smart_crush(records, store=...)` stays pure when `store=None`), and the `retrieve()` interface (`ccr/retrieve.py`) that resolves a marker/object/bare-hash back to the originals or a named `NOT_FOUND` sentinel, never raising. 68 package tests pass (19 Phase 1 + 49 Phase 2; 100% coverage on `ccr/`); the round-trip is provably lossless and survives a store restart; `make validate` emulated green; no shell surface this phase. Deferred SmartCrusher refinements are logged below as DF-v32hr-1..3; the Phase 2 eviction-scheduling deferral is DF-v32hr-4. **Phase 3** (Remaining deterministic strategies): added the three remaining transforms -- `transforms/cache_aligner.py` (KV-cache prefix stabilizer: regex-detects volatile tokens -- dates, times, UUIDs, long-hex hashes, semantic versions, epoch timestamps -- moves those lines to the tail and normalizes whitespace, leaving a byte-identical stable prefix; optional spaCy NER seam default-off and graceful), `transforms/code_compressor.py` (AST-aware function/method body elision that REUSES the `nexus-code-search` tree-sitter extractors via `parse_file` rather than re-vendoring grammars, keeps imports/decorators/signatures/class structure by eliding only innermost body interiors, emits reversible `<<ccr:HASH N_rows>>` markers for bodies >= `ccr_min_lines` and a plain note for smaller ones, with a dependency-free regex/indent/brace fallback for unsupported languages or when the AST infra is absent), and `transforms/content_router.py` (classifies JSON-array / JSON-object / code / log / text and dispatches arrays to SmartCrusher + code to CodeCompressor, splitting mixed content on fenced code blocks and threading the CCR store). Extended the marker codec (`ccr/marker.py`) with `find_marker` / `find_all_markers` for markers embedded in free text (the form CodeCompressor leaves inside code comments) and registered the package in the `make test` target. 130 package tests pass (62 added in Phase 3; 92% total coverage, `ccr/` still 100%, the three new transforms 88-97%); all four sibling extension suites (skill-server 43, code-search 201, web-fetch 29, skill-scanner 87) remain green (no regressions); `make validate` emulated green; `make lint` N/A (Python-only, no shell surface). New Phase 3 deferrals/limitations are logged below as DF-v32hr-5..8. **Phase 4** (Runtime integration + retire rtk): added the runtime seam `compress_output(text, persist=...)` (the single-blob entry the hook and MCP call) plus a CLI (`compress`/`retrieve`/`serve` subcommands), wired the top-level `compress(messages)` through ContentRouter (no longer a no-op; identity on prose, so the Phase 1 scaffold tests stay green), and added a runtime "never expand / never lose output" guard. Shipped the opt-in/default-off PreToolUse hook `catalog/hooks/compress-output.sh` (rewrites a Bash command so its stdout pipes through the engine, preserving the exit code via `PIPESTATUS`; jq-gated, fail-open; registered in `settings.json` and copied by both installers) with a pytest suite, and the internal MCP server (`server.py`, lazy-`mcp` import behind the optional `[mcp]` extra) exposing `context_compress` + `context_retrieve`, registered in `catalog/mcp-configs/mcp-servers.json` (re-full) with a matrix row, auto-registered + `[mcp]`-installed by both installers, and added to CI (the compressor extension suite was not previously CI-gated -- now fixed). Superseded the external rtk recommendation in `guides/RTK_CONTEXT_COMPRESSION.md` (+ the `base-claude.md` template line) with an honest parity note. 159 package tests pass (29 added in Phase 4); the full `catalog/hooks` suite (434, incl. 8 new hook tests), `tests/validators` (136), `tests/installer` (70), `tests/integrations` (197) all green; all `make validate` validators 0 errors; skill-security gate exit 0; ShellCheck clean (new hook + installer.sh); installer.ps1 parses clean; a throwaway-venv `[mcp]`-extra install + `serve` startup confirmed. DF-v32hr-7 is resolved here; new Phase 4 items are DF-v32hr-9..11 and WN-v32hr-1..2; DF-v32hr-4 (auto-prune) refined and kept open.
