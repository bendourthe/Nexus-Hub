## The defect this phase fixes

Three surfaces audited a spec for a scope boundary the canonical template could not express:

- `catalog/templates/spec-quality-checklist.md` line 22 asks whether "Scope is clearly bounded".
- `catalog/agents/scope-guardian-reviewer.md` line 14 flags a missing "explicitly out of scope" section.
- `catalog/skills/developer-experience/idea-refine/SKILL.md` line 152 gates on "Scope is explicitly bounded".

`catalog/templates/spec-template.md` had no section holding that content, so a spec that conformed perfectly to the template still failed all three checks. The finding was caused by the template it was raised against.

A second, independent defect sat in the same neighborhood. `spec-driven-development` SKILL.md told the author to use `spec-template.md` as the skeleton (line 72), then presented a different template inline (lines 176-207), and its Verification checklist (line 295) validated "all six core areas (Objective, Commands, Structure, Style, Testing, Boundaries)", which are the inline template's areas. The skill's completion gate checked an artifact the workflow does not produce.

## 1.1 - Three sections added to the canonical template

`## Problem Statement *(mandatory)*` is now the first section, before User Scenarios. It carries Actor / Problem / Observable outcome, with an authoring note saying it carries forward the `idea-refine` output rather than restating it, and that it stays technology-agnostic.

`## Non-Goals *(mandatory)*` sits after Success Criteria and before Assumptions. Every entry must carry a reason, with the four accepted reasons named (deferred, separate initiative, not yet validated, too expensive), modeled on `product-manager` SKILL.md:137 and the worked example at `test-strategy-doc` SKILL.md:74. Its authoring note states the boundary against Assumptions: an Assumption is a decision the reviewer overturns with one line, a Non-Goal is scope the reviewer is asked to confirm is excluded. If overturning the entry changes WHAT gets built rather than HOW, it is a Non-Goal.

`## Invariants *(include if the change touches existing behavior)*` follows, declaring existing behavior the change must not break, with the boundary against Non-Goals stated at the point of use: a Non-Goal is something that will not be built; an Invariant is something that must not break.

All placeholders use square brackets, so the `validate_skills.py` unfilled-placeholder lint (which treats two or more space-separated lowercase words in angle brackets as a hard error) has nothing to catch.

**The FR-### / SC-### contract was proven rather than assumed.** The diff is `46 insertions(+), 0 deletions(-)`. Zero deleted lines means no pre-existing byte in the file changed, which settles the question for the whole file rather than for the two ID blocks alone. This matters because `cross-artifact-analyzer` joins its Coverage Summary table on those IDs, and a reformat would empty the matrix silently rather than erroring.

## 1.2 - The checklist bound to the new structure

"Scope is clearly bounded" now reads "(the `## Non-Goals` section is present and non-empty)" and is followed by two companion items: every Non-Goals entry carries a reason, and Invariants are declared where the change touches existing behavior. Under Content Quality, "All mandatory sections completed" gained a parenthetical naming Problem Statement and Non-Goals, so an author can tell what "mandatory" now includes. No existing item was renumbered or reworded beyond the binding, and no check was added for a section the template does not have.

## 1.3 - Template authority resolved and the gate repointed

The "Spec template" section now opens by declaring `catalog/templates/spec-template.md` the single canonical skeleton, stating explicitly that there is no second skeleton and no abbreviated variant, and that a section that does not apply is removed rather than replaced with a different structure. The section's closing paragraph was rewritten to enumerate the five mandatory sections in document order plus the two conditional ones, and to name `## Non-Goals` as the section the three auditing surfaces check against.

The Verification checklist was repointed at the canonical template. It now has twelve binary items keyed to real headings (Problem Statement, User Scenarios & Testing with the story format and Independent Test, Requirements with FR-### IDs, Success Criteria with SC-### IDs, Non-Goals with a reason per entry, Assumptions, Invariants where applicable), plus a marker-cap item and a leak check, and it preserves the two items that were never about template sections: the human-approval item and the open-questions item.

**Deviation, logged as DF-1.** The plan named "the rival inline template block at lines 176-207" for removal. That code block was only half the rival artifact. The same structure existed as prose immediately above it, in the "Write a spec document covering six core areas" enumeration at former lines 134-173, and that prose list is what the Verification item actually referenced. Removing only the code block would have left the skill instructing the author to cover six areas the canonical template does not have, which fails this phase's own Stability Gate ("SKILL.md names exactly one canonical template"). Both forms were removed together.

**Relocated, not deleted.** The content the rival uniquely carried (tech stack, executable commands, project structure, code style, testing strategy, and the three-tier Always / Ask first / Never boundaries) is real guidance about project-level context, not per-feature spec content. It moved into a new "Project-level context (distinct from a feature spec)" section placed after "Normative Spec vs Free-Form Context", which names its proper home (the project's own `AGENTS.md` / `CLAUDE.md` or the `docs/` context tree) and states why restating it per feature guarantees drift. The section closes by tying itself to the adjacent normative/context split: that one separates testable requirements from rationale within a feature, this one separates per-feature content from per-project content.

The hard gate (lines 12-23), the marker discipline, the "Normative Spec vs Free-Form Context" section, and the FR/SC ID rationale were left untouched; Phase 2 owns the gate-adjacent prose. The body is 303 lines, within the 500-line norm, with room freed by the removal.

**A verification attempt that backfired, recorded so it is not repeated.** The pre-existence check was first attempted as `git stash && pytest <test> && git stash pop` chained in one command. Recovered with an explicit `git stash pop` (all five restored, verified against `git status`). The cheaper check, used afterward, was `git diff --name-only` against the file the test actually exercises. A stash is the wrong instrument when the command that follows it can be killed.

Every item was tickable from the template alone, including "Scope is clearly bounded", which had been unsatisfiable before this phase.
