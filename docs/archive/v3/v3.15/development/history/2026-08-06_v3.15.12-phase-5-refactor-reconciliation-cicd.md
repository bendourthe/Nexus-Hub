### The final gate failed once, and the failure was worth having

The first combined run came back red on `test_global_install_never_touches_the_real_home` (2576 passed, 1 failed). Investigated rather than retried, and it was a **test defect**:

- The real guard passed. `assert called` confirmed `install_global` routes through the patchable `_copilot_home` accessor, which is the behaviour the test protects.
- The failing assertion required the developer's real `~/.copilot/agents` to hold **no** `*.agent.md` at all. It held 23 - exactly the count the test's own docstring cites.
- Those are Nexus-Hub's own catalog agents from a legitimate global install: `~/.nexus-hub/VERSION` (13:50), `~/.codex/prompts` (13:46), and `~/.copilot/agents` (13:47) share one window. An installer run, not a test leak. Nothing in v3.15.12 touches the Copilot integration.

The assertion conflated "this test wrote here" with "these files exist here", so it failed permanently on any machine where the maintainer had actually installed Nexus-Hub - punishing exactly the people most likely to run the suite, and only once they dogfooded the product. Fixed by snapshotting `*.agent.md` before `install_global` and asserting the set is unchanged after: same intent, no longer environment-dependent, and the 23-file defect it guards would still fail it.

A third assertion was briefly added and then removed, because it assumed a layout for where the isolated root receives agents that is not the one used. An assertion that cannot be grounded is worse than none.

One process note: the task notification for an isolated re-run reported "exit code 0" while the test had in fact failed - that code belonged to the shell pipeline, not to pytest. The log is authoritative; the notification summary is not.
