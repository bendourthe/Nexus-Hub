2. macOS (target: macOS 14 Sonoma; not run on this cycle)
============================================================

Status: NOT RUN on this v2.2.0 release cycle. The Phase 6 host (Windows 11 Enterprise) had no macOS VM or Docker macOS-mode container available.

Inferred status: PASS-by-parity. Rationale:
- The installer.sh code path is identical between macOS and Linux (POSIX bash). The only macOS-specific divergence in the install flow is the file-watcher backend (FSEvents on macOS vs. inotify on Linux), which lives inside the `watchdog` library (>=4.0.0 pin) and is exercised by tests/test_watcher.py on Windows via the Windows-side ReadDirectoryChangesW backend. Cross-OS coverage in `watchdog` is comprehensive and unchanged between v2.1.1 (no watcher) and v2.2.0 (watcher added in Phase 4 T027).
- Tree-mirror parity tests in tests/integrations/test_parity_with_legacy_installer.py assert SHA-256-identical output between the legacy bash `safe_folder_copy` blocks and the Python registry runner; this is OS-agnostic since both paths produce the same byte sequences for catalog skills / commands / agents / rules.

Action item: re-run sub-step 1a-1j on a macOS host before any v2.2.0-tagged binary release. The current v2.2.0 is a source release, so this is an acceptable deferral.
