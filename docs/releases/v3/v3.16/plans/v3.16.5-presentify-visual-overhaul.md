## Overview

A real `/presentify` run (the Nexus-Hub unit-test workflow page, 2026-08-10) surfaced a cluster of defects the maintainer has observed across multiple runs: static text wrapping that strands prose in narrow columns on wide screens, margin notes and footer text rendered too small to read, key tokens (command names) not visually distinct, an SVG loop-back arrow whose dash pattern and arrowhead render as unrecognizable fragments, a pinned pipeline graphic taller than the viewport, and misdrawn connector arrows. Every one of these shipped because the visual-QA loop degraded to the structural scorer: no headless browser exists on the dev host or in CI (v3.15 known-gaps MT-1), so the agent never saw its own output rendered.

This plan fixes the class, not the instances. It has three thrusts:

1. **Contracts** (Phases 1-2): a fluid-layout + readability contract (viewport-ratio spacing, per-element measures that scale, minimum rendered font sizes, emphasis-token rules) and an SVG diagram-quality contract (marker-based arrowheads, geometry verification, viewport-fit for pinned graphics), each with deterministic checks added to `visual_qa_score.py` and grading criteria added to the rubric.
2. **Enforcement** (Phases 3 and 5): make the render step real - provision Playwright with consent, make the iterative screenshot-grade-fix loop the default rather than the silently-degraded path, run it in CI on a gated job - and grade stock/AI image placement (headers, backgrounds, contextual illustrations) inside that same loop.
3. **Intake** (Phases 4 and 6): restructure the imagery question to four additional-imagery options over an always-on procedural base, add a second post-extraction round offering three content-derived color schemes plus Other, and absorb the never-implemented scroll-scrub plan so cinematic surfaces through the interactivity question (explicit option, and agent-selectable under `rich`).

**Goals-first:**

- **Target problem**: presentify pages ship with layout, readability, and diagram defects that a human catches in one glance, because the agent never renders its own output; and the intake questions (imagery tiers, no color-scheme input, no cinematic option) do not match the choices users actually want to make.
- **Persona**: a Nexus-Hub user turning documents, decks, or a codebase into a shareable interactive site, who expects the result to look professionally verified on the first delivery and to be offered choices in their own vocabulary.
- **Definition of done**: a default `/presentify` run on a host with Python renders its own output headlessly, grades every segment against the extended rubric (fluid layout, readability floors, SVG integrity, image placement), iterates until no high-severity finding remains, and records the screenshot evidence trail; the intake asks the restructured imagery question and the two-round color-scheme flow; `--interactivity` accepts cinematic and `rich` may select scroll-scrub; the calibration fixture (`nexus-hub-unit-test-workflow.html`) passes the new gates; `make validate` and the presentify test suite are green.

The former v3.20.1 scroll-scrub plan is ingested wholesale as Phase 6 (its prompts inlined; the file itself deleted).

## Errata: render-session lessons (2026-08-11, binding on remaining phases)

On 2026-08-11 the maintainer and agent iterated the calibration fixture (`nexus-hub-unit-test-workflow.html`) through four real render-grade-fix rounds with Playwright at 2560x1300 and 1920x1080. The session validated the plan's core bet (the structural scorer passed while four real defect classes were visible on screen) and overturned two prescriptions Phases 1-2 had already committed. The fixture at repo root now embodies every item below and serves as the reference implementation. These errata are binding on the remaining phases; E1-E5 correct already-committed Phase 1-2 artifacts and are executed inside Phase 3 (3.2 already rewrites the rubric, 3.3 already touches the scorer), with known-gaps entry BG-E1 tracking them.

- **E1 (corrects Phase 1, `responsive-typography.md`)**: viewport-proportional scaling belongs on the ROOT, not on elements. Per-element `clamp()` font sizes (including the reference's own `body{font-size:clamp(1rem,.55rem+.45vw,1.125rem)}` example) cap out and leave large displays rendering laptop-sized text; three rounds of per-element bumps failed to fix perceived smallness. The contract's primary rule becomes `html{font-size:clamp(1rem, 0.5vw + 0.55rem, 1.6rem)}` (or equivalent slope), so every rem/ch-derived dimension scales with the window; the modular scale then rides the root. Rendered floors are evaluated at the SCALED root, not at 16px.
- **E2 (corrects Phase 1)**: in multi-column zones, fluid `fr` shares beat `ch` caps. The maintainer rejected ch-capped prose twice (dead middle band with a far-edge aside; then "text compacted left"). The contract's example layout becomes fractional columns (e.g. `2fr / minmax(16rem,1fr)`) with margin notes ADJACENT to prose, and no hardcoded measure inside multi-column zones. Record the precedence explicitly: on wide screens, filling the window wins over line-length caps; the 45-85ch measure applies to single-column long-form prose only.
- **E3 (corrects the scorer; lands with 3.3)**: `visual_qa_score.py` resolves px against `root_font=16`, so once E1 root scaling exists its font-floor and full-width band math are wrong (real gutter at 1920 is ~51px, not 44). The deterministic checks must parse and apply the `html` font-size rule before resolving rem/ch values.
- **E4 (corrects Phase 2, `svg-diagram-quality.md`)**: rotated (`rotate(90)`) text labels are themselves a readability defect, not a technique to apply carefully - the maintainer asked for horizontal. The contract's correct example becomes: widen the viewBox and set the label horizontal (multi-line via `tspan` when narrow); rotation is a last resort when horizontal genuinely cannot fit.
- **E5 (extends Phases 1-2 + the rubric)**: three defect classes discovered by rendering, absent from the contracts: (a) sticky-under-sticky - a `position:sticky` table header pinning beneath the sticky nav (rule: at most one sticky layer per scroll context, or offset lower layers by the upper one's height); (b) anchor targets without `scroll-margin-top`, landing section titles under the nav; (c) long command/prompt lines clipping in `pre` blocks (rule: command blocks use `white-space:pre-wrap; overflow-wrap:anywhere`).
- **E6 (amends 3.2)**: screenshot captures must scroll with `behavior:'instant'` and a settle wait - `scrollIntoView` inherits CSS `scroll-behavior:smooth`, and a long smooth scroll outlives fixed waits, producing mid-animation frames that grade as false defects (one nearly shipped a wrong diagnosis this session).
- **E7 (amends 3.2)**: the capture matrix must include a >=2560px-wide viewport. The maintainer's display class showed size/space defects that 1920 renders understated every round.
- **E8 (amends 3.2)**: each loop iteration records cheap computed-metric probes alongside screenshots (root font px, rendered prose/column widths, key element bounding boxes) - they settle size disputes deterministically and cost one `page.evaluate`.
- **E9 (rubric + `interactive-features.md`, via 3.2)**: two authoring rules from maintainer feedback: (a) key-value cells (reads/writes/outputs and the like) render as bullet lists with concrete example values, never comma-run sentences; (b) interactive-control colors (sliders, inputs) stay NEUTRAL and visually distinct from chart data-series colors.
- **E10 (note on 3.1)**: Playwright + chromium were consent-installed on the dev host on 2026-08-11, and the fixture already embodies E1-E9 - so Phase 1.3 / 2.3 / 3.4's fixture work is now verification against the fixed fixture rather than fixing, and 3.1 focuses on the detection script and degradation contract.

## Phase 1: Fluid layout + readability contract

**Goal**: Replace static spacing/wrapping/typography with a fluid, viewport-proportional contract, and make readability floors (rendered size, contrast, emphasis tokens) explicit, checkable, and graded.
**Prerequisites**: None.
**Stability Gate**: `references/responsive-typography.md` exists and is referenced from SKILL.md; `visual_qa_score.py` gains deterministic fluid-layout and font-floor checks with tests; the calibration fixture (`nexus-hub-unit-test-workflow.html`) passes them; `make validate` (orphan-bundle audit) green.
**Recommended model tier**: frontier
**Recommended effort level**: high
**Rationale**: This contract is the foundation every later phase grades against; getting the fluid-scaling rules wrong propagates into the scorer, the rubric, and every future output.

### Sub-tasks

#### 1.1 - Author references/responsive-typography.md

**Objective**: Write the canonical fluid layout + readability contract.

**Prompt**:
> Create `catalog/skills/specialized-domains/document-to-interactive-html/references/responsive-typography.md` (follow `catalog/style-guides/markdown.md`; ASCII-only). Codify, with concrete CSS patterns and observable pass criteria:
>
> 1. **Fluid space, never fixed space**: every macro-layout dimension (band padding, grid gaps, column widths, gutters) is a clamp() of viewport-relative units - `clamp(min, preferred-vw-based, max)` - never a bare px/rem constant. Micro-spacing (within a component) may be rem-based. Pass criterion: no top-level band or grid uses a fixed pixel gap/padding.
> 2. **Wrapping serves the viewport, not a fixed column**: prose measure is per-element (45-85ch) but grid TRACKS must widen/reflow with the viewport (minmax + auto-fit/fr, container queries where useful). The failure this kills: a paragraph hard-trapped at ~55ch inside a 1fr track while half the viewport sits empty beside it (observed 2026-08-10, screenshot 1). Text blocks that share a band with empty space must either widen toward their max measure or the band must reflow to multi-column. Add `text-wrap: balance` for headings and `text-wrap: pretty` (progressive enhancement) for prose.
> 3. **Fluid type scale**: all font sizes derive from a clamp()-based modular scale keyed to viewport width; define the scale once as custom properties.
> 4. **Minimum rendered sizes (hard floors)**: body prose >= 16px rendered at any viewport >= 1280px; secondary text (margin notes, captions, footer link lists, credits) >= 13px rendered - the observed 2026-08-10 failures (unreadable margin notes and footer) were ~11-12px equivalents; nothing interactive below 12px. Floors are checked at BOTH the clamp() minimum and the 1920px resolution.
> 5. **Emphasis tokens**: inline tokens that carry meaning (command names, file paths, key terms) must be visually distinct from surrounding prose by BOTH a color step (>= 2 discernible steps from body color, still meeting WCAG AA 4.5:1 against the background) AND a family/weight change (mono or semibold). A muted-same-color `<code>` is a defect (observed: `/review` invisible inside a margin note).
> 6. **Contrast floors**: body AA (4.5:1); secondary text AA; large display text >= 3:1. Muted-ink-on-dark palettes must be validated, not eyeballed.
>
> Reference this file from SKILL.md Step 6 (one bullet) so the orphan-bundle audit passes. Do not inflate the SKILL.md body; depth stays here.

#### 1.2 - Extend visual_qa_score.py with deterministic layout/readability checks

**Objective**: Make the contract machine-checkable without a browser.

**Prompt**:
> Extend `catalog/skills/specialized-domains/document-to-interactive-html/scripts/visual_qa_score.py` with structural checks derived from `references/responsive-typography.md`:
>
> - **fluid-spacing**: parse top-level band/grid CSS; flag fixed px padding/gap on band-level selectors as a finding (high severity when > 2 occurrences).
> - **font-floor**: resolve every `font-size` declaration (including clamp() minimums, reusing the existing `_len_px` resolver) and fail any secondary-text size whose minimum resolves below 13px or body prose below 16px at a 1920px viewport.
> - **emphasis-token**: heuristic - inline `code`/token selectors must declare a color distinct from the body ink custom property.
> - **contrast**: compute WCAG ratios for each declared ink/background custom-property pair; fail below AA.
>
> Keep it stdlib-only. Add pytest coverage under the existing presentify test surface (fixtures: one passing page, one page seeded with each defect class). Update `references/visual-qa-rubric.md` with matching agent-vision criteria (graded per segment): "prose stranded beside dead space", "secondary text readable at 100% zoom on a 27-inch display", "emphasis tokens discernible at a glance".

#### 1.3 - Fix the calibration fixture

**Objective**: Apply the contract to the 2026-08-10 output so it becomes the standing calibration fixture.

**Prompt**:
> Update `nexus-hub-unit-test-workflow.html` (repo root; coordinate with the maintainer on its final location - Phase 7 may move it under a fixtures dir) to satisfy the Phase 1 contract: convert fixed band paddings/gaps to viewport-ratio clamp()s; let the "Shape" section prose widen toward 85ch when its band has free width (reflow the editorial grid); raise margin-note and footer font minimums to the 13px floor; give `.note code` and footer `code` tokens the emphasis treatment (accent color + mono, AA-checked); re-run `python scripts/visual_qa_score.py` and confirm the new checks pass. This file also carries the maintainer-reported footer fix (R4).

#### 1.4 - Testing and Stabilization

**Objective**: Prove the contract is wired and enforced.

**Prompt**:

## Phase 2: SVG diagram-quality contract

**Goal**: Make authored SVG diagrams structurally correct (arrowheads, connectors, dash patterns) and viewport-fit, so a diagram never ships unrecognizable.
**Prerequisites**: Phase 1 (scorer plumbing).
**Stability Gate**: `references/svg-diagram-quality.md` exists and is referenced; scorer gains SVG structural checks with tests; the fixture's pipeline diagram and loop-back arrow are rebuilt to the contract.
**Recommended model tier**: strong
**Recommended effort level**: high
**Rationale**: Focused, well-bounded authoring discipline plus parser checks; less blast radius than Phase 1 but the defect class (broken arrows) is the most visually damaging one observed.

### Sub-tasks

#### 2.1 - Author references/svg-diagram-quality.md

**Objective**: Canonical rules for hand-authored inline SVG diagrams.

**Prompt**:
> Create `catalog/skills/specialized-domains/document-to-interactive-html/references/svg-diagram-quality.md`. Rules, each with a correct/incorrect snippet pair:
>
> 1. **Arrowheads are `<marker>` elements** (`marker-end` on the path), never separate hand-placed triangle paths - a hand-placed triangle detaches from its line when geometry shifts, which is exactly the 2026-08-10 defect (dashed loop-back whose arrowhead floated disconnected). Markers must use `orient="auto"` and scale with `markerUnits="strokeWidth"`.
> 2. **Dash patterns must not collide with markers or text**: no `stroke-dasharray` on a path segment that passes within the label's bounding box; rotate/offset labels off the path, or carve the path around them.
> 3. **Connectors terminate on node edges**, not node centers or arbitrary coordinates; every connector's endpoints must lie on the boundary of the two boxes it joins (compute from the box geometry; do not eyeball).
> 4. **Viewport-fit for pinned/sticky graphics**: a pinned scrollytelling graphic must fully fit the sticky viewport slot - `max-height: calc(100vh - <sticky-offset>)` with `width: auto`, and the viewBox aspect chosen so ALL nodes are visible at once on a 1080p display (the 2026-08-10 pipeline lost its bottom two stages).
> 5. **Geometry self-check before shipping**: after authoring, verify numerically (coordinates in the viewBox, markers referenced, labels non-overlapping) - authored SVG is code, and unchecked coordinates are unchecked code.
>
> Reference from SKILL.md Step 6. ASCII-only, style-guide compliant.

#### 2.2 - Extend the scorer with SVG structural checks

**Objective**: Deterministic detection of the broken-arrow class.

**Prompt**:
> Extend `visual_qa_score.py`: parse inline `<svg>` blocks (stdlib XML); flag (a) any `<path>` with `stroke-dasharray` that has no `marker-end` yet is followed by a sibling small filled triangle path (the detached-arrowhead smell), (b) `<svg>` elements inside a sticky/pinned container whose computed max-height is unconstrained, (c) markers defined but unreferenced and vice versa. Severity high for (a) and (b). Add pytest fixtures for each. Update the rubric's agent-vision criteria: "every arrow reads as ONE object (line + head attached)", "the whole diagram visible in one sticky viewport", "no label collides with a line".

#### 2.3 - Rebuild the fixture diagrams

**Objective**: Apply the contract to the calibration fixture.

**Prompt**:
> Rebuild the pipeline SVG and loop-back arrow in `nexus-hub-unit-test-workflow.html` per the new contract: marker-based arrowheads, connectors terminating on box edges, the loop-back label moved clear of the dashed path, and the pinned graphic constrained to fit a 1080p sticky viewport with all five stages visible. Re-run the scorer; confirm the new SVG checks pass.

#### 2.4 - Testing and Stabilization

**Objective**: Stabilize and record.

**Prompt**:
> Run `make validate`, the presentify pytest surface, and the scorer over both fixtures. Add a SKILL.md rationalization row rebutting "the diagram looked right in my head / in the code" (reality: authored SVG coordinates are unchecked code; run the geometry self-check). Run `/generate-session-history` for Phase 2.
