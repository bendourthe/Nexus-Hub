# Plan - presentify verbosity intake (content-derived coverage-depth question)

**Project**: Nexus-Hub
**Version**: v3.16.6
**Slug**: presentify-verbosity-intake
**Plan Type**: Feature
**Created**: 2026-08-11
**Goal**: The presentify intake carries a content-derived coverage-depth (verbosity) question in the post-extraction round, and the answer observably changes the generated page's depth; flags, non-interactive fallback, and registries stay coherent.

## Overview

Presentify's intake resolves style, output aspect, interactivity, and imagery, and (as of v3.16.5 Phase 4) a second post-extraction round offering content-derived color schemes. None of these axes answers "how much of my source material survives onto the page". The agent decides content depth silently, so pages either dump everything or over-summarize with no user say. This plan adds a single clean coverage-depth axis: Distilled / Balanced / Comprehensive.

The question lands in the intake's second round (post-extraction), alongside the color-scheme question, because a good answer depends on the extracted content: the agent states what the sources actually contain ("~40 pages across 6 major topics") and offers depth options grounded in that volume. Round 1 stays content-independent (style, aspect, interactivity, imagery); round 2 stays content-dependent (color schemes, verbosity). A `--verbosity <distilled|balanced|comprehensive>` flag presets the answer for scripted runs, keeping parity with the other design flags; the non-interactive fallback is `balanced`, which matches the current implicit behavior most closely.

Enforcement is record-plus-rubric (maintainer decision 2026-08-11): the resolved choice and a per-run section-count target are written to the design-record HTML comment, the authoring step receives explicit per-level depth rules, and the visual-QA rubric gains an agent-graded criterion so an ignored answer is caught in the QA loop. No new deterministic scorer code: word-count bands are crude and would false-positive. Success looks like: the same source set produces visibly different pages under the three levels, the design record names the level and target, and `make validate` plus the presentify test surface stay green.

**Depends on**: v3.16.5 (`feat/v3.16.5-presentify-visual-overhaul`) landing first. This plan extends the two-round intake that v3.16.5 Phase 4 introduces and the QA rubric/loop that Phases 1-3 harden. Do not start Phase 1 until v3.16.5 is merged to `develop`.

**Origin**: deferred from v3.16.5 by maintainer decision 2026-08-11 (raised during v3.16.5 Phase 7; adding it there would have reopened Phase 4's stability gate inside the no-behavior-change refactor phase). Record the corresponding known-gaps entry closure in Phase 2.

## Phase 1: Verbosity axis - round-2 question, flag, authoring rules, rubric criterion

**Goal**: Ship the coverage-depth axis end to end: intake question, CLI flag, non-interactive fallback, design-record entry, per-level authoring rules, and the QA rubric criterion that catches an ignored answer.
**Prerequisites**: v3.16.5 merged to `develop` (the two-round intake and the screenshot QA loop this phase extends).
**Stability Gate**: `catalog/commands/presentify.md` and SKILL.md carry the round-2 verbosity question and the `--verbosity` flag; the resolved level and section-count target appear in the design-record comment; the authoring step documents the three per-level depth rules; `references/visual-qa-rubric.md` grades depth-vs-declared-level; non-interactive fallback is `balanced`; registries updated only if frontmatter changed; `make validate` and the presentify pytest surface green.
**Recommended model tier**: strong
**Recommended effort level**: high
**Rationale**: Multi-surface prose and intake-contract work with an enforcement hook into the QA loop, but no novel engineering and no new script; the risk is coherence across surfaces, not algorithmic difficulty.

### Sub-tasks

#### 1.1 - Round-2 verbosity question and `--verbosity` flag

**Objective**: Add the coverage-depth question to the post-extraction round and the presetting flag to the command surface.

**Failure modes**: A malformed or unrecognized `--verbosity` value (anything outside `distilled|balanced|comprehensive`, case-insensitive) is rejected with a one-line usage note and the run falls back to asking the round-2 question (interactive) or `balanced` (non-interactive); when extraction yields too little content to characterize (a single tiny source), the question still renders but with the generic option descriptions instead of content-derived counts; when `--verbosity` is given AND the round-2 batch would ask, the flag wins and the question is skipped entirely (the flag is a preset, never a second conflicting prompt).

**Build class**: load-bearing.

**Prompt**:
> In the Nexus-Hub repo, extend the presentify intake with a coverage-depth (verbosity) axis. Prerequisite: v3.16.5 is merged, so `catalog/commands/presentify.md` and `catalog/skills/specialized-domains/document-to-interactive-html/SKILL.md` already carry the two-round intake (round 1: style, aspect, interactivity, imagery; round 2, post-extraction: three content-derived color schemes plus Other).
>
> 1. **Command surface** (`catalog/commands/presentify.md`): add `--verbosity <distilled|balanced|comprehensive>` to the usage line and flag list, documented as "how much of the source material survives onto the page". Note the deliberate naming: `--verbosity` (the content axis) is distinct from the existing `--qa-depth` (the QA-loop thoroughness axis); add one clarifying sentence so users do not conflate them. Document the natural-language equivalent (e.g. "keep it comprehensive", "just the highlights") as binding the axis the same way `using the style ...` binds `--style`.
> 2. **Round-2 question** (SKILL.md, the post-extraction round introduced by v3.16.5 Phase 4): alongside the color-scheme question, ask a verbosity question whose stem is content-derived. The agent states what extraction found (approximate page/section/topic counts) and offers exactly three options: **(a) Distilled** - one narrative arc, key findings only; **(b) Balanced** - every major topic present, details summarized; **(c) Comprehensive** - full section-by-section coverage including appendix-grade material. Give each option a content-derived size hint (approximate section count for THIS source set). A `--verbosity` flag or natural-language binding skips the question.
> 3. **Fallbacks**: non-interactive runs and unanswered prompts resolve to `balanced`. Reject unrecognized flag values with a usage note, then fall back per the interactive/non-interactive rule above.
> 4. **Design record**: record the resolved level, whether it was flag-preset / asked / defaulted, and the derived section-count target in the design-record HTML comment next to the existing four choices.
>
> Follow `catalog/style-guides/markdown.md` (ASCII-only). Update `data/SKILL_INDEX.md`, `data/skills.json`, and `data/marketplace.json` ONLY if SKILL.md frontmatter (description/summary_l0/overview_l1) changes; do not touch other `data/` files. Acceptance: the question renders with content-derived counts, the flag presets and skips it, the fallback is `balanced`, and the design record carries the level and target.

#### 1.2 - Per-level authoring depth rules

**Objective**: Make the authoring step consume the resolved level so the choice changes the page instead of decorating the design record.

**Failure modes**: When the resolved level conflicts with a hard content constraint (a `distilled` run over a source set whose per-source attribution contract requires every source to remain a labeled area), the attribution contract wins and the agent narrows within it (distill per source, never merge sources away), recording the tension in the design record; when the design record is missing the level (an older page re-entering the QA loop), the authoring and QA steps treat the run as `balanced` rather than failing; there is no unreachable-dependency case (this is prompt logic, no new script or network surface).

**Build class**: load-bearing.

**Prompt**:
> In `catalog/skills/specialized-domains/document-to-interactive-html/SKILL.md`, wire the resolved verbosity level into the authoring step (the outline/narrative step that runs after extraction):
>
> 1. **Distilled**: a single narrative arc; only key findings, decisions, and conclusions survive; the section-count target is the low bound derived in 1.1; supporting detail collapses into summary devices (callouts, stat tiles) rather than full sections. Per-source attribution is still preserved in compile mode: distill within each source's labeled area, never blend sources.
> 2. **Balanced**: every major topic from the extraction appears; per-topic detail is summarized; appendix-grade material is dropped or reduced to a reference list.
> 3. **Comprehensive**: full section-by-section coverage including appendix-grade material; nothing silently dropped; long tails may be organized into collapsed/expandable regions where the interactivity level allows.
>
> Add one Common Rationalizations row rebutting "the user picked comprehensive but the page flows better short" (reality: the user explicitly chose coverage over brevity; cutting content overrides a recorded choice, which is the exact silent decision this axis removes). Keep the depth rules concise in the SKILL.md body; if they exceed a few bullets, place the detail in the existing intake/authoring reference file for the two-round intake rather than inflating the body (respect the SKILL.md size norm). Acceptance: the three levels produce observably different outlines from the same content model, and the level in the design record matches the built page.

---

#### 1.3 - QA rubric criterion

**Objective**: Catch an ignored verbosity answer inside the existing visual-QA loop.

**Failure modes**: When the rubric grader cannot infer depth from screenshots alone (depth is a content property, not purely visual), the criterion instructs the agent to grade against the design record's section-count target using the page's rendered section structure (headings/nav), not word counts; when the design record lacks the level, grade as `balanced` and emit a finding that the record is incomplete; conflicting-operations case: the depth criterion must not fight the readability contract (a `comprehensive` page still obeys every v3.16.5 layout/readability floor; depth never excuses cramming).

**Build class**: load-bearing.

**Prompt**:
> Extend `catalog/skills/specialized-domains/document-to-interactive-html/references/visual-qa-rubric.md` with one agent-graded criterion: "page depth matches the declared verbosity level" - the built page's section structure is compared against the design record's recorded level and section-count target (Distilled pages must not sprawl; Comprehensive pages must not have silently dropped topics; grade against rendered section structure, never raw word counts). State explicitly that depth never excuses violating the responsive-typography or readability floors. Do NOT add deterministic checks to `visual_qa_score.py` (maintainer decision 2026-08-11: word/section-count bands are crude and false-positive; enforcement is record + rubric only). Acceptance: the rubric file carries the criterion, it references the design-record fields written in 1.1, and the orphan-bundle audit still passes.
