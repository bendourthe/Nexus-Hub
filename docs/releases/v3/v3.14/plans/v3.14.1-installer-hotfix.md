# Plan - Installer Hotfix (Global Manifest Path + Orphaned Auth-Monitor Cleanup)

**Project**: Nexus-Hub
**Version**: v3.14.1
**Slug**: installer-hotfix
**Plan Type**: Bug-fix campaign
**Created**: 2026-07-16
**Goal**: A global install run from any directory (including `C:\Windows\System32`) completes with zero Python tracebacks and writes its manifest under `~/.nexus-hub/`, and a re-run silently removes the orphaned DevAI-Hub "Claude Code Auth Monitor" scheduled task so the "Can not find script file ...run-auth-monitor.vbs" popup stops.

## Overview

This is a dedicated hotfix on top of the in-flight v3.14.0 work, cut from a real user report: someone upgrading from DevAI-Hub v0.9.6 to Nexus-Hub v3.13.0 saw a Python traceback for every one of the 11 integrations during install, and has since been getting a recurring Windows Script Host popup ("Can not find script file C:\Users\<user>\.devai-hub\scripts\run-auth-monitor.vbs"). Both defects are installer-side and are independent of the codex-lb / codesight feature work, so they ship as an isolated v3.14.1 patch rather than being coupled to that scope.

Issue 1 (the tracebacks) is a manifest-path bug. For a **global** install the PowerShell and bash installers do not pass `--target` to the integration runner ([scripts/lib/integrations/runner.py](../../../../../scripts/lib/integrations/runner.py)), so `cmd_install` falls back to `Path.cwd()`. When the one-line bootstrap is run from an elevated `PS C:\Windows\System32>` prompt, the manifest write resolves to `C:\Windows\System32\.nexus-hub\install-manifest.json` and `mkdir` throws `PermissionError [WinError 5]`. The catalog content still installs correctly (each integration's global writer targets `Path.home()` directly, and the run ends with `[verify] PASS`), but the failure sits outside the per-integration try/except, so it aborts each `runner.py` subprocess with a traceback and a non-zero exit, and no manifest is ever written (which quietly breaks `nexus-hub upgrade` manifest-scoped pruning, `doctor`, and `repair`). The fix centralizes the target-root fallback in the runner so global scope resolves to `Path.home()`, and hardens the manifest write so a genuine permission failure degrades to a one-line warning instead of a fatal traceback.

Issue 2 (the popup) is an orphaned Windows Scheduled Task. DevAI-Hub v0.9.x shipped an `Install-AuthMonitor` function that registered a task named exactly "Claude Code Auth Monitor" running `wscript.exe "...\.devai-hub\scripts\run-auth-monitor.vbs"` every 2 minutes. That auth monitor was removed in commit `f473bb6`, and the `~/.devai-hub/` tree was later deleted by the Nexus-Hub rename cleanup, but nothing ever unregistered the task, so it still fires every 2 minutes against a `.vbs` that no longer exists. The fix adds a new entry to the existing legacy self-healing registry ([scripts/lib/integrations/legacy.py](../../../../../scripts/lib/integrations/legacy.py)) that unregisters the task via `schtasks` (Windows-only, no-op elsewhere, no admin required because the task is user-level), mirroring the existing `code --uninstall-extension` cleanup pattern.

Delivery: branch `fix/installer-hotfix` off `develop` per the develop+main model; both fixes land in `scripts/lib/integrations/` (auto-distributed by the integration-registry folder copy, so no installer copy-step edit and no `base-*.md` lockstep change are required); validate with the integration test suite and catalog validators; finalize under `## [Unreleased]` in [CHANGELOG.md](../../../../../CHANGELOG.md); then hand off to `/update release` for the v3.14.1 tag and GitHub Release. Already-affected users get an immediate manual remediation (below) so they are not blocked on the next release.

**Immediate remediation for already-affected users** (documented in the release notes; no admin needed):

```powershell
Unregister-ScheduledTask -TaskName "Claude Code Auth Monitor" -Confirm:$false
```

## Phase 1: Global Manifest Path + Graceful Degradation

**Goal**: A global install computes its manifest path under the user home (never CWD), and any manifest-write failure degrades to a warning rather than a fatal traceback.
**Prerequisites**: None.
**Stability Gate**: `python scripts/lib/integrations/runner.py install --scope global --integrations claude --quiet` run from an arbitrary read-only or privileged working directory writes `~/.nexus-hub/install-manifest.json`, prints no traceback, and exits 0; new regression tests pass.
**Recommended model**: Strong reasoning tier (Opus-class), medium effort. Rationale: `runner.py` is the shared entry point for every integration on both platforms, so the fix must be centralized and covered by regression tests; re-confirm against the live model set at implementation time.

### Sub-tasks

#### 1.1 - Make the target-root fallback scope-aware

**Objective**: Global-scope invocations resolve the target root (and therefore the manifest path) to `Path.home()` instead of `Path.cwd()`, at every call site.

**Prompt**:
> In [scripts/lib/integrations/runner.py](../../../../../scripts/lib/integrations/runner.py), add a single helper `_resolve_target_root(args) -> Path` with this precedence: (1) if `args.target` is set, `Path(args.target).expanduser().resolve()`; (2) else if `getattr(args, "scope", None) == "global"`, `Path.home().resolve()`; (3) else `Path.cwd().resolve()`. Replace every inline `Path(args.target).expanduser().resolve() if args.target else Path.cwd().resolve()` occurrence (the fallbacks at approximately lines 95, 126, 205, 229, 276, 358, 384, 429, 548 - covering `cmd_install`, `_template_vars_from_args`, `print_config`, `doctor`, `repair`, `list_installed`, `verify`, and any other subcommand sharing the pattern) with a call to the helper so the scope-aware behavior is uniform. Do not change the workspace path behavior (workspace installs always pass `--target`, and standalone workspace CLI use should still default to CWD). Update the `--target` argument help text so it accurately states that global scope resolves to the user home (it currently claims global is "ignored" while the code silently used CWD). Acceptance: for `--scope global` with no `--target`, the resolved root is the user home regardless of the process CWD; for `--scope workspace` the behavior is unchanged. Do NOT touch `scripts/installer.ps1` or `scripts/installer.sh` - the fix is centralized in the runner, which both installers already call, so no installer copy-step edit and no `base-*.md` change is needed.

---

#### 1.2 - Harden the manifest write against permission failures

**Objective**: A failed `manifest.save()` never aborts the runner with a traceback or a non-zero exit; it emits one clear warning and the install is still reported as successful when the content itself installed.

**Prompt**:
> In [scripts/lib/integrations/runner.py](../../../../../scripts/lib/integrations/runner.py) `cmd_install`, wrap the `manifest.save(manifest_path)` call (around line 157, which currently sits outside the per-integration try/except and therefore crashes the whole process) in a `try/except OSError as exc` that prints a single warning to stderr - for example `f"[warn] could not write install manifest to {manifest_path}: {exc}; install content is unaffected"` - and continues instead of propagating. Do the same for the `manifest.save(manifest_path)` in `cmd_teardown` (around line 190). The manifest is bookkeeping for upgrade/doctor/repair; its failure must not mask an otherwise-successful install nor produce a scary traceback. Acceptance: monkeypatching `InstallManifest.save` to raise `PermissionError` makes `cmd_install` return 0 (when no integration failed) and print the warning, with no traceback. Keep the existing `failures` accounting for real per-integration install failures unchanged.

## Phase 2: Orphaned Auth-Monitor Scheduled-Task Cleanup

**Goal**: Re-running the installer (or `nexus-hub upgrade`) silently removes the orphaned DevAI-Hub "Claude Code Auth Monitor" scheduled task and any leftover launcher files, ending the recurring "Can not find script file" popup.
**Prerequisites**: Phase 1 (so the runner - which drives the legacy cleanups - is trace-free and the manifest records the cleanup action cleanly).
**Stability Gate**: On a Windows box with the stale task present, one install pass removes it (`schtasks /Query /TN "Claude Code Auth Monitor"` returns not-found afterward); on any box without the task the cleanup is a silent no-op; new tests pass.
**Recommended model**: Strong reasoning tier (Opus-class), medium effort. Rationale: correct subprocess handling with Windows-only guards, idempotency, and dry-run parity, plus test doubles for `schtasks`; re-confirm against the live model set at implementation time.

### Sub-tasks

#### 2.1 - Add the scheduled-task legacy cleanup

**Objective**: A new cleanup function unregisters the "Claude Code Auth Monitor" task, guarded and idempotent, registered under the `claude` integration key.

**Prompt**:
> In [scripts/lib/integrations/legacy.py](../../../../../scripts/lib/integrations/legacy.py), add `_cleanup_windows_auth_monitor_task(ctx) -> Optional[FileAction]` modeled on the existing `_cleanup_claude_legacy_vscode_extension` pattern. Behavior: return `None` immediately when not on Windows (`os.name != "nt"`) or when `shutil.which("schtasks")` is `None`. Otherwise detect the task with `schtasks /Query /TN "Claude Code Auth Monitor"` (via `subprocess.run(..., capture_output=True, text=True, check=False, timeout=10)`); if the return code is non-zero (task absent) return `None`. If present and `ctx.dry_run`, return `FileAction(path="Claude Code Auth Monitor", action="removed")` without mutating. Otherwise delete it with `schtasks /Delete /TN "Claude Code Auth Monitor" /F` (timeout 30); return the `FileAction` on success and `None` if the delete fails (wrap the subprocess calls in try/except for `OSError`/`TimeoutExpired`, matching the VS Code cleanup). The task is user-level (`RunLevel Limited`), so no elevation is required. Register the function in `LEGACY_CLEANUPS["claude"]` (append after the existing three). Add `import os` at the top. Keep the module docstring's contract intact (idempotent, dry-run-aware, safe on systems that never had the artifact).

---

#### 2.2 - Sweep leftover launcher files

**Objective**: Remove any residual `run-auth-monitor.vbs` / `claude-auth-monitor.ps1` if a `~/.devai-hub/scripts/` remnant still exists (belt-and-suspenders; the `.devai-hub` tree is usually already gone).

**Prompt**:
> In [scripts/lib/integrations/legacy.py](../../../../../scripts/lib/integrations/legacy.py), extend the auth-monitor cleanup (or add a small sibling cleanup) to also `_remove_path_if_exists` for `Path.home() / ".devai-hub" / "scripts" / "run-auth-monitor.vbs"` and `.../claude-auth-monitor.ps1`, honoring `ctx.dry_run` and returning the removed `FileAction`(s). This is safe and idempotent via the existing `_remove_path_if_exists` helper (returns `None` when absent). Do not remove the whole `~/.devai-hub/` here - that is already handled by `_cleanup_devai_hub_legacy_global_dir` and must stay gated on `~/.nexus-hub/` existing. Keep `run_cleanups` returning one `FileAction` per artifact actually removed so the runner's action log and manifest stay accurate.

---

#### 2.3 - Testing and Stabilization

**Objective**: Generate and run tests for the scheduled-task cleanup. Iterate until stable.

**Prompt**:
> Extend [tests/integrations/test_legacy_cleanups.py](../../../../../tests/integrations/test_legacy_cleanups.py) with cases mirroring the VS Code extension tests, monkeypatching `legacy.os.name` to `"nt"`, `legacy.shutil.which` for `schtasks`, and `legacy.subprocess.run`: (a) task present -> a `FileAction(path="Claude Code Auth Monitor", action="removed")` is returned and the delete subprocess (`schtasks /Delete ... /F`) was invoked; (b) `schtasks` query returns non-zero (task absent) -> `None`, no delete attempted; (c) `os.name != "nt"` -> `None` with no subprocess call; (d) `shutil.which("schtasks")` is `None` -> `None`; (e) `ctx.dry_run=True` with the task present -> the `FileAction` is returned but no delete subprocess ran; (f) idempotency: a second pass (query now returns not-found) returns `None`. Also add a leftover-file test for 2.2 using the `fake_home` fixture (create `~/.devai-hub/scripts/run-auth-monitor.vbs`, assert it is removed and the action reported; assert `~/.devai-hub/` itself is only removed by the existing gated cleanup). Run `pytest tests/integrations/ -q` and iterate to green. Update the CI path-filtered job from Phase 1.3 if needed so these tests run. Do not proceed until all tests pass. After tests pass, run `/generate-session-history` to document Phase 2, and add the Issue 2 line under `## [Unreleased]` in [CHANGELOG.md](../../../../../CHANGELOG.md) (Fixed: re-running the installer now unregisters the orphaned DevAI-Hub "Claude Code Auth Monitor" Windows scheduled task and sweeps its leftover `run-auth-monitor.vbs` launcher, stopping the recurring "Can not find script file" popup; includes the manual `Unregister-ScheduledTask` one-liner for users who cannot re-run yet).
