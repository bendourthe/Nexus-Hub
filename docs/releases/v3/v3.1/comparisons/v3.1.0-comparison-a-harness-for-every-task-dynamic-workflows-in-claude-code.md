## Section 2: Source Overview

- **Title**: "A harness for every task: dynamic workflows in Claude Code"
- **Authors**: Thariq Shihipar and Sid Bidasaria (Anthropic, members of technical staff)
- **Published**: 2026-06-02
- **Topic**: Dynamic Workflows -- Claude autonomously writing a JavaScript harness that spawns and coordinates isolated subagents for a specific task.
- **Key thesis**: Long, complex tasks fail in a single context window through three predictable failure modes -- *agentic laziness* (declaring partial work done), *self-preferential bias* (preferring/trusting its own outputs when asked to verify), and *goal drift* (losing edge-case and "don't do X" constraints across turns, especially after compaction). Moving orchestration out of the context window and into an executable harness that fans work across focused subagents -- each with its own objective and isolated context -- structurally counters all three. Workflows sit "above" subagents and agent teams, are token-heavy, and should be reserved for high-value work ("does it really need more compute?").

## Section 3: Key Insights Extracted

1. **Dynamic Workflows primitive** (What Are Dynamic Workflows): Claude writes a JS harness on the fly; intermediates live in script variables off the context window; supports per-agent model selection, isolated worktrees, and crash-safe resumption.
2. **Three failure modes** (Why Dynamic Workflows): agentic laziness, self-preferential bias, goal drift -- the structural justification for fan-out + independent verification.
3. **Pattern: Classify-and-Act / routing** (Workflow Patterns): a classifier agent routes work to different agents/behaviors by task type.
4. **Pattern: Fan-Out-and-Synthesize / parallelization** (Workflow Patterns): split into steps, one agent per step, synthesize at a barrier; prevents cross-contamination.
5. **Pattern: Adversarial Verification** (Workflow Patterns): a separate verifier per output agent checks against a rubric -- combats self-preferential bias.
6. **Pattern: Generate-and-Filter** (Workflow Patterns): generate many candidates, filter/dedup by rubric, keep the best.
7. **Pattern: Tournament** (Workflow Patterns): N agents attempt the same task with different approaches; pairwise judging until a winner emerges -- more reliable than absolute scoring. Also used for **sorting/ranking at scale** (rank 80 resumes, sort 1000 tickets).
8. **Pattern: Loop Until Done** (Workflow Patterns): for unknown-volume work, spawn until a stop condition ("no new findings", "no more errors").
9. **When NOT to use + token discipline** (When NOT to Use / Technical Details): workflows are resource-intensive; most coding does not need a panel of five reviewers; set an explicit token budget ("use 10k tokens" as a hard cap); ask "does it really need more compute?".
10. **Invocation + auto-trigger**: ask Claude to make a workflow, or use the `ultracode` trigger word to ensure workflow creation.
11. **Saving & distribution** (Saving & Sharing): press "s" to save to `~/.claude/workflows`; **distribute via skill -- place the JavaScript workflow files in a skill folder and reference them in `SKILL.md`**; prompt Claude to use them as *templates* rather than verbatim scripts. Pair with `/loop` (scheduled/continuous runs) and `/goal` (hard completion requirements); `/deep-research` is a published skill demonstrating fan-out -> fetch -> verify -> synthesize.

## Section 8: Risks and Considerations

- **Redundancy with shipped work (primary risk)**: the orchestration theory already shipped today in `agent-orchestration-primitives`. The chief failure mode for this report would be re-recommending what exists. Mitigation: Section 4 marks ten of eleven insights Already Implemented with file-path evidence; only the workflow-bundle convention is a true gap.
- **Preview-feature fragility**: Dynamic Workflows is plan-gated and research-preview. Any bundled `.js` template MUST degrade gracefully (fall back to subagents / single-agent when unavailable) and be framed as a template to adapt, not a script to run verbatim -- exactly the discipline `agent-orchestration-primitives` already mandates. A bundled workflow that hard-depends on the feature would break for users without it.
- **Token cost**: bundled workflow templates invite fan-out, which is token-heavy. Each must carry the scope-first warning (calibrate on one folder, review the plan on first trigger, confirm before full scale) and cross-link `[[ai-billing-safeguards]]`.
- **Scope creep into platform commands**: `/loop` and `/goal` are Anthropic built-ins. Nexus-Hub should reference them, never attempt to ship them.
