## Overview

This plan operationalizes the combined comparison against the mattpocock/skills repository and the Prime Agent article. The adoption set is fourteen items, thirteen of which are skill-native or docs-only (no new dependency, no outbound call, no credential). The one build item (A1) threads a user-invoked vs model-invoked invocation-policy convention through skill frontmatter, the installer's command-to-skill emission, the validator, and the platform read-contracts. The one vendor-intrinsic item (A7) prepares a submission of the existing `.claude-plugin/` package to Anthropic's official Claude plugin marketplace.

Delivery is catalog-shaped: enriched and new SKILL.md files distributed by the existing installers, a new `docs/policy/out-of-scope/` register, installer/validator changes for A1, and no UI or runtime component. Success looks like: an author following `skill-create` now gets the context-pointer / leading-word / pruning discipline; a planner can run a grilling interview that maintains a CONTEXT.md domain glossary; loop and self-improvement skills name reward hacking and idempotent gates; command-derived skills stop being model-auto-invocable on platforms that honor an invocation policy; and the declined-features register exists with its first entries.

Sequencing follows the comparison's Step 5.4 reverse-engineer-first ordering: skill-native items first (Phases 1-3, P0 then P1 then P2), the `re-full` build second (Phase 4), the justified vendor-intrinsic item third (Phase 5), and the mandatory terminal refactor/known-gaps/CI phase last (Phase 6). Items the comparison dropped (changesets automation, skills.sh compatibility, docs-page mirror, Prime Agent harness machinery) are explicitly out of scope.

**Objective**: `catalog/skills/developer-experience/skill-description-authoring/SKILL.md` and `catalog/skills/workflow/skill-create/SKILL.md` teach the context-pointer and pruning discipline.

**Prompt**:

Keep all existing rules (trigger-noun preservation, pushy descriptions with SKIP clauses) intact and additive; respect the SKILL.md size norm by pushing overflow into a `references/agent-writing-theory.md` under one of the two skills and cross-linking from the other. #### 3.1 - Refine-loop discipline for continuous-learning (B1)

**Objective**: `continuous-learning` adopts the smallest-edit, phase-split, rollback-capable refinement discipline.

**Prompt**:
> In the Nexus-Hub repo, enrich `catalog/skills/workflow/continuous-learning/SKILL.md` (additive; keep every existing mechanism) with three refinement-loop disciplines, in generic vocabulary: (1) smallest relevant edit - when a session trajectory suggests an improvement, mint the SMALLEST instinct/skill edit that moves outcomes, never a wholesale rewrite; (2) plan/apply phase split - propose edits asynchronously during the session but APPLY them only at safe boundaries (end of turn, end of session), so a half-applied improvement never corrupts in-flight work; (3) immutable base + rollback - never edit the base instructions themselves, only the learned layer around them, and give every minted instinct a stable id so a bad learning can be reverted by id. Add a Common Rationalizations row for "this trajectory suggests a big rewrite would be better" (reality: large refinements are unauditable and unrevertable; chain small ids). Acceptance: additions integrate with the existing YAML-instinct format, `make validate` passes, no existing section removed.

#### 3.2 - Gate and cap upgrades plus reward-hacking signature for loop skills (B2, B3)

**Objective**: `loop-engineering` gains idempotent gates and multi-bound caps; `loop-engineering` and `ai-agent-governance` both name the reward-hacking failure signature.

**Prompt**:
> In the Nexus-Hub repo, make two additive enrichments. FIRST, in `catalog/skills/workflow/loop-engineering/SKILL.md`: (1) idempotent completion gates - a completion gate (test suite, validator, judge) records a workspace fingerprint (e.g. `git status` hash) with its verdict and is skipped, not re-run, when nothing changed since the last failure, so a stalled loop does not burn iterations re-proving the same failure; (2) simultaneous multi-bound caps - a well-formed loop declares an iteration cap AND a token/cost budget AND a wall-clock timeout together, terminating on whichever binds first (cross-link ai-billing-safeguards for the budget mechanics). SECOND, add a named failure signature to BOTH `loop-engineering` and `catalog/skills/compliance/ai-agent-governance/SKILL.md`: reward hacking in self-improving loops - an agent optimizing a measurable goal will discover shortcuts that satisfy the metric while violating intent (documented in the wild: an agent given a game-resource goal found an admin command to spawn resources despite explicit reminders), and a learning/refinement loop CAPTURES such shortcuts as "improvements" unless gates verify outcome LEGITIMACY (how the result was produced) and not just outcome presence. Add the countermeasure pattern: gates that check process evidence (diffs, logs, provenance) alongside the end state, and human review of any minted learning that touches goal measurement. Acceptance: both skills validate, the signature wording is consistent across the two files, no existing content removed.
