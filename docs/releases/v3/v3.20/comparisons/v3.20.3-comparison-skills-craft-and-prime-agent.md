## Step 1.5: Source security scan (pre-ingest)

Both sources were scanned BEFORE any content was ingested for analysis.

- **Source A verdict: CLEAR.** Grep sweep over the full clone for injection phrases ("ignore previous instructions" variants), pipe-to-shell, destructive filesystem operations, base64 decode-and-eval, reverse shells, and npm `preinstall`/`postinstall` hooks returned zero hits. `package.json` declares only two changesets devDependencies and three benign scripts. The three repo scripts (`link-skills.sh`, `list-skills.sh`, `sync-plugin-version.mjs`) are dev-only symlink/version helpers with `set -euo pipefail` and no network calls. The one guardrail script (`skills/misc/git-guardrails-claude-code/scripts/block-dangerous-git.sh`) is a defensive blocker, not an offensive payload.
- **Source B verdict: CLEAR.** The page contains no agent-directed instructions, no hidden directives, and no destructive or credential-harvesting code. It is a normal product-announcement article. Its `curl ... | sh` install one-liner is quoted content about Prime Agent's own installer and was not executed.

## Step 7: Risks, conflicts, and NOT recommended

Risks and conflicts on recommended items:

- **A1** is the highest-blast-radius item: it touches skill frontmatter conventions, the installer's command-to-skill emission (Antigravity, Kimi, Cursor, Qwen), `validate_skills.py`, and the platform read-contracts. It must be verified per platform (some SKILL.md consumers may not honor `disable-model-invocation`); where a platform ignores the field, document the gap in the read-contract rather than inventing a surface. New-file-heavy for metadata, edit-heavy for the installer: Medium risk of drift, mitigated by the existing contract-freshness gate.
- **A3** overlaps `idea-refine`, `ambiguity-detector`, and `doc-coauthoring`. The adoption must position the grilling primitive as the reusable interview engine those skills can invoke (mirroring how the source's `grilling` underlies five of its skills), not as a fourth overlapping skill. The `CONTEXT.md` glossary convention must not collide with `.claude/context/architecture.md`; it is a sibling artifact.
- **A4** rewrites guidance other skills cite; keep `skill-description-authoring`'s existing trigger-noun rules intact and additive. Per the Reverse-Engineering Attribution Rule, the distributed skill bodies use generic vocabulary; attribution to the source lives only in this report.
- **A5** ships a script-generating skill: the generated wizard template must follow `catalog/rules/bash/` safety rules and ship a PowerShell sibling per the v3.15.6+ parity gate.
- **A7** hands release-visibility timing to a sha-pinned upstream listing (the source's ADR-0002 documents the pin lagging `main`); document that the marketplace copy can trail tagged releases.

NOT recommended (with grounds):

- **Changesets release automation** (Source A, `.github/workflows/release.yml` + npm changesets): conflicts with the existing `/update release` flow and `check_version_sync.py` guard, and would add npm devDependencies to a repo whose release discipline is already machine-enforced. Bucket: `~` resolved in Nexus-Hub's favor; drop.
- **skills.sh installer compatibility** (Source A README): a third-party distribution service; Nexus-Hub owns its cross-platform installer and adding a second external install path adds a supply-chain surface for no capability gain. MCP Registry Policy decision tree: fails the trusted-vendor test (not an intrinsic data destination, capability fully covered locally). Drop.
- **Published per-skill docs-page mirror** (Source A, `.agents/writing-docs.md`): tied to the author's aihero.dev site; Nexus-Hub's SKILL_INDEX and interactive guide already serve the orientation role. Drop (the writing craft inside that doc is captured by A4).
- **Prime Agent session/daemon machinery** (B7) and **benchmark results** (B8): harness-internal and results-only respectively; nothing for a catalog to ship. Drop.
- **Prime Agent installer** (B9): already implemented (v3.7.0 bootstrap). No action.
