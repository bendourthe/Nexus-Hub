# Plan -- /presentify imagery + interactivity (professional / journalistic visuals)

**Project**: Nexus-Hub
**Version**: v3.13.0 (assumption: v3.14.0 = codex-lb-adoption and v3.15.0 = agentic-setup-adoption are in-flight drafts, so this presentify follow-on takes the next free slot; the number is reslottable at release)
**Slug**: presentify-imagery-and-interactivity
**Plan Type**: Feature / Enhancement (existing skill + command; no new skill)
**Created**: 2026-07-15
**Depends on**: v3.13.0 presentify universal-ingestion (on `develop`, unreleased); branch off `develop`.
**Goal**: Give `/presentify` a professional / journalistic visual voice through a tiered imagery system and a richer interactivity control, all commercial-use-safe and content-relevant, WITHOUT breaking the self-contained / offline / zero-external-request output guarantee or the local-first ethos. Tier 1 (LLM-native procedural visuals: original inline SVG / CSS backgrounds, duotone / gradient treatments, editorial dividers, generative textures, simple illustrations) is the ALWAYS-ON, zero-outbound default. Tier 2 (license-free stock images / video from Openverse / Wikimedia / Pexels / Coverr / Mixkit) and Tier 3 (LOCAL AI-generated images via Apache-2.0 / Open-RAIL-M models) are OPT-IN and, for any outbound path, explicit-consent-gated; every fetched or generated asset is base64-embedded at build time (so the output still opens offline with zero external requests), is verified free-for-commercial-use, is chosen for relevance to the content, and records its source / license / attribution in a visible credits block. A new "Imagery and interactivity" design question (after style, after layout) resolves the imagery tier and the interactivity level (restrained / balanced / rich scrollytelling); the interactivity level extends the existing site-wide interaction layer.

## Overview

The v3.13.0 overhaul made `/presentify` ingest anything and preserve source visuals; this plan makes the OUTPUT look and feel like a designed, journalistic web story rather than a reflowed document. Analysis of two reference pages (a C&EN "Cancer Alley" scrollytelling feature and a Stanford-style interactive data story) shows the "professional / journalistic" quality comes from four things working together: editorial typography and layout (serif body, sans headlines, big callout numbers, a neutral palette with one thematic accent, a disciplined reading measure with wider data zones), relevant full-bleed imagery placed at narrative junctures, restraint (the credible end of the spectrum avoids gratuitous motion), and purposeful interaction (hover-readout charts, click-toggle legends, zoom / pan timelines, expand / collapse, and at the richer end pinned graphics and photo-to-text scrollytelling). Crucially, MOST of that look needs no external images at all - it is typography, layout, color, restraint, and LLM-authored SVG / CSS - which is why Tier 1 is both the default and a large share of the value.

The imagery capability is authoring-stage, not extraction-stage: visuals are ADDED to the output, not read from the source, so this plan touches the skill's references, the SKILL.md design-resolution and authoring steps, the command's option / menu surface, and adds two opt-in bundled helper scripts (a license-free stock fetcher and a local AI-image generator). It does not change the content-model schema or the extractor's behavior.

The delivery is: (1) an "Imagery and interactivity" design question after style and layout, resolving the imagery tier (procedural / stock / AI, or a mix) and the interactivity level (restrained / balanced / rich); (2) a Tier-1 procedural-visual authoring rule and a scrollytelling / parallax / pinned-graphic pattern catalog, both LLM-native and reduced-motion-guarded; (3) a visual-provenance and credits convention (every non-procedural visual records source, license, and attribution, surfaced in a credits section and an HTML comment); (4) an opt-in, consent-gated stock fetcher that base64-embeds openly-licensed media; (5) an opt-in local AI-image generator; and (6) worked examples, registration sync, known-gaps, and CI coverage of the new pure-function logic.

## Policy and Offline-Guarantee Check

*GATE: Must pass before Phase 1. This feature sits on Nexus-Hub's governance boundaries, so the reconciliation is explicit.*

- **Offline guarantee holds.** The output must be a single self-contained file with zero external requests. ALL imagery - procedural, stock, or AI - is emitted as inline SVG / CSS or base64 `data:` URIs. Any fetch or generation happens ONLY at authoring (build) time; nothing external is referenced from the delivered HTML. A verification step greps the output for external references and expects none, exactly as today.
- **Local-first default.** Tier 1 is fully local and LLM-native (zero outbound, zero new dependency, no credential). Default runs and all non-interactive / headless runs use Tier 1 only. There is no silent outbound path.
- **The MCP Registry Policy hard-no list is respected.** No MCP registry entry is added. There is NO search-as-service, scraping-as-service, or generation-as-service wrapper. Tier 2 is a bundled, opt-in, consent-gated helper that makes a direct build-time HTTPS GET to openly-licensed media sources (Openverse first - a nonprofit CC / public-domain aggregator with per-file license metadata; then Wikimedia / Pexels / Coverr / Mixkit) and embeds the result; it routes only short content-derived keywords, never the source document, and only on explicit consent. Tier 3 generates images with a LOCAL model runtime (Apache-2.0 FLUX.1 schnell or Open-RAIL-M SDXL) - local compute, zero outbound; a third-party generation API (DALL-E / Midjourney / FLUX Pro / hosted SD) is explicitly OUT (generation-as-service).
- **Commercial-use safety is a first-class gate.** Every fetched asset must resolve to a free-for-commercial-use license (CC0 / public-domain preferred; custom no-attribution licenses allowed where their terms permit programmatic embedding); every asset records its license and attribution; AI-generated images record the model license and the "pure-AI output may not be copyrightable" caveat.
- **Consent + flag gating.** Any outbound path (Tier 2, and any optional cloud fallback) runs ONLY when the user passes `--images` (or answers the imagery question affirmatively) AND confirms the build-time network use; otherwise the run stays on Tier 1.
- **Installer-neutral.** New helper scripts live in the skill's auto-copied `scripts/` directory (no installer edit); new dependencies (`requests` / stdlib `urllib` for the fetcher; `diffusers` / `torch` or a local CLI for AI-gen) are lazy-imported with `pip install` hints and degrade gracefully to Tier 1 when absent. Both are `.py` (no `.ps1` sibling required).
- **Attribution Rule.** Generic descriptive naming throughout; the reference sources are named only where a user-facing credit or a license decision requires it (attribution is a legal requirement for CC-BY assets, so source names appear in the credits block by necessity, not as endorsement).

No constitution file exists at `docs/v3/v3.13/constitution.md`; this section is the informational reconciliation.

## Phase 2: Tier 2 -- license-free stock media (opt-in, consent-gated)

**Goal**: When the user opts in and consents, fetch highly-relevant, free-for-commercial-use images / video from openly-licensed sources at build time, verify the license, capture attribution, base64-embed them (output stays offline), and record credits - degrading gracefully to Tier 1 when offline, un-consented, or a source is unavailable.
**Prerequisites**: Phase 1 (the question, the credits convention).
**Stability Gate**: `scripts/fetch_stock_media.py` runs ONLY on explicit invocation with a consent flag; it queries Openverse (CC0 / PD / commercial-filtered) first with Wikimedia / Pexels / Coverr / Mixkit as configured fallbacks, filters to free-for-commercial licenses, downloads within size caps, emits base64 + a credits manifest (source, URL, license, attribution), and never raises on a missing library / network (prints a hint, exits with a degrade signal); default and non-interactive runs never call it; validators green.
**Recommended model**: Strong reasoning tier, high effort. Concrete (Claude Code): Opus 4.8, high effort. Rationale: licensing correctness and the consent / offline-default discipline are the risk surface - a wrong license filter or a silent outbound call is the failure mode. `/implement` re-confirms.

### Sub-tasks

#### 2.1 -- The stock-media fetch helper (local, opt-in, consent-gated)

**Objective**: A bundled script that turns content-derived keywords into license-verified, base64-embedded assets plus a credits manifest.

**Prompt**:
> Create `catalog/skills/specialized-domains/document-to-interactive-html/scripts/fetch_stock_media.py` (lazy-import `requests`; fall back to stdlib `urllib`; NO other dependency). CLI: `python fetch_stock_media.py --query "<keywords>" [--kind image|video] [--count N] [--license cc0|commercial] [--source openverse|wikimedia|pexels|coverr|mixkit] [--max-bytes N] [--consent] -o assets.json`. Behavior: (1) It performs NO network call unless `--consent` is passed; without it, it prints a one-line notice and exits with a documented degrade code (the authoring stage then stays on Tier 1). (2) With consent, it queries Openverse by default (the `/images` and `/audio` (and video via configured sources) endpoints with a `license_type=commercial` / explicit `license=cc0` filter), taking the top relevant results; Wikimedia / Pexels / Coverr / Mixkit are optional sources (Pexels / Pixabay need an API key from the environment, never hardcoded; absent key => that source is skipped). (3) For each candidate it VERIFIES the license is free-for-commercial-use (CC0 / PD / a documented no-attribution license), downloads within `--max-bytes`, and records `{source, url, license, license_url, attribution, author, title}`. (4) It emits a JSON manifest of `{data_uri, alt, width, height, provenance{...}}` entries (base64-embedded, so the authoring stage inlines them and the output stays offline). (5) It never raises on a missing library, missing key, network error, or zero results - it prints a hint and returns an empty manifest with a degrade note. Constraints: `catalog/rules/python/`; lazy imports; no hardcoded secret; deterministic ordering given a fixed response (document that live results vary); ASCII-only. Acceptance: without `--consent` it makes no network call and signals degrade; with `--consent` on a live network it returns license-verified base64 assets + a credits manifest from Openverse; a missing key / offline / zero-results case degrades cleanly.

#### 2.2 -- Attribution correctness and the credits manifest

**Objective**: Make the license / attribution handling correct and auditable, per the source terms.

Constraints: ASCII-only; Attribution Rule (source names appear only in the credits, as a licensing necessity). Acceptance: the license filter is documented and enforced (a non-commercial asset is skipped); CC-BY attribution strings are built correctly; the reference documents the per-source rules and the compiling-content trap.

## Definition of Done

- `/presentify` offers an "Imagery and interactivity" choice after style and layout: an imagery tier (procedural default / opt-in license-free stock / opt-in local AI-gen) and an interactivity level (restrained / balanced / rich scrollytelling).
- Tier 1 (LLM-native procedural visuals) is the always-on, zero-outbound default and produces a genuinely professional / journalistic look via editorial typography, layout, color, restraint, and original SVG / CSS visuals; default and non-interactive runs use it exclusively.
- Tier 2 fetches license-free, free-for-commercial-use, content-relevant stock images / video ONLY on explicit opt-in + consent, verifies each license, base64-embeds them, and credits them; Tier 3 generates images with a LOCAL commercially-clean model ONLY on opt-in, credits the model + copyright caveat, and degrades to Tier 1 when no runtime is present.
- The output remains a single self-contained file with ZERO external network requests (all media base64-embedded at build time); no third-party generation-as-service or paid-search-as-service is ever called; no MCP registry entry is added.
- Every non-original visual carries provenance and appears in a credits section with a free-for-commercial-use license and any required attribution.
- Registration surfaces stay consistent, CHANGELOG documents the feature, known-gaps are reconciled, CI covers the new pure-function logic, and `make validate` / `make lint` / `make test` are green.
