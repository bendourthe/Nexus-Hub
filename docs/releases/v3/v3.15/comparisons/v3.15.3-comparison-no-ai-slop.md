## What the source is

`no-ai-slop` is a single writing-editing skill distributed as an open-standard `SKILL.md` plus a small cross-harness interface stub. Its files:

- `SKILL.md` (9994 bytes): a sharp-human-editor persona with a dual-mode workflow, a catalog of 20+ named AI-slop prose patterns (each with a quoted smell and a concrete before/after fix), a banned-words list, and empty-adverb / empty-phrase lists.
- `eval.md` (3119 bytes): a pass/fail content-quality rubric the skill runs on its OWN output before returning, looping until every check passes.
- `README.md` (2035 bytes): install and usage copy.
- `agents/openai.yaml` (239 bytes): a 4-line display-name / default-prompt interface stub for OpenAI-family harnesses.
- `LICENSE` (1088 bytes): MIT.

## Step 7: Risks, conflicts, and NOT-recommended items

### Conflicts and cautions

- A1's em-dash pattern must be reconciled with the project's existing ASCII-punctuation rule and the user's stronger "no clause-joining `" - "` dashes" preference. Adopt the source's em-dash guidance as the FLOOR and keep the project rule as the ceiling; do not weaken the project rule to the source's "1-2 are fine in longer drafts".
- The source's banned-words list is opinionated. Ship it as guidance the editor applies with judgment (the source itself says "cut them when they add nothing, keep them when they carry emphasis"), not as a hard lint, to avoid flattening legitimate voice.
- Triggering overlap with `writing-editing`: give `anti-slop-editing` a pushy, specific description (trigger phrases: "make this less AI-sounding", "does this read as AI", "de-slop this", "remove AI patterns"; SKIP clause fencing off general documentation writing) so the two skills route cleanly and neither under-triggers.
