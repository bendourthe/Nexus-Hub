## Goal

Make the end of a task deliberate on every supported platform, in both directions.

1. **Notify the human only when their attention is actually required.** Today a single `Stop`-chain hook fires a desktop toast at the end of *every* conversational turn, labeled with `basename $(pwd)`. A background-driven session produces many short turns, so one long task generates a burst of toasts that carry no signal, and the label frequently names a subdirectory instead of the repository. The fix is two purposeful triggers, not one indiscriminate one.
2. **Make the agent close out clearly.** Every completed task should end with a short, factual summary of what changed and what comes next, on every platform, without the agent having to be reminded.

**Persona**: the maintainer running long, partly-autonomous sessions across several repositories and editors at once, who needs to know when a session wants them and what state it left behind.

## Definition of Done (observable)

- A permission request or a question raises exactly one notification, labeled `<repo> (<branch>)`.
- A genuinely finished task raises exactly one notification, labeled the same way.
- A sub-agent or sub-task completion raises **zero** notifications.
- A per-turn toast is no longer possible from the shipped catalog: no hook notifies purely because a turn ended without either condition above.
- The notification hook can be silenced per-invocation from something it reads at run time, verified by a test that silences it **without** relying on the process environment.
- Every substantive instruction template carries the end-of-task summary rule, and `scripts/check_base_template_parity.py` fails if any lockstep template loses or diverges on it.
- `make validate`, `make lint`, and `make test` pass; every new `.sh` has a `.ps1` sibling with asserted exit-code parity.

## Non-goals

- Changing what a notification looks like beyond its trigger and label (no custom toast art, no sound design).
- Delivering notification hooks to platforms with no hook surface. GitHub Copilot has none, and OpenCode's `plugins/` is a JS/TS Bun runtime rather than a shell/python hook host (documented non-gap DF-4). Both are recorded as permanent non-coverage, not attempted.
- Reformatting files that are already non-`ruff format` conformant (the v3.15.9 disposition stands).

## Notes for Implementers

- **A hook cannot write the summary.** By the time `Stop` fires the agent has finished generating, so a hook can only print its own text. Deliverable 2 is therefore instruction text, and a skill would under-trigger against the stated requirement of "always". Do not re-litigate this as a hook or a skill.
- **The kill switch must not be environment-only.** Measured on 2026-08-04: a User-scope environment variable read back correctly while a freshly spawned child under the running editor read it as empty, because child processes inherit the parent's environment block rather than the registry. The hook file is re-read from disk on every invocation, so a file-based switch takes effect immediately. Any opt-out that only checks the environment cannot silence a hook inside a running session.
- **Do not wire `SubagentStop`.** It is the single change most likely to reintroduce the noise this release removes, and Phase 1's test asserts its absence.
- **Verify the Google include assumption.** The Antigravity and Gemini CLI templates are 10 to 15 lines and open with `@base-google-shared.md`, which suggests editing the shared file covers all four surfaces. Confirm it rather than assuming it.
- **`ci.yml` names test directories explicitly.** A new test directory is invisible to CI until listed. `tests/plans` was in exactly that state once.
- **Environment realities on this host.** `make`, `pytest`, and `ruff` are not on PATH; invoke through `python -m`. The 2-minute tool timeout means long suites need a detached process. The repository lives under OneDrive, so filesystem-heavy integration tests are I/O-bound rather than CPU-bound and do not speed up on more cores unless fanned out across processes.
