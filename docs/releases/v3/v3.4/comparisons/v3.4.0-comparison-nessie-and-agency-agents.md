# Comparison: Nessie (nessielabs.com) and agency-agents vs Nexus-Hub

- **Date**: 2026-06-12
- **Target version**: v3.4.0 (next minor; active dev line - latest release v3.3.4)
- **Sources**:
    - Nessie - `https://nessielabs.com/` (web article / commercial tool; YC F25)
    - agency-agents - `https://github.com/msitarzewski/agency-agents` (Git repository, MIT)
- **Scope**: Nessie analyzed as an **article/concept** source (insight extraction); agency-agents analyzed as a **repository** source (multi-dimension comparison). One combined report because both sources sit in the same theme (cross-platform agent distribution + a reusable agent/context memory layer) and feed a single adoption plan.
- **Skill**: `cross-project-comparison` (per the `/compare` dispatcher). Step 5 Security and Reverse-Engineering Assessment is mandatory and is included below.

## Executive Summary

Neither source is adopted wholesale. After the reverse-engineer-first gate (Step 5), the comparison yields a small, identity-aligned plan:

1. **One genuinely novel local capability from Nessie**: a skill that **distills prior sessions into a reusable, deduped, topic-organized context pack** the next session/agent loads. Nexus-Hub has every ingredient (`session-query`, `solution-knowledge-base`, `continuous-learning`, the file-based memory system) but no single skill performs the distill-and-persist step. This is `skill-native`, zero new outbound surface.
2. **Platform breadth from agency-agents**: extend the integration registry to **Aider** and **Windsurf** (and optionally Kimi / Qwen / OpenClaw). agency-agents reaches 12+ platforms via a purely-local conversion script; Nexus-Hub reaches 9. This is `re-full`, zero new outbound surface.
3. **Source-breadth from Nessie's ingest model**: extend `session-query` discovery to additional **local** sources (Obsidian vaults, exported ChatGPT/Gemini history). `re-full`, local-only.

Dropped to the NOT-recommended list with grounds: **Nessie the product / any Nessie API** (`drop-outright` - closed-source vendor + data egress + new commercial relationship; the capability is reverse-engineerable locally), agency-agents' **personality/vibe theater and business-division breadth** (out of scope - conflicts with the engineering/security/workflow identity and the terse, verification-first skill style), and **multilingual catalog** (style-guide conflict; English ASCII-only).

Two candidate "gaps" were checked and rejected as **already implemented**: agency-agents' interactive selective-install wizard and `--dry-run` are matched by Nexus-Hub's installer (`Select-Platforms` menu, `--check`/`--dry-run`, `nexus-hub init --dry-run`).

## Source 2: Nessie (article / commercial tool)

### What it is

Nessie is a private-beta **Mac desktop app** (Y Combinator F25; founders Anna Zhang and Tiger Wang) positioned as "the context layer for AI-native work". It ingests AI chat history (ChatGPT, Gemini, Claude), local agent sessions, and Obsidian vaults; organizes them into topics and distilled notes; makes everything searchable; tracks generated contexts, profile signals, and source metadata; and lets context be reused by you, your team, and your agents. It is marketed as local-first and says it "does not store the content of your chats or notes on its servers", with local preprocessing and user control over what is uploaded. It is **closed-source commercial software**, not open source.

### Extracted insights and status

| ID | Insight (article section / claim) | Status in Nexus-Hub | Evidence |
|---|---|---|---|
| I1 | Ingest chat history across tools + local agent sessions + Obsidian into one local store | **Partially implemented** | `session-query` reads local Claude/Codex/Cursor JSONL logs (zero-outbound) but not ChatGPT/Gemini exports or Obsidian vaults; it queries, it does not build a persisted store - `catalog/skills/workflow/session-query/SKILL.md` |
| I2 | Distill history into topic-organized, deduped, reusable project-ready context you build on over time | **Partially implemented (assembled, not first-class)** | Ingredients exist - `session-query`, `solution-knowledge-base`, `continuous-learning`, file-based memory + `MEMORY.md` - but no single skill performs distill -> dedupe -> persist into a reusable context pack |
| I3 | Shareable / team memory layer reusable by you, your team, and agents | **Partially implemented** | `ShareOnboardingGuide`/`ONBOARDING.md` shares onboarding; `loop-engineering` already names an "external-memory layer" primitive; team-shared distilled context is not a first-class committed artifact |
| I4 | Keep long conversations going past context limits | **Already implemented** | `context-compression`, `context-manager`, `context-engineering`, `prompt-token-optimization`, the `nexus-context-compressor` engine |
| I5 | Nessie the product / Mac app / any Nessie cloud API | **Not applicable to adopt (vendor)** | Closed-source vendor; see Step 5 - `drop-outright` |

## Step 5: Security and Reverse-Engineering Assessment (MANDATORY)

Per the [MCP Registry Policy](../../../../../AGENTS.md) (reverse-engineer-first; Hard-No on search/embeddings/scraping/generation-as-service), every candidate is gated here before it can enter the plan.

### 5.1 Threat-model comparison

| Aspect | Nexus-Hub (current) | agency-agents | Nessie |
|---|---|---|---|
| New runtime dependencies | none added by any candidate | none (bash + coreutils, local) | closed-source Mac app; beta cloud-sync component |
| Outbound-call destinations | zero (catalog is local; policy bans service-as-X) | zero (`convert.sh`/`install.sh` are local file transforms) | uploads a user-controlled subset of chat/note data to Nessie servers; tracks profile signals + source metadata |
| Credentials / API keys | none | none | Nessie account (private beta); potential future API key |

| New commercial relationship with a third party? | no | no (MIT, self-hosted scripts) | yes (vendor SaaS) |

Reading: every agency-agents candidate adds **zero** new outbound surface. Every Nessie *concept* candidate is rebuildable locally with zero surface. Only **Nessie the vendor** introduces a third-party processor and a commercial relationship - which is exactly what the policy exists to gate.

## Adoption Plan (reverse-engineer-first ordered)

### Phase 1 - skill-native (highest value, zero code, zero surface)

- **A1 (N-B + N-C): Session-distillation context-pack skill.** A new local skill that turns `session-query` digests (and solved-problem / instinct records) into a **persisted, deduped, topic-organized context pack** - a committed markdown artifact the next session, a teammate, and an agent all load. Folds in the shareable/team angle (N-C).
    - **Target location**: new `catalog/skills/workflow/<name>/SKILL.md` (+ a thin Tier-3 script if dedupe/merge benefits from determinism); register in `data/SKILL_INDEX.md`, `data/skills.json`, `data/marketplace.json`.
    - **Cross-links**: `session-query` (source digests), `solution-knowledge-base`, `continuous-learning`, `context-engineering`, `loop-engineering` (the "external-memory layer" primitive it realizes).
    - **Conflict / risk**: none outbound. New files only (low risk). Must carry a pushy, SKIP-claused description and binary Verification per AGENTS.md.
- **A2 (C3): Selective agent-body enrichment.** Where a Nexus-Hub agent would benefit, add a concise "Success Metrics" / "Deliverable Template" section. Backlog-tier; do only where it earns its length.
    - **Target location**: specific files under `catalog/agents/`.
    - **Conflict / risk**: edits existing files (higher risk than new files); keep terse - do not import persona narration.

### Phase 2 - re-full (build internal equivalents)

- **A3 (C1): Extend platform coverage to Aider and Windsurf** (then optionally Kimi, Qwen, OpenClaw).
    - **Target location**: new subclasses under `scripts/lib/integrations/` (e.g., `aider.py`, `windsurf.py`); register each in `scripts/lib/integrations/__init__.py::_register_builtins()`. No `base-*.md` lockstep edit (these are new integrations, not template edits).
    - **Transform notes**: Aider -> consolidated `CONVENTIONS.md`; Windsurf -> `.windsurfrules`; (Kimi -> `agent.yaml` + `system.md`; Qwen -> `.md` with optional `tools`; OpenClaw -> SOUL/AGENTS/IDENTITY split).
    - **Attribution rule**: implement generically; do not name the upstream repo in shipped artifacts; record provenance only in `docs/policy/mcp-reverse-engineering-matrix.md`.
    - **Conflict / risk**: none outbound. Each new integration needs an installer dry-run verification into a throwaway dir.
- **A4 (N-A): Extend `session-query` discovery to additional local sources** - Obsidian vaults and exported ChatGPT/Gemini history files.
    - **Target location**: `catalog/skills/workflow/session-query/` bundled `scripts/discover-sessions.{sh,ps1}` (add roots) and `extract-session.{py,ps1}` (parse exported-history formats). Keep the zero-outbound invariant; `.sh`/`.py` need `.ps1` siblings (parity rule).
    - **Conflict / risk**: none outbound. Edits existing extractor (test with the hook/pytest suite).

### Phase 3 - architectural (backlog)

- **A5 (C2): Generalize per-subclass transforms into a declarative canonical->variant table.** Consider only if platform count keeps growing and the bespoke-subclass approach becomes a maintenance drag. High effort; no user-facing value on its own.
