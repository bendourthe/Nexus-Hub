## 1. Executive Summary

This is the **third** Nexus-Hub comparison against Spec Kit, covering the 17-day upstream window between the v3.6.0 snapshot (`3b6b6f9`, 2026-06-16) and today's HEAD (`bba473c`, 2026-07-02): **177 commits and 15 releases (0.11.0 through 0.12.4)**. The v3.6.0 adoption ledger is verified closed in Section 2 -- all five recommended candidates landed in v3.6.0 itself, the deferred self-upgrade candidate landed in v3.7.0 as `nexus-hub upgrade`, and the two policy declines (third-party extension install, plaintext-PAT auth framework) are durably recorded in the reverse-engineering matrix, which is exactly what kept them from re-surfacing as fresh candidates in this pass.

The upstream delta has four genuinely new systems and one loud ecosystem signal. New systems: a **`specify bundle` subsystem** (role-based composition of extensions/presets/workflows/steps into one versioned installable unit), a **`/speckit.converge` command** (assess the codebase against spec/plan/tasks and append the remaining work as traceable tasks), a set of **label-gated agentic bug workflows** (bug-assess -> bug-fix -> bug-test, each stage gated by a human applying a GitHub label, with a strict safe-outputs contract), and **GitHub Copilot native skills mode** (commands scaffolded as `SKILL.md` directories under `.github/skills/`, warned as the default in an upcoming release). The ecosystem signal: **integration roster churn** -- upstream retired Windsurf ("absorbed into Cognition Devin"), Roo Code ("extension shut down"), and iflow ("product discontinued"), and updated Kimi for the new "Kimi Code CLI". Nexus-Hub ships both a Windsurf and a Kimi integration, so this is a direct maintenance signal, not background noise.

Unlike the v3.6.0 delta (dominated by trust-boundary-crossing machinery), this delta is **mostly policy-clean**. The headline outcome: **8 recommended candidates (S1-S8), zero new declines beyond dispositions inherited from v3.6.0**. The two most valuable items are skill-native or local: the converge discipline (S1) closes a real gap in Nexus-Hub's post-implementation loop, and the Copilot native-skills surface (S3) upgrades a whole platform from behavioral-guardrails-only to a first-class per-skill distribution channel. Three items are one-sitting hardening or maintenance fixes (S2 SHA-pinning, S4 roster verification, S7 host-less URL rejection -- S7 is a confirmed live bug in `scripts/import_skills.py`). The one new surface that would cross the trust boundary (the community-installable workflow **step catalog**) inherits the v3.6.0 N1b `drop-outright` disposition unchanged.

**Overall recommendation: adopt the disciplines, skip the runtimes, verify the roster.** Every recommended item is a local file, script, or skill-body change with zero new outbound calls, credentials, or third-party processors.

- **Bundle capability, locally.** `data/bundles.json` v1.4.0 (role bundles + install profiles + capability modules) predates and exceeds spec-kit's role-only `bundle.yml` on selection granularity, with zero remote fetch. Spec-kit leads only on per-component version pinning and bundle-level provenance -- which a monorepo catalog mostly does not need.
- **Idempotency design in tasks-to-issues.** Marker-based (`[gh#<num>]`), local-authoritative, zero network -- stronger than upstream's query-GitHub approach (#2992).
- **Pre-install skill-security scanning** (`skill-security-scan` + `nexus-skill-scanner`) remains a structural advantage; spec-kit's growing community catalog (10+ new extensions this window) still installs unscanned third-party content.
- **Decline durability.** The RE-matrix rows written in v3.6.0 did their job this pass: the two dropped systems grew upstream and still required zero re-litigation.
- **CI hygiene parity already held** on shellcheck and Dependabot; only SHA-pinning (S2) was missing.

## 9. Risks and Conflicts

- **S3 frontmatter compatibility.** Copilot's skills mode rejected `mode:` frontmatter (#2819) and had non-ASCII frontmatter issues (#2917) upstream. Nexus-Hub SKILL.md frontmatter (`summary_l0`, `overview_l1`, optional framework-mapping fields) must be validated against Copilot's accepted schema before seeding; a thin wrapper SKILL.md (pointer + description) may be safer than copying catalog files verbatim.
- **S3 scope discipline.** `.github/skills/` is project-scoped and commit-visible: seeding 259 skills into user repos is unacceptable bloat. Seed a curated subset (or command wrappers only), and make it opt-in via `nexus-hub init` flags.
- **S4 evidence standard.** Spec-kit's retirements are hearsay until verified: confirm the Windsurf/Devin absorption and the Kimi Code CLI migration against vendor announcements before touching the roster (the Gemini-CLI sunset note in AGENTS.md cites the vendor blog, not a third-party changelog -- keep that standard). Note the divergence risk in the other direction too: Windsurf's guardrails file may still serve existing installs; prefer deprecate-with-note over hard deletion.
- **S1 boundary with existing skills.** Converge must not duplicate `known-gaps-tracker` (a manual per-version ledger) or `/spec analyze` (artifact-vs-artifact). Its identity is *code-vs-artifact* assessment with append-only task emission; state that boundary in the skill body to prevent trigger collisions.
- **S5 must not read as a runtime endorsement.** The skill documents a pattern whose deployment cost is a model credential in CI; the safe-outputs contract and human-label gates are mandatory parts of the pattern, and `ai-billing-safeguards` is a required cross-link.
- **Breaking changes:** none. All recommended items are additive or hardening; a backward-compatible **MINOR** bump.
