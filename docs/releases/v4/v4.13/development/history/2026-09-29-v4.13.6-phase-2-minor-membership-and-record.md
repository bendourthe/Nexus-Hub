## What this phase was for

`/implement vX.Y` must resolve its member plans from real state and hold every member's approvals in one signed record that is the only authority. v4.13.5 WN-2 and WN-3 (transport overrides and a non-origin push remote could send a push elsewhere while `approval.remote` read `met`) name this plan as owner and sit on the same code path, so they were closed here.

## Steps taken

1. **T012-T014**: `vX.Y` is a scope token in `catalog/commands/implement.md` "Argument resolution", mirrored in the implement-phase skill and runbook without restating the driver loop; malformed tokens (including leading zeros) and per-plan mode tokens after a minor print usage.
2. **T015-T017**: new `scripts/completion_minor.py`, dispatched from the checker and registered in both installers. `members vX.Y` globs canonical, legacy, and archive layouts, excludes shipped plans (tag local and remote with a published Release) and plans owned by another live run (a per-plan record found by key or content, a runner lock, another live minor record, or an unmerged local, remote-tracking, or remote `feat/<version>-*` branch), sorts by integers, and reports exclusions on stderr. An `ls-remote` failure makes ownership undecidable and blocks. An owned plan is excluded and reported, not treated as a blocker (Deviations).
3. **T018**: schema-2 minor record with a schema-dispatching loader (schema 1 unchanged), `scope`, `minor`, members identified by version, the four minor approval classes, run-wide `spend` and `unattended-with-bypass`, an extended HMAC payload, a new record key (`sha256(root, owner/repo, plan:<path> | minor:vX.Y)`) with the legacy key still read, `project()`, a plan hash that excludes only a bare header Status value, `record retire`, a minor runner lock, one authority in both directions, a live minor record that a second session cannot overwrite, and a resume in a new session through the exact-paste binding.
4. **WN-2 / WN-3**: `repo_host.verify_push_route` treats transport overrides as `cannot-verify` (ssh command overrides, remote helpers and `::` URLs, `GIT_EXEC_PATH`, `curloptResolve`, anything weakening TLS verification, and an `insteadOf` rewrite that changes the verified repository), probes ssh as git does (`ssh -G [-p port] user@host` with git's own ssh), and requires the effective push remote to be origin. A proxy with TLS verification intact is not an override.
5. **T019**: the completion contract owns the record schema, membership, one-authority rule, retire rule, and push route.
6. **T020**: `tests/validators/test_completion_minor_record.py` (114 tests) plus new cases in `test_check_plan_completion.py` and `test_repo_host.py`.

An adversarial review found 12 defects (8 reproduced, 4 high: ssh `Match user` blocks, `remote.<name>.vcs`, an off-key per-plan record invisible to the minor run, and unhashed text on a Status line); all 12 were fixed with regression tests.

## Deviations

- Sub-task 2.2's failure mode says an owned plan blocks the minor run, while Definition of Done 1 and the Verification Expectation exclude it and still record. The implementation follows Definition of Done 1: excluded and reported; only a frozen member that later becomes owned stops the run.
- Git for Windows' system-scope `http.sslBackend` and CA bundle are not overrides, because counting them would make every Windows install `cannot-verify`; CA settings in global, local, worktree, or command scope are.
