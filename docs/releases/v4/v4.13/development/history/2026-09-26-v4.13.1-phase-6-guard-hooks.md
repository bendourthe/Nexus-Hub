## What this phase was for

On hook-capable platforms, enforce the two rules without relying on the agent remembering them: block a change onto a user-edited file (warn inside a git worktree), and block AI attribution on every publishing route.

## Steps taken

1. **Design: logic in Python, thin shell adapters.** Both hooks put every decision and every message in Python that already ships with the install: a new `hook` subcommand of the skill's `edit_guard.py` (flattened with the skill) and a new `scan` subcommand of `scripts/nexus_git_attribution.py` (already copied to `~/.nexus-hub/scripts/`). No installer edit was needed. Each `.sh`/`.ps1` pair only applies the user's disable switch, forwards stdin byte for byte, enforces the time budget, and applies the "Python unavailable" fallback. Because both siblings relay the same Python process, their stderr is identical by construction, not by keeping two regex sets in step.
2. **T013 `user-edit-guard`** (`catalog/hooks/user-edit-guard.{sh,ps1}`, `edit_guard.py hook`).
    - PreToolUse on Write, Edit, and Bash (and Cursor's Shell tool): `check` each existing target. Bash destinations are parsed with `shlex` from `cp`, `mv`, `install`, `rsync`, `Copy-Item`, `Move-Item`, `tee`, `shutil.copy`, and `>`/`>>` redirection, resolving a directory destination to the copied file name. Exit 3 or 4 blocks outside a git worktree with the plan's fixed message and warns inside one; exit 5 or an error gives the "cannot verify, ask the user" message with the same block/warn split.
    - PostToolUse: Read records `--from read` (and warns when the file changed since the last record), Write and Edit record `--from write`. For Bash, the pre step writes a per-session start marker; the post step re-records every destination plus every tracked file under the working folder whose modification time is after the marker and whose fingerprint changed.
    - Budget: 2 seconds (`NEXUS_EDIT_GUARD_TIMEOUT_SECONDS`). On timeout, missing Python or helper, or a helper crash, a write-like payload is blocked outside a worktree and warned inside; post steps and non-writing payloads pass.
    - Only a truncated (120-character), control-stripped path is printed. Warnings also go to stdout as `hookSpecificOutput.additionalContext` so the agent sees them.
3. **T014 `attribution-guard`** (`catalog/hooks/attribution-guard.{sh,ps1}`, `nexus_git_attribution.py scan`).
    - Routes: `git commit` and `git tag` (`-m`, `--message`, `-F`, `--file`), `gh pr|issue|release create|edit|comment|review|merge` (`--body`, `-b`, `--notes`, `--title`, `--body-file`, `-F`, `--notes-file`, and `--fill` by reading `git log <base>..HEAD`), `gh api` body fields (`-f`/`-F body=...`, `@file`), heredoc bodies anywhere in the command (including Claude Code's `-m "$(cat <<'EOF' ...)"` form), and the GitHub MCP tools (`mcp__github__*`, `mcp__plugin_github_github__*`).
    - Patterns reuse `TRAILER` and `AGENT` from the existing script: an agent-naming or vendor-noreply `Co-authored-by` trailer (a human co-author passes), any `made-with`/`generated-by`/`ai-generated`/`claude-session` trailer, a line-start generated/made/created with or by `<vendor>` footer in the last six non-empty lines, and robot badges (the emoji or `:robot:`). The block message names the pattern id and at most 80 ASCII, control-stripped characters of the matched line.
    - A body file that is missing, not a regular file (FIFO, device), over 1 MB, named by an unexpanded variable, or read from stdin without a heredoc warns "cannot verify body" and passes; a device or FIFO is never opened (`lstat` first). A Write or Edit to `CHANGELOG.md` or `docs/` warns on the same patterns. Budget 5 seconds (`NEXUS_ATTRIBUTION_TIMEOUT_SECONDS`), with the inner `git log` capped at 3.
4. **Registration and essential status.** `catalog/hooks/settings.json`: `user-edit-guard` joins the `Write|Edit|Bash` PreToolUse group and gets a `Read|Write|Edit|MultiEdit|Bash` PostToolUse group; `attribution-guard` gets a PreToolUse group matching `Bash|Write|Edit|MultiEdit|mcp__github__.*|mcp__plugin_github_github__.*`. Both ignore `NEXUS_HOOK_PROFILE=minimal` and honor only the user's `NEXUS_DISABLED_HOOKS`; both were added to the essential exclusions in `test_hook_sibling_parity.py` and to the Cursor-import compatibility list (`test_cursor_import_compat.py`). Hook count 35 to 37 in `AGENTS.md` and the three current-state lines of `README.md`. CHANGELOG `Added` entries for both hooks.

## Troubleshooting

### The Windows Store Python lives under WindowsApps

The first adapters skipped any interpreter under `WindowsApps` to avoid the Store alias, and failed closed on this machine, whose only Python is the Store build in that folder. The adapters now probe a `WindowsApps` candidate once with `-c "import sys"` and use it if it runs. PowerShell 5.1 drops an empty-string argument to a native executable, so the first probe (`-c ""`) became a bare `-c` and failed; the probe argument is non-empty in all four adapters.

### An optional Office library crashed detection

`python-pptx` raised `AttributeError` on a minimal archive, which escaped `_office_text` and crashed both `diff` and the non-text check inside `check`. `_office_text` now falls back to a standard-library reader (text runs per content part from the archive XML) whenever the library is missing or fails, so an optional library can improve the diff but never break detection.

### Parallel formatter hooks raced the post-write record

Claude Code runs an event's matching hooks in parallel, so the post-write record could snapshot a file a moment before `auto-format-on-write` or `lint-on-write` rewrites it, and the next check would report the formatter's change as a user edit. The hook's pre-check (not the CLI `check`, which stays strict) treats a change as agent-caused when the last record came from the agent's own write or command and the file's modification time is within 5 seconds of it, re-records it, and logs a `settled` event. The residual risk is a genuine user edit landing within those 5 seconds, accepted and covered by `test_user_edit_after_the_settle_window_still_blocks`.

### The machine's own Git attribution hook refused a fixture commit

The `--fill` test needs a range that already holds an attributed commit, and the installed global attribution hook correctly refused to create one. The fixture sets `core.hooksPath` to an empty folder for that throwaway repository only.

### The full profile caught drift the fast profile never runs

Phases 3 to 5 ran only the fast profile, so three drift checks went stale unseen, and four test groups failed downstream of them or of one missed count:

- `build_legacy_fingerprints --check`: the Phase 4 skill changed an input; regenerated (`scripts/lib/installer/legacy_fingerprints.json`).
- `stamp_guide_counts --check`: the website guide said 337 skills and 31 hooks; restamped to 338, 33, and 18 pre-action hooks.
- `check_handbooks.py`: the distribution handbook declares `scripts/nexus_git_attribution.py` as an input. Its claims were reviewed (an addendum in `distribution-handbook-attribution-ban-review.md`), `build_presentation.py --check` reproduced the same output bytes, and the input hash and content receipt were refreshed.
- `tests/skills`: `data/marketplace.json` and `.claude-plugin/plugin.json` still described 337 skills, a count Phase 4 missed; both now say 338.
- The integrations-install, guides, and governance groups passed on rerun once the drift above was repaired.

### Fixtures were not Office archives

Text written into `.pptx` names is rightly refused as an unreadable archive. The tests build minimal zip archives with a slide part, which also exercises the per-content-part fingerprint.

## Plan delta

**Disposition: Minor delta, recorded.**

- The settle window is an addition the plan did not name; it is the answer to the plan's own "conflicting operations" failure mode once parallel hook execution is taken into account.
- The attribution guard's budget is 5 seconds rather than the edit guard's 2, because `--fill` runs `git log`; the plan set a 2-second budget only for the edit guard.
- The Windsurf Cascade hook map (`scripts/lib/integrations/windsurf.py`) was not extended: it translates hooks to Cascade's own events and payloads, a separate integration surface outside this phase's `settings.json` channel.
