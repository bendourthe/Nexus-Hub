## What this phase was for

`/implement <plan> full` existed, yet full runs stopped partway because the stops were written into the procedure: a per-phase confirmation, a per-phase closing summary that read as "done", a stop on context exhaustion, and fresh approval prompts for push, merge, release, refactor moves, and CI changes. This phase made the full driver the default, moved every approval to one upfront round recorded in the run record, and made each approval point read that record.

## Queue re-assessment (phase entry)

No drift. Prerequisite Phase 2 is committed (`e16a527a`). The touched files (`catalog/commands/implement.md`, the implement-phase skill and runbook, the final-phase template, and the approval steps of `project-refactor`, `docs-layout-refactor`, and `cicd-architect`) are not edited by any queued plan in flight.

## Steps taken

1. **Command default** (`catalog/commands/implement.md`). `/implement <plan>` and bare `/implement` run the full driver; one phase needs `phase <N>` or `next`; `phase-by-phase` stays opt-in; `full` and `in-full` remain aliases; bare resolution picks the lowest queued plan by semantic version whose queued predecessors are merged, and asks when ambiguous; `/implement pause` pauses and `/implement <plan>` resumes. A new "Upfront round and completion" guarantee names every approval class, states that CI workflow, permission, and secret changes are never pre-approvable, and refers to the completion contract for what "done" means.
2. **Driver** (skill and runbook). A new Phase 0a runs the upfront round, shows any open blocker or pause, records answers with `check_plan_completion.py record create`, and prints the interactive goal line where a platform's goal is interactive-only. In full mode the per-phase confirmation is replaced by the round, model routing confirms automatically unless an upshift is needed, the closing summary becomes one progress line, and the driver stops only on a terminal verdict. Context pressure is handled by compaction and the runner.
3. **Record-aware approval points.** 9.0 duty 1, the 9F push, re-push, and merge steps, the final-phase template (refactor, CI, push, re-push, merge), `project-refactor`'s gate, and `docs-layout-refactor`'s Step 7 accept "explicit approval, or the matching approval recorded in the run record"; `cicd-architect`'s approval step states that a run record never covers a pipeline, permission, or secret change.
4. **Version-scoped evidence file.** Five catalog files and three lifecycle tests now name `<version_dir>/development/<version>-last-phase-evidence.md`.
5. **Registry.** `data/skills.json` carries the updated `implement-phase` description and overview (the overview is 164 words, down from 166).
6. **CHANGELOG** `Changed` entry for the new default and how to run one phase.
