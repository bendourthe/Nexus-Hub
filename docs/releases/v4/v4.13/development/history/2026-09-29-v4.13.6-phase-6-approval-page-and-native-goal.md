## What this phase was for

One paste now authorizes several releases, deletions, and an archive, so the page the user reads before pasting must say, in everyday words, everything the paste approves. On a platform where a typed `/goal` reaches the capture hook, the same line also sets the native goal.

## Steps taken

1. **T045**: `catalog/skills/workflow/implement-phase/references/approval-page.md` is the single template: the two biggest effects first, the steps in order, what changes on GitHub (labelled as today's estimate), gaps to fix and gaps that may move, what you are approving, what it never does without asking, spending, how to stop, the paste line, and the plan data in one fenced block after it.
2. **T046**: `scripts/approval_page.py` is the single renderer and reads only the canonical JSON that `record render` binds, so the page and the code cannot disagree. `record render --page --platform <row>` prints it. The "What you are approving" section has one sentence per approval class with a strictly validated bound; an unknown class or a malformed bound renders nothing. Plan titles and gap text sit only in the fenced details block, JSON-quoted with backticks and tildes escaped. The page is rendered before the pending round is written, so a failed render never supersedes the user's previous valid round.
3. **Paste shapes** follow `goal_capture`: `verbatim` gives one `/goal` line that approves; `not-captured` gives the plain approval line, then a separate `/goal` line; `no-goal`, `unverified`, and unknown platforms give the plain line, plus an optional `/goal` line where a goal command exists. Only the approving line's digest is bound. The goal condition names the verdict line (`MINOR COMPLETE v0.5`, or `PLAN COMPLETE` followed by the plan file) and carries no path, script name, nonce, or plan text.
4. **T047-T048**: both installers copy `approval_page.py`; the handbook evidence hashes were refreshed.
5. **T049**: `completion-levers.md` states that the native goal is advisory and the deterministic checker decides done, and that on Codex, with no deterministic Stop gate, the goal's judgment is not the definition of done.
6. **T050**: runbook step 4 ends the page with the paste line.
7. **T051**: `scripts/run_plan.py` launches the resumed session with the goal line headlessly for Claude Code (`claude -p ... --continue --output-format stream-json --verbose`), Qwen, and Kimi, from the vendor pages recorded in `completion-levers.json`. Kimi's documented goal exits 3 and 6 count only when the checker then reports BLOCKED or PAUSED. Copilot CLI slips per the cut-line: its documented headless path needs `--yolo`, which the runner refuses, so it keeps the printed interactive line, as do Codex, Cursor, Antigravity CLI, Hermes, and OpenClaw.
8. **T052**: `tests/validators/test_approval_page.py` (94 tests): every shape for a plan and a minor, banned jargon above the paste line, a 25-word sentence ceiling, the first section naming releases and deletions, paste lines under 300 characters, injection fixtures (HTML, links, fences, fake paste lines, bidi characters), every approval class producing a sentence, and headless launch argv.

An adversarial review found that the page omitted most bound approval classes (including `unattended-with-bypass` and the push target), that plan text was not escaped for Markdown or HTML, and that fixed wording could overstate releases. All six findings were fixed with regression tests.
