## What this phase was for

A turn-end gate keeps a live session going, but every platform eventually ends a turn anyway: Claude Code, Qwen, and Copilot CLI after 8 consecutive blocks, Cursor after 5, OpenClaw after 3 revisions, or on a crash. The runner is the layer that continues past that, by relaunching the platform's headless CLI with its documented resume flag until the checker's verdict is terminal.

## Queue re-assessment (phase entry)

No drift. Prerequisites (Phases 2 and 3) are committed. `scripts/nexus_hub_cli.py` and the installers are not edited by any queued plan in flight.

## Steps taken

1. **Runner** (`scripts/run_plan.py`, exposed as `nexus-hub run-plan <plan> --platform <row> [--max-cycles N]`). Hard-coded launch and resume templates for the 15 rows whose headless lever is VERIFIED in `docs/policy/completion-levers.json`; the matrix decides which rows are offered but is never read for flags. After each cycle it runs the checker: a terminal verdict ends the loop; `INCOMPLETE` with a higher met count relaunches with resume; three cycles without progress write a `no-progress` blocker; a CLI that fails twice on the first cycle writes `platform-unavailable`.
2. **Headless goals.** On Claude Code, Qwen, and Kimi the first cycle is `/goal ...` naming the checker's `PLAN COMPLETE` line and the run nonce, the three platforms whose docs show a headless goal entry point. Elsewhere the first cycle is `/implement <plan>`, and the upfront round prints the interactive goal line.
3. **Safety.** No template carries a permission-bypass or config-override flag (a per-row denylist is asserted in tests, and `check_argv` refuses an injected one); the runner refuses to launch when the platform's own config bypasses approvals (Claude `defaultMode: bypassPermissions`, Codex `approval_policy = "never"` or `danger-full-access`, Gemini CLI and Qwen `approvalMode: yolo`) unless the user approved `unattended-with-bypass` upfront; plan paths must match `docs/**/plans/*.md` with a safe-character allowlist; a Windows `.cmd` shim never receives cmd metacharacters; one runner per record by lock; every launch is an argument list.
4. **Never creates approvals.** The runner requires an existing run record, found through a new `check_plan_completion.py record path <plan>` subcommand, so the key formula has one owner.
5. **CLI and installers.** `nexus-hub run-plan` forwards to the installed script; both installers copy `run_plan.py`.

## Troubleshooting

### Windows paths leaked into the agent's prompt

The first run showed `/implement docs\releases\...` in the prompt: `str(Path)` on Windows. Prompts now use the POSIX form, and the test asserts the exact launch and resume prompts.

### `typing.Self` would break Python 3.10

The lint rule for context-manager return types suggests `typing.Self`, which needs Python 3.11; the installers support 3.10. The annotation stays the class name, with a targeted suppression that names the reason.
