# v4.13.10 Phase R38 (Revision 11)

Maintainer review: a web page cannot open a terminal or run a command, so the Home installation opens on the visitor's system and gives one large copy button instead of a one-click install.

## Scope

- The install section in `guides/website/nexus-hub-guide.html` has three tabs, Windows, macOS, and Linux, on the existing `data-tabs` widget with `role="tab"`, `aria-selected`, `aria-controls`, and arrow, Home, and End keys; macOS and Linux carry the same curl command.
- Detection reads `navigator.userAgentData.platform` first, then `navigator.userAgent` and `navigator.platform`: Windows (Windows, Win32, Win64), macOS (Mac, iPhone, iPad, iPod), and Linux (Linux, X11, CrOS, Chrome OS, Android).
- A match selects that tab and shows a "Detected: <OS>" caption beside the tabs; no match keeps Windows selected with no caption, which is also the no-script state.
- A manual tab choice (click or keyboard) is stored in localStorage under `nexus-hub-guide:install-os` inside try/catch; a stored valid choice beats detection, an unknown stored value is ignored, and detection alone never writes.
- Each tab gives two numbered steps: open the terminal (the system's shortcut shown as keycaps), then copy and run with a large "Copy install command" button, the terminal mockup with the exact command under it, and "Paste it into the terminal and press Enter."
- The button reads its command from that panel's `code[data-copy]`, so each command exists once per panel; it shows a check and "Copied" and announces "Copied to clipboard" in `#nhg-copy-status`; the install terminal no longer adds a second small copy chip.
- The intro now introduces the two steps and keeps the facts about `~/.nexus-hub/`, wiring detected assistants, and preserving customized files; the verification steps follow on as 3 and 4 (`start="3"`), and Troubleshooting is unchanged in content.
- The commands are byte-identical and the installer is untouched; typography comes only from `data-ty` roles, with no accent stripes or eyebrow labels.

## Troubleshooting

- The copy button label rendered teal on teal because the later `h4` role colour outranked `.install-copy`; the rule is now `.nhg-install-wrap .install-copy`.
- At 390 px the install command and the Troubleshooting wget command scrolled sideways; both now wrap with `overflow-wrap:anywhere`, which removes every horizontal scroll bar in the section.
- The stored-choice test reseeded localStorage on reload through its init script; it now seeds once per tab session.
- `phase6_verification_sweep` expected ArrowRight to land on "macOS / Linux"; it now expects the tab after whichever one opened, because the opening tab follows the host system.
- The edit guard flagged the guide and the test file from stale records; `git status` was clean at HEAD 1a9dd6f85, so there were no user edits to carry forward.
