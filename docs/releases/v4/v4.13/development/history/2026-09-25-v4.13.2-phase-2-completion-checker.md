## Troubleshooting

### Two string replacements matched nothing and reported success

A scripted edit meant to thread a `plan=` parameter through the fixture builder missed both anchors, so `test_task_needs_a_commit_touching_its_path` exercised the default plan and reported complete. It was caught only because the assertion failed. Fixed with line-anchored edits and confirmed by re-reading the lines. The same failure mode is why the repository's HTML rules require asserting an anchor is present and unique before replacing.

### The first run took 405 seconds for 16 tests

Each fixture build made about ten commits, and `git init` plus one commit took 5.4 seconds on this host against 0.04 seconds for `git --version`. The developer's global git configuration runs commit hooks. An autouse fixture now points `GIT_CONFIG_GLOBAL` at an empty file with `GIT_CONFIG_NOSYSTEM=1`, which took one commit to 0.14 seconds and makes the tests independent of host git configuration. The full suite now runs in about 90 seconds.

### The bash installer cannot complete on Windows

The throwaway install through `scripts/installer.sh` under Git Bash exited 2 while building the MCP server venv, because it calls `$venv_path/bin/python` and a Windows venv puts the interpreter in `Scripts/`. This predates the plan; the PowerShell installer is the Windows path and was used for the install check instead.
