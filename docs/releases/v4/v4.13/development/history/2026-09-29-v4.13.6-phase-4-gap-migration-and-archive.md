## What this phase was for

A minor run fixes what it can in a bounded gap scope, migrates the rest with bound ids and provenance, and archives the closed minor without losing its member plans. A lost or falsely closed gap is silent, so the checker must refuse anything it cannot parse.

## Steps taken

1. **T029**: Migrate mode in `catalog/skills/workflow/known-gaps-tracker/SKILL.md`, backed by the new `scripts/minor_close.py migrate` (registered in both installers). An item migrates only when its id is in the record's frozen list (and named individually when it is security or high severity), with a reason from `vendor-feature`, `user-credential`, or `user-deferred`; the target entry carries `- **Migrated from**: <minor>#<id> on <date> (reason: <reason>)` and the source heading ends ` - MIGRATED to vX.Y.0`.
2. **T030**: `gaps.minor` in `scripts/completion_minor.py` covers every ledger for versions at or below the run's minor (canonical, legacy, archive). The parser reads item headings at levels 3 to 6 with alphanumeric id suffixes, follows CommonMark fence rules, accepts RESOLVED or CLOSED only at the end of a heading, and returns `cannot-verify` for an id-like row it cannot parse, a header count that disagrees, or an unclosed fence. A migration verifies only when it moves forward to a later minor's `.0`; beyond the run's minor only the next minor is accepted. A ledger is excluded only for live work of another run (a worktree, a live record, or an open pull request), never for the run's own minor, and an excluded ledger with open items is `cannot-verify`.
3. **T031**: the completion contract's "Minor gaps and archive" section owns `gaps.minor` and `archive.minor`.
4. **T032**: "Archive a closed minor" in the docs-layout-refactor skill, with the refusal table and reference classes in `references/archive-closed-minor.md`, backed by `minor_close.py archive --dry-run|--apply`. It refuses on any failed closure condition or a plan bound by another live record, moves with `git mv`, repairs links everywhere and plain mentions only in an allowlist (never inside URLs, code, or `docs/archives/**`), runs the link baseline before and after, commits once, and rolls back on any error. `--confirmed` works only without a record.
5. **T033**: `/update release` step 2a2 runs the archive under the `archive-minor` approval and otherwise keeps reporting and asking.
6. **T034**: `tests/validators/test_gap_migration_and_archive.py` (56 tests).

An adversarial review reproduced three false-close paths (a self-migration marker, level-3 and non-numeric ids invisible to the parser, and a stale branch excluding a ledger) and three archive defects (rewritten permalinks and archived evidence, no rollback on a mid-repair error, and `--confirmed` overriding a record). All ten findings were fixed with regression tests.

## Deviations

- The plan says only the next minor is a migration target; a strict reading would make a later run unable to finish, because earlier minors' forward migrations sit inside its scope. Forward migrations into an in-scope minor are accepted and judged on their copy; beyond the run's minor only the next minor is accepted.
- On this repository, 30 of 41 in-scope ledgers read `cannot-verify` under the stricter parser; recorded as v4.13.6 WN-2 for normalization before the first real minor run.
