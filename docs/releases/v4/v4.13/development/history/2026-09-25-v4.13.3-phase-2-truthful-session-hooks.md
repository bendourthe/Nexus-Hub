## What this phase was for

Every session Nexus-Hub started was told it ran v1.1.5 with 184 skills and 33 commands, and was pointed at two commands removed in v3.2.0. The session hooks also repeated the git log the harness already supplies, once at start and once in the digest. This phase made both hooks state only facts read from real files, one line each.

## Queue re-assessment (phase entry)

No drift. The four hook files are touched by no queued plan in flight; v4.13.2's hook work is confined to its new `completion-gate` and `approval-capture` hooks and the settings registry.

## Steps taken

1. **T009-T010, banner.** Both `session-start` implementations resolve `${NEXUS_HOME:-$HOME/.nexus-hub}` once and print one line, `Nexus-Hub v<version> active; full skill index: <home>/data/SKILL_INDEX.md`. The version appears only when `VERSION` is one line of at most 32 characters matching `^[0-9]+\.[0-9]+\.[0-9]+([-+][0-9A-Za-z.]+)?$`; any other payload drops the version and is never echoed. The branch, status, and three-commit block became `Git: <branch>, <n> changed file(s)`, or `Git: unavailable` outside a repository or without git. The digest read and its `NEXUS_SESSION_START_MAX_CHARS` cap are unchanged.
2. **T011-T012, digest.** Both `session-summary` implementations replace the branch, status, and five-commit block with the same one git line (`detached` for a detached HEAD). The `.ps1` now writes with `[System.IO.File]::WriteAllText` and `UTF8Encoding($false)` plus the `.sh` sibling's trailing newline. `NEXUS_SESSION_DIGEST_NOW` fixes the timestamp for tests.
3. **T013-T014, tests.** New `catalog/hooks/tests/test_session_start.py` (parametrized over both implementations): valid, prerelease, and CRLF versions; missing, empty, multi-line, over-long, non-semver, and two-part payloads dropped without echo; no counts or removed commands; one git line inside and outside a repository. `test_session_digest.py` gains a both-implementation check of the git line in the clean, dirty, detached, and non-repository states, and a byte-identity plus BOM check; two older assertions moved to the new format.

## Troubleshooting

### The digests differed by one trailing blank line

Before this phase the `.sh` digest ended with an extra blank line the `.ps1` did not write, and the `.ps1` added a UTF-8 BOM on PowerShell 5.1. Both were fixed while restructuring the output, so the two digests are now byte-identical, not only equal after normalization.

### Two string literals were mangled by the edit tooling

A scripted test edit turned `"x\n"` and a byte-order-mark literal into raw characters, which broke collection. They were repaired by line position and confirmed by lint and a passing run.
