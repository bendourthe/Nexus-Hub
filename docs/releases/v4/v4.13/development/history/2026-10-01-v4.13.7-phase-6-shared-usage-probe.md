## What this phase was for

One stdlib-only module that returns per-window usage for Claude Code, Codex, Cursor, and Copilot, so the Phase 7 guard can act at the threshold without each platform reimplementing the read.

## Execution order

Phase 6 ran before Phases 1 to 3. Its Copilot provider reads only the monitor's percentages-only state file, whose schema the plan settles in decisions item (6); a fixture built from that schema stands in until Phase 2 writes the real file.

## Steps taken

1. **T027**: `catalog/hooks/_usage_probe.py` exposes `probe(platform)`, which never raises and never writes to stdout, and a CLI (`--platform <key> --json`, exit 0). Results carry `status` (`ok`, `stale`, `unavailable`), `cached`, `fetched_at`, windows (`name`, `percent`, `resets_at`, `source`), and a fixed-text `reason`. The cache under `~/.nexus-hub/state/usage-probe/` holds percentages and reset times only, lives 300 s (60 s once a window reaches 90%), and is written atomically. A failed fetch returns the last value as `stale` when it is under 30 minutes old and backs off the network for 60 s. The whole fetch, credential read included, runs under a 3-second wall-clock deadline.
2. **T028**: providers. Claude Code reads `~/.claude/.credentials.json` (or the macOS Keychain under the same deadline) and maps `five_hour` and `weekly` (the highest of the seven-day windows). Codex reads `auth.json` and maps the 7-day window by length. Cursor reads one allowlisted key from `state.vscdb` opened read-only and maps the monthly percentage. Copilot reads the monitor's state file with no network call. Each provider may call only its own vendor host over https, and redirects are refused so the token never follows one.
3. **T029**: `catalog/hooks/tests/test_usage_probe.py` (109 tests), including a leak test that records every cache write, scans the test folder and new files in the system temp folder, matches any 12-character slice of each fixture secret, and walks error chains.
4. `scripts/lib/integrations/_hooks_common.py` now ships every `_*.py` helper a delivered hook imports (comma lists, aliases, literal `importlib.import_module`, transitive imports, and helpers a shell hook runs), so Codex, Copilot, Antigravity, and Windsurf also receive `_skill_rules.py` beside `skill-activation-suggest.py`.

An independent security review found no token leak and six defects: an out-of-range reset date that broke the probe and discarded the stale value, a leak test that missed three of six planted leaks, a per-read rather than total timeout, unchecked cached text fields, a shared host allowlist, and import forms the helper scan missed. All six were fixed with regression tests; the rebuilt leak test catches each of seven planted leaks.

## Verification expectation

A read-only probe on this machine returned, as percentages only: Claude Code `five_hour` 59% and `weekly` 85%, Codex `weekly` 100%, Cursor `monthly` 95.51%, and Copilot `unavailable` ("state file missing (Copilot Usage Monitor not running)"). Repeating within the cache window returned the same values with `cached: true`.

## Deviations

- The Verification Expectation named the weekly window `seven_day`; the plan's 6.1 and decision (3) name it `weekly`, which the probe uses, and the expectation text was corrected.
- A 60-second network backoff after a failed fetch is not in the plan; without it an offline machine would wait the full timeout on every tool call.
- Cursor's curated hook list must gain `_usage_probe.py` when `usage-guard.py` is added in Phase 7.
