## 2. Chronological Steps

### 2.1 Create size headroom

The maintainer chose to preserve the 500,000-byte ceiling. The 32x32 favicon PNG was losslessly recompressed, with decoded pixel equality. The inline room WebP was re-encoded and inspected at native and 2x scale against the original; the paired captures are in `../training-rebuild/`. The two asset changes saved 5,652 normalized bytes before engine additions. Three asset/guide checks passed. No commit was made before the Phase 1 gate.

### 2.2 Extract the instance factory

The first factory test failed because `window.NexusShooter.instances` was not a function. The arcade now creates one closure per `[data-arcade-game]` root, keeps instance state and listeners inside that closure, and exposes named registry access while preserving the legacy singleton methods for existing consumers. Shared spawn, collision, fixture, and painter helpers stay module-scoped and stateless. The existing game has ID `buggy`. A two-root browser fixture proves stepping one game does not advance the other. A second red test found that duplicate IDs silently overwrite registry lookup; a preflight guard now rejects the collision before any instance is constructed. No commit was made before the Phase 1 gate.

### 2.3 Add viewport lifecycle and disposal

An offscreen test first failed because `offscreen` was absent from `pauseReasons`. The observer now pauses and resumes each instance separately. Disposal cancels its frame, disconnects its observer, removes owned listeners, and unregisters the instance; the disposal test was red before that method existed and green afterward. The original single-slide deck could not scroll the game offscreen, so the test moves its fixture root outside the viewport. No commit was made before the Phase 1 gate.

### 2.4 Inspect browser behavior and inherited visual findings

A direct Chromium interaction observed `idle`, then a manual pause reason, then tick `0 -> 1` after one explicit step. Desktop and mobile captures show the Training view without document-level horizontal overflow. The visual detector nevertheless exits nonzero on two 420 px navigation buttons. Running the same detector against the untouched `HEAD` guide produced the identical two selectors, severities, and viewport values. Both JSON receipts are in `../training-rebuild/`; these warnings remain owned by Phase 6's deck replacement and are not called a Phase 1 pass.

The first fast-profile attempt failed in `validate_no_personal_paths`: the generated JSON receipts contained an absolute Windows username in their `file` fields. The two fields were replaced with repository-relative identifiers without altering findings. The full fast profile then passed 17/17.
