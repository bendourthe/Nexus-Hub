## What this phase was for

Cleanup widens from the run's own branches to every branch and worktree that is merged and idle, which reverses a report-only policy. This is the only phase that deletes other people's work if it is wrong, so every removal is gated by per-item checks re-read immediately before acting.

## Steps taken

1. **T021**: decision record `docs/decisions/proposed/policy/2026-09-28-verified-merged-and-idle-cleanup.md` with alternatives, the seven checks, the honest property ("merged, and idle as far as this machine and GitHub can show"), the accepted trade-offs (other ignored files inside allowlisted build and dependency directories are deleted; the sensitive-name scan is a safety net), the 1000-PR fail-safe, and the activity API retention limit.
2. **T022**: `scripts/cleanup_merged.py`, dry-run by default. It enumerates local branches, remote branches, and worktrees and prints `REMOVE <item>` or `KEEP <item> <check>`. Removal uses `git worktree remove` without `--force`, `git update-ref -d <ref> <sha>`, and `git push --force-with-lease=refs/heads/<b>:<sha> <remote> --delete <b>` only to a verified origin. Checks cover protection, hosting availability, an open PR, a MERGED same-repository PR into the integration or default branch whose head equals every tip, local-ahead, worktree state (dirty, untracked, ignored outside the allowlist, hidden `assume-unchanged` or `skip-worktree` edits, links or junctions, nested worktrees or repositories, sensitive file names in allowlisted directories, locked, in use), ownership by a live run, idle time from the reflog, file times, and the GitHub activity API, unsafe ref names, and unreadable run records.
3. **T023-T024**: both installers copy the executor; the handbook evidence hashes were refreshed.
4. **T025**: `check_release_preconditions.py --branches` prints the executor's dry run (one source of candidate logic) and stays report-only.
5. **T026**: `cleanup.merged` is met only from a sealed final-pass receipt (nonce, integration branch and tip, idle hours of at least 24, removed and kept items) whose removed items are still gone; no receipt is written when a global unknown kept items. The completion contract owns the rule.
6. **T027**: `/update release` "Clear what the release consumed" runs the executor: dry run first, then `--apply --receipt` under the recorded approval or an explicit confirmation.
7. **T028**: `tests/validators/test_cleanup_merged.py` (84 tests), using real `.exe` stand-ins built by `tests/fixtures/gh_stub/launcher.py`; `repo_host.absolute_tool` now skips Windows `.cmd` and `.bat` shims.

An adversarial review reproduced ten ways to lose data or skip a check (two critical: a junction followed outside the worktree, and hidden `assume-unchanged` edits). All thirteen findings were fixed, each with a regression test except two documentation-only items.
