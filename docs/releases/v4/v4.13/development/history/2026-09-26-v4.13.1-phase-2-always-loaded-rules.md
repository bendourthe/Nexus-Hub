## Troubleshooting

### The Google-family instruction files silently lacked every shared rule (pre-existing defect, fixed)

The three-platform install check found that the installed `~/.gemini/GEMINI.md` for Antigravity 2.0 held the literal line `@base-google-shared.md` and nothing from that file. The platform resolves the import relative to the installed file, and no `base-google-shared.md` is installed there. So Autonomous Operation, Writing Discipline, and now both new rules never reached Antigravity 2.0, Antigravity CLI, or Gemini CLI. The plan's stability gate requires those rendered files to state the ban once; they stated it zero times.

Root-cause fix: `MarkdownIntegration._render` now inlines whole-line imports of sibling templates, recursively. Cycles, unknown names, and path-like names are left as written. `tests/integrations/test_template_includes.py` (registered in `repo-tests-integrations-install`) covers every shim, cycle safety, unchanged substantive rendering, and an installed Antigravity file.

### Always-loaded word budget

The two rules add 51-53 net words per lockstep template, over the `docs/policy/doc-budgets.json` ceilings. Following the v4.12 attribution precedent, the five ceilings were raised to the measured sizes with a written `_v4_13_1_user_edit_and_attribution_justification`; v4.16.0's review must count both rules.

### The fingerprint check would go stale on every template commit

v4.13.3's `build_legacy_fingerprints.py` built from committed history and recorded the newest template revision, so any template edit failed `--check` right after it was committed.

- The builder now also hashes the working-tree sources, which after the commit equal HEAD, and no longer records a revision.
- It still refuses to build without template history, which would otherwise yield a partial set.
- The regenerated set (3,727 lines) is in this commit, with a test.

### Handbook receipt

`git-attribution.md` is a reviewed input of the `distribution` handbook. The claim review ([`distribution-handbook-attribution-ban-review.md`](../distribution-handbook-attribution-ban-review.md)) found no false claim, and the build reproduced the committed bytes; the receipt was refreshed. `check_handbooks.py` passes.
