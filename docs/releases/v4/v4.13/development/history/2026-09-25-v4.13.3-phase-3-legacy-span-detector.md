## What this phase was for

Old installs left a full copy of the instruction template and skill index ABOVE the managed markers, so later installs added a second index instead of replacing the first. Phase 4 will offer to remove those leftovers, which means deleting lines from a file the user owns. This phase built the part that decides which lines are candidates, and a way to measure what an instruction file costs, before any writer touches a file.

## Queue re-assessment (phase entry)

No drift. No queued plan touches `scripts/lib/installer/`, the new scripts, or `scripts/ci/profiles.py`'s hygiene groups.

## Steps taken

1. **T015-T017, fingerprints.** `scripts/build_legacy_fingerprints.py` reads every git revision of `templates/ai-instructions/*.md` and `data/SKILL_INDEX.md` through one `git cat-file --batch`, and records each line literally and once per historical default value of each placeholder it contains. Defaults come from the `installer.sh` sed rules, the `installer.ps1` `.Replace` calls, and `_DEFAULT_TEMPLATE_VARS` in `base.py`. It writes 3725 sorted SHA-256 hashes (schema 1) to `scripts/lib/installer/legacy_fingerprints.json` through a temp file and rename, and fails loudly on empty history or a non-UTF-8 revision. `--check` runs in a new unscoped `legacy-fingerprints` group in the full profile. It is unscoped because a template edit that skipped a catalog-scoped group would otherwise let the set drift; CI already clones with `fetch-depth: 0`.
2. **T018, detector.** `scripts/lib/installer/legacy_instruction_block.py` exposes `detect` and `detect_bytes`. Marker semantics follow `instruction_merge.py` (first start, last end). A candidate is a maximal run of blank or fingerprint lines, trimmed, with at least 3 non-blank lines, inside an out-of-marker region holding both the skill-index heading and a `**Total:` line. Every other line is kept and ends a run. Each span carries a content hash, byte offsets that hold under CRLF and a BOM, and a consent hash over a JSON encoding of the resolved path, whole-file hash, offsets, and content hash. The statuses `absent`, `unreadable`, `markers-malformed`, and `no-fingerprints` never raise.
3. **T019-T020, measurement.** `scripts/measure_rendered_context.py` reports estimated tokens and words, H1/H2 section sizes (headings inside code fences ignored), duplicate headings, skill-index rows and `**Total:` lines, and candidate spans. It imports `estimate_tokens` rather than copying it. `--redact` keeps a heading only when its line is in the fingerprint set, so "produced by a Nexus-Hub template" has one definition shared with the detector. Both scripts are in `DEV_ONLY_SCRIPTS`.
4. **T021, baseline.** Rendered the five lockstep integrations through `runner.py` into a throwaway home (Cursor at workspace scope, because it has no global Markdown file) and measured them and this machine's installed files. Written to `docs/releases/v4/v4.13/development/rendered-context-baseline.md`, redacted.
5. **T022-T024, tests.** 43 tests across `test_legacy_fingerprints.py`, `test_legacy_instruction_block.py`, and `test_measure_rendered_context.py`, covering every fixture and failure mode named in 3.2 and 3.3.

## Troubleshooting

### The fingerprint default path could not be redirected in a test

`load_fingerprints(path=FINGERPRINTS)` bound the default when the module was imported, so a test patching `FINGERPRINTS` still read the real file and the missing-fingerprint case could not be exercised. The default now resolves at call time.

### A scripted test edit failed its anchor

A heredoc-escaped replacement matched zero times, and the anchor assertion stopped it before anything was written. It was redone with the Edit tool.
