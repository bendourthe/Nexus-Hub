## Steps taken

1. **T001-T002 (1.1)**: probed Claude Code 2.1.283 with a throwaway `UserPromptSubmit` hook. Headless `claude -p "/goal test condition"` fired the hook with `prompt` exactly `/goal test condition`, and the transcript records `Goal set: test condition`. The first attempt through Git Bash was rewritten by MSYS path conversion to `C:/Program Files/Git/goal test condition`, a host-shell artifact. Official vendor pages were fetched for Codex, Copilot CLI, Cursor, Kimi, Qwen, OpenClaw, Hermes, and Antigravity 2.0: none states that a typed slash command reaches the prompt-submit hook verbatim, so none is `verbatim`; Antigravity 2.0 and its CLI are `not-captured` (no prompt-submit event exists). Every row of `docs/policy/completion-levers.json` now carries `goal_capture`, and the validator accepts `verbatim` only from an interactive probe, so the `claude` row is `unverified` with `probe_mode: headless` until a typed probe runs. Decision record: `docs/decisions/proposed/policy/2026-09-28-approval-paste-sets-native-goal.md`.
2. **T003-T004**: new `scripts/approval_binding.py`. `record render` builds the canonical JSON of what the approval page shows, derives an 8-character base32 code from an HMAC of it with the runs secret, and writes an owner-only pending round (MAC over every field, 30-minute expiry, session binding). `record create`, `record answer`, `record pause`, and `record resume` recompute the page from live state and require exactly one captured whole-prompt digest equal to the rendered paste line; the round is consumed on use and its nonce becomes the record nonce. Refusals name `page-changed`, `code-used`, `code-expired`, `approval-not-captured`, `runner-launched`, `session-too-new`, `session-mismatch`, and `pending-unreadable`. The terminal-paste fallback was removed, so a platform without capture fails closed.
3. **T005-T007**: both approval-capture hooks skip capture when `NEXUS_RUNNER_LAUNCH=1` (the `.ps1` now drains stdin on that path, as the `.sh` does), `completion_gate.py capture` stores only the whole-prompt digest, and `scripts/run_plan.py` sets the variable for every session it launches.
4. **T008-T009**: both installers copy `approval_binding.py` beside the checker; the handbook distribution evidence hashes were refreshed.
5. **T010**: the completion contract's Approval origin section owns the exact-binding rule and its threat model; the runbook and `implement.md` link to it.
6. **T011**: `tests/validators/test_approval_binding.py` covers each WN-9 bypass fixture, single use, page change, expiry, the authenticated pending file, a newer render invalidating the older code, and runner-launched sessions on both hooks.

An adversarial panel (bypass, parity, contract lenses) raised nine findings; all nine were confirmed and fixed, two of them only partly (see Deviations).
