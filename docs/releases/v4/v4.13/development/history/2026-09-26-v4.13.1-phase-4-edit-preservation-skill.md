## Troubleshooting

### A JSON rewrite changed existing escapes

The first registration wrote `data/skills.json` with `ensure_ascii=False`, turning existing `\u` escapes into raw non-ASCII characters. It was re-serialized with `ensure_ascii=True` (the file round-trips exactly that way), so the diff is the new entry plus the two count lines.

### Asking before writing was conditional

The first draft said to ask "when the change could disturb their edits", which contradicts the plan's expectation and the always-loaded "ask first". After any detected change the skill now always asks, then accepts, then writes.
