## What this phase was for

`check-minor` is the single definition of done for a minor run, member plans must run strictly one after another from a develop that already holds the previous release, and the minor closes through one pull request. Every restatement of the goal points at this verdict, so a false `MINOR COMPLETE` would defeat the whole plan.

## Steps taken

1. **T035**: `check-minor <minor>` and `score-minor` in `scripts/completion_minor.py`. Each member is evaluated through `project()` and the per-plan `evaluate`; then `members.approved`, `gaps.minor`, `minor.close-pr`, `cleanup.merged`, and `archive.minor`. Exit codes match the per-plan check (0 `MINOR COMPLETE <minor> <head> <nonce>`, 1 `INCOMPLETE`, 3 `BLOCKED`, 4 `PAUSED`, 2 malformed); precedence is tampered, paused, blocked (a member blocker reads `BLOCKED: <category> (vX.Y.Z)`), member gate, new unapproved member, then predicates. The run is capped at 120 s with at most 20 s per member; an environment override can only lower the cap.
2. **T036**: the completion contract's "Minor verdict" section owns these verdicts.
3. **T037**: the runbook's "Minor driver" section adds the member gate and the eleven-step minor close. `record member-start --head <sha>` refuses unless the previous member is `PLAN COMPLETE`, the fetched integration tip is current, and it contains the previous release tag; it signs `start_head` into the member entry. Every member after the first needs a recorded `start_head` that contains the previous tag and sits under the member's merged pull request.
4. **T038-T042**: `scripts/run_plan.py` accepts a `vX.Y` target and confirms a blocker was actually written before reporting it; `scripts/completion_gate.py` makes one `check-minor --json` call so verdict and score come from the same run, never counts a timed-out score as no progress, and reserves budget for the blocker write. The two gate hooks and four plugins call the core unchanged (header comments only).
5. **T043**: `/update release` gains the minor close.
6. **T044**: `tests/validators/test_completion_minor_verdict.py` (51 tests).

An adversarial review reproduced two false `MINOR COMPLETE` paths (an uncommitted migration with a closing pull request matched by name only, and a member gate that was opt-in) plus an unsigned `excluded` list, an unsigned `completed` field that disabled blocker writes, and a slow check letting a turn end with no blocker. All seven findings were fixed with regression tests; `gaps.minor` now reads ledgers from the integration branch, and the closing pull request must merge after the last release and carry the migrated ledgers and archive.
