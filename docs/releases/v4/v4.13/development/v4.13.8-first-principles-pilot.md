# v4.13.8 First-Principles Pilot

The record of a small, pre-registered pilot on whether adding a first-principles sentence to a bug-localization prompt changes Claude Sonnet 5.5's root-cause accuracy. It states the go rule and power before any result, then the design, the receipts, the outcome, and the follow-on. Status: **stopped by its own effort rule after the smoke run; the hypothesis was not tested.** Read it before re-running the pilot or citing it.

Plan: [`v4.13.8-adoption-sonnet-5-5-profile-and-first-principles-test`](../plans/v4.13.8-adoption-sonnet-5-5-profile-and-first-principles-test.md), Phase 5. Design decision: `## T319` in [`v4.13.8-admission.md`](v4.13.8-admission.md). Run date: 2026-09-30.

## Go rule and power (pre-registered, recorded before any paid run)

- **Go rule.** Go only if the `first-principles` arm's assertion pass rate is at least 20 percentage points above `baseline` AND at least equal to `control`. Otherwise the verdict is "not shown at this power". It is never "rejected".
- **Power.** With 5 prompts per arm, each arm's rate moves in steps of 20 points, and only gaps of about 40 points or more separate signal from noise. A go would have authorized designing a powered test. It would not have been evidence of an effect.
- **Stop rule.** If the run metadata cannot confirm that `--effort high` took effect, the pilot stops after the smoke run and records the effort confound instead of claiming it was controlled.
- **Spend.** Cap USD 20, a fail-closed ledger checked before every dispatch, a USD 1.00 per-run ceiling enforced by the CLI (`--max-budget-usd`), and approval bound to the exact matrix. The user approved this on 2026-09-30.

## Design

| Element | Value |
|---|---|
| Skill | `bug-localization` (body supplied with `--append-system-prompt-file`) |
| Model | `claude-sonnet-5-5` |
| Effort | `high`, passed with `--effort high` |
| Arms | `baseline` (no addition); `first-principles` ("Reason from first principles: restate the problem in your own terms and identify what must be true before choosing an approach."); `control` ("Think the problem through before you answer.") |
| Prompts | 5 self-contained failures whose root cause sits in a different function from the symptom: [`evals/bug-localization.json`](v4.13.8-first-principles/evals/bug-localization.json) |
| Runs | 5 prompts x 3 arms, one trial each: 15 cells, order shuffled once with seed 42 ([`order.json`](v4.13.8-first-principles/order.json)) |
| Grading | Programmatic and blind to arm: the reply's last `ROOT CAUSE:` line must be present and must name the reference function. Naming the symptom function fails. No LLM grader. |
| Isolation | `claude -p --bare --setting-sources "" --tools "" --no-session-persistence --output-format json`, run from an empty scratch directory. The API key reaches the child only through its environment. |

Every fixture was executed once locally before the pilot and reproduced its stated failure (the `KeyError`, the `$1,250.00` total, the leaked tags, 2,500 records written, the swapped recommendation).

|---|---|---|---|

| p2-discount-hundredfold | not run | not run | not run |
| p3-tags-leak | not run | not run | not run |
| p4-missing-last-page | not run | not run | not run |
| p5-cache-collision | not run | not run | not run |

Per-arm pass rates: `baseline` 1/1, `first-principles` 0/0, `control` 0/0.

**Why the smoke run stopped the pilot.** The smoke cell (baseline, prompt 1) completed and passed. The CLI's metadata, however, cannot show that `high` effort was in effect:

- Claude Code 2.1.283 wrote `[claude-code:unrecognized_model] {"model":"claude-sonnet-5-5"}` to stderr. The request was still served and billed as `claude-sonnet-5-5`.
- The model-usage block records `costBasis: "unknown"` and `maxOutputTokens: 32000`, which looks like a fallback for a model the CLI does not know.
- The JSON output has no effort field at all, and `thinking_tokens` is 0.

A CLI that does not recognize a model may not forward capability-gated options such as effort, so whether `--effort high` reached the API cannot be confirmed. The stop rule applied, and the user chose to close the pilot under it.

**Reasons for the 14 missing runs.** Each of the 14 cells other than `p1-invoice-keyerror__baseline` was not dispatched because the pre-registered stop rule fired after the smoke run. None was attempted, errored, or dropped.

## Confounds that remained

- **Effort is uncontrolled.** This is the confound that stopped the pilot, as described above.
- **Prompt length.** The first-principles and control arms add 128 and 45 characters respectively.
- **Thinking mode** was left at the model default and is not visible in the metadata beyond the token count.
- **One model and one skill.** Nothing here generalizes beyond them.
- **The skill delivery path.** The skill body arrives as an appended system prompt, not through native skill loading, because this CLI documents no `--skill` option (filed as WN-4).
- **Ceiling risk.** The prompts are moderate in difficulty, and the one baseline run passed. A full run might have read 5/5 in every arm.
- **Vendor evidence scope.** The vendor's evidence for the think-first line covers structured-JSON reasoning tasks at low and medium effort. A result at `high` effort on bug localization would not have generalized to that case.

## Verdict

**Not shown at this power.** The pilot was stopped by its own pre-registered effort rule before any arm comparison existed, so this record is not evidence for or against a first-principles instruction. No shared instruction surface was changed: the diff against the baseline commit is empty for `templates/ai-instructions` and `catalog/rules`.
