## Resolved decisions

1. Hook strength: block a mismatch outside a Git worktree and warn on shell commands inside a worktree.
2. AI attribution: carry the user's widened ban into every installed instruction template.
3. Version placement: rank queued plans by execution priority; this plan takes v4.13.1 without renumbering existing plans.
4. User edits: never restore the pre-edit version; review the user's changes, carry them forward, and offer suggestions separately without applying them unasked.
5. Protected files: use a cross-session store for the agent's last-known state on reads, writes, and file-changing commands; compare Office content rather than metadata.
6. Block release: only `edit_guard.py accept <path>` after a same-session `diff`, with the acceptance logged and included in the end-of-task summary.
7. Stored copy: keep the agent's last-written file version outside synced drives with owner-only access and 30-day retention; exclude secret-looking paths and provide purge.
8. Attribution enforcement: derive a separate `attribution-guard` hook from `scripts/nexus_git_attribution.py` patterns, cover Git and GitHub publication commands and MCP tools, and warn on changelog and document writes.
9. Replay: run four scenarios by three conditions by five Claude trials, plus the hook-disabled Codex condition, under a USD 40 cap; allow one fix-and-rerun cycle before asking the user to decide.
10. Plan numbering remains an independent phase and is the first cut if necessary.
11. Registering `user-edit-guard` and `attribution-guard` in `catalog/hooks/settings.json` was approved on 2026-09-23.
