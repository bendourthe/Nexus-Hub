## Human and manual testing suggestions

Only what automated tests and the replay cannot cover:

1. On a real OneDrive or SharePoint folder, ask your agent to build a deck and copy it there, edit a slide in PowerPoint (move a picture as well as changing text), close PowerPoint, then ask for a small revision. Confirm your edit survives and the agent names both changes before writing. This closes the gap between the replay's stand-in folder and a real synced drive (online-only placeholders, sync-rewritten metadata).
2. Repeat step 1 with the deck still open in PowerPoint: the agent should ask you to save and close it rather than write.
3. Start a new session the next day and ask for another revision of the same deck (WN-1): note whether the agent mentions your earlier edits.
4. From a normal repository, ask your agent to open a pull request and watch for the attribution guard: the pull request body must carry no co-author trailer, generated-with footer, or robot badge, and a body that merely mentions a tool ("generated with pandoc") must go through.
5. On a platform without hooks that you use (Copilot or Cursor, for example), repeat step 1 once: the always-loaded rule and the skill are the only protection there (MT-1).
