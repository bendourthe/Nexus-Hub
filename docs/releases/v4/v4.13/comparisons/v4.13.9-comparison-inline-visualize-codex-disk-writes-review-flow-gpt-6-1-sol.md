## Risks and conflicts

- **Name collision (V1):** a Nexus-Hub `/visualize` may conflict with Cursor's built-in. Unverified. Options if a collision is confirmed: skip the Cursor mirror for this command, or rename. Decide after the throwaway-install check.
- **Honest degradation (V1):** on a terminal host the command cannot draw a chart. The skill must say which tier it used and never imply inline rendering happened. Generated HTML must pass the rendered self-verification rule (headless render, clipped capture, computed-style checks) before V1 reports done.
- **Data exposure (V1):** a visualization of logs can embed secrets in a shareable file. Apply `egress-redaction` before writing HTML and keep all assets inline.
- **Stale version floor (D1):** a hard-coded Codex version would rot. Keep it in a data file with `source_url` and `verified`, and verify it against OpenAI's release notes before shipping. The outlet-reported floor of 0.142.0 is unverified today.
- **Scope (R1):** drafting comments is fine; any step that posts to a pull request is an outward-facing action and stays with the user.
- **Existing-file edits:** M1, M2, R1, and D1 edit existing files (higher risk than adding files). V1 mostly adds files. The `user-edit-preservation` check applies before each edit.
