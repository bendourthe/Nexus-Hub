## Overview

The seeding comparison read four sources: a social post claiming that telling a model to think from first principles adds a large quality gain, the Sonnet 5.5 building guidance, a retrieval CLI with a cost benchmark, and an enterprise agentic-coding guide. The guide was already covered almost entirely. The other three left concrete gaps: no Sonnet 5.5 profile although every current plan's model map lists that model as the standard tier, no rule against cost-saving claims that leave out the helper model's own cost, an optimizer that selects and reports on one split, and an unmeasured claim.

**The provisional answer to the user's question is no for every shared instruction surface.** The claim is one self-hedged anecdote about a different model family, and the vendor's own Sonnet 5.5 guide reports a measured effect only for a narrow case (a "Think the problem through before you answer" line for JSON-answered reasoning tasks, where the model often skips thinking). This plan can change that answer in one way only: a pilot may show that a skill-level line deserves a powered test.

Phase 1 fixes baselines and settles two decisions. Phase 2 authors the Sonnet 5.5 profile through the governed `/tune-prompting` path. Phase 3 adds the cost-claim rule and two optional guidance items. Phase 4 is optional: it makes the optimizer label its optimistic score and adds a three-way split for large eval sets. Phase 5 runs the pilot. Phase 6 is the mandatory final phase.

Nothing is sent to a new destination. The pilot uses the `claude` CLI the operator already has, with an explicit fixed effort, under a USD 20 cap.
