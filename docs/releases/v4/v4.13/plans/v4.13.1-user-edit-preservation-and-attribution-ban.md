# Plan -- User-Edit Preservation and AI-Attribution Ban

**Project**: Nexus-Hub
**Version**: v4.13.1
**Slug**: user-edit-preservation-and-attribution-ban
**Filename**: `v4.13.1-user-edit-preservation-and-attribution-ban.md`
**Plan Type**: Bug fix / Safety (three user-mandated tracks: user-edit preservation, AI-attribution ban, priority-ordered plan versions)
**Created**: 2026-09-23
**Status**: queued
**Seeded from**: user incident reports on 2026-09-23 (no comparison); queue ranking in `docs/releases/v4/v4.13/development/v4.13.1-queue-assessment.md`

**Goal**: An agent on any Nexus-Hub-supported platform never overwrites, regenerates over, or copies over a file the user changed since the agent last read or wrote it without the user's consent, and instead reviews the user's changes, carries them forward, and offers suggestions separately; no agent adds any reference to AI contributions to commits, tags, pull requests, issues, comments, releases, changelogs, or documents; and every new plan's version number reflects its execution priority.

## Definition of Done

**Must have:**

1. The user-edit rule and the AI-attribution ban are always loaded on every platform whose instruction file Nexus-Hub installs, byte-identical across the directory-derived roster, asserted by validators; per-platform coverage (including project-scope-only and non-covered platforms) is recorded.
2. The incident replay passes: in every "after the fix" run of every scenario, the user's edit survives and the agent reports it, including the scenarios with the hook disabled; the verdict records the rule-of-three confidence bound for the run count.
3. On hook-capable platforms, `user-edit-guard` blocks a Write, Edit, or shell copy or move onto a file outside a git worktree whose current content differs from the agent's last-known state, or onto an existing file the agent never recorded; inside a git worktree it warns. `attribution-guard` blocks AI attribution in `git commit`, `git tag`, `gh`, `gh api`, and GitHub MCP tool calls. Both `.sh`/`.ps1` pairs pass parity tests.
4. `edit_guard.py accept` is the only way to release a block, works only after a `diff` of that file in the same session, and every use is logged and surfaced.
5. The pptx, docx, xlsx, pdf, document-to-interactive-html, and deep-research skills and the presentify command revise an existing deliverable by editing the current file or by saving to a working path and merging, never by saving or copying directly onto the deliverable.
6. `plan-queue-assessment` states that every new plan's version must sort before every plan it must precede, `cross-project-comparison` and `implementation-plan` call it, and a fixture run shows the placement.

**Nice to have (cut in this order):** Phase 7 (priority-ordered plan versions) as a whole; per-cell xlsx diff; pdf text diff.

## Non-Goals

- Guarding writes made by processes outside the agent's harness (an editor, a sync client, a user script run by hand). The guard sees only the agent's tool calls.
- Blocking a script whose own `.save()` targets a deliverable. The hook cannot see a path inside a script; this is covered by the post-command re-hash (Phase 6), the procedure (Phase 4), and the document-skill rule to save to a working path (Phase 5).
- Retrofitting past losses. The procedure points to version history (OneDrive, SharePoint, git); no tool performs recovery.

## Overview

Two incidents on 2026-09-23 drive this plan. An agent revising a PowerPoint deck rebuilt it from its generator script and copied it over the user's OneDrive file twice, erasing a slide the user had edited; the user reports a prior occurrence. And a pull request went out with a "Generated with" footer because a harness reminder asked for one, although `catalog/style-guides/git-attribution.md:7` already bans such footers: the always-loaded template only points at that guide, and nothing checks what `gh` publishes.

A seven-lens plan review of this plan's first draft found that its guard would not have caught the incident: the existing provenance ledger is per session (`catalog/hooks/provenance-ledger.sh:104-112`), records only Write and Edit targets, and stores no contents by rule. This version therefore builds a separate cross-session edit-guard store keyed by path, written whenever the agent reads a file, writes it, or runs a command that changes a tracked file; the guard compares against that store, blocks outside git worktrees where there is no other history, and warns inside them to stay quiet during normal coding. Office formats are compared by content parts, excluding metadata that AutoSave and sync rewrite.

The layers stay independent so none has to be remembered: an always-loaded rule on every platform, a procedure skill with a helper, a document-skill revision rule, two hooks on hook-capable platforms, and a replay that proves the behavior on the incident's own path, with and without hooks. A third track fixes the planning rule that let an ordering live only in prose. Everything is local: stdlib Python plus the optional `python-pptx`, `python-docx`, and `openpyxl`, imported lazily with install hints. No new destination, credential, or dependency.

## Resolved decisions

From the user on 2026-09-23, across two interview rounds:

1. Hook strength: block on a mismatch; warn on shell commands inside git worktrees.
2. AI-attribution ban: the user's global rule was widened on 2026-09-23; the same ban ships to every template.
3. Placement: rank against the queue and number by priority. This plan ranked first and took the free slot v4.13.1; no existing plan was renumbered.
4. User edits: never restore the pre-edit version; review the user's changes and suggest improvements without applying them unasked.
5. Protected files: a cross-session store records the agent's last-known state on every read, write, and file-changing command; outside a git worktree the guard blocks on a mismatch and on overwriting an existing unrecorded file; inside a worktree it warns; Office files compare content, not metadata.
6. Release: only `edit_guard.py accept <path>`, only after a `diff` in the same session, logged and shown in the end-of-task summary.
7. Stored copy: the agent's last-written version of each file, owner-only, outside synced drives, retained 30 days, secret-looking paths excluded, with a purge command.
8. Attribution enforcement: a separate `attribution-guard` hook built on the `nexus-hub attribution check` patterns, covering `git commit`, `git tag`, `gh pr|issue|release`, `gh api`, and GitHub MCP tools; trailer- and footer-anchored patterns; a warning on CHANGELOG and docs writes.
9. Replay: four scenarios by three conditions by five runs on Claude, plus the hook-disabled condition on Codex; spend cap USD 40; one fix-and-rerun cycle, then the user decides.
10. The plan-numbering track stays in this plan as an independent phase and is the first cut.
11. Registering `user-edit-guard` and `attribution-guard` in `catalog/hooks/settings.json` is pre-approved (AGENTS.md "Ask first" satisfied on 2026-09-23).

### Sub-tasks

#### 3.1 -- Store and helper

**Objective**: Implement the store and all subcommands.

**Failure modes**: Malformed or absent input (missing path, unreadable or corrupt Office archive, non-regular file, symlink or junction): `check` exits 2 and never reports "unchanged"; a OneDrive cloud-only placeholder is reported "cannot verify" (exit 5) without being read, so the helper never triggers a download. Unreachable or slow dependency (`python-pptx`, `python-docx`, or `openpyxl` absent; a file over the streaming limit): detection falls back to a content-part or whole-file hash, still exits 3 on a change, and prints the `pip install` hint for the diff; hashing streams so large decks are covered. Conflicting operations (two agents or sessions recording one path; a record while the file is open): records are per path with a monotonic sequence, the latest verified record wins, `record` refuses (exit 3) when the file differs from its last record, and an Office lock file (`~$<name>`) or a conflict copy (`<name>-<machine>.<ext>`) makes `check` exit 3 with "open or conflicting copy".

**Build class**: load-bearing.

**Prompt**:
> Write `catalog/skills/workflow/user-edit-preservation/scripts/edit_guard.py` (stdlib; lazy imports with install hints). Store: `NEXUS_EDIT_GUARD_DIR` (default `~/.nexus-hub/cache/edit-guard/`), one JSON record per canonical path keyed by the sha256 of that path, with no session scoping and no line trimming; directory mode 0700 and files 0600 (owner-only ACL on Windows); refuse a store resolving inside the workspace, a git repository, or a OneDrive, SharePoint, or Dropbox synced root. Canonical path: absolute, symlinks and junctions resolved, separators normalized, 8.3 names expanded, case-folded on Windows and macOS; shared test vectors. Subcommands: `record <path> [--from read|write|command]` stores the content fingerprint and a copy of the file as the agent left it (skip the copy for secret-looking paths such as `.env*`, `*.pem`, `*.key`, `id_*`, `credentials*`, `*.kdbx`, and above a size cap); `check <path>` exits 0 unchanged, 3 changed (with a summary), 4 no record, 5 cannot verify, 2 error, and logs the result; `diff <path>` shows text diffs, per-slide pptx changes (titles, body, notes, tables, grouped shapes, slide count and order), per-paragraph docx changes, xlsx cell changes (nice to have), and for any hash change with an empty text diff, "non-text change" listing the changed zip parts; `accept <path>` re-baselines only if `diff` ran on that path in the same session, and logs the acceptance; `log` prints accepts for the end-of-task summary; `purge [--path]` deletes records and copies, and records older than 30 days are pruned. Office fingerprint: hash content parts only, excluding `docProps/*`. Write parametrized pytest tests for every case in the Stability Gate. Acceptance: tests pass; exit codes as specified.
