A post claimed one `smartctl` command "fixes" Codex writing diagnostic logs; the command is read-only, and the real defect (Codex builds before 0.142.0 writing TRACE-level logs to a local SQLite file) is reported fixed by updating Codex. Phase 1 settles the one decision later phases depend on (Cursor handling) and records baselines. Phase 2 lands the model profile and map. Phase 3 builds `/visualize`. Phase 4 adds draft review comments. Phase 5 bounds hook sizes and ships the runbook. Phase 6 is the mandatory final phase.

One fact shapes the runbook. Outlets report the Codex SQLite file is rewritten in place and does not balloon, so file size is a weak signal; the Codex version is the real one. The runbook therefore tells readers to check the version and states the fix version as unverified unless two primary sources agree.
