## Overview

This plan implements the six candidates in the [comparison](../comparisons/v4.13.0-comparison-evidence-driven-agent-improvement.md). It changes catalog guidance, adds only small local examples/fixtures needed to demonstrate that guidance, and reuses existing validators and evaluation tools. It does not implement a product telemetry backend or claim to reproduce a vendor's production performance. A measured no-change result is a valid pilot outcome; an unmeasured experiment is not.

The delivery surface is the existing recursive skill installer. New bundled references and the one bounded trace-example script are linked from their owners. No new skill, command, hook, external collector, memory backend, model training, scheduler, or MCP is planned. A1/A6/A2 are prioritized first; A4/A5/A3 follow under existing owners. The observability phase carries the highest privacy and evidence risk. Runtime examples use synthetic inputs and disposable local files.

That authorization applies to this documentation publication, not execution of the future plan or its release. Implementation phases each end in one local commit; only Phase 7 may publish implementation work after its own concrete approval. No new issue fan-out is requested.

## Goals First and Definition of Done

**Target problem**: The current catalog contains most required methods but leaves specific gaps at the transitions between judging, learning, tracing, and assembling instructions/context. These gaps can produce misleading success claims, payload leakage in examples, or unnecessary work.

**Personas**: the maintainer evolving catalog skills; the developer applying those skills to an existing agent; and the reviewer deciding whether an improvement is proven and safe to retain.

- **US1**: As a maintainer, I can trace a proposed improvement from a confirmed observation through a minimized regression and an independent accept/reject result.
- **US2**: As an agent developer, I can run a private local trace example and understand which operations were observed, which content is omitted, and which evidence is unavailable.
- **US3**: As a user, I receive the smallest useful explanation and current, sourced context without mandatory unnecessary artifact generation or rereading.
- **US4**: As a catalog reviewer, I can accept or reject concise trigger changes using measured two-model behavior rather than an assumption that shorter is better.

**Completion contract**: all six candidates have their mapped artifacts and observed closing evidence; synthetic examples are explicitly distinguished from real model evaluations; default trace outputs contain zero sentinel payload/exception secrets; rejected learning candidates restore the exact prior bytes; stale facts are never promoted to current merely from confidence; and the frozen trigger pilot is measured with a qualifying change or MEASURED_NO_CHANGE. A missing capability, missing measurement, failed essential criterion, or unrun pilot remains incomplete. Known-gap recording never turns a missing core Goal into PASS. Phase 7 completes integration evidence and release handoff, but does not tag/release automatically.
