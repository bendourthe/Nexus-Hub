**Goal**: A VS Code or Cursor user on GitHub Copilot sees their Copilot usage as a status-bar percentage with the same status bar, dashboard, and settings as the Claude, Codex, and Cursor monitors, computed only from figures GitHub serves (a personal plan's own quota, or an organization's shared AI-credit pool once an owner connects a read-only token), and never from a guessed allowance. ## Overview

Two capabilities ship together because the second depends on the first for one platform.

**Part A, Copilot Usage Monitor (Phases 1-3).** The native Copilot Status item shows credits used with no percentage. A GitHub usage monitor shipped in v3.15.8 and was withdrawn in v3.18.2 because the Actions allowance it displayed had to be reconstructed from data GitHub does not serve ([withdrawal record](../../../../decisions/implemented/architecture/2026-08-22-withdraw-the-github-usage-monitor.md)). Copilot does not have that problem, and on 2026-09-28 it was checked against a live Business organization rather than assumed:

| Figure | Source | Verified 2026-09-28 |
|---|---|---|
| Personal credits used, plan quota, reset date | `GET https://api.github.com/copilot_internal/user`, the endpoint the Copilot extension's own popup reads, with the user's VS Code GitHub session (undocumented, same class as the Codex monitor's endpoint) | Returned figures on a personal account |
| Organization pool used | `GET /organizations/{org}/settings/billing/ai_credit/usage`, sum of `usageItems[].discountQuantity` | 10,928.07 from the API; the billing page read 10,990 a few minutes later during active use |
| Organization pool total | `GET /orgs/{org}/copilot/billing` `.seat_breakdown.total` times the published per-seat credit rate | 7 seats x 1,900 = 13,300, matching the page |

Only owners and billing managers can read the organization figures, so the pool bar needs a one-time connect step: the owner pastes a read-only fine-grained token, stored in VS Code secret storage. A Business or Enterprise member without billing access has no personal cap unless an owner sets a user-level budget, so for them the monitor shows credits used with no percentage rather than inventing one. Accounts stay separate: the personal figure uses whichever GitHub account the user pins for the extension, and nothing touches git identity or the `gh` login.

**Reset availability in the Codex and Claude monitors (Phase 3, added 2026-09-30).** Both vendors' usage pages now list one-time limit resets ("Full reset, expires Oct 29" on ChatGPT; "Full reset, expires Oct 22" on Claude). The Codex and Claude monitors show an available reset and its expiry, offer an "Open reset page" link button that is enabled only while a reset is available, and refresh after the user uses one. They never trigger a reset: that spends a one-time, expiring credit through an undocumented endpoint, so the user presses the vendor's own button.

**Part B, Usage-Limit Handoff (Phases 4-8).** A usage cap is enforced by the vendor's server: once it is hit, the next model request is rejected and the agent never gets another turn. Nothing inside the agent can react at 100%, so this plan acts before it, in three layers. Layer 1 is a portable contract: a `session-handoff` skill behind a new `/handoff` command that writes `.nexus-hub/handoff.md` and prints a self-contained prompt, plus a short checkpoint rule in every instruction template so the file stays current during long work. Layer 2 is automatic: a new `usage-guard` hook reads the platform's own usage figure through a shared, stdlib-only probe and, at 99% of a tracked window, injects a directive telling the agent to finish the current step and run the handoff; a Stop-event continuation catches the case where the agent ended its turn without doing so. Layer 3 is the fallback for platforms with no readable usage figure: the same `/handoff` command, run by the user or by the agent when the platform itself warns about limits.

Coverage by platform follows two facts, both verified against first-party documentation on 2026-09-28: whether a hook can put text in front of the model mid-session, and whether the platform's usage can be read locally.

| Platform | Mid-session context injection | Turn-end continuation | Usage source | Result |
|---|---|---|---|---|
| Claude Code | `PostToolUse` / `UserPromptSubmit` `additionalContext` | `Stop` `decision: block` | Anthropic OAuth usage endpoint (already used by `usage-display.sh`) | Automatic |
| Codex | `PostToolUse` / `UserPromptSubmit` `additionalContext` ([docs](https://learn.chatgpt.com/docs/hooks)) | `Stop` `decision: block` | `chatgpt.com/backend-api/wham/usage` (undocumented; used by `codex-usage-monitor`) | Automatic, fragile |
| Cursor | `postToolUse` `additional_context` ([docs](https://cursor.com/docs/hooks)) | `stop` `followup_message` | Cursor usage RPC with the local `state.vscdb` token (undocumented; used by `cursor-usage-monitor`) | Automatic, fragile |
| GitHub Copilot | Local harness `PostToolUse` / `UserPromptSubmit` add context ([docs](https://code.visualstudio.com/docs/agent-customization/hooks)) | Local harness `Stop` | The Copilot Usage Monitor's percentages-only state file (Part A); the hook reads no credential | Automatic when the monitor supplies a percentage; silent otherwise |
| Gemini CLI, Qwen, Kimi | Hooks exist; they receive `settings.json` hooks | Hooks exist | None known | Checkpoint + `/handoff`; `usage-guard` stays silent |
| Windsurf, Antigravity | Hooks exist; curated hook lists | Hooks exist | None known | Checkpoint + `/handoff`; `usage-guard` not registered |
| OpenCode, Aider, Pi, OpenClaw | No shell-hook surface | None | None | Checkpoint + `/handoff` |

**Known limitation, stated up front.** A 99% threshold leaves 1% of the window. On a 5-hour Claude window a single large turn can consume more than that, so the automatic layer can arrive after the cap. The threshold is the user's explicit choice and stays the default; the rolling checkpoint (layer 1) is what guarantees a resumable record when the guard is too late. The threshold is configurable per user through `NEXUS_HANDOFF_THRESHOLD`.

**Out of scope.** Switching platforms automatically, sending the handoff anywhere (it is printed and written locally only), reading usage for platforms with no known source, a one-click organization sign-in for the Copilot monitor (declined for now; see resolved decision 2), and repairing `/usage`, which dispatches to a `check-usage` skill that is absent from `catalog/skills/` (recorded as a known gap in 4.1 so it is not lost; the probe built here is the natural backend for it later), and triggering a usage-limit reset from any monitor (resolved decision 6).

#### 2.2 -- Personal Copilot provider

**Objective**: Read the user's own Copilot quota through VS Code's GitHub session.

**Failure modes**: No GitHub session: return `no-credentials` and show a "Sign in to GitHub" action, never prompt on a background refresh. Session revoked or 401: `token-invalid`. 429: `rate-limited`, back off to the next interval. #### 6.1 -- Probe core and cache

**Objective**: A provider-agnostic core the hook and, later, `/usage` can share.

**Failure modes**: Credentials missing, unreadable, or expired: return `unavailable` with a reason and never attempt a refresh that writes to the vendor's credential file. Endpoint unreachable, slow, or returning an unexpected shape: 3-second timeout, return the last cached value if it is younger than 30 minutes marked `stale`, otherwise `unavailable`. Two hook processes probing at once: the cache is written to a temporary sibling and renamed into place, so concurrent readers see the old or the new file, never a partial one. Clock skew on reset times: percentages are used as returned and reset times are only displayed, never used for the trigger decision.

**Build class**: load-bearing.

**Prompt**:
> Create `catalog/hooks/_usage_probe.py` (stdlib only: `json`, `urllib.request`, `pathlib`, `time`, `os`; no `requests`, no `jq`, no `curl`), importable by hooks and runnable as `python _usage_probe.py --platform <key> --json`. Its public function `probe(platform: str) -> ProbeResult` returns `status` (`ok`, `stale`, `unavailable`), a list of windows each with `name` (`five_hour`, `weekly`, `monthly`), `percent` (0-100 float), and `resets_at` (ISO string or null), plus `cached: bool`. Cache under `~/.nexus-hub/state/usage-probe/<platform>.json`: 300 seconds while every window is below 90%, 60 seconds once any window reaches 90%, so the probe is cheap on every tool call but fresh near the threshold. The cache stores percentages and reset times only, never tokens or raw responses. Every exception path returns `unavailable`; the module never raises to its caller and never writes to stdout except in `--json` mode. Honor `NEXUS_USAGE_PROBE_DISABLED=1` as a global off switch and `NEXUS_USAGE_PROBE_PROVIDERS` (comma-separated subset of `claude,codex,cursor,copilot`, default all) as a per-provider switch. Keep the cached path fast: read the cache file and threshold before importing `urllib` or `sqlite3`, because the hook runs on every tool call and, where a compatibility launcher wraps it, starts Python twice.
> **Delivery is NOT automatic beyond Claude Code.** Only the Claude path copies `catalog/hooks/` wholesale; Codex, Copilot, Antigravity, and Windsurf copy the registered scripts plus `sourced_modules()` from `scripts/lib/integrations/_hooks_common.py`, which today detects only `_*.sh` and `_*.ps1` helpers.
