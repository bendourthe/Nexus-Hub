# v4.13.4 Guide Training rebuild - implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans` to implement this plan task by task. Steps use checkbox (`- [ ]`) syntax for tracking. This repository's own `/implement` command consumes the phase structure; either entry point is valid.

**Goal:** Rebuild the Training tab as seven headed sections walking the Nexus-Hub command loop, carried by a production-quality arcade game with varied enemies, asteroids and a futuristic player ship.

**Architecture:** The arcade engine becomes an instance-per-element factory so three games can live on one page. Entity variety is added to the model first and the painters second, all drawing from the existing `rngSpawn` stream so the seeded bug demo stays reproducible. Section-scoped binding is prepared while the old deck remains usable; then the deck markup, source data and presentation controls are replaced together.

**Tech Stack:** Vanilla ES5-style JavaScript inside a single self-contained HTML file (`guides/website/nexus-hub-guide.html`), Canvas 2D, pytest plus Playwright Chromium for verification. No new dependency is introduced.

**Spec:** `docs/releases/v4/v4.13/development/training-rebuild/design.md`

## Global Constraints

- Runtime behavior stays inside the self-contained `guides/website/nexus-hub-guide.html`; tests, release evidence, the maintainer source `guides/website/example/training-scenes.json`, and its README change as needed. No new runtime dependency or external asset.
- `damageOutcome(mode, lives)` keeps its exact signature and behavior. It is the seeded bug the whole narrative depends on. Spec A2.
- All new randomness draws from the instance's `rngSpawn` stream. `Math.random` is never used in engine code. Spec A3.
- Drawing stays in logical units. The device-pixel-ratio change scales the backing store, while the new logical height requires retuning player geometry, bounds and fixtures. Spec A7.
- The guide stays strictly below 500,000 bytes. The starting blob is 495,467 bytes, allowing at most 4,532 more bytes; remove obsolete deck code and optimize existing self-contained assets before new content exhausts the budget. Run `python -m pytest -q tests/guides/test_nexus_hub_guide.py::test_file_size_budget` after each phase; do not raise its ceiling.
- Accessibility carries over per instance: canvas `aria-label`, the boot-silent `aria-live` region, touch controls, `prefers-reduced-motion` settled frames, keyboard-operable start. Spec "Accessibility and motion".
- Markdown written by this plan follows `catalog/style-guides/markdown.md`: ASCII only, blank line around every list, table, code block and heading, no hard-wrapped paragraphs.
- Every phase ends with exactly ONE local commit, after its full phase gate. Intermediate task checkpoints are not commits. No non-final phase pushes or opens a pull request. Only the final phase pushes. See AGENTS.md "Plan lifecycle".
