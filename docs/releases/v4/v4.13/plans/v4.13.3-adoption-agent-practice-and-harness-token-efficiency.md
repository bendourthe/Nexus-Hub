# Plan -- Truthful Session Context and Measured Instruction Size

**Project**: Nexus-Hub
**Version**: v4.13.3
**Slug**: adoption-agent-practice-and-harness-token-efficiency
**Filename**: `v4.13.3-adoption-agent-practice-and-harness-token-efficiency.md`
**Plan Type**: Feature / Adoption (from comparison, reverse-engineer-first ordering)
**Created**: 2026-09-24
**Status**: queued
**Seeded from**: `docs/releases/v4/v4.13/comparisons/v4.13.3-comparison-agent-practice-and-harness-token-efficiency.md` (adoption target v4.13.3, confirmed by the user on 2026-09-24)

**Goal**: Every session Nexus-Hub starts receives truthful context (a validated version, no removed commands, no duplicated git block), a candidate legacy instruction block left by an old install is reported and removable only by reviewable hash-bound consent without removing any nonmatching line, and an opt-in skill-index pointer plus a local measurement tool let users shrink and maintainers measure rendered instruction size.

**Legacy Instruction Block**: A candidate pre-marker Nexus-Hub block is an out-of-managed-marker region containing the historical `# Nexus-Hub Skill Index` heading and `**Total: N skills across M categories**` line, with candidate spans made of consecutive blank lines and full-line fingerprints from shipped templates. A text match is not proof of authorship: a user may have written identical text. Detection is report-only by default; removal requires the user to inspect the printed span and proposed diff and supply the exact file-specific consent token reported after the preceding install. Lines outside the consented span are never removed by this feature.

## Definition of Done

**Must have (MVP: items 1-3):**

1. `catalog/hooks/session-start.sh` and `.ps1` print a one-line banner: the version from `${NEXUS_HOME:-$HOME/.nexus-hub}/VERSION` only when it matches a bounded semver pattern (omitted otherwise) and the path of the full skill index under the same resolved home. No skill count, no command count, no command removed in v3.2.0. The hook's own git block collapses to one line (`Git: <branch>, <n> changed file(s)`). A test asserts values against fixture files, never literals, and asserts that a multi-line payload in either file prints nothing.
2. The digest written by `catalog/hooks/session-summary.sh` / `.ps1` replaces the five-commit log with the same one-line git summary. The 8000-character cap (applied on read by session-start through `NEXUS_SESSION_START_MAX_CHARS`) is unchanged. `.sh` and `.ps1` digests match after normalizing the timestamp header and line endings, and the `.ps1` writes without a BOM.
3. `scripts/lib/installer/legacy_instruction_block.py` detects candidate Legacy Instruction Blocks as defined above by exact match against a generated fingerprint set `scripts/lib/installer/legacy_fingerprints.json`, reports each candidate span with its line range and SHA-256, and never classifies a line absent from the fingerprint set as a candidate. `scripts/measure_rendered_context.py` reports estimated tokens, per-section sizes, duplicate headings, skill-index line count, and candidate legacy spans for any instruction file, and a dated baseline is recorded.
4. Every install through a marker-merged integration reports a candidate span (with its estimated token cost and exact removal command), writes a hash-verified owner-only backup, and removes only that span when the run carries `--remove-legacy-instructions=<consent-sha256>` bound to the resolved target path, current full-file hash and span hash. A default or `--yes` run never removes, and backups are not automatically pruned. After all reported candidates are individually consented and removed, the file has zero detected candidate spans and exactly one skill-index `**Total:` line; every nonmatching line outside each consented span is byte-preserved, and each file write is atomic with line endings and BOM state preserved. Identical user-authored text inside an explicitly consented candidate span cannot be distinguished from shipped text; the shown diff, file-specific consent and retained backup make that boundary visible and recoverable.
5. `NEXUS_HUB_SKILL_INDEX=pointer` renders the Skill-Index Pointer instead of the embedded table on every integration where Native Skill Enumeration holds (contract read path AND an installed skill destination for the scope), removing at least 90% of the embedded index's estimated tokens there. The default remains the full index everywhere, and ineligible platforms render the full index under both values.
6. `prompt-engineering` carries the capable-model authoring rules, and the context-skill cluster declares one rule-ownership table (labelled catalog hygiene, not part of the injected-context outcome).

## Resolved decisions

Decided in the Step 4.5 grill on 2026-09-24, seeded from six plan-review lenses.

1. **Skill-index pointer ships opt-in everywhere** (user choice). The default flip is not decided here; it is recorded as a known gap owned by `v4.16.0-instruction-necessity-review`, whose evidence is the Phase 3 measurement plus an organic-selection comparison that the current pilot runner cannot yet perform.
2. **Legacy removal is exact-match only, with hash-bound per-run consent** (user choice, recommended). Candidate lines are those in a fingerprint set generated from every historical revision of the shipped templates and skill index; matching does not establish authorship. Consent is a per-invocation flag carrying a path-and-file-bound SHA-256 token after the user reviews the exact diff, never a standing environment variable. Verified backups are retained without automatic rotation.
3. **Hooks become lean and truthful** (user choice, recommended). Plan-state detection in the digest is parked: no plan-status contract exists that `/implement` writes, so a detector would report "none detected" almost always.
4. **Phase 1 keeps 1.1 and 1.2; the todos-on-demand question moves to v4.16.0** (user choice, recommended), with this plan's measurement tool as its evidence.
5. **v4.13.1's `edit_guard.py` is not the preservation path for the installer** (lens finding, factual): it tracks files an agent session touched and releases only after an in-session diff, and an installer subprocess has no session and never recorded the block. Phase 4 uses an installer-native preservation step: hash-verified backup, shown diff, hash-bound consent.
6. **The organic-selection pilot is parked with a spend cap of 0** (lens finding, factual): `scripts/run_trigger_pilot.py` varies only SKILL.md description lines and runs with `--setting-sources project`, so it cannot compare instruction-file variants without a new variant mode.
7. **Render work lives only in `scripts/lib/integrations/base.py`** (lens finding, factual): the bash `render_template` path was removed in v2.3.0 (`scripts/installer.sh:1839`); both installers render instruction files through the Python integration runner.

## Overview

The seeding comparison read two sources about agent practice and harness token cost against Nexus-Hub. Most of their advice is already shipped or queued in v4.16.0 through v4.17.3. What survived is narrow: the context Nexus-Hub injects is partly false, partly duplicated, and unmeasured. The session-start hook announces v1.1.5, 184 skills, and two commands removed in v3.2.0 to every session. One observed global instruction file carries a leftover pre-marker install that doubles the skill index, interleaved with rules the user edited. And the 337-row index is embedded in thirteen templates.

Phases run in reverse-engineer-first order. Phase 1 is zero-code catalog hygiene. Phase 2 makes the two session hooks truthful and lean. Phase 3 builds the read-only detector, its fingerprint set, and the measurement script. Phase 4 acts on detected spans through the instruction writer, with consent bound to the exact span. Phase 5 adds the opt-in pointer and measures its saving.

Everything stays local. No phase adds an outbound call, a credential, a runtime dependency, or a third-party data processor. The measurement script uses an offline token estimator and never downloads a tokenizer.

## Phase 3: Legacy-span detector, fingerprints, and measurement

**Stability Gate**: detector, fingerprint builder, and script tests pass; `python scripts/build_legacy_fingerprints.py --check` exits 0; `python scripts/measure_rendered_context.py --path <fixture> --check` exits 1 on the two-index fixture and 0 on a clean one; the baseline file exists.

**Recommended model tier**: frontier
**Recommended effort level**: high
