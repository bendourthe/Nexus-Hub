## Overview

This plan is the instruction-surface half of the comparison against OpenAI's "Rethinking skills and prompts for GPT-6 Astra". It was originally Phase 2 of `v4.13.1` and was split out after a seven-lens plan review: the scope and product lenses independently found it unrelated to the model-routing work, touching a disjoint artifact set, carrying twenty times the blast radius, and higher in user value. It is explicitly independent of that plan's verdict, so it ships whether or not a model-adaptive runtime is ever built.

The problem is accumulation. `AGENTS.md` is 541 lines, it is loaded in every session on roughly twenty platforms, and nothing has ever obliged anyone to ask whether a rule in it is still earning its place. The source article's argument is that guidance authored to compensate for weaker models actively degrades stronger ones, which makes an unreviewed instruction surface a cost that compounds silently. Two rules in the user's global `CLAUDE.md` illustrate the shape the article warns about: a mandatory description on every shell invocation, and a mandatory one-sentence explanation before every file read.

**What "highest value" means here, and why it is bounded.** The review found the original phase unbounded: "enumerate every standing rule" caps the audit but not the work the audit generates, since every conversion fans out across five machine-guarded templates plus eight unguarded ones. This plan therefore caps conversions at a stated number for this release and routes the remainder to the recurring review it establishes. The audit is exhaustive; the edit is not.

**What this plan does not do.** It does not edit the user's global `CLAUDE.md`, which lives outside this repository. It does not weaken any trust-boundary, data-loss, security, or accessibility rule; `Construction Discipline` names those as never-cut, and "a newer model needs less handholding" is not a reason to remove a safety rail. It introduces no model-specific text into any shared body, since a shared body ships verbatim to every platform and one model-named line is wrong for every other reader. It creates no new skill, command, hook, or validator.

**Knowledge-base grounding.** No `docs/solutions/` store and no root `STRATEGY.md` exist; grounding is the seeding comparison plus `AGENTS.md` itself. Task ids begin at `T201` so this plan, `v4.13.1` (`T101`+), and `v4.13.0` (`T001`-`T034`) can be fanned out together without collision.

## Definition of Done

1. Every standing rule in `AGENTS.md` carries one of four verdicts with a one-line reason, recorded in `development/instruction-necessity-audit.md`.
2. A capped set of `make contextual` verdicts is applied, and `scripts/check_base_template_parity.py` passes.
3. The eight non-lockstep substantive templates were checked by hand and the result recorded, since the parity script does not cover them.
4. A before/after figure (line count and approximate token cost) is recorded for `AGENTS.md`.
5. The recurring review is absorbed by an existing governance owner, or explicitly deferred with a reason.

## Phase 1: Audit and cap

**Goal**: Produce a per-rule verdict for every standing rule, plus an agreed cap on how many conversions this release applies, before any file is edited.

**Prerequisites**: None. Confirm the `v4.12.0` history rewrite has landed or been deferred before starting.
**Stability Gate**: `development/instruction-necessity-audit.md` holds a verdict and reason for every standing rule in `AGENTS.md`, plus a before-figure for line count and approximate token cost, and the user has agreed the conversion cap.
**Verification Expectation**: Count the rules enumerated in the audit table and confirm the count matches an independent enumeration of `AGENTS.md`'s standing rules; quote both numbers. A mismatch means the audit is incomplete, not that the count is wrong.
**Recommended model tier**: frontier
**Recommended effort level**: high
**Rationale**: Judgment-heavy reading of behavioral guidance whose removal changes agent behavior on roughly twenty platforms; under-scoring here produces edits nobody can justify later.

### Sub-tasks

#### 1.1 -- Audit every standing rule for continued necessity

**Objective**: Assign every standing rule one of four verdicts with a reason.

**Prompt**:
> Enumerate every standing rule in `AGENTS.md` and assign each: **keep** (still earns its tokens), **make contextual** (should fire on a trigger rather than always), **remove** (the condition that motivated it no longer holds), or **defer** (needs evidence this phase cannot gather).
>
> Write the result to `docs/releases/v4/v4.13/development/instruction-necessity-audit.md` as a table with a one-line reason per rule.
>
> Apply the source article's test as the standard: a rule survives if someone can name what goes wrong without it. A rule whose only defence is that it has always been there is a `remove` or a `defer`, not a `keep`.
>
> Two scoping rules. First, do NOT edit `AGENTS.md` in this sub-task; auditing and editing are separated so the verdicts are reviewable independently of the diff. Second, the user's global `CLAUDE.md` is outside this repository and must not be edited; where a finding applies to it, record the recommendation and mark it out of scope. Two of its rules are the clearest instances of the pattern under review (a mandatory description on every shell invocation, and a mandatory explanation before every file read), so recording them is worthwhile even though acting on them is not this plan's to do.
>
> Also record the BEFORE figure: `AGENTS.md` line count and approximate token cost. It was 541 lines on 2026-09-14.

## Phase 2: Apply, propagate, and establish recurrence

**Goal**: Apply the capped conversions and approved removals with template parity intact, review boundary language once for over-constraint, and make the review recur under an owner that already exists.

**Prerequisites**: Phase 1, including the agreed cap.
**Stability Gate**: `scripts/check_base_template_parity.py` passes; the eight non-lockstep templates were checked by hand with the result recorded; and the after-figure is recorded beside the before-figure.
**Verification Expectation**: Run `python scripts/ci/run.py --profile full` and observe `check_base_template_parity.py` pass. Then open two of the five lockstep templates and confirm by eye that an edited invariant block is byte-identical in both. If no invariant block was edited, record that explicitly and state which verdicts were applied instead; that is a valid outcome, not a skipped check.
**Recommended model tier**: frontier
**Recommended effort level**: high
**Rationale**: Cross-cutting edits to behavioral guidance distributed verbatim to roughly twenty platforms; a wrong edit ships to every reader and the lockstep rule turns a partial edit into a build failure.

### Sub-tasks

#### 2.1 -- Apply the capped conversions

**Objective**: Convert the agreed blanket requirements into contextual triggers.

**Failure modes**: If an edit changes a lockstep invariant block in only some of the five templates, the parity guard fails the build rather than shipping a divergence; revert and reapply across all five in one change. If a rule's trigger condition cannot be stated precisely enough to be checkable, it stays unconditional and is recorded as `defer` rather than converted to a vague trigger, because a trigger nobody can evaluate is worse than an honest blanket rule. If two rules conflict after conversion (one contextual, one still blanket, covering the same concern), the `AGENTS.md` rule-ownership convention applies: name one owner and have the other reference it.

**Build class**: load-bearing.

**Prompt**:
> Apply exactly the conversions inside the Phase 1 cap, and exactly the approved removals. Do not exceed the cap; route anything beyond it to the recurring review.
>
> The source article's own example is the pattern: replace "read architecture.md before every edit" with "use architecture.md for service boundaries".
>
> Where an edit touches a section that also appears in `templates/ai-instructions/base-*.md`, apply it to all five lockstep templates (claude, codex, cursor, gemini, opencode) AND check the eight other substantive templates named in `AGENTS.md`. **Note precisely what the parity script covers**: `check_base_template_parity.py` defines `LOCKSTEP_FILES` as those five and iterates only over them, so the other eight are checked by hand and their result must be recorded explicitly. Treating the script as covering thirteen is the silent-miss this sub-task exists to prevent.
>
> Run `python scripts/check_base_template_parity.py` after every template edit, not once at the end, so a divergence is attributed to the edit that caused it.
>
> Record the AFTER figure (line count, approximate token cost) beside the before-figure from 1.1, plus the final counts of keep / make-contextual / remove / defer. That pairing is what turns the recurring review into "a review against a number" rather than a formality.

---

#### 2.2 -- Review boundary language for over-constraint

**Objective**: Check existing shared-body boundary language for the failure mode the article describes, introducing no model-specific text.

**Prompt**:
> Review safety and boundary language across `AGENTS.md` and the thirteen instruction templates for guidance that helped an earlier model but causes unnecessary hesitation in a more capable one.
>
> Three hard rails, none relaxable:
> 1. No edit may introduce a model identifier into a shared body. The `model-prompting-research` apply engine blocks this independently; do not work around it.
> 2. A finding true of one model rather than all models is `model-specific` by definition and belongs in the profile layer, not a shared body. Ambiguity resolves to `model-specific`.
> 3. Do NOT weaken any trust-boundary, data-loss, security, or accessibility rule. `Construction Discipline` names those as never-cut.
>
> Rail 3 has a concrete precedent worth stating: the companion `v4.13.1` plan's Phase 1 audit found that the per-model profile layer already contains a claim reading "so REMOVE explicit verification instructions and legacy harness verification scaffolding". That is exactly the edit rail 3 forbids, arriving with vendor-sourced authority. Treat any similar-sounding recommendation with the same suspicion regardless of where it came from.
>
> Record the review under a `## Boundary language` heading. A finding of "no over-constraint found" is valid only when the review's scope is stated and a representative sample is quoted.

>
> Whichever way it goes, record the owner (or the deferral) and the reason in the audit file, and state the number the future review measures against: the recorded line count and verdict counts.
