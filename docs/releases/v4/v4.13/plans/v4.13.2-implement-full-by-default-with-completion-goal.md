**Project**: Nexus-Hub
**Version**: v4.13.2

**Status**: queued
**Seeded from**: user request on 2026-09-24 (no comparison); placement in `docs/releases/v4/v4.13/development/v4.13.2-queue-assessment.md`

**Goal**: On every platform Nexus-Hub installs into, `/implement <plan>` (or bare `/implement`) implements the whole plan without stopping, through every task, phase, and known gap, green CI with the tests the work needs, the merged integration, the full release, and the removal of the plan's merged branches and worktrees, stopping only on a named blocker outside the approvals collected at the start or on the user's own pause, with completion decided by a checker script and enforced by the strongest mechanism each platform documents.

## Definition of Done

**Must have:**

1. `/implement <plan>` and bare `/implement` run the full driver by default and set up the completion goal; one phase runs only with an explicit `phase <N>` token; `phase-by-phase` stays opt-in; bare `/implement` shows the resolved plan as the first line of the upfront round.
2. One upfront round collects every approval the run needs as exact, hash-frozen actions (the resolved plan, push and merge, the release version with tag and publication, the release PRs and back-merge for that version, re-pushes after a locally reproduced fix up to 3, generated release notes, refactor moves inside plan-touched folders, spend caps, and each "Ask first" surface the plan names); no approval recorded there is asked again; CI workflow, permission, and secret changes are always named blockers.
3. `check_plan_completion.py check <plan>` prints a first line of exactly `PLAN COMPLETE <plan> <head> <nonce>`, `INCOMPLETE: <predicate ids>`, `BLOCKED: <category>`, or `PAUSED`, and exits 0, 1, 3, or 4 (2 on malformed input); known gaps pass only when resolved, or deferred under a gap type the user named upfront (reported as `PLAN COMPLETE ... (N deferred)`); every predicate has a fixture test.
4. `docs/policy/completion-levers.json` records, per registered platform, its native goal, turn-end continuation, and headless levers as VERIFIED with a vendor URL and date, or "none documented"; a validator fails when a registered platform is missing or a VERIFIED row lacks a source.
5. On every platform with a VERIFIED continuation lever, the `completion-gate` adapter refuses or continues the stop while the checker reports `INCOMPLETE`, in that platform's documented format, and allows it on `PLAN COMPLETE`, `BLOCKED`, or `PAUSED`; parity tests cover each adapter.
6. `nexus-hub run-plan <plan> --platform <key>` relaunches the platform's documented headless CLI with resume until the checker reports a terminal verdict, setting the native goal where the platform documents a headless goal entry point, for every platform with a VERIFIED headless lever.
7. `/implement pause` stops a run at the user's request on every platform, and the run resumes with `/implement <plan>`.
8. `/update release` consumes the recorded release approvals and asks only about differences from them.
9. The end-to-end evaluation passes for the automatable layers (native goal plus hook plus runner on Claude Code, hook plus runner on Codex, plugin plus runner on OpenCode), with the IDE hook-only layer covered by the last-phase human test and a recorded gap; if it still fails after five fix-and-rerun cycles, the fallback slice ships (below) and the miss is an owned known gap.

**Fallback slice (resolved decision 3):** the checker, the gate adapters, the runner, and the pre-approved release path ship; `/implement <plan>` keeps its previous one-phase default unless `full` is given.

## Non-Goals

- Changing a platform's own continuation caps (for example Claude Code's and Qwen's 8 consecutive Stop blocks, Copilot CLI's 8, Cursor's `loop_limit` of 5, OpenClaw's 3 revisions). The runner is the layer that continues past them.
- Enforcement on Windsurf/Devin Desktop IDE Cascade (its turn-end hooks are logging-only), Aider (no hook), and Nexus-AI (no documented events): these receive the completion contract as instructions, plus the runner where a headless CLI is documented (Aider `--message`, Devin CLI).
- Removing any safety gate. The `user-edit-guard` and `attribution-guard` hooks from `v4.13.1`, destructive actions outside the recorded approvals, and unreproducible red checks remain named blockers.

## Overview

`/implement <plan> full` already exists (`catalog/commands/implement.md:21`), yet full runs stop partway. The stops are designed in: a per-phase pre-flight confirmation (`catalog/skills/workflow/implement-phase/SKILL.md:35`), driver stops on context exhaustion (`:40`), mid-run approvals for push, merge, release, refactor moves, and CI changes, and a closing summary at every phase that reads as "done".

This plan replaces "remember to keep going" with a checkable finish line enforced in layers. A checker decides done from repository and hosting state. On each platform, the strongest documented mechanism enforces it: a native goal command, a turn-end hook or plugin that refuses or continues the stop, and a Nexus-Hub runner that relaunches the platform's headless CLI with resume when a session ends or a platform cap is reached. Where none exists, the command and skill text carry the contract. The command defaults to the full driver, collects every approval once as exact actions, and `/update release` consumes them.

Research on 2026-09-24 against official vendor pages (recorded in Phase 1) found native goal commands on Claude Code, Codex (feature flag), Cursor (gated rollout), Copilot CLI, Antigravity 2.0 and CLI, Qwen Code, Kimi Code, and Hermes; continuation hooks on Claude Code, Codex, Copilot CLI and VS Code, Cursor, Gemini CLI, Antigravity, Qwen, Kimi, and Devin CLI; plugin continuation on OpenCode, OpenClaw, Pi, and Hermes; and headless modes on nearly all. The formats differ: top-level `decision: "block"` (Claude, Codex, Copilot CLI, Qwen, Devin CLI), nested `hookSpecificOutput` (VS Code), `followup_message` (Cursor), `decision: "continue"` (Antigravity), `decision: "deny"` (Gemini CLI), exit 2 (Kimi; a warning only in Copilot CLI), and typed plugins (OpenCode, OpenClaw, Pi, Hermes). One gate core with thin per-platform adapters handles them.

All logic is local. The checker and runner use `git`, the platforms' own CLIs, and the user's own `gh` pinned to the approved repository; none adds a third-party destination, credential, or dependency.

#### 1.3 -- Run record

**Objective**: Specify run state the agent cannot forge or lose.

**Prompt**:
> Specify in the contract: the run record lives outside any working tree at `~/.nexus-hub/runs/<sha256(repo root + remote URL + plan path)>.json`, owner-only, with a `schema` field; it binds the session id (and worktree path) of the run, the plan file's hash at approval time, and the approvals as exact action tuples (plan path, remote URL and `owner/repo`, source and target branch, release version, tag name, the list of branches and worktrees to remove, the approval classes with their bounds), each with the verbatim user approval text, all frozen by a hash. Approvals must originate with the user: on platforms with a prompt-submit hook (Claude `UserPromptSubmit` and its documented equivalents), an `approval-capture` hook stores a digest of each user prompt in hook-owned state, and `record create`, `answer`, and `pause` reject any approval whose verbatim text is not in a captured prompt from the bound session; where no such hook exists, those commands read confirmation from the terminal directly (`/dev/tty` or `CONIN$`), never from stdin or arguments, and fail closed when unattended. The approvals hash is an HMAC keyed by an owner-only secret the installer creates and no prompt text references. Any record tracked by git, whose plan hash no longer matches, or whose approvals HMAC changed mid-run is rejected (`BLOCKED: record-tampered`). Blockers are records inside the run record with one category from a closed list (`approval-not-covered`, `unreproducible-red-check`, `user-edit-guard`, `destructive-outside-approval`, `ci-security-change`, `no-progress`, `record-tampered`, `platform-unavailable`) plus evidence (a command and its output); a blocker whose question the approvals already answer is rejected. Pause is a user-origin record written only by `/implement pause`. The refusal counter and progress score are hook-owned state beside the record, not inside it. Resume: `/implement <plan>` shows any open blocker in the upfront round, records the user's answer as an approval, and clears it. A stale record (session gone, older than 72 hours) is reported once and ignored by other sessions. Record the location choice as a decision with alternatives (worktree `.nexus/`, git common dir, home). Acceptance: every adversarial and security finding from the 2026-09-24 review maps to a rule.
