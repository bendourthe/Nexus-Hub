**Goal**: Make the first generated draft of a handbook, report or deck survive inspection without a human acting as the rendering engine, by converting the field lessons from an extended manual build into gates that fail a build rather than advice a build can rationalise past.
**Source**: `agent-document-and-deck-quality-lessons.md`, compiled after an extended manual build of `docs/handbooks/algorithms/lvedp-algorithm.html` in the `rd-data-dev` repository - a 562 KB self-contained interactive handbook carrying 24 inline SVG figures and a 21-slide presentation mode. Roughly 60 numbered rules, about a third already marked `[GATE]` by its author.
**Predecessor**: [v4.11.0 interactive handbooks](v4.11.0-interactive-handbooks-and-presentation-default.md), whose nine rendered-output gates this plan extends. Its ledger is [v4.11 known gaps](../known-gaps.md).

## Goals first and definition of done

**The problem.** A document is a visual artifact: its correctness lives in rendered geometry, not in source text. An agent that inspects only its own markup is checking the wrong thing, so the user becomes the rendering engine - pasting screenshots back and saying "this is unreadable", "text overlaps the figure", "you did not edit this section at all". In the source project nearly every correction traced to that one behaviour, and several took five or more rounds.

**The persona.** A maintainer who asks for a handbook and expects to read it, not to proofread it. The measure of success is the number of visual corrections they must supply, and the target is zero for mechanically detectable classes.

**Definition of done.** Every rule in the source document that can be mechanically checked is a gate that fails a build, wired into `measure_handbook.py` or a bundled script, negative-controlled so it demonstrably fails without the fix. Every rule that cannot be mechanically checked without an authorship or beauty detector - which this repository forbids - is gated on a recorded attestation instead: the build emits an explicit record naming what it did, and a missing or empty record fails. Nothing in the source document is demoted to prose an agent can skip in silence.

### Why everything is gated, and what that means for the unmeasurable rules

The user's instruction is that everything is gated. The source document argues the same from its own experience: "an agent can rationalise its way past advice, but it cannot argue with a failing check."

The v4.11.0 cycle supplies the counter-evidence that shapes HOW this is done rather than whether. Three defect classes were pre-empted by guidance alone, before any gate fired: animated sourced digits, print contrast, and lost layout declarations. Two gates actively made things worse: an activate-and-observe control check produced only false positives on idempotent controls while missing the defect it was built for, and the `text-overlap` rule has now deleted working sticky navigation three times.

The resolution is not fewer gates. It is that a gate must key on a signal that is crisp. Where the signal is crisp - a computed font size, a duplicate legend colour, a declared property that did not compute - the gate asserts the defect directly. Where it is not - whether prose was cut enough, whether a composition is balanced - the gate asserts that the decision was MADE AND RECORDED, not that it was made correctly. An attestation gate cannot be passed by silence, which is the failure mode that matters, and it does not fabricate a judgement the machine cannot make.

### Out of scope

Rewriting the `rd-data-dev` handbook, importing its content or data, building a charting engine, a general diagram editor, an authorship or beauty detector, or any hosted rendering service. `construction-debt: no second extractor, no second chart framework, no new MCP, no new hosted dependency.`

## Phase 1: Geometric audit foundation

**Goal**: Ship the mechanically-detectable defect audit as a bundled script, measured in screen space, with the two false-positive defences that made the source project's first version useless.
**Prerequisites**: v4.11.0 Phase 7 complete and merged; clean feature worktree from refreshed develop.
**Stability gate**: The audit reports zero findings on a known-good fixture and a specific non-zero finding on each deliberately broken fixture, one per check.
**Verification expectation**: Run the audit against the retained v4.11.0 qualification artifacts and against purpose-built broken fixtures. Every check must fire on its own fixture and stay silent on the others.
**Recommended model tier**: frontier
**Recommended effort level**: max
**Rationale**: Cross-project scope and distributed context are high; the false-positive defences are subtle geometry work.

### Sub-tasks

#### 1.1 - Build the audit in screen space

**Prompt**:
> Create `catalog/skills/specialized-domains/document-to-interactive-html/scripts/geometric_audit.py`, taking Appendix A of the source document as the reference implementation rather than copying it verbatim. It checks six classes: text extending outside its SVG viewport, two labels overlapping each other, a label sitting on a plotted trace, two legend entries sharing one colour, type rendering far above the document scale, and inconsistent stroke widths across comparable traces. Measure in SCREEN space with `getBoundingClientRect`, never `getBBox`, because `getBBox` ignores transforms and reported every rotated y-axis title as clipped. For label-on-trace, sample real points along the path with `getPointAtLength` rather than testing against the trace's bounding box, which is the whole panel for a wiggly trace, and respect `clip-path` because geometry clipped away is never visible and produced phantom overlaps. Emit a JSON record naming each finding's element, check and measurement. An unavailable renderer reports unverified with its exact error, never a pass.

- [ ] T001 Build the audit in screen space `catalog/skills/specialized-domains/document-to-interactive-html/scripts/geometric_audit.py`

#### 1.2 - Prove each check independently

Add the two false-positive fixtures explicitly: a rotated axis title that must NOT report clipped, and a label beside a wiggly trace within the trace's bounding box but not on its ink, which must NOT report an overlap. Negative-control every assertion by disabling the check and confirming the matching test fails.

## Phase 2: Type roles and the SVG render ratio

**Goal**: Make type size a rendered property rather than an authored one, and close the one-sided font gate.
**Prerequisites**: Phase 1 committed.
**Stability gate**: A figure whose authored font size renders outside the document scale fails, and the same figure passes once its size is derived from its measured ratio.
**Verification expectation**: Measure each figure family's ratio in the browser at the document's real reading width, and confirm derived sizes land within tolerance of the target rendered size.
**Recommended model tier**: frontier
**Recommended effort level**: max
**Rationale**: The scaling trap is non-obvious, measurable, and produced visibly inconsistent type across four families in the source project.

### Sub-tasks

#### 2.1 - Derive authored size from the measured ratio

**Prompt**:
> An SVG scales to its container: a `font-size` written into the file is multiplied by css width divided by viewBox width. Two figures carrying `font-size:14px` render at different sizes when their viewBox widths differ relative to layout width; the source project measured ratios of 1.271, 1.330, 1.125 and 1.188 across four families. Add to `references/responsive-typography.md` the complete named text-role inventory (title, subtitle, heading 1 to 3, lead, body, caption, plot-title, axis-title, axis-tick, legend, annotation, annotation-strong, table-header, table-cell, mono), the rule that every text node belongs to exactly one role, and the derivation: authored size equals target rendered size divided by that family's measured ratio. State that the ratio is MEASURED in the browser at the real reading width, never estimated. Keep the HTML scale and the SVG scale as two implementations of one scale, with the rendered measurement as arbiter.

- [ ] T004 Derive authored size from the measured ratio `catalog/skills/specialized-domains/document-to-interactive-html/references/responsive-typography.md`

#### 2.2 - Gate oversized type and role coverage

**Prompt**:
> Extend `measure_handbook.py` with an oversized-type ceiling. The existing font pass enforces floors only, so text rendering far ABOVE the document scale passes silently, which is exactly how the scaling trap escapes. Add the ceiling per role using the same `getScreenCTM` scaling the floor pass already applies. Add a role-coverage check: every visible text node must carry a resolvable role, and an unassigned node fails with its text and selector. Negative-control both.

- [ ] T005 Gate oversized type and role coverage `catalog/skills/specialized-domains/document-to-interactive-html/scripts/measure_handbook.py`

#### 2.3 - Automated testing and stabilization

**Prompt**:
> Run affected suites and the fast profile, record CI impact, write phase evidence and session history, and create exactly one scoped local commit. Do not push.

- [ ] T006 Verify and locally commit Phase 2 `docs/releases/v4/v4.11/development/document-quality/phase-2-evidence.md`

## Phase 3: Figure and diagram construction gates

**Goal**: Gate the figure rules that carry crisp signals, and crop the dead space that the source project's user asked to remove at least ten times.
**Prerequisites**: Phase 2 committed.
**Stability gate**: Legend integrity, tick range, stroke consistency and viewBox cropping each fail their own fixture and pass a corrected one.
**Verification expectation**: Run against the retained qualification artifacts and the broken fixtures; confirm no check fires on a legitimate figure.
**Recommended model tier**: frontier
**Recommended effort level**: high
**Rationale**: Boundary verification across several independent checks, each with a clear pass condition.

### Sub-tasks

#### 3.1 - Legend and tick integrity

**Prompt**:
> Add to `references/figure-reconstruction.md` and gate in the audit: every legend entry must correspond to something actually drawn and its swatch must match the drawn mark; no two legend entries may share a colour when the rendering keys legends by colour; and no tick may be emitted outside the data range, which produced a "1 s" tick outside a 0.97 s panel. Real defects the source project shipped include a legend showing filled dots where the figure drew rings, a legend listing items absent from the plot, and a legend dot in a different colour from the figure's dots.

- [ ] T007 Legend and tick integrity `catalog/skills/specialized-domains/document-to-interactive-html/references/figure-reconstruction.md`

#### 3.2 - Colour identity and stroke consistency

**Prompt**:
> Add the one-colour-per-signal-identity rule: a raw signal, its resampled version, its smoothed version and its derivatives are the SAME signal, so they keep one colour and are distinguished by dash pattern. Gate consistent stroke width across comparable traces; the audit already reports stroke widths per class to expose drift. Record that arrows take the colour of the label they belong to, and that a secondary trace is drawn under the primary one, thinner and at lower opacity.

- [ ] T008 Colour identity and stroke consistency `catalog/skills/specialized-domains/document-to-interactive-html/references/svg-diagram-quality.md`

#### 3.3 - Crop viewBoxes to content

**Prompt**:
> Gate dead space: measure actual content bounds and fail a viewBox carrying more than a small margin beyond the ink. Cropping the viewBox is strictly better than moving elements, because coordinates stay untouched so nothing drifts. Worked examples from the source project: a flowchart declaring `viewBox="0 0 1240 470"` with content at y 40 to 436 cropped to `"0 22 1240 432"`; a Gantt chart declaring `"0 0 1240 538"` with content at y 58 to 492 cropped to `"0 34 1240 480"`. Also gate the recurring gap between the x-axis title and the legend, and check clamped spacing tokens at realistic widths rather than at their minimum, where a footer clamp resolved to 72 px of dead space at 1600 px.

- [ ] T009 Crop viewBoxes to content `catalog/skills/specialized-domains/document-to-interactive-html/scripts/geometric_audit.py`

## Phase 4: Deck integrity gates

**Goal**: Gate the deck defects that are invisible in markup and only appear while a slide is current.
**Prerequisites**: Phase 3 committed.
**Stability gate**: A slide overflowing its canvas fails; an element left invisible by a fill-mode collision fails; a dangling clone reference fails.
**Verification expectation**: Walk every slide while it is the current slide, at the design canvas, and confirm each check fires only on its own defect.
**Recommended model tier**: frontier
**Recommended effort level**: max
**Rationale**: Timing-dependent and state-dependent verification, the class that has most often produced false results.

### Sub-tasks

#### 4.1 - Clone resolution and canvas fit

**Prompt**:
> Add to `references/dual-view-handbooks.md` and gate: slides CLONE the document's figures at runtime rather than carrying their own copies, because two drawings of one thing diverge on the first edit. Renumber ids in the copy rather than stripping them - a figure referencing an arrow marker by id twice appeared to work only because the original was still in the document to resolve against - and rewrite `url(#x)` and `href="#x"` literally, not by regex. Append the container node, not its children. Gate that every clone holder resolves and is non-empty, and that no slide overflows the fixed canvas in x or y, scaling offenders to fit rather than clipping, since there is nowhere to scroll.

- [ ] T011 Clone resolution and canvas fit `catalog/skills/specialized-domains/document-to-interactive-html/references/dual-view-handbooks.md`

#### 4.2 - Animation order and fill-mode collisions

**Prompt**:
> Gate two animation defects. First, sequencing: an animation must follow the slide's narrative order, so a step cannot begin before the thing it acts on is drawn; express a group's delay as its start in the narrative and stamp a per-child index from the engine rather than relying on `nth-child`, which broke when a list's length changed and animated the last rows first. Second, fill-mode collisions: combining a staggering utility that sets `opacity:0` filling forwards with a component that animates itself filling backwards left four tiles permanently invisible, undetectable in markup review and trivially detectable by measuring opacity after the animation window. Measure each slide WHILE IT IS THE CURRENT SLIDE - a probe that checks all slides at the end reports everything hidden, because only the current slide is displayed, which produced a false alarm in the source project.

- [ ] T012 Animation order and fill-mode collisions `catalog/skills/specialized-domains/document-to-interactive-html/scripts/measure_handbook.py`

#### 4.3 - Automated testing and stabilization

**Prompt**:
> Run affected suites and the fast profile, record CI impact, write phase evidence and session history, and create exactly one scoped local commit. Do not push.

- [ ] T013 Verify and locally commit Phase 4 `docs/releases/v4/v4.11/development/document-quality/phase-4-evidence.md`

## Phase 5: Attestation gates for the unmeasurable

**Goal**: Gate the rules that cannot be mechanically judged, by requiring a recorded decision rather than a heuristic score.
**Prerequisites**: Phase 4 committed.
**Stability gate**: A build with a missing or empty attestation record fails; a build with a complete record passes; no attestation asserts a judgement the machine made.
**Verification expectation**: Confirm the record is emitted, is machine-checkable for completeness, and that removing any required entry fails the build.
**Recommended model tier**: strong
**Recommended effort level**: high
**Rationale**: Contract design rather than novel measurement, but it must not drift into scoring taste.

### Sub-tasks

#### 5.1 - Figure class and data provenance

**Prompt**:
> Every figure declares itself ILLUSTRATIVE or EVIDENTIAL in the retained record, and the build fails if any figure is unclassified. Illustrative figures carry no measured values and label the rule rather than the number - "walk-stop threshold: 25 % of this window's own peak", not "threshold = 4.0"; the source project's user asked three separate times to remove real values from conceptual plots. Evidential figures carry values traceable to a real computation. Gate that no point, dot or marker comes from a hardcoded list chosen to look right: the record names the computation each series came from, and an unsourced series fails. Where a number appears in both a figure and its prose, the record names the single shared source it was derived from, because a quoted figure in the source project flipped between 4.7 and 27.8 depending only on where a window was cut.

- [ ] T014 Figure class and data provenance `catalog/skills/specialized-domains/document-to-interactive-html/references/figure-reconstruction.md`

#### 5.2 - Content cuts and claim verification

**Prompt**:
> Require a recorded content-discipline attestation: what was cut and why, since a generated first draft is typically two to three times longer than the useful version and the source project's user asked for reductions repeatedly. Require that any claim about how code behaves names the file and function it was verified against IN THE SAME SESSION - the source project stated three confident errors about thresholds and algorithms that the user's questions exposed. An empty or absent record fails. The gate checks that the decision was recorded, not whether the prose is good.

- [ ] T015 Content cuts and claim verification `catalog/skills/specialized-domains/document-to-interactive-html/references/content-intent.md`

#### 5.3 - Document-specific AI tells

**Prompt**:
> Extend `anti-slop-editing` with the document-specific tells: coloured left-border callout stripes as the default emphasis device, uniform three-card grids as the answer to every piece of content, emoji as section markers in a professional document, heavy em-dash rhythm, sentences that announce structure instead of delivering content, and every section carrying exactly three bullets of similar length. Gate the mechanically detectable members of that list - left-border stripes and uniform card grids are countable in the rendered DOM - and require an attestation for the rest. New content matches the SURROUNDING document's conventions rather than importing a house style.

- [ ] T016 Document-specific AI tells `catalog/skills/developer-experience/anti-slop-editing/SKILL.md`

#### 5.4 - Automated testing and stabilization

**Prompt**:
> Run affected suites and the fast profile, record CI impact, write phase evidence and session history, and create exactly one scoped local commit. Do not push.

- [ ] T017 Verify and locally commit Phase 5 `docs/releases/v4/v4.11/development/document-quality/phase-5-evidence.md`

## Phase 6: Wiring, rule file, and cross-surface consistency

**Goal**: Make the loop mandatory repository-wide, wire the gates into the commands that produce documents, and gate the reorder consistency that survived many sessions in the source project.
**Prerequisites**: Phase 5 committed.
**Stability gate**: The composite gate is callable from `presentify`, `/update docs` and `/update release`; a section reorder that leaves navigation or cross-references stale fails.
**Verification expectation**: Exercise each wired command against a fixture and confirm the gate runs and can fail.
**Recommended model tier**: frontier
**Recommended effort level**: high
**Rationale**: Cross-surface wiring with a one-owner constraint and several existing consumers.

### Sub-tasks

#### 6.1 - The global visual-verification rule

**Prompt**:
> Create `catalog/rules/html/visual-self-verification.md` beside the existing `responsive-layout.md`. It states that any task producing or editing a rendered artifact is incomplete until the agent has rendered it headless, captured the edited region and inspected the capture; that the agent never requests a screenshot the agent can render itself, because a user supplying screenshots is a symptom of a broken loop; that verification reads computed DOM values, never re-read authored source; that every programmatic edit asserts its anchor is present and unique before replacing, since a replacement matching nothing does nothing and reports success; and that captures are clipped to the edited REGION and capped near 1500 px longest edge at device scale 1, because oversized images are silently rejected by the image pipeline and cost the agent its only feedback channel. Extend `verification-before-completion` so rendering evidence is explicitly required for visual artifacts and "I made the edit" is not evidence.

- [ ] T018 The global visual-verification rule `catalog/rules/html/visual-self-verification.md`

#### 6.2 - Command and gate wiring

**Prompt**:

Add the gate definition to `quality-gate-definitions`: the artifact renders with zero page errors, the geometric audit returns zero findings in every category, no element overflows its designed container, all figure and table references resolve, line endings are unchanged from baseline, and the agent has captured and inspected the edited region. ## Risks and cut lines

- **Gate noise is the primary risk.** The v4.11.0 cycle shipped one check that fired only on working controls and another that has deleted working navigation three times. Every gate here must fail its own fixture and stay silent on the others before its phase closes; a check that cannot be shown to fail is not evidence.
- **Attestation gates must not become scoring.** The moment an attestation gate judges whether prose is good rather than whether a decision was recorded, it is a beauty detector and the plan forbids it.
- **The source document is one project's experience.** Its rules were paid for with real corrections, but a rule that cannot be stated as a check on this catalog's artifacts is recorded as a known gap rather than forced into a gate.
- **Scope**: no charting engine, no diagram editor, no authorship detector, no hosted service. Add a helper only for a concrete behaviour with no existing implementation.
- **Cut line**: Phases 1 to 4 carry the mechanically detectable value. If scope must be cut, Phase 5's attestation gates are the first candidate to defer, and their rules revert to recorded known gaps rather than silent prose.
