## Goals First / Definition of Done

**Persona and problem**: A Nexus-Hub user writing an agent prompt or technical diagram needs trustworthy cost explanations and readable figures. The current cache example can report 900% when 900 tokens were read from cache and 100 were uncached. Visual guidance covers many static defects but needs an explicit source-detail decision and targeted geometry evidence.

| ID | Observable completion condition |
|---|---|
| D1 | The actual distributed example reports 90% for uncached/read/created = 100/900/0, 100% for 0/900/0, 0% for 100/0/0, and 75% for 100/900/200. An all-zero request is explicitly no input, not evidence of cache effectiveness; malformed or unavailable telemetry is unknown/error. |
| D2 | Cache guidance distinguishes stable prefixes, tool definitions, top-level versus per-message effort, diagnostics and prewarming restrictions with dated official links. It makes no savings promise or automatic runtime change. |
| D3 | A bounded prompt audit produces a before/after decision record while preserving user requirements, trust boundaries, hard budgets, and required proof. Synthetic demonstrations are explicitly labeled; they do not prove live agent behavior or savings. |
| D4 | Three examples demonstrate queue flow, diverging decision paths, and trust boundaries; the chosen structure makes the intended relationship explicit. Existing readable text and accessibility rules still apply. |
| D5 | Faithful reconstruction and an explicitly authorized derived summary each account for every source node and relationship. The concise summary visibly exposes retained, merged, and omitted details; it never replaces or mislabels the lossless reconstruction, and approval is required for substantive omissions. |
| D6 | Local verification detects a connector label hidden by a later opaque node and a connector routed through an unrelated node, passes intentional badges and clean routing, and returns unchecked coverage for unsupported geometry instead of a false pass. Browser evidence corroborates the supported cases across declared widths/themes. |
| D7 | The final evidence connects D1-D6 to actual artifacts, preserves existing scorer/API behavior, proves distribution on supported operating systems, and records all scoped validation and independent review results. Publication and release claims wait for their explicit gates. |

Cache share means cache-read input divided by the sum of uncached, cache-read, and cache-created input tokens. It is a token proportion, not a currency saving or the percentage of requests that hit cache. A source-detail ledger is a short accounting table beside the existing reconstruction guidance, not a new persistent data service.
