## What this phase set out to do

Close the plan: reconcile architecture and known gaps, exercise the feature
through its real boundary, bring the pipeline into line once, and prepare a
single approval-gated integration.

## What it actually found

Four defects, none of which the phase was looking for. All four are the same
shape: a gate that reported clean while the thing it guards was broken.

1. **The conflict-marker gate matched only seven characters.** Git widens the
   run when the two sides disagree about the path, so the rename that moved this
   plan into `v4.11` committed eleven unresolved conflicts that the check could
   not see. Eight of the eleven had byte-identical sides, which is the signature
   of a rename conflict.

2. **Two skills owned rendered overlap and contradicted each other.** The
   `text-overlap` rule reported a sticky navigation bar drawn over body text as a
   defect, while the declared-position gate required that bar to be sticky.
   Working navigation had been deleted three times to satisfy both. The cluster
   had no rule-ownership table, which `AGENTS.md` requires.

3. **The repository's own handbooks had never faced a gate this plan shipped.**
   They were built at `a4349d40` and recorded as passing; the opening-screen
   opacity gate landed four commits later at `59492077`. Re-measuring the
   unchanged bytes failed with 100 errors.

4. **`check_handbooks.py` was wired into no CI profile.** A freshness gate the
   plan built that the repository never ran - which is why (3) went unnoticed.

## The decision that mattered most

The 100 opacity failures were a deliberate `opacity: .85` de-emphasis in the
handbook's own `design.css`, not an animation. Rather than decide by preference
whether that was a defect, the composited contrast was measured: 10.75:1 against
a 4.5:1 floor. The text is legible, so the gate was wrong.

The root cause was a split concern. Contrast scored the DECLARED ink, ignoring
both `opacity` and the ink's own alpha, so semi-transparent text measured as
opaque. The opacity floor was patching that hole from the other side with a bare
number that cannot tell 0.85-on-black from 0.96-on-grey. Contrast now composites
effective alpha and owns legibility; the opacity floor narrowed to 0.5 and keeps
only what contrast cannot see.

The net result is stricter, not looser: the old pair passed low-alpha text
outright while failing legible text.

## The lesson worth keeping

A negative control caught a test that would have shipped as false evidence. The
first transparency fixture, `rgba(120,120,120,0.62)`, scores 4.42:1 on the
declared ink - already below the floor - so it failed with or without the fix.
It was replaced with `rgba(85,85,85,0.45)`: 7.46:1 declared, 2.11:1 rendered.

A test that cannot fail against the unfixed code is not evidence, and running it
against the unfixed code is the only way to find out.
