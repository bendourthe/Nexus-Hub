# Comparison - Evals, Test Trust, and Visual Agent Communication

**Project:** Nexus-Hub
**Date:** 2026-10-08
**Baseline:** `develop`, `4f2da0bf56759e0550f16ea44560f90471d25081`
Adoption target: v4.18.4
**Placement status:** Provisional recommendation, not user-confirmed. The queue ends at v4.18.3 and no existing plan, comparison, or local release tag occupied v4.18.4 when checked. This work follows the related queued changes rather than renumbering them.
**Scope:** Six-source comparison and prioritized adoption recommendations. Catalog, templates, runtime behavior, and release status are unchanged.

Nexus-Hub can make agentic work easier to follow through diagrams, measured plots, interactive artifacts, and prominent risk notices. Much of the necessary guidance already ships. The remaining work is to make these choices at useful workflow moments, use each host's documented display capabilities, and evaluate whether the result improves understanding and preserves factual and safety information. A prompt can choose and author a representation; the host controls whether it renders inside chat.

## Findings by Source

### S1 - Evaluation Playbook

The strongest recommendations are already present in Nexus-Hub: real failure analysis, cheap checks for objective requirements, held-out judge validation, human labels, confusion metrics and intervals, controlled degradation, independent trials, regression cases, and full-cost accounting. The owners are [ai-output-evaluation](../../../../../catalog/skills/developer-experience/ai-output-evaluation/SKILL.md), its [evaluator-validation reference](../../../../../catalog/skills/developer-experience/ai-output-evaluation/references/evaluator-validation.md), [eval-pipeline-audit](../../../../../catalog/skills/ai-development/eval-pipeline-audit/SKILL.md), and [skill-eval-loop](../../../../../catalog/skills/workflow/skill-eval-loop/SKILL.md). Hamel's article supports human trace review, scoped assertions, validated model evaluators, and later user-outcome experiments.

The partial gap is comparative reporting. Same cases, model, trial count, and rubric are already required. The inspected owners do not provide a complete recipe for casewise gains and losses, a paired difference interval, or the assumptions behind an equivalence or detection claim. Add those to the existing evaluation owner, with a compact visual report exposing uncertainty and regressions. Do not create another evaluation framework.

| PDF evidence | What it supports | What it does not establish |
|---|---|---|
| p5: 34/60 human passes; overlapping failure categories | Read outputs and preserve failure evidence | Reproduced product performance or mutually exclusive error counts |
| p7: 36/60 agreement; judge passes 42, humans pass 34; 10/26 failures caught; kappa 0.15 | The example judge misses many failures; implied failure recall is 38.5% | A universal kappa release threshold |
| pp10-11: 70% for both prompts; paired difference interval [-11.7, +11.7] percentage points; approximately 14% regressions | Equal averages can hide different failed cases | Equivalence or a universal 12-point minimum detectable effect |
| pp12-14: stage evaluation, independent repeats, final state, path, cost per correct outcome | Separate retrieval, generation, execution correctness, and permitted actions | A retry-only pass replacing the original failure |
| pp14-16: benchmark setup, drift, report card, gates and monitoring | Pin setup and retain ongoing regression evidence | Leaderboard rank deciding whether a particular product ships |

The PDF's 12-point detection-floor claim omits a significance level, desired power, discordant-pair count, and calculation. Its displayed interval half-width is not a powered minimum detectable effect. A nonsignificant result does not establish equivalence. Its 0.6/0.8 kappa heuristics should not replace the existing reference's explicit rejection of universal thresholds. Likewise, a practical two- or three-point tripwire is a policy tolerance, not automatically a statistically supported non-inferiority result.

### S2 - Testing Tests

The excerpt's conclusion exceeds its stated evidence. It says success differences were not statistically significant and expressly leaves E2E testing untested. Neither finding proves that tests are useless. A 44-task subset with no detected effect requires an effect margin and uncertainty before it can support equivalence. The observed unit/integration proportions do not independently estimate their causal value without randomized test-type comparisons. Long-term regression protection and maintenance outcomes are also outside the described short-term benchmark.

The useful hypothesis is that code and tests can share one mistaken reading of the request. Nexus-Hub already addresses weak assertions in [false-confidence-test-audit](../../../../../catalog/skills/tests-generation/false-confidence-test-audit/SKILL.md), including tautologies, mocked subjects, re-baselined snapshots, and targeted mutation proof. [Functional-verification](../../../../../catalog/skills/testing/functional-verification/SKILL.md) requires observations through real boundaries.

Adopt independent expected outcomes from the requirement, a reproduced defect, a known-good external contract, or human-supplied cases. Preserve meaningful tests and existing regression suites. Use a deliberate wrong implementation or negative control to show a critical check detects the defect. Reuse the queued v4.17.6 and v4.18.3 testing work before adding more rules. A separate reviewer reduces shared context but does not, by itself, create independent ground truth.

### S3 - Agent Scripts

The transferable pattern is a small shared instruction owner plus reusable local helpers for repeated operations, rather than a large bespoke orchestration layer. The pinned [README](https://github.com/steipete/agent-scripts/blob/79150cfac4a6ba4df13cf30176bf2db85170ae6c/README.md), [docs-list helper](https://github.com/steipete/agent-scripts/blob/79150cfac4a6ba4df13cf30176bf2db85170ae6c/scripts/docs-list.ts), and [skill-sync helper](https://github.com/steipete/agent-scripts/blob/79150cfac4a6ba4df13cf30176bf2db85170ae6c/scripts/sync-skills) show discoverable operations and preservation of real destination directories. Nexus-Hub already distributes platform instructions, skills, helpers, and handoff artifacts. [Helper-script-authoring](../../../../../catalog/skills/developer-experience/helper-script-authoring/SKILL.md), [user-edit-preservation](../../../../../catalog/skills/workflow/user-edit-preservation/SKILL.md), [session-handoff](../../../../../catalog/skills/workflow/session-handoff/SKILL.md), and the queued v4.17.3 shared-instruction work cover much of this ground. The source's symlink topology does not justify replacing Nexus-Hub's existing copy-based installers.

Apply the pattern only to a measured repeated task that lacks an existing helper. Treat its central instructions as examples to compare, not rules to inherit. Do not copy platform-specific paths, permissive execution flags, automatic permission clicks, account integrations, or instructions that conflict with Nexus-Hub's edit, attribution, branch, and evidence rules.

### S4 - Material Risk Notices

The official Claude Code v2.1.287 changelog verifies `/plugin enable cc-plugin-you-should-know@builtin`. It describes an additional agent that flags missed information and limits availability to first-party sessions with telemetry enabled. The [current Mods overview](https://code.claude.com/docs/en/plugins/mods/overview) describes a side agent watching longer work and showing a note above the prompt, disabled by default and listed if available for the organization. This is broader than scanning only a final summary and does not guarantee a particular callout label or complete detection. The official Mods tutorial documents `ui.render` and typed host components. These are Claude Code features, not portable APIs.

Nexus-Hub's [agent-communication](../../../../../catalog/skills/developer-experience/agent-communication/SKILL.md) already requires Open items and the [communication style guide](../../../../../catalog/style-guides/agent-communication.md) limits verbose summaries. The narrower improvement is placement: put a material unresolved limitation or user-impacting risk near the outcome, with its evidence and consequence, before supporting details. Suppress empty or duplicate notices. A portable instruction can do that without enabling a plugin, adding a second model call to every response, or relying on a particular telemetry setting.

### S6 - CodeAF and Harness Measurement

The pinned [DeepSWE benchmark README](https://github.com/Agent-Field/CodeAF/blob/8761488a2e1db65a625ff072c29e411e4590fb6a/docs/benchmarks/deepswe/README.md) and its [arm table](https://github.com/Agent-Field/CodeAF/blob/8761488a2e1db65a625ff072c29e411e4590fb6a/docs/benchmarks/deepswe/arms.csv) substantiate the rounded headline as self-published results. Ten harnesses used 113 tasks and `deepseek/deepseek-v4-flash-0731` through OpenRouter, one seed/attempt per task, a three-hour task limit, four shards per harness, and verifiers pinned to `0b9fabb`. Nine arms ran on September 11 and the `senior-dev` arm on September 12.

| Arm | Solved | Success | Reported spend | Cost per solved issue |
|---|---|---|---|---|
| CodeAF `senior-dev` | 62/113 | 54.9% | USD 24.73 | USD 0.399 |
| Claude Code with the same open model | 16/113 | 14.2% | USD 21.72 | USD 1.358 |
| OpenCode with the same open model | 30/113 | 26.6% | USD 56.96 | USD 1.899 |

These totals yield 3.875 times Claude Code's solves, 2.067 times OpenCode's solves, and approximately 4.76 times lower cost per solve than OpenCode. The cost advantage over Claude Code is approximately 3.40 times. This compares particular harness configurations using one open model, not the assistants with their native/default models.

The source discloses one seed, an unresolved 62-versus-56 lead over mini-swe-agent, different explicit sampling parameters (`senior-dev` omitted temperature/top-p while other arms used 1.0/0.95), five missing outcomes counted unsolved, and aggregate-only costs for six harnesses. Published two-file evidence did not provide exact historical CLI versions or the per-issue paired outcomes needed here to independently establish paired uncertainty. Later solo-arm 88/113 and 78/113 results use different models and are not ten-arm comparisons. Record per-attempt versus aggregate cost availability and sampling mismatches alongside future comparisons.

The adoption is measurement discipline: evaluate model plus harness plus policy under a pinned budget and verifier, retain every failure and retry, and divide whole-run cost by verified successful outcomes. [v4.17.3](../../v4.17/plans/v4.17.3-adoption-harness-economics-and-portable-engineering-system.md) already queues a local harness-pairing evaluator. Extend its report if gaps remain after it ships. Do not adopt a universal number-one ranking, replace supported platform runtimes, or add an OpenRouter/service dependency to reproduce the headline.

The pinned [CodeAF README](https://github.com/Agent-Field/CodeAF/blob/8761488a2e1db65a625ff072c29e411e4590fb6a/README.md) also shows task trees, work needing judgment, changed files, cost, and incomplete work. Those are useful inputs for A2's observed-state map, not evidence that a portable skill can install a native task rail. The [benchmark guide](https://github.com/Agent-Field/CodeAF/blob/8761488a2e1db65a625ff072c29e411e4590fb6a/bench/README.md) describes an internal failure despite an outer zero exit and a green existing suite; the existing functional-verification/loop owners already require outcome evidence beyond exit status. Its [headless contract](https://github.com/Agent-Field/CodeAF/blob/8761488a2e1db65a625ff072c29e411e4590fb6a/docs/HEADLESS.md) is a reference for an existing CLI's stdout/stderr and result contract, not a reason to build another runtime.

## Prioritized Adoption Sequence

1. Refresh the baseline after the predecessors below. Reuse their completed outcomes; remove recommendations they already satisfy. Freeze realistic cases and expected behavior before editing instructions.
2. Apply A1 and A2 to existing communication owners. Keep safety, uncertainty, and needed decisions explicit in plain language; delegate the representation choice rather than copying the ladder into every template.
3. Apply only the remaining A3/A4 gaps. Specify the practical effect margin and statistical procedure when making an equivalence/non-inferiority claim; preserve the existing blocked-item and slice floors.
4. Reuse an existing viewer/chart path for A5. Add the minimum local artifact only if the current path cannot express the required evidence.
5. Qualify A6 on actual available hosts. Record version, surface, action, observation, and fallback. Unavailable hosts remain named gaps. A7 is optional and requires demonstrated repetition.
6. Run a bounded, preregistered comparison of the communication change: matched cases, independent expected answers, blind review where subjective, separate factual accuracy/risk recall/task comprehension measures, observed user actions where applicable, runtime cost including helper calls, and repeated independent trials. Presentation preference alone does not establish improved comprehension. Use existing evaluation and accessibility owners. Do not count an unrun user study as complete.

This is the adoption plan embedded in the comparison, not an approved implementation-phase plan. Source examples and prototype recipes are not measured Nexus-Hub gains. No new recurring side-agent, animation engine, hosted site, platform runtime, or benchmark service is needed by default.
