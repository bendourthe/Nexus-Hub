# Comparison - Dashboards and Motion, Evidence Ledgers, and Reliable Agent Automations

**Project:** Nexus-Hub
**Date:** 2026-10-09
**Baseline:** `develop`, `05f53d1cc4d973405597ededfb1774f0c397dd96`
Adoption target: v4.18.5
**Placement status:** User-confirmed on 2026-10-09. The queue ends at v4.18.4, and every recommendation here builds on v4.17.3, v4.18.0, v4.18.3, or v4.18.4, so it follows them rather than renumbering them.
**Scope:** Three-source comparison and prioritized adoption recommendations. Catalog, templates, runtime behavior, and release status are unchanged by this report.

Nexus-Hub can make every supported agent more autonomous and more visual without adopting any hosted product. The strongest gain is a portable reliability contract for unattended runs: per-source bookmarks, commit-after-confirm, a reported-item ledger, failed reads never treated as quiet days, re-verification before acting, and a checked spend cap. The second gain is an evidence ledger for `/compare`, so every gap claim carries a citation, a confidence level, and a bounded-search statement. The visual items (a query-provenance dashboard and code-rendered animation exported to MP4) are achievable locally but conflict with the cut ceilings of two queued plans, so they are recommended as gated follow-ons.

## Findings by Source

### S1 - Dashboards and Motion

Dashboards turns a plain-language question into a warehouse query, renders the answer as a chart, stamps each chart with its data freshness, and lets the reader click a number to see the query behind it. Motion writes a short explainer animation as code over text, charts, shapes, and images, with no video-generation model and no generated people, and exports MP4. The connectors, hand-offs to analytics vendors, hosted editor, refresh scheduling, and admin enablement are hosted-product features.

Two stated principles transfer to any platform: **show the work** (every number traces to its query; every animation stays editable code) and **animate your own content** (deterministic rendering, never generated footage).

Nexus-Hub already owns most of the representation layer. [html-output-conventions](../../../../../catalog/skills/developer-experience/html-output-conventions/SKILL.md) defines the representation ladder and [inline-visualization](../../../../../catalog/skills/developer-experience/inline-visualization/SKILL.md) (shipped in v4.13.9 with `/visualize`) charts a file or pasted table. The gaps are specific:

- **No query-backed chart.** [Data intake](../../../../../catalog/skills/developer-experience/inline-visualization/references/data-intake.md) reads one file or table snapshot, never runs a query, and never refreshes. [sql-expert](../../../../../catalog/skills/language-specialists/sql-expert/SKILL.md) has no chart content. The queued v4.18.4 plan explicitly declines a second dashboard.
- **No MP4 path.** The design already exists as v4.18.0's parked branch P1 (`seek(t)` frame contract, ffmpeg hardening, an `ffprobe`-verified tracer bullet). That branch targets deck and scene video, not chart-to-animation.
- **Templates do not steer agents toward visuals.** Every `templates/ai-instructions/base-*.md` Communication Contract covers prose, commands, and lists, but none points at the representation owners. v4.18.4 T006 connects workflow moments to those owners inside [the communication style guide](../../../../../catalog/style-guides/agent-communication.md); the always-loaded templates remain silent.

So, to the user's question: yes, agents on every platform can communicate through higher-end visuals. The portable route is local artifacts (self-contained HTML/SVG charts, code-rendered animation, locally encoded MP4) chosen through the existing ladder, with native host rendering used only where [platform-contract-verification](../../../../../catalog/skills/workflow/platform-contract-verification/SKILL.md) has qualified it. Prompt text cannot make a host render inline.

### S3 - Reliable Agent Automations

The article's design is a scheduled daily brief built on Claude Managed Agents. Of its 25 extracted mechanisms, 21 are platform-neutral and can be expressed as skill instructions plus local state files. The load-bearing ones:

1. **Per-source bookmarks, not time windows.** Each source reads from the timestamp of its newest item already read, so early or late runs neither skip nor repeat.
2. **Commit only after the destination confirms.** Bookmarks and the ledger advance together, after the post returns success. A failed source keeps its old bookmark.
3. **A failed read is never a quiet day.** The run reports the unreadable source by name and still delivers the rest.
4. **A reported-item ledger with stable ids.** One line per item: date, source id, stable item id, last status. Open items carry forward as one marked line; closed items drop; changed items are corrected.
5. **A run record with explicit states.** `posting` is written before the action, then `posted` with the destination id, or `maybe posted` when the result is unclear, in which case nothing else changes. Items dropped during verification are listed as cuts.
6. **Idempotency by destination search.** Before posting, search the destination for today's title and skip if present.
7. **Re-verify each item against its live source just before acting**, copy links from the source's own field, and drop what cannot be confirmed.
8. **Rules the agent cannot edit.** Preferences are read-only and re-read every run so planted source text cannot rewrite them; if they cannot be read, stop. Proposed changes go to state for a human.
9. **A spend cap whose stop reason is checked**, because a capped run looks like a quiet day. Start at 3 to 5 times a normal run's cost.
10. **Pin the time zone** and **grant least privilege** (read-only tokens, narrow scopes, web tools off).

Nexus-Hub's [loop-engineering](../../../../../catalog/skills/workflow/loop-engineering/SKILL.md) already supplies the loop schema (iteration cap, check command, exit condition, optional budgets, state contract, trace log), a scheduled-triage recipe, idempotent completion gates, stall detection, and checkpoint resume. [session-handoff](../../../../../catalog/skills/workflow/session-handoff/SKILL.md), `catalog/hooks/usage-guard.py`, and the completion-gate hooks cover interruption. The queued v4.17.3 plan adds run outcomes (`no-data`, `stale-input`, `partial`, `complete`, `failed`), an idempotency key, and processed/failed/skipped counts.

What no shipped surface or queued plan covers: per-source bookmarks, a failed-read ledger, commit-after-confirm with a `maybe posted` state, re-verification before recording, a required spend cap for unattended runs ([ai-billing-safeguards](../../../../../catalog/skills/ai-development/ai-billing-safeguards/SKILL.md) targets application SDK code, not harness runs), a read-only rules file, and any scheduler guidance beyond Claude Code. Nothing in `catalog/`, `guides/`, `docs/policy/`, or `templates/` mentions how to schedule an agent on Codex, Cursor, Gemini or Antigravity, OpenCode, or plain OS or CI schedulers. Other hosts today get "manual re-invocation".

## Prioritized Adoption Sequence

1. **Skill-native reliability and evidence first** (B1, B2, C1, C2). These have no dependency on the v4.18.x visual plans and give the largest autonomy and trust gain per line. Refresh against v4.17.3's outcome vocabulary and v4.15.0's report-output contract before editing.
2. **Cross-platform reach** (B3, V1). Qualify scheduler levers per host under the do-not-invent rule, then add the single lockstep template bullet once v4.18.4's T006 has shipped.
3. **Local builds** (C3, V2). Bundle the citation checker. Record the decision lifting v4.18.4's dashboard ceiling, then extend inline-visualization rather than create a new dashboard skill.
4. **Heavier optional capability** (C4, V3). Wire built-artifact sources only to existing owners. Un-park the video branch after v4.18.0 ships its illustration discipline and contact sheet.

This is the adoption plan embedded in the comparison. Each recommendation reuses an existing owner; no new runtime, scheduler daemon, hosted service, or MCP entry is required.
