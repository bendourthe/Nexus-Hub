**Goal**: Illustrations Nexus-Hub produces for `/presentify` pages, PowerPoint decks, and Word, PDF, and research-compilation reports follow one declared production discipline (a declared medium, a named anti-reference, recurring elements defined once, and at most three ordered reads per visual with data labels kept), any sequence of rendered states can be reviewed as one contact sheet, and a pre-registered before-and-after evaluation records whether the discipline changes generated output, with no new third-party destination, credential, or dependency.

## Definition of Done

**Must have:**

1. `catalog/skills/developer-experience/hallmark-design/references/cross-format-patterns.md` carries a production-bible section (declared medium, named anti-reference, palette arc, a visual-system registry for recurring elements, a parallel-worker brief with a shared-file edit ban, a quiet zone behind large text, an opening hook, and scale variance) and a rule-ownership table naming one owner per illustration concern.

The `document-to-interactive-html` state table (`references/content-intent.md`) and storyboard (`references/dual-view-handbooks.md`) carry a `reads` field (at most three ordered reads, one focal idea) and a no-duplicate-text rule that exempts text by role (axis titles, tick labels, legends, units, data labels, diagram node names) and is paired with a required-labels check for data figures.

4. `catalog/skills/testing/functional-verification/scripts/contact_sheet.py` composes PNG captures into labeled sheets no larger than 1500 px on the longest edge, splits past a tile cap and reports the split, makes zero network requests, adds no Python dependency, and is named by `catalog/rules/html/visual-self-verification.md` as the preferred capture for a sequence of states.
5. `docs/releases/v4/v4.18/development/v4.18.0-illustration-eval.md` records the rule pre-registered in this plan, the fixtures, command lines, spend under USD 25, per-arm results, and a separate verdict of CHANGED, NO_CHANGE, or NOT_MEASURED for DoD 1 and for DoD 2. A NO_CHANGE item gets one revision round and a re-measure; an item still not CHANGED stays as low-cost guidance and is recorded as a known gap.

## Non-Goals

- The code-rendered video skill, the `/presentify` video export, and audio timing. They move to a follow-on plan (see `## Complexity Tracking`, parked branch P1). This plan's evaluation does not validate them.
- Any hosted image, video, music, or speech generation. Generation-as-service is a hard no under the `AGENTS.md` MCP Registry Policy.
- Shipping a vendor mascot, brand asset, meme image, or third-party font. A recurring character is optional; the default recurring element is a visual system (icon family, color order, chart styling) that suits formal decks and reports.
- Any always-loaded instruction-template edit. Every change lives in a Tier-2 skill body, a Tier-3 reference, or a rule file, which keeps this plan outside the `v4.16.0` standing-rule cap.
- Retrofitting existing handbooks, decks, or reports. The rules are forward-only.

## Overview

The seeding comparison found that the quality of the recent code-rendered videos came from production discipline, not tools. The best-documented example drew every frame in code with no generation model, after writing a storyboard with timed "reads" per shot and a style guide every parallel worker read. Nexus-Hub already has the machinery around that discipline (a design record, a storyboard, a four-viewport render loop, anti-slop gates) but not the discipline itself: no declared medium for figures, no rule limiting a visual to one focal idea, no single definition of a recurring element, and no way to review a sequence of states as one image.

Phases 2 and 3 are Markdown edits to existing references plus one-line handoffs in six producing skills, so the discipline reaches decks and reports alike. Phase 4 adds a contact-sheet composer to `functional-verification`, which already owns how an artifact is exercised and already ships a shared visual script. Phase 5 measures whether the rules change output, with the verdict rule fixed in this plan before any run, and a single revision round if an item shows no change.

The plan review split the original draft: the video renderer is a larger, separately valuable capability the user did not directly ask for, and bundling it would have delayed the cheap wins behind it. Its design and every reviewer finding about it are carried in parked branch P1 so the follow-on plan starts from them.

## Resolved decisions

Recorded from the 2026-09-28 plan review (seven lenses) and design interview:

1. Adoption target v4.18.0.
2. Split: this plan ships the static-illustration rules, the contact sheet, and the evaluation. The video skill, presentify video export, and audio timing move to a follow-on plan (parked branch P1).
3. Report skills are in scope: `docx-generation`, `pdf-document-generation`, and `deep-research-compilation` get the same handoff as the presentation skills.
4. Evaluation cap USD 25, covering generation and grading. Reaching the cap before every run completes yields NOT_MEASURED; the run is never extended.
5. Verdict rule, pre-registered here and copied unchanged into the admission file before any run. Fixtures: three source documents (two prose-only, one with tabular data that needs a chart). Task per run: produce the figure brief, storyboard, and figures for a five-slide deck from the fixture. Runs: 3 per fixture per arm (18 generations), plus 9 treatment re-runs if a revision round happens. Grading: one blind grader call per output with shuffled arm labels. DoD 1 passes a run when the output declares one medium and an anti-reference and every recurring element is reused consistently. DoD 2 passes a run when every visual lists at most three reads with one focal idea, no figure repeats body text, and the data fixture keeps its axis titles, legend, and units. An item is CHANGED when the treatment passes at least 3 more of 9 runs than the control and the data fixture passes in the treatment at least as often as in the control; otherwise NO_CHANGE.
6. On NO_CHANGE for an item: revise that item's rule once within the remaining cap and re-measure the treatment arm only; if still not CHANGED, keep it as low-cost guidance and record a known gap. The rules are never reverted on a negative verdict.
7. The contact sheet lives in `functional-verification/scripts/`. Callers reference it through its installed skill path and report the review as not covered when it is missing; no caller copies it.
8. For the follow-on video plan: its CI reconciliation installs `ffmpeg` in the existing `guide-render` job. Recorded in parked branch P1.
9. Evaluation isolation: each arm loads skills from its own git worktree (control at the baseline commit, treatment at the Phase 3 commit) with an empty home directory, and records the sha256 of every skill file it loaded; the run fails if the control's loaded text contains the production-bible heading.
