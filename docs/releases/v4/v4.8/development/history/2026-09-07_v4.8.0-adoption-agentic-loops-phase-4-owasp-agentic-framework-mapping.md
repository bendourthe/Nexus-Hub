## What the plan assumed and what the tree held

The plan's design held completely: a separate field, membership validation, a matrix column, and no Navigator contamination. Three things differed from what the plan wrote down, all of them the plan's own safeguards working.

First, **two official titles were wrong in the plan**. It transcribed ASI03 as "Identity and Privilege Abuse" and ASI06 as "Memory and Context Poisoning"; the official titles use ampersands. The plan required a re-fetch precisely so a transcription could not become the catalog's record, and that is what happened.

Second, **the URL the plan named does not contain the list**. The resource page describes the framework and links a downloadable document without enumerating the ten entries inline; the 2025-12-09 announcement does. Both are now recorded, because a reader verifying the mapping needs the one that actually enumerates.

Third, **three of the plan's fifteen tag hypotheses were rejected on evidence**, and three identifiers were added that the plan did not predict. Details under Tagging judgments.

**Three rejections, with reasons.**

- **`loop-engineering` ASI08 (Cascading Failures): REJECTED.** The failure-mode ownership table this same plan added in Phase 1 assigns cascading error to `agent-orchestration-primitives`, with `loop-engineering` bounding only fan-out cost. Tagging both would report one root cause twice in the coverage matrix, which is exactly what the ownership table exists to prevent. This rejection is recorded inside `loop-engineering`'s own `standards.md` so the next reader does not "fix" the apparent omission.
- **`ai-agent-governance` ASI09 (Human-Agent Trust Exploitation): REJECTED.** The body's four pillars cover guardrails, risk, security, and observability; a grep for human-oversight, approval-gate, and escalation language found only one rationalization row about least privilege. Nothing in the body teaches a human-trust control, and a tag with no supporting sentence is a mistranscription presented as coverage.
- **`agent-execution-isolation` ASI02: initially rejected, then CONFIRMED on a second reading.** A keyword grep for tool-scoping language returned nothing, which nearly produced a wrong rejection. Reading the body showed layer 2 step 2 ("Remove anything the current task does not call") and the governing principle that the execution system enforces any required approval before a call proceeds. The body uses "binary, interpreter, parser, helper" and "call" where the grep looked for "tool". Recorded because the lesson generalizes: on a judgment mapping, grepping is a way to locate candidate evidence, never a way to conclude its absence.

**Three additions the plan did not predict**, each tied to a numbered step: `ai-attack-patterns` ASI02 (tool and function-call abuse is a named attack surface in its overview), `agent-execution-isolation` ASI03 (step 6 keeps real credentials out of the agent environment entirely) and ASI07 (steps 3.6 to 3.8 record agents establishing inter-agent communication through a shared writable service after being denied it, with a four-rung remediation ladder).

## Plan delta

**Disposition: Incomplete (non-blocking, resolved inside the phase).**

Evidence, in four parts.

1. **Two official titles in the plan were wrong** (ASI03, ASI06: ampersands, not "and"). Corrected against the fetched source, exactly as the plan's re-fetch instruction required. The plan's `verified on 2026-09-04` date was also superseded by a fresh 2026-09-07 verification.
2. **The plan's single source URL does not enumerate the ten entries.** A second source (the 2025-12-09 announcement) was needed and both are now recorded.
3. **T021's named file was not created.** The plan named `tests/validators/test_validate_skills_framework_fields.py`; the ten membership cases were added to the existing `tests/validators/test_framework_field_shape.py` instead, which already owns the validator subprocess harness and the identical fixture helpers. A new file would have duplicated `write_skill` and `run` to hold tests of the same invariant on the same script, which the `AGENTS.md` test-retention policy explicitly argues against. The plan's second named file (`test_owasp_agentic_mapping.py`) WAS created, for the concerns that genuinely are OWASP-specific rather than shape-related.
4. **Three tag hypotheses were rejected and three identifiers added**, as the plan's own "treat these as hypotheses to confirm or reject, recording each rejection with the reason" instruction anticipated.

Consequence for remaining phases: Phase 5's terminal CI/CD reconciliation should note that this phase changed two repository validators that gate CI (`validate_skills.py`, `build_framework_coverage.py`), both already in `DEV_ONLY_SCRIPTS` and both already invoked by the `validate` job, so no pipeline edit is expected. Phase 5's known-gaps reconciliation must carry `WN-E` (the routing degradation) and the decision record's own recorded residual gap: nothing detects a tag whose supporting sentence is later deleted from the skill body, which is a weaker guarantee than the per-identifier standards check provides.
