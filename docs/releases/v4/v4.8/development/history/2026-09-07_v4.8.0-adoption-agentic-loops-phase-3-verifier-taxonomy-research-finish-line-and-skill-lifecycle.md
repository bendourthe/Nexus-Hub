## Outcome

Every deliverable can now name the verifier class that grades it, and two verifier gaps closed. `/research` and the compilation skill end on five computed metrics rather than the producer's confidence, explicitly advisory in this release and explicitly for a stated reason. A capability eval case now graduates into the regression set by a rule with a default, and is retired rather than rewritten when it stops reflecting intent. The stocktake can propose a skill whose behavior a model refresh has made redundant, and structurally cannot delete one.

## What the plan assumed and what the tree held

The plan's premise held for all four clusters, and one of its choices proved load-bearing in a way worth recording: it required the completion-evidence block to be advisory WITH its reason stated. Writing the reason down ("no measured baseline exists yet, so a threshold would either pass everything or fail honest work") is what makes the advisory stance a decision a later release can revisit rather than an omission someone later "fixes" by adding a threshold nobody calibrated.

One thing the plan did not anticipate surfaced during the gate-5 exercise and is recorded under the Plan delta below.

## Plan delta

**Disposition: Incomplete (non-blocking, resolved inside the phase).**

Evidence: the plan enumerated three failure modes for the completion-evidence block (an uncited claim, an unresolvable URL, and a scope conflict) and all three were implemented. A fourth surfaced only by running the block against a real deliverable: when the corpus is entirely LOCAL, URL resolution is `0 of 0`, and a bare zero sitting beside four healthy metrics reads as a broken run rather than as "this research had no web sources". This is not a hypothetical shape for this repository -- the deliverable used in the exercise is a comparison report seeded from two local documents, and a compile run merging user-supplied files meets the case as its PRIMARY shape. Both surfaces now report `0 of 0` with the reason "local corpus, no web sources" and state that coverage and freshness still apply against the local documents; `test_local_corpus_reports_zero_urls_with_a_reason` pins it on both.

A second, smaller observation is recorded rather than changed: citation coverage cannot be computed by a regex, because enumerating the factual claims that form its denominator is a model-based step. This is consistent with how the block and the taxonomy already class it (deterministic for sections, duplicates, and resolution; evidence-based for coverage and freshness), so nothing was edited. It is worth stating because a future attempt to automate the block into a script would hit exactly this boundary, and the honest split is that four of the five metrics are scriptable and the fifth is not.

Consequence for remaining phases: none for Phase 4, which touches a disjoint set of files (the skill validator, the coverage builder, the framework-mapping skill, and the agent-security skills). One consequence for Phase 5: the advisory stance recorded here is the kind of deliberate scaffolding the release-notes capability gate asks to be documented, so v4.8.0's notes should name the completion-evidence block as an advisory surface, state that it never blocks, and name the measured baseline as the condition for revisiting it.

### Functional exercise A - completion-evidence metrics against a real deliverable

- **Revision**: `feat/v4.8.0-agentic-loops`, working tree after T011 to T017.
- **Artifact and boundary**: the completion-evidence block as a computation over a finished research deliverable. The real boundary is that computation, so it was run against a real 240-line comparison report in this repository rather than against a synthetic sample.
- **Command or action**: compute the four scriptable metrics (duplicate sources, URL resolution, required sections present, source freshness) from `docs/releases/v4/v4.8/comparisons/v4.8.0-comparison-agentic-loops-and-coding-agent-practice.md`, with no new fetch, per the block's own constraint.
- **Expected contract**: each metric computable from the deliverable alone; each reported value interpretable without guesswork.
- **Observed**: cited URLs 0, distinct 0, duplicate sources 0; top-level sections 10, enumerated; source freshness oldest 2026-09-01, newest 2026-09-04; 27 candidate claim-bearing bullets.
- **Comparison**: MISMATCH on interpretability. Three metrics were computable and self-explanatory, but URL resolution returned a bare `0`, which does not distinguish "no web sources were used" from "every URL failed to resolve". The finding is in the block's specification, not in the arithmetic.
- **Fix and rerun**: both surfaces now report `0 of 0` with the reason "local corpus, no web sources". Re-run of the phase suite produced `51 passed` including the new regression test; the unicode gate re-ran clean.
- **Comparison, final**: matches.
- **Environment**: Windows 11, CPython 3.12, Git Bash.
- **NOT COVERED**: a live `/research` run on a fixed public topic. It would exercise the agent's own research behavior and outbound fetching rather than this phase's deliverable, and the question it answers (is the block useful or noise) requires a researcher's judgement. The plan already routes exactly that to a Phase 5 human test ("a researcher runs `/research` on a topic of their own and judges whether the advisory completion-evidence block is useful or noise"), so this is deferred to a named owner rather than dropped.
