## 2. Chronological Steps

### 2.1 Author the proportional functional-verification procedure

**Plan specification**: Create a pushy, conformant skill that owns how to exercise built artifacts while leaving evidence freshness, gate policy, accessibility, visual judgment, browser diagnosis, E2E architecture, adversarial rules, code-vs-plan convergence, and gap lifecycle with their existing owners.

**What happened**: Added `catalog/skills/testing/functional-verification/SKILL.md` with concrete real-boundary procedures for CLI, public library or API, web UI, hook or script, document or artifact generator, configuration, and narrow documentation-only changes. Every procedure distinguishes evidence that counts from common false substitutes. The output record requires the exact revision, representative input, action, exit code or measurement, observed result, environment, evidence paths, delegates, and uncovered scope.

**Routing contract**: The description retains all five required trigger phrases and natural-language forms of the three skip intents on one unquoted ASCII line. The first draft exceeded Nexus-Hub's local 250-character hard limit even though agentskills.io permits 1,024 characters. The final description is 236 characters and passes both validators without leaking YAML quote bytes into the registry.

**Independent review finding and correction**: The first record schema captured execution and observed output but did not require the expected contract or an explicit comparison, so a zero exit with wrong output could still satisfy the checklist. The final schema records expected and observed values, classifies `matches`, `mismatch`, or `cannot-run`, and keeps the latter two as findings for gate disposition.

**Ownership result**: The skill delegates freshness and completion claims to `verification-before-completion`, disposition to `quality-gate-definitions`, visual and accessibility judgments to their owners, durable browser suite design to `e2e-testing-automation`, hostile testing to `adversarial-verifier`, code-vs-plan comparison to `implementation-convergence`, and residual-gap lifecycle to `known-gaps-tracker`. A missing delegate produces an explicit `NOT COVERED` record rather than reconstructed rules.

### 2.2 Add the bounded whole-plan deep pass

**Plan specification**: Define an objective blast-radius verdict, exercise every feature from every phase, invoke rendered-surface and adversarial owners, audit Goal-vs-plan sufficiency, and stop after a finite rerun budget.

**What happened**: Added `references/deep-pass.md` as a ten-step Tier 3 runbook. Ambiguous blast radius selects `run`; a no-op requires exact diff evidence. The inventory combines the full plan and final diff, then exercises every independently observable feature. Browser HTML receives browser, accessibility, geometry, and visual delegates; non-HTML documents use their intended consumer and record browser-only instruments as not applicable. The adversarial pass and `implementation-convergence` run before a distinct four-question Goal-vs-plan audit.

**Independent review findings and corrections**: The first draft applied the HTML-only geometry detector to every generated document or presentation and allowed a missing hard input to remain merely incomplete. The final runbook limits the detector to local HTML, requires intended renderers for PDF, DOCX, PPTX, and other non-HTML artifacts, and turns every missing hard input into a named `NOT COVERED` item owned through `known-gaps-tracker` and `quality-gate-definitions` under a fail-closed result.

**Iteration contract**: The deep pass has one global maximum of three fix-and-rerun cycles across all features and delegates. At exhaustion, remaining findings go to `known-gaps-tracker` and `quality-gate-definitions`; the counter cannot reset per finding.
