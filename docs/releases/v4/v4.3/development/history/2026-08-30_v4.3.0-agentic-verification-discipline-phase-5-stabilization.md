### 2.3 Regression triage

A throwaway detached worktree at `HEAD` ran the same three affected test files and passed 29 of 29, establishing that all six failures were regressions introduced by the uncommitted platform work rather than inherited flakiness. The worktree was then removed.

Three distinct root causes were isolated:

**RC1 - the Copilot opt-in gate no longer guarded anything.** Agent and native-hook installation had been inserted into `wire_project_surfaces` ABOVE the `_copilot_skills_enabled` check, so 82 files were written into `.github/agents/` and `.github/hooks/` with the opt-in absent. `.github/` is commit-visible, which is precisely why that surface is documented as off by default; the defect would have placed 82 uninvited files into every consuming repository.

**RC2 - a silent write failure in the ownership helper.** `_link_like_managed_ancestor` compared only `os.path.abspath` spellings, which normalizes neither Windows 8.3 short names nor POSIX symlinked parents. Every write under such a root returned `kept` with nothing on disk and no error raised. Demonstrated directly on this host, where `TEMP` is the short-name form.

**RC3 - an intentional change applied to one adapter and not the other.** A vendor-verified move of `AGENTS.md` to the workspace root was applied completely to OpenCode (config, code, and read contract) but only to Antigravity 2.0's code, leaving its config declaring `.agents` while the code wrote to the root. The same contract update also invalidated a test that hardcoded `.opencode/AGENTS.md` instead of reading the config its sibling test reads.

### 2.4 Fixes, test-first

RC2 was fixed with a failing-first regression test that constructs an alternate spelling of the target root (Windows short name, or a POSIX symlinked parent, skipping where neither is available); it failed with `expected a real write, got 'kept'` before the fix. The repair adds `_relative_within`, which falls back to a canonical comparison only for containment. The ancestor walk deliberately continues to use the ORIGINAL spelling, because `realpath` resolves exactly the symlinked entries the guard exists to detect.

RC1 was fixed by moving the agents and hooks install below the opt-in early return. One assertion in the bundle-selector test was scoped to the skills tree rather than every created file, which preserves what it checks (the correct bundle was seeded) without weakening it.

A third defect surfaced while fixing RC2: the guard refused EVERY destination outside `target_root`, silently disabling global-scope writes to `~/.copilot`, `~/.claude`, and the VS Code user directory. On the maintainer's decision the guard now treats an out-of-root destination as having no managed ancestor to police, and leaf-level protection is retained. Two regression tests cover it: the out-of-root write lands, and a hard-linked destination is still never written through.

RC3 was fixed by declaring `instruction_workspace_dir` on the Antigravity 2.0 config so the config remains the single source of truth for placement, and by deriving the OpenCode teardown path from that config.
