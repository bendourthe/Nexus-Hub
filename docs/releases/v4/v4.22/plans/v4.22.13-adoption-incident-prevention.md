## Overview

The maintainer reviewing repeated coding mistakes needs a reproducible path from evidence to prevention. Extend continuous-learning and review-trapdoors instead of adding an observer, collector, service, command, or skill. The report names its population and gaps, counts independent incidents, proposes diffs, and stops before applying them.

This teaching release is demonstrated on synthetic local exports and isolated current-revision check fixtures. It does not perform a real 60-day audit, claim measured reduction in mistakes, execute historical patches, mutate persistent memory, change production types, edit standing instructions, or delete rules. Existing native enforcement and completion evidence gaps stay open.

construction-debt: One new distributed reference, two existing skill-body changes, one focused test module, one fixture subtree, exact coordinator metadata text deltas, and release-scoped evidence. Keep verified-improvement-loop.md unchanged. No runtime parser, repository connector, scheduler, custom judge client, generic citation engine, or additional CI job.

## Goals First

**Problem**: Repeated failures can lead to additional prose without proof that a future agent or gate will catch the original defect.
**Persona**: A repository maintainer reviewing repeated coding-agent mistakes; authorship can remain unknown.
**Outcome**: An agent follows the installed reference to produce a sourced recurrence table, proposed diffs, per-incident check verdicts, and an advisory instruction-to-check mapping.
**Definition of Done**: Every applicable frozen synthetic case has the independently expected recurrence and evidence-coverage result; duplicate comments do not inflate counts; overbroad checks fail valid controls; inactive or undiscovered checks cannot justify retirement; a missed incident prevents full-coverage claims; incomplete history is visible; source instructions do not change authority; the reference is discoverable and distributed by existing installers; terminal required evidence is complete.
**Measure**: Exact case-level expected/observed agreement and unauthorized-mutation count, including denominators and unknown cases. Required cases must all agree and unauthorized mutations must be zero. A miss reopens its owning task; no general effectiveness percentage is inferred.

## Scope and Authority

Use already-local PR metadata, review threads, CI summaries, revert/fix links and safe Git rule-change history as data. Default to 60 calendar days and a 14-day follow-up correlation window, both configurable and recorded. The audit interval is [start,end) in a named timezone. Follow-up evidence extends only through the collection cutoff; an incident without a full follow-up window is immature, not evidence of no later fix.

Use all PRs in the supplied population by default: this repository prohibits AI attribution, and absence of attribution does not prove human authorship. Two independently confirmed incidents establish a repeated-mistake group. Related comments, retries, reverts and fix PRs on one defect count once. Same-file follow-ups are candidate relationships, not proof of causality. Confirmed, candidate-related, disputed and unknown remain distinct. Ambiguous labels never become instincts without the outcome-labeling owner's decision.

An audit can write only a new scoped report containing proposal diffs and evidence references. It cannot apply those diffs, mint instincts, edit root instructions, run historical commands, fetch private systems, introduce a model client, or change tests.evidence. Existing owners govern trust, redaction, test proof, approved application and authorization. Implementation admission, publication, merge and release follow implement-phase completion-contract Authorization policy and Approval origin within exact scope. Silence is not approval.
