## Goals First and Definition of Done

The primary user is a maintainer who delegates engineering work to installed agents and must understand their explanations and assess their evidence. Existing owners cover much of the source material, but lack concrete grammar checks, a qualified supporting-copy decision, a task-level consolidation comparison, a safe daily log recipe and a mobile-specific verification path. The deliverable is original guidance delivered through existing installers, plus reviewed examples showing how to apply it. It is not a new agent service, an app, a scheduler or a claim of measured behavioral improvement.

1. Communication guidance reviews dense wording without treating a short answer as inherently clear. Worked rewrites preserve facts, quantities, paths, conditions, uncertainty and the next action. An independent evaluator must recover the action, reason, blocker and uncertainty against expected answers frozen before the rewrite; absent information is reported as not supplied. The normal chat structure and optional controlled-language register retain their current owners.
2. UI-copy guidance distinguishes repetition from format help, error recovery, permission reasons, consequences and accessible names. It hands layout repairs and accessibility judgments to their existing owners.
3. A consolidation worksheet compares task-level outcomes and identifies regressions hidden by equal aggregate scores. It preserves independent verification, permission boundaries and valid parallel work. Unknown costs and timings stay unknown.
4. A daily log recipe reads only declared, approved inputs, establishes the inference-processing boundary before sensitive content is ingested, and produces proposals with evidence and uncertainty. It preserves the existing ban on new analytics/API calls and credentials. It does not schedule, write fixes, send messages, deploy or merge.
5. A mobile verification reference covers navigation state, keyboard, themes, large text, interrupted interactions and full-flow motion evidence. Reviewed examples distinguish a proposed check from one actually run, screenshots from recordings, and recordings from measured performance/accessibility proof. No iOS, Android or real-device test is claimed without the relevant execution evidence.
6. The complete revised skill/reference set is delivered into isolated install targets and read back. Reviewed worksheets and delivery checks prove procedure consistency and installation, not agent adherence, statistical improvement, human comprehension, or live containment. Any such stronger claim requires separately scoped observations.
7. Each phase verifies locally and ends with one local commit. The final phase owns complete-plan validation, independent Goal review and the one authorized integration publication; release follows green merged integration through its own flow.

## Evidence Contract

Phase 1 freezes inputs, expected decisions and factual invariants before candidate guidance is written. Use plain JSON/Markdown/CSV examples and independently computed arithmetic where relevant. Never place the answer key in an agent-facing task. Reviewers receive the source input, candidate output and frozen acceptance criteria, and record the exact revision, role, decision and reason. Any reviewer who authored a candidate cannot supply its independent acceptance. A missing or inconclusive review remains unresolved.

The examples are load-bearing procedure demonstrations, not disposable application mocks. Test only facts a deterministic check can establish, including fixture arithmetic, evidence-source references, malformed evidence rejection and actual installed-file resolution. Do not write tests that merely assert prose keywords, that grade their own generated answer key, or that simulate an agent and claim its behavior was measured. A deliberately defective example must be rejected by each meaningful checker.

| Group | Frozen cases | Required distinction |
|---|---|---|
| W01-W05 | Dense clause, noun cluster, overcompressed instruction, valid long technical term, exact quote/identifier | Freeze expected action/reason/blocker/uncertainty readback before rewriting; independently recover it and preserve all factual invariants; absent facts remain not supplied |
| U01-U06 | Repeated tagline, required format, error recovery, permission reason, consequence/accessibility name, unclear grouping | Delete repetition while retaining necessary copy; repair layout through its owner |
| C01-C03 | Equal mean with different task outcomes; self-verifier substitution; permission-isolated task | Show a task regression even when kept `[1,1,0,0]` and folded `[1,0,1,0]` both average 0.5; preserve verification and actual permissions |
| L01-L07 | Known error, missing/rotated input, empty window, malformed timestamp, instruction-shaped log data, failed run, overlapping windows | Distinguish observed event from cause/impact; retain coverage gaps, time zone, source boundaries and unsuccessful-run status |
| M01-M04 | Screenshot-only motion claim, unavailable platform, missing navigation state, recording without performance/a11y measurement | Accept evidence only for its demonstrated dimensions; missing proof stays unverified |

Include a synthetic sensitive-data marker in one L case and test the processing decision before raw content would enter the configured agent. If the boundary is unknown, do not ingest it: request a pre-redacted export under the approved boundary or require approved local processing. Do not install a redactor, claim an automatic sandbox, or infer authorization from an existing provider connection.
