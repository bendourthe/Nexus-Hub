## Overview

The target user is a maintainer who uses Nexus-Hub agents for security work and for building MCP servers. The comparison found that the security skills stop at "patch" with nothing for the window before a patch exists, that pentest findings have no validation gate before reporting, and that `mcp-builder` predates MCP tasks, elicitation, and server-shipped skills. This plan closes those gaps (comparison items A3, A4, A5, A7) through skills that already own each concern. It adds no skill, command, hook, MCP server, or runner.

These four items depend on no queued plan, so this plan can be implemented and published ahead of its companion. On 2026-11-25 the user chose to split the comparison into two plans for that reason (Review and Decision Record).

construction-debt: Two new distributed reference files (`vulnerability-prioritization-with-ssvc/references/interim-mitigation.md`, `mcp-builder/references/protocol-capabilities.md`), short edits to four existing SKILL.md files, one decision record, one focused contract module with one fixture manifest, coordinator metadata deltas, and release-scoped evidence. ## Goals First

**Problem**: Security guidance ends at "patch", so an agent facing an unpatched, actively exploited vulnerability has no procedure for a temporary control and may either do nothing or deploy something unsafe. Pentest findings can reach a report without a check that they are in scope, authorized, and reproduced. `mcp-builder` does not teach the MCP capabilities released in 2026.
**Persona**: Maintainer running coding agents with the Nexus-Hub catalog installed, doing authorized security work or building MCP servers.
**Outcome**: An agent following the installed guidance proposes (never deploys) a narrow, tested, expiring interim control and keeps the vulnerability open; refuses to report or re-test a finding that fails scope, authorization, or reproduction; and finds current, cited MCP capability guidance in `mcp-builder`.
**Definition of Done**: The A4 and A5 frozen cases produce the expected decision in 3 of 3 recorded fresh-session runs on the candidate catalog, within the USD 15 cap; every MCP capability statement cites the primary specification version and retrieval date; the A7 decision record exists with Alternatives considered; both installers deliver the changed files through their existing recursive copy; required final gates pass.

**Grounding**: No root STRATEGY.md, `docs/solutions/` store, or release constitution was found. README.md, AGENTS.md, the seeding comparison, and the named owner skills ground the plan.
