## Recommendation

Correct the performance skills first. The shipped review skill recommends "add caching layer" as the remedy for repeated work, which is the reflex Source 2 warns about, and no performance owner audits whether an existing cache is masking a slow design. Then add case-matched hotspot triage with a report-first contract, and one design-system authoring reference that turns a team's decisions into an agent-readable system. A data-oriented-design reference is useful but cuttable.

All five candidates are skill-native edits to existing owners. No candidate adds a dependency, MCP server, outbound call, or new skill. Faster agent-produced fixes and more on-brand agent UI remain hypotheses; this comparison ran no paired agent evaluation and did not profile any project.

Claim qualification:

- **"Caching is cope for a slow design."** Overstated as a universal rule. Caches are legitimate for remote I/O latency, bounded expensive pure functions, and rate-limited dependencies. The defensible core, adopted here, is narrower: examine whether the slow path can be redesigned before adding a cache, and audit existing caches for ones that hide a slow design.
- **Hash tables to flat arrays, pointers to indices, hot data packed into index bits.** The speedup depends on runtime. Contiguous arrays and integer handles gain most in C, C++, Rust, Go, and Java through cache locality; in CPython the gain is usually small unless the data moves into typed arrays or NumPy. Packing data into index bits trades readability and correctness margin for speed and belongs only in a measured hot loop.
- **"Find the 5 slowest spots."** Five is an arbitrary default. A cumulative-share cut (the spots that account for most self time) is the general form; five stays a reasonable default.
- **"Expected speedup."** Any figure written before the change is an estimate and must be labeled as one, then confirmed with a before/after profile.

## Exclusions and Risks

Not recommended:

- **An absolute "never add a cache" rule.** Rejected as stated; A1 adopts the qualified form. A ban would push agents to rewrite remote-I/O paths that a cache serves correctly.
- **Bit-packing as a default triage case.** Kept only inside A3, behind a measured-hot-loop condition and a correctness test.
- **Installing a third-party design-system skill.** drop-outright under the MCP Registry Policy reasoning above; the capability is skill-native.
- **A design-system MCP server.** Not proposed; no consuming call site.
- **Token semantic-versioning governance.** Out of scope; the consuming project's release policy owns it.
- **Running S2's prompt against Nexus-Hub.** Not done. Nexus-Hub's runtime surface is mostly installers and validators; a profile of the CI gate could be a separate, explicitly requested exercise.

Risks:

- A1 edits wording that existing tests may assert. Grep `tests/` for the replaced strings before editing.
- D1 adds an ownership row to a validated table; `test_ui_cluster_contract.py` must pass.
- D1's description change consumes Tier-1 tokens in every session; keep the added trigger phrases short.
- S1 was analyzed from its summary. If the maintainer supplies the full article before planning, rerun its capability table.
