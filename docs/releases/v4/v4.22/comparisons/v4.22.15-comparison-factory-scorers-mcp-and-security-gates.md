# Factory Scorers, MCP Capabilities, and Security Gates Comparison

**Date:** 2026-11-25
**Adoption target:** v4.22.15
**Status:** Target accepted by the maintainer on 2026-11-25 by running `/plan from-comparison`. During planning the maintainer split the adoption into two plans and cut A6: [v4.22.15](../plans/v4.22.15-adoption-security-gates-and-mcp-capabilities.md) carries A3, A4, A5, and A7 with no prerequisites; [v4.22.16](../plans/v4.22.16-adoption-redraft-rule-and-transcript-scorers.md) carries A1 and A2 after v4.21.0 and v4.22.13 merge; A6 is recorded as a known gap. No implementation or release performed.
**Scope:** Seven user-supplied sources compared with the Nexus-Hub catalog: software factory engineering, live exploit-path shields, new MCP capabilities, engineering writing, a Gemini Neon user verdict, a fast React app prompt, and a security-research skill bundle.
**Baseline:** Fresh `origin/develop` at `3397295f8` (fetched 2026-11-25), latest tag `v4.15.5`. The main checkout was not used as evidence because it is on an unrelated feature branch.

## Recommendation

Adopt six small items, five of them instruction-only, through existing owner skills. The highest-value item is a sampled transcript scorer: an LLM judge that grades the user's own past agent sessions against a rubric and feeds repeated failures into the verified improvement loop that v4.21.0 is building. The second is a "redraft, do not append" rule for skill edits. The other four refresh `mcp-builder` for the current MCP capabilities, add an interim-mitigation step for unpatched vulnerabilities, add a finding-validation gate before pentest reports, and add absolute byte budgets to the frontend performance guidance.

Do not adopt a cloud factory, a Shirudo integration, any bug-bounty vendor MCP, or the security bundle's skills. Source 5 adds no new item: the queued v4.22.14 plan already covers it.

## Adoption Sequence

1. **A1 Redraft rule (P0).** Owner: `[[continuous-learning]]` promotion step and `[[skill-create]]`. Add one rule: a fix rewrites the affected section as a whole and deletes guidance it supersedes; an appended "also note" paragraph is a defect. Place after v4.21.0 merges, because v4.21.0 edits `continuous-learning`; do not edit v4.21.0's plan text.
2. **A3 MCP refresh (P1).** Owner: `[[mcp-builder]]` references. Fetch the primary specification, then document tasks (status, failure, retry), elicitation (ask before spend or deletion, linked to `## Consequential Decisions`), server-shipped skills, and a tool-search note for multi-server setups. Record file uploads as deferred.
3. **A4 Interim mitigation (P1).** Owner: `[[vulnerability-prioritization-with-ssvc]]` decides when an interim control is needed (an Act outcome with no patch); `[[security-patch-advisor]]` keeps the patch. Steps: pick the narrowest control, test it against the exploit, monitor before enforcing, record an expiry and the removal path, remove it when the patch ships.
4. **A5 Validation gate (P1).** Owner: `[[pentest-reporting]]`. Before writing a finding: target in the authorized scope, impact class accepted by the engagement, reproduced with evidence, not a known non-qualifying class, not a duplicate, impact shown only as far as the rules of engagement allow.
5. **A2 Transcript scorers (P1).** Owner: `[[ai-output-evaluation]]` defines the scorer format (rubric, labels with 0 to 1 scores, pass threshold, sample rate, judge tier) in a reference file; `[[session-query]]` selects transcripts; failures enter the v4.21.0 loop as candidate evidence with run identifiers. Start instruction-only; add a stdlib sampler script only when a real run shows the instructions are not enough. Depends on v4.21.0 and on v4.16.2 Phase 5.2.
6. **A6 Frontend budgets (P2).** Owners: `[[performance-regression-gate]]` (absolute budget mode next to the baseline mode), `[[react-expert]]` (intent preloading), `[[dependency-manager]]` (switch-gated trials with ship and fallback criteria). Sequence after v4.22.11, which edits `frontend-ui-engineering` and `performance-regression-gate`.
7. **A7 MCP skills surface (P3).** Decision record first; build only after the extension is stable and at least one client in the platform roster documents support.

## Risks and Conflicts

- **A1** changes how every future skill fix is written. It agrees with the user's "targeted edit" preference because it applies to the affected section, not the whole file.
- **A2** is the only item with ongoing cost: judge calls spend usage. It also handles transcripts, which can contain secrets; redaction before judging is mandatory, and transcripts never go to a new destination.
- **A3** depends on an unverified secondary source. If the primary specification differs, the primary wins and the item shrinks.
- **A4** must not read as advice to delay patches; the skill text states that an interim control expires.
- **A6** touches two files that v4.22.11 also edits, so it must follow that plan.
- **A7** adds a protocol surface while the feature is in public beta for some Claude plans only.
