## Source Findings

S1 documents `gemini-4-neon` between Hydrogen and Carbon, with Carbon reserved for the hardest problems. Neon supports `low`, `medium`, default `high`, and `xhigh`. Its 1,048,576-token window is shared by input, thinking, and output; synchronous output is limited to 65,536 tokens per hop. Longer generation uses background execution or continuation. These are vendor specifications, not measured Nexus-Hub performance. Claims of fewer steps or better reliability require local evaluation before adoption as guarantees. [S1](https://aistudio.google.com/docs/whats-new-gemini-4-neon)

S3 confirms context-forked side questions while the main conversation continues. The fork inherits settings and workspace permissions; read-only behavior is an instruction, not a separate sandbox. App tabs support follow-ups and promotion to a separate conversation. CLI cards support one turn, one active side question, and deny calls requiring approval. Headless and remote agent sessions are excluded. `/copy btw` copies Markdown to the clipboard; it does not merge an answer into the main conversation. The supplied announcement's universal parallel-thread and promote-back wording needs those qualifications. [S3](https://antigravity.google/docs/commands/btw/)
