# Comparison - REA Workflows and Verified Agent Output

**Project:** Nexus-Hub
**Date:** 2026-10-19
**Baseline:** `develop`, `1224a4ddef6abbc7eec534e506edfe3736aabf75`
Adoption target: v4.22.3
**Placement status:** User-confirmed on 2026-10-19. The REA refinements amend the queued [v4.22.2 plan](../plans/v4.22.2-adoption-dashboards-motion-evidence-ledger-and-reliable-automations.md) in place; the verification items open v4.22.3 directly after it. The Claude Code mods plan moved from v4.22.3 to v4.22.4 to make room, at the maintainer's direction.
**Scope:** Two-source follow-up comparison and prioritized adoption recommendations. Catalog, templates, hooks, runtime behavior and release status are unchanged by this report.

This report adds to the [v4.22.2 comparison](v4.22.2-comparison-dashboards-motion-evidence-ledger-and-reliable-automations.md), which already inspected REA's repository at commit `cfce91d4` and turned its evidence method into the v4.22.2 plan. The new REA material is secondary (a promotional write-up with three example workflows). It confirms that plan rather than changing its direction, and it adds five concrete limits for the `/compare` built-artifact route: check official routes first, refuse a fixed list of prohibited actions, accept only three authorization bases, record the source license with a reuse mode per adopted item, and name missing analysis tools without installing them. These are applied to the v4.22.2 plan as amendments.

The Meta article contributes four items no shipped surface or queued plan owns. The most valuable is a change-set check that flags a red-to-green change that weakened its own tests. The others are a pull request body that carries a test plan and links to the verification evidence, an opt-in hook that blocks publication without a fresh passing local check for the current commit, and memory metrics in the performance regression gate. Most of Meta's other practices already exist in Nexus-Hub.

## Amendments Applied to v4.22.2

| Task | Change |
|---|---|
| T010 | The ledger header records each source's license (SPDX identifier, or `unknown`), and each adoption item records a reuse mode. |
| T011 | An adoption item reuses source text or code only under `copy` with a compatible license confirmed through `licensing-compliance`; otherwise it is re-authored, and an `unknown` license forces `re-author`. |
| T012 | The citation checker reports a `copy` item whose source license is `unknown` or not recorded as compatible as `unlicensed-copy` and exits 1. |
| T025 | Authorization accepts only `owned`, `open source (license named)` or `terms permit (clause cited)`; "cannot say" stops before ingestion. The route checks, in order, published source, a documented API or integration, and published documentation, and analyzes the bundle only when none answers the question, recording each rung checked. Prohibited actions: using any account or credential that is not the user's own, bypassing authentication, encryption, DRM or license checks, and contacting the vendor's live services. Each deferred route names the analysis tool class it would need and the rule: name the tool and its official download page, never install it. |
| T026 | Two more hostile fixtures: an authorization answered "cannot say", and a target whose published source answers the question, so the bundle route must not run. |
