## Recommendation

Prioritize a local data-analysis validation procedure and a product-review preset composed from existing skills. Preserve Nexus-Hub's platform portability, selective installation, and reverse-engineer-first policy. A bounded local web-fetch extension is a real but substantially larger opportunity and should have a separate implementation scope. DeepInfer does not belong in this catalog's runtime, and the Supabase anecdote supplies no evidence that twelve agents improve engineering outcomes.

The useful gap is procedure coverage rather than catalog size. The recommendations below adapt patterns into existing owners; they do not import an upstream catalog or add a new hosted service.

## Prioritized Adoption Outline

1. **A1: Local analysis QA.** Resolve the numerical-QA owner before authoring. Start with local CSV/JSON and known-answer fixtures: a clean analysis, a many-to-many join multiplying totals, a changing denominator, an incomplete month, a zero denominator, and mixed time zones. The observed report must identify the seeded defects, reproduce the correct quantities, and state unavailable checks. Company-specific definitions stay with the consuming organization or project rather than upstream catalog content.

2. **A2: Product-review preset.** Reuse existing skills to turn supplied local metrics into a brief with findings, limits, and actions. Missing input remains missing; the preset must not invent a query result, create an external connector, or publish a message. Show a real invocation on a fixed local dataset and compare its result with the expected answer. Recheck installer reachability before adding any bundle.

3. **A3: Separate retrieval evaluation.** Compare existing single-URL fetching plus available browser fallback with a small set of static, redirected, duplicate, JavaScript-dependent, partial-failure, and private-address cases. Implement only the smallest retrieval slice that fixes an observed deficiency. Any crawl needs page/depth/byte/time/concurrency limits, same-origin rules, cancellation, robots handling, deduplication, per-URL outcomes, and explicit partial completion. Browser rendering and PDF/DOCX parsing need separate decisions and are outside this outline's implementation cut.

Use existing evaluation owners for quality and cost. Do not claim a speed or cost improvement before measuring correct completed outcomes. A1 precedes A2 semantically. A3 has independent source files but still needs its own approved scope; shared catalog, tracker, release and publication changes remain serialized. This outline is not a phased implementation plan or a concurrency admission decision.

## Rejected Candidates and Limits

- **More agents from the anecdote**: inspected the existing orchestration selection guidance and available anecdote evidence. A fixed twelve-agent default lacks a measured failure that requires it.
- **Another role installer or marketplace**: inspected `data/bundles.json`, `agent-presets`, and upstream marketplace metadata. Existing composition and installation mechanisms are sufficient for A2.
- **A new cost or benchmark framework**: inspected existing owners and the v4.21.2/v4.22.3 task surfaces. The queue already addresses stronger evaluation and resource evidence.
- **A full finance/legal/sales catalog**: sampled role files demonstrate domain procedures, but this request does not establish those users or a concrete local acceptance case. Keep them outside the recommended scope.
- **Browser rendering inside a basic crawler**: the existing SSRF boundary is not automatically inherited by browser subresource requests. Defer it instead of hiding the extra security scope inside A3.
- **Copied source with renamed attribution**: no source code is proposed for copying. Generic pattern adaptation does not authorize removing required notices from copied code.

Security conclusions cover fetched samples only. No external applications were installed or run. Retrieval quality, model performance, savings, user adoption, and the behavior of every marketplace entry remain unmeasured.
