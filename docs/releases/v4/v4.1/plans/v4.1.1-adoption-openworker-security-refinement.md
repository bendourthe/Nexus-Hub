## Goals First

**Target problem**: Nexus-Hub has broad supported security capabilities and a strong closure gate, but its current `security-audit` workflow is an unordered skill list. Component coverage does not prove that every applicable deterministic scanner ran, and the workflow does not require the original detector to re-scan a fix or require a verifier other than the fixer.

**Primary persona**: A developer or security engineer invoking Nexus-Hub's security-audit workflow against a local repository.

**Secondary persona**: A Nexus-Hub maintainer evolving security skills without adding third-party services or weakening local-first boundaries.

**Observable definition of done**:

- Existing schema-v1 closure records remain valid, while schema-v2 records add fail-closed scanner receipts.
- Every applicable scanner has a receipt with one of `RAN`, `NOT_APPLICABLE`, `UNAVAILABLE`, `FAILED`, or `DECLINED`; no applicable scanner disappears silently.
- A corrected scanner finding links equivalent before and after detector receipts and records the finding delta.
- The patch-producing context cannot be the only post-fix verifier.
- `agent-presets` contains an ordered `security-audit` preset aligned with `data/workflows.json` and the existing security skills.
- Semgrep, gitleaks, OSV-Scanner, ecosystem audit tools, Trivy, and Checkov are optional local recipes owned by existing skills; none is auto-installed or replaced by a hosted service.
- Cloud posture stays read-only and never applies infrastructure changes.

## Non-Goals

- Integrate OpenWorker, its desktop runtime, connectors, memory, scheduling, or approval engine.
- Add an MCP server or hosted vulnerability-scanning provider.
- Add OpenRouter, Ox Alpha, or any generation-as-a-service route.
- Auto-install scanners or mutate a user's package-manager state.
- Apply IaC or cloud remediations.
- Import upstream prompts, security corpora, or product-specific coworker names into distributed Nexus-Hub artifacts.
- Rewrite unrelated security skills or expand this release into a catalog-wide security architecture refactor.

## Overview

This plan implements SR1 through SR4 from the seeding comparison. It extends the existing `security-review` closure gate instead of creating a parallel tool, adds scanner recipes to current rule owners, and turns the existing security-audit manifest into an ordered preset with role-separated verification. The implementation remains local and skill-native.

The source repository is evidence, not a dependency. Attribution stays in the comparison and plan. Distributed skill, agent, workflow, test, and reference artifacts use generic terms such as scanner receipt, remediation handoff, and independent verifier.

Each non-final phase ends with local verification and one local commit. No non-final phase pushes or starts remote CI. The final phase performs terminal pipeline reconciliation, publishes the completed branch once with approval, validates the merge result, and hands a green integration to the governed release workflow.
