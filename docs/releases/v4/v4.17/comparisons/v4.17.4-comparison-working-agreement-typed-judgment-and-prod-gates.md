This comparison reads three independent sources against Nexus-Hub and asks one question of each: what does it know about constraining an agent that Nexus-Hub does not already state somewhere? The sources were chosen by the user and share no author, but they converge on a single move (replacing a prose judgment with a typed, gated one), which is why they are analyzed together rather than as three separate reports.

## Step 7: Risks and conflicts

- **Item 7 (A11) contradicts an existing sentence.** `## Autonomous Operation` instructs the agent to stop short of actions clearly beyond what the request implies. A11 instructs it to complete an obvious missing step the operator would ask for next. These are compatible only when "obvious missing step inside the authorized scope" is defined sharply enough to exclude scope creep, and that block is byte-locked by a validator across thirteen templates.
- **Item 6 is bound by template parity.** Any shared-body change lands in all five machine-guarded `base-*.md` templates and is checked by hand against the eight unguarded ones. `scripts/check_base_template_parity.py` covers the guarded five only.
- **Item 8's matching mechanism must be portable.** Reading another process's working directory is `/proc/<pid>/cwd` on Linux and `lsof` on macOS, and is effectively unavailable on Windows. A rule built on it is unfollowable on a primary supported platform.
- **Item 8 as a hook changes an existing surface.** A rule file is additive. A hook needs a `.ps1` sibling with proven exit-code parity, registration on every matcher that can carry a kill command (not `Bash` alone), heredoc-body separation so it does not block its own rule file, and a Windows PowerShell 5.1 test leg.
- **Item 11 can hide a regression.** Incremental reuse is the only item whose failure mode is a false negative in a safety gate. Its invalidation rule must include a reachability condition: keying only on files a prior finding cited cannot catch a changed caller making an unchanged callee reachable.
- **Items 9 and 10 edit files another queued plan edits.** v4.16.2 Phase 5 is already inside Stage 1 of `multi-agent-code-review`. Sequence explicitly.
