This comparison reads four sources that all revolve around one product idea: a "System One" model that chooses, scores, or verifies from a supplied option set instead of generating text. It asks what each source knows that Nexus-Hub does not already state. It does not re-assess the hosted model itself, because [`v4.17.4-comparison-working-agreement-typed-judgment-and-prod-gates.md`](v4.17.4-comparison-working-agreement-typed-judgment-and-prod-gates.md) already rejected it (item B1) and already queued "selection over generation" (item 3, in `v4.17.5`) and a shared judgment-primitive vocabulary (item 5, in `v4.17.4`). This report only adds what those items do not cover.

The adoption target is `v4.17.9`, the next free slot after the queue. It was confirmed by the user because `v4.17.8` also edits `[[context-compression]]`, the lead target here, and landing after it avoids two plans editing the same preservation contract at once.

## Source A: `fast-jev-compaction`

A Claude Code plugin and npm library. On `/compact` it asks the hosted model, per tool call, whether the call and its result are still needed, then deletes or truncates stale ones and keeps all user and assistant text verbatim, instead of writing a summary.

| # | Insight (source section) | Status in Nexus-Hub | Evidence |
|---|---|---|---|
| A1 | Prune, do not summarize: only tool calls and tool results are removal candidates; user and assistant text is never rewritten ("What and why") | **Partially implemented** | `[[context-compression]]` Pattern 2 "Tool Output Compaction" replaces file reads with agent-written 3-5 bullet summaries, which is the lossy rewrite this source avoids. The preservation contract (six categories) weights user words "close to verbatim", but no approach deletes tool output while leaving everything else byte-identical. |
| A2 | Three-way decision per call: keep call and result; keep the call but truncate the result to its head plus a note; remove both ("How it works" step 6) | **Missing** | No catalog text distinguishes "the call still matters" from "its output still matters". |
| A3 | Drop criterion: a result may go when "re-running the tool would not do" is false, that is, when the tool can reproduce it ("How it works" step 4) | **Missing** | Nothing names re-runnability as the test. The inverse matters as much: a test run, a timestamped log, or a network read is not reproducible and must not be dropped on this criterion. |
| A4 | Pinning invariants: the first message and the newest N messages are never touched; a result is never left without its call ("How it works" steps 1 and 7) | **Missing** | No pin rule exists for client-side compaction or handoff documents. |

## Step 7: Risks and conflicts

- **Item 1 can contradict the `v4.10.1` retention correction.** A dead-end tool result is re-runnable in principle but its value is that it already failed. The re-runnability criterion must exclude results that recorded a negative finding, or pruning will recreate the retry loop that correction fixed.
- **Item 1 promises less than the source.** Without a host hook the agent cannot delete entries from its own transcript. Wording that implies surgical deletion on every host would be a false claim; the skill must say "directive" on hosts without a hook.
- **Item 6 reads session transcripts, which can contain secrets.** Its output files inherit that sensitivity. Cross-link `[[egress-redaction]]`, write output beside the input with owner-only permissions where the platform allows, and never upload it.
- **Item 6's transcript format is host-specific.** Build it against one documented format first and fail loudly on an unrecognized record rather than silently skipping it.
- **Item 2 overlaps an existing rule's vocabulary.** `visual-self-verification.md` mandates screenshots. The new section must scope itself to choosing actions, or an agent will read the two as contradictory.
- **Item 3 edits a file another plan owns.** Deliver it through the `v4.17.4` plan or after it lands, never in parallel.
