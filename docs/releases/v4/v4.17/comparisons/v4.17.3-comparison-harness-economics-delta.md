## Step 6: Adoption shape

### D1: Amend v4.17.3 decision 6 and Phase 4

- Replace "Bedrock, Vertex, Foundry" with a version floor: at least 2.1.277 generally, at least 2.1.281 for hosted providers, gateways and telemetry-off sessions.

Map the legacy `projectInstructions` key when `instructionFiles` is unset. Treat a missing key as `claude-md-or-agents-md`. Never read project `.claude/settings.json` for this key.
- Treat `claude-md` and `managed-only` as "fallback disabled". Treat a disabled built-in plugin as disabled. Treat `--bare`, `--safe-mode` and `CLAUDE_CODE_DISABLE_CLAUDE_MDS` as no-load modes that are out of scope.

- Classify `instructionFiles` in `docs/policy/platform-defaults-levers.md` as VERIFIED, with source URL and date. **Do not seed it**: the vendor default is already the value Nexus-Hub wants. This follows the seed-if-absent rule without changing behavior.

## Step 7: Risks, conflicts, and items not recommended

### Conflicts

| Concern | Conflict | Resolution |
|---|---|---|
| Project-scoped setting | Teams may expect `nexus-hub init` to set `instructionFiles` per repository. | The vendor ignores project settings for plugin options (S5.8). Document it; do not work around it. |

| Parity claims | The mod lists eight residual differences. | Phase 4 reports "converged with documented exceptions", never "equivalent". |

### Not recommended

**Author a Nexus-Hub Claude Code mod. Classification: `drop-outright`.** Mods are Claude-only, early-access and explicitly unstable ("may change between releases without notice"). They would also break the rule that shared behavior is platform-agnostic. The `agents-md` mod is a source of truth to read, not a pattern to copy.

**Seed `instructionFiles` at install. Classification: `drop-outright`.** The vendor default is already correct. Seeding it would add a write for no behavioral gain and could conflict with a user's later `/config` choice.

**Grokbot confidence-gated auto-merge. Classification: `drop-outright`.** This conflicts with protected-branch integration through a human-reviewed pull request.

**Adopt ECC Lean/Full/Auto profiles. Classification: defer.** Only commit titles were seen. Nexus-Hub's bundles, hook profiles and skill-index pointer already cover the same ground.

### Considered but rejected

- A new skill-index pruning mechanism: the v4.13.3 pointer already exists. The open question is the default, which D4 routes to the evidence that can decide it.
- A second payload measurer inside B: `scripts/measure_rendered_context.py` already reports estimated tokens, section sizes, duplicates and legacy spans.
- Using `/skill-doctor` as the organic-selection evidence for DF-1: it is Claude-only and reports usage, not selection quality. It supports B but cannot replace it.
