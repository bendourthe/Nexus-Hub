## Overview

The v4.17.12 comparison found that the catalog never tells an agent to refactor before changing scattered code, that its caching guidance covers Anthropic only, and that its own routing policy allows a mid-phase model switch without naming the cache cost. It also found that the harness ideas in a decision-harness tutorial are worth teaching once separated from the hosted scorer, and that the consumer Gemini app's new skills are a surface Nexus-Hub cannot install into.

The plan lands each rule in one owner, routes it so ordinary feature requests reach it, and then measures whether it changes agent behavior. Phase 1 records predecessor states, freezes the evaluation fixtures, and captures the control arm at the baseline commit before any catalog text moves. Phases 2 to 4 land the rules. Phase 5 runs the treatment arm against the pre-registered rule. Phase 6 is the mandatory fail-closed final phase. No skill is added, so no registry file changes.

Success is observable twice: the rule-ownership test fails on a missing handoff or a copied rule, and the evaluation file shows per-rule verdicts that follow mechanically from the per-arm table.

4. The write-containment hook is cut to a follow-on plan (interview Q2). Its specification is parked branch P1.
5. The subsystem baseline review is nice-to-have; the harness reference stays must-have, trimmed to the ideas v4.17.4 and v4.17.9 do not already own, with no executable-snippet test (Q3; narrowed 2026-10-01 after the placement review found those two plans cover deterministic-first, the judge cascade, and option sets).
6. Cache helper contract per DoD 3 (Q4).
7. Evaluation: cap USD 40 covering every model call (Q5); it measures refactor-first and enumerate-every-copy, each with its own verdict (Q6); grading is deterministic from artifacts, with no grader model (Q7); both arms run `claude-sonnet-5-5` at its default effort (Q8). Reaching the cap before every run completes yields NOT_MEASURED; the run is never extended.
8. Verdict rule, pre-registered here and copied unchanged into the admission file before any run (Q9). Fixtures: three small repositories, each with one expression duplicated across three files (a pricing-style formula, a display format string, a numeric threshold), a passing test suite, and a task asking for a feature that needs that logic. Runs: 4 per fixture per arm (24 runs), plus up to 12 treatment re-runs in one revision round. A run passes refactor-first when its transcript shows a green test run after the last refactor edit and before the first feature edit, and the final suite is green. A run passes enumerate-every-copy when a search of the final tree finds the expression in exactly one definition and every original caller uses it. A rule is CHANGED when the treatment passes at least 4 more of 12 runs than the control; otherwise NO_CHANGE.
9. On NO_CHANGE for a rule: revise that rule's wording once within the remaining cap and re-run the treatment arm only; if still not CHANGED, keep it as low-cost guidance and record a known gap. Rules are never reverted on a negative verdict.
10. Evaluation isolation: each arm loads skills from its own git worktree (control at the baseline commit, treatment at the Phase 4 commit) with an empty home directory, and records the sha256 of every skill file it loaded; a control run fails if its loaded text contains the refactor-first anchor clause. Credentials come from `NEXUS_PILOT_ANTHROPIC_API_KEY`, mapped only into the child process environment.
11. The ownership table is data inside `tests/skills/test_rule_ownership.py`, named for the behavior, not read from a release document that the docs-retention policy will archive. Each row's anchor is a distinctive clause of the rule, never its title, so a handoff that names the rule does not trip the absence check; that check is a copy-paste tripwire, not proof of single ownership.
12. Placement v4.17.12 (moved from v4.18.1 on 2026-10-01 under the `[[plan-queue-assessment]]` placement rule). Every content predecessor sits at or below v4.17.11, the plan shares no surface with v4.18.0, and v4.17.12 is the lowest free slot that sorts after all of them.
