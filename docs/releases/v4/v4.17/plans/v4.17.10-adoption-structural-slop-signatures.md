**Project**: Nexus-Hub

**Goal**: When Nexus-Hub de-slops or generates a prose-first artifact (a README, guide, handbook page, release-note narrative, presentify page, deck, or chat reply), `anti-slop-editing` repairs the document's shape before its wording, never drops a claim, number, or link in the process, and exempts template-governed records. Generation reaches the skill through a self-check request ("write the guide, then check it for AI slop"), a route the skill's routing trigger cases test. The offline heading detector reports the countable shape tells, and a paired evaluation on Claude shows fewer shape findings and zero dropped claims with the change than without it. No new third-party destination, credential, runtime dependency, or model download is added.

## Non-Goals

- Any authorship classifier, authorship score, or "percent AI" output. Detect mode's no-verdict rule stands; the comparison rejects the source's classifier on MCP Registry Policy grounds (new outbound scoring calls and a new data processor).
- Word-level model detectors (fine-tuned encoders, likelihood-based zero-shot scoring). They need model downloads, which the zero-model-download posture in `AGENTS.md` forbids.
- Per-model structural tells as editing targets. Several are practices Nexus-Hub requires (numbered procedures, stated caveats, baselines for numbers).
- Retrofitting existing Nexus-Hub documents. The rules are forward-only, like the `v4.17.6` heading rule.
- Title and heading style. `v4.17.6`'s Keyword Style bullet in `## Writing Discipline` owns it; this plan references that owner and never restates it.
- Any always-loaded template edit. Every change lives in a Tier-2 skill body, a Tier-3 reference, or a bundled script, which keeps this plan outside the `v4.16.0` standing-rule cap.
- Hard-gating on shape findings. They are advisory; only the existing `defect` class gates.

## Overview

The seeding comparison found that AI-generated prose carries a structural signature that survives rewording: the payoff is promised in the title, the thesis and section flow are announced before the first section, and the close restates the thesis. In the source study, rewording that replaced 73% of each post's 13-word sequences left structural detection unchanged. Nexus-Hub's de-slop pipeline works at word and sentence level, and its detector skips headings, so a draft it cleans can keep that shape.

Phase 1 fixes the exemption set and the detector interface. Phase 2 runs the two follow-up comparisons the user added to scope, so their findings feed the catalog before it is written. Phase 3 adds the preservation gate, the shape-first edit order, and the admission test. Phase 4 writes the structural-shape catalog. Phase 5 teaches the heading detector `v4.17.6` ships to count the countable tells. Phase 6 measures whether behavior actually changed. Phase 7 is the mandatory final phase.

The work is Markdown plus changes to one standard-library Python script. Phase 2 reads two public sources through the existing comparison skill, and Phase 6 runs 30 headless Claude Code sessions on the maintainer's existing login; neither adds a destination, credential, or dependency.
