**Goal**: An agent reads a dictated prompt by intent rather than wording, reconciles finished work against the original request and every later correction, knows the single boundary governing when to complete an obvious missing step, and retains decisions, review, and integration when it delegates -- with every rule admitted through the `v4.16.0` standing-rule cap rather than around it, and each one proved to change behavior rather than merely to exist.

## Definition of Done

**Must have:**

1. `v4.16.0` has landed and its standing-rule baseline is recorded before any rule in this plan is written.
2. Every admitted rule has a paired with-rule and baseline evaluation run showing a behavior difference, not only a parity test showing the text exists.
3. Template parity passes across the five guarded templates, and `tests/validators/test_autonomy_block_rule.py` passes across all thirteen.
4. Any item the cap defers carries a known-gap entry with an owner and a next step.

**Nice to have:** the operator identity and tooling placeholders (item 6), which change no agent behavior and are the first cut when the cap binds.

## Why this plan is separate

The six items here are always-on instruction rules. They live in a surface loaded on every session across roughly twenty platform integrations, and `v4.16.0-instruction-necessity-review` exists specifically to cap and reduce accumulation in that surface, which currently runs to 541 lines. Shipping six new rules before its before-and-after baseline is recorded would make that measurement report a surface this work had just inflated.

So the dependency here is a **hard block, not a preference**. There is no provisional-cap path: if `v4.16.0` has not landed, this plan does not start. The eight local-logic items from the same comparison were split into the sibling plan precisely so the highest-value safety work is not held behind this gate.

## Phase 4: Behavioral evaluation of every admitted rule

**Goal**: Each admitted rule is shown to change agent behavior, not merely to exist in a file.
**Prerequisites**: Phases 2 and 3.
**Stability Gate**: A paired with-rule and baseline run exists per admitted rule, each graded against a written assertion, with the difference recorded. A rule showing no behavioral difference is reported as such rather than quietly kept.
**Verification Expectation**: Open the recorded evaluation results and observe, per admitted rule, two graded runs and a stated difference. A rule with only a parity test and no paired run has not satisfied this phase.
**Recommended model tier**: strong
**Recommended effort level**: high
**Rationale**: Bounded harness work, but it is the only phase that produces evidence the plan achieved anything, and a weak fixture here makes every preceding phase unfalsifiable.

### Sub-tasks

#### 4.1 -- Build the fixtures

**Objective**: Create the inputs that can distinguish rule-following from rule-absence.

**Prompt**:
> Via `[[skill-eval-loop]]`, build one fixture per admitted rule. For dictation tolerance: a prompt with run-on phrasing, a homophone error, and a mid-sentence self-correction, where the literal reading and the intended reading diverge in what gets built. For reconcile-against-corrections: a request followed by three corrections, where the third silently conflicts with the original ask. For the anticipate boundary: one case where the missing step makes the work unusable (the rule should fire) and one where it would merely improve it (the rule should not fire); a fixture with only the first case cannot detect an over-firing rule. For the delegation split: a delegated task whose returned work carries no means of independent verification. Each fixture carries a written assertion that can be graded without re-reading the rule. Acceptance: one fixture per admitted rule, the anticipate fixture carries both the fire and no-fire cases, and every assertion is written before the runs.

---

#### 4.2 -- Run the pairs and record the differences

**Objective**: Produce the evidence, including negative results.

**Prompt**:

A rule showing no behavioral difference is recorded as showing none and escalated as a finding, not quietly retained; standing-rule budget spent on a rule that changes nothing is exactly what `v4.16.0` exists to recover. Acceptance: paired results per admitted rule, differences stated, and any null result reported rather than omitted.
