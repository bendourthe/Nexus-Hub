**Goal**: In Claude Code, a rule the user pins during a session is back in the model's context after every automatic or manual `/compact`. The repository then gains three smaller changes. When compacting, agents drop tool output they can re-run instead of paraphrasing the conversation, and record what they dropped in a defined ledger format. Agents that drive a browser do so from an indexed page snapshot in a throwaway, credential-free profile. Enumerated verdict sets and cheap-judge-first cascades fail safe. Other hosts receive the instruction-level parts, and the release notes state per host what is guaranteed. No new third-party destination, credential, runtime dependency, or model download is added.

## Overview

The seeding comparison started from a specific pain: after hours of work, `/compact` loses a rule the user stated early, and the user has to re-explain it. The hosted decision models in the sources are rejected on policy grounds, as `v4.17.4` already did. The plan review found that the first draft did not relieve this pain in Claude Code, because the host's own summarizer never reads a Nexus-Hub skill.

The official Claude Code hooks reference supplies a deterministic fix. A `SessionStart` hook with the `compact` matcher runs after every automatic or manual compaction, and its output is added to the model's context. Phase 2 builds a small hook pair on that seam. The user pins a rule with a short prefix, the rule goes to a per-session file outside the repository, and the hook puts it back after each compaction. Project instruction files are also re-loaded after compaction, so the skill tells agents to offer saving a lasting rule there too. That part works on every host.

Phase 3 adds the prune-not-summarize method from the compaction source as prose, with a concrete ledger format. Phase 4 is the first cut: a read-only script that turns a long transcript into a Markdown handoff digest. Phase 5 adds browser-action rules, hardened by the security review. Phase 6 adds two small decision-design rules.

All work is Markdown, one `.sh`/`.ps1` hook pair, and optionally one standard-library Python script. Nothing is sent anywhere.

### Sub-tasks

#### 2.1 -- Build the hook pair

**Objective**: Capture pins on prompt submit and re-inject them after compaction.

**Build class**: load-bearing.

**Failure modes**: Malformed or absent input (stdin not JSON, a missing `session_id`, a `session_id` that is not a plain identifier, an empty rule after the prefix): exit 0 and do nothing, and never block the user's prompt. Store directory unwritable or disk full: exit 0, write nothing, and emit one factual line to stdout on the pin turn saying the pin was not saved. The prompt is never blocked. Conflicting operations (two prompts pinning at once in the same session): append with a single write of one complete line so concurrent appends cannot interleave within a line; duplicates are allowed and de-duplicated on output. No network dependency.

**Prompt**:
> Create `catalog/hooks/pinned-rules.sh` (`#!/usr/bin/env bash`, `set -euo pipefail`) and `catalog/hooks/pinned-rules.ps1`, following `catalog/rules/bash/security.md` and the sibling rules in `AGENTS.md` "Adding or Modifying a Hook". Parse stdin JSON with `jq` in bash; if `jq` is absent, exit 0. Use `ConvertFrom-Json` in PowerShell and `[System.IO.File]` writes with `UTF8Encoding($false)` so no BOM is written. Honor `NEXUS_DISABLED_HOOKS=pinned-rules` and `NEXUS_HOOK_PROFILE=minimal` exactly like `catalog/hooks/approval-capture.sh`. Behavior by `hook_event_name`: (a) `UserPromptSubmit`: if `prompt` starts with the T004 prefix, take the trimmed remainder, drop it if it matches a T004 secret pattern, otherwise append it to the T004 store path, and prune store files older than 7 days. Print one line that becomes context for this turn: `Pinned rule recorded for this session: <rule>`. Never block the prompt, and never print for a prompt without the prefix. (b) `SessionStart` with `source` equal to `compact`: read the store for `session_id`, de-duplicate while keeping order, and print `Rules the user pinned earlier in this session, restored after compaction:` followed by one `- <rule>` line each. Keep the total under 10,000 characters, the documented cap, truncating with a final line that states how many were omitted. Print nothing for any other `source`. Write facts, not imperative system commands, because the official reference warns that command-style text can trigger prompt-injection defenses. Acceptance: the Verification Expectation holds for both implementations.
