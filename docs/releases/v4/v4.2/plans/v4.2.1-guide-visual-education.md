**Project**: Nexus-Hub
**Target version**: v4.2.1
**Slug**: guide-visual-education
**Rank**: 18 of 18 in [`docs/roadmap-prioritization.md`](../../../../roadmap-prioritization.md)

**Created**: 2026-08-29
**Goal**: Turn the unpublished v4.2.0 guide into a concise, illustrated, highly interactive, and accessible first-contact site that teaches AI terms visually, walks a fun buggy web app to a fixed one with a new feature, and merges Workflows plus Reference into one Cheatsheets tab, without changing command semantics or the single-file offline contract.

## Overview

v4.2.0 merged to `develop` as PR #145 and is **not** a public GitHub Release. Catalog version on disk is still 4.1.2. Maintainer visual QA of the live file (seven screenshots, 2026-08-29) found chrome bugs, light-theme contrast failures, a dated Home loop, and a Foundations plus Training rewrite that buried the educational purpose under dense technical prose.

This patch keeps the v4.2.0 shell that still works: hash routing, dual theme, Home install constants, closed eight-command Training set, copy contract, and no CDN. It reverses the teaching-model mistakes: Foundations must again lead with visual, interactive explanations of prompt engineering, context engineering, harness engineering, and loop engineering; Training must be a slideshow of a fun visual example, not an IDE workbench of walls of text; Workflows and Reference merge into one Cheatsheets tab.

Do not tag v4.2.0 as a GitHub Release of the rejected UI. After this plan's integration is green, `/update release` cuts **v4.2.1** from 4.1.2. Changelog prose may still describe the unpublished 4.2.0 redesign as the substrate this patch lands on.

Each non-final phase ends with local verification and one local commit. No non-final phase pushes, opens a pull request, authors GitHub Actions, or starts remote CI. The final phase archives the v4.2.0 last-phase evidence, writes a v4.2.1 evidence file, publishes once with approval, and hands a green integration to `/update release`.

## Goals First

**Target problem**: First-time visitors, including people who are not software engineers, cannot quickly see what a model, a harness, and Nexus-Hub's loop actually do, and the current pages are neither readable in light theme nor engaging enough to hold attention.

**Primary persona**: A curious evaluator who may or may not write code daily. They need pictures, short labels, and interaction, not a field manual.

**Secondary persona**: A software engineer or workshop facilitator who still needs accurate command names, install lines, and a cheatsheet of arguments after the visual teaching lands.

**Observable definition of done**:

- A first-time visitor can explain, in plain language, what prompt engineering, context engineering, harness engineering, and loop engineering each change, after using Foundations, without reading a long essay.
- The same visitor can step Training as a slideshow and watch a visual web app go from buggy to fixed plus one new fun feature, with one command per major stop.
- Chrome is solid while scrolling, the GitHub control is icon-only, theme is a sun/moon toggle that defaults to dark, and the Nexus-Hub wordmark is readable in both themes.
- Install terminals in light theme use light-theme tokens, and every Copy control sits at the right end of its terminal box.
- Primary nav is Home, Foundations, Training, Cheatsheets. Cheatsheets opens on the loop overview, then a command cheatsheet with arguments, then extra workflow detail only when it is not a repeat of Training.
- The file stays one self-contained HTML document: no CDN, no runtime fetch, no framework. Reduced-motion users get a complete static equivalent of every motion effect.

**Success measures**:

- Structural: focused `tests/guides/test_nexus_hub_guide.py` pass locally against the new contract (slideshow allowed, Cheatsheets page present, Foundations four-layer teaching present, no primary range-slider comparison).
- Accessibility: last-phase Lighthouse Accessibility at least 90 in both themes; no high-severity contrast, keyboard, heading, or reduced-motion defect. Wordmark contrast in light theme is a must-pass, not advisory.
- Fidelity: desktop, tablet, phone, light, and dark visual QA records no open high-severity hallmark issue on the seven screenshot classes that triggered this plan.
- Lighthouse Performance, SEO, and Best Practices remain advisory.

## Scope

### Must-ship

- Opaque sticky header (no see-through nav as content scrolls under it).
- GitHub control is the GitHub mark only, with an accessible name. Theme control is a sun/moon toggle. First visit with no stored preference is dark.
- Light-theme wordmark uses theme ink, not hardcoded white on beige.
- Copy buttons are pinned to the right edge of the terminal chrome, not glued to the command string. Light theme terminals (header, body, copy chip) use light tokens.
- Home loop graphic modernized: less rigid squared boxes, more visual nodes, same six stops and exact `Map and evaluate` string.
- Foundations rewritten as the educational tab: visual, interactive, minimal text. Teach prompt / context / harness / loop engineering as first-class stations. Replace the range slider and the three identical text cards as the hero teaching.
- Training restored as a slideshow (keyboard and on-screen next/previous). Hero is the example app transforming. File/IDE detail is optional disclosure, not the default view. Closed command set remains eight scenes, hard cap twelve slides.
- Replace Trivia Quiz as the taught example with **Glow Booth** (frozen below). Keep `guides/website/example/trivia-quiz/` on disk until the last phase confirms nothing published still points at it.
- Merge Workflows and Reference into **Cheatsheets**. Hash redirects from `#workflows`, `#explore` and the other six workflow ids, and `#reference`.
- Presentify-like scroll and cinematic *patterns* on Home and Foundations: pinned/sticky illustrations, scroll-triggered reveals, progress-linked stage states. No video clips. No copy of `scroll-scrub-engine.js`. Reduced-motion deletes the motion and keeps the teaching.
- Rewrite tests and `guides/website/README.md` to the new contract.

### Later (explicitly not required to ship v4.2.1)

- Workshop versus self-guided dual modes.
- Autoplay, speed control, fullscreen, or timed in-slide animation.
- online-portfolio `scripts/sync-nexus-hub-guide.mjs` and portfolio README work.
- Lighthouse Performance or SEO as merge gates.
- A public v4.2.0 GitHub Release of the pre-polish guide.

### Out of scope

- Changing Nexus-Hub command semantics, installer behavior, catalog contents, or supported-platform behavior.
- Adding telemetry, a server, a framework, a CDN, remote fonts, or runtime network dependencies.
- `design_seed` uniqueness, hosted image generation, or embedding presentify's cinematic engine or video pipeline.
- Authoring GitHub Actions path filters or a second required workflow. The existing `pytest tests` job already covers `tests/guides/`.
- Hardcoding catalog skill or command counts in onboarding copy.
- Absorbing v4.1.x or v4.0 known-gaps into this close-out.

| Capability | Guide use | Reason |
|---|---|---|
| `nav=scroll` | Inherit for Home, Foundations, Cheatsheets | Those pages remain a scrolling field guide |
| `nav=slides` inside Training only | Inherit with a cap | Maintainer asked to keep slideshow capability. Whole-site slide routing stays rejected |
| `applyState(scene, beat)` idempotence, fragment beats, key-disengage, `replaceState` for beat ticks | Inherit | Cold URLs must render a full snapshot |
| Rich before/after, pinned graphic, click-to-swap visual states | Inherit for Foundations | Replace the range slider as the hero comparison |

| Copying `scroll-scrub-engine.js` or embedding video clips | Reject | Size, offline budget, and reduced-motion deletion of video |
| `design_seed` uniqueness / entropy | Reject | The guide must still match the portfolio, not look new every generation |
| html-output-conventions, hallmark-design, visual-QA viewports | Inherit | Offline, no CDN, reduced-motion static equivalents |
| `/presentify` as a taught command | Keep | Cheatsheets lists `--nav` and `--interactivity` flags. Training closer still produces the HTML artifact |

### URL grammar

- Pages: `home`, `foundations`, `training`, `cheatsheets`. Unknown page id maps to `home` and rewrites the URL.
- Compatibility rewrites (replaceState, no extra history): `#reference` and `#workflows` to `#cheatsheets`. `#explore`, `#plan`, `#build`, `#harden`, `#ship`, `#communicate` to `#cheatsheets/<id>` when those were page ids, or to Cheatsheets plus the matching section id.
- Training: `#training/<scene-id>` with optional `?beat=<n>` via `replaceState`. `#training` loads slide 1.
- ArrowLeft / ArrowRight / Space on Training change slides only while the page is `training` and focus is not inside an interactive region. They never change the primary page.
- `#home/install` still scrolls to `#nhg-install`.

### Trust boundary (unchanged)

- Fixture strings render with `textContent` / `createTextNode`. No `innerHTML` for scene data.
- Inline JSON lives in `<script type="application/json">` with `</script>` encoded.
- `portfolio-theme` accepts only `light` or `dark`. Wrap `localStorage` in try/catch.
- No runtime CDN, fonts, analytics, or fetch.
