# Plan -- Interactive Guide Cinematic Rebuild

**Project**: Nexus-Hub
**Version**: v4.2.2
**Slug**: guide-cinematic-rebuild
**Plan Type**: Feature / Enhancement (ground-up page re-engineering)
**Created**: 2026-08-29
**Goal**: A visitor to the published guide experiences a modern, cinematic, interactive four-page site in which every complaint from the 2026-08-29 screenshot review is resolved, Foundations and Training are rebuilt from scratch as animated educational experiences (Training doubling as a fullscreen slide walkthrough with an interactive Glow Booth mockup and a simulated terminal), Cheatsheets explains every command scope in place, and every phase ships with rendered browser evidence -- judged better than both the unpublished v4.2.1 UI and the live pre-4.2.0 site.

## Overview

This plan supersedes the unpublished v4.2.1 UI. The guide (`guides/website/nexus-hub-guide.html`, single self-contained offline HTML, currently 2,906 lines) is re-engineered from the ground up rather than patched: a new design system (compact spacing, motion language, light/dark parity), a rebuilt Home page fixing the seven concrete screenshot defects, a from-scratch Foundations page teaching model / platform / harness / context interplay through animated diagrams (pitched between the v4.1.2 baseline and the v4.2.x attempt), a from-scratch Training page built as an interactive step-by-step walkthrough with a working Glow Booth app mockup and a simulated terminal that "runs" each command, and a Cheatsheets page whose sections carry meaningful names and per-scope descriptions derived from `catalog/commands/`.

Delivery is unchanged: one hand-authored HTML file, zero runtime network calls, copied byte-identical to the sibling portfolio repo. The existing 39-test gate (`tests/guides/test_nexus_hub_guide.py`) is updated in lockstep with each phase, and a new dev-only Playwright render harness produces per-phase screenshots (dark + light, three widths) so no visual change ships unrendered again -- closing the v4.2.1 open gap DF-1 by construction. v4.2.1's publication step (T026) is never run; v4.2.2 is the first public cut of the redesigned guide.

Success looks like: the published page at the portfolio host renders with no warning box, a correct GitHub icon button, hero text sharing the title's measure, Windows-first install tabs, slim copy buttons, copyable verify-command cells, compact section rhythm, a light-mode logo chip, an animated Foundations, a slide-capable interactive Training, a self-explanatory Cheatsheets -- with screenshot evidence per phase and a green integration PR to `develop`.

#### 1.2 -- Playwright render harness (dev-only)

**Objective**: A local script that renders the guide in a real browser and saves screenshots per page x theme x width, so every later phase verifies visually before committing.

**Failure modes**: If the guide file is missing or unparseable, the script exits non-zero naming the path instead of writing empty images. If Playwright or its browser download is unavailable (offline machine), the script exits with a one-line install hint (`pip install playwright && playwright install chromium`) and phases fall back to documented manual browser review -- the fallback is recorded in the phase's session history, never silently skipped. If two runs race on the same output directory, the second run overwrites atomically by writing to a temp name and renaming.

**Build class**: load-bearing for this plan's QA loop; dev-only, never installer-copied.

**Objective**: A written scene-by-scene script for the page before any markup: what each section teaches, what each diagram shows, how each animates.

**Prompt**:

Design Foundations as a scrollytelling sequence of 4-6 scenes, each one concept with one animated diagram: (1) the model alone -- prediction from training plus the current turn, and what it cannot do (no hands, no memory of your repo); (2) the platform -- the agent loop reading files, running tools, editing the repo, drawn as an animated loop diagram; (3) context engineering -- a visual "context window" filling with the right vs wrong material, showing how what the model sees changes what it produces; (4) the harness -- Nexus-Hub's skills, commands, hooks, and gates wrapped around the loop, animated as guardrails engaging; (5) how they compose -- one connected animated chart showing model + platform + context + harness interacting on a real task, contrasting outcome quality without and with the harness (both states visible in the flow, NOT toggled by a selector); optionally (6) a "what this means for you" bridge into Training. Draw the middle ground between v4.1.2's simple card structure and a stronger animated ambition, per the design brief.
