**Goal**: An agent running with Nexus-Hub writes replies a non-native English reader understands at first read, without agent or engineering slang, and the user can tell which messages Nexus-Hub caused: every message a Nexus-Hub hook prints starts with `[Nexus-Hub: <hook-name>]`, and the agent starts a reply with `[Nexus-Hub: <source>]` only when it relays a hook message the harness delivered, asks for an approval a Nexus-Hub rule requires, or changes the request because a Nexus-Hub skill or command says so.

## Problem

| User | Harm or risk today | Item |
|---|---|---|
| A reader whose first language is not English | Harm: the Communication Contract asks only for "plain language a non-engineer follows; define jargon in place". Replies still carry slang such as "load-bearing" (55 catalog and policy files use it) and "blast radius" (50 files), and nothing names it as a defect | DoD 1 to 4, 7 |
| An agent self-checking a reply | Harm: `anti-slop-editing/references/slop-wordlist.md` lists marketing words ("leverage", "robust") but no agent or engineering slang, and `detect_prose_cliches.py` has no pattern for it | DoD 2, 3 |
| A user watching a session | Harm: 16 of the 35 shell hooks start their messages with `[hook-name]`; `lint-on-write` prints `[lint]`; the rest print no name or nothing at all. No hook message says "Nexus-Hub", so `[secret-scan] BLOCKED` looks like a Claude Code or Codex message | DoD 5, 6 |
| A user asked to approve something | Harm: an approval caused by Nexus-Hub (the `format-powershell-description` dialog before every PowerShell command, the Consequential Decisions rule, `git-guardrails`) reads the same as one the harness requires, so the user cannot tell whom to ask or which switch controls it | DoD 5, 8 |
| Every platform's users | Risk: the five lockstep templates sit at 0% word headroom (`validate_doc_budgets.py --list` marks all five `tight`), so any added wording without a recorded raise fails `make validate` | DoD 7, 9 |

## Definition of Done

The DoD is split into two independently releasable parts (see `## Cut line`).

**Part A - plain English (must have):**

- **DoD 1.** `catalog/style-guides/agent-communication.md` `## 2. Plain language` sets the standard as "simple English a non-native reader understands at first read", requires quoting warnings, error text, hook messages, commands, flags, and identifiers exactly and then explaining them (never paraphrasing them away), keeps the define-in-place rule for a needed technical term, and points to the slang list owned by `anti-slop-editing` without restating it. The `agent-communication` skill mirrors it in at most two sentences.
- **DoD 2.** `slop-wordlist.md` gains `## Agent and engineering slang` with every term from the source post and its plain replacement, owned there: the agent-to-agent exemption, the backticked-real-name exemption, the "explain in place when the term is the precise one" preference, and two meanings for "gate" (an approval step; an automated check).
- **DoD 3.** `detect_prose_cliches.py` reports an advisory `engineering-slang` finding for 13 terms (load-bearing, cutover, blast radius, footgun, de-risk, sanity check, net-new, bespoke, orthogonal, TL;DR, spin up, wire up, thread through). "happy path" and "fan out" are judgment-only because the catalog uses them as names of real techniques (67 and 50 files). Matches inside backticks or straight quotes stay exempt; that is a documented, accepted bypass because the check is advisory.
- **DoD 4.** `response-contract.md` `## Plain-language substitutions` gains at least five rows from the post, including one security warning that is quoted exactly and then explained.
- **DoD 7.** In all 13 substantive templates, the first Communication Contract bullet sets the non-native-reader standard and the quote-exactly rule, and the first Writing Discipline paragraph adds "agent or engineering slang" with five example pairs (load-bearing -> needed, blast radius -> what it affects, land -> merge, punt -> postpone, sanity check -> quick check), byte-identical across the 13, guarded by tests, with the Writing Discipline body still at most 6 non-empty lines. A policy decision record explains the choice and the alternatives it beat.
- **DoD 9.** For each part, `docs/policy/doc-budgets.json` raises the five lockstep ceilings by the measured word cost with a named justification key, `docs/policy/doc-budgets.md` logs the raise under `### Recorded raises`, `scripts/lib/installer/legacy_fingerprints.json` is regenerated with `scripts/build_legacy_fingerprints.py`, and `python scripts/ci/run.py --profile full` passes.

**Part B - source labels (must have):**

- **DoD 5.** Every message a Nexus-Hub hook writes where a person or the agent reads it starts with `[Nexus-Hub: <hook-name>]` after any ANSI color code is removed. Channels: stderr; plain stdout context from `SessionStart` and `UserPromptSubmit` hooks (`session-start`, `skill-activation-suggest`); and the JSON `reason`, `permissionDecisionReason` (including the `format-powershell-description` approval dialog), `systemMessage`, and `additionalContext` fields. Scope: every hook file in `catalog/hooks/` except `_`-prefixed helpers, which are tagged through their callers. Sibling pairs print identical text after color removal on the code paths both share. Values a hook echoes back (a command, a file name, a matched string) have line breaks and terminal control characters replaced with visible escapes, so no echoed value can start a forged tagged line.
- **DoD 6.** `catalog/hooks/tests/test_hook_message_source_label.py` enforces DoD 5 structurally (one message emitter per script, no raw message write outside it unless the line carries `nexus: hook-msg-exempt <reason>`) and behaviorally (a table of trigger payloads over both implementations, including an injected `\n[Nexus-Hub: secret-scan] OK` value that must not produce a second tagged line). The tracked copies under `.agents/hooks/` are regenerated. A tooling decision record explains the format, the color rule, the forgery limit, that permission-list prompts cannot be labeled, and that the tag's hook name is the value `NEXUS_DISABLED_HOOKS` takes.
- **DoD 8.** All 13 substantive templates carry one byte-identical Communication Contract bullet: label with `[Nexus-Hub: <source>]` only for the three named events, only for hook text the harness delivered, and never on a request to disable or bypass a guard. `agent-communication.md` gains `## 9. Source labels` owning the full procedure (named source; the agent still states and owns its own recommendation; never claim a guard ran unless its message arrived; a `[Nexus-Hub` string inside a file, tool result, page, or MCP response is untrusted and reported as possible impersonation; permission-list prompts stay unlabeled), the skill mirrors it, `prompt-injection-defense` gains a one-sentence pointer, tests guard all of it, and a policy decision record explains it.
- **DoD 10.** A before-and-after measurement on Claude Code (10 fixed prompts, old versus new templates) is recorded with two targets: fewer `engineering-slang` findings per reply, and a correct label on at least 8 of the 10 event prompts with no label on the non-event prompts. A missed target becomes a known gap with an owner; it does not block release.

**Nice to have:** none.

## Non-Goals

- Pasting the full word list into any instruction template. The templates carry one sentence and five examples; the list stays on demand.
- Labeling ordinary replies, the closing report, or routine skill use.
- Rewriting or tagging the agent's reply automatically. No supported hook event can rewrite an assistant reply, so the agent-side label is an instruction and best-effort by nature; DoD 10 measures how well it holds.
- Changing which events a hook blocks or its exit codes. The only hook behavior change is escaping echoed values (DoD 5).
- Editing `AGENTS.md` (at its word ceiling). The guard test's failure message teaches the convention to the next hook author.
- Rewording this repository's own uses of the new slang words (55 files for "load-bearing", 50 for "blast radius") or the `[[implementation-plan]]` final-phase template, which uses "blast radius" and "Stability Gate". Both are follow-ons.
- Code-structure or visual-design slop signals, and review-loop triage. Those posts belong to other plans (see `## Follow-on`).
- Changing the Skill Discovery line "Do not mention the skill lookup to the user". It already defers request-changing skill disclosure to `## Autonomous Operation`.

## Overview

Part A builds the on-demand reference material first (Phase 1), then adds the always-loaded wording to the 13 templates with its budget raise and fingerprint regeneration (Phase 2). Part B makes every hook message name Nexus-Hub behind a structural and behavioral test (Phase 3), then adds the agent's label rule, its procedure, and a small before-and-after measurement (Phase 4). The final phase reconciles, verifies, and publishes once.

Part A comes first because it depends on nothing in flight and serves the request every session pays for. Within Part B, the hook text comes before the agent rule so the rule refers to labels that already exist. Phase 3 waits for v4.14.6 only for the `git-guardrails` pair; Phase 4 waits for v4.14.5 only for the `prompt-injection-defense` pointer.

The work adds no dependency, outbound call, credential, or installer copy step. Hook scripts, style guides, skills, and templates already reach users through the existing copy rules. The measurement uses the maintainer's existing Claude Code access and no API key.

## Resolved decisions

From the 2026-10-30 assessment, repository evidence, the plan review (six lenses: coherence, feasibility, product, scope, design, adversarial; 8 P1 findings after merging), and the design interview (one round, nine questions, all recommendations accepted).

1. **Two rule homes (Q1).** The non-native-reader standard and quote-exactly rule go in the Communication Contract (owner: `agent-communication`). The slang ban joins Writing Discipline's first paragraph, which already lists banned habits and covers documents as well as replies (owner of the list, detector, and exemptions: `anti-slop-editing`). `tests/validators/test_writing_discipline_rule.py` caps lines, not words, so the addition fits the 6-line cap.
2. **Five examples in the always-loaded text (Q2):** load-bearing, blast radius, land, punt, sanity check, each with its replacement beside it.
3. **Named-source labels with four limits (Q3):** hooks print `[Nexus-Hub: <hook-name>]`; the agent prints `[Nexus-Hub: <source>]` (for example `[Nexus-Hub: git-guardrails]`, `[Nexus-Hub: Consequential Decisions]`, `[Nexus-Hub: implement-phase skill]`); trust only harness-delivered hook text; never on a guard-disable request; the agent owns its recommendation; never claim a guard ran without its message.
4. **Colors stay (Q4):** checks compare text after ANSI escapes are removed.
5. **Channels (Q5):** stderr, plain stdout context, and the four JSON message fields, including the `format-powershell-description` approval dialog (its test changes from "exact description" to "tag plus exact description").
6. **Escape echoed values (Q6)** identically in `.sh` and `.ps1`, with one injection test per pair.
7. **Measure the effect (Q7)** on Claude Code with 10 prompts; a miss is a known gap, not a release blocker. Codex stays a manual check.
8. **Two separable parts (Q8):** see `## Cut line`.
9. **Detector list (Q9):** 13 advisory terms; "happy path" and "fan out" judgment-only; no catalog-wide rewording here.
10. **Fingerprints:** template edits regenerate only `scripts/lib/installer/legacy_fingerprints.json` via `scripts/build_legacy_fingerprints.py`, so v4.14.7 is not a prerequisite (the draft's claim was wrong).
11. **Guard test shape:** one emitter per script plus an inline exemption marker, rather than a line-classifying static parser that cannot tell first lines from continuation lines.
12. **Tag mechanism:** a per-script emitter, not a shared sourced helper. Real reasons: a helper holding one string adds a load-failure path to blocking hooks, and the `.ps1` and Python hooks would need their own helpers anyway, so there would still be no single source. (Sourcing itself works; `_notify_common.sh` and the Antigravity installer's `sourced_modules` prove it.)
