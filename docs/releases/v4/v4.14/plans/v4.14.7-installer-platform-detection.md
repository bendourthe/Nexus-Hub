# Plan -- Installer Platform Detection: No Folders for Tools That Are Not Installed

**Project**: Nexus-Hub
**Version**: v4.14.7
**Slug**: installer-platform-detection
**Filename**: `v4.14.7-installer-platform-detection.md`
**Plan Type**: Feature (installer bug-fix campaign)
**Created**: 2026-10-29
**Status**: queued
**Seeded from**: the maintainer's 2026-10-29 home-folder audit, which found `~/.kimi-code`, `~/.qwen`, `~/.hermes`, `~/.nexus-ai`, and `~/.aider.conf.yml` on a machine where none of those tools is installed, plus the obsolete `~/.agent` and home-root `~/.opencode` layouts. Decisions D1 to D9 below were confirmed in that session, after a seven-lens plan review (findings and their disposition in the appendix).

**Goal**: A global Nexus-Hub install writes a platform's surfaces only when that platform's tool is actually present, judged by evidence the installer did not create itself, so a machine without Kimi Code CLI, Qwen Code, Hermes, Pi, Aider, OpenCode, or the Nexus-AI desktop app ends the install with none of their folders or config files, and the install output says why each was skipped and how to override it; a user can force any platform by naming it with `--platforms`; machines that already carry stale Nexus-Hub surfaces are told about them and can remove them with one explicit command that never deletes a file the user wrote or changed; and the obsolete `~/.agent` and home-root `~/.opencode` layouts are removable through the same explicit command when every file in them is recognized Nexus-Hub output.

## Overview

Each platform integration under `scripts/lib/integrations/` decides whether to install by setting `WriteResult.detected`. Four defects make that decision unreliable. **(A) Circular detection**: Kimi, Qwen, Hermes, and Pi treat "the tool's home folder exists" as proof of installation, but that folder is also where Nexus-Hub writes, so a single earlier write (on the maintainer's machine, `.kimi-code`, `.qwen`, and `.hermes` appeared in the same minute on 2026-08-08, during the v3.16.0 defaults-seeding work, commit `7ea867c04`) makes every later install count the tool as present. **(B) Nexus-AI is never gated**: `NexusAiIntegration.install_global` always writes `~/.nexus-ai/catalog`. **(C) Aider is never gated**: `AiderIntegration.install_global` always writes `~/.aider.conf.yml`, and because `detected` stays `None`, the `base.py` defaults-seeding gate (`detected is not False`) also lets seeding through. **(D) OpenCode is gated only for its plugin, and circularly**: the global surfaces are always written into `~/.config/opencode`, and the completion plugin is gated on that same folder existing, so the second install adds executable plugin code even when OpenCode is absent. A second, independent folder-existence detector lives in `docs/policy/platform-read-contracts.json` (`install_verify[].detect`), read by `nexus-hub verify`; left alone, it would tell users to reinstall a platform the fixed installer then skips.

The fix declares each platform's detection signals once, as a `detection` entry in the integration's class-level `config` dict, and evaluates them with one shared primitive. A platform is detected when the user named it explicitly with `--platforms`, when one of its declared executables resolves on `PATH`, or when its home root holds an entry Nexus-Hub did not write; a root holding only Nexus-Hub entries is not evidence, while a merged user config or a `*.nexus-hub.bak` backup is evidence that the tool existed. Install, `doctor`, `verify`, and removal all read the same declaration, and a not-detected install no longer erases the platform's recorded file hashes. Both installers gain a minimal, parity-tested change: they pass the user's explicit platform list through as forced, and print one evidence line and one remedy line per NOT DETECTED platform.

Two remediation paths follow, both opt-in. Stale surfaces on existing machines are reported by `nexus-hub doctor` and the install summary, and removed only by an explicit command that defaults to a dry run. That command works per entry kind: a whole file Nexus-Hub created is deleted only when its hash still matches; files under a tracked directory are compared with the catalog source and extras are kept; a merged or shared file has only its Nexus-Hub block removed; `*.nexus-hub.bak` files and anything outside the platform's declared root are never deleted; nothing is removed recursively. The obsolete `~/.agent` and home-root `~/.opencode` layouts are handled by the same command, but only after a spike proves that the historical files can be recognized; if it cannot, that phase moves to a follow-up plan and the rest ships alone.

### Non-Goals

- **No change for Claude Code, Codex, Cursor, Gemini, Antigravity, or Gemini CLI.** They are not detection-gated today (`detected=None`) and stay that way.
- **No change to OpenClaw, Windsurf (Devin Desktop), or Copilot gates in this plan.** They are detection-gated on vendor-owned roots; sub-task 2.2 audits them and records any circular finding as a known gap rather than editing them.
- **Workspace-scope installs are unchanged.** A workspace install is an explicit request for that folder.
- **No other obsolete layouts** beyond `~/.agent` and home-root `~/.opencode`.
- **`*.nexus-hub.bak` files are never removed automatically.** They are copies of user configuration.
- **No installer-script change beyond D8.**
- **No automatic deletion anywhere.** Every removal is behind an explicit command that defaults to a dry run.

**Objective**: Fix, with evidence, which executables, roots, vendor entries, and Nexus-Hub entries apply to each of the seven gated platforms, before any code relies on them.

**Prompt**:

#### 1.2 -- Detection spec and shared primitive

**Objective**: Declare signals on each integration and evaluate them in one place.

**Build class**: load-bearing.

**Failure modes**: Malformed or absent input: a missing root, a root that is a file, an unreadable root, or a spec with no executables returns a verdict with an evidence string and never raises; a redirected root (symlink, junction) is inconclusive for the root check, is never read through, and evaluation falls through to the PATH probe. Unreachable or slow dependency: `PATH` resolution is local, but an entry on an unreachable network share can stall `shutil.which`, so the root check runs first and no subprocess is ever started; the resolved executable is never executed, sourced, or version-probed. Conflicting operations: the primitive is read-only and never creates the root it inspects; manifest reads tolerate a missing or corrupt manifest by falling back to the spec's declared Nexus-Hub entry names with a reported warning, never a traceback.

**Prompt**:
> In Nexus-Hub, add a `"detection"` entry to the class-level `config` dict of `kimi.py`, `qwen.py`, `hermes.py`, `pi.py`, `nexus_ai.py`, `aider.py`, and `opencode.py`, holding the values from `docs/releases/v4/v4.14/development/v4.14.7-detection-signals.md`: `executables`, `corroborate` (for collision-prone names), `root` (relative to the home), `nexus_entries`, and for Nexus-AI `app_paths` per OS. Create `scripts/lib/integrations/_detection.py` exposing `detect_platform(ctx, integration) -> Detection`, a frozen dataclass `(detected: bool, evidence: str, kind: str)`. Order: (1) user-forced (`ctx.forced_keys` contains the key, set in Phase 4) -> detected, evidence "named with --platforms"; (2) root check: the root is a real directory containing at least one entry that is not Nexus-Hub's -> detected; (3) PATH probe via `getattr(ctx, "which", shutil.which)`, ignoring relative PATH entries, current-directory hits, and on WSL any hit under `/mnt/<drive>/`; a collision-prone name needs its `corroborate` condition; (4) for Nexus-AI, `app_paths` existence; else not detected. An entry is Nexus-Hub's when its normalized path (resolve with strict=False, `os.path.normcase`, long-path prefix stripped, compared relative to the root) is in the union of `manifest.files_for`, `shared_for`, organization files, and `actions_for` paths for that key, or lies under a tracked directory, or matches `nexus_entries`. These are NEVER Nexus-Hub's, and count as vendor evidence: any `*.nexus-hub.bak`, and any tracked config whose first recorded action was a merge into a pre-existing file (`updated`). These are ignored entirely: OS metadata (`desktop.ini`, `.DS_Store`, `Thumbs.db`, `._*`, `$RECYCLE.BIN`) and `*.nexus-hub.tmp`. Record the absolute resolved executable path in the evidence string. Add `which: Callable[[str], Optional[str]] = shutil.which` and `forced_keys: FrozenSet[str] = frozenset()` to `InstallContext` in `scripts/lib/integrations/base.py`. Do not wire the primitive into any install path yet.

#### 1.3 -- Preserve hash history and harden the manifest

**Objective**: A not-detected install must not erase the per-file hashes that `doctor` and removal compare against, and the manifest must not be lost to an interrupted write.

**Build class**: load-bearing.

**Failure modes**: Malformed or absent input: a corrupt manifest no longer raises in `cmd_install` before detection runs; it is reported once, moved aside as `install-manifest.json.corrupt-<timestamp>`, and the install proceeds with an empty manifest plus the spec fallback. Unreachable or slow dependency: none. Conflicting operations: two concurrent installs serialize on a lock file next to the manifest for the load-modify-save window; the save writes a temporary file and `os.replace`s it.

**Prompt**:
> In `scripts/lib/integrations/runner.py` (`cmd_install`, around `manifest.record_actions(key, result.files)`), keep the previous action record for a key when `result.detected is False`, instead of replacing it with an empty record. Add regressions to `tests/integrations/test_detection.py`: install with the tool present, install again with it absent, assert `actions_for(key)` still holds the original per-file hashes; and a corrupt-manifest install that completes with one warning.
