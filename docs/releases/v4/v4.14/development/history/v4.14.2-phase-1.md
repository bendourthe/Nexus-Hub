## Plan delta

**Delta, non-blocking.**

- **Control baseline**: refactor-first and enumerate-every-copy each passed 0 of 12. Every run added the feature beside the three copies without a refactor edit. Under Resolved decision 8, each rule is CHANGED only when the treatment passes at least 4 of 12. Consequence: Phase 5 needs no recomputation; the bar is 4 treatment passes per rule.
- **Permissions shape the behavior**: the frozen permission set allows only `python -m pytest`. Two control runs had a non-suite command denied, and only 5 of 12 ran the exact suite command the grader counts. Both arms share these permissions, so the comparison stays fair. Consequence for Phase 2: the refactor-first text must name the suite run as the proof step, because the agent otherwise often runs none.
- **Instrument fix**: the first paid run exposed a normalizer gap (a denied call has no post hook). The fix and its regression tests came first, and that run is excluded rather than re-normalized, so every counted run used one instrument.
- **Gap deferrability**: DF-17 cannot use the `File <scope> as a known gap` template because this plan predates it. Recognizing it needs the recorded follow-on rule in pull request 507 plus a runtime re-adoption, which the maintainer chose on 2026-10-21. Consequence: Phase 5's NO_CHANGE gap, if any, uses the same recorded form.
- **OpenAI cache guide**: the 2026-10-20 raw text documents cache-write tokens (`input_tokens_details.cache_write_tokens`, split by lifetime) and explicit breakpoints on GPT-5.6 and later. `input_tokens` is still the total, with cached reads and writes as disjoint subsets. Consequence for Phase 3: the helper premise holds, and the step-8 section must state that writes are a separate subset, quoting only lines verified against the raw page.
