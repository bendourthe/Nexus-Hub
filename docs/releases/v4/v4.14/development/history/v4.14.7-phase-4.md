## Sub-tasks

- **4.1 (T024 to T026)**: both installers pass `--forced <key>` on their global runner call when the user gave `--platforms` / `-Platforms` (`$script:PlatformsExplicit` in PowerShell, `PLATFORMS_ARG` in bash). `runner.py install` accepts `--forced`, keeps only keys in the same run (`_forced_keys`), sets `InstallContext.forced_keys`, and records a forced platform in the manifest when it installs and carries a detection spec. `runner.py teardown` clears the mark for every platform it removes.
- **4.2 (T027)**: `WriteResult` gains `evidence`; the seven gated integrations pass it to `mark_not_detected`. The runner summary adds `evidence` and a one-line `remedy` for a not-detected platform. The bash installer reads them in `render_platform_from_summary`; the PowerShell installer in the new `Resolve-UndetectedReason` (the reason logic moved out of `Invoke-RegistryPlatform` unchanged so both installers can be tested on the same footing). `tests/installer/test_detection_messages.py` extracts the functions from the real installers and asserts identical output for one summary.
- **4.3 (T028)**: [`v4.14.7-release-notes-draft.md`](../v4.14.7-release-notes-draft.md) holds the "Platform detection changed" entry and the capability usage note for forcing; `docs/policy/platform-detection.md` gains "Forcing and Install Output".

## Plan Delta

**Disposition: Incomplete (non-blocking).**

Evidence: the plan assumed an existing `nexus-hub uninstall --platforms <key>` would serve as the rollback for forcing. No such user command exists (only `runner.py teardown`). Teardown now clears the forced mark, and the user-facing rollback becomes an unforce option on the Phase 5 removal command. Hermes and Pi have no block in either installer (they are reached through the runner only), so the installer-side change covers OpenCode, Aider, Kimi, Qwen, and Nexus-AI.

Consequence for remaining phases: Phase 5's command must offer the unforce option, and the release-note draft's rollback row is finalized there.
