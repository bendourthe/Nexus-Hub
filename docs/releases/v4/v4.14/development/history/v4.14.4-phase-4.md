## Implementation

The decision record ([opt-in bypass-flag guard](../../../../../decisions/proposed/tooling/2026-10-14-opt-in-git-bypass-flag-guard.md)) fixes the switch (`~/.nexus-hub/guardrails.json`, key `block_git_bypass_flags`, read on every run, `NEXUS_GUARD_GIT_BYPASS` override read only from the hook environment), one table of blocked and allowed forms, the stripping and scanning rules, the limits, and the single `Bash|PowerShell` registration. Both `git-guardrails.sh` and `git-guardrails.ps1` gained a dedicated block after every existing block, with the limits list in both headers. It strips quoted `-m`/`--message`/`-F`/`--file` values and file-writing heredoc bodies, keeps heredoc bodies fed to an interpreter, joins line continuations, splits segments, and matches git global options before the subcommand, `--no-verify` and `--no-gpg-sign` prefixes, `-n` as a commit option (stopping at argument-taking letters), and inline or persisted `gpgsign=false` in any letter case. A missing or malformed file means off (one warning naming the file for a malformed one). The nice-to-have also landed: the `core.hooksPath` and `core.fsmonitor` checks now match in any letter case, in both languages.

Three defects found while proving parity were fixed in the same change. (1) Without jq, the `.sh` cut the command at the first escaped double quote, so anything after quoted text was never scanned, including the existing destructive-command blocks; the extraction now accepts escaped characters, and a mode-independent regression test covers it. (2) In Windows PowerShell 5.1, `-is [pscustomobject]` is true for any value (scalar, array), so the new file check uses the concrete type. (3) A quoted inline value (`-c commit.gpgsign="false"`) escaped the first draft of the pattern in both languages. The `guides/reference/CLAUDE_CODE_SETTINGS_REFERENCE.md` guide gained a short section on the PowerShell-tool coverage and the opt-in mode.

T013 (the `catalog/hooks/settings.json` registration) is a protected path, so it is delivered as a patch, not an edit. The change is one line: the git-guardrails entry's matcher `Bash` becomes `Bash|PowerShell`, the form `console-window-guard` already uses. `.agents/hooks.json` is the Antigravity project hook file (matcher `run_command`); it does not mirror settings.json matchers and needs no change.
