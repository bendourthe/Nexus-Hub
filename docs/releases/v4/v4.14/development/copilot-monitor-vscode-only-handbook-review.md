# Distribution Handbook Copilot Monitor Host Verification

**Covers**: why the distribution handbook needs no content change when the Copilot Usage Monitor becomes VS Code only, and the evidence behind refreshing the two installer input digests.

Both installers change in the same three places. The Copilot monitor's install call drops Cursor as its second host (`"$cursor_cli" "$cursor_label"` in `scripts/installer.sh`, `-AlsoCodeCli $cursorCli -AlsoCodeLabel $cursorLabel` in `scripts/installer.ps1`). The legacy-extension sweep adds `nexus-hub.copilot-usage-monitor` to its removal list for the Cursor host only, so copies older installers left in Cursor are uninstalled while the VS Code copy stays. The extension banner and vendor comments now say Claude, Codex, and Copilot install into VS Code only. Each installer gains three lines in the sweep, and the eleven `data-src` installer citations in `guides/website/nexus-hub-guide.html` after that point were remapped through a line-exact diff; no citation pointed at an edited line.

The handbook explains distribution, settings ownership, attributed identity, and verification boundaries. It makes no claim about usage-monitor extensions or which editor receives them (`git grep -n -i -E 'usage monitor|second host|--install-extension' -- docs/handbooks` returns nothing), so no handbook text or rendered output changes. Only the two installer input digests in `docs/handbooks/_sources/distribution/evidence.json` are refreshed, and this record becomes the content check's evidence. No new browser run is claimed; the existing rendered evidence still applies because the handbook output is unchanged.
