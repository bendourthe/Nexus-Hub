# v4.14.0 Strict Counter Proposal

Both installers can report the selected strict overlay as current while all 34 shipped rules are missing. This proposal corrects the two strict merge functions. It is not applied. Blocker 2's approved case-sensitive PowerShell repair is already applied and remains separate.

## Problem

An existing deny list containing 23 copies of one user entry and an ask list containing 13 copies of another makes the old length-difference counter report zero. Deduplication cancels the 22 missing deny and 12 missing ask entries, so the installer skips the actual write. Both original native helper controls fail the rule-presence assertion. The source reader and hook corrections are already applied and passed 394 affected tests with 10 skips on Windows PowerShell 5.1 and 226 tests on PowerShell 7.6.7; those results do not cover this proposed permission change.

## Exact change

The [PowerShell patch](v4.14.0-phase-7-receipts/strict-counter-proposal/installer-ps1.diff) changes one counter line to count entries absent from the original list. The [Bash patch](v4.14.0-phase-7-receipts/strict-counter-proposal/installer-sh.diff) changes only merge_strict_permissions: count missing entries, validate the two document shapes and refuse invalid data before backup or write. Positional jq inputs retain Unicode filename support; source filename tags require exactly one JSON document from each file, preventing an empty settings file and a multi-document overlay from being confused. Both count and merge retain that file-role check.

No shipped rule, allow list, strict flag, default, workflow, secret or dependency changes. The existing 22 deny and 12 ask entries, messages and backup behavior remain. The [scope audit](v4.14.0-phase-7-receipts/strict-counter-proposal/scope-audit.json) proves that all source outside the two strict functions is identical. Patch size: PowerShell 1 added/1 removed; Bash 29 added/10 removed.

## Verification

The final candidate passed 61 new boundary checks, 82 existing strict checks and 24 additional Unicode-path and empty-file checks. These are native helper calls using real readers/writers, Git Bash with jq 1.8.2, Windows PowerShell 5.1 and PowerShell 7.6.7. Both original duplicate-entry controls fail as expected. The independent verifier passed 23 further Bash cases on the exact final candidate. Bash syntax and warning-level ShellCheck pass. The [test patch](v4.14.0-phase-7-receipts/strict-counter-proposal/tests.diff) proposes permanent regressions; it is not yet applied or claimed as a passing tracked suite.

The cases assert all shipped rules are present, user allow/custom values survive, the backup matches original bytes, repeated valid merges preserve bytes and backup count, and already-present rules avoid rewriting user duplicates. Malformed roots, parents, lists, overlays, empty/whitespace files and multiple JSON documents refuse without a settings write, false success or backup. Unicode profile and overlay paths cover brackets, dollar signs, backticks and semicolons. Source-wide profiles, complete installers, coverage and remote CI remain pending after approval. No model calls, paid API usage or real user-profile installer writes were made by these probes.

## Decision

Applying the proposal makes an already selected strict option install its existing intended rules despite duplicate user entries. Doing nothing leaves the demonstrated omission and prevents completion. Recommendation: approve these two strict-function changes and their regression tests, then rerun the actual affected and full gates. This approval grants no additional rule, workflow or secret change. Existing publication, release and cleanup approvals remain in effect.
