# Distribution Handbook Antigravity Launcher Probe Verification

**Covers**: why the distribution handbook needs no content change when the Gemini usage monitor install chooses its Antigravity launcher by a bounded `--version` probe instead of by existence, and the evidence behind refreshing the two installer input digests.

Both installers change in the Antigravity detection block and add one helper. Detection now lists every launcher that exists, in the previous order (PATH hits `antigravity-ide` and `antigravity`, then the known install paths, with a known path skipped when a PATH hit already resolves to it). Under the GOOGLE header the helper (`select_working_launcher` in `scripts/installer.sh`, `Select-WorkingLauncher` in `scripts/installer.ps1`) runs `<launcher> --version` for each candidate in turn and uses the first that exits 0 within 30 seconds. A candidate that fails or hangs is named in a yellow note and skipped; when none works the install prints the manual `--install-extension` command and continues, as it already did. The PowerShell helper reuses `Invoke-CommandWithTimeout`, so `.cmd` launchers start with no console window and a hung one is ended with its process tree; the bash helper reuses `run_with_timeout`, which needs no GNU `timeout`. The edits add 23 lines to `scripts/installer.ps1` and 44 lines to `scripts/installer.sh`; the `data-src` installer citations in `guides/website/nexus-hub-guide.html` after them were remapped through a line-exact diff, and no citation pointed at an edited line.

The handbook explains distribution, settings ownership, attributed identity, and verification boundaries. It makes no claim about usage-monitor extensions or Antigravity launchers (`git grep -n -i -E 'antigravity|--version|launcher|usage monitor|--install-extension' -- docs/handbooks ':!docs/handbooks/distribution.html'` returns nothing), so no handbook text or rendered output changes. Only the two installer input digests in `docs/handbooks/_sources/distribution/evidence.json` are refreshed, and this record becomes the content check's evidence. No new browser run is claimed; the existing rendered evidence still applies because the handbook output is unchanged.
