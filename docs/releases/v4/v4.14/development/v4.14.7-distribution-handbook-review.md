# Distribution Handbook Review - v4.14.7

Summary: whether the distribution handbook's claims change when v4.14.7 adds platform detection, the forced-platform pass-through, and the stale-surface removal command, and the evidence behind refreshing its input digests.
Read this when: auditing the `content` check of `docs/handbooks/_sources/distribution/evidence.json`, or deciding whether the handbook should describe platform detection.
Covers: the five changed handbook inputs, the claims reviewed, the decision, the evidence refresh, and the guide citation remap.

## Changes reviewed

Five of the handbook's inputs differ from the snapshot recorded at v4.14.6:

- `scripts/lib/integrations/runner.py` (+217 lines): the `--forced` argument and its per-key record, the `prune-undetected` command (`cmd_prune_undetected`), the stale-surface report (`_report_stale`), the rule that a not-detected install keeps the platform's earlier action record, and the evidence and remedy fields in the install summary.
- `scripts/lib/integrations/aider.py`: the global install is gated on the `aider` executable (decision D9) and reports not detected otherwise.
- `scripts/nexus_hub_cli.py`: the `prune-undetected` subcommand beside develop's `settings` subcommand.
- `scripts/installer.sh` and `scripts/installer.ps1`: both pass an explicit `--platforms` / `-Platforms` choice to the runner as `--forced`, and both print the evidence line and one remedy line for each NOT DETECTED platform.

The detection primitive itself (`scripts/lib/integrations/_detection.py`) and the removal engine (`scripts/lib/integrations/_stale.py`) are not handbook inputs. The merge of develop (v4.14.3 to v4.14.6) also touched `scripts/installer.sh`, `scripts/installer.ps1`, `scripts/nexus_hub_cli.py`, and `scripts/lib/integrations/manifest.py`; those changes were reviewed when they landed (`v4.14.6-distribution-handbook-review.md`, `upgrade-feedback-handbook-review.md`) and merged without a textual conflict in either installer.

## Claims reviewed

A search of `docs/handbooks/_sources/distribution/source.md` for `detect`, `kimi`, `qwen`, `hermes`, `pi`, `opencode`, `aider`, `nexus-ai`, `--platforms`, `prune`, and `stale` finds no match, so the handbook makes no claim about which platforms the installer writes or how it decides. The statements that touch the changed code are these:

- Route section (`source.md` line 5): "The Python integration runner selects the requested platform and scope." Still true. Detection adds a check inside the runner after it selects a platform; a platform the user names with `--platforms` is installed regardless (decision D5), so the requested platform is still the selected one, and a default install selects the detected set.
- Ownership section (`source.md` line 17): owned-file writing consults the installation manifest, repairs an artifact Nexus-Hub created, and preserves a user-authored file. Still true, and the new removal command follows the same rule: it deletes only files whose recorded hash still matches, keeps every file the user changed or added, and saves the manifest once at the end so every surviving file stays tracked.
- Verification section (`source.md` line 23): inspect reported actions and installed files rather than trusting a copy. Still true; the install summary now reports a not-detected platform with its evidence instead of an empty result.

No claim in the handbook is contradicted. A sentence describing detection ("a tool that is not installed receives nothing, unless you name it") is a possible follow-on to make the handbook complete, not a correction, because the existing text states nothing false about it.
