### Seed-record format

`scripts/installer.sh` (`install_core_settings`) reads `~/.nexus-hub/core-settings-seeds.json`, a JSON object `{"schema_version": 1, "target": ".claude/settings.json", "values": {"<dotted key>": <value>}, "removed": ["<dotted key>"]}`. The maintainer's file holds `{"values": {"env.CLAUDE_CODE_SUBAGENT_MODEL": "sonnet"}, "removed": []}`. Keys are dotted strings, while the Phase 3 ownership record `~/.nexus-hub/settings-control.json` addresses keys as segment arrays, so the `owned-keys` helper must emit paths the installers can compare without splitting a model id.

## T005

### Proof-spike design

| Tool | Scratch home | Sign-in files copied | Automatic observation | Manual observation | Tool restriction |
|---|---|---|---|---|---|
| Claude Code CLI | `CLAUDE_CONFIG_DIR`, plus `HOME`, `USERPROFILE`, `APPDATA`, `LOCALAPPDATA` set to a scratch directory, scrubbed environment | none | `claude -p ... --output-format stream-json --verbose`: the `init` event carries `model`, `permissionMode`, and `apiKeySource` (must be `none`) | effort (needs a model request) | `--tools ""` and `--max-turns 1`; not `--restricted`, which ignores user, project, and local settings files |
| Claude Code VS Code panel | `code --user-data-dir <scratch>` with the extension | not applicable | none | all rows: set the keys, open a new panel conversation, read the mode indicator | not applicable |
| Codex | `CODEX_HOME` plus the same scratch `HOME` variables | none: the vendor tells you to treat `auth.json` like a password, and a copy could be refreshed in place of the real one | `codex doctor --json` reports `config.load.details.model`; `codex debug prompt-input` prints the effective `sandbox_mode` and the approval policy | `model_reasoning_effort` (needs a model request) | none needed: neither command runs a model turn |
| VS Code Copilot Chat | `code --user-data-dir <scratch>` | not applicable | none | all rows | not applicable |
| Copilot CLI | `COPILOT_HOME` | none | not available | not installed | not applicable |
| git-guardrails | scratch `HOME` holding `.nexus-hub/guardrails.json` | not applicable | hook exit code for a piped `git commit --no-verify` payload | none | the hook only reads the payload |

Why no sign-in is copied: Claude Code and Codex both report the field in question before any request is made, and a scratch home with no credentials cannot make a billable request. The harness stops the run if a probe reports a credential source other than `none`. One side effect was recorded: a single exploratory `codex exec` in a scratch home with no sign-in reached `api.openai.com` and received `401 Unauthorized`; no model ran and nothing was billed, and it is not part of the harness.

6. **Cannot remove, Claude.** `.git` and `.claude` protected paths are not listed, because the vendor page says bypass mode writes to them without a prompt.
7. **No sign-in copying.** The plan's scratch homes copy sign-in files; this phase copied none, because the observed fields need none (see T005).
