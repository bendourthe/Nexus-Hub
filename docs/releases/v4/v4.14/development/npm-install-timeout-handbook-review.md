# Distribution Handbook npm Install Timeout Verification

**Covers**: why the distribution handbook needs no content change when the usage-monitor extension build bounds its `npm install`, and the evidence behind refreshing the two installer input digests.

Both installers change in one place. The extension build's `npm install --silent` now runs through a timeout helper (`run_with_timeout` in `scripts/installer.sh`, `Invoke-CommandWithTimeout` in `scripts/installer.ps1`) with a 300-second default that `NEXUS_HUB_NPM_TIMEOUT` overrides. On a timeout the installer prints a skip line for that extension and continues, as it already did when `npm install` failed. The PowerShell helper starts its child with no console window and ends the whole process tree on a timeout. The helpers add 41 lines to each installer; the seventeen `data-src` installer citations in `guides/website/nexus-hub-guide.html` after them were remapped through a line-exact diff, and no citation pointed at an edited line.

The handbook explains distribution, settings ownership, attributed identity, and verification boundaries. It makes no claim about usage-monitor extension builds or npm (`git grep -n -i -E 'npm|usage monitor|--install-extension' -- docs/handbooks` returns nothing), so no handbook text or rendered output changes. Only the two installer input digests in `docs/handbooks/_sources/distribution/evidence.json` are refreshed, and this record becomes the content check's evidence. No new browser run is claimed; the existing rendered evidence still applies because the handbook output is unchanged.
