## Changed: Platform Detection

Nexus-Hub now writes a tool's global files only when that tool is actually installed. Kimi Code CLI, Qwen Code, Hermes, Pi, Aider, OpenCode, and Nexus AI Studio are detected by evidence the installer did not create itself: the tool's command on `PATH`, files the tool wrote in its own folder, its own data folder, or its installed application. A folder that holds only files an earlier Nexus-Hub install wrote no longer counts. Before this release, one earlier write made every later install treat the tool as present, and Nexus AI Studio, Aider, and OpenCode files were written on every machine.

- **Check**: the install output lists each skipped platform under NOT DETECTED with the reason, for example `Qwen Code (not detected: qwen not on PATH; ~/.qwen holds only Nexus-Hub files)`, followed by how to fix it.
- **Recover from a missed detection**: name the platform explicitly, for example `--platforms qwen` (`-Platforms qwen` on Windows). The choice is remembered, so later installs keep the platform.
- **Existing folders are left in place.** Folders an earlier install created for tools you do not have stay until you remove them (see the removal command in this release).

## Capability Usage Note: Forcing a Platform with `--platforms`

| Element | Value |
|---|---|
| Activation | Name the platform in `--platforms <key>` (`-Platforms <key>`) on a global install, for example `scripts/installer.sh --platforms qwen` |
| Validation | `nexus-hub doctor` lists the platform as user-forced; the install output shows its surfaces rather than a NOT DETECTED line |
| Disable or roll back | `nexus-hub prune-undetected --unforce <key>` clears the remembered choice; the next install then evaluates the platform normally |
| Authority it does not grant | It never installs the tool itself, never changes the tool's own settings beyond the seeded Nexus-Hub defaults, and never forces OpenClaw, Devin Desktop, or Copilot, which keep their own checks |
| Documentation | `docs/policy/platform-detection.md` |

## Added: `nexus-hub prune-undetected`

`nexus-hub doctor` now lists Nexus-Hub files left for tools that are not installed, and `nexus-hub prune-undetected` removes them. It previews by default; add `--yes` to remove.

## Capability Usage Note: `nexus-hub prune-undetected`

| Element | Value |
|---|---|
| Activation | `nexus-hub prune-undetected` (preview), then `nexus-hub prune-undetected --yes`; `--integrations <keys>` narrows it |
| Validation | Run it again: the platform is no longer listed, or only the files it keeps for your review are; `nexus-hub doctor` shows the same |
| Disable or roll back | Without `--yes` nothing is removed. Removed files are unchanged Nexus-Hub output, so reinstalling the platform (with the tool present, or `--platforms <key>`) restores them |
| Authority it does not grant | It never deletes a file you changed, a file you added, a settings file (it only removes Nexus-Hub's hook entries from Kimi and Qwen settings), a `*.nexus-hub.bak` backup, a link, or anything outside the platform's own folder, and it never touches a tool that is detected or that you forced |
| Documentation | `docs/policy/platform-detection.md`, section "Stale Surfaces and Removal" |
