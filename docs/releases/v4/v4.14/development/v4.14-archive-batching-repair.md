# v4.14 Archive Batching Repair

Summary: the approved maintenance repair for the v4.14 minor-close archive transaction. Covers bounded Git move batches, recovery after partial filesystem moves, unchanged transaction budgets and approval checks, qualification, publication, and delivery of the reviewed helper. Implementation and qualification are pending.

## Goal

Archive the existing v4.14 tree within the original 180-second work budget and recover a failed transaction with verified stopped writers within its original 120-second rollback budget, preserving file contents, unrelated work, archived records, and all native completion checks. An unverified writer or file ownership produces a retained-state refusal without recovery mutations.

## Current State

The repair branch is `fix/v414-archive-batching`, based on develop at `4b6c6105d`. The separate close worktree is clean at checkpoint `0df078f25`. The primary checkout's modified manifest is outside this repair's ownership.

The close tree has 820 tracked files across 144 parent directories, an existing archive destination, and an ignored `development/eval/__pycache__/grade.cpython-311.pyc`. Twenty individual Git moves against the same 9,180-entry index took 7.703 seconds; extrapolating to 820 moves gives about 316 seconds before other archive work. A journal derived only from successful commands or staged rename rows would miss that moved file.

## Design

Keep the existing whole-prefix move when its destination is absent. For an existing destination, enumerate only tracked paths, group files by the same destination parent, and pass each bounded group to Git's native multiple-source move. Preserve exact source-to-destination mapping and basename semantics; keep the single-source path for mappings that cannot share one destination directory. Bound both the number of paths and the encoded command length, including executable, repository path, separators, and quoting, so long names cannot exceed the Windows command-line limit. Use argument arrays, never a shell command string.

Use the existing owned-process context for mutating batches with the sanitized environment, hidden Windows launches, and the original remaining work budget. The context must stop and drain the owned process tree before inspecting partial results or beginning rollback. Complete the context's exit before accepting even a successful leader result. Prove compatibility on supported Windows and POSIX paths; do not silently narrow a previously supported platform because the reused owner has a stricter platform prerequisite. If process termination cannot be verified, enter a distinct retained-state outcome that bypasses every rollback mutation, including reset, identity unsealing, repaired-byte writes, filesystem compensation, index restoration, and exception-handler fallback recovery.

Windows qualification found that a Git hook's Python process and its child can run outside the private job, even when a direct installed Python executable is used. The existing direct-Python descendant regression passes, so the process owner proves only the tree it actually owns; it is not an operating-system sandbox. A launched mutating Git command that reaches its deadline therefore enters retained state after the shutdown attempt, without asserting complete writer quiescence or attempting rollback. A budget exhausted before launch can fail normally because it introduced no new writer. Tests require a started child, retained state, and no recovery mutations; they do not require every Windows installation to reproduce the same broker behavior.

Journal each attempted batch before execution, then reconcile its source and destination states even when Git fails or times out. Record filesystem moves whose source is absent and mapped destination is present, including destinations still untracked because Git never wrote its index. Preflight ownership for the complete recovery set before any reset, identity unsealing, or repaired-byte write. Ambiguous states, collisions, links outside the intended worktree, an occupied original source, or an unfamiliar replacement file enter the same retained-state outcome; no generic exception handler may fall through to Git checkout or other mutation. For an existing destination, existing archive files and ignored source files remain outside the move set. The absent-destination whole-prefix path retains its current semantics, including moving ignored contents with that prefix.

Ordinary rollback restores each written repair's original bytes, reverses only the observed filesystem moves with scoped no-overwrite checks, and then restores only the Git index with one scoped `git reset -q pre --pathspec-from-file ... --pathspec-file-nul`. The existing UTF-8 reader and atomic writer both use `newline=''`, so `Repair.original` already preserves CRLF and lone CR exactly; retain those fields and reader semantics without a new byte field or archive snapshot. The restoration set includes every mapped source and destination, not only destinations whose reference text was repaired. Reversing filesystem moves first recovers an untracked destination from a failed Git batch. Index-only recovery avoids checkout EOL or smudge transformations; a local Git probe confirms it accepts mapped paths absent from both the original and current index, preserves an unrelated literal-path neighbor, and does not change file bytes. If any filesystem compensation fails, retain state without proceeding to index reset or fallback content restoration. Keep the existing explicit pre-content recovery scope for a verified committed-result mismatch, together with signed-identity undo, commit readback, refusal semantics, clean-tree verification, and the independent rollback budget.

Filesystem compensation must refuse an original path created after preflight too. Use the native exclusive rename operation through the standard library: Windows rename, Linux `renameat2` with `RENAME_NOREPLACE`, and macOS `renamex_np` with `RENAME_EXCL`. If the platform or filesystem cannot provide that operation, retain state without falling back to an overwrite-capable rename. Qualification on this Windows host does not establish actual Linux or macOS behavior; their existing CI jobs must exercise the platform cases.

Every exact restoration pathspec uses the `:(literal)` prefix, including the existing committed-mismatch content-recovery path. A NUL-delimited pathspec file preserves filename boundaries but does not disable Git glob interpretation. A local probe confirms that an unprefixed `[ab].md` can otherwise match and remove an unrelated pre-existing `a.md`; tests must prove literal scope for both index-only and content recovery.

## Risks

- A failed Git batch can leave filesystem moves without any index rename. Reconcile attempted pairs after the owned command stops and test that exact failure with a real Windows file lock.
- A Git-hook process can be outside its launcher's private Windows job. Attempt owned-tree shutdown on timeout, retain state without recovery mutations when complete quiescence is unverified, and qualify direct-tree cleanup separately from this retained-state case.
- A bulk directory move into an existing destination could carry ignored files or pre-existing archive contents. Batch the exact tracked-file set into destination parents and leave unrelated entries untouched; preserve current whole-prefix behavior for absent destinations.
- A rollback that restores only repaired destination paths can leave untracked copies or stale staged entries. Include both sides of the complete mapped move set and prove clean recovery after partial failure.
- File replacement during recovery can make compensation destructive. Preflight the complete recovery set and retain state on ambiguous ownership or an occupied original path, bypassing every mutation and fallback. Failed compensation stops before index reset.
- Git pathspec glob interpretation can widen a scoped reset or removal despite NUL separators. Use `:(literal)` for every exact path and prove unrelated glob matches survive both recovery paths.
- Checkout-based ordinary rollback can change raw bytes through EOL or smudge rules. Restore captured repair bytes and filesystem locations, then reset only the index; retain explicit content recovery for verified committed mismatches.
- A lower process count alone does not prove runtime qualification. Measure the complete real CLI success and failed-transaction recovery on the Windows host before installing the helper.
