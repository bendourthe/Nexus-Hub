# Distribution Handbook Claim Review - Completion Gate Default Removal

**Covers**: why the distribution handbook needs no content change when the completion gate's turn-end registration leaves the default install, and the evidence behind refreshing its input digests for `scripts/installer.sh`, `scripts/installer.ps1`, and `scripts/lib/integrations/cursor.py`.

The change removes the `completion-gate` handler from the `Stop` registration in `catalog/hooks/settings.json` and from the Cursor and Antigravity hook renderers, makes the OpenCode, OpenClaw, Pi, and Hermes plugins opt-in, and adds one retirement step to the Claude settings reconciliation in both installers. In `scripts/installer.sh` and `scripts/installer.ps1` the only additions are the retirement helpers (`retired`, `drop_retired`, `retire_hooks` in the jq program, `retire_hooks` in the Python fallback, `Test-RetiredManagedHook` and `Remove-RetiredManagedHooks` in PowerShell) and the call that applies them after the existing add-only merge. In `scripts/lib/integrations/cursor.py` the change drops one `stop` entry and one curated script name.

The handbook explains distribution, settings ownership, attributed identity, and verification boundaries. Its ownership claims remain true after the change: an owned artifact can be repaired or retired by Nexus-Hub, and a file or entry authored by the user is preserved. The retirement matches only a handler whose command points at `.../hooks/completion-gate.sh` or `.../hooks/completion-gate.ps1` (the Nexus-Hub hooks directory), and the installer tests keep a user's own `completion-gate.sh` elsewhere, a user Stop handler in the same group, and unrelated settings. No sentence in `docs/handbooks/_sources/distribution/source.md` or its composition fragments names the completion gate, the Stop event, or hook removal, so no handbook text or rendered output changes.

Only the three input digests in `docs/handbooks/_sources/distribution/evidence.json` are refreshed, and this record becomes the content check's evidence. No new browser run is claimed because the handbook output is unchanged.
