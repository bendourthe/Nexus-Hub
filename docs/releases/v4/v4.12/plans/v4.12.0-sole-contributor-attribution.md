# Plan -- Sole GitHub Contributor Attribution

**Project**: Nexus-Hub
**Version**: v4.12.0
**Slug**: sole-contributor-attribution
**Filename**: `v4.12.0-sole-contributor-attribution.md`
**Plan Type**: Feature / Enhancement (repository attribution and maintainer-only prevention)
**Created**: 2026-09-06
**Goal**: After GitHub refreshes, both the Code tab contributor list and Insights > Contributors (all time, default branch, excluding merges) show exactly one account, `bendourthe`, every historical ref has been rewritten to `Ben Dourthe <50595044+bendourthe@users.noreply.github.com>`, and new commits whose author, committer, or trailer maps to `cursoragent` or the old `benjamin-dourthe` identity cannot land.

## Overview

GitHub maps commit author emails and `Co-authored-by` trailers to accounts. A `.mailmap` file does not change the Code tab or Insights. `cursoragent` commits cannot be claimed by adding an email to `bendourthe`, because that identity belongs to Cursor. `benjamin-dourthe` is a second GitHub account for the same person. The only way both public surfaces show a single contributor is to rewrite every ref and force-push.

This plan is repository operations plus a maintainer-only gate. It does not add a catalog skill, a catalog hook, an installer copy step, an MCP entry, or a runtime dependency. `git-filter-repo` is an operator tool for the rewrite session, not a pinned project dependency. The checker script is `DEV_ONLY_SCRIPTS` so the installer never copies it to `~/.nexus-hub/scripts/`.

**Goals First.** Target problem: visitors see extra GitHub identities as Nexus-Hub contributors. Persona: the owner, plus anyone judging the repo from the Code tab or Insights. Definition of done: those two GitHub surfaces show only `bendourthe`; a full-history scan of every ref finds no forbidden author, committer, or trailer; CI and a local non-catalog hook reject new forbidden identities.

**Resolved interview.** Rewrite all branches and all tags. Target identity is `Ben Dourthe <50595044+bendourthe@users.noreply.github.com>`. Strip `Co-authored-by` and `Made-with` trailers that GitHub maps to `cursoragent`. Prevention is a CI reject plus a local `.githooks/` hook, never `catalog/hooks/`. Open pull requests keep their branch names and are force-updated in place (the unanswered PR question, closed as the recommended default when the repo was declared ready). GitHub-signed merge commits will show as unverified after rewrite; GitHub's own committer `GitHub <noreply@github.com>` is allowlisted and not rewritten.

**Publication deviation.** A normal integration pull request cannot rewrite `main` history, so it cannot satisfy the Goal. Phase 4 publication is an explicit, approved force-push of every rewritten ref, including `main`, `develop`, other branches, and tags. Feature commits for the checker and CI ride on the rewritten history and go out in that same force-push. The first remote CI run is that rewritten tree.

**Sequencing.** Phase 1 ships the checker and fixture tests without scanning this repository's live history, because that scan must fail today. Phase 2 rewrites a mirror, then the working refs, until the live scan is clean. Phase 3 turns the live scan on in `make validate` and CI, using a full-history checkout so a shallow clone cannot pass vacuously. Phase 4 reconciles the tree and force-pushes.

**Prior known-gaps ingest.** Open v4.4 `DF-1` (vendor marks) and v4.8 ledger-condition work are unrelated and stay with their owners. No `STRATEGY.md` or `docs/solutions/` store exists.

**What this plan does not do.** It does not squash-merge as the prevention mechanism. It does not ship attribution stripping to Nexus-Hub users. It does not add a sixth required status-check context; the live scan runs inside the existing unconditional `validate` job so `ci-required` wiring does not grow.
