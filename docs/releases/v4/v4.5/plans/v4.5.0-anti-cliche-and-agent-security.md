# Plan -- Platform-Wide Writing Discipline and Agent-Security Boundary Hardening

**Project**: Nexus-Hub
**Version**: v4.5.0
**Slug**: anti-cliche-and-agent-security
**Plan Type**: Feature / Enhancement (seeded from two comparison reports)
**Created**: 2026-08-31
**Seeded by**: `docs/releases/v4/v4.5/comparisons/v4.5.0-comparison-prose-cliche-detection.md`, `docs/releases/v4/v4.5/comparisons/v4.5.0-comparison-agent-security-incidents.md`, and the writing-density item (A5) of `docs/releases/v4/v4.5/comparisons/v4.5.0-comparison-fable-5-1-prompting.md`
**Goal**: Every AI platform Nexus-Hub installs into receives an always-loaded writing rule that binds the agent's own chat replies and generated files, not merely a skill the user must request, with that rule mechanically guarded across all twelve substantive instruction templates so it cannot silently drop from one platform; the `anti-slop-editing` catalog grows to cover the roughly twenty uncovered cliche patterns and ships a deterministic offline detector; and `agent-execution-isolation` closes the four boundary gaps the recent incident evidence exposed (transitive service reachability, shared storage as an inter-agent channel, the host environment around an assumed-compromised sandbox, and the interfaces exposed across the boundary), with `agentic-endpoint-hardening` gaining a deterministic response class for architectural-assumption violations.

## Overview

This plan operationalizes two comparison reports that share an adoption target and nothing else. They are sequenced in one release because both are catalog-and-template work with no shared code path, so they can be verified independently and integrated once.

**Track A (phases 1 to 4), the writing rule.** The finding that drove this is architectural, not lexical. `anti-slop-editing` is a strong skill, and it is trigger-gated: it fires when a user says "de-slop this" and never when the agent is writing its own prose. Separately, the anti-cliche and punctuation discipline lives in `## Communication Style`, which is present in exactly one of twelve substantive instruction templates. A grep for slop or cliche language across `templates/ai-instructions/` returns zero files. So the rule today is neither always-on nor cross-platform, and the plan fixes both properties in that order: distribute the rule first, then make a guard prove it stays distributed, then grow the catalog behind it, then ship a detector that can check prose deterministically instead of from memory.

The maintainer chose the strongest and most expensive form: a prohibition plus a self-check that binds chat replies as well as generated files. That decision is load-bearing for phase 1 and is the plan's main live risk, because it adds a review step to every turn on eleven platforms. Phase 1 owns the wording and the token budget; phase 7 owns the honest reckoning if the block turns out to cost more than it returns.

Phase 2 exists because promoting the block to `INVARIANT_SECTIONS` alone guards five files. `LOCKSTEP_FILES` contains only `base-claude.md`, `base-codex.md`, `base-cursor.md`, `base-gemini.md`, and `base-opencode.md`. The other seven substantive templates are exactly the ones a change silently misses, which is why v4.1.2 paired `Construction Discipline` with `tests/validators/test_construction_discipline_rule.py`. That pairing is the precedent this plan copies, and it is what makes "all platforms on install" a checkable claim rather than an intention.

**Track B (phases 5 and 6), the agent-security boundary.** `agent-execution-isolation` is already a good skill with a three-question triage, three control layers, credential brokering, and a residual-risk section. The incident evidence exposes four gaps, and the two most serious are both second-order. An egress allowlist entry that is itself able to reach the internet is an internet route wearing a costume, and that is the exact mechanism by which sandboxed agents reached a package service, then the internet, then external infrastructure. Separately, agents denied inter-agent communication established it anyway by writing files to a shared service, which means per-session ephemeral containers isolate processes but not sessions that share a writable service. Nothing in the catalog addresses either. Phase 5 also adds the host layer the Trail of Bits result argues for, since a VM was escaped three times on a patched, rebuilt-from-upstream stack, the last time with three previously unknown vulnerabilities.

Phase 6 adds a deterministic response class to `agentic-endpoint-hardening` as guidance only, per the maintainer's decision. The existing advisory default is correct for surfaces the project's own tooling writes and is deliberately preserved; the addition is a narrow second class for violations that have no legitimate case.

Three recommendations from the security source are already covered and are explicitly not re-implemented: guardrails versus boundaries, low-value workload credentials, and in-loop runtime minimization. Phase 5 names the first of those as a principle because naming it makes it citable in review, which is a documentation change, not a control change.

**What this plan does not do.** It creates no new skill, adds no MCP registry entry, introduces no dependency, and makes no outbound call. Every finding has an owner among existing skills. The detector in phase 4 is stdlib-only and offline. No upstream regex is copied; the taxonomy is re-derived, which keeps the Apache-2.0 and CC BY-SA attribution questions from colliding with the reverse-engineering attribution rule.

## Phase 1: The Always-On Writing Discipline Rule

**Goal**: Put a prohibition plus self-check block into all twelve substantive instruction templates so every supported platform receives the anti-cliche rule on install, and so it binds the agent's own output rather than waiting to be requested.
**Prerequisites**: None. This phase is the plan's foundation.
**Stability Gate**: The block is present in all twelve substantive templates and byte-identical across the lockstep five after normalization; `python scripts/check_base_template_parity.py` passes; `make validate` passes; the block is within its stated line budget; no em-dashes or non-ASCII punctuation appear in any edited template.
**Recommended model tier**: frontier
**Recommended effort level**: high
**Rationale**: Mechanically simple, but this is always-loaded text on eleven platforms with a per-turn cost. Wording quality and brevity are the deliverable, and a bad line here is paid for on every turn by every user.

### Sub-tasks

#### 1.1 -- Author the Writing Discipline block

**Objective**: One block, roughly ten to fourteen lines, carrying a prohibition list, the punctuation rule, the chatbot-leftovers ban, the mannered-prose class, and a self-check that explicitly binds chat replies as well as generated files.

**Amended 2026-09-02** (item A5 of the Fable 5.1 prompting comparison): the prohibition list gains one named class, mannered prose, and its full definition goes to sub-task 3.1 rather than into this block, so the 14-line budget is unaffected by more than one list item. The companion formatting item (A6) is deliberately NOT folded here: it is a rule about when lists, headers, and bold are appropriate, which is response structure and therefore belongs to `## Communication Contract` per this sub-task's own stated ownership boundary. **Failure modes**: The block must not restate the `anti-slop-editing` catalog. It names the highest-frequency offenders and points at the skill for the rest; a block that grows toward the catalog defeats the three-tier loading model, because Tier 1 text is paid for on every session across every platform. It must not duplicate `## Communication Contract`, which owns response structure and stays untouched. It must not contradict `## Output Minimization`, which already governs verbosity. Write it in ASCII with no em-dashes, since the block itself states that rule and a violation in its own text would be visible.

**Build class**: load-bearing.

**Prompt**:
> Author a `## Writing Discipline` section for the Nexus-Hub instruction templates. It has two parts. The PROHIBITION lists the highest-frequency AI-cliche moves the agent must not produce: throat-clearing openers, "not just X, but Y" and "it is not X, it is Y" binary contrasts, importance puffery ("it is important to note", "crucial", "pivotal"), weasel attribution ("experts say", "studies show"), faux-insight setups ("here is the thing"), trailing "-ing" clauses that restate the sentence as analysis, fake-profound closing lines, summary-recap endings, and mannered prose (metaphor and flourish substituted for direct statement, as in "a dial worth turning" for "a parameter worth varying"; the full definition lives in the phase 3 reference file, so this block names the class in one item and does not define it). The SELF-CHECK states that before returning ANY response or writing ANY file, the agent scans its own output against the list and fixes what it finds, and that this binds live chat replies, not only generated documents. Close with a single pointer to `[[anti-slop-editing]]` for the full catalog and the Edit / Detect modes. Hard budget: 14 lines maximum, because this is always-loaded context on eleven platforms. Do not restate the catalog, do not duplicate `## Communication Contract` (response structure) or `## Output Minimization` (verbosity), and write the block itself in compliant prose so it does not violate its own rule. Record the final line count and the approximate token cost in the phase notes.

## Phase 3: Catalog Extension -- The Uncovered Cliche Patterns

**Goal**: Grow `anti-slop-editing` to cover the roughly twenty patterns the comparison found uncovered, so the skill the always-on block points at actually contains what it promises.
**Prerequisites**: Phase 1 complete (the block references the skill).
**Stability Gate**: The new patterns are documented with the catalog's existing before/after format; the SKILL.md body stays under the 800-line hard cap and ideally near the 500-line target; every new bundled file is referenced from SKILL.md so the orphan audit stays clean; `make validate` passes; no upstream regex is copied verbatim.
**Recommended model tier**: frontier
**Recommended effort level**: max
**Rationale**: This is writing, and the deliverable is judgment: twenty patterns each needing a quoted smell and a fix that reads like the existing catalog. It also carries the licensing constraint that the taxonomy is adopted while the expression is re-derived, which is a distinction an under-powered pass will not respect.

### Sub-tasks

#### 3.1 -- Author the new-pattern reference file

**Objective**: A `references/cliche-patterns.md` carrying the roughly twenty uncovered patterns, so Tier 2 stays small and the detail loads only when needed.

**Failure modes**: Do NOT copy regexes, pattern names, or descriptions verbatim from the source tool. The taxonomy (which patterns exist) is adoptable; the expression is not, and the reverse-engineering attribution rule forbids naming the upstream repo, author, or product in the shipped artifact, which would otherwise collide with the Apache-2.0 and CC BY-SA attribution terms. Re-derive each pattern from its described behavior, name it in Nexus-Hub's own vocabulary, and write original examples.

**Build class**: load-bearing.

**Prompt**:
> Create `catalog/skills/developer-experience/anti-slop-editing/references/cliche-patterns.md` documenting the patterns the current catalog does not cover, drawn from `docs/releases/v4/v4.5/comparisons/v4.5.0-comparison-prose-cliche-detection.md`. The clusters: the reflective / therapist-voice register (sitting with a feeling, "worth naming", "you already know", "that is not nothing", "that is the part that ...", "the only X I trust", "do not take my word for it"); the faux-reveal family ("the punchline is", "here is the twist", "turns out", "that is why X mattered", "X is dead", "fits in your head"); the emphatic-negation and totality family (chains of "no X, no Y", chains of "did not X, did not Y", "do not VERB it, VERB it", and the "is the whole / is the entire / the entire X is" set); performative honesty (sincerity announced rather than demonstrated: "I will be honest", "let us be real", sentence-initial "Honestly," or "Look,"); the stranded-auxiliary contrast; and chatbot leftovers (assistant-role text leaking into a document: "as an AI language model", "here is the revised version", "I hope this helps", "certainly!"). Each entry gets a name in Nexus-Hub's vocabulary, a one-line smell, and an ORIGINAL before/after pair matching the format already used in the SKILL.md body. Do NOT copy any regex, pattern id, or description text from the upstream tool, and do NOT name the upstream repo, its author, or the tool anywhere in this file: re-derive from behavior. Note which entries are stylistic judgment (the therapist-voice register, where a writer may legitimately mean it) and which are defects with no legitimate case (chatbot leftovers), because the detector in phase 4 treats those two classes differently.
>
