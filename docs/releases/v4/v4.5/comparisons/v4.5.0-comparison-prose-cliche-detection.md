## What the source is

A single-page tool that highlights 38 machine-checkable "this reads as LLM output" patterns in pasted prose. Each pattern is a named detector with an id, a human description, and a finder function (a regex, a chain counter, or a structural run detector). The detectors split into two groups.

- 27 observed-in-the-wild patterns covering the 2025-26 "therapist-voice / LinkedIn-essay" register: `sit-with`, `worth-naming`, `not-nothing`, `already-know`, `punchline`, `heres-the-twist`, `thats-the-part`, `the-only-i-trust`, `take-my-word`, `turns-out`, `fits-in-your-head`, `x-is-dead`, `thats-why-mattered`, `stranded-auxiliary`, `dont-verb-it`, `performative-honesty`, the `is-the-whole` / `is-the-entire` / `the-entire-is` family, the `no-chain` and `did-not-chain` list forms, `colon-triple`, `stacked-questions`, `sentence-anaphora`, and `echo-triad`.
- 11 patterns adapted from Wikipedia's "Signs of AI writing" guide: `ai-vocab`, `not-just`, `note-that`, `testament`, `crucial-role`, `landscape`, `vague-experts`, `despite-challenges`, `participle-tail`, `promo`, and `ai-leftovers`.

Three of the detectors are structural rather than lexical, which matters: `echo-triad` (consecutive sentences sharing a 4-gram skeleton), `sentence-anaphora` (consecutive sentences opening on the same non-function word), and `stacked-questions` (runs of consecutive rhetorical questions). These catch rhythm, which a wordlist cannot.

## Gap analysis

### G1. The rule does not govern the agent's own output (structural, highest value)

`anti-slop-editing` is trigger-gated. Its `description` fires on "de-slop this", "make it less AI-sounding", "does this read as AI". It is an editing service the user requests for a draft they hand over.

The user's requirement is different: no AI cliche in **any** writing the agent produces, including generated documents and ordinary chat replies. Nothing in the harness currently enforces that. An agent answering a question, writing a README, or drafting a CHANGELOG never loads this skill, so none of the 20 named patterns apply to its own prose. The skill's own body half-acknowledges this ("A draft the agent itself produced needs a final pass to strip its own tells before it ships"), but a final pass the agent must remember to request is not a control.

This is the difference between a linter you can run and a lint rule that is always on.

### G2. The always-loaded surface reaches only one platform (distribution)

The anti-cliche and punctuation discipline lives in `## Communication Style`, which exists in exactly one of the twelve substantive instruction templates: `templates/ai-instructions/base-claude.md`.

Verified across the template set:

- `## Communication Contract` is present in 11 substantive templates (aider, claude, codex, cursor, gemini, google-shared, kimi, openclaw, opencode, qwen, windsurf) plus `generic-instructions.md`. It governs response *structure*: outcome first, runnable commands, numbered steps, the Completed / Verified / Open / Next close, the waiting-state banner. It says nothing about cliche.
- `## Communication Style` (logical punctuation, no em-dashes, professional teaching tone, no hard-wrapping) is present in `base-claude.md` only.
- `grep -lniE "slop|cliche|AI-sounding|filler"` across `templates/ai-instructions/` returns **zero files**.

So the direct answer to "can we make sure this applies across all platforms upon installing the latest release?" is: today it does not, and the punctuation half of the rule reaches Claude Code alone. A Codex, Cursor, Gemini, OpenCode, Qwen, Kimi, Windsurf, OpenClaw, Aider, or Antigravity user who installs the current release receives no anti-cliche guidance at all.

`## Communication Style` is not on the invariant-block list in `AGENTS.md` (Tech Stack, Key Commands, Branching, End-of-Task Summary, MCP Registry Policy), so `check_base_template_parity.py` does not currently catch this divergence. The rule is platform-agnostic by intent, which is the same argument that made `End-of-Task Summary` an invariant block in v3.15.10.

### G3. No deterministic detector (tooling)

`hallmark-design` ships `scripts/detect_visual_defects.py` for the visual "looks AI-generated" failure mode. There is no prose equivalent. Every anti-slop judgment today is the model grading its own prose from memory, which is exactly the situation the source tool exists to fix. Thirty-four of the 38 detectors are plain regex or short structural passes and port cleanly to a local Python script with no dependencies.

### G4. Roughly 20 uncovered named patterns (content)

Listed in the overlap table above. The therapist-voice register and `ai-leftovers` are the two clusters most worth adding, and `ai-leftovers` is the one with a genuine safety edge: "here is the revised version" or "as an AI language model" leaking into a shipped document is a visible defect, not a matter of taste.

## Reverse-engineering assessment (MCP Registry Policy decision tree)

- **Tier 1 (local-only)**: not applicable, no MCP server involved.
- **Tier 2 (LLM-native skill)**: **this is the correct bucket for the taxonomy.** The 38 patterns are knowledge, and knowledge belongs in `SKILL.md` plus a `references/` file, not in a server. Adopt here.
- **Tier 3 (reverse-engineer into a local internal component)**: **the correct bucket for the detector.** Re-derive the checks as `catalog/skills/developer-experience/anti-slop-editing/scripts/detect_prose_cliches.py`, an offline stdlib-only script, following the existing `detect_visual_defects.py` precedent. Bundled skill scripts execute without their source entering the context window, so a 300-line detector costs zero tokens until it runs.
- **Tier 4 (trusted vendor wrapper)**: not applicable.
- **Tier 5 (drop)**: not applicable.

**Attribution and licensing.** The upstream repository is Apache-2.0, which permits reuse with attribution. Nexus-Hub's reverse-engineering attribution rule forbids naming the external repo or product in the distributed artifact. These two constraints only conflict if we copy expression. Resolution: **do not copy the regexes.** Adopt the pattern taxonomy (ideas and facts, not copyrightable) and write independent detectors from the described behavior. Record the upstream source in the reverse-engineering matrix row's Rationale column, where attribution belongs. The Wikipedia-derived group is CC BY-SA, which reinforces the same conclusion: re-derive, do not lift.

Do **not** name the upstream tool, its author, or its repo in `SKILL.md`, in the references file, or in the script.

## Prioritized adoption plan

Ordered by value per unit of risk. Items 1 and 2 answer the user's question directly; 3 and 4 make the answer verifiable.

### P0 - Make the anti-cliche rule always-on and platform-wide

1. Add a compact `## Writing Discipline` block (or extend `## Communication Contract`) to all 12 substantive instruction templates in lockstep: the five machine-guarded files (claude, codex, cursor, gemini, opencode) plus `base-google-shared.md`, the five guardrails-only files (aider, kimi, openclaw, qwen, windsurf), and `generic-instructions.md`. Keep it to roughly 6 to 10 lines, because this is always-loaded context on every platform. Name the highest-frequency offenders, point at `anti-slop-editing` for the full catalog, and state that the rule binds chat replies as well as generated files.
2. Promote the block to an **invariant block** in `scripts/check_base_template_parity.py` and record it in `AGENTS.md`, so a future edit cannot silently drop it from one platform. This is the mechanism that makes "applies across all platforms upon installing the latest release" true rather than aspirational.
3. Reconcile `## Communication Style` (currently Claude-only) into the shared block so the punctuation discipline stops being a single-platform rule.

**Risk**: token cost on every session across every platform. Mitigation: hard-cap the block and keep the long catalog in the skill, where it loads only on trigger.

### P1 - Extend the pattern catalog

Add the roughly 20 uncovered patterns to `anti-slop-editing`. Put the therapist-voice register and `ai-leftovers` in the body catalog with before/after fixes matching the existing format; push the long-tail lexical variants into `references/slop-wordlist.md`. Add the three structural detectors (echo runs, sentence anaphora, stacked questions) as countable rules rather than prose descriptions.

Watch the 800-line hard cap on the SKILL.md body. At 279 lines there is room, but a naive paste of 20 patterns with examples will consume most of it. Prefer a new `references/cliche-patterns.md`.

### P2 - Ship the deterministic detector

Write `scripts/detect_prose_cliches.py` under the skill: stdlib-only, reads a file or stdin, emits pattern id, line, column, and the matched span. Mirror the `detect_visual_defects.py` conventions. Bundle a `.ps1` sibling only if it is registered as a hook; a skill-bundled script needs no sibling, though the installer copies the tree recursively either way, so no installer edit is required.

Keep it advisory. A cliche detector that blocks a commit will be disabled within a week.

### P3 - Prove it

- Extend `evals/trigger-cases.json` with the new patterns.
- Add a repo test asserting the writing-discipline block is present and identical across all 12 templates (the parity guard from P0 covers this, so make it a guard test, not a duplicate).
- Add fixture prose with known cliche counts under `tests/verification/` and assert the detector's output, following the `test_visual_defect_detector.py` precedent.

### Deliberately not adopted

- The HTML UI itself. Nexus-Hub distributes skills and scripts, not web pages, and a browser tool cannot govern agent output.
- The upstream `eval()`-based self-test harness. Nexus-Hub uses pytest.
- Any verbatim regex. See the attribution note above.

## Open questions for the user

1. Should the always-on rule be a **prohibition** ("do not write these") or a **self-check** ("scan your own output before returning")? A prohibition is cheaper in tokens; a self-check catches more but adds a step to every turn.
2. Should the always-on block cover chat replies specifically, or only generated files? The request says both, which is the stronger and more expensive reading.
3. Is `## Writing Discipline` acceptable as a new invariant block, given that adding one raises the floor cost of every session on every platform?
