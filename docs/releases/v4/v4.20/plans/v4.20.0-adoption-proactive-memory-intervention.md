**Goal**: An agent diagnosing a long-session failure tries targeted reactivation of the one still-quotable item before proposing a session restart.

**Secondary outcomes** (deferrable per the cut-line, and not part of the single Goal check in T018):

- A developer building an agent finds memory-intervention architecture in Nexus-Hub's memory guidance, not storage-and-retrieval only.
- An advisory surface is bound by a stated rule that silence is a valid output and that a cheaply-routed advisor can be worse than none.

## Overview

This plan operationalizes the three recommended candidates from its seeding comparison, split into four rules (see `## Ownership decisions`), in the reverse-engineer-first order that comparison fixed. All are `skill-native`: no outbound call, no credential, no new runtime dependency, no third-party data processor.

**The deliverable is instruction text. Phase 2 carries a paired behavioral eval; Phases 3 and 4 do not, for stated reasons.** Phase 2's rule governs a diagnosis that can be posed to a model as a fixture and graded binary, exactly as the v4.19.0 plan's repair gate can, so it gets a real instrument. Phase 3 teaches an architecture with no single graded response, and Phase 4 adds a style-guide clause; neither has a comparably cheap grader, and building one would be a larger instrument than the change it measures. Those declines are per-phase and stated, not plan-wide.

**A first draft specified a trigger-eval routing probe instead, and it was unbuildable.** `scripts/run_trigger_evals.py` is a skill-description near-collision detector: it scores a probe by lexical overlap against each skill's frontmatter `description` only. No phase here edits a description, so a pre/post delta would have been zero by construction. Worse, the step runs `--gate` in the `catalog` group (`scripts/ci/profiles.py:160`), so a baseline with headroom is a misroute that turns `--profile full` red, which every phase's exit checklist requires green. The probe is removed. This is recorded because specifying an instrument from its name rather than from its implementation is the error, and it is repeatable.

**A fifth candidate is deliberately not planned.** The comparison classified a deterministic, model-free reminder hook as `re-partial` and feasible (`catalog/hooks/workflow-phase-notice.sh` is the precedent), but it is context injection, and v4.13.1 is a queued plan whose entire purpose is deciding whether an injection runtime should be built at all. That candidate stays blocked; Phase 5 records it as a known gap rather than this plan pre-empting a decision another plan owns.

**The trust-boundary constraint binds Phases 2, 3 AND 4**, not Phase 4 alone. Every one of them edits a distributed artifact. Neither installer copies the repo-root `AGENTS.md`; both in fact WRITE an `AGENTS.md` into user-controlled space (`scripts/installer.sh:1544` writes `~/.codex/AGENTS.md`, `:1954` and `scripts/installer.ps1:2093` write a repo-root `AGENTS.md` into the user's project). A distributed artifact naming that file therefore resolves, on a user's machine, against a file Nexus-Hub does not control. The ban and its assertion land in Phase 2, with the first distributed edit, and are extended by later phases rather than introduced by them.

The highest-risk phase is **Phase 4**: it edits a distributed style guide reaching every consuming project, and it must place a clause inside another plan's artifact without contradicting that artifact's own no-suppression floor.
