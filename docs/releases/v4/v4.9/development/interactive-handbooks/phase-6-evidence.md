### The failures are concentrated in measurement blindness, not in authoring effort

Both runs spent their entire correction budget on defects their tooling could see, then delivered a high-severity defect their tooling structurally cannot see. Each blind spot was confirmed by reading the checker source, not inferred from the runner's report.

- The contrast check pairs custom-property names at root scope. A nested-scope block that redefines a token inside the same rule that consumes it (`color:var(--ed-paper)` alongside `--ed-paper:#172b3b`, on an `--ed-ink` background) resolves dark-on-dark at computed-value time and scores clean. Twenty sub-AA rendered pairs reached the delivered bytes at a worst ratio of 1.0 to 1, present already in the frozen first build.
- The SVG checks are exactly `check_svg_arrowheads`, `check_svg_viewport_fit` and `check_svg_marker_integrity`. None compares text bounds against shape bounds and the module never calls `getBBox`, so edge labels painting over stage-card rectangles pass every automated gate.

Both were found only by screenshot inspection, and in both cases only after the correction budget was exhausted. This is the same failure shape the v4.4.x record describes, one layer up: the gates are now materially deeper (210 measured states, 288 alternate-state measurements across 24 states and 12 viewports, 34 factual checks, all genuinely passing) and the defect that ships is still the one nobody measured. Adding measurement depth does not address a missing measurement kind. Closing these two blind spots is T019's stated mandate to grade both views and every instance with non-vacuous checks, not new scope.

### Defects owned by committed code and contract rather than by authoring

Of the three findings first attributed to committed code or contract, one did not survive reproduction. The remaining two would recur on every future invocation regardless of how well the next runner authors.

- The reported scroll-restore defect in `assets/dual-view-runtime.js` was WITHDRAWN after direct reproduction; see `known-gaps.md` BG-2. The runtime restores correctly through the public API and through an in-page `click()`, and fails only when the entry button is driven by Playwright's `locator.click()`, which scrolls its top-of-page target into view before dispatching and therefore moves the viewport to zero BEFORE the deck opens. The runtime then correctly saves and restores zero. An intermediate note in this cycle attributed the behavior to a missing layout flush; that explanation was wrong, since `scrollTo` forces layout itself and the existing runtime test already asserts a restored scroll and passes. Only two committed-code or contract gaps survive below.
- The retained chart renderer offers no axis-limit control although `SKILL.md` requires one, which is a contract-to-implementation gap rather than an authoring miss.
- `scripts/extract_content.py` has no `.html` reader. It handles roughly seventy-five extensions including `.docx`, `.pptx`, `.pdf`, `.xlsx`, `.md`, `.csv`, images and about fifty code and configuration types, and `.html` appears once in the module and never as an input format. T020 requires exercising legacy HTML migration and the frozen repository fixture supplies `docs/handbooks/html/operations.html`, so the repository case ingested eight of nine files and disclosed the omission on the delivered page rather than concealing it.
