## Confirmed findings

### AF-1: Absent graph seeds are converted into qualified evidence (P2)

**Location**: `catalog/skills/code-review/security-review/scripts/_graph_receipt.py`, function `project` (initial validation and result construction).
**Confidence**: 100; observed failing tests.
**Input route**: The documented pure `project` boundary accepts caller-observed output and `qualified_symbol`; the supported operation in the proof is `code_context`, whose public MCP schema requires a symbol. Neither `index_graph` nor status operations are admitted by this helper, so a legitimate seedless index/status case does not explain the acceptance.
**Observed behavior**: An empty-string seed and a null seed each return a receipt with `availability="RAN"` and `qualified=true`. `symbol_id` hashes either value, hiding the absence/type error behind a syntactically valid opaque identifier; `validate` therefore cannot detect the invalid original seed.
**Proof**: `test_adversarial_absent_seed_cannot_be_qualified` in private-local evidence `AV-PROOF-01` fails for both parameter values because no `ValueError` is raised.
**Consequence**: A malformed/absent required graph seed becomes a valid-looking qualified receipt, contrary to Phase 3's explicit incomplete-inventory requirement. This finding does not assert process execution or a globally clean audit.
**Suggested fix**: Validate the qualified seed's type and required nonempty identity before hashing it or setting `qualified=true`; reject absent/malformed seed values through the stable error contract. Add focused regression cases at the producer boundary.

### AF-2: Contradictory zero-match graph evidence reaches a successful closure summary (P2)

**Location**: `catalog/skills/code-review/security-review/scripts/_graph_receipt.py`, functions `validate` and `project` (count/location consistency).
**Confidence**: 100; real closure CLI reproduction.
**Input routes**: Raw `code_context` response passed to `project`; alternatively the resulting metadata receipt supplied directly in a schema-v2 profile. Both converge on `graph.validate`.
**Observed behavior**: A synthetic raw response reporting zero matches while containing a valid node produces `GRAPH_NO_RESULT`, `result_count=0`, `quality=unknown`, and a nonempty location list. Substituting that receipt into the otherwise valid degraded record is accepted by `closure-gate.py RECORD --summary`, which exits 0 and emits the normalized envelope.
**Proof**: `test_adversarial_zero_matches_cannot_carry_node_to_closure` in private-local evidence `AV-PROOF-01` fails with observed return code 0 instead of a rejection/failed outcome.
**Consequence**: The same bound receipt claims absence and supplies positive node evidence. It can therefore carry location/symbol evidence while claiming no result, violating the non-deferrable contradictory-evidence contract. Unknown graph quality does not make contradictory metadata well-formed.
**Suggested fix**: Reject impossible zero-result/nonempty-location combinations in the shared receipt validator and validate operation-appropriate result structure before projection. Preserve legitimate matched nodes with no outgoing callees: their matched-seed count is nonzero even when traversal edges are empty.
