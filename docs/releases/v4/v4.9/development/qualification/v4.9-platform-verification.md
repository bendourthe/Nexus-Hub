## Independent maintenance findings

### P1: Copilot bypass-permission seed uses an unsupported boolean

- Location: `configs/platform-defaults.json:278`; rationale at line 286.
- Current source: `permissions.disableBypassPermissionsMode` is boolean `true`.
- Current official contract: the CLI configuration-directory table lists a string with `disable` and `allow-auto-only`; the managed-settings example also uses `disable`.
- Impact: a new installation cannot rely on the seeded boolean to suppress bypass flags under the current documented contract. This is a documentation-confirmed schema mismatch; no live Copilot rejection or fallback behavior was claimed.
- Recommended owner/action: platform-default maintenance or separately authorized release handoff should change the declaration to string `disable`, update the rationale, and verify generated/installed output. Seed-if-absent means existing user configurations need a separate migration decision; silently rewriting them is not implied.
- v4.9 disposition: pre-existing and independent. The new audit implementation does not change or depend on this provider default. The audit goal's mutation guard belongs to the review/audit contract, not this global provider setting. No change applied.
- Source: [GitHub CLI configuration reference](https://docs.github.com/en/copilot/reference/copilot-cli-reference/cli-config-dir-reference), fetched 2026-09-08.

### P2: Antigravity legacy global workflows differ from the current documented directory

- Location: `scripts/lib/integrations/antigravity.py:120`; global capability declaration also uses the legacy name at line 72.
- Current source: `~/.gemini/config/global_workflows/`.
- Current official migration table and scan instructions: `~/.gemini/config/workflows/`; workspace `.agents/workflows/` still matches. The official Workflows page documents planned migration to skills by November 1, 2026.
- Impact: the compatibility global workflow copy is not documented at its emitted location by the current migration contract. This does not prove the older directory is rejected by every installed version. Native command-skills remain an independently verified delivery path, and v4.9 adds its audit capability through skills.
- Recommended owner/action: platform-read-contract maintenance should reconcile the legacy global workflow mirror against a supported platform version, preserving native skill delivery. No broad workflow migration or removal belongs to this plan.
- v4.9 disposition: pre-existing and independent; no new audit delivery failure established. No change applied.
- Source: [Official workflow migration](https://antigravity.google/docs/migration/workflows-to-skills), fetched 2026-09-08; exact table names the two directories separately.
