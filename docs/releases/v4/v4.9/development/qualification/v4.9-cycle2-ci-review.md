## Considered but rejected

- **Long-path setup after checkout:** rejected as a finding because every affected Windows checkout is preceded by the native Git setting; a repository-local helper would be too late for checkout itself.
- **Linux/macOS executing Windows tests:** rejected because the added command explicitly runs only on the Windows host class; regression coverage tests all three host classes.
- **Interpreter gate present but unreachable:** rejected because both selected profiles contain the existing group and the workflow selection explicitly includes its name.
- **Windows test timeout exceeding the job budget:** the added command has a bounded 20-minute limit inside the existing 60-minute job. Existing commands also have individual limits, but the sum of worst-case limits does not imply actual runtime exhaustion; no measured overrun was presented or observed in this review.
- **Repeated five-line workflow setup:** retained as the smallest direct pre-checkout operation across independent jobs. Moving it into a repository action would require checkout first and defeat its purpose.
- **Exact file-list assertions duplicating implementation:** retained because the approved contract requires these particular boundary suites to be reachable on Windows. An assertion only checking a group name would allow silent loss of coverage.
- **Future matrix layouts using `include` rather than `matrix.os`:** the regression's detector covers the actual current workflow forms and explicitly requires the five affected jobs. A hypothetical future unsupported matrix shape is not a current correctness finding.
