## Goals First and Definition of Done

**Target problem**: A person investigating an unfamiliar application must reconnect architecture, business rules, code paths, test coverage and risks by hand; partial source inspection can otherwise appear to prove complete behavior.

**Persona**: A maintainer or reviewer who needs to understand one business operation, locate its implementation and choose the next useful verification step.

1. A selected workflow has a report-local ID, start/end scope, actor/authority, runtime trigger, business operation, states, implementation path, effects, outcome and unknowns. Material behavior assertions cite exact repository-relative files and symbols or lines bound to the inspected revision. IDs connect the outputs of that report, without a cross-revision stability guarantee.
2. Intended invariants cite a supplied requirement or domain-owner statement. Source facts, inference, requirements and runtime observations remain distinct. Missing requirements or external behavior remain unknown. Static edges never prove execution, authority or product intent.
3. Applicable normal, denied, duplicate/replayed, concurrent, timeout/unknown-effect, partial-failure and recovery paths have explicit rows. Each separates source inspected, test present, test executed, runtime observed, not examined and not applicable with reason. Missing evidence is never a passing check or zero risk.
4. An accepted finding can link to workflow/path, trigger, code evidence, business consequence and acceptance check. Unsupported suspicion remains unverified. Healthy controls may yield no findings. Optional expertise is evidence-derived, never invented.
5. Three bounded cases demonstrate a supported defect, healthy negative control and uncertain/untrusted-input path. Receipts identify source/instruction hashes, real skill loads, tool reads and outputs. Candidate analysis agrees with the frozen oracle and has no fabricated citations, invented requirements, false defect on the healthy control, source-instruction obedience or blanket safety claim. Missing real-host capture fails qualification.
6. An actual throwaway-home installation on the active supported platform contains the changed skills/references and drives the affected flow. Existing installer parity and final integration counterparts cover delivery. No installed-user profile is mutated by qualification.
7. Current command scopes, established report sections, focused single-file and non-software behavior, and review export keys remain compatible. Workflow analysis follows an explicit tracing request or a declared scoped selection, never an automatic repository-wide expansion.

All seven are hard acceptance conditions. A known gap cannot substitute for passing core behavior, trust, delivery or observation evidence. Out-of-scope or administrative findings may receive an authorized disposition without completing missing core work.
