# Plan -- Guide Visual and Arcade Rebuild

**Project**: Nexus-Hub
**Version**: v4.4.1
**Slug**: guide-visual-and-arcade-rebuild
**Plan Type**: Feature / Enhancement (corrective visual, teaching, and Training rebuild)
**Created**: 2026-08-31
**Goal**: Deliver a self-contained Nexus-Hub guide whose Home identity and five-platform compatibility rail are polished and accurate, whose Foundations page teaches the requested AI concepts in a compact and professionally ordered visual narrative, and whose Training page remains readable in and out of fullscreen while the eight-command walkthrough operates a deterministic arcade shooter with the requested lives bug, asteroid hazard, and vertical-movement feature.

## Overview

This corrective patch responds to direct visual review of v4.4.0. Home currently separates the brand mark from an incorrectly hyphenated hero title, uses incomplete platform treatments, and compresses the command loop into undersized one-line pills. Foundations contains accurate pieces but presents them with excessive unused space, inconsistent terminology, and diagrams whose process relationships are not obvious. Training places too much material into one viewport, lets panels overlap in fullscreen, and teaches an Asteroids scenario instead of the requested arcade-shooter debugging exercise.

The release keeps the guide's existing delivery contract: `guides/website/nexus-hub-guide.html` remains one offline HTML file with no server, build step, CDN, remote font, or runtime network call. The file is already 492,252 bytes against a strict 500,000-byte guard, while its embedded Nexus mark consumes roughly 220 KB. Phase 1 therefore replaces that payload with compact reviewed geometry, records a byte allocation for every new logo and media example, and fails closed before visual work expands the file. Platform sources may be fetched during implementation for review, but the shipped file contains only sanitized inline assets.

Foundations is rebuilt in this exact order: Tokens Definition, Prompt Engineering, Context Engineering, Models, Agentic Platform, Chatbot vs. Agentic Platform, Harnesses, and Nexus-Hub Harness. Models and Agentic Platform use one shared visual grammar so the learner can compare a provider-trained model processing a prompt and context with an agentic platform that can coordinate specialized agents, use permitted tools, modify files or documents, run terminal processes, and feed observations back into the work loop. Any reasoning animation is explicitly an abstract work-cycle illustration, not a transcript of hidden chain-of-thought.

Training preserves the eight existing command IDs and the cumulative terminal and file-explorer teaching pattern, but replaces the game contract completely. A portrait or square playfield begins behind a real `Click to start` control. The player moves left and right and fires, enemies and their shots descend, asteroids fall at seeded speeds, enemy projectiles consume three lives, and any asteroid collision destroys the player immediately. The seeded bug makes the first enemy projectile destroy the player; `/implement` fixes damage to consume one life; the follow-on feature enabled after `/compare` adds up-and-down movement without adding a ninth scene.

Execution is intentionally sequenced after v4.4.0 closes. Do not create or implement the v4.4.1 feature branch until v4.4.0 Phase 7 is complete, its integration is green and merged, its release/back-merge is complete, and a refreshed `develop` contains that result. The implementation branch is `feat/v4.4.1-guide-visual-and-arcade-rebuild`. This plan does not modify the active v4.4.0 tracker or authorize any push, pull request, merge, tag, or release.

No `STRATEGY.md` or `docs/solutions/` store exists in the current checkout, so Goals First is grounded in the user's accepted requirements, the guide's maintainer contract, the v4.4.0 implementation evidence, and the open v4.4 known gaps.

## Goals First and Definition of Done

### Target problem

The guide's visual hierarchy and teaching diagrams make a newcomer work too hard to understand Nexus-Hub, while the Training page becomes unreadable in presentation mode and demonstrates a game and defect that do not match the requested workshop exercise.

### Target personas

- **Primary - newcomer**: A reader without deep AI or software terminology who needs to understand prompts, context, models, agentic platforms, harnesses, and Nexus-Hub from the pictures as well as the prose.
- **Secondary - workshop learner**: A participant who must play, diagnose, fix, extend, test, and present the game through the existing eight-command loop.
- **Secondary - trainer or maintainer**: A presenter who needs a dense but readable fullscreen layout, deterministic demonstrations, offline delivery, and retained verification evidence.

### User stories

- **US1 - Home comprehension**: As a newcomer, I can recognize Nexus Hub and the five supported platforms, then read the workflow loop without zooming.
- **US2 - Foundations comprehension**: As a learner, I can distinguish prompt, context, model processing, agentic execution, and the Nexus-Hub harness by following one ordered visual narrative.
- **US3 - Training exercise**: As a workshop participant, I can start and control a polished shooter, observe the seeded damage bug, fix it, add vertical movement, and inspect the generated evidence without panel overlap.
- **US4 - Safe maintenance**: As a maintainer, I can prove the guide is offline, within its explicit byte budget, accessible, deterministic, responsive, and covered by fail-closed local and integration browser gates.

### Observable definition of done

- Home renders the exact title `Nexus Hub` with nav-matched typography and theme colors; the complete mark-and-wordmark lockup floats when motion is allowed; and the platform rail contains exactly Claude, ChatGPT, Gemini, Cursor, and GitHub Copilot in that order, with OpenCode and its note removed.
- The Home loop keeps its existing command sequence, puts each command on the first line and its description on the second, and remains readable without overflow at 320, 420, 900, and 1440 px in both themes.
- Foundations contains exactly the eight accepted sections in the accepted order, uses professional titles rather than `What Is` or `What Are`, visibly reduces unused space, and presents legible token, prompt, context, model, agentic, comparison, harness, and Nexus-Hub diagrams.
- The Models scene distinguishes provider training and delivery from a later user prompt plus context, shows an abstract effort-dependent work cycle, and displays accessible examples of text, image, embedded GIF/video, and audio output without runtime network access.
- The Agentic Platform scene shares the Models scene's visual language and shows specialized missions, parallel work where useful, permissions, file or document changes, terminal or process execution, verification, returned observations, and a final report using capability-qualified language such as `can`, `when supported`, and `when permitted`.
- Training begins idle behind `Click to start`; active controls are Left/Right or A/D and Space; Escape pauses and releases the game; a persistent accessible HUD visibly updates remaining lives from 3 to 2 to 1 to 0 after the fix; enemy ships, enemy shots, and intermittent asteroids enter or travel downward from the top toward the player; asteroid contact is immediately fatal with visible explosion feedback; and Up/Down or W/S change vertical position only after the follow-on feature is enabled.
- At desktop fullscreen sizes of 1280x720, 1366x768, 1440x900, and 1920x1080, the toolbar/progress, title/intent, complete game and HUD, terminal command/result summary, explorer/artifact summary, takeaway, and navigation are simultaneously visible without page-level scrolling; only long terminal or file detail may scroll in one bounded secondary evidence pane. Narrower layouts may use one intentional slide scroll surface. Every declared case has zero pairwise panel intersections and horizontal overflow, and `Full screen` with a standard four-corner icon is immediately left of Outline and remains reachable inside fullscreen.
- The canonical HTML remains one self-contained offline file. The preferred release ceiling remains 500,000 bytes after replacing the oversized mark; any proposed cap increase is a separately approved decision backed by a measured byte ledger, never an implicit test edit.
- Dark, light, keyboard-only, 200 percent zoom, reduced-motion, canvas-unavailable, offscreen, hidden-tab, hostile-fixture, and deterministic-replay cases have observable automated or last-phase human evidence. No completion claim relies only on structural scoring.
- Last-phase human testing asks representative newcomers, without maintainer coaching, to identify prompt versus context, distinguish provider training from a live request, explain the qualified relationship between higher effort and work cycles, distinguish chatbot output from permitted agentic action, and place a platform's built-in harness relative to Nexus-Hub. Answers and any comprehension gap are recorded honestly; an unavailable cohort is recorded as a known gap rather than a fabricated pass.
