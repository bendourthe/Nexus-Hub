## Sub-tasks 4.1-4.4 -- The five scenes

All five became semantic HTML node trees on the primitives Phase 3 established, replacing 41.5 KB of per-scene SVG (including a dual desktop/mobile drawing of the old model diagram). Total page delta for the phase, INCLUDING all four base64 media payloads: **+5,035 bytes**.

**Models** is two titled regions. The provider region (training then release) is strictly before the user region in DOM order, and the copy states outright that a prompt never retrains the model. The user region runs the shared entry motif (the same contract prompt plus the four context kinds), the abstract work-cycle glyph, and a four-kind output gallery: text, the approved inline image, the GIF behind an explicit Play control resting on its poster, and the audio with native controls, `preload="none"`, and a transcript-equivalent description. The effort-level sentence is qualified exactly as the plan requires: it can allocate more computation "when supported" and "does not promise a fixed number of iterations". The cycle is labelled an abstraction, not hidden chain-of-thought.

**Agentic Platform** shares the grammar by construction, not by convention: the entry motif and the work-cycle glyph are emitted by the same functions, and a test asserts the two entry blocks are byte-identical. After the shared opening, three specialized missions run as parallel lanes, every action routes through one visible permission-and-tool boundary carrying "when permitted" / "when supported" qualifiers, and observations return to the loop before a final report. A DOM-order assertion pins the execution sequence: entry, cycle, missions, boundary, observations, report.

**Chatbot vs. Agentic Platform** became the two-lane card comparison, chatbot lane first, each lane with explicit Boundary / Action / Outcome / Leaves-behind labels. The honest-copy contracts from v4.4.0 were preserved verbatim: "answer handoff", "you apply and check", "work handoff", "saved change", "check result", the chatbots-can-use-tools qualifier, "where the work happens", and "what each lane leaves behind". Neither lane is caricatured and neither promises success.

**Harnesses** and **Nexus-Hub Harness** split the old single hierarchy. `fx-harness` now teaches only the built-in platform loop (context, tools, permissions, execution, observations) with the model nested inside. `fx-practice` carries the Nexus-Hub layer with the five repository-anchored claims (`one-source-catalog`, `matched-procedures`, `event-hooks`, `written-gates`, `durable-artifacts`, each keeping its `data-artifact` anchor), the "does not replace the model or the platform runtime" scope qualifier, the hooks-only-where-the-host-exposes-the-event qualifier, the PLATFORM LOOP versus PLATFORM LOOP + NEXUS-HUB trail comparison, and the absorbed durable-trail takeaway.

## Dead-code reconciliation

Rebuilding the scenes orphaned an entire generation of SVG machinery, and each retirement follows the fx-grow pattern from Phase 3: delete the dead rules, convert the orphaned test into a guard that a reintroduced consumer must satisfy.

- The retirements are guarded: `test_foundations_pulses_...` now asserts `fx-pulse` and `offset-path` are absent, the mobile-variant test asserts the variant system is absent, and the retired route-motion browser test names its living replacements (the visual detector's containment rules and the new Phase 4 file) in its guard.

## Plan delta

**Disposition: No delta.** Every Phase 4 requirement was implementable as written, and the plan's two hard constraints (approved-bytes-only media, one shared grammar) turned out to be mutually reinforcing: generating the media locally made the hash discipline trivial, and emitting the shared motifs from one function made the grammar assertion exact rather than approximate.

Evidence worth recording: the plan's byte anxiety (60,000 allocated for this phase) was off by an order of magnitude in the safe direction, because replacing bespoke per-scene SVG with HTML primitives recovered more than the media cost. The running total the Phase 1 contract projected for the end of Phase 4 was 384,441; the actual is 280,351.

**Consequence for remaining phases**: Phase 5's 55,000-byte allocation for the arcade engine now sits on 219,649 of real headroom, so the engine should be built for clarity rather than byte-golfed.
