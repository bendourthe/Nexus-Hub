## What the review asked, and what it got

Four things on one figure. The reveal animation went, because it made the boxes hard to read: every box now paints visible and the only motion is a dot travelling down each connector. The four logos are the marks already approved in the asset ledger. Each triangle now shares the target grid's track definition, which is the only way it can sit on the centre of its own box at every width. And the mid-task strip, which was a left-packed row inside a full-width box, is now a five-track grid that fills it.

## Sharing one vendor mark failed twice before copying won

The obvious design was to hoist the four marks into `<symbol>` elements and point both the rail and the figure at them, which would have made showing each mark twice cheaper than showing it once. It failed twice, in two different ways, and neither failure said a word.

Cloning the Gemini mark rendered a **blank box**. A `<use>` copies content into a shadow tree and Chromium resolves a `url(#id)` mask reference against that tree first, so the reference found the cloned mask rather than the real one. Hoisting the mask and filters to document level, the documented workaround, rendered an unmasked **square**. In both states the element was present and the reference was correct, so a presence assertion passed. Only looking at the page showed anything wrong, which is why the test now asserts a painted box larger than 8px rather than an element that exists.

The third failure settled the design. Rewriting a rail chip into a `<use>` tripped the ledger hash guard, whose message says re-approval is required rather than a ledger update. That is correct: the approved bytes belong exactly where they were approved. So the figure gets a copy, with the mark's internal ids namespaced per instance, and the roughly 12 KB is paid rather than argued with. The alternative was to redraw a vendor's logo to suit a rendering bug.

## A measurement that invented a 530px error

The first centring check reported a triangle 530px off centre inside a 720px figure. Below the collapse breakpoint the fan hides its extra lanes, a hidden lane reports a zero rect, and the check was comparing that zero rect against a real box. The figure was fine; the measurement was not. A geometry check has to filter for visibility before it compares, and the version in the test does.

It also pinned down what the narrow layout is for. With the platform list two wide over two rows, no per-box arrow can be honest, because it would point at the gap between two boxes. One centred arrow says the same thing.
