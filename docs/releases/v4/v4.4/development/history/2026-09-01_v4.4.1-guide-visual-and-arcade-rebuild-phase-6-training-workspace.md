## Sub-task 6.2 -- Fullscreen control, Outline, and Escape precedence

The old hero `Present` button is gone. The control now lives in `.nht-bar` immediately before `Outline`, INSIDE the fullscreen root, so it survives the transition rather than disappearing with the page chrome. It is labelled `Full screen` / `Exit full screen`, carries a four-corner icon and an `aria-pressed` state, and reconciles that state from `fullscreenchange` rather than assuming the change was script-initiated, because the user agent may consume Escape and exit natively.

Outline is a nonmodal disclosure, not a dialog: `aria-expanded` on the trigger, a labelled `region` panel, normal tab order, no focus trap, dismissal by outside click or Escape with focus returning to the trigger.

Escape precedence in the overlay is exactly: close Outline first; otherwise, if focus is inside the active game, pause it and release its keys; otherwise exit the overlay and return focus to the fullscreen trigger.

## Sub-task 6.3 -- Presentation geometry

The slide is a two-column layout in which head, takeaway, and controls span both columns, the game column takes a bounded share, and the evidence column owns the one permitted secondary scroll. Below 1024 px (which 200 percent zoom also reaches) the whole slide reflows into ONE vertical scroll surface.

Three earlier attempts (plain flex column, explicit grid tracks, subgrid) each let one panel's content decide another panel's position, which produced overlaps that MOVED between viewport sizes as free height changed. Bounded columns is what made the geometry stable across the matrix.

## Defect BG-11: the Outline reflow latched the game stage

Worth recording in full, because the diagnosis inverted twice.

The Escape-precedence test failed only inside the full suite and passed in isolation, which reads as a flake. Treating it as one would have shipped the bug. Replacing its fixed `wait_for_timeout` calls with explicit condition waits (`wait_for_function` on `pauseReasons` containing `manual`, and on the game owning focus) made it fail CONSISTENTLY -- which is the opposite of what a timing flake does, and the signal that the fixed sleeps had been masking a real defect.

The real failure was that clicking `Click to start` timed out with `.nht-slide` intercepting pointer events. Measurement showed why: opening Outline collapsed the game stage from 180 px to 42 px, and closing Outline never restored it. The start button was left outside the clipped stage, so the topmost element at its centre was the slide.

Root cause was a flex circularity, in two stacked layers. `.nht-col:first-child` was content-sized (`flex: 0 0 auto` with `max-height: 58%`) while `.nag-stage` inside it was fill-sized (`flex: 1 1 auto`). A fill-sized child has nothing to resolve against inside a content-sized parent, so Chromium answered from layout history: the Outline reflow drove the stage to min-content and the value stuck. Giving the column a DEFINITE `height: 58%` fixed the column but not the stage, because `.nht-game` between them was itself content-sized; making it `flex: 1 1 auto` closed the chain. State now round-trips exactly through an open-and-close of Outline.

The fix then broke the narrow reflow, for the reason this file has now hit twice (BG-4 was the first): a media query adds NO specificity. The narrow reset matched `.nht-col` at three class-level components while the new desktop rule matched `.nht-col:first-child` at four, so the reset lost and the stacked column kept a percentage height. The reset had to repeat the `:first-child` shape. Both rules carry comments recording this.

Deferred (recorded in `known-gaps.md`): while Outline is OPEN, the in-flow panel still squeezes the game panel in present mode. It restores correctly on close and no acceptance criterion covers it, so overlaying the panel was left out of a late layout diff rather than taken on unvalidated.
