## 2. Chronological Steps

### 2.1 Replace the scenario source of truth

**What happened**: Rebuilt `guides/website/example/training-scenes.json` around an `initial` project and eight ordered command deltas. The initial project contains the actual buggy collision and hit-outcome seams. Every scene supplies second-person intent, command, tools, output, strict Asteroids state, real file changes, a focused file, artifact, gate, and takeaway.

**Artifact quality**: The cumulative project now contains an analysis grounded in the 636-to-8 wrapped-edge reproduction, a P1 review naming direct-distance collision, a one-phase repair plan that excludes splitting, a `minimumImage` implementation and real diff, focused collision and deterministic fragment tests, a comparison adoption decision and follow-on plan, a changelog, and a self-contained briefing.

**Safety contract**: The literal `<img onerror>` and `</script>` fixtures remain in the data. The embedded JSON is script-safe, parses equal to the source file, and is minified to preserve the guide budget.

### 2.2 Build the cumulative explorer

**What happened**: Replaced Peek with a full-width two-pane explorer. A pure reducer starts from `initial.files`, applies scene deltas through a requested index, and derives the current marker without replaying commands. Created files show `new`; modified files show `changed`; earlier files persist as existing. The current command's focused path appears as `pending` before Run and displays `Not created yet` rather than an empty pane.

**Rendering contract**: Tree items, paths, badges, content, output, and diff lines are created with `createElement` and assigned through `textContent`. Diff files distinguish added and removed lines without using `innerHTML`. The tree exposes labelled `treeitem` buttons, selected state, visible focus, ArrowUp, ArrowDown, Home, and End navigation. Rebuilding the tree restores focus to the selected replacement node so keyboard traversal continues.

### 2.3 Make Run one idempotent transaction

**What happened**: Scene entry derives the complete state through the prior command. Run commits the current output, files, and strict game state together. This gives `/implement` an observable before-and-after transition instead of loading the fixed result before the learner acts. A direct jump derives the same baseline in one reduction; backward navigation removes later files and features; rerunning recomputes the same state.

**Visible transitions**: The `/implement` result changes collision mode from buggy to fixed while splitting remains off. The `/compare` result explicitly includes its follow-on plan and implementation and enables splitting without adding a ninth scene. Later steps retain both behaviors and may move from the seeded boundary situation into free play.

**Test seam**: Published frozen `window.NexusTraining` and compatible `window.NHTraining` methods for direct navigation, immediate Run, file selection, snapshot, and hash synchronization. Snapshots expose the scene, applied index, selected path, cumulative paths, declarative game state, and whether the current command ran.

They are not linked, offered to readers, or used by Training. No file was deleted under an inferred approval.

## 5. Plan Discrepancies

## Plan delta

**Command-entry semantics**: A direct jump establishes state through the prior command, then Run applies the selected command. This is the only interpretation that satisfies both free navigation and the requirement that `/implement` visibly changes the game. The reducer computes that baseline directly rather than replaying earlier UI actions.

**Comparison follow-on placement**: The comparison scene records the adoption decision, follow-on plan, implementation, and splitting regression together. Splitting therefore appears when `/compare` completes, matching the stability gate without inventing a ninth command scene.

**Legacy beat grammar**: The old two-beat scene mechanism was removed with its Glow Booth schema. A legacy `?beat=n` suffix remains accepted and ignored, then the URL normalizes to `#training/<scene-id>`. The compatibility browser test records this behavior.

**Asset retention**: The plan required a decision and explicit approval before deletion. The legacy ZIP and folders still have regression-fixture value, so Phase 5 removes them from the reader path and retains them. No deletion was proposed as necessary for this phase.
