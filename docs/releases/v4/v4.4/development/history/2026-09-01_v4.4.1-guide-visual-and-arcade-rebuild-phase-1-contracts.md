### 1.2 -- Replace the oversized Nexus mark and allocate the byte budget

The `#nexus-mark` symbol held a single 220,140-character base64 PNG (165,104 decoded bytes) inside an `<image>` element.

Rather than estimate the geometry, the embedded PNG was decoded and measured with Pillow: corner-node blob centroids, node radius, hub centre, per-column triangle extents for all four quadrant shapes, and the perpendicular bar thickness derived from the measured 44.62-degree diagonal. Those measurements produced the replacement directly -- four nodes at (106,97), (410,97), (106,395), (410,395) at r=34; two 26-unit round-capped diagonals; a white hub at (258,246) r=30; large gradient triangles with vertical bases at x=89 and x=425 spanning y=144..356 with apexes at (196,250) and (320,250); and two narrow gradient wedges, the second an exact 180-degree rotation of the first about (258,250). A single `feGaussianBlur` layer reproduces the original luminous halo, which a first attempt using a flat translucent underlay did not: on the dark ground it read as a dark edge rather than a glow, and was replaced after visual comparison.

### 1.3 -- Approve the five platform marks and stage output media (decision task)

Four marks were fetched from the exact Wikimedia sources the plan names (all HTTP 200) and the two local Cursor candidates were read. All five sanitized files were staged under [`assets/`](../guide-visual-and-arcade-rebuild/assets/) with full provenance in [`asset-provenance.md`](../guide-visual-and-arcade-rebuild/asset-provenance.md), then rendered at 44 px in both themes as a contact sheet before approval was requested.

Two findings changed the outcome:

**The plan's local Cursor candidates were rejected in favour of the official brand archive.** `cursor-seeklogo.svg` carries gradient ids of the form `lobe-icons-cursorundefined-fill-0`, identifying it as LobeHub-derived rather than first-party despite its filename; its fills are `#000`/`#555`, so it is invisible on dark and would need a hand-authored variant with no vendor counterpart. The companion `.png` is disqualified by the byte budget. Cursor's own archive supplies `CUBE_2D_LIGHT` and `CUBE_2D_DARK` at 793 bytes each. A byte comparison proved those two differ ONLY in a single fill hex, so one sanitized file using `fill="currentColor"` reproduces either sanctioned variant exactly. The plan explicitly permitted preferring the official archive when its variants are clearer, so this is the branch the plan provided rather than a deviation from it.

**The GitHub Copilot codicon is CC BY 4.0, so attribution is mandatory.** Upstream metadata was queried for all four Wikimedia files: Claude is CC0, ChatGPT and Gemini are public domain, and all four are flagged `trademarked`. Only the Copilot codicon carries a licence that imposes an obligation on the shipped page. This is now requirement H12, and the maintainer approved a collapsed keyboard-accessible "Trademarks and credits" disclosure beside the rail, naming Codicons and Microsoft Corporation under CC BY 4.0 plus one nominative-use statement covering all five marks. Phase 2 must implement and assert it in the same commit that inlines the marks.

All five marks were approved at their exact sanitized SHA-256 values, totalling 14,177 bytes against the 30,000-byte Phase 2 allocation. Every mark is true vector geometry with no raster payload, no script, no event handler, no `foreignObject`, no `@import`, and no external reference beyond the required `xmlns`. Gemini was the only mark declaring ids; all 13 were namespaced to `nxp-gm-*` with every `url(#...)` reference rewritten, because upstream names like `maskme` are collision-prone. Its alpha mask and five blur filters were retained as declarative rendering.

The four Phase 4 output-media candidates were recorded as Phase 4 blockers, which the plan's stability gate permits explicitly. They will be generated as original local media and hashed into the ledger before Phase 4 embeds them. This blocks Phase 4 only; Phase 2 is unblocked.

## Plan delta

**Disposition: Incomplete.**

The plan is correct in substance and its Phase 1 sequencing held, but two defects in the plan document itself surfaced during execution, and both would have failed a gate later:

1. **The plan file leaked personal filesystem paths.** Sub-task 1.3 named the local Cursor candidates as `C:/Users/<user>/Downloads/...`, and `scripts/validate_no_personal_paths.py` reported 4 findings against the plan document. That validator runs in `make validate` and in CI, so the plan as authored would have failed the pipeline the moment it was committed. The paths were redacted to a username-free `~/Downloads/...` form, matching the same fix applied to a v4.1 document. **Evidence**: `validate_no_personal_paths: 4 finding(s) in 2176 scanned file(s)` before the redaction, clean after.
2. **The plan's `## Current model map` carried a stale Google frontier tier.** It listed `gemini-3.7-flash` as frontier, where the vendor documents `gemini-3.1-pro-preview` as its advanced-intelligence offering. The identical error was found and corrected in `last-known-model-map.json` during the v4.4.0 release earlier in this session, so the plan had inherited it. The plan's map is now corrected and annotated, with the strong/standard split recorded as a maintainer judgment.

**Consequence for remaining phases**: none blocking. Both fixes are local to documents and neither changes a phase's scope, ordering, or acceptance criteria. Phase 2's inputs are unchanged and its inline bytes are pinned by the approved hashes. The lesson worth carrying is that a plan document is itself subject to the repository's validators, so a future `/plan` run should scan its own output before the plan is committed.

Two further observations that are explicitly NOT deltas, recorded so a later reader does not mistake them for drift. The Cursor source substitution is a branch the plan itself offered ("prefer Cursor's official brand archive ... when its documented use terms and sanctioned light/dark variants are clearer"), and the deferral of output media is an outcome the plan's stability gate names as acceptable.
