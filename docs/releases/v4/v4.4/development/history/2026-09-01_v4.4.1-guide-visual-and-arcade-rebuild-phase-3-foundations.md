## Sub-tasks

### 3.1 -- Reorder the eight scenes and establish compact layout primitives

All eight scenes were reordered to the accepted sequence and retitled, with zero `What Is` or `What Are` constructions surviving anywhere in Foundations.

**The height problem had one dominant cause.** Seven of the eight scenes carried `fx-wide`, which collapses the scene grid to one column and stacks copy ABOVE a full-width diagram. Making the exception the default is what produced a 7,235 px page at 1440. Full width is now reserved for the two scenes whose content is intrinsically two-across (`fx-chatbot-agent` and `fx-harness`); the other six returned to the copy-beside-diagram grid, with the scene gap and padding tightened from `--sp-6`/`--sec-pad` to 30 px/26 px.

The layout was measured before it was committed to. Converting every scene to two columns would have reached 4,286 px, a 40.8% cut, but that shrinks each diagram into a 7fr column further than the target requires. Keeping the two comparison scenes wide lands at 5,280 px with 555 px of margin under the gate, so the diagrams keep 608 px (1072 px for the wide pair) rather than being squeezed to hit a number.

### 3.2 -- Rebuild Tokens Definition

The old scene failed three of its requirements: its sample was a plain sentence rather than a prompt, its chips used two colours with no explained meaning, and its image "tokens" were **empty coloured rectangles** next to an abstract shape that was not a recognizable picture.

**The split is verified, not asserted.** `Summarise this contract and list every deadline.` was run through `tiktoken` `cl100k_base`, giving exactly the ten tokens now displayed. That prompt was chosen over the alternatives specifically because `Summarise` splits into `Sum` + `mar` + `ise`, so the page demonstrates that a token is not a word instead of merely stating it. The test asserts the full ten-token list, so a future edit to the prompt without re-running the tokenizer fails.

**Every chip now shares one style,** because the tokens are equivalent units and a second colour would imply a category the tokenizer does not have. The prompt itself is HTML at a 19 px floor rather than SVG text, since a computed-size requirement cannot be guaranteed by text whose size depends on a viewBox scale.

**The image cells contain real pixels.** The artwork is one original procedural landscape defined once as `#nxp-tokimg`. Each of the nine grid cells is a namespaced `clipPath` over a `<use>` of that same artwork, translated so the cell shows exactly the region beneath it. Cell size equals region size, so the crop is 1:1 with no resampling. The result is verifiable by eye: the trunk lands in the bottom-centre cell and the sun in the top-right.

### 3.3 -- Prompt and Context as one request story

Both scenes were rebuilt as semantic HTML node trees with one small connector SVG, which is what sub-task 3.1 prefers and what made them 14 KB smaller than the SVG versions they replaced.

Prompt Engineering shows the same contract request twice: vague (`Look at this contract.`) and then precise, broken into Goal, Material, Done, and Format as a description list. Context Engineering continues that request, separating the text query from the four kinds of optional material (image, file or document, project folder or workspace, codebase) and then showing one finite budget spent two ways.

The weaker state always precedes the stronger one in DOM order, so reading order, keyboard order, and screen-reader order match the teaching sequence at every breakpoint without layout tricks.

## Four real defects found during the phase

1. **A media query that silently lost.** The narrow-screen stacking rules for the new components were placed in an existing `@media (max-width: 720px)` block at line 403, while the base rules they override were added around line 490. A media query adds no specificity, so source order decided and the base rule won: `.fx-states` still computed `105px 34px 105px` at 320 px and overflowed. The overrides were moved below the definitions, with a comment recording why the position is load-bearing.
2. **Unbalanced HTML that broke a different page.** A two-step edit converting `<section class="fx-budget">` to `<div>` had its first step refused by a guard assertion, but the second step ran anyway, leaving `<section>` openings with `</div>` closings. The browser's error recovery re-parented everything after it, so `#page-training` became a direct child of `<body>` instead of `<main>`, and presentation mode's inert walk stopped before reaching `.site-header`. **A Training test caught a Foundations markup bug**, which is the clearest argument for running the broad suite rather than the touched file.
3. **SVG text clipped at the viewBox edge.** Two caption lines in the Tokens diagram ran past the 360-unit width and were cut mid-word. SVG text does not wrap, so the captions moved to an HTML paragraph beneath the diagram.
4. **A dead animation primitive.** `fx-grow` lost its only consumer when the SVG context-budget diagram became HTML, leaving three orphan CSS rules and a reduced-motion check that failed on an empty set. The CSS was deleted, the check made vacuously safe while staying strict for any element that exists, and a guard added so a reintroduced consumer must restore its static state.
