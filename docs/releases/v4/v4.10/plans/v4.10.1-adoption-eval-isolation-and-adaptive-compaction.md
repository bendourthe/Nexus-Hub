**Goal**: Nexus-Hub's skill evaluations run with the operator's own configuration excluded from every arm and with a pinned model, its catalog is proven to load on a real host platform in CI rather than only to parse, and `[[context-compression]]` states both halves of the compaction decision - when to fire and when to suppress - with the retention rule corrected so that dead-end paths and negative results are no longer classed as discardable exploration.

## Overview

This plan operationalizes the nine adoption items from the seeding comparison. Two of them are corrections to shipped behavior rather than new capability, and that is what sets the plan's shape: the first two phases fix things that are currently wrong in ways that read as working, and everything afterwards builds on the corrected base.

The first correction is methodological. `[[skill-eval-loop]]` runs paired with-skill / without-skill comparisons but never isolates the invocation from the operator's own agent configuration, so the baseline arm of every comparison it has ever run contained the globally-installed Nexus-Hub catalog. The fix is small - isolation flags and a model pin across four CLI branches in one reference file - and its consequence is not: prior paired numbers are not comparable to post-fix numbers, and any locked regression baseline captured under contamination needs re-capture. The plan states that consequence rather than quietly re-baselining.

The second correction is doctrinal. `[[context-compression]]` diagnoses the mid-reasoning compaction failure correctly and then offers only one remedy, compacting earlier, with no condition under which an agent should decline to compact at all. The SELFCOMPACT source supplies the missing half as an evidence-gated rubric, and supplies one rule that contradicts what the skill currently says: value dispersed across dead-end queries and negative results is not summarizable, because discarding it is what makes an agent re-walk paths it already eliminated. The contradiction is repaired before the rubric that depends on it is added.

The remaining work is additive and lower-risk: completing the compaction contract with verification-debt and probe-hygiene rules, adding a real load-layer CI gate that installs the catalog on a host platform instead of only parsing its manifests, and hardening the eval loop with a weighted release gate and deterministic blinding. Phases follow the comparison's reverse-engineer-first ordering: every `skill-native` item ships before any `re-full` item, with P-tier ordering inside each bucket.

**Recommended model tier**: strong
**Recommended effort level**: medium

### Sub-tasks

#### 3.1 -- Verification debt and anti-inference across the boundary (A5)

**Objective**: Stop a compaction from silently promoting an unverified claim into a settled fact.

**Prompt**:
> Add three summarization rules to `catalog/skills/orchestration/context-compression/references/compaction-rubric.md`:
>
> 1. **Carry verification debt forward.** If a result was found but not verified, the summary must say so explicitly. A compaction that drops the unverified marker converts an unverified claim into an apparently settled fact, and every later turn then treats it as established. Cross-link `[[verification-before-completion]]`.
> 2. **Do not infer.** The summary includes only what is explicitly present in the trajectory. It must not add assumptions, guesses, or inferences, and information that is missing or unclear is omitted rather than reconstructed. A summary that infers is indistinguishable from one that observed.
> 3. **Preserve the resolved result.** When the trajectory reached a concrete result, the summary preserves it verbatim rather than paraphrasing it.
>

## Phase 6: Eval Release Gate, Deterministic Blinding, and Headroom Method

**Rationale**: Determinism under resumption and correct grouped judging are easy to implement in a way that looks right and is not; the failure is silent and reproduces as noise in results.

### Sub-tasks

#### 6.1 -- Weighted rubric, blocker flag, and numeric release gate (A6)

**Objective**: Replace an unweighted verdict with a scored gate that can fail closed.

**Failure modes**: When a dimension score is missing for a condition, the group is reported as unscorable and excluded rather than scored with an implied default, because a defaulted dimension silently moves the weighted total. When a blocker is set, the gate fails regardless of the weighted score, so a high average cannot mask a dangerous or contract-violating output. When two conditions tie within the gate's tolerance, the result is reported as no-difference rather than resolved arbitrarily in the candidate's favor.

**Build class**: load-bearing.

**Prompt**:
> Add a weighted scoring rubric and an explicit release gate to `[[skill-eval-loop]]`.
>
> The rubric assigns each dimension a weight summing to 100 percent, and carries a boolean `blocker` for a dangerous instruction, a material factual error, a failure to follow an explicit output contract, or an agent-autonomy regression that prevents task completion. The source's weighting was correctness 35, autonomy 25, actionability 20, safety 10, concision 10; adopt the structure and set weights appropriate to Nexus-Hub's own eval axes rather than copying the numbers unexamined, and say which you chose and why.
>
> The release gate passes only when: there are no blocking findings; correctness and safety are each no worse than baseline by more than a stated tolerance; and the weighted score exceeds baseline. >
> Acceptance criteria: weights sum to 100; the gate is stated as a conjunction that fails closed; the no-worse-than tolerance is an explicit number, not a qualitative phrase.

#### 6.2 -- Deterministic blinding and grouped judging (A7)

**Objective**: Make blinding structural and reproducible, and judge conditions against each other rather than in isolation.

**Failure modes**: When a group is missing a condition, it is reported on stderr and excluded rather than judged, since the conditions would no longer be compared on identical rows. When a run resumes, the permutation must be recomputed from the group key so the labels match the first pass; a random source would relabel on resume and corrupt an already-written result file. When the rubric file contains gate rules that name conditions, they must be outside the region sent to the grader.

**Build class**: load-bearing.

**Prompt**:
> Replace the delegated shuffle in `catalog/skills/workflow/skill-eval-loop/agents/comparator.md` and its runner contract with three properties:
>
> 1. **Deterministic permutation.** Derive the label order from a digest of the group key rather than from a random source, so a resumed run reproduces the labels it used the first time. State why: a random shuffle relabels on resume, and a partially-written result file then mixes two labelings.
> 2. **Grouped judging.** Group responses by case and trial and grade every condition for a case in ONE call, so conditions are compared against each other rather than scored in isolation. A group missing a condition is reported and excluded, not silently dropped.
> 3. **A judge-region marker.** Fence the portion of the rubric sent to the grader with explicit begin and end markers, and keep everything condition-identifying - the release-gate rules from 6.1 in particular - outside that region. Those rules name the conditions, and sending them to a blind grader leaks the exact vocabulary the blinding exists to hide.
>
> Acceptance criteria: the same group key yields the same labels across two runs; a group missing a condition is excluded with a reported reason; the grader-visible region provably excludes the gate rules.

#### 6.3 -- Oracle-headroom ceiling estimation (A10)

**Objective**: Give gate design a way to know its own upper bound before investing in it.

**Prompt**:
> Add a headroom-estimation method to `catalog/skills/workflow/skill-eval-loop/references/`. The technique: before investing in a gate, simulate a perfect-information oracle that makes the ideal decision at each opportunity, and measure it. The oracle's score is the gate's ceiling, so the gap between the current policy and the oracle is the maximum available gain.
>
> Cite the source's worked instance: an oracle that suppressed summarization whenever the current answer was already correct, but otherwise followed the same fixed schedule, scored 11.5 points above fixed-interval. >
> Cross-link the locked regression sets and per-slice floors already in the skill: those measure whether a gate regressed, this estimates whether a gate is worth building.
>
> Acceptance criteria: the method is stated as a procedure with the oracle-construction step made explicit; the cited number is attributed to the source; the distinction from regression floors is stated.
