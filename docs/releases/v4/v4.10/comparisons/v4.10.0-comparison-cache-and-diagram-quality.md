# Comparison: cache-aware agent practice and diagram quality

This report compares the supplied Claude cost article and Diagram Design repository with Nexus-Hub. It identifies six bounded improvements for existing owners, distinguishes current capability from queued work, and records source trust, policy decisions, and acceptance evidence.

Date: 2026-09-09

Adoption target: v4.10.0

Status: comparison complete; adoption target confirmed by the user on 2026-09-09; implementation not started.

Baseline: Nexus-Hub `develop` at `27136cd74ce1dbfec757adea6fbfea9efabcaaa5`, manifest v4.9.0, 336 catalog skills. Existing uncommitted handbook edits were inspected as working-tree proposals, not represented as released behavior.

## Recommendation

Extend existing skills rather than import either source wholesale. The immediate defect is incorrect cache-share arithmetic in a distributed example. The most valuable diagram addition is focused label/connector geometry verification. Complement those with a short cache-stability checklist, a bounded prompt audit, semantic diagram selection, and explicit diagram-detail accounting.

The article concerns Claude API economics; Diagram Design concerns visual authoring. They are independent tracks. No new MCP, hosted generation service, model switch, automatic optimizer, or standalone diagram framework is warranted by this comparison.

### Concrete defect: cache percentage

[The current example][N1] assigns `usage.input_tokens` to `total_input` and divides `cache_read_input_tokens` by it. S4 defines three separate input buckets: uncached, cache creation, and cache reads. A synthetic case with 900 read, 100 uncached, and zero creation tokens produces 900% in the current expression; the cache-read share is 90%.

Correct the example to divide reads by the sum of all three buckets, handling zero total explicitly. Name this metric cache-read share, not cost savings or request hit rate. Actual cost requires the applicable rates, cache-write durations, output usage, and a stated baseline. This is a demonstrated documentation-example defect; no production billing impact was measured.

### API qualifications that must survive adoption

Top-level effort changes invalidate earlier cached prefixes. Supported per-message effort changes preserve them and require `mid-conversation-output-config-2026-07-01`; current S5 names Opus 5, Fable 5.1, and Mythos 5.1. Effort is a behavioral control, not a hard spending cap.

S4 documents `max_tokens: 0` prewarming with explicit constraints: streaming, enabled extended thinking, structured output, forced tool choice, and batches are unsupported combinations. Cache writes still have a cost. TTL runs from request start and refreshes on use. Do not recommend a recurring warmer without measured benefit and an authorized budget.

S6 distinguishes request-structure diagnostics from actual cache reuse in usage fields. Its beta is Claude API-only; missing, pending, or unavailable diagnostics must remain unknown. S7's message/tool capabilities need their own compatibility checks. None of these levers is assumed to exist in Codex, every Claude hosting platform, or Nexus-Hub's current session.

### Visual strengths and limits

The useful conceptual split is between what a diagram explains and how it is arranged. A backlog example needs arrivals, capacity, waiting work, and outcomes before choosing a flow layout. This can become a few examples under the existing HTML owner rather than 39 new skill types.

The pinned `scripts/verify-geometry.py` detects label-mask rectangles partly overlapped by later-painted node rectangles. Its shape-size heuristics fit its own templates; it is not a general SVG collision solver. `scripts/lint-render.py` supplements geometry with pixel-based inspection and declares unchecked cases. Nexus-Hub should adopt the narrow defect model and explicit coverage limits, not copy heuristic thresholds and claim universal coverage.

Upstream `references/output-spec.md` records merged, collapsed, omitted, and fully retained details. Nexus-Hub's figure worksheets already protect source semantics. The incremental improvement is making approved simplification traceable at the node/edge level. A simplification budget cannot override whole-source coverage or silently discard security boundaries.

## Conflicts and considered-but-rejected candidates

- **Wholesale prompt cleanup:** reject. Redundant ritual and required evidence are different. The article does not authorize deleting release gates, security checks, or source scans.
- **Default low effort or autonomous hill climbing:** reject as a global change. Preserve routing defaults, user choices, and hard-budget ownership; reuse the v4.13 evaluation protocol for future experiments.
- **Prewarming every session and universal one-hour caching:** reject as defaults. They add cost and may be inapplicable; only measured workloads justify them.
- **All 39 types and import/export commands:** defer. No current request requires full parser maintenance. Revisit only with real Mermaid/draw.io inputs and explicit supported syntax, limits, and hostile-input cases.
- **A fixed nine-node ceiling, mandated orthogonal connectors, tiny labels, and fixed palette:** reject as universal policy. Use readable geometry and source coverage to determine complexity. Radial, scientific, and presentation content need other arrangements.
- **Replacing presentation motion with static-only output:** reject. Static fallback is useful; the queued handbook plan also requires meaningful presentation builds, replay, reduced-motion support, and content-dependent timing.
- **Replacing brand profiles:** reject. Nexus-Hub already owns brand tokens outside installed bundles. A second profile system creates precedence and concurrent-workspace problems.
- **Copying the upstream SVG export as native PowerPoint delivery:** reject. SVG/PNG export does not prove native-editable PPTX or animation fidelity.
- **Copying upstream release automation:** reject. Its post-merge main-branch version bumps conflict with Nexus-Hub's declared lifecycle.
- **Rebranding copied source without notices:** reject. Re-author patterns independently. Any later copying of substantial MIT material must retain required notices; review third-party asset terms separately.
