**Adoption target: v4.10.1**

**Authored during**: the v4.10.0 cycle (`fix/target-manifest-git-trust-skip`)
**Authored on**: 2026-09-11
**Source type**: two sources of different class - one Git repository (project source, 11-dimension matrix) and one research paper (article-class source, insight extraction)
**Sources**:

- **Source A**: [`github.com/ayghri/i-have-adhd`](https://github.com/ayghri/i-have-adhd) - a single-skill, multi-platform agent distribution. Cloned at depth 50 into a session scratchpad; 62 tracked files.
- **Source B**: *Self-Compacting Language Model Agents*, Li et al., Johns Hopkins University and Apple, `arXiv:2606.23525v2 [cs.CL]`, 10 Jul 2026. Local PDF, 1391 lines of extracted text.

## Section 1: Executive Summary

Two sources, and the reason they are reported together is that both land on the same seam: **what an agent does at a context boundary, and whether the evidence that it works is trustworthy.**

**Source A is a structural peer, not a subject-matter peer.** It ships one skill where Nexus-Hub ships 336, so nothing in its catalog content is adoptable. What it has built around that one skill is another matter: a paired baseline/candidate evaluation harness with structural blinding and a numeric release gate, and a CI job that installs the plugin into a scratch config directory and fails unless the platform reports it enabled. On the eleven comparison dimensions, Nexus-Hub leads or matches on nine. It loses on two, and both losses are load-bearing.

**The highest-value finding in this report is a methodological invalidity inside machinery Nexus-Hub already ships.** `[[skill-eval-loop]]` is a sophisticated 341-line harness with crash-safe resumption, a blind comparator sub-agent, adversarial eval batteries, and locked regression sets. It has no runner configuration isolation. A full-bundle search for `--setting-sources`, `--ignore-user-config`, and `--ephemeral` returns zero hits across all ten bundled files. Source A's `evals/README.md` names precisely this trap and names it against itself: without isolation, "user-level plugins, hooks, memory, and output styles leak into every condition", and its own always-on flag "would inject the full i-have-adhd ruleset into the **baseline** condition and make the comparison measure the skill against itself." Nexus-Hub is more exposed than the source, not less. Its installer is global-scope-by-default across every detected platform, so the operator running a skill eval has the entire catalog live in *both* arms. Every paired number the loop has ever produced was measured with the treatment present in the control.

**Source B's contribution is the half of compaction Nexus-Hub does not have: when not to.** The paper's finding is not that compaction helps - Nexus-Hub knows that and shipped `nexus-context-compressor` in v3.2.0. It is that *timing* dominates, that a model cannot judge its own context rot unprompted, and that a short evidence-gated rubric supplies the missing judgement at inference time with no training. The ablation is the interesting part: exposing a compaction tool without the rubric loses most of the gain, because models fire it reflexively or not at all (Table 5 region, Section 4.2). Nexus-Hub's `[[context-compression]]` already diagnoses the failure mode correctly at line 94 - the autocompact trigger "fires mid-reasoning, drops context Claude was about to use, and quality tanks for the next several turns" - and then offers only one remedy: compact *earlier*. There is no suppression condition anywhere in the catalog. Nothing tells an agent "do not compact now."

**One source finding contradicts a rule Nexus-Hub currently states, and the correction matters more than any addition.** `[[context-compression]]` retains decisions and discards exploration. The paper's C2 gate says the opposite in a specific case: answer N when the trajectory's value is "dispersed across many small inferences (e.g., a list of dead-end queries needed to avoid retries, negative results that constrain hypothesis space)". Discarded exploration is what stops an agent re-walking paths it already eliminated. This is a defect in existing guidance, not a gap.

**One candidate is declined because it runs against a decision already in flight.** Source A's authorship-provenance taxonomy requires disclosing the agent and model behind every contribution. The in-flight [`v4.12.0-sole-contributor-attribution`](../../../../archives/v4/v4.12/plans/v4.12.0-sole-contributor-attribution.md) plan rewrites history so that exactly one identity appears and strips the agent trailers GitHub maps. The two point in opposite directions. One clause of it survives independently and is adopted separately.

**Recommended adoption: nine items, all `skill-native` or `re-full`, zero new outbound calls, zero new API keys, zero new third-party processors, zero new runtime dependencies.** Six further items are declined, three of them because Nexus-Hub has already recorded the opposite decision or already owns the capability.

### 3a. Dimension 7 in detail: the load-layer gap

Source A runs two jobs that Nexus-Hub has no equivalent of.

`.github/workflows/plugin-load-check.yml` installs Claude Code, points `CLAUDE_CONFIG_DIR` at a scratch directory, adds the checkout as a marketplace, installs the plugin, and fails unless `claude plugin list` contains the enabled marker. Its header comment states the purpose exactly: "Catches load-layer breakage that schema validation misses, e.g. the duplicate hooks declaration in #61."

`.github/workflows/pi-load-check.yml` installs Pi with `--ignore-scripts` and runs `scripts/check_pi_extension.py` to verify "the Pi package, commands, status, and persisted mode."

Nexus-Hub's gate list in `scripts/ci/profiles.py` contains `catalog-parse`, `hygiene`, `catalog`, `security`, `workflows`, `platform-contracts`, `docs`, `version`, `tests`, `extension-tests`, `shell-lint`, `powershell-parse`, `windows-hooks`, `interpreters`, and `release-checks`. A grep across `.github/workflows/` and `scripts/ci/` for `claude plugin install`, `claude plugin validate`, or `npm install -g @anthropic-ai/claude-code` returns nothing. Every existing gate verifies a *declared* property: that JSON parses, that a path matches the read contract, that a `.ps1` parses as an AST. None verifies the *achieved* property: that a supported platform actually loads the catalog.

This is not a hypothetical bug class for this repository. `AGENTS.md` records that `session-summary.ps1` "shipped in v3.11.0 with a parse error and was therefore dead on Windows for four minor versions, because nothing parsed catalog `.ps1` files." The AST-parse gate was the fix for that instance. A load test is the general form of the same lesson, one layer up: the plugin manifest at `.claude-plugin/plugin.json` declares `"version": "4.9.1"` and a one-level skills scan, and nothing today proves a host accepts it.

### 3b. Dimension 11 in detail: the eval contamination gap

Source A's `evals/README.md` documents four properties, in descending order of how badly Nexus-Hub needs them.

1. **Configuration isolation.** "Both example runners isolate the call from the operator's own agent configuration: `--setting-sources ""` for Claude, `--ignore-user-config --ephemeral` for Codex. Keep that isolation when adding runners: without it, user-level plugins, hooks, memory, and output styles leak into every condition and shape the responses being judged."
2. **Model pinning as a consequence of isolation.** "Isolation also drops the operator's saved model and effort settings, so the claude runner pins `--model` explicitly. Keep a pin when editing the runner: without one, the eval silently runs whatever the operator (or the CLI release) defaults to; the model would vary between operators and over time, and per-token cost varies with it."
3. **Budget enforcement.** A USD cap per condition, the remaining budget passed on every call, and runners without cost reporting rejected outright "unless `--allow-unmetered` is supplied."
4. **Structural blinding and grouped judging.** `scripts/judge.py` "groups responses by `(case_id, trial)` and grades every condition for a case in one call, so the conditions are compared against each other rather than scored in isolation." Blinding is "structural, not a convention the grader is asked to respect": labels are permuted per group from "a digest of the group key rather than a random source, so a resumed run reproduces the labels it used the first time."

Against Nexus-Hub's bundle:

| Property | Nexus-Hub state | Evidence |
|---|---|---|
| Runner config isolation | **Absent** | Zero hits for `setting-sources`, `ignore-user-config`, `ephemeral` across all 10 bundled files |
| Model pinning | Partial | `references/schemas.md:32` has an optional per-eval `model` field, for choosing a cheaper model - not a pin defending against operator/CLI drift |
| USD budget per condition | **Absent** | 3 incidental hits, none a cap; cost governance lives in `[[ai-billing-safeguards]]`, not wired to the loop |
| Blinding | Present, weaker | `agents/comparator.md:12`: "The runner is responsible for **shuffling** A/B or A/B/C per eval and keeping the shuffle map outside the comparator's context." Shuffle is delegated to the runner with no determinism requirement, so a resumed run need not reproduce its labels |
| Grouped single-call judging | **Absent** | Zero hits for grouped / single-call judging; `agents/grader.md` grades per response |
| Judge-region markers | **Absent** | Zero hits. Source A fences the grader's view with `<!-- judge:begin -->` / `<!-- judge:end -->` so release-gate rules that name conditions cannot leak the vocabulary blinding exists to hide |
| Weighted dimensions + `blocker` | **Absent** | Zero hits for `weight` or `blocker` |
| Numeric release gate | **Absent** | No "within 0.1 of baseline" style guard |
| Crash-safe resumption | **Present, stronger** | `SKILL.md:170-186`: started/done markers, write-then-read-back verification, re-read at every phase boundary |

The isolation gap outranks the rest because it invalidates results rather than degrading them. The others make a comparison noisier; isolation makes the control arm contain the treatment.

## Section 7: Sequencing (Step 6)

Five groups. Within a group, items are independent and can proceed in parallel.

**Group 1 - correct what is wrong (P0, `skill-native`).** A4 then A3. ### 8.2 Risk notes

- **A1 changes measured history, not just future runs.** Every published paired number from the loop predates isolation. The honest consequence is that prior results are not comparable to post-isolation results, and any locked regression baseline captured under contamination needs re-capture. State this rather than quietly re-baselining.
- **A2 is the only item that can fail for reasons unrelated to Nexus-Hub.** A vendor CLI release can break the install step and turn a green gate red with no local cause. Keep it non-required until it has demonstrated stability, and give it a timeout.
- **A3's rubric is unvalidated on this repository's workloads.** The paper's conditions were tuned for competition math and agentic search. The paper itself says rubrics are task-specific (S17). Adopting the *structure* - evidence-gated, fire only on all-positives-and-not-stuck - is well supported; adopting its literal thresholds (40k tokens, 0.30 x context, >= 3 iterations) is not, and those numbers should be presented as the source's values, not as Nexus-Hub's.

### 8.4 Relationship to the waiting v4.14 comparison

[`v4.17.0-comparison-frontier-agent-practice`](../../v4.17/comparisons/v4.17.0-comparison-frontier-agent-practice.md) item A3 is a "compression adversarial-recall probe" - a fixture that queries an ordinary mid-distribution record and requires the model to answer NOT PRESENT rather than guess, testing whether `nexus-context-compressor` *loses* data.

That is complementary to this report's A3, not duplicative. The v4.14 item asks "does compaction preserve what it kept?" This report's A3 asks "should compaction have fired at all?" A recall probe cannot detect a well-preserved summary that fired mid-derivation, and a timing gate cannot detect a badly-lossy summarizer. Both are wanted. Cross-link them when either is implemented.
