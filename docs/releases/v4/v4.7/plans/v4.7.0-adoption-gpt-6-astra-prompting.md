## Overview

This is an amendment set, not a standalone release plan. The comparison it operationalizes found that the GPT-6 Astra prompting guide's adoptable items are all owned by phases the main v4.7.0 plan already defines: routing data (its Phase 1), the autonomous-operation block across twelve templates (its Phase 2), and the remaining behavioral guidance (its Phase 5). Writing these items into a later release would mean editing the same twelve templates and the same model map a second time for the other vendor's statement of the same behaviors. So each phase below names the main-plan phase it executes inside, and the sub-tasks are written so an implementer running the main plan can splice them in at the named point. Task ids continue from the main plan's last id (`T036`) so the two files can be fanned out to issues together without collision.

**What the amendments add.** One routing decision with quoted evidence (the vendor's models catalog and model guide disagree about `gpt-6-astra`'s availability on 2026-09-04, and the v4.4.6 guide plan and the v4.8.0 plan authored the same day disagree about mapping it). One template paragraph with a decision ticket in front of it, because the new disclosure rule sits next to a shipped rule that says the opposite for a different moment. Two citations and one example added to prompts the main plan already carries. Two wordlist lines. And one per-model profile, preceded by a schema decision, because the profile index records a single platform roster today and an OpenAI model verified against the Codex roster does not fit without one.

**What this plan does not do.** It adopts nothing model-specific into any template, command, or shared skill body: the seven API-level Astra items (`O13` to `O19` in the comparison) go only into the profile layer, per the `model-prompting-research` hard rail. It does not adopt the vendor's "parallelize whenever you can delegate" rule, which the catalog overrides by design. It adds no dependency, credential, registry entry, or runtime outbound call; the research pass fetches vendor documentation through the web tool the runbook already requires.

**Fable 5.1 re-check.** The comparison also re-checked the Anthropic prompting page against the 2026-09-02 report and found no delta, so this plan carries no Anthropic-sourced item; the main plan's routing of those seventeen insights stands.

**Prior known-gaps ingest.** `docs/releases/v4/v4.4/known-gaps.md` items are unrelated to this scope and carry forward unchanged. The v4.1.0 `DF-1` gap (OpenAI model ids unprofiled in the prompting layer) is directly addressed by Phase 3 here and should be closed or narrowed by it.

**Knowledge-base grounding.** No `docs/solutions/` store and no `STRATEGY.md` exist; grounding is the two comparison reports and the main plan.

**Objective**: Reconcile the shipped "Do not mention the skill lookup to the user" rule with the new disclosure rule before either is edited.

The GPT-6 Astra guide says that when a skill's guideline causes a pause or changes what the user asked for, the agent should name and link the exact SKILL.md and quote the instruction. Options: (a) keep lookup silent and disclose only when a skill instruction blocks, narrows, or alters the user's request; (b) disclose every skill load; (c) keep everything silent and rely on the user reading the skill index. Recommend (a), state the exact wording of the boundary, and record `## Alternatives considered`. This decision unblocks 2.2 and 2.3. ASCII only.
