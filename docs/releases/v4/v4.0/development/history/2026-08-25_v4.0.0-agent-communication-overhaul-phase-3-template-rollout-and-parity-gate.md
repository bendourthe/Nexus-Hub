## 2. Chronological Steps

### 2.1 Design the compact in-template contract

**Plan specification**: Sub-task 3.1. At most 90 words, compressing the contract to six testable behaviors, ending with a deep link. Verify against the budget headroom; trim first, relocate second, never raise a ceiling.

**What was done**: Drafted `## Communication Contract` at 93 words including the heading and the deep-link line. The six behaviors are compressed into five bullets, because the docs deep-link rule folds naturally into the plain-language bullet ("put detail beyond ~5 lines in a linked docs/ file") and splitting it into its own bullet cost words without adding a rule.

The 93-word draft was 1 word short of fitting `base-codex.md` and `base-gemini.md` on its own, and the plan also required amending the `End-of-Task Summary` block. See 2.2 for how that was resolved without raising a ceiling.

### 2.2 Roll out to all 12 substantive templates

**Plan specification**: Sub-task 3.2. Insert byte-identically into the lockstep five, the guardrails five, `base-google-shared.md`, and `generic-instructions.md`. Reconcile `generic-instructions.md`'s `## Response Format`. Amend `End-of-Task Summary`. Do not touch the four stubs. Leave the Read/Glob/Grep narration asymmetry alone.

**What was done**: A scripted insertion placed the identical section immediately after each file's existing communication bullets: before `## Critical Rules` in `base-claude.md` (which has a dedicated `## Communication Style` section), before `## Branching` in the nine files whose communication bullets close `## Working Conventions`, and before `## Consequential Decisions` in `base-google-shared.md` and `generic-instructions.md`, neither of which has a Branching section in that position. Every file moved by exactly +81 words, which is itself the evidence the edit was byte-identical.

**Budget resolution (the interesting part).** Adding the contract AND appending a labeled-parts bullet to `End-of-Task Summary` would have cost roughly +110 words against +94 of headroom. Rather than relocating words out of a non-invariant section (the plan's fallback), the `End-of-Task Summary` amendment was made subtractive: three overlapping bullets (`**Completed**: ...`, `**Next**: ...`, and `State blocked, skipped, or deferred work explicitly ...`) were replaced by one bullet naming all four labeled parts. That is a net saving of about 12 words, and it also removes a rule stated twice in adjacent sections, which the repository's own rule-ownership convention discourages. Net delta: +81 per file, leaving `base-codex.md` at +13 and `base-claude.md` at +52.

`generic-instructions.md` reconciliation: `## Response Format` keeps its three-part shape but now opens with one line scoping it to mid-task turns, with task-ending turns directed to the Completed / Verified / Open / Next report. The `## Global Style & Communication Preferences` section needed no change; it governs punctuation and tone, which the contract does not restate.

The four surface-note stubs (`base-antigravity-10.md`, `base-antigravity-20.md`, `base-antigravity-cli.md`, `base-gemini-cli.md`) were not touched, and a test asserts they stay untouched.

**Deliberate non-change**: the Read/Glob/Grep narration bullet still exists only in `base-claude.md` and `base-codex.md`. It is a Claude/Codex-specific verbosity control, not part of this contract, and it is left as it stands.

### 2.3 Extend the parity gate

**Plan specification**: Sub-task 3.3. Add the heading to `REQUIRED_HEADINGS` and `INVARIANT_SECTIONS`; add tests proving the gate fails on a seeded one-word divergence and passes on the real tree; confirm the guard needs no installer registration.

**What was done**: Added `"Communication Contract"` to both lists in `scripts/check_base_template_parity.py`, with a comment explaining why it belongs in both (same reasoning as `End-of-Task Summary`: platform-agnostic by intent, no legitimate per-platform variation).

Added two tests to `tests/validators/test_check_base_template_parity.py`, following the existing seeded-mutation pattern: a one-word reword of the report bullet in `base-cursor.md` must fail naming both the file and the section, and deleting the heading from `base-codex.md` must fail as a distinct finding. Both pass; the real-tree baseline test still passes.

`check_base_template_parity.py` was already in `DEV_ONLY_SCRIPTS` in `catalog/hooks/tests/test_installer_smoke.py`, so no installer copy step is needed and none was added.

### 2.4 Testing and stabilization

**What was done**:

- `python scripts/check_base_template_parity.py`: 5 of 5 lockstep templates in parity.
- `python scripts/validate_doc_budgets.py`: 8 budgeted docs within ceiling.
- Full `validate` target: all catalogs valid.
- `python scripts/validate_unicode_safety.py --strict`: clean across the repository.
- New file `tests/validators/test_communication_contract_rollout.py`: 21 tests, all passing. This is the aggregate coverage the plan asked for, written data-driven per the test-retention policy rather than as seven near-identical per-file tests. It asserts the heading and deep link in all 12; that the contract body is byte-identical across all 12 (stronger than the parity gate, which covers only 5); that the four stubs stay clean; that the `End-of-Task Summary` labeled parts reached every template carrying that block; and that the deep-link target exists with all seven contract sections.

The roster-completeness test is the load-bearing one: it compares the classified file list against the directory listing, so adding a new template fails the suite until it is classified as substantive or a stub. Without it, a future template could silently escape the rollout check, which is the same "silently ships a platform with the old behavior" defect class the phase exists to prevent.

- CI: the pytest suite is auto-discovered under `tests/`, so the new file needs no wiring. Confirmed, no CI edit.

## 3. Troubleshooting

**Word budget overrun.** Described in 2.2. Resolved by making the `End-of-Task Summary` amendment subtractive rather than additive.

**Test file syntax error.** The first write of the new parity test emitted a literal newline inside a Python string literal (a shell-quoting artifact), producing `SyntaxError: unterminated string literal`. Fixed by writing the escape correctly. Caught immediately by running the file.
