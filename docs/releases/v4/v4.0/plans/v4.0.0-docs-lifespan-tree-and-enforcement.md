# Plan - Docs Lifespan Tree and Enforcement

**Project**: Nexus-Hub
**Target version**: v4.0.0 (third member of the breaking bundle) - **CONFIRMED 2026-08-21**, see [Version classification](#version-classification) below
**Slug**: docs-lifespan-tree-and-enforcement
**Rank**: 15 of 17 in [`docs/roadmap-prioritization.md`](../../../../roadmap-prioritization.md)
**Plan Type**: Refactor (breaking, distributed)
**Created**: 2026-08-20
**Class**: Breaking - changes what an already-installed Nexus-Hub does on upgrade
**Goal**: Every supported agentic platform, on its next install, receives a docs-tree standard organised by one enforceable axis (document lifespan) plus the four mechanisms that make adopting it survivable - so a consuming project can reshape its docs tree and prove nothing broke, rather than asserting it.

## Overview

Nexus-Hub prescribes a docs layout today, but it prescribes it on a mixed axis. `docs-layout-refactor` resolves version-scoped artifacts by semver bucket (correct, and already two-level since v3.11.0) and then hands everything else to a **name allowlist** of roughly 55 recognised directory names, whose documented fallback is "when in doubt, treat a subtree as cross-cutting". That is a subject-shaped test: it works only for names someone already thought of, and its miss case is a junk drawer. Downstream, the mechanisms that would prove a reshape safe are described as suggestions - reference repair is a substitution pass, and link integrity is an absolute "all links resolve" check that no inherited repo can satisfy, so it gets waived exactly when it matters most.

This plan replaces the axis with a single admission test - **when does this document stop being true?** - which has exactly one true answer per document and is therefore answerable by someone who has never seen the repo. It renames the two container levels to match (`docs/releases/` and `docs/archives/`, a breaking `2.0.0` change to the skill's prescription, taken deliberately with a migration path), ports the four mechanisms that made the source refactor survivable, and then distributes all of it so it reaches every platform class Nexus-Hub installs into - including the guardrails-only platforms that receive no skills at all and would otherwise never see the standard.

The sequencing is the load-bearing design decision: **the mechanisms ship before the rename**, because they are what proves the rename did not silently drop files or break links. Phase 6 then migrates Nexus-Hub's own tree using the tool, which is simultaneously the migration and the acceptance test.

Success looks like: a consuming project can run one command to reshape its docs tree and receive a set diff proving zero newly-broken links; a `docs/releases/` file edited after its release closed is flagged automatically; an ADR can no longer be filed under a release; living `docs/handbooks/` stays at the docs root (edited in place, snapshotted into `docs/archives/v<M>/v<M>.<m>/handbooks/` at release close); and the standard is present on Claude, Codex, Cursor, Antigravity, Gemini, OpenCode, Qwen, Kimi, Hermes, Copilot, Aider, Windsurf, and OpenClaw after a single `nexus-hub upgrade`.

Living handbooks are not invented here. They are introduced by [`docs/releases/v3/v3.21/plans/v3.21.0-plan-implement-lifecycle-and-docs-architecture.md`](../../../v3/v3.21/plans/v3.21.0-plan-implement-lifecycle-and-docs-architecture.md). This plan consumes that equivalent at rename time rather than declining it.

## Design inputs (repo grounding, verified 2026-08-20)

### What is already correct, and must not be re-litigated

- `docs-layout-refactor` v1.3.0 already prescribes the two-level `docs/v<MAJOR>/v<MAJOR>.<MINOR>/` active tree and the matching `docs/archive/v<MAJOR>/v<MAJOR>.<MINOR>/` archive, with patch releases sharing a minor dir and full `vX.Y.Z` confined to filenames. Shipped v3.11.0 (`docs/archive/v3/v3.11/development/history/2026-07-07_phase-1-canonical-docs-layout-scheme.md`). `docs/versions/...` survives ONLY in the legacy-detection branch and the `--canonicalize-layout` source list.
- **Stale metadata, not stale design**: `data/skills.json`'s `long_description` for `docs-layout-refactor` still describes the pre-v3.11 `docs/versions/` + `docs/archive/versions/` shape, and the installed `~/.claude/CLAUDE.md` skill-index line inherits it. This is a live defect, and the reason an external reading of the delta over-counted the gap by two items. Fixed in Phase 3.6.

### What is genuinely wrong

- The cross-cutting-subtree rule in `docs-layout-refactor` is a 55-name allowlist plus a "when in doubt, treat as cross-cutting" fallback. Subject-shaped, with an unbounded miss case.
- `documentation-consistency` gates on an absolute "All internal links verified and working" and reports `len(broken_links)` - a count. A count holds level while one link breaks and another is fixed, and the absolute form is unsatisfiable on any inherited repo, so it is waived.
- `docs-layout-refactor` step 9 (reference repair) is a substitution pass with no resolution proof. `project-refactor` has a copy+verify+delete protocol but **no `.gitignore` pre-flight**.
- `known-gaps-tracker` steps 4 and 6 say *recompute* the summary table; nothing asserts it sums. Hand-tallied tables were wrong twice in the source refactor.
- `session-history` declares **no output path at all** - the actual defect, rather than a wrong one.
- `architecture-decision-record` writes only to `docs/adr/` and has no rule against release-scoping. Separately, this repo's own AGENTS.md mandates records at `docs/decisions/<lifecycle>/<class>/` and **no skill knows that path exists**.
- `verification-before-completion` has a `Docs-only edit` evidence row but no claim row for "references repaired".

## Phase 1: Enforcement mechanisms (non-breaking)

**Why first**: these mechanisms are what proves Phases 3 and 6 did not silently drop a file or break a link. Shipping the rename before the proof would be exactly the failure this plan exists to prevent.

**Recommended model tier**: strong | **Recommended effort level**: high

**Rationale**: well-specified mechanisms with a known reference implementation. The difficulty is in the edge cases (directory links, binary files, symlinks), not the design.

### 1.1 - Link-set baseline and set diff

**Prompt**: Create `catalog/skills/code-cleanup/docs-layout-refactor/scripts/link-baseline.py` (stdlib-only, matching the existing `audit-docs.py` house style) with two subcommands. `baseline --root . --out <file>` walks every tracked Markdown file, extracts relative links (skipping `http`, `mailto`, and bare `#` anchors), resolves each against its containing file, and emits the **set** of unresolved links as sorted NDJSON of `{source, link, resolved_target}`. `diff --before <a> --after <b>` compares the two sets and reports three disjoint sets - `newly_broken`, `fixed`, `unchanged` - plus totals, exiting **1** if `newly_broken` is non-empty and **0** otherwise. Print absolute totals as context, never as the gate. Add a `scripts/link-baseline.ps1` sibling per the AGENTS.md `.ps1`-parity rule, preferring native cmdlets (`ConvertFrom-Json`, and `[System.IO.File]::WriteAllText` with `UTF8Encoding($false)` to avoid the PowerShell 5.1 BOM). Reference both by basename from SKILL.md so the orphan-bundle audit passes. No installer edit is required, because per-skill `scripts/` is recursively copied.

### 1.2 - Rename-map repair

**Prompt**: Create `catalog/skills/code-cleanup/docs-layout-refactor/references/link-integrity.md` documenting the repair algorithm as a Tier-3 reference: run `git diff --name-status -M` to obtain the rename map, resolve each broken link against the source file's **pre-move** location, then re-express it from the post-move location. State explicitly that git tracks **file** renames only, so links pointing at a directory need a separate pass keyed on a directory-prefix map. Include the concrete failure this replaces: hand-counting `../` depth produced 30 dead links on the first attempt in the source refactor. Then rewrite `docs-layout-refactor` Step 9 to invoke this reference and the 1.1 scripts as a REQUIRED gated step, and replace its Verification item "No broken internal markdown links" with "`link-baseline.py diff` reports zero `newly_broken` against the pre-move baseline".

### 1.3 - The .gitignore pre-flight

**Prompt**: Add a `### .gitignore pre-flight` subsection to `catalog/skills/code-cleanup/project-refactor/SKILL.md` under `## Safe Move Protocol`. Explain the mechanism precisely: a bare directory pattern (`test-results/`, `data/`) matches at any depth, and files beneath it stay tracked only because git ignores *untracked* files - so the moment a rename makes them untracked at a new path, `git add -A` skips them while the old paths stage as deletions, producing a clean-looking rename that silently drops files. Mandate the check: for every staged deletion with no paired addition, run `git check-ignore -v` on the **new** path. State the fix rule: re-include the **directory** before its contents, because git cannot re-include a file whose parent is excluded. Add one Verification checkbox and one Common Rationalizations row citing the concrete failure mode - it fired three times in one release in the source repo and would have deleted three validation records.

### 1.4 - Documentation claims need documentation evidence

**Prompt**: In `catalog/skills/workflow/verification-before-completion/SKILL.md`, add one row to the Claim-to-Evidence table: claim "References repaired", proving command `link-baseline.py diff --before <baseline> --after <current>`, evidence "zero `newly_broken` and a zero exit code; a completed search-and-replace is not evidence that links resolve". Add one row to `### Change surface to evidence` for a docs-tree move (set-equality of the pre-move inventory against destinations, plus the link set diff). Add one fraud class to the Anti-Costume-Rigor audit: **repair claimed from the substitution rather than the resolution**, whose mechanical tell is a report citing a replacement count with no post-move resolution receipt.

## Phase 2: Lifespan axis (non-breaking)

**Recommended model tier**: frontier | **Recommended effort level**: high

**Rationale**: replacing a project's decision axis is the highest-leverage and least-reversible judgment in the plan. Getting the admission test's boundaries wrong, especially the controlled-record and generated-output classes, propagates into every consuming repo.

### 2.1 - The admission test

**Prompt**: Add a `## Lifespan admission test` section to `docs-layout-refactor/SKILL.md`, placed **before** the cross-cutting-subtrees section. State the single question - "when does this document stop being true?" - and why it is enforceable: it has exactly one true answer per document, and it is answerable by someone who has never seen the repo. Contrast it explicitly with the subject-based alternative and why that was rejected: "is this about development?" has no false answer, so the bucket absorbs anything and needs reorganising again within a year. Then give the disposition table: **living** (never stops being true; edited in place; must never describe a past state), **append-only** (stops on supersession; the superseded record is kept), **frozen-at-close** (stops at release close, then moves with its shape preserved), **controlled record** (never, because it is a record; never edited after signing; never archived by tooling), **already-frozen**, and **generated** (regenerable, bound by a drift test, never archived).

### 2.2 - Demote the allowlist to a fast path

**Prompt**: Rewrite the `## Cross-cutting documentation subtrees` section so the 55-name table is explicitly a **lookup fast path** over the admission test, not the rule. Replace the current fallback - "when in doubt, treat a subtree as cross-cutting" - with this: an unrecognised subtree is classified by answering the admission test for its contents, and only a subtree whose answer is genuinely indeterminate falls back to the Cat 3 leave-in-place floor. Keep every existing hard floor intact (signals 2 and 6, the Cat 3 floor, and generated-output handling). Update Edge Case 11 to reference the test rather than the name list.

### 2.3 - Signal 9: lifespan contradiction

**Prompt**: Add signal 9 to the Step 4 heuristics table: **lifespan contradiction**, a document whose location contradicts its edit history. The canonical case is a file under a frozen-at-close bucket (`releases/v<M>/v<M>.<m>/`, or `docs/v<M>/v<M>.<m>/` pre-rename) whose newest commit post-dates that release's close, determined from `git log -1 --format=%cI -- <path>` against the release tag date. Emit these into a new `## Lifespan contradictions` section of the cleanup report with the file, its bucket, the release close date, and the offending commit date. This is a **finding, never an automatic move** - the correct resolution is sometimes to relocate the file and sometimes to revert the edit, and the skill cannot tell which. Per the user's decision, mirror this as a standalone check in `catalog/skills/workflow/documentation-consistency/SKILL.md` so it is reachable without a full refactor run; factor the rule into `references/link-integrity.md` and have both skills cite it, so there is one definition rather than two that drift.

### 2.4 - Snapshot naming

**Prompt**: Add the snapshot-naming convention to `docs-layout-refactor/SKILL.md` and `references/archive-layout.md`: a per-release snapshot is named for **the version the content describes**, not the release that prompted the snapshot. Include the concrete failure it prevents - taking the snapshot before applying a release's changes and naming the folder after that release produces an archive directory whose name asserts one version while its content is another, which an auditor reasonably misreads and no explanatory README repairs. Bump the skill to **1.4.0** at the end of this phase; it is still non-breaking.

## Phase 3: Breaking rename of the prescription

**Recommended model tier**: frontier | **Recommended effort level**: max

**Rationale**: the only phase whose output is irreversible for downstream consumers. Roughly 30 artifacts must change consistently, a path parser must change with them, and the migration path must work on a repo the author cannot inspect.
