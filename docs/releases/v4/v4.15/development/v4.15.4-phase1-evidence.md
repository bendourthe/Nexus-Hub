The preservation rule inspects both lexical and resolved paths for a case-insensitive `evidence` directory. Ordinary repair revalidates the inspected file identity, resolution, and bytes immediately before atomic replacement. A changed target is refused and the temporary replacement is removed.

## Limits

This is a directory-convention guarantee. Captures under `development/`, standalone terminal logs, archives without an `evidence` component, and receipts stored elsewhere are not automatically protected by this Unicode rule. An outside hard-link alias can be replaced, while the protected original remains byte-identical; this is not a claim of inode-wide immutability. File-symlink controls require POSIX or a Windows host with symlink permission at terminal qualification. The identity check detects observed changes before replacement and is not an OS compare-and-swap filesystem primitive.

Ruff reports two unchanged baseline findings: SIM103 in the existing `is_text_file` return and I001 in the pre-existing test import block. Both findings were reproduced on the original `HEAD` blobs through Ruff's stdin interface. No new lint finding was introduced and no unrelated cleanup was applied.
