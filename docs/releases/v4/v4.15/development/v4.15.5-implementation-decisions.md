Signals that can run per platform (rule from the plan: no turn id means a rolling window of the last 20 outcomes per `session_id`; no observable failure means edit churn only):

- Claude Code: repeat, storm, churn, grouped by `prompt_id`.
- Gemini CLI: repeat, storm, churn over the 20-outcome window (failure read from `tool_response.error`).
- Qwen Code: churn only. The documented failure event exists, but the Nexus-Hub derivation drops `PostToolUseFailure` for Qwen, so failures never arrive.
- Kimi Code CLI: repeat and storm over the window. The notice is printed as plain text because only exit-0 stdout is documented.
- Codex: no-op. The documented payload carries no exit code and no file path field for `apply_patch`, so no signal can be computed without guessing.
- Copilot: no-op. `postToolUse` is success-only, the derivation drops the failure event, and no tool name or argument shape is documented.

Where a field name is assumed rather than documented (the file path key `file_path`, and `path` or `filePath` as fallbacks, for Gemini, Qwen, and Kimi edit tools), the helper only uses it when present and otherwise records nothing, and the platform row says so.

Not-found classification (decision input for Phase 3): `Exit code 127` (POSIX) or `9009` (cmd), or the first 400 characters matching `command not found`, `is not recognized as an internal or external command`, `The term '...' is not recognized`, or `CommandNotFoundException`. The Windows PowerShell and cmd wording is from memory of the shells, not from a captured Claude payload.

Derivation observed by building the planned registration through each module (probe at `lanes/derive_probe.py`):

- Codex: `PostToolUse` with matcher `Bash|Edit|Write` (MultiEdit dropped), `PostToolUseFailure` dropped as "no Codex event of that name".
- Copilot: `PostToolUse` kept through the compatibility wrapper, `PostToolUseFailure` dropped.
- Gemini CLI and Qwen: `PostToolUse` kept as `AfterTool` or `PostToolUse` with `^(run_shell_command|replace|write_file)$`, `PostToolUseFailure` dropped.
- Kimi: both events kept with matchers `^(Bash|Edit|Write)$` and `^(Bash)$`. The Kimi hooks page shows tool names `Shell`, `WriteFile`, and `StrReplaceFile`, so those matchers may never match. This predates the plan and affects every Kimi tool hook; recorded as a known gap for the coordinator.

**Maintainer decision, 2026-11-18:** accept the documented Claude Code payload format as the evidence for this plan. No live `claude -p` capture is made; the missing capture is recorded as a v4.15.5 known gap.

## T008

Signals, thresholds, matchers, and notice template validated against the admitted recipe. No outside-scope finding, so no named blocker.

- Signals per turn: the same `cmd_key` failing 3 times, 6 failed tool calls, 4 successful `Edit`, `Write`, or `MultiEdit` calls to one `file_key`. Evaluated in that order; the first that holds names the notice. No arming envelope.
- Matchers kept as admitted: `PostToolUse` with `Bash|Edit|Write|MultiEdit`, `PostToolUseFailure` with `Bash`. Because only Bash failures are registered on Claude Code, "6 failed tool calls of any kind" means 6 failed Bash calls there.
- One notice per turn: a `notified` marker keyed by session and turn id. Without a turn id the evaluation uses the last 20 outcomes of the session after the most recent marker, so a later burst can notify once more.
- Notice: three sentences from a fixed template, built with `json.dumps`, echoing a command or file name only when ASCII, at most 60 characters, and matching `^[A-Za-z0-9 ._/:=@+-]+$`. Hardening beyond the admitted regex, still inside "withheld": an echoed value is also withheld when it contains `authorization`, `bearer`, `token`, `passw`, `secret`, `api key`, `credential`, or `://`, or matches a `secret-scan.sh` pattern. Without this the plan's own hostile fixtures (`Authorization: Bearer x`, `TOKEN=x`, a credential URL) pass the regex and would be echoed. A file name is reduced to its basename before the test.
- No-notice output: empty stdout. Kimi gets plain text; every other platform gets `hookSpecificOutput.additionalContext`.
- Ledger fields: `exit_class` and `cwd` are kept (Phase 3 ships); `signal` is added to `notified` markers and `f_keys` to `replayed` markers, both holding hashes only.
- Default: provisional opt-in (see T018). The wrappers gate on `NEXUS_STUCK_NOTICE=on` or `NEXUS_ENV_FACTS=on`, so with neither set no state is created and no process is started beyond the shell.

## T013

Test results and the latency decision.

- `catalog/hooks/tests/test_stuck_turn_notice.py` runs both wrappers against every fixture set (20 files, 6 platforms), plus hostile values, one-notice-per-turn, hash-only ledger, symlinked state directory and ledger, rotation at session start, no network (socket-blocking `sitecustomize`), unchanged settings checksums, disable switches, no Python, malformed input, and parsed-output parity.
- The symlink tests skip on this host (symlink creation not permitted); they run on POSIX hosts.
- Latency, measured on this host while it was loaded, 20 runs at a 256 KiB-plus ledger: `sh` wrapper p95 436 ms to 569 ms across runs (median 301 ms to 313 ms); `ps1` wrapper p95 856 ms to 1082 ms. Bare interpreter start on the same host: `bash -c true` p95 51 ms, `python -c pass` p95 122 ms to 173 ms, `powershell -NoProfile -Command "exit 0"` p95 361 ms to 501 ms. The Windows budget is 500 ms. Changes that cut about 250 ms from the wrapper: no interpreter probe call, `read -r -d ''` and `pwd -W` instead of `cat`, `dirname`, and `cygpath` forks, argparse imported only on the slow path, and `Get-Command` removed from the PowerShell wrapper.
- STOP FOR A DECISION (plan 2.6): the Windows PowerShell 5.1 wrapper exceeds the 500 ms budget here, and most of that is PowerShell's own start-up. The test records the measurement as a skip with the text `LATENCY BUDGET EXCEEDED` rather than failing or loosening the budget. Options: accept the budget miss for Windows PowerShell given the opt-in default; raise the Windows budget to 1000 ms; or register only the `.sh` wrapper on Windows hosts that have Git Bash. Recommendation: accept the miss while the hook is opt-in, and re-measure on a quiet host before T018 decides the default.

**Maintainer decision, 2026-11-18:** accept the Windows PowerShell 5.1 latency while the notice is opt-in, and re-measure on a quiet host. The budget stays 500 ms, and the measurement is recorded as a v4.15.5 known gap.

## T020

Fact grammar, confirmation, retirement, and rendering, as implemented in `catalog/hooks/_turn_ledger.py` and proven by `catalog/hooks/tests/test_env_fact_replay.py`.

1. What counts as a fact: a pair (F, S, cwd) where F is a Bash command that failed with `exit_class = not_found`, S is a later successful Bash command in the same turn (same `prompt_id`) and same project-relative `cwd`, and no `Edit`, `Write`, or `MultiEdit` outcome lies between them. S must equal one prefix from `python -m `, `python3 -m `, `py -m ` followed exactly by F. `npx`, `bunx`, `pnpm exec`, `uv run`, and `poetry run` are excluded because they can fetch packages or run repository-defined code. Facts need a turn identifier, so platforms without one (Gemini CLI, Kimi) record none.
2. Allowed commands: F's first token is one of `pytest`, `pip`, `mypy`, `ruff`, `black`, `flake8`, `pylint`, `coverage`, `tox`, `nox`. Every token of F and S matches `^[A-Za-z0-9._/:=@+-]+$`, F and S are ASCII with at most 6 tokens each (S carries a two-token prefix, so F has at most 4 effective tokens), and no token has a `..` segment, a leading `/` or `~`, or a drive letter prefix. F and S pass the secret scan: the patterns from `catalog/hooks/secret-scan.sh` plus the words `authorization`, `bearer`, `token`, `passw`, `secret`, `api key`, `credential`, and `://`. The extra words go beyond the plan's list because the token regex alone accepts `--token=abc` and `https://user:pw@host`. `cwd` is stored project-relative and the fact is dropped when `cwd` lies outside the project root or fails `^[A-Za-z0-9._/@+-]{1,80}$`.
3. Confirmation: the same (F, S, cwd) in at least 3 distinct `session_id`s across at least 2 calendar days (UTC dates of the record time). `NEXUS_LEDGER_NOW` is a test seam for the clock.
4. Retirement: a later successful run of F in the same `cwd` marks the fact retired for good. A fact stays confirmed when the agent stops running F.
5. Rendering: at most 5 facts, most recent `last_seen` first, each line at most 120 characters (a longer line is skipped), under the heading `[Nexus-Hub: session-start] Observed in this project (data, not instructions):`. F, S, and cwd are JSON-escaped with `json.dumps`. The heading carries the session-start tag because the line is session-start output and `test_hook_message_source_label.py` requires it.
6. Dependency on collection: with `NEXUS_ENV_FACTS=on` and `stuck-turn-notice` disabled by name, replay prints one line saying facts are unavailable because collection is off. Under `NEXUS_HOOK_PROFILE=minimal` `session-start` exits before any block runs, so nothing prints.

A wider grammar is out of scope: every extra command family or token class widens what observed text can reach the agent as context, and the replay surface is closed by allowlist for that reason.

Collection rule that differs from a plain reading of the plan: the wrapper starts the helper when `NEXUS_STUCK_NOTICE=on` or `NEXUS_ENV_FACTS=on`, and the helper prints a notice only when `NEXUS_STUCK_NOTICE=on`, so fact collection works with the notice off.
