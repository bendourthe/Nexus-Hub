# v4.15.2 Claude AGENTS.md Evaluation

Summary: the synthetic before-and-after measurement of the old Claude project layout (a managed `CLAUDE.md`) against the supported layout (shared `AGENTS.md` plus a `.claude/rules/` sidecar), run through the Phase 3 evaluator, with the v4.13 skill-index decision (DF-1, tracked in the v4.15 ledger as DF-6). Read this for the release-gate figures and for what remains `needs-live-validation`.

**Version**: v4.15.2
**Evidence class**: synthetic only. No provider was called and no live Claude session was run (the spend cap for this run is USD 0).

## Layouts compared

Both layouts were produced by installing the real `ClaudeIntegration` into throwaway workspaces with `NEXUS_HUB_CLAUDE_VERSION` fixed (2.1.270 for the old layout, 2.1.281 for the supported layout), the full skill index, and no organization bundle. The rendered files were measured with `scripts/measure_rendered_context.py` (the one token estimator).

| Layout | Files Claude reads at session start | Bytes | Estimated tokens |
|---|---|---|---|
| Old: managed project `CLAUDE.md` | `CLAUDE.md` | 81,944 | 18,453 |
| Supported: shared project `AGENTS.md` plus Claude-only sidecar | `AGENTS.md` (79,953 B, 17,916 tokens) and `.claude/rules/nexus-hub-claude.md` (2,008 B, 522 tokens) | 81,961 | 18,438 |

The supported layout is 17 bytes larger (+0.02 percent) and 15 estimated tokens smaller (-0.08 percent) than the old one: a wash, as expected for a move of the same text between files.

## v4.13 DF-1: the skill-index default

Decision: **left open under this plan**. The required `NEXUS_HUB_SKILL_INDEX=full` against `pointer` pair exists as a synthetic receipt (Phase 3): the pointer variant cuts the instruction payload from 408 to 36 estimated tokens on the fixture pair (a 91.2 percent reduction), and the real rendered files above show the index is the bulk of each file (340 index rows in each rendered file). But organic skill selection, including guard skills such as `security-review`, is `unavailable (needs-live-validation)`: synthetic adapters load no skills. A synthetic receipt cannot flip the default, so the pointer stays opt-in.

Missing evidence, named: a live paired run in which a real harness sees only the pointer and still selects the skills it selects when it sees the table, at a predeclared gate (guard skills included), under `metered-live` mode with a proven isolation backend. Owner: this plan carries it forward; next step for the next owner is to run that pair when an isolation backend and a hard spend limit exist.

## Reproduction

The measurement and the evaluator run are scripted from the repository: install `ClaudeIntegration` into two temporary workspaces with the version variable set, measure the rendered files with `scripts/measure_rendered_context.py --path FILE --json`, and run `scripts/evaluate_harness_pairings.py run` over a manifest whose two pairings point at those files. The test suite covers the same boundary (`tests/installer/test_verify_read_paths.py`, `tests/integrations/test_harness_pairings.py`).
