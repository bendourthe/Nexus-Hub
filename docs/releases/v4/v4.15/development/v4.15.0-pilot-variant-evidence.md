## Behavior

The paired `--instruction-full-index` and `--instruction-pointer` flags select instruction mode. Arm A receives the first file as `CLAUDE.md`; arm B receives the second in a separate directory. All four sampled skills use the same prevalidated original byte snapshots in both arms. The description variant file is not loaded in this mode. The labels are caller declarations, not semantic certification that a Markdown document contains a complete index or an effective pointer; links and includes are not followed by preflight.

Instruction mode requires exactly one of `--stage-only` and `--run`. Missing pairs, no action, and combined stage/run actions refuse before output creation or CLI discovery. Stage-only needs no Claude installation. The new live instruction path requires explicit `--run`; the existing description-mode invocation remains compatible without that new flag.

Before writes, preflight snapshots both readable regular Markdown files and all four skill files. Each bounded read permits at most 2 MiB, verifies file identity and change metadata around the read, rejects links and reparse ancestry, validates UTF-8, and rejects blank, BOM-only, NUL-containing, identical-source, or identical-byte instruction arms. Outputs must be fresh and separate, with directory ancestors and no input/output containment. Snapshot bytes are staged even if the caller changes an input after preflight.

New fixture creation uses `mkdir(exist_ok=False)`. Initial instruction receipts use exclusive file creation rather than replacing a path that another process claimed after preflight. The fixture path stays lexical, with a fresh link check before the claim, so an inserted dangling fixture link cannot redirect creation. These are bounded path and ownership controls, not an OS sandbox or protection against every possible concurrent ancestor replacement.

Stage-only receipts contain instruction and skill SHA-256 hashes, no source paths or raw instruction contents, `staging_complete: true`, `complete: false`, `measurement_status: UNMEASURED`, zero calls, zero spend, and no results. Invalid inputs and output failures use fixed diagnostics. A late staging or receipt failure can leave the new experiment's partial fixture or incomplete receipt for inspection; it does not delete competing outputs or report a completed measurement.
