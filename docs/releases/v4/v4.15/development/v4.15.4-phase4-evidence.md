# Archive and Controller Boundaries

Summary: v4.15.4 Phase 4 local evidence for operational archive preflight and read-only controller diagnostics. Read this before archiving supported inputs or integrating the worker. Covers refusal and owner repair, captured bytes, bounded inventory, source compatibility, and remaining candidate gates.

## Archive Behavior

Before preview and again after the successful Markdown-link baseline, the existing archive transaction inventories tracked inputs and refreshes the tracked-file list immediately before its first move. Supported operational references are repository-relative JSON strings and path-map keys, canonical relative/slash forms, handbook input/output/evidence paths, and literal or glob .gitattributes selectors rooted at the moved tree. Unresolved supported live references refuse movement with a repository-relative location, line/key, classification, and owner-input remedy. Embedded JSON mentions are explicitly unverified. Historical captures and code/Markdown mentions are reported separately. The inventory never repairs a JSON input or attribute selector.

The child uses isolated Python startup and the existing archive command's remaining budget. Reads are bounded to two MiB plus one detecting byte. A file exceeding that bound, an unreadable or changed input, invalid UTF-8/JSON, a symbolic link, or a Windows reparse ancestor makes inventory incomplete and refuses movement. Native junction detection uses lstat attributes and does not require Python 3.12's Path.is_junction. At most 100 sorted findings are displayed; full totals and display_omitted remain available when classification completes. Display truncation alone is distinct from incomplete inventory. newly_broken describes the Markdown-link comparison only.

Raw captures and machine-readable receipts retain their bytes, including files whose suffix resembles a program under an evidence directory. Existing authored Markdown navigation repair remains transactional. The established live source-string exception is retained only for nonhistorical program files under scripts/ or tests/: .py, .sh, .ps1, .psm1, .js, .mjs, .cjs, and .ts. Python comments and triple-quoted docstrings are masked with standard-library tokenization; other suffixes use conservative quoted/comment spans. No new source path or suffix becomes repairable. JSON, YAML, TOML, CSV, plain text, attributes, and raw captures are outside that source repair.

## Controller Behavior

Explicit detail from a verified sibling controller reports mutation-controller-mismatch without adopting its authority. Distinct clones, even with the same push URL, are unrelated. Foreign remotes, changed records, unavailable controllers, competing authorities, and unverifiable input disclose no trusted scope. A previously valid signed record whose controller has actually been removed reports sanitized controller-unavailable rather than falsely alleging tampering. The native Windows short-name alias resolves to the existing controller without a rekey or record write.

Final review reproduced forced-verdict loss when a valid BLOCKED or PAUSED record appeared beside more than 32 candidates. The collector now derives that verified state before returning the capped result, rechecks its bytes, and preserves its original exit with incomplete=true, scanned/omitted counts, and empty findings. An unforced capped inventory still cannot disclose controller scope. Direct-tamper precedence and earlier timeout/import-isolation controls remain covered.

Later growth controls reproduced unbounded reads of a record, a ledger, and the final record recheck after the initial size observation. The existing record and ledger readers now accept an optional max_bytes, unused by their ordinary callers. Detail requests a two-MiB physical bound plus one detecting byte, reuses the existing authenticated MinorSnapshot hash, and performs a bounded final hash comparison. Oversized or unreadable input is unavailable, not a claim of HMAC failure. Signature, provenance, controller, and frozen-plan verification still use the existing validators.

## Qualification Limits

The initial operational parser does not claim arbitrary-language syntax, arbitrary JSON prose interpretation, every possible Git attribute pattern, or universal reference completeness. Supported text suffixes are the existing source/config set plus Markdown, HTML, log, and XML. Unsupported embedded references stay visible for owner review. Filesystem checks sample containment/identity and do not provide a hostile concurrent-mutation sandbox. No real maintained handbook fixture exists in the throwaway archive repository; the actual refreshed candidate still requires check_handbooks.py and rendered/source evidence. Focused and subsystem receipts do not replace the complete local profile, installed-copy, POSIX, handbook, independent review, Tier 3, or remote integration gates.
