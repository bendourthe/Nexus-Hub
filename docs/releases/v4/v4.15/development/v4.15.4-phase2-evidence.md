# Portable Input Compatibility

Summary: v4.15.4 Phase 2 observations for exact release headings and canonical ledger roots. Read this before evaluating a consumer's release evidence or refreshing the publication candidate. Covers supported formats, malformed input, containment, and platform aliases.

## Changes

The changelog predicate now accepts exact requested bracketed versions in H1 or H2 headings, optionally linked and followed by dates or titles. It reuses the existing CommonMark fence mask, rejects prefix collisions, malformed links and H3 examples, and reports undecodable or unreadable input as unverifiable. Tag, hosted-release, and other publication predicates remain separate.

Ledger discovery canonicalizes its root once, verifies containment before reading a discovered ledger, preserves the lexical layout identity, and reports unreadable or escaping entries rather than dropping them. A missing or nondirectory root produces an explicit unavailable observation. Existing legacy layouts and parse problems retain their prior policy.
