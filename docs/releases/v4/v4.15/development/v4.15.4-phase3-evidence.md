## Behavior

`record block --minor ... --category approval-not-covered --approval-class gap-migration --item <minor#gap>` validates requested canonical items against readable ledgers and frozen migration coverage. Unknown, malformed, unverifiable, and all-covered requests are refused. An uncovered list is retained in the blocker request; the frozen approval text and signature remain unchanged. Schema-1 item selection is unavailable.

`check-minor --detail` and `minor_close.py status --detail` run only local observation in an isolated Python child process. They never call completion evaluation, render a decision, consume an approval, or query hosting. Established blocked/paused/tampered verdicts remain first with their original exits. Other local observations cannot prove completion. The default command path is unchanged.

The child has a ten-second total cap, at most 32 candidate records, two MiB per inspected record or ledger, and 100 displayed findings. Output retains scanned/omitted counts and full finding totals. An omitted candidate prevents trusted scope disclosure because it could hide competing ownership. Display truncation is distinct from incomplete classification. Record-byte changes invalidate collected detail. Authenticated controller discovery reuses Git common-directory, remote/repository, and frozen-plan bindings without transferring authority.

Approval summaries now label open problems as `Open gaps in scope`. A zero-task phase contributes no build time, a release-only estimate is labeled separately, and malformed task counts fail validation. Existing approval paste templates and signing inputs are unchanged.
