## Native Interface

The action is `permit-member-execution-paths`, rendered and consumed through the existing `record` interface with an exact member and `--execution` JSON file. That file contains only `write_paths`. Native code derives kind and role from the closed table and derives a registration recipe from exactly one `### Native Execution Registration Recipe` section in the frozen plan. The recipe is one fenced JSON object shaped as `{"hooks":{"Event":[FULL_GROUP]}}`; no caller-supplied role, kind or recipe override qualifies.

Accepted permissions use one append-only signed history and a separate explicit execution protocol. A dormant implementation permission may be re-captured for a moved or rebased worker; only the worker identity may change, and the latest entry is effective. Granted workflow and pre-commit files are limited by path only, so the page tells the user their content needs review before merge. A worker permission stays dormant until ordinary clean implementation admission. Coordinator permission stays dormant until ordinary ordered publication admission. The exact temporary `ci-security-change` authorization view borrows no parent policy and cannot promote an unknown or downgraded host mode.
