## Functional routing exercise

The changed skill was read and applied in the current agent session, with no nested model session, provider inference request, credential discovery, or runtime adapter. The prompt was: "For claude-opus-5 on a long-running coding plan, should I change harnesses to save cost?" Repeated work makes context/retry overhead a material consideration, but no workload-specific overhead measurement is assumed.

The observed answer was: "claude-opus-5 is unmeasured for this model; verify before assuming. Cost and task-quality outcomes for the proposed pairing are both unknown, so no ratio or cheaper default is justified. The current host remains unchanged; an alternative harness is advisory for a future session."

This is the skill's actual in-session recommendation boundary, not a statistical model-quality trial or proof of a host's scriptable switching surface. No harness switch, current model switch, or cost saving is claimed. With unavailable matching evidence, the unknowns remain explicit rather than being filled from a neighboring model or generation.
