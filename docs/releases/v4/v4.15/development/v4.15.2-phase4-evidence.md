## Plan delta

Disposition: Wrong (two vendor facts) and Incomplete (claims), non-blocking.

- **Plugin ID changed.** The plan names `agents-md@builtin`. The vendor page fetched today says the ID is `cc-plugin-agents-md@builtin` from Claude Code v2.1.285, with `agents-md@builtin` as the earlier ID and v2.1.285 and later reading either. The probe reads both and treats differing values under the two IDs as a conflict (unknown, `CLAUDE.md`).
- **Residual differences.** The plan recorded eight; the vendor memory page lists three, plus nested-file loading on a text Read. Only sourced items are published.
- **Roster tests and fingerprints fall outside the admitted claims.** A new file in `templates/ai-instructions/` fails five roster tests and the legacy-fingerprint test. The plan's task list does not name them. They are verified coordinator patches, not worker edits.
- **`check_installer_smoke.py` falls outside the claims** (v4.15.6 also writes it). Same treatment.
- **Latent defect fixed on the way.** `InstallManifest.all_keys()` lists only integrations with tracked files, so a consumer that tracks only a shared instruction file was invisible; consumer discovery now reads the serialized shared map. A second latent issue in `harness_audit.py::_has_marker` (wrong marker spelling) is pre-existing and recorded, not fixed.
- Consequence for Phase 5: the final gate on this branch is red on the six roster tests until the coordinator applies the delta; Phase 5 records that and verifies green with the delta applied locally.
