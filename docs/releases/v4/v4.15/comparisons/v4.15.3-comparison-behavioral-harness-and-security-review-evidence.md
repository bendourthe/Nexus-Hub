### Evidence Package

The proposed package references existing evidence instead of duplicating it. Where the underlying record already has a field, the consumer carries that field through.

- Finding ID, target revision, affected component, location, and trust-boundary assumptions.
- Existing disposition and separate severity/confidence; an explicit distinction between candidate, statically supported, and observed reproduction evidence.
- Reproducer or proof reference, environment/tool versions when material, exact command when executed, expected vulnerable/safe outcomes, and observed result artifact.
- Root-cause/duplicate/chain references where relevant; candidate fix and optional introduction commit with its evidence or an explicit unknown.

Static analysis may establish a finding without executing an exploit. Runtime evidence is required only for a claim that execution occurred. A missing environment leaves an explicit pending step; it does not establish safety. References and checksums support integrity and traceability, but cannot prove that a recorded observation happened.

`/review` continues to leave the target unchanged. It may describe a reproducer or consume supplied evidence. Any execution requiring scratch artifacts, elevated access, network targets, or remediation follows the separately authorized verification workflow and its isolation owner. Comparing these articles authorizes none of those runs.

### Cadence Experiment

Reuse v4.15.2's planned evaluator, budgets, immutable receipts, isolation, and independent outcome grader. Compare development-time feedback with final-gate feedback across a locally chosen model/workload matrix; keep the final acceptance bar identical. Include representative integration boundaries, not just syntax or unit checks.

Freeze the requirements, examples, grader, permitted repair policy, budget, and stopping rule before trials. Record initial acceptance separately from acceptance after repairs, all failed attempts, feedback/repair rounds, elapsed time, token use, and measured or estimated spend with provenance. Preserve v4.15.2's repeat and uncertainty requirements; a small pilot supports a bounded decision, not a universal reliability claim.

Report aggregate spend divided by accepted artifacts only when the denominator is nonzero, alongside acceptance counts and uncertainty. This descriptive ratio is not a forecast of retry cost. Track authoring/maintenance labor separately when available, and do not silently count missing labor as zero. Choose a default only if predeclared quality and cost criteria pass; otherwise retain the existing focused-check/final-gate policy. Do not weaken security, data-loss, or final acceptance gates based on a model label.
