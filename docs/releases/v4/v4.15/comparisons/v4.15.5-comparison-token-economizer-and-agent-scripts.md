# Comparison: Learned Token Economy and Agent Operations Scripts

**Adoption target: v4.15.5**

**Sources**:

1. TokenEconomizer, <https://github.com/microsoft/TokenEconomizer>, commit `1b02972` (2026-11-05), version 0.1.0, Apache-2.0. A hook-based plugin from Microsoft Research and UC Berkeley that learns from finished sessions in one repository and lowers token spend in later sessions through three switchable mechanisms: learned one-line repository facts ("micro-skills"), pruning of unused tool schemas, and a turn-length envelope with a stuck-agent redirect.
2. agent-scripts, <https://github.com/steipete/agent-scripts>, commit `d210c0a` (2026-10-30), version 0.12.0, MIT. One maintainer's personal operations pack: a shared `AGENTS.MD`, 54 in-repo skills plus 15 symlinked ones, a symlink-based skill sync script, Codex delegation helpers, and macOS fleet tooling.

**Source types**: both are Git repositories. The 11-dimension comparison is applied, focused on the dimensions that carry a real difference (AI configuration, skills, hooks, security posture, developer experience).
**Authored during**: v4.14 closing cycle, on `publish/v4.15.5-comparison-token-economizer` cut from `origin/develop` at `dd83aa1d1`
**Date**: 2026-11-05
**Slot rationale**: Every candidate that claims a cost saving must be measured by the harness-pairing evaluator that v4.15.2 builds, so this comparison follows v4.15.2. v4.15.5 is the next free patch after v4.15.4 and needs no renumber. The maintainer chose v4.15.5 over v4.16.4 (after v4.16.3's per-tool-call context attribution); the consequence for candidate B is recorded under Queued-plan impact.

Nexus-Hub already covers most of what these sources do around distribution, delegation, attribution, and safety, and in several places it covers it better (copy plus manifest ownership instead of symlinks, enforced guard hooks instead of advisory rules, 17 platforms instead of two). Three gaps are real, all from TokenEconomizer. First, nothing notices when an agent is stuck inside a single turn: retrying the same failing command, accumulating errors, or rewriting one file repeatedly. Second, nothing tells a user which tools a repository never uses, so their schemas keep costing context on every request. Third, Nexus-Hub records observations (`learning-capture.sh`) but never replays a confirmed environment fact, such as "bare `pytest` fails here, `python -m pytest` works", into the next session. Each gap can be closed locally and deterministically, without the model side calls TokenEconomizer uses. agent-scripts contributes two small instruction-level refinements to existing skills and a list of practices Nexus-Hub must not adopt.

## Step 1.5: Source security scan

Both repositories were shallow-cloned into separate empty scratch folders and scanned mechanically before any content was read. No code from either source was installed or run. Scanner scripts ran from a third folder with the source paths passed as arguments.

**Source 1 verdict: CLEAR.**

| Check | Result |
|---|---|
| Prompt injection / agent-directed instructions | None aimed at an auditing agent. The plugin deliberately sends text to the coding agent it runs under, for example `plugin/hosts.py:166-172` ("Put this line, word for word, in your next message to the user") and slash commands that ask for verbatim command output (`plugin/slash-commands/status.md`). These are disclosed product behavior. |
| Hidden or obfuscated directives | No zero-width or bidirectional characters, no long base64 runs. |
| Malicious or destructive code | None. `rm -rf ~/.tokeneconomizer` appears only in uninstall instructions in `plugin/README.md`, scoped to the tool's own state folder. `curl ... \| bash` appears only as documented vendor CLI installs in `experiments/`. |
| Supply-chain risk | Low. The package is stdlib-only Python 3.10+ (`pyproject.toml`), with no `preinstall` or `postinstall` hooks and no binaries. The benchmark harness under `experiments/` needs provider API keys (`experiments/.env.example`) but is not part of the plugin. |

**Source 2 verdict: PROCEED-WITH-CAUTION.**

| Check | Result |
|---|---|
| Prompt injection / agent-directed instructions | No injection strings, but the repository is a skill pack, so most of its text is instructions to agents by design. All of it was read as data. |
| Hidden or obfuscated directives | No zero-width or bidirectional characters, HTML-comment payloads, or base64 runs. |
| Malicious or destructive code | No malware. The cautions are policy, not code: `AGENTS.MD` pre-approves sending unpublished diffs to a review service and using saved mail credentials "without asking", `skills/codex-first/SKILL.md` runs `codex exec --yolo` and resumes with `--dangerously-bypass-approvals-and-sandbox`, and `skills/browser-use/auto-allow.py` clicks Chrome's "Allow remote debugging?" security prompt automatically. |
| Supply-chain risk | Medium for anyone installing it: `npx -y @steipete/oracle` downloads on demand, two skills document `curl ... \| bash` vendor installers (`skills/codex-first/references/launch-details.md:67`, `skills/xurl/SKILL.md:54`), and 15 skills are symlinks to repositories outside the clone. Nothing from it is proposed for adoption as code. |

While the scan ran, Nexus-Hub's own `console-window-guard` hook blocked Python launched from inside the cloned agent-scripts tree, because that tree contains about 130 console launches without a hidden-window flag. The guard did its job; the workaround was running the scanner from a separate folder.

## Step 5: Security and Reverse-Engineering Assessment

### 5.1 Threat model comparison

| Factor | TokenEconomizer | agent-scripts | Nexus-Hub adoption as proposed |
|---|---|---|---|
| New runtime dependencies | None beyond Python 3.10 | Ruby, Bun, Node 24, `uv`, `tmux`, `op`, `mcporter` | None; Python stdlib and existing hook runtime |
| Outbound calls | Model side calls through the user's agent CLI (proposer, loop judge); no telemetry | OpenAI, Gemini, npm, Twilio, Cloudflare, X, two private services | None |
| Credentials | None of its own; uses the agent CLI's login | 10 or more tokens (OpenAI, Gemini, 1Password, Twilio, Cloudflare, npm, GitHub) | None |
| Code, prompts, or text leaving the machine | Session digests (command shapes, masked error lines, file names) go to the model provider through side calls | Unpublished diffs to a review service, pre-approved | Nothing |
| New commercial relationship | No | Several | No |

### 5.2 Per-item risk scorecard and 5.3 reverse-engineering class

| ID | Candidate | Risk | RE class | Rationale |
|---|---|---|---|---|
| A | Deterministic stuck-turn advisory hook (from T1) | Low | `re-full` | Signals are counts over the hook payload stream; no judge model. MCP Registry Policy tier 1 (local-only): no outbound call. Advisory only, so a false positive costs one context line. |
| B | Local unused-tool report (from T2) | Low | `re-partial` | Counting tool use from local transcripts is fully local. Automatically writing `permissions.deny` is dropped: it changes a permission surface without a human, and v4.18.1 states the installer never alters permissions unasked. The report prints a suggested deny list the user applies. |
| C | Confirmed environment-fact replay (from T3) | Medium | `re-full` | Detection is deterministic over `.nexus/observations.jsonl`. Risk is indirect injection: facts derive from repository-controlled command output (TokenEconomizer admits this, `docs/PLUGIN.md:670`). Requires a closed fact grammar (a failing command form and its working form), length cap, and opt-in. |
| D | Cost-accounting rules for the v4.15.2 evaluator (from T5) | None | `skill-native` | Text in a guide; no code. |
| E | Prompt-cache-aware write timing (from T6) | None | `skill-native` | Guidance in `prompt-token-optimization` and the hook-authoring section of AGENTS.md. |
| F | Delegation escape-route rule and busy-session check (from A2, A3) | None | `skill-native` | Two rules in `cross-model-orchestrator`. The source's sandbox-bypass flags are excluded. |
| G | No-progress watchdog for background runs (from A4) | None | `skill-native` | One rule in `loop-engineering`. |
| H | Model-proposed micro-skills (T4) | High | `drop-outright` | Adds model calls that send session digests to a provider, contradicting `learning-capture.sh`'s "no external observer model" constraint. The authors keep it off by default and report it "saved nothing" on a small repository (`docs/PLUGIN.md:490-497`). `continuous-learning` already does in-session promotion. |
| I | Model-judged loop redirect (T1 judge) | Medium | `drop-outright` | A side call per suspected stuck turn; the authors state the redirect's effect on a looping model "is not established" (section 5). The deterministic signal in A captures the measurable part. |

### 5.4 Recommendation ordering

1. `skill-native`: D, E, F, G.
2. `re-full` / `re-partial`: A, then C, then B.
3. `vendor-intrinsic`: none.
4. `drop-outright`: H, I, plus the agent-scripts practices in NOT Recommended.

## Adoption Plan

Ordered per Step 5.4; P-tier applies within each bucket.

1. **D (P0, skill-native).** Add to the v4.15.2 harness-pairing guide: cost includes every model call the harness itself adds; report cache-aware effective tokens; workloads that test a learning mechanism run in a fixed order from an empty state and report the break-even task count.
2. **F (P1, skill-native).** In `cross-model-orchestrator`: every prohibition in a delegated work order names the allowed alternative; check a delegate session is idle before resuming or stopping it; cite v4.17.1 for process ownership.
3. **G (P1, skill-native).** In `loop-engineering`: a background run whose output has not changed for a set window (default 5 minutes) is reported as hung, alongside the wall-clock cap.
4. **E (P1, skill-native).** A hook or command that rewrites settings or instruction files during a session invalidates the prompt cache for the rest of it; defer such writes to session end or the next start.
5. **A (P1, re-full).** `stuck-turn-notice` hook, advisory, exit 0, on `PostToolUse`. Signals per turn: the same command failing N times with the same normalized error, M error outputs, or K edits to one file. One notice per turn. Disabled by `NEXUS_DISABLED_HOOKS=stuck-turn-notice` and `NEXUS_HOOK_PROFILE=minimal`. PowerShell sibling and parity test required. Thresholds start at TokenEconomizer's published values and are tuned by the v4.15.2 evaluator.
6. **C (P2, re-full).** Opt-in replay of confirmed environment facts at session start. A fact is a pair (failing command form, working form) seen in at least 3 sessions with no contradiction; at most 5 facts; each under 120 characters; only command text, never error text, is replayed.
7. **B (P2, re-partial).** `/usage tools`: list tools never invoked across the last N local sessions for this project, print the bytes they cost when the platform exposes it, and print a suggested deny list. It never writes settings.

## Risks and Conflicts

- **A false positives.** A long, legitimate refactor can edit one file many times. Mitigation: advisory only, one notice per turn, thresholds gated by measurement.
- **A cross-platform reach.** `PostToolUse` payloads differ by platform. Claude Code is the first target; other platforms receive it only where the hook surface matches, per `docs/policy/platform-read-contracts.md`.
- **C injection surface.** Facts originate from repository-controlled output. The closed grammar and command-only replay are required, and the feature stays off by default.
- **B reads transcripts.** Transcripts can hold secrets. The report prints tool names and counts only, never payloads.
- **Modified files.** A edits `catalog/hooks/settings.json` (AGENTS.md "Ask first": changing hook logic). C edits `session-start.{sh,ps1}`, an always-on hook. Both need maintainer sign-off in the plan.
- **No installer edit expected.** New hook files live in `catalog/hooks/`, already copied recursively.
