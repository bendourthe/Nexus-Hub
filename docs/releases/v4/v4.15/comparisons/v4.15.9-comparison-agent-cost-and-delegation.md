# Comparison: Agent Cost Levers and Delegation Discipline

**Project**: Nexus-Hub

**Date**: 2026-11-10

**Baseline**: `origin/develop` at `c33f7aede` (PR #626 merged); latest release tag `v4.14.8`

Adoption target: v4.15.9

**Placement status**: User-confirmed on 2026-11-10. The queue on `origin/develop` runs v4.15.0 through v4.22.10, and open PR #604 claims v4.22.11. v4.15.9 is the first free slot after v4.15.8. The maintainer chose it over v4.16.4 and v4.22.12 because the main finding, the effort that every shipped subagent inherits, costs money on every delegated turn, and it is cheap to fix. The slot still follows v4.15.2, whose evaluator measures any cost-saving claim this plan makes. Open PR #628 grants native write permissions for v4.15.5 to v4.15.8 only, so v4.15.9 is outside that run and needs its own authority when it starts.

**Source types**: ten article-class sources (three supplied PDFs, five pasted excerpts, two fetched web pages) plus one Git repository read only through its public landing page. The insight-extraction mode applies; the 11-dimension matrix does not.

**Scope**: catalog, templates, hooks, and runtime behavior are unchanged by this report. It records findings and an adoption plan only.

## Summary

Ten sources were read against Nexus-Hub. Most of their advice is already shipped: verification gates, fresh-context review, plan-first work, recorded corrections, context in the repository, fresh-session handoffs, and per-phase model routing all have owners in the catalog. Saying so up front matters, because the remaining gaps are few and specific.

The one high-value gap is a cost leak in Nexus-Hub's own agents. All 23 files in `catalog/agents/` pin `model: opus`, and none sets `effort:`. The first-party subagent documentation says a subagent on the main conversation's model "runs at the level you pick in the session", so a maintainer working at `xhigh` or `max` pays that level on every review persona, planner, and doc updater the catalog spawns. The archived v4.14.0 subagent-cost plan addressed the subagent model default and explicitly left the `model: opus` pin unchanged; it never set effort.

Six smaller gaps are instruction-level and need no dependency or outbound call. They are an effort escalation ladder, a filter-first rule for bulk data (which also needs a scope fix in `direct-corpus-interaction`), a refactor-first stop rule against bolted-on features, a two-failed-corrections reset with pilot runs, an implicit-state-machine and deep-module refactoring pass, and a post-model-release project audit. Two sources (latent sparse attention and the 0sec security harness) produce nothing to adopt.

## Source Security Scan

All sources were treated as data. No source text became an instruction for this session, and no upstream installer, package, or script was run.

- **S1, S2, S4, S6, S8, S9, S10**: no agent-directed text, hidden content, or executable payload. S1 and S8 contain configuration examples (agent frontmatter, environment variables), which are normal for their subject and were read as data.
- **S3**: the fetched page contains a related-post title, "You are absolutely right!?", which is not an instruction.
- **S5**: the excerpt recommends `git add -A && git commit -m "pre-refactor checkpoint"`. It is not hostile, but run as written it stages every unrelated change in the worktree, and `&&` is a parse error in Windows PowerShell 5.1. It is recorded as a hazard, not an adoption (see Not Recommended).
- **S7**: the landing page installs through a pipe-to-shell command, `curl -fsSL https://raw.githubusercontent.com/0sec-labs/0/main/install.sh | bash`. Its default executor runs a shell on the host, and it carries a "For AI agents" pointer to an `llms.txt` index. The pointer is informational, and this session did not follow it. `install.sh` and `package.json` were not inspected, so their behavior is unverified.

No finding reached BLOCK.

## Adoption Plan

1. **Phase 1, agent effort (A)**: fetch the sub-agents page again at execution time and record its date in `docs/policy/platform-defaults-levers.md` beside the existing `CLAUDE_CODE_SUBAGENT_MODEL` evidence. Assign each of the 23 agents an effort by role. Confirm how the Gemini and Codex installers treat an unknown `effort:` key before shipping. Add a validator assertion that every `catalog/agents/*.md` declares `effort:` from the documented set. Acceptance: the validator fails on an agent file with the key removed, and a fresh session at `max` effort that spawns `doc-updater` shows the agent's own effort in `/usage`.
2. **Phase 2, cheap reader (B)**: add one read-only agent with `tools: Read, Grep, Glob, Bash`, a cheap tier, and a body that forbids edits. Acceptance: the agent appears in the installed `~/.claude/agents/`, and a log-reading task routed to it returns failures without editing any file.
3. **Phase 3, instruction edits (C, E, F, H, I)**: one edit each in its owning skill. C must state the boundary in one sentence: DCI governs code-retrieval evidence, and filter-first governs bulk data the agent would otherwise read in full. Acceptance: `python scripts/ci/run.py --profile fast` passes, and each edit is referenced from its skill's Verification section.
4. **Phase 4, refactor-first stop (D)**: after v4.15.0 records its verdicts, add the rule to the right lockstep block (or to `base-agents.md` if v4.15.2 has landed it). Regenerate legacy fingerprints and check the doc budget. Acceptance: `scripts/check_base_template_parity.py` passes, and the companion validator finds the rule on all thirteen substantive templates.
5. **Phase 5, refactoring passes (G)**: add both passes to `refactoring-expert` (owner) and a cross-link from `code-simplification`. The checkpoint step uses a scoped commit of tracked paths, never `git add -A`. Acceptance: the passes appear in the skill, and its Verification section requires the test suite before and after.
6. **Final phase**: reconcile CI through `cicd-architect`, run the full local profile, push once, and open the integration pull request to `develop`.

## Risks and Conflicts

- **A changes behavior every user sees**: lower effort on review personas could miss findings that `xhigh` would catch. The per-role assignment must keep the planner, architect, security reviewer, and adversarial reviewer at `high` or above until the v4.15.2 evaluator measures a lower setting.
- **A crosses platforms**: `catalog/agents/` reaches Claude, Gemini, and Codex. An unknown key may be ignored or rejected depending on the reader. This is the item's real risk, and Phase 1 checks it first.
- **C edits a rule another skill owns**: `direct-corpus-interaction` owns the anti-pre-filter rule. C narrows its scope in that skill rather than adding a contradicting rule elsewhere, per the rule-ownership convention in `AGENTS.md`.
- **D edits the distributed templates**: it changes behavior on every installed platform, needs all thirteen substantive templates, and triggers the fingerprint regeneration and doc-budget checks.
- **S1 and S8 disagree on executors**: S1 routes edits to Haiku; S8, the first-party source, keeps edits on the main model. The plan follows S8.
