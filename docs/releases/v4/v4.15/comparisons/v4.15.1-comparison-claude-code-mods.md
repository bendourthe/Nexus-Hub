## Section 1: Executive Summary

Mods are Claude Code plugins whose behavior is TypeScript running inside Claude Code's engine. The architecture is a Koa-style middleware algebra over a single engine interface named `$`. Every affordance a plugin can call is an event every other plugin can hook, and `$` is the only door: the environment running a plugin's hooks "has no ambient file system or network, so what a plugin did is exactly the calls it made on `$`" (Section 4). A module that manipulates `$` any other way fails `claude plugin validate`, which makes a plugin's side effects statically determinable.

**This comparison is not primarily an adoption opportunity. It is a contract-drift finding and a security finding.**

The contract drift is that `hooks.json` has gained a fifth hook type. Beside the four documented types (command, prompt, agent, http), it may now name a `modules` array pointing at a `.js`, `.ts`, `.jsx`, or `.tsx` file in the plugin's `hooks/` directory (Section 1). Nexus-Hub's living platform read-contract, which exists precisely to catch this class of change and which hard-gates a release, does not know this surface exists. Grepping the repository for `function hook`, `CLAUDE_CODE_ENABLE_FUNCTION_HOOKS`, and `mods` returns zero hits across `catalog/`, `docs/`, `guides/`, `scripts/`, and `configs/`.

The security finding is the reason the `sec-default` built-in mod exists. Its stated purpose is to keep "an organization's classic hooks, prompt content, managed settings and tool policy out of reach of installed plugins", and it is seated outermost only "on machines with managed settings or for Team/Enterprise organizations". Nexus-Hub installs 32 shell hooks with 32 PowerShell siblings and 7 Python hooks onto individual developer machines, which by definition do not have managed settings. Those hooks are Nexus-Hub's only mechanical guardrails, and on the target install profile nothing seats above an installed third-party mod.

**What Nexus-Hub should NOT do is build mods now.** The surface is gated behind `CLAUDE_CODE_ENABLE_FUNCTION_HOOKS=1`, is declared "EARLY ACCESS: this surface may change between releases without notice", and shipped as a GitHub issue plus a PDF rather than stable public documentation. Nexus-Hub's own do-not-invent rule requires a fetched official vendor document with a `source_url` and a `verified` date before a platform lever enters `configs/platform-defaults.json`, and the v3.15.0 `.kimi/agent.yaml` incident is the standing precedent for what happens when that bar is lowered. Mods also cut directly against the catalog's architecture: TypeScript runtime code distributed to roughly twenty platforms, of which exactly one can execute it, would fracture the five-template lockstep parity model into a two-tier catalog where Claude users get enforcement and everyone else gets advice.

**Recommended adoption: four items, all zero-code or repo-internal, zero new outbound calls, zero new dependencies, zero new credentials, zero new third-party processors.** Two further items are recorded as explicitly trigger-gated on Anthropic publishing stable public documentation. Two are declined outright.

## Section 8: Risks, Conflicts, and NOT Recommended (Step 7)

### Risks and conflicts for recommended items

- **A** touches `platform-contract-verification`, which hard-gates a release. Recording an early-access surface in a contract whose purpose is verified stability needs an explicit stability field, or the freshness gate will churn on every Claude Code release. Mitigation: record the `modules` key with its status marked early-access and its verification cadence stated, rather than promoting it to a VERIFIED lever in `configs/platform-defaults.json`. The do-not-invent rule in AGENTS.md forbids the latter until stable public documentation exists.
- **B** is documentation about a third-party risk. It must describe the exposure without implying that Nexus-Hub can mitigate it, because on the target install profile (individual machine, no managed settings) Nexus-Hub cannot.
- **C** risks duplicating the v4.13.0 observability work. Mitigation is the routing decision recorded in Section 7.
- **D** adds vocabulary to a surface bound by five-template lockstep parity if it lands in a shared instruction block. Mitigation: place it in `AGENTS.md` and the settings reference, both repo-internal, not in `templates/ai-instructions/base-*.md`.

### Explicitly NOT recommended

| Item | Grounds |
|---|---|
| Ship TypeScript mods in the catalog now | The vendor declares the surface "may change between releases without notice" and gates it behind `CLAUDE_CODE_ENABLE_FUNCTION_HOOKS=1`. The Nexus-Hub do-not-invent rule requires a fetched official vendor document before a platform behavior enters the distribution; a GitHub issue and a design PDF do not meet that bar. The v3.15.0 `.kimi/agent.yaml` fabrication is the standing precedent |
| Migrate the 39 classic hooks to function hooks | Would strand the nine other skill-bearing platforms. Classic hooks are the only mechanical guardrail those platforms receive, and the source itself keeps "command, prompt, agent and http hooks in `hooks.json` running beside" function hooks, so migration buys nothing even on Claude Code |
| Adopt `$.telemetry` | `drop-outright`. Nexus-Hub is local-first and adds no analytics surface. The built-in mod "sends nothing when Claude Code analytics are off", but adopting it would make Nexus-Hub behavior depend on a vendor analytics setting the user controls elsewhere |
| Build item F or G in this cycle | Deferred with an explicit trigger: revisit when Anthropic publishes function hooks in stable public documentation at `code.claude.com/docs` with a version guarantee, and the `CLAUDE_CODE_ENABLE_FUNCTION_HOOKS` gate is removed. Until then any build ships unstable runtime code to user machines |

### Answering the invoking request directly

The pasted use case was: "in the desktop app, hide sensitive values by default and reveal them on hover." That is a `ui.render` hook (Section 3.2) matching on a component with the `desktop` surface, rewriting props before continuing the chain. It is not achievable by any existing Nexus-Hub setting, skill, or classic hook, and it is not achievable by a mod today without the early-access flag. It is a legitimate future mod, and it is precisely the class of capability item F would cover. It is out of scope for v4.15.1 on the same instability grounds as F.
