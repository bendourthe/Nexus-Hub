# Comparison - Agent Speed: KV-Cache Handoffs, Instruction Payload, Mods Delta, and Local Search

**Project:** Nexus-Hub
**Date:** 2026-10-12
**Baseline:** commit `e3f9e3256` (PR #437, merged into `develop`) plus the 2026-10-12 queue reorganization
Adoption target: v4.15.3
**Placement status:** User-confirmed on 2026-10-12 as v4.14.1, then moved to v4.15.3 by the same-day queue reorganization ([record](../development/2026-10-12-queue-reorganization.md)), which the maintainer approved. It follows v4.15.2, whose skill-index default flip and rendered-context receipts these items extend.
**Scope:** Four-source comparison and prioritized adoption recommendations. The maintainer asked whether these sources can make agentic work on Nexus-Hub-equipped platforms faster without degrading output quality. Catalog, templates, and runtime behavior are unchanged by this report.

The KV-cache techniques cannot be adopted on any platform Nexus-Hub supports, because they need model weights and internal cache access that closed-API hosts do not expose. Their underlying lesson does apply: switching models and handing work between agents are slow because the receiver re-reads (re-prefills) the whole context. On the platforms Nexus-Hub targets, the context it controls is the always-loaded instruction payload. That payload is measured below at about 28,900 estimated tokens in this machine's global `~/.claude/CLAUDE.md`, which carries two skill indexes. The largest speed gain available today is a cleanup with tools that already ship. The catalog changes recommended here are small: surface payload bloat in `doctor`, tighten handoff payloads, and persist dense search vectors.

## Findings by Source

### S2 - KV-cache handoffs (the speed question)

| # | Insight (source section) | Status vs Nexus-Hub | Evidence |
|---|---|---|---|
| K1 | Switching models re-runs prefill over the accumulated context, because a KV cache is model-specific (article, "Why AI model handoffs become expensive"; paper, Section 1) | Already implemented as guidance, queued for completion | `model-routing` upshifts at sub-task boundaries; v4.14.2 DoD 4 adds the cache cost of a mid-conversation model or effort change. Step-8 owns the cache rules (`prompt-engineering/references/step-8-optimize-cost-and-latency.md:120`). |
| K2 | Cross-model KV transfer: closed-form ridge mapper, 2.7x to 25x faster than re-prefill, 73% to 98% accuracy retention on four of six pairs, sharp degradation on two (paper, Abstract and Conclusion) | Not applicable | It needs weights and cache access, and works within one model family only (paper, Limitations 3 and 4). Every supported host serves models through a closed API. The article says so too: "Developers working through closed-model APIs cannot insert these transformations." |
| K3 | Cache-to-Cache (C2C) fusion avoids the sender's text generation and the receiver's re-reading: about 2.5x average latency speedup and +3.1 to +5.4 points accuracy (article, "Cache-2-Cache transfer") | Not applicable as a technique | Needs a trained fuser and internal caches. |
| K4 | Text handoffs cost three ways: the sender generates the message token by token, the receiver re-reads it, and a short summary can lose or blur detail (article, "Cache-2-Cache transfer") | Partially implemented | `agent-orchestration-primitives/SKILL.md:44` frames subagents as compression; `multi-agent-coordinator/SKILL.md:672` requires decisions in the brief. No rule bounds what a subagent returns, or says the receiver should re-read only anchored ranges rather than re-derive. |
| K5 | A hybrid of a textual interpretation plus shared context beat either alone (article, final section) | Partially implemented | Anchored returns (`file:line` plus a one-line claim) are the closed-API analogue: the receiver reads the source itself instead of trusting a paraphrase. `direct-corpus-interaction` already requires `file:line` per exact claim; handoffs do not. |
| K6 | Match the handoff to the task: compatible-model session moves, specialist exchanges, or short text for narrow tasks (article, "What this means for agent developers") | Partially implemented | `agent-orchestration-primitives` chooses between single agent, subagents, and teams by task shape, not by the re-read cost of the handoff. |

| `~/.claude/CLAUDE.md` | 28,905 | 547 | 2 | 15 | 3 |
| `~/.copilot/copilot-instructions.md` | 17,701 | 339 | 1 | 0 | 3 |

The tokens in this table are estimates, not billed tokens, and no latency was measured.

### S4 - DigUp local semantic search

| # | Insight (README section) | Status vs `extensions/nexus-code-search` | Evidence |
|---|---|---|---|
| L1 | On-device model; no network except a one-time model download and a daily update check ("Private") | Already implemented, stricter | The dense extra reads only pre-placed weights and never downloads (`README.md`, "Optional offline dense retrieval"). |
| L2 | Hybrid ranking: nearest vectors plus an exact-word boost, "because no embedding holds an invoice number exactly" ("How it works") | Already implemented | `hybrid_search` mixes normalized keyword and cosine scores (`search_dense.py:141`). |
| L3 | Vectors are computed once at index time, kept in one SQLite file, and updated incrementally a second after a file lands ("How it works", "What it reads") | **Missing** | `hybrid_search` encodes the query and every chunk on every call (`search_dense.py:163`); no vector is persisted. Hybrid search therefore costs one full-corpus encode per query, which grows with repository size. |
| L4 | The index records which model version made its vectors, and a test checks each engine update against stored reference vectors ("How it works") | **Missing** | No encoder fingerprint is recorded; a grep of `src/` for model hash, digest, or version returns nothing. This becomes necessary once L3 persists vectors, because swapping `model.onnx` would otherwise mix incompatible vectors silently. |
| L5 | Never reads keys, certificates, password files, `~/.ssh`, git-ignored, vendored, or generated code ("What it reads", "Code") | Partially implemented | `.gitignore` and `.nexusignore` are honored (`README.md`, exclusions section); the env audit never reads a real `.env`. No explicit key and certificate filename deny-list for chunking was found. |
| L6 | Ranking changes are measured against stored queries in `evals/` | Already implemented | `benchmarks/goldset.json`, `benchmarks/harness.py`, and `nexus_code_search.eval`. |

## Not Recommended and Considered but Rejected

| Inspected candidate | Decision and reason |
|---|---|
| Cross-model KV transfer or C2C in Nexus-Hub | Drop. Requires weights, cache access, and a trained mapper or fuser; no supported host exposes them. Revisit only if Nexus-AI ships self-hosted family-matched models, and then under that project. |
| Mid-session model switching to save cost | Reject. K1 shows the switch re-pays prefill; v4.14.2 already makes the cost explicit and prefers sub-task boundaries. |
| Distributing `prompt-cache-control`, `plan-progress`, or `image-view` | Reject. Third-party code with an unpinned install path, Claude-only, and the v4.22.3 build gate is still closed. |
| A Nexus-Hub cache keep-warm loop | Reject. It sends billed requests to save latency; step-8 already states the refresh-on-read rule for users who choose it. |
| Downloading EmbeddingGemma 2 or bundling DigUp | Reject. Violates the no-download guarantee of the dense extra; users may place any local encoder themselves. |
| Multimodal (image, audio, video) search in `nexus-code-search` | Reject. Out of scope for a code-search server and not a speed issue. |
| Rust Office-format runtime from S3 | Reject. Adds a runtime without reducing work over the existing Python generators. |
