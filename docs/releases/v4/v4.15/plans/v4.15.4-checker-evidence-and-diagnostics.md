## Goals First

**Target problem**: Legitimate consumer workflows encounter checker incompatibilities and incomplete diagnostics, while automatic repair can mutate the bytes used as evidence.
**Persona**: Maintainers and coding agents closing releases on Windows and POSIX under exact approval and evidence requirements.
**Success metrics**: Zero protected-evidence byte changes; equivalent valid inputs produce equivalent predicates; zero diagnostic writes to run records; unresolved supported operational references prevent archive movement; no false completion or approval expansion in adversarial controls.

### Definition of Done

1. Every included defect has a failing-before/passing-after regression and an observed CLI or artifact proof on the final candidate.
2. Unicode auto-fix preserves protected evidence even when unsafe characters remain reportable; unresolved findings retain a nonzero result.
3. The changelog gate accepts exact requested versions in supported H1/H2 plain or linked bracket headings, excluding fenced examples and prefix collisions.
4. Relative, absolute, and Windows short-name ledger roots resolve equivalently; invalid or unreadable input fails explicitly without silently changing historical scope.
5. Item-specific blocker reporting distinguishes frozen coverage from uncovered items and cannot grant approval, answer a blocker, or mark work complete.
6. Explicit detail preserves blocked, paused, and tampered verdicts and exit codes, discloses only verified diagnostic data, and never writes completion markers.
7. Archive preflight reports operational references and historical mentions separately. Unresolved supported live references block before movement; raw non-Markdown captures and machine-readable receipts are never silently rewritten; existing Markdown navigation repair is the explicit exception defined below.
8. Approval summaries describe open gaps rather than claiming fixes; zero-open-task phases contribute zero building time, with any remaining release-only time labeled separately.
9. Existing handbook LF/CRLF normalization remains covered and unchanged. Isolated installed copies pass the same affected boundary exercises as repository sources.
10. Focused tests, full local gates, handbook candidate checks, independent Goal review, remote integration checks, and native completion evidence remain distinct. Publication and release require their matching approvals.

### Archive Classification and Recovery

Initial supported operational references are (a) repository-relative path-valued inputs, output and evidence fields in docs/handbooks/handbooks.json, (b) any exact repository-relative path string or path-prefix value in tracked, non-protected JSON, and (c) literal or glob path selectors rooted at the moved tree in .gitattributes. Unknown JSON shapes are not treated as clean: unsupported embedded path mentions are reported as unverified. Protected JSON under evidence or archive roots is historical evidence and is reported without rewriting. Markdown code spans and code comments are informational historical/ambiguous mentions, not automatic operational failures. A matching path in a live manifest blocks; the same string in an archived receipt is informational. Existing supported Markdown-link repair continues through its current transaction.

For each blocking reference, diagnostics name its repository-relative path and line/JSON key plus the remedy: explicitly update the live source/configuration to the projected archive path or regenerate the consumer-owned manifest/receipt through its established generator. Never advise editing a sealed receipt's bytes. Re-run preflight after that repair. Phase 4 must demonstrate both the refusal case and a successful archive after supported live references are resolved, with operational path resolution and check_handbooks.py (where a handbook fixture exists) passing afterward. Unsupported embedded references remain an explicit qualification limit; no output may claim universal reference completeness.

### Preservation Boundaries

The Unicode fixer protects every file beneath the evidence-directory convention, including Markdown. Archive byte preservation is narrower: raw non-Markdown captures and machine-readable receipts stay byte-identical. The existing transactional Markdown navigation repair remains an explicit exception, including authored Markdown evidence reports and archived Markdown receipts; only its established link-destination repairs are permitted, and changed-file/link counts must be reported. This plan does not introduce a general immutable-Markdown-receipt format. Add an archived Markdown receipt containing a moved-tree link to the regression matrix and prove only the existing navigation transformation occurs, while companion raw logs and JSON receipts retain their bytes. Do not describe this bounded guarantee as all evidence being immutable.

### Diagnostic Limits

Reuse existing CLI budget and text-size constants where available; record their resolved values in tests. The new local detail path has a 10-second total budget, no new network calls, at most 32 candidate controller records, and at most 100 displayed findings sorted by path and item ID. The archive inventory reuses the tracked-file list, inspects at most 2 MiB per text file, and prints at most 100 findings. Protected evidence may be scanned but is never repaired. Size, record-count, time, or display limits emit deterministic scanned/omitted counts and an incomplete marker. A bounded subprocess isolates potentially blocking filesystem/Git access if the existing budget mechanism cannot interrupt it; an expired diagnostic worker is terminated and its data is unavailable. No unbounded waiting thread is accepted as a timeout implementation.

Display truncation may omit detail only when inventory/classification completed and full totals remain available. An incomplete archive scan cannot authorize movement; an incomplete run diagnostic retains the original verdict/exit and reports unknown. Malformed/tampered records are never used to derive trusted scope. Tests exceed every limit and compare record/tree bytes before and after diagnostic calls.
