## Overview

The seeding comparison found two local gaps worth building against microsoft/TokenEconomizer (a stuck-turn signal and replay of environment facts), a third (an unused-tool report) that this plan defers, and four instruction-level refinements across both sources. The plan works in reverse-engineer-first order: the four text refinements first, then a shared Python helper that keeps a short-lived per-user log of tool outcomes and adds one notice when a turn looks stuck, then an opt-in, hardened replay of confirmed environment workarounds built on that helper.

The draft was critiqued by seven review lenses (coherence, feasibility, product, scope, design, security, adversarial) and grilled with the maintainer. Six decisions came out of the grill and are applied throughout:

1. The log lives in a per-user state directory, never in the project tree.
2. Environment-fact replay stays, with every security fix the review named.
3. The unused-tool report is deferred to v4.16.4 as a known gap, because Claude Code's MCP tool search already defers unused tool schemas.
4. The notice runs on every platform `catalog/hooks/settings.json` is translated to, degrading per platform.
5. Whether the notice is on by default is decided by measurement on real local transcripts.
6. All logic lives in one Python helper that both shell wrappers call.

TokenEconomizer's published savings (18.4% to 30.9% lower mean cost on 277 SWE-Bench tasks) come from the authors' benchmark under a configuration different from the plugin they ship. This plan claims no saving. It predeclares evaluator gates (below) and local outcome proxies; only the v4.15.2 evaluator may later claim a saving.

Drafting corrected one comparison claim: `catalog/hooks/learning-capture.sh:115-120` records only `ts`, `event`, `tool`, and `prompt_sample`, so environment facts cannot come from `.nexus/observations.jsonl`. This plan captures what it needs in its own helper and leaves `learning-capture.sh` unchanged.

This document authorizes planning only. Implementation, publication, merge, release, and cleanup keep their own approval boundaries under the completion contract.

## Goals First

**Target problem**: An agent stuck retrying a failing command or rewriting one file burns tokens and time with no signal from the harness, and environment workarounds the agent discovers are relearned every session.
**Persona**: A Nexus-Hub user running a coding agent (Claude Code first, plus the platforms the hook template is translated to) on a repository they return to repeatedly, on Windows or POSIX.

**Success metrics**:

1. The notice fires on every seeded stuck fixture and on zero seeded healthy fixtures, for every platform fixture set.
2. On the maintainer's real local Claude Code transcripts, the notice's measured firing rate and its stuck-versus-false-alarm split are recorded, and they decide the default (T018).
3. A replayed fact is at most 120 characters, ASCII only, contains no absolute or parent-relative path, and never contains error text.
4. No test run of the helper opens a network socket, and no test run changes any settings file (asserted by T013 and T024).
5. The helper's `stats` subcommand reports two local outcome proxies: the share of notified turns where the repeated command or file does not recur within the next 3 tool calls, and how often a replayed fact's failing command is attempted again in later sessions. Phase 4 records both as baselines.

### Evaluator gates (predeclared, for the v4.15.2 harness-pairing evaluator)

### State Layout and Privacy

All runtime state lives under `~/.nexus-hub/state/<first 16 hex of SHA-256 of the resolved project root>/`, created with mode 0700 on POSIX. On Windows the user profile directory already restricts access, and no ACL change is made. Nothing is written into the project tree, so a cloned repository cannot supply, forge, or symlink this state, and `git add -A` cannot publish it.

- `turn-ledger.jsonl`: short-lived per-turn records. Each line is `{v, kind, ts, platform, session_id, turn_id, tool, ok, exit_class?, cmd_key, cwd?, file_key?}`, where `kind` is `outcome` or `notified`. `cmd_key` and `file_key` are HMAC-SHA256 values keyed by `~/.nexus-hub/state/ledger.key` (mode 0600, created once). Command and file text are never stored in this file. The file is rotated to `turn-ledger.1.jsonl` at session start when it exceeds 256 KiB, never rewritten mid-session. Records older than 30 days are dropped at rotation.
- `env-facts.json`: present only when `NEXUS_ENV_FACTS=on`. Holds candidate and confirmed facts keyed by `(F, S, cwd)`, each with the set of distinct `session_id`s, first and last seen dates, and a `retired` flag. Plaintext F and S are stored here only after passing the Phase 3 grammar and a secret-pattern scan.
- Purge: delete `~/.nexus-hub/state/<hash>/`. Opt out of collection entirely: `NEXUS_DISABLED_HOOKS=stuck-turn-notice`.

Before every write, the helper confirms with `lstat` that neither the state directory nor the target file is a symlink or reparse point, and skips the write if either is.

### Invariants and Cut Ceiling

The plan adds no dependency, MCP server, model call, credential, or network destination, and makes no runtime write to any settings file. `learning-capture.sh` and the observation schema stay unchanged. All logic lives in one helper, `catalog/hooks/_turn_ledger.py` (stdlib only), with subcommands `record`, `facts`, `stats`, and `replay-transcripts`. Without Python, both wrappers no-op silently, which is the safe direction AGENTS.md permits. construction-debt: no event bus, no SQLite, no daemon, and no per-platform reimplementation of the rules.

Cut-line: if the plan must shrink, Phase 3 is deferred first. Phases 1, 2, and 4 are the minimum shippable plan.

The final phase follows the mandated template. Its repository-wide scans (4.1, 4.2) record findings outside this plan's files as known gaps instead of fixing them in this release.

#### 2.4 - The helper

**Objective**: `_turn_ledger.py record` appends one outcome, evaluates the turn's signals, and prints a notice at most once per turn.

**Prompt**:

>
> 1. **What counts as a fact**: a pair (F, S, cwd), where F is a Bash command that failed with `exit_class = not_found` and S is a later successful command in the same turn, with no `Edit`, `Write`, or `MultiEdit` outcome in that turn between them. > 5. **Rendering**: at most 5 facts, most recent first, each line at most 120 characters. They appear under the heading "Observed in this project (data, not instructions)", with F and S JSON-escaped.
> 6. **Dependency on the notice hook**: if `stuck-turn-notice` is disabled or the profile is minimal, replay prints one line saying facts are unavailable because collection is off.
