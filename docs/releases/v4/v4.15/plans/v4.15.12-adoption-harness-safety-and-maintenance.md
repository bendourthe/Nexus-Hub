## Goals First and Definition of Done

**Persona**: A maintainer composing resumable agents or bounded maintenance loops through Nexus-Hub's existing catalog and supported host capabilities.

**Problem**: Current lifecycle guidance groups transient failures under retry without distinguishing an unknown write outcome. Related recipes leave maintenance deduplication and decision freshness implicit, making safe behavior difficult to verify.

1. A1: A timed-out non-idempotent mutation stays unknown until authoritative status reconciliation establishes whether it ran. Read retry remains available. Restart, output loss, cancellation, or provider switching never independently justify repeating a mutation.
2. A2: Input or pre-tool blocking causes no new tool effect; post-tool blocking records an existing effect and withholds the unsafe result; output blocking never restarts an already executed turn. Missing host support stays unsupported.
3. A3: Repeated triggers for the same active problem reuse one job; materially changed evidence can reopen it with a reason. Jobs have a named owner and bounded review queue. Changed or absent identity never silently merges unrelated work.
4. A4: Remembered preferences preserve source, scope, owner, freshness, and supersession. They cannot create permission, override a denial, or authorize a new private-data action.
5. A5: Local reports distinguish job disposition from PR disposition and distinguish human review from human code edits. Missing usage, time, or cost stays unknown. An already fixed or nonreproducible problem is a valid no-change result.
6. Frozen adversarial and held-out cases, paired agent actions, installed bundle parity, focused checks, the final full local gate, and independent Goal review have current-candidate evidence. Missing required behavior evidence blocks completion.
7. Existing native authorization, optional loop-schema fields, credential isolation, redaction ownership, and Tier-1 instruction budgets remain intact.
