## Overview

The seeding comparison found one cost leak in Nexus-Hub's own catalog. Every file in `catalog/agents/` pins `model: opus` and none declares `effort:`. The first-party sub-agents page says a subagent on the main conversation's model runs at the session's effort level. Nexus-Hub seeds `high` through per-model `modelSettings` (`configs/platform-defaults.json`), so at the default nothing leaks; when a user raises the session to `xhigh` or `max`, every review persona, planner, and doc updater the catalog spawns pays that level too. Phase 1 declares `effort: high` on every agent, moves the per-agent model and effort classification into one living reference file, and replaces four hand-written `("model",)` strip tuples with one `CLAUDE_ONLY_AGENT_KEYS` constant so the new key cannot reach a platform that does not read it.

Who notices: a user at the default sees no change. A user who raises effort keeps it for the main conversation, and helpers stay at `high`. A user who wants a helper at `max` for one task can still get it: a per-invocation effort and the `CLAUDE_CODE_EFFORT_LEVEL` variable both outrank the frontmatter field, and the release notes say so.

Phases 2 to 4 add one read-only fast-tier agent (`log-reader`, no shell), the effort escalation ladder and filter-first rule (must-ship), a two-failures reset, pilot runs, a revert countermeasure, and a post-model-release audit (deferrable), and an implicit-state-machine pass in `refactoring-expert`. Phase 5 measures the cost claim once. No phase adds a runtime dependency, an outbound call, or a credential. The refactor-first template rule and the deep-module pass are deferred (see Scope, Cut-Line, and Exclusions).
