# Plan -- Approval Modes

**Project**: Nexus-Hub
**Version**: v4.15.10
**Filename**: v4.15.10-approval-modes.md
**Slug**: approval-modes
**Plan Type**: Feature
**Created**: 2026-11-11
**Status**: superseded (folded into v4.15.4 and v4.15.8 on 2026-11-12)
**Goal**: The checker asks for decisions with a short reply instead of a pasted code line, and a user picks one approval mode (`manual`, `auto`, or `full-auto`) in the Nexus Hub settings panel that decides both how often an `/implement` run asks and which permission posture the host tools use: `manual` asks for every decision, `auto` asks once at the start of a run and afterwards only for a fixed checker-verified list, and `full-auto` never asks and stops with a plain message where a fixed limit or an unplanned high-risk action is reached; a missing or invalid mode file is treated as `manual`, an agent-issued mode change is blocked by a guard on hosts that support hooks, and the documentation states plainly what the seal and the guard do not prevent.

## Rationale

The tasks of this plan wrote the same files that two other queued plans own. The checker tasks changed `scripts/check_plan_completion.py`, `scripts/completion_minor.py`, and `scripts/approval_page.py`, which v4.15.4 owns. The settings tasks changed `extensions/nexus-hub-settings/`, `scripts/lib/settings_control/`, and both installers, which v4.15.8 owns. The earlier rule was to run v4.15.10 serially after both plans. Folding each task into its owner satisfies that rule, removes the serial chain and a third pipeline run, and leaves one owner per file. v4.15.8 now depends on v4.15.4. Release ordering between the two destination plans is an open maintainer decision recorded in the v4.15.4 plan under Interim Release State.
