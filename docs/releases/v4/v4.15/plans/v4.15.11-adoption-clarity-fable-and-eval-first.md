## Overview

This plan adopts the v4.15.11 comparison, which compared Nexus-Hub against an article on why AI writing is unclear, Anthropic's Fable 5.2 prompting guide, a post on the codebase-ownership sentence, and a LangChain article on eval-driven development. Every item changes an existing owner. No new skill, command, hook, MCP entry, or runtime dependency is created.

The order puts template edits last. Phase 1 refreshes the baseline and records the Fable 5.2 profile. Phase 2 writes a generic test-first procedure for instruction files, sets up isolated test sessions, and freezes three case sets. Phase 3 adds a clarity reference under `writing-editing` and four fixes to the evaluation guidance. Phase 4 ships the ownership snippet beside the scope rule it relaxes. Phase 5 runs the baseline on the template text that exists at that moment, makes the three template edits, and compares results case by case. Phase 6 is the mandatory final phase.

No `STRATEGY.md` or `docs/solutions/` store exists, and no constitution exists, at `origin/develop` `cae44b15a`. The comparison, AGENTS.md, and the inspected templates ground the problem.

## Goals First and Definition of Done

**Problem and persona**: Every agent that installs Nexus-Hub reads `templates/ai-instructions/`. A developer reading that agent's output can meet prose that avoids the banned cliches yet hides who acts, turns that stop at an ordinary error, and summaries that use names the agent invented mid-task. These three defects come from the comparison's sources and are the hypotheses the Phase 5 baseline tests on Nexus-Hub's own templates. The maintainer changes those templates often, and no change is measured for behavior today.

**Must have**:

1. A generic procedure for testing any instruction file (CLAUDE.md, AGENTS.md, rules files, templates) reuses `skill-eval-loop`'s runner, grader, and gates (in this repository, trials execute on the shared v4.15.2 evaluator) and adds only what instruction files need: the keep-working case, the isolation canary, and the section diff. AGENTS.md links it from the template step.
2. Isolated test sessions: headless CLI runs with a throwaway configuration directory containing only the text under test, one fixed model for both arms, and an isolation canary that must pass before any case result counts. Runs execute on the shared v4.15.2 evaluator.
3. Three frozen case sets (clarity, self-coined terms, obstacles), committed before any baseline run.
4. For each of the three template rules, one of two outcomes is recorded: it ships with a baseline that failed on the pre-edit text and a case-by-case comparison showing at least one gain and no loss; or it is dropped or reverted with a known gap. Both outcomes satisfy this item.
5. A `claude-fable-5-2` prompting profile records each measured finding from the Fable 5.2 guide with its source and date.
6. `writing-editing` owns a three-fault clarity reference; `anti-slop-editing` Detect mode links it as a second output section.
7. `ai-output-evaluation` and `skill-eval-loop` cover tool-path scoring, narrow pass/fail judge questions, rewritten-variant coverage, and per-PR versus scheduled eval cadence.
8. The ownership sentence ships only as an opt-in snippet under `minimal-construction`, off by default, with the five capability-gate elements in the release notes.

**Measures**: per case, pass means at least 4 of 5 runs pass; a gain or loss counts only when a case's pass count moves by 2 or more; per rule, the comparison table lists gains, losses, no-change, unstable, and not-run cases; output tokens per arm and added input tokens per rendered template are recorded; live-run spend stays at or under USD 80; +0 skills, commands, hooks, MCP entries, and runtime dependencies. No claim is made about prose quality beyond the recorded cases.

## Scope and Construction Limit

In scope: comparison items A1, A2, A3, A4, A5, A7, A8a, A9, and a single A6 count handed to v4.15.0. Out of scope: A8b (cut on 2026-11-11; known gap owned by v4.21.2's paired-run work), the full Fable 5.2 "Finishing work" block, the ownership sentence as a default, harness reminders through mid-conversation system messages, hard STE or sentence-length limits in default templates, LangSmith or any hosted eval service, a detector score as a clarity metric, and API-level effort settings (comparison items N1 to N8). Rewording absolute "never" rules belongs to v4.15.0; the subagent-briefing rule belongs to v4.15.9.

**Spending limit**: live test runs use the pilot Anthropic API key, mapped only into the child process environment, with a hard cap of USD 80 for the whole plan. Estimated cost: about USD 32 for one baseline and one after run of all three sets, about USD 75 worst case with two revision rounds and grading. When the cap is reached, every remaining case is recorded as "not run" and nothing is retried.

**Revision limit**: at most two revision rounds per rule across Phase 5. Each round re-runs only that rule's case set.

**Template size limit**: each rule adds at most three sentences. New text is folded into existing sentences and trimmed first. A line cap in a template test or a ceiling in `docs/policy/doc-budgets.json` rises only by the measured delta, with a justification key.

**Construction-debt**: new files are one prompting profile and its test, one instruction-file eval reference, one clarity reference, one ownership reference, three case files and their fixtures, one decision record, and evidence files under `docs/releases/v4/v4.15/development/`. Edited files: thirteen templates, AGENTS.md, `docs/policy/doc-budgets.json`, `CONTEXT.md` (two glossary terms, added during planning), and six skills: `model-prompting-research`, `skill-eval-loop`, `writing-editing`, `anti-slop-editing`, `ai-output-evaluation`, `minimal-construction`, plus the `agent-communication` mirror. Each addition has a consumer: the profile feeds `/tune-prompting`, the cases feed Phase 5, the clarity reference feeds Detect mode, the snippet serves users who opt in.

**Prompt**:

The comparison concludes PASS only when every required field has observable evidence; a green pipeline run is not evidence, because a pipeline that checks nothing is green for the wrong reason. If this repository ships more than one installer, run or add a declarative cross-installer parity gate covering distributed artifacts, supported platforms, named capability counterparts, and external-tool fallbacks, then use [[cicd-integration]] to select real-installer proof for affected delivery boundaries with identical postconditions. Required broad target-OS coverage runs in the integration matrix unless this plan or a recorded acceptance criterion requires that local proof; do not create an all-platform local run for an unchanged installer. Cross-link [[platform-contract-verification]] so discovery and delivery are checked in the same pass. If the repository ships zero or one installer, record a silent no-op and continue.
