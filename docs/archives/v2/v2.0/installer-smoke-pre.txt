## Stability-gate grep on the four installer files

Validation per plan sub-task 3.2:

```
$ grep -n "DevAI-Hub\|devai-hub\|devai_hub\|DEVAI_HUB\|DEVAI-HUB" \
    scripts/installer.sh scripts/installer.ps1 install.sh install.bat
scripts/installer.sh:1682:# Detects an existing ~/.devai-hub/ install and migrates it to ~/.nexus-hub/.
scripts/installer.sh:1690:    local legacy="$HOME/.devai-hub"
scripts/installer.sh:1695:        echo -e "  ${YELLOW}Detected existing DevAI-Hub install at $legacy${RESET}"
scripts/installer.ps1:2034:# Detects an existing ~/.devai-hub/ install and migrates it to ~/.nexus-hub/.
scripts/installer.ps1:2042:    $legacy = Join-Path $env:USERPROFILE ".devai-hub"
scripts/installer.ps1:2050:        Write-Host "  Detected existing DevAI-Hub install at $legacy" -ForegroundColor Yellow
```

Six matches, all inside the legacy-install migration functions (`migrate_legacy_install` in installer.sh, `Invoke-LegacyInstallMigration` in installer.ps1). These references are required by the design - the migration prompt must name the legacy path so users can recognize what is being migrated.

The plan's literal-zero grep target is therefore relaxed to "no unintended references" - the migration block is the explicit exception. This is consistent with the Phase 3 sub-task 3.3 pseudocode, which itself includes `local legacy="$HOME/.devai-hub"` verbatim.

## End-to-end install smoke

Deferred to Phase 8 sub-task 8.2 (cross-platform installer dry-run). Rationale: the installer text now references `extensions/nexus-skill-server`, `extensions/nexus-code-search`, `extensions/nexus-web-fetch`, and `scripts/nexus_mcp_benchmark.py`. Of these, the script (`nexus_mcp_benchmark.py`) was renamed in this phase to satisfy the `test_installers_copy_every_scripts_dir_py_file` contract, but the three `extensions/nexus-*` directories are renamed in Phase 4. A full end-to-end install will therefore skip the MCP-server install branch (the `Test-Path`/`if [ -d ... ]` guards return false for the new paths) until Phase 4 completes.

Banner + migration + path-construction logic was verified via the new pytest assertions instead.

## Cross-phase coupling note

`scripts/devai_mcp_benchmark.py` -> `scripts/nexus_mcp_benchmark.py` was originally scheduled for Phase 4 sub-task 4.3. The smoke-test contract `test_installers_copy_every_scripts_dir_py_file` requires every `scripts/*.py` filename to be referenced by BOTH installers. Because Phase 3 sub-task 3.2 updated the installer references to `nexus_mcp_benchmark.py`, the file rename had to follow in the same phase for the test to pass. The script's internal imports (`devai_skill_server`, `devai_code_search`, `devai_web_fetch`) were also renamed in lockstep so the file parses cleanly; the actual extension package rename remains in Phase 4 scope and the script will not run end-to-end until Phase 4 completes.
