| BG-P3-1 | `merge_marker_section` truncated the block at the first nested mention of the end marker | BG | Phase 3 (T019 contract suite surfaced the failure) | The `gemini` integration's `base-gemini-ide.md` template references both `<!-- NEXUS_HUB_START -->` and `<!-- NEXUS_HUB_END -->` literally in its body to explain the marker mechanism to users. `_replace_between_markers` and `_strip_between_markers` used `text.index(end_marker, start)` (first occurrence), so the second install treated the nested mention as the boundary and rewrote a partial block. Fixed by switching both helpers to `text.rindex(end_marker, start)` so templates can quote the markers without breaking idempotency. |
| BG-P3-2 | Copilot first-install wrote the rendered template without a marker; subsequent installs appended the marker block to themselves | BG | Phase 3 (T019 contract suite surfaced the failure) | `CopilotIntegration.install_workspace` originally branched on `dst.exists()`: pre-existing file -> merge `marker + rendered`; absent file -> write `rendered` bare. The second install then saw a marker-less file and appended `marker + rendered`, leaving the file growing on every run. Fixed by always emitting `<marker>\n\n<rendered>\n` on first install so the second install sees the marker and short-circuits to `kept`. |
| BG-P4-1 | TypeScriptExtractor missed `extends` / `implements` clauses in tree-sitter-typescript 0.23+ | BG | Phase 4 (T028 stabilization surfaced the failure) | Initial Phase 4.3 (T025) implementation read the class heritage via `class_node.child_by_field_name("heritage")`, but tree-sitter-typescript 0.23+ exposes `class_heritage` as a named child without a field name (the older `heritage` field was removed). The extractor returned `None` for the heritage lookup so no `EXTENDS` / `IMPLEMENTS` edge was emitted. Fixed by walking `node.named_children` to find the `class_heritage` node, then iterating its `extends_clause` / `implements_clause` children and emitting one edge per base type. The two failing tests (`test_ts_extractor_emits_class_and_interface`, `test_ts_extractor_emits_extends_for_class`) pass after the fix. |
