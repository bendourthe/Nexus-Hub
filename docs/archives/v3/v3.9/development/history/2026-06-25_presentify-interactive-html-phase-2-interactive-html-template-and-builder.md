## Goal

Build the reusable, offline, single-file presentation template and a deterministic baseline builder that injects the content model into it (inlining CSS/JS, base64 images, and inline SVG charts), plus the design spec that defines the interactive feature set and the LLM enrichment pass that takes the baseline to "captivating". Zero external network requests in the output; the offline guarantee is enforced by a self-check, not assumed.

## What shipped

- **`catalog/skills/specialized-domains/document-to-interactive-html/assets/presentation-template.html`** (new): a single self-contained HTML scaffold. All CSS in one `<style>` block, all JS in one `<script>` block, zero external references (system font stacks only; inline SVG omits the `w3.org` namespace attribute on purpose so it does not read as an external reference). Carries a design-token `:root` block driven from theme tokens, a slide model (one `.slide` per section), navigation (Prev/Next, full keyboard map, an outline panel auto-built from the DOM, a top progress bar, a slide counter, fullscreen), deep-link hash sync (`#s3`), directional slide transitions guarded by `prefers-reduced-motion`, responsive layout (phone simplification + projector widening), a print/PDF path that stacks every slide, and presenter notes hidden until toggled. Opened raw it shows a four-slide demo and every control works offline. Three marker regions the builder replaces: the `<title>`, the `/* NEXUS_THEME_START */ ... /* NEXUS_THEME_END */` CSS custom-property block, and the `<!-- NEXUS_SLIDES_START --> ... <!-- NEXUS_SLIDES_END -->` slides region.
- **`catalog/skills/specialized-domains/document-to-interactive-html/assets/theme.json`** (new): the default presentation theme on the `theme-tokens` schema (six-slot palette, three font stacks, spacing base + scale, radius, shadow) plus an optional `chart_palette` for multi-series charts. Matching the theme-tokens schema is what makes the override hook free: a curated theme-tokens file or a brand-styling brand JSON is already this shape and drops in as a `--theme` override with no adapter.
- **`catalog/skills/specialized-domains/document-to-interactive-html/scripts/build_presentation.py`** (new, ~430 lines): the deterministic baseline builder. Reads a content-model JSON (Phase 1 contract), deep-merges an optional theme override over `assets/theme.json`, emits the theme as CSS custom properties, renders every block kind server-side (paragraph, depth-nested bullets, table, base64 image, quote, code, hidden speaker notes; unknown block types ignored for forward-compat), and renders `chart` blocks as inline SVG (bar/line/pie/doughnut) with no charting library and no CDN. Writes ONE self-contained `.html`, then runs a post-write self-check (`assert_no_external`) that fails the build (exit 3) if the output contains an off-host fetching construct (external `src`/`href`/`poster`/`cite`/`action`/`xlink:href`, `@import`, `url(http...)`, `<script src>`, or `<link rel=stylesheet>`). Rejects an unsupported `schema_version` (exit 2). `--help`, deterministic output, all diagnostics to stderr. ruff-clean, type-hinted, no bare excepts, zero network imports.
- **`catalog/skills/specialized-domains/document-to-interactive-html/references/interactive-features.md`** (new): the design contract - the full interactive feature catalog (keyboard map, outline, progress, fullscreen, deep links, transitions, reduced-motion, responsive/projector, print path, speaker notes), the inline chart-type guidance (when to use bar/line/pie/doughnut), the theme override path (theme-tokens / brand-styling, with the exact tokens the builder consumes and the `chart_palette` fallback), the five-move LLM enrichment pass tied to `hallmark-design`, and the single-deck/report/multi-file input-mode decision rule. This is the Tier-3 reference SKILL.md will link to in Phase 3.

## Key decisions / troubleshooting

- **Template/builder split: server-side block rendering, DOM-driven chrome.** The Python builder renders block HTML (including inline SVG charts) and injects it into three marker regions; the client-side JS builds the outline, progress, and counter from whatever `.slide` elements are in the DOM. So the builder never injects the outline separately, and the raw template is a fully working standalone deck (demo slides + working controls) - which is also what makes the "opens standalone" acceptance true.
- **Inline SVG omits the namespace attribute deliberately.** `xmlns="http://www.w3.org/2000/svg"` would be an `http://` token that a naive offline grep flags. Inline SVG inside an HTML document does not need the namespace declaration (the HTML parser implies it), so it is omitted - keeping both the template's own grep clean and the output free of any `w3.org` reference (verified).
- **The self-check distinguishes a fetch from a mention.** A source document can legitimately contain a URL as body text; that text is HTML-escaped into element content and is NOT a fetch. `assert_no_external` therefore scans only for fetching constructs (resource attributes pointing off-host, `@import`, `url(http...)`, external script/stylesheet), not for any `https?://` substring. Verified: a slide whose paragraph literally contains `https://example.com` builds clean, while an injected external `<link>` or `url(http://...)` raises exit 3.
- **theme.json matches the theme-tokens schema on purpose.** Rather than a bespoke shape, the default theme is a theme-tokens object, so the override path is a free deep-merge of any theme-tokens or brand-styling JSON. `chart_palette` is the one additive extension; when an override omits it the builder derives chart colors from accent/primary/secondary/muted.
- **Well-formedness verified with the right tool.** Python's stdlib `html.parser` gives a confidently-wrong verdict on this document (it does not implement HTML5 foreign-content mode for inline SVG and cannot even see the `<body>`/`<main>` start tags, so it reports a phantom "stray </main>"). The authoritative check is `lxml.html.fromstring` (parses with no exception) corroborated by a direct per-tag open/close balance (all 26 distinct tags in the injected region balanced, each SVG internally balanced). Browsers use the HTML5 tree builder, which handles inline SVG correctly.
- **No installer edit and no registry edit this phase.** Per-skill `assets/` / `scripts/` / `references/` subdirectories are auto-copied recursively by both installers (AGENTS.md "Distribution channels" row 1), so no `installer.{sh,ps1}` copy step is needed. With no SKILL.md yet, the skill is still not counted and the three registries are untouched - registration is Phase 3's job.
