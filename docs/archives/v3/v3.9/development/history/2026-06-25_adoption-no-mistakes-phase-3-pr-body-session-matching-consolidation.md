## Key decisions / troubleshooting

- **N7 deferred, not built (the recommended default).** The decision turns on internal consistency: N7 reconstructs intent after the fact from session transcripts, but the Phase 1 N3 enrichment already taught the agent to capture intent verbatim from the live conversation (which the source tool itself calls faster and less flaky). Building N7 would partially work against the doctrine just imported, so its value is low whenever the agent already knows the intent. Deferred with a recorded condition (a genuine need for after-the-fact intent recovery) and the build recipe (the matching section, the required RE-matrix row, the redaction confirmation). `session-query/SKILL.md` was therefore left untouched.
- **Registry-edit decision: no edit needed.** Read the final `summary_l0` / `overview_l1` of all six enriched skills. Each enrichment is a doctrine refinement within the skill's existing scope (the finding-action taxonomy under `intent-based-review`'s "verify acceptance criteria" core; the verbatim-escalation rule under `receiving-code-review`'s "no performative agreement" stance; round-history hygiene under `multi-agent-code-review`'s "confidence-gated findings pipeline"; the canonical gate under `shipping-and-launch`'s "pre-flight checks"; the no-busy-poll note under `loop-engineering`'s "goal-terminated loops"; the PR-body-from-trail pattern under `pr-description-writer`'s "risk, and reviewer notes"), not a new headline capability that changes a one-line summary. So `data/SKILL_INDEX.md`, `data/skills.json`, and `data/marketplace.json` were left unchanged, following the v3.8.0 / v3.9.0 precedent recorded in the same known-gaps file.
- **Attribution: the report path is the only place the product token appears.** The Reverse-Engineering Attribution Rule forbids upstream names in distributed artifacts (the SKILL.md files) but locates attribution in the RE-matrix Rationale column. The matrix prose stays generic ("a local git-proxy verification-gate runtime"); the telemetry endpoint and the opt-out env-var are described, not named; the only occurrences of the product token are the `comparison-no-mistakes.md` / `adoption-no-mistakes.md` path citations in the matrix, known-gaps, and CHANGELOG (none of which the installer distributes), consistent with how the sibling looper / deer-flow rows cite their reports.
- **PR-body pattern uses only generic vocabulary.** The N5 section avoids the source's schema tokens (`step rounds`, `rounds`, `prsummary`): it says "issue-then-fix-then-verification narrative", "flat chronological log", and "how many attempts a fix took". Confirmed by a focused grep.
