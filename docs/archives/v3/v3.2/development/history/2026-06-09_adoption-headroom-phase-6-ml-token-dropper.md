## Reconciliation (2026-06-10)

Phase 6 was implemented twice in parallel -- once on this machine and once, accidentally, on a second machine the night before -- producing two designs that diverged on the same axis: the pushed commit `e6ddbc5` was a **pure-lossy** dropper (no CCR, no retrieval), while the in-session work was **CCR-reversible**. The maintainer chose "reconcile: keep the pushed base + add reversibility". Mechanically this was a clean fast-forward (the local uncommitted work was stashed; `e6ddbc5`'s parent was the local Phase-5 HEAD, so no merge bubble), then reversibility was grafted onto `e6ddbc5`'s stronger base (it has the more faithful sub-word tokenization and a larger test suite) rather than replacing it:

- `drop_tokens` gained an optional `store` parameter (the same CCR write seam `smart_crush` / `compress_code` use). When a store is supplied and a real drop occurs, the full original is persisted behind a content-hashed `<<ccr:HASH N_rows>>` marker appended to the kept preview, so the lossy preview resolves back to the exact original via `retrieve` -- the engine's every-drop-reversible invariant now holds for this strategy too.
- A **never-expand guard** persists + marks only when the reversible preview is actually smaller than the original (the marker's token cost, notably the content hash, can outweigh the drop on a small input); otherwise the original is kept verbatim. Growing the payload is never acceptable.
- With `store=None` (the default) behavior is byte-for-byte e6ddbc5's pure lossy preview, so all 35 of its original tests pass unchanged; 7 reversibility tests were added on top.

## Goal

Add the free-text compression path the deterministic engine deliberately lacks. SmartCrusher/CodeCompressor compress structured content (JSON arrays, code) reversibly via the CCR store; logs and prose pass through untouched (the ContentRouter leaves `TEXT` verbatim). Phase 6 ports headroom's Kompress strategy -- a pre-trained ModernBERT importance classifier that scores units of free text and drops the lowest-importance ones to a target ratio. This is the engine's only *lossy* strategy, which is exactly why the plan scopes it as a DEFAULT-OFF, opt-in module gated behind the Phase 5 accuracy harness, with zero new outbound calls and no user data leaving the machine.

## Subtasks completed

1. **T019 -- the ML token-dropper** (`src/nexus_context_compressor/transforms/ml_token_dropper.py`). A default-off, lossy free-text compressor. `MLTokenDropperConfig` (`enabled=False`, `target_ratio=0.5` keep-fraction, `min_words=20`, `model_dir=None`) and `DropResult` (text + token/word accounting + `ran`/`degraded`/`hint`, with `ratio` and `dropped_words` properties). `drop_tokens(text, *, config, scorer=None)` is the entry point: with the default (disabled) config it is a pure identity that never loads a model; when enabled it scores each whitespace word, keeps the top `target_ratio` by importance (deterministic tie-break by earliest position, always >= 1 word), and rebuilds readable text. The importance scorer is a pluggable seam: an injected `scorer` wins, otherwise `build_onnx_scorer(config)` constructs the default ONNX backend or returns a precise install hint. The backend probes `onnxruntime` -> `numpy` -> `tokenizers` -> a local weights bundle (`model.onnx` + `tokenizer.json` under `config.model_dir`, `NEXUS_COMPRESS_MODEL_DIR`, or the `~/.nexus-hub/cache/models/importance-scorer` default, mirroring the CCR store's path convention), and on any missing piece returns `(None, hint)`. The live inference (`_onnx_word_scores`) encodes the joined words with offsets, runs the session, reduces per-sub-word logits to an importance scalar (`_reduce_logits_to_importance`: softmax positive-class for a classifier, raw scalar for a regressor), and mean-pools sub-word scores up to their covering word (`_pool_subword_scores`). Reconstruction (`_reconstruct`) preserves the original inter-word spacing -- including newlines/indentation -- between surviving neighbors and collapses a dropped span to a single space. Exported from `transforms/__init__.py` (like the standalone `align`); the `[ml]` extra grew from `onnxruntime` to `onnxruntime`+`numpy`+`tokenizers` (the three standard, lightweight companions for local ONNX text inference, documented in `pyproject.toml`).
2. **T020 -- tests + stabilization** (`tests/test_ml_token_dropper.py`, 35 tests). Covers every plan stability-gate assertion: off by default (identity, scorer never called); enabled-below-`min_words` identity; enabled drops low-importance words to the exact keep budget with all keywords surviving; `target_ratio` 1.0 keeps everything verbatim and 0.0 keeps exactly one word; determinism; the absent-backend degradation (real CI path: onnxruntime absent -> original text + install hint, no crash); failing/wrong-length scorer degradation; a no-network proof (the socket layer is poisoned and the enabled dropper still returns cleanly, because the module never fetches); every `build_onnx_scorer` guard branch via `sys.modules` stubs (each dep absent, weights absent, load failure, all-present-returns-callable); the pure helpers (`_select_keepers` top-by-score + tie-break + ratio clamp, `_reconstruct` spacing/newline preservation across drops, `_word_spans` round-trip, `_pool_subword_scores` mean-pool + uncovered-word-zero, `_safe_scores` guards, `_resolve_model_dir` precedence); the numpy reduction (guarded by `importorskip`); and a re-run of the Phase 5 accuracy gate asserting it still PASSes with the module present.

## Key decisions

- **Whitespace-word granularity, not sub-word.** The upstream classifier scores sub-word tokens; this port scores and drops at the word level. A word reconstructs to readable text without a sub-word detokenizer, surviving-run spacing is preserved, and it is the unit a reader/agent sees. The model's sub-word scores are mean-pooled up to their covering word. Logged as DF-v32hr-15.
- **Pluggable scorer seam.** The drop logic depends on a `Scorer = Callable[[list[str]], list[float]]`, not on the ONNX backend. This makes the entire selection/reconstruction/ratio logic testable with an injected deterministic scorer (no heavy deps), lets a consumer supply its own model, and isolates the un-CI-runnable inference glue behind one function guarded by `_safe_scores`.
- **The module never downloads weights -- the strongest offline-first posture.** Rather than fetch-and-cache, it only *loads* pre-placed local weights (like tiktoken's vocab cache and the v3.0.0 OSV.dev DB). This makes "no outbound call" a structural guarantee, not a mocked behavior: there is no fetch path to mock. The install hint tells the user how to obtain the public weights once; that download carries no user data and is the user's step.
- **Standalone transform, NOT wired into the default pipeline.** The dropper is exported from `transforms/` and callable directly, but the default `ContentRouter`/`compress`/`compress_output` path is unchanged -- free text still passes through. A lossy default belongs off the auto pipeline (the same stance as CacheAligner, DF-v32hr-9). The runtime auto-wiring carve-out is DF-v32hr-14. This keeps every changed line traceable to T019/T020 and the deterministic strategies as the default.
- **`[ml]` extra expanded to onnxruntime+numpy+tokenizers.** Real local ONNX text inference needs the runtime, tensor I/O, and a sub-word tokenizer; declaring only `onnxruntime` would ship a broken extra. The three are standard, lightweight (the `tokenizers` HF runtime, not the heavyweight `transformers` stack) and carry no outbound dependency.
- **DF-v32hr-10 resolved, DF-v32hr-14 carved out.** The Phase-4 free-text-parity deferral is discharged (the scheduled mechanism shipped); the residual default-off/not-auto-wired property is the narrower DF-v32hr-14 -- the same resolve-with-carve-out shape as DF-v32hr-7 -> DF-v32hr-9.
- **CCR-reversible via the store seam (reconciliation, 2026-06-10).** Rather than leave the dropper as the engine's one irreversible strategy, reversibility was grafted on keyed to an optional `store` parameter: a store-backed drop persists the full original behind an appended `<<ccr:HASH N_rows>>` marker and is resolvable via `retrieve`, while `store=None` stays the pure lossy preview. This makes reversibility opt-in at the call site (exactly how a runtime would thread its shared store) without changing the lossy default, and upholds the engine's every-drop-reversible invariant. A never-expand guard prevents the marker's token cost from growing a small payload. See Reconciliation above.
