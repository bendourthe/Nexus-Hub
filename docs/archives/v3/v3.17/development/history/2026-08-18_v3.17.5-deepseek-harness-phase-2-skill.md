**2. The plan understated the registration surface, by half.** It named three registry files. There are six places:

| # | Surface | Caught by |
|---|---|---|
| 1 | `SKILL_INDEX.md` table row | (known) |
| 2 | `SKILL_INDEX.md` `**Total: N skills**` line | `test_registry_consistency.py` |

| 4 | `skills.json` `statistics.total_skills` + `statistics.categories` | `test_registry_consistency.py` |

Surface 6 is the dangerous one. The capability modules have been category-complete since schema 1.5.0 precisely so that every skill is reachable by a focused install, and a skill absent from all of them is reachable only via `full`. Nothing in the fast validator loop detects it; only `test_every_catalog_skill_is_reachable_through_some_module` does, and that suite takes about 30 minutes locally. It failed with "1 catalog skills are reachable only via `full`: ['deepseek-harness']", which was the correct and useful message.

## The Routing Failure Worth Recording

The first eval run failed:

```text
FAIL routing: deepseek-harness: weakest positive 'pos-dump-config' (0.38)
  does not clear strongest near-miss 'neg-claude-sdk' (0.83) by the 1.15x margin
```

The scorer uses containment overlap, `|A intersect B| / min(|A|, |B|)`, not Jaccard. Because a user prompt is almost always the smaller set, a skill's score answers "what fraction of the user's words does this description claim?".

The original description claimed the generic quartet *build*, *agent*, *tool*, and *sdk*, and additionally carried the literal phrases "build an agent with" and "Claude Agent SDK" (the latter from an over-explicit SKIP clause). A Claude-SDK prompt therefore matched at 0.83.

The fix was to trade generic vocabulary for specific vocabulary in both directions at once: name the routing targets by capability rather than by competitor product ("any other vendor's agent runtime or harness, each of which has its own dedicated skill"), and add the concrete trigger surface the positives actually use (`ctx.tools`, `ctx.llm`, `ctx.sandbox`, `dump-config`, "patch layer", "one-shot"). That raised the weakest positive and lowered the strongest near-miss simultaneously.

This is a reusable authoring rule: a pushy SKIP clause that names a competitor product verbatim imports that competitor's trigger vocabulary into your own description, which is the opposite of what the SKIP clause is for.
