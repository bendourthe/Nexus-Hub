## Design Decisions Beyond the Plan

The plan specified the failure classes and the manifest shape. Three details it left open were decided during implementation and documented in the code:

1. **Code fences and tables are counted.** Exempting them would make "move the prose into a code fence" the cheapest way to pass the gate, which lowers the number without lowering the token cost.
2. **Duplicate detection runs twice, because there are two distinct bugs.** `object_pairs_hook` catches a literal repeated JSON key (which `json.loads` would otherwise resolve last-one-wins, silently enforcing only the second ceiling); path normalization catches the semantic duplicate (`./AGENTS.md` vs `AGENTS.md`, or Windows separators).
3. **Booleans are rejected explicitly.** `bool` subclasses `int` in Python, so `"AGENTS.md": true` would pass a naive `isinstance(x, int)` check and then compare as ceiling `1`.

`--list` is a reporting mode, not a gate: it exits 0 even when a doc is over budget, and flags any budget with under 5% headroom as `<- tight`, since a doc that tight is effectively frozen rather than budgeted.

- Negative proof against the real repo: forcing the `AGENTS.md` ceiling to 100 via `--manifest` produces `OVER AGENTS.md: 9138 words exceeds the 100 ceiling by 9038` and exit 1. The gate was proven to fail, not only to pass.
- `tests/validators/test_validate_doc_budgets.py`: 23 passed.

- `check_incident_notes.py`, `check_version_sync.py`, `check_base_template_parity.py`, `check_installer_parity.py`: all green.

`make` is unavailable in this environment, so the `make validate` target was exercised by running its constituent validators directly. `make lint` is ShellCheck over shell scripts; this phase added no shell, so it is not applicable.

## Findings Recorded

The plan's seeding rule was followed as written, so this is not a Phase 1 failure, but the gate measures the cost without reducing it.
