## Model Routing

The plan rated this phase `frontier` / `high`, the heaviest in the plan, on the grounds that it "redefines the boundaries between three existing memory surfaces, and a wrong split creates a fourth redundant store". The session ran on Opus 5 (`strong`), which is below that rating, so the gap was surfaced rather than silently accepted.

The user chose to continue on `strong`. The reasoning offered and accepted: the frontier rating was for the surface-split *design*, and the plan itself already resolves that design in full (class taxonomy, folder layout, per-lifecycle skeletons, the split definition). What remained was execution against a settled design.

## The Withdrawn Step

Sub-task 4.1 instructed: "Migrate `.claude/memory/decisions.md` content into dated implemented/rejected records ... and replace that file's body with a one-line pointer."

**That file does not exist in this repository.** The only `decisions.md` is `catalog/memory/decisions.md`, which is a blank ADR template the installer copies to every end user's `~/.claude/memory/`. It contains a `[Decision Title]` skeleton and no Nexus-Hub decisions.

So the instruction had nothing to migrate, and executing it literally would have meant editing a **distributed artifact**, changing what every user receives on their next install, under the guise of consolidating this repo's memory. The two are unrelated surfaces that happen to share a filename.

The user was asked and chose to skip the migration and record the finding. `catalog/memory/decisions.md` is untouched. Recorded as `MT-4`.

The validator now guards against the confusion in both directions: a `.claude/memory/decisions.md` containing `# Decision:` fails with a relocation hint, while one containing only the ADR template passes untouched. Both directions are tested.

## The CI Path-Filter Catch

`docs/decisions/**` is validator INPUT, but the CI path filter excludes `docs/**`. Without re-inclusion, a push adding a malformed record would skip CI entirely, so the exact edit the guard exists to catch would be the edit that never ran it.

This is a recurring defect class in this workflow, already fixed twice: `docs/policy/**` and `docs/incidents/**` both carry comments explaining their own re-inclusion on identical grounds. `docs/decisions/**` was added to both the `push` and `pull_request` filters with a comment following the established pattern. The rule those comments state, and that this follows, is "a docs path earns a trigger only when a guard reads it".

## Design Notes

**Rejected records are frozen.** The README states that a proposal moving to `rejected/` is moved without editing its body, and the validator enforces the corollary: proposal-era headings (`## Proposal`, `## Acceptance criteria`) are banned in `implemented` records but explicitly allowed in `rejected` ones, with a test asserting that. A future proposer needs to see what was actually proposed, not a summary of why it lost.

**`## Consequences` is mandatory in `implemented`.** A decision with no stated consequences has not been thought through to its cost.

**No `feature` class.** Per the plan. The validator's error message says so explicitly, since "feature" is the obvious wrong guess and a bare "unknown class" would not tell the author where feature intent actually belongs.
