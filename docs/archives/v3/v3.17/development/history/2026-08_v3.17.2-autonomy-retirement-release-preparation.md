### 2.2 Fail-safe legacy-state restoration

**Branch**: `release/v3.17.2` | **PR**: none | **Merged to**: pending

**What happened**: Added one idempotent Python helper that restores only version-1 controller state within the resolved repository boundary. It restores recorded backups byte-for-byte, deletes a provider config only when the controller created it from nothing, preserves unresolved state for retry, removes stale `autonomy-expiry` and `autonomy-guard` Claude hook registrations, and retains unrelated user settings and hooks. Both installers deploy and invoke the helper at global and workspace scope, and a temporary SessionStart handler retries projects that were not open during upgrade.

**Key files changed**: `catalog/hooks/retire-provider-override.py`, `catalog/hooks/settings.json`, `scripts/installer.sh`, `scripts/installer.ps1`, `configs/installer-parity.json`, and focused regression tests.

**Troubleshooting**:

- **Problem**: `installer parity: FAIL: function: posix.install_retired_override_cleanup has no documented counterpart or exception` and the equivalent Windows failure.
- **Root cause**: The implementations matched, but the generic parity manifest did not yet declare the new function pair.
- **Resolution**: Added the exact Bash/PowerShell counterpart group to `configs/installer-parity.json`; the parity gate then passed.
- **Problem**: ShellCheck reported `SC2088: Tilde does not expand in quotes` for the global hook path.
- **Root cause**: The tilde is intentionally stored in Claude settings for expansion when the hook executes, not expanded by the installer assignment.
- **Resolution**: Documented the deferred expansion and suppressed `SC2088` only at that assignment; ShellCheck then passed.

## 5. Plan Discrepancies

- The original v3.17.0 plan implemented the autonomy controller. v3.17.2 follows its approved retirement amendment because the product acceptance criterion cannot be met through supported VS Code APIs.
- Release review added the provider-state restoration migration before publication. Controller removal alone was insufficient for users who had already enabled it.
- The generic installer parity manifest required one additional counterpart declaration discovered by the hard gate.

---

## 6. Assumptions Made

- **One-release compatibility window**: users may upgrade directly from v3.17.0 or v3.17.1 after v3.17.2 ships, so the helper and SessionStart retry remain until v3.17.3.
- **Provider authority boundary**: restoration is limited to recorded controller state; the migration never enables a provider mode or attempts to bypass provider approval logic.
- **Remote CI authority**: hosted Linux, macOS, and Windows jobs are authoritative for the broad installer matrix that exceeds the local Windows time bound.
- **No layout mutation**: active v3.17 plans, comparisons, evidence, and histories remain Cat 4; no archive or deletion is justified.
