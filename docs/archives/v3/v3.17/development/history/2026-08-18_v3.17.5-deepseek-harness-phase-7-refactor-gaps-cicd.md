## MT-5: The Full Repair, and a Correction

The maintainer chose the full repair over the two narrower options. All 156 drifted fields were synced from `SKILL.md`, which is the source of truth because it is the file agents actually load: 141 fields in `skills.json` (74 `description`, 51 `overview_l1`, 16 `summary_l0`) and 15 summaries in `SKILL_INDEX.md`. The six encoding-corrupted entries now carry the same `U+2014` their sources do, in place of the `U+00E2 U+20AC U+201D` cp1252 mojibake that was shipping to users and feeding the MCP search server.

The gate is now `--strict` in both `make validate` and CI, so any reappearance is a fresh regression rather than inherited debt. The Phase 5 test that asserted the drift stayed *visible* was replaced by one asserting it is *zero*, which is what that test's own message instructed its future reader to do.

**A correction to the Phase 5 risk assessment.** Phase 5 recorded that repairing this would rewrite 74 routing descriptions and therefore needed a full eval re-run to catch routing shifts. That caution was overstated for this direction: `run_trigger_evals.py` scores descriptions read from `catalog/skills/`, not from `skills.json`, so syncing the registry FROM SKILL.md cannot move a routing score by construction. The gate was re-run anyway and passed with 0 failures and 0 un-allowlisted collisions. The caution remains correct for the opposite direction, editing SKILL.md itself, which is exactly why `MT-7` (nine non-ASCII descriptions) was recorded rather than fixed on release eve.

The diff is confined: 141 changed line-pairs in `skills.json` and 15 in `SKILL_INDEX.md`, with no field outside `description`, `summary_l0`, and `overview_l1` touched.

## 7.3 CI/CD

**Coverage.** All three new validators run in the existing `validate` job and in `make validate`. All five new test files live in `tests/validators/` and `tests/integrations/`, both of which the `tests` job already enumerates by name. That enumeration is a documented trap in the workflow's own comments (a new test *directory* is invisible to CI until listed), so it was checked explicitly; no new directory was created, so nothing was missed.

Path filters were extended once, in Phase 4, to re-include `docs/decisions/**` in both the `push` and `pull_request` filters. It is validator input sitting under a blanket `docs/**` exclusion, so without it a push adding a malformed record would skip CI entirely, making the exact edit the guard exists to catch the edit that never runs it. This is the third time that fix has been needed after `docs/policy/**` and `docs/incidents/**`, which is noted as a consequence in the Phase 4 decision record: the exclusion's default may be wrong for guarded paths.

**Optimization.** The honest finding is that the pipeline is already optimized along every axis the plan names, and the plan's four suggestions were all in place before this work started:

| Suggested lever | State |
|---|---|
| Path filters | In place, with per-path justification comments |
| Concurrency cancel-in-progress | In place at workflow level |
| Dependency caching | In place, pip cache keyed on the hook config |
| Gate expensive-OS jobs | In place: `bootstrap-windows` and `tests-windows` are gated to non-`pull_request` events |

Every job also carries `timeout-minutes`. The remaining expensive matrices (`install-smoke`, `installer-smoke`) are required status checks, so gating them would remove merge-gating coverage rather than waste.

This plan's net CI cost is approximately zero: three sub-second Python steps appended to an existing job, no new job, no new matrix leg, no new runner.

## 7.4 Testing and Stabilization

The full-suite run found a real bug that every scoped evidence set in Phases 2 through 6 had missed, which is worth recording plainly.

`tests/skills/test_org_authoring_surface.py` is a test about ONE skill's registration, but it also froze the whole-catalog total in three places. Phase 2 took the catalog from 272 to 273 and broke it. It survived undetected for five phases because every scoped run covered `tests/validators`, `tests/integrations`, and `catalog/hooks/tests`, and this test lives in `tests/skills`.

Two fixes, immediate and root-cause:

1. The totals in that test are now DERIVED from `len(skills["skills"])`, so it still asserts internal consistency without freezing a number that changes on every skill addition. A grep confirmed no other test hardcodes the old value.
2. The change-surface table this plan added to `verification-before-completion` in Phase 3 had no row for this case, and now does: a catalog-wide count is a global invariant, so changing it requires grepping the old value across the whole test tree rather than reasoning about which suite "should" own it.

The second matters more than the first. The discipline this plan shipped is exactly what failed here, so repairing the discipline was the real fix. Recorded as `BG-1`.

- Every `make validate` constituent run individually: 17 validators, all exit 0, including the three added by this plan and the newly-strict registry gate.
- `run_trigger_evals.py --gate`: PASS, 0 routing failures, 0 un-allowlisted collisions, after the 156-field registry sync.
- Full suite (`tests/` + `catalog/hooks/tests/`): 3768 passed, 56 skipped on the first run, with the two failures above; re-run clean after the fix (final count in the commit message).
- `tests/skills/`: 696 passed after the fix.
- The other failure was `WN-1`, the carried Windows Git-Bash `tar` quirk. This phase touched no installer or bootstrap file, and CI is authoritative for that test.
- The refactor changed no behavior because there was no refactor; the audit found a clean layout.

## Plan Retrospective

Seven phases, nine adoption items, and the pattern worth carrying forward is that **most of the value came from the guards finding things nobody was looking for**:

- The Phase 5 drift-check found a schema violation introduced in Phase 2 that no test asserted, a category typo inflating the index's category count, and 156 drifted fields including live encoding corruption.
- The Phase 2 selective-install suite found a skill unreachable from every capability module, which is invisible to every fast check.
- The Phase 6 do-not-invent rule caught two search summaries asserting vendor fields that do not exist.

Three plan errors were caught and recorded rather than executed: a stale catalog count (`MT-2`), an understated registration surface (`QG-1`), and a migration step targeting a file that does not exist (`MT-4`). A comparison-seeded plan inherits its source project's assumptions, and checking each one against the target repo before acting is what kept those from shipping.
