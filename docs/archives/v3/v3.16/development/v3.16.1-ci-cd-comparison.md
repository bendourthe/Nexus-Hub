## The one change: QG-1

**Defect.** `ci.yml` triggered on `['**', '!docs/**', 'docs/policy/**']`. v3.16.1 added tests that assert against a document under `docs/` -- `tests/skills/test_evaluation_methodology.py` reads `docs/v3/v3.16/development/evaluation-artifact-contract.md`. Under the blanket exclusion, a push editing only that contract skipped CI entirely, so **the exact edit the guard exists to catch was the edit that never ran it**.

This is not a new class of problem. The same defect was found and fixed for `docs/policy/**` in an earlier cycle, and that file's own comment records the reasoning verbatim.

**Fix applied.**

```yaml
- 'docs/v*/*/development/*.md'
```

**Why this glob and not a broader one.** Re-including all of `docs/**/development/**` would also re-include `development/history/`, and a `*` never crosses a `/`, so scoping to `*.md` directly under a `development/` directory matches the contract docs and excludes the session histories one level deeper. Session histories are frozen records that no test reads; re-including them would run the full matrix on every phase write-up for no signal. Applied to both the `push` and `pull_request` events, since GitHub Actions requires them to be configured independently.

**Verified**: both events now carry the fourth entry, and `validate_workflow_security.py` still passes.

## New test coverage: no workflow change needed

v3.16.1 added five test modules. Every one is picked up by an existing invocation, because CI invokes test *directories*, not individual files:

| New module | Covered by |
|---|---|
| `tests/skills/test_evaluation_methodology.py` | `pytest tests/skills` |
| `tests/skills/test_eval_pipeline_audit.py` | `pytest tests/skills` |
| `tests/skills/test_skill_stocktake_directive_density.py` | `pytest tests/skills` |
| `tests/installer/test_install_selection.py` | `pytest tests/integrations tests/installer` |
| `tests/installer/test_selection_parity.py` | same, plus the Windows leg |
| `tests/integrations/test_selective_install.py` | same |
| `tests/validators/test_selection_aware_verification.py` | `pytest tests/validators` |

The two `slow`-marked end-to-end installer tests run in CI (nothing deselects them there) and skip gracefully when their shell is unavailable. The `slow` marker is registered in `tests/conftest.py` rather than a root `pytest.ini`, because this repo deliberately runs several separate pytest roots and a root config would apply to invocations that never asked for it.

New fixtures under `tests/fixtures/install-selection/` sit inside the existing `paths` filter, so no trigger change is needed.

## Retained differences

| Difference | Decision | Reason |
|---|---|---|
| No `jq` installed or asserted in CI | **Retain.** | Nothing in the repo requires `jq` any more. The jq resolver written in Phase 6 was deleted unshipped precisely because it could not be verified (DF-5); both installers now call the tested Python resolver. |
| No per-job path filters within `ci.yml` | **Retain.** | Decided in v3.16.0 (its DF-1): the workflow has no per-job filters at all, and adding a positive filter would narrow coverage rather than save minutes. |
| No Python lint gate (`ruff`) in the Makefile or CI | **Retain, recorded.** | `make lint` covers shell only. Adding a Python linter is a repo-wide decision outside this plan's scope, and is recorded as v3.16.1 WN-1 rather than introduced here. |
| Windows leg does not run the full suite | **Retain.** | It runs the installer, validator, and platform-native subsets that are Windows-sensitive. Running everything twice would roughly double action minutes for little added signal. |

## Result

One migration (QG-1), applied and verified. Every other element of the optimized contract was already present and is retained. No workflow was added, removed, or restructured.
