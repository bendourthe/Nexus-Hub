## Source 1: watermarks-remover (repository)

### What the tool does

Three distinct layers, which have very different adoption postures:

- **Layer A (deterministic text cleaning)**: strips invisible Unicode - zero-width space, bidi control characters, Unicode tag characters, "exotic space" homoglyphs, and emoji glue sequences (VS16, ZWJ). Python 3.10+, stdlib-only for the core scripts, CLI entry points (`inspect_text.py`, `clean_text.py`), JSON or human-readable reports, atomic writes.
- **Layer B (statistical watermark defeat)**: heavy rewrite (paraphrase, "humanization", code-comment rewrites) to defeat token-sampling watermarks. The repo itself notes this degrades text quality and depends on a non-origin model.
- **File metadata layer**: removes C2PA chunks, EXIF, XMP, and generator tags from PNG/JPEG/SVG/PDF/DOCX/ODT/HTML/Markdown; optional pixel-domain mark removal via an external CtrlRegen checkout (non-commercial license).

### What Nexus-Hub already has (evidence)

- `scripts/validate_unicode_safety.py` detects the core Layer-A character set: bidi override/isolate controls (Trojan Source, CVE-2021-42574) and zero-width characters (ZWSP, ZWNJ, ZWJ, word joiner, BOM), as hard errors; plus non-ASCII punctuation (em/en dash, curly quotes, ellipsis, NBSP) as warnings, promoted to errors with `--strict`.
- It is already wired into `make validate` and CI (`.github/workflows/ci.yml` line 151), with tests at `tests/validators/test_validate_unicode_safety.py`.
- The ASCII-only norm is codified in `catalog/style-guides/markdown.md` (section 14, "Plain ASCII commit messages and code") and the global Critical Rules.

## Step 7: Risks, conflicts, and NOT-recommended items

### Risks and conflicts

- **Fix mode on hand-edited files**: `--fix` rewrites files. Confining auto-fix to files the agent just generated (`/plan` output) and release artifacts at release time keeps the blast radius to content the workflow owns. Detect-only remains the default everywhere else.
- **CI overlap, not conflict**: CI already runs the validator repo-wide in detect mode with punctuation as warnings. The new `/update release` gate is stricter and earlier (pre-commit, `--strict`); the two compose.
- **Grandfathered warnings**: pre-existing em-dash warnings (WN-v23-3 lineage) exist in older files. The release gate should scope `--strict --fix` to release-cycle artifacts, not the whole repo, to avoid a mass rewrite outside the change's scope.

### NOT recommended (with policy grounds)

| Item | RE class | Reason |
|---|---|---|
| Vendoring or depending on the watermarks-remover repo | drop-outright | MCP Registry Policy bucket 3 mandates reverse-engineering into a local equivalent, which already exists (`validate_unicode_safety.py`); the repo's optional backends carry non-commercial and all-rights-reserved licenses (supply-chain and licensing risk for a MIT-distributed catalog). |
| Layer B statistical watermark defeat (paraphrase/"humanization" rewrites) | drop-outright | No value for the stated use case (hygiene of self-generated plan/release Markdown); the upstream itself documents quality degradation; adopting machinery whose purpose is defeating third-party provenance signals adds ethical and trust cost with zero workflow benefit. Deterministic character hygiene fully satisfies the user's intent. |
| C2PA/EXIF/XMP/pixel-domain stripping for images and binary formats | drop-outright | Out of scope for a Markdown-first catalog; requires external binaries (`c2patool`, `exiftool`) and a non-commercial-license pixel backend (MCP Registry Policy: new dependencies and supply-chain surface without a call site). |
| "Minimal harness pack" templates from the course | drop-outright | Strict subset of what the installer already distributes; adopting it would duplicate existing artifacts. |
