## 1. Executive Summary

This is the second Nexus-Hub comparison against `no-mistakes`, covering the 34-day upstream window between the v3.9.0 snapshot (2026-06-25) and today: roughly 13 releases from `v1.38.0` to `v1.41.2`. Two findings dominate, and neither is a large adoption.

**The v3.9.0 ledger is verified closed.** All seven candidates from the first pass landed, and Section 2 cites the file and line for each. That matters more than it sounds, because the verification nearly produced a false negative: searching the catalog for the source's own vocabulary (`auto-fix`, `ask-user`, `no-op`) returns **zero hits**, which reads like the adoption never happened. It landed as `escalate bucket` and `mechanical-fix bucket` instead. That is the reverse-engineering attribution rule working exactly as intended (the doctrine transferred, the source's naming did not), and it is a methodological lesson for every future delta pass: verify a ledger against the concept's target file, never against the source's strings.

**The upstream delta is thin and almost entirely non-adoptable.** Of the 13 releases, the overwhelming majority is Go control-plane plumbing: daemon startup recovery and gate migration hardening, SSH host alias resolution for provider routing, Azure DevOps PR description handling, branch-sync reconciliation for diverged heads, custody recovery for terminal pipeline-owned runs, bounded daemon logs, and AXI output and polling fixes. Every one of those falls under the standing `drop-outright` for host-side runtimes (pre-adjudicated in v3.1.0 for `/loop` and v3.8.0 for standalone loop runtimes, and re-affirmed in v3.9.0 for this same project). Two genuine candidates survive the filter, both small prose folds, plus one marginal item and one already-covered item.

**Both v3.9.0 declines were re-verified and hold unchanged.** The runtime decline stands (the delta is the runtime getting more runtime-shaped). The telemetry decline stands on fresh evidence: `internal/telemetry/telemetry.go` still carries `defaultHost = "https://a.kunchenguid.com"` with `/api/send`, still enabled by default, still opt-out only via `NO_MISTAKES_TELEMETRY` set to `0`, `false`, or `off`. The payload remains usage-shaped (website id, hostname `cli`, title, event path, event name, timestamp, OS, architecture, version) with no indication that source code, diffs, prompts, file paths, or repository names are transmitted. It is still egress-by-default to a third-party-owned endpoint, which the MCP Registry Policy classifies as a hard-no.

**Overall recommendation: adopt nothing on a release slot; record two small folds as known-gaps items and keep both declines.** Zero new outbound calls, credentials, dependencies, or skills. This report is primarily a re-verification record.

## 7. Disposition: Known-Gaps Entries (in place of an adoption plan)

Per the maintainer decision on 2026-07-29, this report opens no release slot and produces no from-comparison plan. Its actionable output is the following entries, to be written into `docs/v3/v3.16/known-gaps.md` via `[[known-gaps-tracker]]`. Each is a deferred prose fold with a named target, so whichever cycle next touches that skill can absorb it without re-running this comparison.

**Entry 1 (M1): nested-invocation guard for `loop-engineering`.**

- **Type**: Deferred enhancement (prose fold, `skill-native`).
- **Target**: `catalog/skills/workflow/loop-engineering/SKILL.md`, alongside the existing `iteration_cap` and stall/fault-detection material.
- **What to add**: a re-entrancy rule. An agent operating inside a bounded loop or verification gate must detect that it is already inside one and refuse to start a nested instance rather than proceeding. The mechanism is an environment marker set by the outer invocation and checked by the inner one. State the failure mode explicitly: iteration caps bound each level independently, so they do not bound the recursion, and a nested loop can therefore multiply its own budget without tripping any cap. Cross-link `[[ai-billing-safeguards]]` (a nested loop is a budget-multiplication path) and `[[using-git-worktrees]]` (isolation does not imply non-re-entrancy).
- **Provenance**: reverse-engineered from an upstream re-entrancy guard. Per the attribution rule, do not name the external project in the skill body; record provenance in `docs/policy/mcp-reverse-engineering-matrix.md` if and when the fold lands.
- **Non-blocking**: nothing today is broken; the gap is an unguarded failure mode.

**Entry 2 (M2): extend `egress-redaction` beyond the egress boundary.**

- **Type**: Deferred enhancement (prose fold, `skill-native`).
- **Target**: `catalog/skills/security/egress-redaction/SKILL.md`, whose current framing is "before it leaves the host" (line 17).
- **What to add**: two additional boundaries at which the same detect-and-classify policy applies. First, **local persistence**: redact a credential before writing it into stored configuration or state, with the embedded-credential URL form (`scheme://user:token@host/path`) named as the canonical example, since it is routinely persisted by clone and remote-add flows. Second, **error surfaces**: redact before a credential reaches an error message, a stack trace, or a log line. State the reasoning that makes this a distinct gap: neither boundary is an egress boundary, so a skill framed only on egress does not cover them, yet both leave a secret in plaintext on local disk. The existing BLOCK classification for Credentials (lines 57, 89) already supplies the policy; only the boundary list needs widening.
- **Provenance**: as Entry 1.
- **Non-blocking**.

**Entry 3 (M3, optional): repair-loop prompt-size cross-link.**

- **Type**: Deferred, optional (cross-link only).
- **Target**: `loop-engineering`, cross-linking `[[context-compression]]` and `[[prompt-token-optimization]]`.
- **What to add**: note that a bounded repair loop can fail on accumulated prompt size before it reaches its iteration cap, and that compaction between rounds is the mitigation.
- **Lowest priority**; drop if the ledger is being trimmed.

## 9. Strengths to Preserve (where Nexus-Hub leads)

- **Zero telemetry, still.** Thirteen upstream releases later, `no-mistakes` remains egress-by-default. Nexus-Hub's zero-telemetry posture is a genuine differentiator worth citing by name in the MCP Registry Policy's rationale as a concrete, dated example of the pattern the hard-no list forbids.
- **The layer decision keeps paying off.** The entire delta is runtime maintenance: daemon recovery, custody, branch sync, SSH aliases, PR-host quirks. A catalog that had reimplemented the gate in v3.9.0 would now owe 34 days of that maintenance. The doctrine Nexus-Hub imported instead has required zero upkeep across the same window.
- **Native vocabulary over imported strings.** The v3.9.0 adoption expressed the finding taxonomy in Nexus-Hub's own terms (escalate bucket, mechanical-fix bucket) rather than copying `auto-fix` / `ask-user` / `no-op`. That is the attribution rule applied correctly, and it makes the doctrine read as native rather than borrowed. The tradeoff is that ledger verification must search concepts, not strings.
- **Decline durability, three passes running.** The runtime decline has now held across v3.1.0, v3.8.0, and both `no-mistakes` passes without re-litigation.
- **Cursor parity timing validated.** Upstream promoting Cursor to a first-class alias independently confirms the v3.15.0 Phase 2 investment.

## 10. Risks and Conflicts

- **M1 must not read as a prohibition on legitimate nesting.** Some architectures deliberately nest (a workflow spawning subagents that themselves loop). The rule is about *unintended re-entrancy* into the same gate or loop instance, not about depth. Phrase it as "detect and refuse an unintended nested instance of this same loop", and cross-link `[[agent-orchestration-primitives]]` so deliberate fan-out is not discouraged.
- **M2 must not duplicate the egress policy.** The data classes and the BLOCK verdict already exist in `egress-redaction`. Only the boundary list widens. Adding a parallel policy table would create two sources of truth for the same classification.
- **No conflicts with existing conventions.** All three candidates enrich existing skills additively.
- **Deliberate naming deviation.** This file's minor-only prefix is explained in the header. If a future cycle does adopt M1 or M2, prefer creating a normal release-prefixed plan at that time over retro-renaming this report.
- **N7 carries no status claim.** It was optional in v3.9.0 and was not verified in this pass. Do not record it as either closed or open.
- **Breaking changes**: none. Nothing is being shipped.
