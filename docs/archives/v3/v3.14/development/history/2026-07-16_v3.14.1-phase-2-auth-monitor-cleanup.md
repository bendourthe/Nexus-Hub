## Goal

Re-running the installer (or `nexus-hub upgrade`) silently removes the orphaned DevAI-Hub "Claude Code Auth Monitor" Windows scheduled task and any leftover launcher files, ending the recurring "Can not find script file `...\.devai-hub\scripts\run-auth-monitor.vbs`" Windows Script Host popup. DevAI-Hub v0.9.x registered the task (running `wscript.exe` on the `.vbs` every two minutes); the auth monitor and the `~/.devai-hub/` tree were later removed, but nothing ever unregistered the task.

## Sub-tasks completed

1. **2.1 - Scheduled-task cleanup.** Added `_cleanup_windows_auth_monitor_task(ctx) -> Optional[FileAction]`, modeled on `_cleanup_claude_legacy_vscode_extension`. Returns `None` when not on Windows (`os.name != "nt"`), when `schtasks` is not on PATH, when `schtasks /Query /TN "Claude Code Auth Monitor"` exits non-zero (task absent - the normal case), or when the query/delete subprocess raises (`OSError` / `TimeoutExpired`). Otherwise deletes the task with `schtasks /Delete /TN "Claude Code Auth Monitor" /F` (timeout 30); dry-run returns the `FileAction` without mutating. The task is user-level (`RunLevel Limited`), so no elevation is required. Added `import os`.
2. **2.2 - Leftover launcher sweep.** Added two sibling cleanups, `_cleanup_devai_hub_auth_monitor_vbs` and `_cleanup_devai_hub_auth_monitor_ps1`, that `_remove_path_if_exists` on `~/.devai-hub/scripts/run-auth-monitor.vbs` and `claude-auth-monitor.ps1`. They never remove the whole `~/.devai-hub/` tree (that stays gated on `~/.nexus-hub/` existing in `_cleanup_devai_hub_legacy_global_dir`). All three new functions are registered under `LEGACY_CLEANUPS["claude"]` after the existing three, so `run_cleanups` reports one `FileAction` per artifact actually removed.
3. **2.3 - Tests.** Extended `tests/integrations/test_legacy_cleanups.py` with nine cases (schtasks a-f + three leftover-file cases).

## Design decision

Three sibling single-artifact functions (task + vbs + ps1) rather than one combined function, because `CleanupFn` returns a single `Optional[FileAction]` and per-artifact reporting is the `run_cleanups` contract; a combined function could only report one of up to three removals. The plan explicitly sanctioned a sibling cleanup for the leftover files.

## Test strategy note

The schtasks cases monkeypatch `legacy.os.name`, `legacy.shutil.which`, and `legacy.subprocess.run`, so they exercise the Windows branch deterministically on the Linux CI runner. This is safe because `_cleanup_windows_auth_monitor_task` constructs no `Path` object while `os.name` is patched to `"nt"`, avoiding the `NotImplementedError: cannot instantiate 'WindowsPath'` trap.
