## Overview

Phase 4 fixes the Codex Usage Monitor's "No Usage Data" dead-end (BUG 1) and the invisible dashboard tab icon (BUG 4). The endpoint the extension polls (`https://chatgpt.com/backend-api/wham/usage`) is the real one the official Codex CLI uses, but it is undocumented and could not be exercised from this environment, so the fix follows the plan's belt-and-suspenders approach: improve the auto-fetch mapping best-effort AND ship a guaranteed manual-entry fallback with an honest, actionable empty state.

## Sub-tasks completed

- **4.1 Auto-fetch mapping (best-effort).** Public reports of the Codex CLI's `get_rate_limits` parsing indicate the `wham/usage` windows may be named `primary_window`/`secondary_window` or `five_hour_limit`/`weekly_limit`, nested under `rate_limits` or at the top level. `locateWindows` (`src/providers/codex.ts`) now probes all of those aliases in addition to the original `primary`/`secondary`/`five_hour`/`weekly`/`5h`/`7d` set. The exact schema is still unverified (no live capture), documented in the function comment and DF-1.
- **4.2 Manual-entry fallback.** New `codex-usage.enterManual` command (registered in `package.json` + `extension.ts`) prompts for the current 5-hour and weekly percentages (validated 0-100) and writes a `dataSource:"manual"` `UsageData` to the store - which the status bar and dashboard already render. Exposed from the command palette AND as a button in the dashboard empty state (a new `onEnterManual` callback + `enterManual` webview message).
- **4.3 Honest empty state + banner + deep link.** The `usage-unavailable`/`parse-error` banner (`errors.ts`) now states plainly that automated retrieval is unavailable and points to manual entry (it stays honest: still names the undocumented endpoint). The dashboard empty state message is rewritten and gains "Enter usage manually" (primary) + "Open Usage Page" + "Retry auto-fetch" buttons. `onOpenUsagePage` now deep-links to the real usage page (`https://chatgpt.com/codex/settings/usage`) instead of bare `https://chatgpt.com`.
- **4.4 Theme-adaptive dashboard tab icon.** Created `icons/codex-dark.svg` (dark glyph, `fill="#424242"`) and `icons/codex-light.svg` (light glyph, `fill="#e8e8e8"`) from the fill-less `codex.svg`, and set `panel.iconPath = { light: codex-dark.svg, dark: codex-light.svg }` (mirrors the Claude extension). Confirmed both ship in the VSIX (`.vscodeignore` excludes only `icons/*.png` and `fonts/*.svg`).
