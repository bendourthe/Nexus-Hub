## Deviations

- **CI defect repaired (in-charter for 7.3).** `.github/workflows/ci.yml`'s "Validate skill catalog (bundle orphan audit)" step had a duplicate `run:` key (`validate_skills.py --bundles-only` immediately followed by a second `run:` for `validate_no_personal_paths.py`). YAML keeps only the last duplicate key, so in CI the bundle-orphan audit was silently dropped and `no_personal_paths` ran under the wrong step name. Confirmed pre-existing on `develop` (`git show develop:.github/workflows/ci.yml`), so NOT caused by this release - but the 7.3 charter is "CI covers every change / comprehensive testing", and a silently-dropped validator is precisely what a CI audit should catch. Split into two well-formed steps; ci.yml re-parses clean, a scan confirms 0 remaining duplicate-`run` steps, and `validate_workflow_security.py` stays exit 0.

Verification (`git show develop:scripts/installer.sh`) showed Codex/Gemini/Copilot already install via the registry runner on `develop` - the framing was stale BEFORE v3.14.5. Rewriting canonical historical architecture prose (intertwined with the v2.1.0/v2.2.0 migration notes + DF-001) for a fact this release did not touch would violate the no-out-of-scope-cleanup rule and risk a new inaccuracy, so it was triaged and deferred as DF-3 rather than rewritten.
