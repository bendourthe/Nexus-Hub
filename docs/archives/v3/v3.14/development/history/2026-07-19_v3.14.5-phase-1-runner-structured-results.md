## Overview

Phase 1 is the foundation the rest of v3.14.5's installer-UX work stands on: it teaches `scripts/lib/integrations/runner.py` to return a structured, per-platform, per-surface install summary (which surfaces installed, their paths, and whether the platform was detected or skipped) even when the installer runs it with `--quiet`. The installer today suppresses all per-file output under `--quiet` and then prints an unconditional "Installed (global scope)" line, which is also why an undetected platform (Kimi/Qwen/OpenClaw) currently looks installed when its subclass silently skipped it. This phase produces the data the Phase 2 checklist consumes, and makes the detected-vs-skipped state a first-class signal.

## Sub-tasks completed

- **1.1 Design the summary contract.** Chose a summary keyed by platform with a fixed canonical surface order (instruction, skills, commands, agents, rules, hooks, settings), a status per surface (`installed` / `error`), a representative path, the detection outcome, and the notes. Surfaces are derived by classifying `FileAction` paths (no parallel data model, no new `FileAction` field), which captures surfaces regardless of how each integration computes its paths (e.g. Codex delivering commands as `prompts/` + skills).
- **1.2 Implement the summary channel.** Added `_classify_surface`, `_common_path`, `_build_platform_summary`, and an opt-in `--summary-json PATH` to the `install` subcommand. `cmd_install` builds the summary directly from each integration's `WriteResult` (not via `_render_write_result`, which is print-only), so it is populated regardless of `--quiet`. Existing stdout is byte-identical when `--summary-json` is not passed.
- **1.3 Surface detection state.** Added `WriteResult.detected: Optional[bool]` plus a `mark_not_detected()` helper (sets the flag and appends the existing note) and detection propagation through `WriteResult.extend()`. Flipped the five detection-gated subclasses (`kimi`, `qwen`, `openclaw`, `windsurf`, `copilot`) to call `mark_not_detected()` on their skip branch and set `detected = True` on the positive path.

## Test results

- New suite `test_install_summary.py`: 25 passed (~1s).
- Troubleshooting loop (1 iteration): the first full `tests/integrations` run was 326 passed / 2 failed. Both failures were `'_StubIntegration' object has no attribute 'key'` in `test_runner_target_root.py`, from `_build_platform_summary` reading `integ.key`. Root cause: needless coupling - `cmd_install` already holds the authoritative registry key. Fix: `_build_platform_summary(key, integ, result)` takes the key from the caller and uses `getattr(integ, "display_name", key)`. Re-run of the two affected files: 32 passed.
- Full `tests/integrations` re-run: green (definitive record run recorded at commit time).
- End-to-end dry-run: `codex`/`cursor`/`opencode` report real classified surfaces; `kimi`/`qwen` report `detected: false` with no surfaces (the fix for the false "Installed" line).

## Deviations

- `# DEVIATION:` The summary is captured directly from the `WriteResult` in `cmd_install` rather than by modifying `_render_write_result` (as the plan's 1.2 wording suggested). The `--quiet` early-return in `_render_write_result` only suppresses printing, not the data, so building the summary from the `WriteResult` already in hand is lower-risk and keeps existing stdout byte-identical.
- Lint: the project does not use ruff as a gate (no config, not in the Makefile or CI). Ruff flagged one pre-existing unused import (`FileAction` in `qwen.py`), untouched by this phase's edits and left in place per the "no out-of-scope cleanup" rule; logged as a WN.
