## Overview

Phase 3 finishes the installer-log workstream with two cosmetic-but-visible fixes the user called out: (1) the stacked blank lines between the tail sub-sections (nexus-hub CLI, Project auto-seed, Install verification) are collapsed to a single blank, and (2) the single "Usage Monitors" block is split into vendor-grouped sections so the Anthropic utility (Claude Usage Monitor) and the OpenAI utility (Codex Usage Monitor) each build under their own vendor header.

## Sub-tasks completed

- **3.1 Spacing.** Each tail sub-section emitted a manual `Write-Host ""` / `echo ""` immediately BEFORE its `Write-SubSectionBanner` / `write_subsection_banner` (which itself emits a leading blank) and a trailing blank at the function end, so between sections 2-3 blank lines stacked. Removed the redundant leading blank before the banner in `Install-CliLauncher` / `install_cli_launcher`, `Install-ProjectAutoseed` / `install_project_autoseed`, and the Install-verification block, plus the trailing blank at the CLI-launcher function end - relying solely on the banner's built-in single leading blank. Result: exactly one blank line between tail sections.
- **3.2 Vendor-split utilities.** The parent sub-section header "Claude Code Utilities" is renamed to the vendor-neutral "Usage Monitors (VS Code Extensions)". Inside `Install-VSCodeExtensions` / `install_vscode_extensions`, the shared Node/npm + VS Code CLI discovery still runs once, then the two extensions build under their OWN vendor header: `Write-Header "ANTHROPIC"` / `write_header "ANTHROPIC"` for the Claude Usage Monitor, `Write-Header "OPENAI"` / `write_header "OPENAI"` for the Codex Usage Monitor. The redundant top-level "> Usage Monitors" line and the joint "Usage Monitor Installation Complete" line are dropped (each build reports its own success). Both installers in lockstep.
