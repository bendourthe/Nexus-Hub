## Overview

Phase 5 finishes the two remaining items from the original request: the status-bar items across the two independent extensions now order correctly (both used 100/99, so their gears bunched together), and each extension gains a compact-mode toggle that drops the "<Name> Usage: " label.

## Sub-tasks completed

- **5.1 Status-bar priorities.** VS Code renders a higher Right-aligned priority further LEFT. Both extensions previously used 100 (usage) / 99 (gear), so the two usage items and the two gears each tied and clustered by priority. Set non-overlapping, strictly-decreasing values so the four items read [Claude usage][Claude gear][Codex usage][Codex gear]: Claude `statusBarItem`=103 / `gearItem`=102, Codex `statusBarItem`=101 / `gearItem`=100. The load-bearing constraint (documented in both files) is Codex usage (101) < Claude gear (102).
- **5.2 Compact-mode toggle.** Added a `compactStatusBar` boolean (default false) to each extension's `package.json`, a shared private `statusText(...)` in each `statusBarManager.ts` that omits the "<Name> Usage: " segment when the setting is on (applied to BOTH the no-data and data branches), and a `compactStatusBar` clause in each extension's `onDidChangeConfiguration` watcher so toggling refreshes the status bar live. Full form: `<icon> Claude Usage: X% (current) Y% (week)`; compact: `<icon> X% (current) Y% (week)`.
- **5.3 Version bumps.** Claude `0.8.0 -> 0.9.0`, Codex `0.1.0 -> 0.2.0` (covers the Phase 4 + Phase 5 extension changes; extension versions are independent of the project `check_version_sync` surfaces).
