# Comparison: Nexus-Hub vs. The Three Layers of AI Agent Security

- **Date**: 2026-08-17
- **Adoption target: v3.20.0** (v3.17.4 is in flight on `feat/v3.17.4-org-knowledge-layer`; v3.17.5 is taken by `docs/v3/v3.17/plans/v3.17.5-adoption-deepseek-harness.md`; v3.17.6 is the first free slot per the Step 6.5 resolution rule)
- **Sources**:
    1. Article (PDF): "The three layers of AI agent security: from sandboxes to network proxies"
    2. Repo: https://github.com/NVIDIA/NemoClaw (Apache 2.0) - OS-level sandbox stack for heavy agents (OpenShell container sandboxes, Landlock filesystem confinement, seccomp, network namespaces, credential-brokering gateway)
    3. Repo: https://github.com/nanocoai/nanoclaw (MIT) - minimalist agent runtime (single process, few source files, per-session Docker containers, credentials injected at request time, never inside the container)
    4. Repo: https://github.com/brexhq/CrabTrap (MIT) - self-hosted HTTP/HTTPS egress proxy (TLS termination, static URL rules, LLM-as-judge for unmatched requests, human-in-the-loop escalation, SSRF blocking, Postgres audit log)

## NOT Recommended

- **E. Internal egress-proxy build (`extensions/`)**: legitimate under MCP Registry Policy bucket 3 (reverse-engineer locally), but declined now on the AGENTS.md Boundaries scope-fit gate: no active call site. Nexus-Hub distributes skills into third-party harnesses; it does not operate agent network paths. A TLS-MITM proxy also carries a CA-certificate trust surface (Medium risk) that guidance does not. Revisit only if Nexus-AI (the downstream runtime) needs an egress boundary; the skill from item A documents the pattern in the meantime.
- **F. Echo-style hardened runtime service**: MCP Registry Policy hard-no territory (a vendor-operated continuous-rebuild service is X-as-service); the local-first equivalents already exist (`dependency-security-audit`, `cve-reachability-analyzer`, `containerization` multi-stage/scanning guidance).
- **G. Adopting NemoClaw or NanoClaw wholesale**: not applicable; Nexus-Hub is an upstream catalog, not an agent runtime. Their *patterns* are captured in A/B.

## Risks and Conflicts

- No conflicts with existing conventions: all items are additive skill content. Item A requires the standard 3-file registry update and a pushy description with a SKIP clause (per AGENTS.md) fencing it off from `agentic-endpoint-hardening` (host trust seam) and `egress-redaction` (content-level policy) to avoid routing collisions; `evals/trigger-cases.json` with near-miss negatives against both is recommended.
- Maintenance burden: one new skill (271 -> 272) plus three small edits. Low.
- The article's incident anecdotes should not be reproduced as fact in any skill body; cite the structural argument, not the unverified stories.
