## Goal

Add a deterministic token-savings benchmark (compiled map vs simulated manual exploration) on real repos including Nexus-Hub, and a map-health lint (orphan articles, missing backlinks, staleness). The benchmark validates the measured half of the definition of done.

## Sub-tasks completed

### 5.1 - Token-savings benchmark

- `contextmap/benchmark.py` (patterned on `nexus-context-compressor/evals`): `benchmark_repo` / `run_benchmark` / `check_baseline` / `measured_baseline` + a `--check`/`--json`/`--repo`/`--update-baseline` CLI. Manual-cost model: `sum(per-file tokens) * REVISIT_MULTIPLIER + per-entity overheads`; `reduction = 1 - map_cost / manual_cost`. Constants documented in-module (the tool's own heuristic).
- Generator gained `estimate_map_tokens` (renders the map + articles in memory, no `.nexus/` write) so a benchmark run is side-effect-free; each repo indexes into a throwaway dir.
- Corpus: three realistic committed sample repos under `tests/fixtures/benchmark/` (`shop_api`, `blog_ts`, `tasks_py`) - the tiny per-framework fixtures show negative savings (a map is not worth its overhead on a 2-file repo). Committed `benchmark_baseline.json` records per-repo floors.
- Measured: sample corpus 44-55% reduction (aggregate 49%); **Nexus-Hub itself: ~22k-token map vs ~1.9M manual tokens = ~99% reduction (443 files)**. README documents the methodology.

### 5.2 - Map-health lint

- `contextmap/maphealth.py`: `lint_context_map` -> `HealthReport(orphans, missing_backlinks, stale, healthy)`. Staleness compares the map's embedded source-hash to a freshly-recomputed fingerprint; I extracted `current_source_hash` in the generator so the lint and generator agree exactly.
- Exposed as the `map_health` MCP tool + `nexus-hub map --lint` (exit 1 when unhealthy).
- **Decision (5.2)**: ships as extension code, NOT a new catalog skill - the richer semantic checks stay in the `documentation-consistency` skill - so no `data/` registry change. Phases 1-5 remain entirely extension-only.

### 5.3 - Tests

- `test_context_map_measurement.py` (19): benchmark (positive reduction, corpus-meets-baseline, seeded-regression gate, side-effect-free, CLI modes, `measured_baseline` floors) + lint (healthy, seeded orphan/backlink/stale, no-map, CLI exit codes, MCP handler).

## Deviations

- **Benchmark corpus is realistic sample repos, not the tiny extraction fixtures.** The plan says "patterned on the compressor evals ... on real repos incl. Nexus-Hub". The tiny per-framework fixtures are too small to show savings (map overhead > 2-file repo), which would misrepresent the DoD. The committed deterministic corpus is three realistic mini-repos; the real-repo headline is the Nexus-Hub run. Faithful to the intent (measured, deterministic, regression-guarded) while honest about where savings materialize.
