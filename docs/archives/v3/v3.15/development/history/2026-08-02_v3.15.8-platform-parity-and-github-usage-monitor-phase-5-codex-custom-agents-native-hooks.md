### 2.2 Transform catalog agents into Codex TOML

**Branch**: `feat/v3.15.8-platform-parity` | **PR**: N/A | **Merged to**: not merged

**Plan specification**: Add custom-agent delivery at the exact supported location, preserve existing `~/.codex/` and shared `.agents/` ownership boundaries, use manifest ownership for Nexus-Hub content, and never overwrite user-authored agents.

**What happened**: Added `scripts/lib/integrations/_codex_native.py` rather than growing `codex.py`, because a transform and a merge algorithm are a different kind of thing from the copy-and-template logic the integration base already provides. `render_agent_toml` reads each `catalog/agents/*.md`, takes `name` and `description` from the frontmatter, and emits the full Markdown body as a TOML `instructions` value, preferring a multi-line literal string so an agent body containing quotes or backslashes needs no escaping. An agent missing a required frontmatter field is skipped rather than emitted half-formed.

`infer_sandbox_mode` reads the `tools` frontmatter field and emits `sandbox_mode = "read-only"` when every declared tool is non-mutating. This was a decision point put to the maintainer: `tools` has no direct Codex equivalent, and agents like `planner` and `code-explorer` declare only `Read`, `Glob`, and `Grep`. Dropping the field would have handed those agents write authority their own definition never asked for.

Writes go through `write_owned_file`, which consults the install manifest: a path Nexus-Hub owns is refreshed, a path it does not own is left exactly as the user wrote it, and identical content is a no-op so a reinstall produces no diff.

**Key files changed**: `scripts/lib/integrations/_codex_native.py`, `scripts/lib/integrations/codex.py`

**Troubleshooting**: None in the transform itself. The ownership plumbing is what needed care, and it is covered by dedicated tests rather than inspection.

### 2.3 Merge native hooks and enable the feature flag

**Branch**: `feat/v3.15.8-platform-parity` | **PR**: N/A | **Merged to**: not merged

**Plan specification**: Add hook configuration only for confirmed events and schemas, merge structurally, preserve user entries, remove only Nexus-Hub-owned entries during repair or teardown, retain the existing deny layer, keep `.sh` and `.ps1` behavior equivalent, and add malformed-config, duplicate, collision, backup, and rollback tests.

**What happened**: `build_hook_entries` walks `catalog/hooks/settings.json`, normalizes each matcher into Codex's vocabulary, and drops any hook whose matcher has no Codex equivalent instead of approximating it - a guardrail that fires on the wrong event is worse than one that is absent. The maintainer chose full coverage over a curated subset, so every mappable hook ships. Each handler gets a `command` pointing at the copied `.sh` and a `commandWindows` pointing at its `.ps1` sibling, which is where the v3.15.6 PowerShell parity work pays off on a platform whose schema happens to have a slot for it.

`merge_hooks_json` reads any existing `hooks.json`, strips the handlers whose command path sits under the Nexus-Hub-owned base, re-inserts the current set, and leaves every other handler, group, and top-level key untouched. That means a user handler inside a group Nexus-Hub also writes to survives, and a malformed existing file is preserved and backed up rather than overwritten. `prune_hooks_json` is the same operation in reverse for teardown, deleting the file outright when nothing but Nexus-Hub content was in it.

`enable_hooks_feature` sets `[features] hooks = true` in `config.toml` idempotently. This was the second maintainer decision: the installer already merges a permissions block into that file, so leaving the engine disabled would have shipped a surface that exists on disk and does nothing. An explicit user `false` is respected and never flipped.

**Key files changed**: `scripts/lib/integrations/_codex_native.py`, `scripts/lib/integrations/codex.py`

**Troubleshooting**: Two defects, both found by tests rather than by reading. `enable_hooks_feature` prepended a newline before `[features]` when `config.toml` was empty or absent, so a fresh install produced a file that opened with a blank line; the separator is now derived from the existing content instead of assumed. And `teardown` passed while leaving `agents/` and `hooks/` behind as empty directories, which is a clean uninstall only by a generous definition - `_remove_if_empty` now runs after the prune.

## 6. Assumptions Made

- **Filename is the agent key**: Codex keys an agent by its TOML filename, so `catalog/agents/planner.md` becomes `planner.toml` and the manifest tracks that exact path. A user file at the same path is theirs, not a collision to resolve.
- **A read-only tool list means a read-only agent**: `sandbox_mode` is inferred only when every declared tool is non-mutating. Any unrecognized or mutating tool leaves the field unset, which is the permissive default and therefore the safe direction for a wrong inference.
- **Command path prefix is a sound ownership marker for handlers**: Nexus-Hub handlers point at scripts under its own copied directory, so prefix matching identifies them without embedding a marker key the Codex schema does not define.
- **`commandWindows` carries the `.ps1` sibling faithfully**: this relies on the v3.15.6 invariant that every `catalog/hooks/<name>.sh` has a behavior-matched `.ps1`, which `test_hook_sibling_parity.py` enforces independently.

## 9. Summary and Next Steps
