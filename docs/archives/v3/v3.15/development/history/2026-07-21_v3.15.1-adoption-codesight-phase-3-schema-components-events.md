## Goal

Add ORM schema extraction (fields, types, primary/foreign keys, unique constraints, relations), component/props extraction, and background-event detection - each feeding the compiled map and fixture-gated for zero false positives, with correct relation resolution (the plan's hardest item).

## Architecture (consistent with Phase 2)

All post-graph source parsing inside `contextmap/`; no new extraction-time resolvers. Class-based ORMs are located from the `class` nodes already in the graph and parsed from their source span; Prisma / env-example / .prisma files are read directly. Scope (highest-value first, rest deferred as explicit DF-3 coverage): schema = SQLAlchemy + Django + Prisma; components = React; events = declaration-strong signals. Deferred: TypeORM / Drizzle / ActiveRecord / GORM; Vue / Svelte; invocation-only event patterns.

## Sub-tasks completed

### 3.1 - ORM schema extraction

- `contextmap/schema.py`: `extract_schema(conn, root)` returns `ModelInfo(name, framework, source_file, fields, relations)`.
    - SQLAlchemy: `Column`/`mapped_column` fields (PK via `primary_key=True`, FK via `ForeignKey(`, unique via `unique=True`) + `relationship()` relations.
    - Django: `models.XField` fields; ForeignKey / OneToOneField / ManyToManyField -> relations with kinds (many-to-one / one-to-one / many-to-many); target de-quoted from the first arg.
    - Prisma: `.prisma` `model` blocks; `@id` -> PK, `@unique` -> unique; non-scalar / `@relation` fields -> relations (`[]` -> one-to-many else many-to-one).
    - Detection keys on ORM tokens, so a plain class (or Django `Meta`) is never a model. A `_statements` helper joins multi-line field defs until parens balance.
- Model: `FieldInfo` / `RelationInfo` / `ModelInfo`; generator renders a Data Models section + a `context/database.md` article; fingerprint covers `.prisma`.

### 3.2 - Component + event extraction

- `contextmap/components.py`: React components in `.tsx`/`.jsx` (exported PascalCase function/const); props unioned from the destructured param AND the resolved prop type (`}: Props` annotation or `React.FC<Props>` generic resolved to its `interface`/`type`).
- `contextmap/events.py`: declaration-strong signals only (Celery `@shared_task`/`@x.task`, BullMQ `new Queue/Worker('name')`, Kafka, `new EventEmitter`), deferring FP-prone invocation patterns.
- Generator renders Components + Events sections.

### 3.3 - Accuracy harness extension

- `accuracy.py`: `evaluate()` now scores only the sections a fixture declares (Phase 2 fixtures untouched), adding models / relations ("Model.rel->Target") / components / events.
- Fixtures `tests/fixtures/contextmap/{schema_app, frontend_app}` with hand-counted `truth.json`; `test_relation_resolution` asserts 100% relation recall + zero FP across Django, SQLAlchemy, and Prisma.
