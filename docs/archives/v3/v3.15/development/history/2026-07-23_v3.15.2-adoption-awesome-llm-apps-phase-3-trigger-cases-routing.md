## Goal

Define a per-skill `trigger-cases.json` convention and extend the Phase 1 runner to verify, for each skill that has cases, that positive prompts out-rank near-miss negatives and route to the intended skill first; CI warns (never fails) on skills lacking cases.

## Model-routing pre-flight

Phase 3's recorded recommendation is the strong reasoning tier at high effort (Opus 4.8) - schema design + routing logic + case authoring. The session was already on Opus 4.8, matching the recommendation; proceeded without a switch.

## Sub-tasks completed

### 3.1 - Schema + convention

- Location: `catalog/skills/<category>/<name>/evals/trigger-cases.json`. Schema: `{skill, purpose, cases: [{id, prompt, should_trigger, assert, lexical?}]}`; `lexical` defaults true, `lexical: false` cases are reasoning-routed and skipped by the deterministic runner.
- Documented in AGENTS.md: added `evals/` to the per-skill bundled-resources tree and a full schema + authoring-rules block next to the unfilled-placeholder lint.
- Orphan-bundle audit reconciled: `evals/` is deliberately excluded from `validate_skills.py`'s `BUNDLED_SUBDIRS` (runner-consumed, not SKILL.md-referenced), locked with a code comment. Confirmed `--bundles-only --verbose` emits no `evals/` orphan warning.

### 3.2 - Runner extension

- Added `find_trigger_cases` (discovers files, keyed by resolved SKILL.md name, carries a parse error as `_error`), `_top_competitor`, and `assert_routing` to `scripts/run_trigger_evals.py`.
- Assertions per lexical case: (a) a `should_trigger` prompt must rank its own skill first among all skills (reusing the Phase 1 tokenizer + `overlap_ratio` as the prompt-to-skill routing score); (b) the weakest positive must clear the strongest near-miss negative by `--margin` (default 1.15x).
- `lexical: false` cases counted + skipped; skills without a file emit a WARN (aggregate always, per-skill under `--verbose`), never a FAIL. Added `--margin`; JSON gained a `routing` block; gate mode exits non-zero on un-allowlisted collisions OR routing failures, missing-cases never fails.

### 3.3 - First tranche

- Authored `trigger-cases.json` for 6 distinctive-noun skills: react-expert, vue-expert, gdpr-compliance, ccpa-compliance (all Phase 1 near-collision pairs), docx-generation, and kubernetes-expert. Each has 3 positives + 3 near-miss negatives drawn from sibling vocabulary.
- All 36 lexical cases pass, 0 routing failures. Coverage: 6/267 skills have cases; 261 on the WARN path (logged as MT-1).
- One iteration: vue's `neg-react` near-miss initially failed the 1.15x margin because generic "component"/"state" words overlap both frameworks; retuned to react-distinctive vocabulary ("optimize react rendering with hooks"). This was the eval correctly flagging a real lexical overlap, and the fix a cleaner near-miss - not a skill-description change.

### 3.4 - Testing and stabilization

- Added routing tests to `tests/validators/test_run_trigger_evals.py`: rank-first pass, misroute, margin-fail, `lexical: false` skip, malformed-file discovery, no-cases WARN (exit 0), JSON routing block, and a real-catalog tranche guard (0 failures, >= 6 skills with cases). Runner line coverage 95%.
- Two test-fixture corrections during authoring: a hand-written `tokens` set must use stemmer-stable words (prompt tokens are stemmed, so `shared` -> `shar` mismatched). Implementation was correct in both cases.
- CI: no edit needed - the extended eval is the same warning-only `run_trigger_evals.py` step from Phase 1, and the new tests ride the existing `pytest tests/validators` step; the WARN-on-missing path keeps CI exit 0.
