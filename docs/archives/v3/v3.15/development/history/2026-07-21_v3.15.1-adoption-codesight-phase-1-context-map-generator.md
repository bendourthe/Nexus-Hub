## Sub-tasks completed

### 1.1 - Context-map data model and generator core

- New `contextmap/` package: `model.py` (rendering-free `ContextMapModel` / `ModuleSummary` / `FileEntry` / `SymbolEntry` + `compute_source_hash` over sorted `(path, content_hash)` rows + a `GENERATOR_VERSION` in the fingerprint), `tokens.py` (`count_tokens` prefers tiktoken/cl100k_base, falls back to a stdlib word+punctuation heuristic; any tiktoken failure - missing package or offline vocab fetch - falls through cleanly), and `generator.py` (reads files/nodes from the graph, groups by top-level module, counts significant symbols, renders the map + `index.md` + one article per module, writes with LF newlines).
- Guarantees: neutral-path guard (`is_relative_to(<root>/.nexus)`), no wall-clock timestamp (byte-identical tool vs CLI), content-hash no-op (source fingerprint embedded in the map's metadata line, compared on regen), and a per-file token-count header measured over the document EXCLUDING its own metadata line (non-circular).

### 1.2 - MCP tool + `nexus-hub map` one-shot CLI

- `server.py`: added the `generate_context_map` tool definition, dispatch branch, `_handle_generate_context_map` handler, and an instructions entry.
- `contextmap/cli.py`: a standalone CLI (`[root] --force --json`) that resolves the index dir, checks the graph DB exists (exit 2 otherwise, exit 1 for a missing root), runs the generator, and prints a human summary or JSON.
- `scripts/nexus_hub_cli.py`: wired a `map` verb (intercepted before argparse and forwarded verbatim, mirroring `verify` / `setup-media`) via a `cmd_map` late-import of the extension CLI, plus a `map` subparser so `--help` lists it. **No installer edit was needed** - `nexus_hub_cli.py` is already installer-copied and the map logic lives in the extension, so the plan's ask-first installer gate was not tripped (verified against the dispatcher wiring first).

### 1.3 - Testing and stabilization + CI

- `tests/test_context_map.py` (22 tests): section presence, per-file token-header accuracy, neutral-path (no writes outside `.nexus/`; never writes AI-config files), no-op-when-unchanged vs force-regenerates-byte-identical vs graph-change-invalidates, MCP-tool-vs-CLI byte-identity, empty-graph valid map, CLI exit codes (missing graph -> 2, missing root -> 1), and the tiktoken-preferred + tiktoken-failure-fallback + empty-string token paths.
- New `.github/workflows/code-search.yml`: path-filtered to `extensions/nexus-code-search/**` (+ the workflow file), pip-cached on the extension manifest, `concurrency: cancel-in-progress`, installs `[dev]` and runs the suite.

## Deviations

- **CI approach**: the plan's 1.3 said "create or update the CI/CD pipeline ... path-filtered". Because GitHub Actions path filters are workflow-level (not per-job), a dedicated `code-search.yml` was added rather than editing the monolithic `tests` job; the always-on `ci.yml` extension step was retained for cross-cutting safety, with the resulting duplicate-run logged as QG-1. Faithful to the "path-filtered" intent; the de-duplication is deferred to the phase that owns CI optimization (Phase 7).
