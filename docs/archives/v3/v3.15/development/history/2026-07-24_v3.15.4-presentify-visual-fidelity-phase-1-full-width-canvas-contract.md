## Sub-tasks completed

### 1.1 - Concrete, measurable full-width contract in the reference

- `references/interactive-features.md` ("Output aspect (the canvas)"): replaced the prose "Full-width" bullet with an enforceable contract covering the page shell (`--page-max: 100%` or a large cap with named `--gutter` tokens, NOT a centered `max-width` column), full-bleed top-level bands (`100vw`), the per-prose-element `--measure` rule (never the wrapper, headings, hero text, charts, tables, or image bands), and the observable success metric (widest top-level content band at least ~95% of a 1920px viewport after gutters, with no global zoom / `transform: scale()` / `zoom`).
- Added a one-line "Failure to avoid (full-width)" note: a narrow centered column that only looks right at 200% browser zoom is the exact defect the contract prevents.
- Standard / portrait / other bullets left unchanged. Markdown style honored (blank lines around the nested list, ASCII-only, no clause-joining spaced hyphens in the new prose).

### 1.3 - Aspect support in the baseline builder and template

- `scripts/build_presentation.py`: added `--layout {full|standard|portrait}` (default standard) backed by an `ASPECTS` preset map (`full` -> page-max 100% + `clamp(1rem, 2vw, 2rem)` gutter; `standard` -> 1180px + `clamp(24px, 7vw, 140px)`; `portrait` -> 46rem + `clamp(20px, 6vw, 72px)`). `aspect_to_css` injects the `--page-max`/`--gutter` pair into a new `NEXUS_ASPECT` marker block (mirroring the existing `NEXUS_THEME` regex-replace mechanism), and `set_aspect_attr` stamps `data-aspect` on the root `<html>`. `build_html` threads `layout` through; `main` passes `args.layout`.
- `assets/presentation-template.html`: added `data-aspect="standard"` to `<html>` and a default `NEXUS_ASPECT` block; replaced `--slide-max` with `--page-max`, `.slide` horizontal padding with `var(--gutter)`, and `.slide__body` max-width with `var(--page-max)`; added `html[data-aspect="full"] .chart-figure { max-width: 100% }`; and gated the >=1700px projector-padding widening to `html:not([data-aspect="full"])` so full-width stays edge-to-edge on large displays. `--measure` remains scoped to prose (`p`, `.slide__subheading`, `.notes`), never the wrapper.
- Verified: `standard` reproduces today's centered column byte-for-byte; `full` yields ~96.7% band at 1920px; `portrait` yields a 46rem column. Offline self-check (`assert_no_external`) passes for all three.

## Deviations

- **DEVIATION (root-cause fix, RESOLVED) - TITLE_RE swallowed the document head**: the pre-existing `<title>.*?</title>` (DOTALL) regex matched the template header comment's literal "<title>" mention and spanned to the real `</title>`, deleting the comment close, `<html>`, `<head>`, and the `<meta>` tags on every build. Confirmed pre-existing by building from the committed template. Fixed the root cause (`<title>[^<]*</title>`) because Phase 1.3 requires the builder to emit a valid `<html data-aspect="...">` with an intact head. Logged inline as a `# DEVIATION:` and guarded by `test_head_survives_title_substitution`.
- **BG-1 (discovered, NOT fixed - out of scope)**: `theme_to_css` emits `--color-background`/`--color-foreground` while the template consumes `--color-bg`/`--color-fg`, so BUILT output loses theme background/foreground colors (the raw template renders fine standalone). Pre-existing and orthogonal to the full-width canvas contract; fixing it would change "today's look" for `--layout standard`, which Phase 1 must reproduce. Recorded as v3.15.4 BG-1 for a later phase.
