## Goal

Stop the extension being mistaken for a Copilot usage monitor, without claiming it is Actions-only.

**Outcome**: achieved. Every user-visible surface says `GitHub Billing`, the description names both covered surfaces and the single-owner scope, and the breaking id change was avoided rather than managed.

---

## Decisions

### The extension id was kept (T017)

The plan offered two branches and recommended this one. A VS Code extension id is `publisher.name`, so renaming `name` mints a **new** extension rather than updating the installed one. A user who had already installed `nexus-hub.github-usage-monitor` would end up with two extensions, both activating on `onStartupFinished` and both writing a status-bar item, with nothing to indicate which was which. Managing that would require both installers to uninstall the superseded id first, which is teardown logic that must be exactly right on every platform and every re-run, traded for a cosmetic id no user reads.

Renaming only the display surfaces is non-breaking: an existing install updates in place and keeps its SecretStorage token and cached snapshot. Unchanged: the extension id, the `github-usage.*` command ids, the `githubUsage.*` configuration prefix, the storage keys, the view ids, and the `extensions/github-usage-monitor` directory.

The one user-visible cost is recorded in the README: a Command Palette search for "GitHub Usage" no longer matches.

### The prefix moved across the whole visible surface

The plan asked for a deliberate choice between keeping `GitHub Usage:` on command titles and moving to `GitHub Billing:`. The maintainer chose full consistency, which is what the plan's own exit checklist ("renamed consistently across manifest, commands, and panel copy") requires. Command titles, category, status-bar label, panel titles, and hover all moved.

### Installer edits are display strings only

Because the id is unchanged, T018 / T019 reduce to the `DisplayName` and `StatusHint` arguments in each installer's single GitHub invocation. A new test asserts that no `uninstall-extension` step for GitHub was introduced, so a later edit cannot add teardown for an id that was never superseded.

## Troubleshooting trail

1. **BG-11, the one real defect, and the phase gate would not have caught it.** `catalog/hooks/tests/test_installer_smoke.py` pins both renamed strings: `USAGE_MONITORS` asserted the display name `GitHub Usage Monitor`, and `test_github_monitor_status_hint_promises_no_percentage` asserted the literal `GitHub Usage: --` hint. That file is under `catalog/`, not `tests/`, and `ci.yml` collects the two trees in separate steps, so the rename went green locally and would have failed on the ubuntu runner. It was found by grepping `catalog/hooks/tests` for the old strings, on the general suspicion that a rename's blast radius exceeds the plan's file list. While fixing it, the no-percentage assertion was **extended** to also reject `GitHub Billing: --%`, so the renamed prefix cannot reintroduce the false-quota claim that test exists to prevent.
2. **A bulk replace dropped a space.** Replacing `"title": "GitHub Usage: ` with a string missing its trailing space produced `GitHub Billing:Dashboard` across all nine titles. Caught by reading the file back instead of trusting the replace, then fixed with a lookahead-anchored regex and re-validated by parsing the JSON and printing every title.
3. **The new installer test was wrong twice before it was right.** Its first line filter matched any line mentioning the extension directory, which included the explanatory comment the rename had just added, so it found two "invocations". Tightening it to the bash function name then found zero in PowerShell, whose function is hyphenated (`Build-And-Install-One-Extension`). Fixed by normalizing hyphens to underscores before matching, which now covers both shells.
