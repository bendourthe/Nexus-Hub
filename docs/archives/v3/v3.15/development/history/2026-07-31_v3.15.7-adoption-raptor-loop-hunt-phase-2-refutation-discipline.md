## 2. Chronological Steps

### 2.1 Add the refutation-validity taxonomy

**Branch**: `feat/adoption-raptor-loop-hunt` | **PR**: N/A | **Merged to**: N/A

**Plan specification**: Distinguish observed contradictions from assumptions, require build and default-configuration evidence for reachability claims, preserve false-negative symmetry, and route unobservable layers to `needs-live-validation`.

**What happened**: Added `Step 4.1` to `adversarial-verifier`. Valid refutation now requires an observed contradiction, verified unreachability or gating, observable mitigation, or an established trust model. Unseen server behavior, presumed authentication, and assumed framework protection are invalid. Optional-looking behavior is considered reachable when it is enabled by the default build or configuration. A panel rejection requires a majority whose reasons point to observed evidence; missing visibility does not require consensus before assigning `needs-live-validation`.

**Key files changed**: `catalog/skills/orchestration/adversarial-verifier/SKILL.md`

**Troubleshooting**: None. No commit was created for this subtask because the phase uses one commit after the post-phase gate.

**Verification**: Bundle validation and quality validation passed after the edit.

### 2.2 Add the rejection proof burden and review integration

**Branch**: `feat/adoption-raptor-loop-hunt` | **PR**: N/A | **Merged to**: N/A

**Plan specification**: Require the rejection record to inventory actual input sources, account for each relevant route, and provide reachability evidence; add a thin reference from `security-review` without duplicating the taxonomy.

**What happened**: Added `Step 4.2` to `adversarial-verifier`. The rejection record now includes the counter-hypothesis, actual source inventory, route-by-route execution or reasoned not-applicable result, and build or default-configuration evidence when reachability or gating is asserted. A bare route list and a single passing route are explicitly insufficient. Updated the report template with separate rejected-finding evidence and needs-live-validation tables. Added a thin rejection gate to `security-review` that identifies `adversarial-verifier` as the doctrine owner and points live validation to `pentest-reporting`.

**Key files changed**: `catalog/skills/orchestration/adversarial-verifier/SKILL.md`, `catalog/skills/code-review/security-review/SKILL.md`

**Troubleshooting**: A review sweep found two stale sentences that still implied every surviving finding required failing evidence and still referred to the old false-positive log. Both were corrected to use the new disposition and rejection-record language.

**Verification**: Both skill files remain below the 500-line target, their frontmatter is unchanged, and no catalog-registry regeneration was required.
