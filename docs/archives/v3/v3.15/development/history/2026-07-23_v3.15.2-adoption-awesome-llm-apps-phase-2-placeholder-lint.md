## Goal

Extend `validate_skills.py` to catch unfilled angle-bracket template placeholders in a skill's description and body, so scaffolded-but-unfinished skills cannot pass validation silently, with zero false positives on the real 267-skill catalog.

## Sub-tasks completed

### 2.1 - Placeholder detection in the validator

- Added `validate_placeholders(skill_file, content, fm)` to `scripts/validate_skills.py`, plus the module-level `PLACEHOLDER_PATTERN` and helpers `_strip_inline_code` / `_body_after_frontmatter`.
- Placeholder = a multi-word lowercase angle-bracket span, `<[a-z]+(?: [a-z-]+)+>` (two or more single-space-separated lowercase words, hyphens allowed). HARD ERROR in both the `description` frontmatter field and the SKILL.md body prose.
- Exclusions (the tight shape keeps the catalog at zero false positives): single-word CLI notation (`<path>`), uppercase template tokens (`<MAJOR>`), HTML tags (contain `=`/`"`/`/`), comparison operators (space after `<`), and content inside fenced code blocks or inline-code spans. Fence tracking mirrors the CommonMark-aware logic in `scan_text_for_secrets`.
- Wired into BOTH `validate_skill_dir` (full mode) and the `--bundles-only` branch that `make validate` and CI invoke, so it is enforced wherever the strict-YAML gate is.

### 2.2 - Run over the catalog and triage

- First run over all 267 skills: ZERO findings - no genuine unfilled scaffolds and no false positives - so no SKILL.md needed a fix.
- A positive/negative control confirmed the regex is not inert: it matches real placeholders (`<what this skill does>`, `<one sentence describing it>`, `<test command>`) and rejects every look-alike (CLI notation, HTML with/without attributes, `<MAJOR>`, `x < y and y > z`, `<skill-name>`, and backticked examples).

### 2.3 - Testing and stabilization

- Added 14 cases to `tests/validators/test_validate_skills.py`: description hit, body hit, CLI-notation / HTML / uppercase-token / comparison-operator negatives, fenced-code / inline-code / backticked-description exemptions, a nested-fence guard (4-backtick outer fence), `_body_after_frontmatter` with and without frontmatter, and two end-to-end `--bundles-only` CLI tests (scaffold -> exit 1, clean -> exit 0).
- New-code line coverage 100% in-process (the whole-file 66% is the pre-existing subprocess-only `main()`, unchanged by this phase).
- CI: no edit needed - the lint runs inside CI's existing `validate_skills.py --bundles-only` step and the tests run via the existing `pytest tests/validators` step; path filters and caching are unchanged, no redundant job added.
