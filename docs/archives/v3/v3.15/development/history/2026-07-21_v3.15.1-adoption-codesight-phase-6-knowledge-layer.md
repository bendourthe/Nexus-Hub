## Goal

Add a deterministic knowledge-map extractor over a folder of Markdown notes (decisions, meeting notes, retros, specs, research) emitting `.nexus/KNOWLEDGE.md`, independent of code extraction.

## Decision (re-confirmed at implementation)

Ship as extension code, NOT a new catalog skill - consistent with the Phase 5.2 lint decision, the mechanical value is real (a committed cold-start knowledge primer), and narrative synthesis stays with the LLM-native `solution-knowledge-base` skill. **Phases 1-6 remain entirely extension-only (no `data/` registry, installer, or `base-*.md` change).**

## Sub-tasks completed

### 6.1 - Knowledge-map extractor

- `contextmap/knowledge.py`: scans `.md` notes (graph-independent), classifies each by a weighted filename (3) / heading (2) / body (1) signal score into decision / meeting / retro / spec / research (else note), and extracts key decisions (paragraph under a `## Decision` heading or a decision-verb line), open questions (items under an Open Questions heading + standalone `TODO`/`TBD`/`FIXME` lines), and a categorized note index -> `.nexus/KNOWLEDGE.md`. Supports YAML frontmatter (title/tags), a token-count header, the neutral-path guarantee, and a content-hash no-op (fingerprint over the note files).
- Exposed as the `generate_knowledge_map` MCP tool + a `nexus-hub map --knowledge [path]` CLI mode (run before the graph-index check, since it needs no graph).

### 6.2 - Tests

- `tests/fixtures/knowledge/` (committed): a mixed note-folder (ADR / meeting / retro / spec / research / plain note). `test_context_map_knowledge.py` (9): zero-misclassification classification, decision + open-question extraction, categorized index, neutral-path, no-op + change-invalidation, CLI + MCP surfaces.
