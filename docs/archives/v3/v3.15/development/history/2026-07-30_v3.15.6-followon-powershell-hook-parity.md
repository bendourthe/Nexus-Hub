## Task 1 - correct the WN-v36-1 citations

The canonical entry (v3.6 known-gaps) blamed the space-containing checkout path and concluded the failures were unavoidable. Both are wrong, and the wrong diagnosis produced a wrong remedy: "optionally make the affected tests skip cleanly", which would have permanently skipped tests that were always capable of passing.

**What changed.**

- The canonical entry now carries a dated RESOLVED correction naming PATH shadowing as the cause, with the measurement that disproves the space theory (the same space-containing checkout passes with Git Bash ahead of the WSL stub), and its superseded remedy explicitly marked as one that would have entrenched the misdiagnosis.
- Live surfaces that stated the premise as fact were reworded: two `ci.yml` job comments, three `tests/installer` module docstrings, two `skipif` reasons, and `mac-smoke-test.md`.
- A single file-wide correction notice was added at the top of the v3.15 known-gaps.

**What deliberately did NOT change.**

- The historical session-history narratives and the earlier v3.15.x advisory blocks are left as written. A gap ledger records what was believed at the time; rewriting them would falsify the record. The correction notice points readers at the fix instead.
- Two Windows skips in `tests/installer` were RETAINED, on a narrower and still-valid ground: those tests drive the full installer, a path this suite has never verified on Windows. Unskipping them on the strength of a diagnosis, without verifying the installer path, would have been the same mistake in the opposite direction.

## Task 2 - a PowerShell sibling for every hook

Coverage went from 8 of 25 to **25 of 25**.

**The diff-review family collapsed to a template.** The four `*-diff-review.sh` variants differ from each other by 2 lines (CLI binary, log tag, install hint, install URL), and `antigravity-cli-diff-review.ps1` was already a shipping PowerShell implementation of exactly that hook. A one-off generator produced the four `.ps1` files from it, so the family stays in lockstep by construction rather than by discipline. The generator is scratchpad-only; the generated FILES are the committed artifact, matching how the `.sh` family is already maintained as full copies.

**The remaining thirteen were written individually** against each `.sh`. Where PowerShell has a native equivalent it was preferred over emulating shell mechanics:

| Shell mechanic | PowerShell equivalent used |
|---|---|
| `jq` dependency (hook inert without it) | `ConvertFrom-Json` (always works) |
| `[ ! -t 0 ]` | `[Console]::IsInputRedirected` |
| GNU-vs-BSD `stat` probing | `(Get-Item).LastWriteTime` |
| GNU-vs-BSD `date` branching | `DateTimeOffset` parsing |
| `Set-Content -Encoding utf8` (emits a BOM on 5.1) | `[System.IO.File]::WriteAllText` with `UTF8Encoding($false)` |
| `curl` + `jq` | `Invoke-RestMethod` |

Several siblings therefore work where the bash version silently no-ops (a host with no `jq`). That asymmetry is documented in each header and is always in the safe direction: warn or block MORE, never less.

**One subtlety worth remembering**: `compress-output.ps1` emits BASH syntax, including a literal `${PIPESTATUS[0]}`, because the command it rewrites is a Bash command. The `.ps1` is the hook's implementation language, not the target shell.

## Task 3 - a generic parity harness

`catalog/hooks/tests/test_hook_sibling_parity.py`, deliberately generic rather than 17 bespoke files:

- the structural invariant in BOTH directions (no `.sh` without a `.ps1`, no `.ps1` without a `.sh`), so a future one-language hook fails immediately;
- a syntax floor per file (`bash -n` and PowerShell AST);
- exit-code agreement per pair across six quiet payloads;
- targeted cases for the three BLOCKING hooks, where a divergence means an action refused on one platform and allowed on the other;
- a redaction assertion that `secret-scan.ps1` reports the finding CATEGORY and never the matched value.

Being generic, it protects hooks nobody has written yet. Side-effecting hooks are run with `HOME` redirected into a temp directory, so no test can reach real credentials, caches, or the developer's own DEVLOG.

## What the harness found (three pre-existing defects, and one of mine)

| ID | Defect | Cause |
|---|---|---|
| BG-6 | `require-description.sh` and `require-powershell-description.sh` silently failed to BLOCK on a jq-less host | Under `set -euo pipefail` a `grep` matching nothing returns non-zero, and a failing command substitution in an assignment aborts the script, so the hook exited 1 BEFORE reaching its refusal |
| BG-7 | `git-guardrails.sh` exited 1 on any payload carrying no command | Same `set -e` interaction |
| BG-8 | Both languages' description gates blocked on a malformed payload | A parse failure is not evidence of a missing description; `git-guardrails.sh` already documented the right behaviour and the gates lacked it |

BG-6 is the significant one: it is a security control that, on a host without `jq`, allowed exactly what it exists to refuse. It is the same class as the Phase 2 finding that `escalation-trigger.sh` was inert, now on a third code path.

The PowerShell half of BG-8 was **my own** defect: my siblings failed open on a parse ERROR but still fell through to the block for a well-formed payload with no command, so they refused a `Write` tool call. The harness caught it on the run after the bash fix.

A behavioural sweep of all 25 `.sh` hooks confirms the `set -e` class is now empty.

**One asymmetry recorded rather than "fixed"**: `secret-scan.sh` needs `jq` and cannot scan without it, while the `.ps1` always scans. My first version of that test asserted symmetry and failed; the corrected test states the `jq` dependency explicitly and asserts blocking conditionally for bash, unconditionally for PowerShell.
