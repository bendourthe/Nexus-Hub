## Goal

When a source figure is a base image carrying author-added annotations (map regions, colored zones, callout labels, leader lines), recreate those annotations as a registered interactive overlay on the extracted base image, instead of demoting them to a textual list beside a flat base map.

### 3.3 - Extractor: preserve PPTX overlay geometry

New helpers `_shape_bbox`, `_pptx_solid_hex`, `_pptx_line_hex`, `_pptx_annotation` emit each annotation as `{shape_type, bbox (image-relative 0..1), text?, fill?, line?, group?}`.

- **Coordinate-space decision**: the annotation bbox is normalized to the underlying image's PLACED RECTANGLE (image-relative), not the plan's literal "slide coordinates", because that is exactly the coordinate space the part-5 overlay layer consumes directly (no re-projection field needed). Documented in content-model.md.

## Deviations

- **Builder overlay rendering (3.4a) is beyond the plan's named sub-tasks** (reference + extractor + tests) but is required by 3.4's acceptance ("assert the authored HTML contains a registered overlay layer") - the builder is the only deterministic producer of authored HTML, so it consumes the extractor's `annotations` to realize the pattern testably. In-spirit, not scope creep; documented here and in the DEVLOG.
- **Annotation bbox is image-relative, not slide-relative** (see 3.3): a deliberate interpretation serving the part-5 overlay layer directly.
