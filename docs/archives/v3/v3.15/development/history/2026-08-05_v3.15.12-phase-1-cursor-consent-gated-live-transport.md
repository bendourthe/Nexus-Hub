## Troubleshooting trail

1. **A real incoherence in the consent gate, found by writing its test.** On a failed persist, `ensure()` returned `granted` while `isGranted()` re-read storage and returned `false`, so `resolveLiveCapability` would enable live transport while the credential source refused it. Fixed with an explicit non-durable `sessionDecision`; tests now pin coherence in both the grant and refusal directions.
2. **Raw control characters in a regex.** The first `session.ts` write embedded literal control bytes in a character class. Rewritten as an explicit codepoint scan. An earlier attempt, `[ -]`, would have rejected any token containing a hyphen, which is most base64url tokens.
3. **A test harness hiding the implementation.** Two "expired session" cases passed a valid token because the harness used `overrides.row ?? default`, and `undefined ?? x` and `null ?? x` both yield `x`. Switched to an `in` check. The implementation was correct throughout.
4. **A too-naive negative assertion.** "Never claims a public API" matched the fixture's own note, which legitimately contains the forbidden string while forbidding it. Rewritten to assert over structural values with the note excluded.
5. **One intended test failure.** `extension.test.ts` asserted the refresh notice contains `HO-5`. Classified `TEST`: the assertion encoded the old contract. It now asserts the notice names the provenance of what is on screen and does not cite an internal gap id.

## What was not achieved, and why

**HO-5 is narrowed, not closed.** The plan's ingest table says "Closed by Phase 1". The consent gate, adapter, transport, degradation, and labelling all shipped and are tested, but nothing here establishes that the undocumented JSON route exists at the assumed path with the assumed field names and units. That needs one bounded probe with the maintainer's own session on their host. The mitigation is structural rather than optimistic: `verified: false` is committed, the fixture and the code constant are asserted to agree, a non-matching payload is rejected, and any failure demotes to cache with an explicit staleness label. The Phase 1 exit-checklist item "one consent click yields live numbers on a real host" is therefore recorded as unverified rather than ticked.

**Two new gaps.** WN-5: reading the state database needs Node 22.13+ in the extension host, so the Definition of Done is host-dependent and unproven on the maintainer's specific Cursor build; `node:sqlite` also emits an upstream experimental warning. QG-6: the Cursor CI workflow is path-filtered to the extension directory and the wire fixtures live under `tests/fixtures/`, so a fixture-only edit would not run the test asserting fixture-constant agreement. The two-line diff was proposed, not applied.
