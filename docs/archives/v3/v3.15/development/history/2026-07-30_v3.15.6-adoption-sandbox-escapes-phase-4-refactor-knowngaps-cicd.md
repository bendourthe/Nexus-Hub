## DF-2 closed better than the approved remedy

The approved remedy was "convert the ~17 hook test files to the `bash_bin` fixture". Converting each file's module-level `shutil.which("bash")` and `skipif` into fixture plumbing is a wide diff across varied patterns with real risk to existing assertions.

Implemented instead at the root. The cause is PATH; `shutil.which` reads PATH at call time; and pytest imports `conftest.py` BEFORE it imports any test module. So a module-level PATH repair in `conftest.py` lands ahead of every test module's own resolution and fixes every `shutil.which("bash")` and every `subprocess.run(["bash", ...])` call site with **zero edits to the 11 affected files**, and keeps working for files added later.

| Tree | Before (no PATH help) | After |
|---|---|---|
| `catalog/hooks/tests` | 91 failed / 523 passed | **0 failed / 658 passed** |
| `tests/installer` + `tests/validators` | 4 failed | **0 failed / 516 passed** |

The `tests/conftest.py` copy was outside DF-2's original scope but is the same root cause and the same remedy, and it de-risks the new `tests-windows` job, which runs that tree and would otherwise depend on the runner image's PATH ordering. That is the complete 103-failure set carried across several releases as WN-v36-1, now structurally resolved rather than worked around. The `bash_bin` / `powershell_bin` fixtures are retained for tests that want the interpreter explicitly.

## 4.3 - CI/CD (three changes, all evidence-driven)

1. **`.ps1` AST-parse gate** (new, in the `shellcheck` job). Unconditional by design: the parametrized hook tests SKIP when no PowerShell interpreter is present, and a skip emits no signal, so this is the syntax floor that always runs.
2. **The catalog `shellcheck` step is now enforcing.** The `|| true` that terminated it is removed. Safe as of this release: all 36 catalog `.sh` files pass `--severity=warning` with zero warnings, verified batched exactly as the CI step runs it, so the gate starts green.
3. **A push-only `tests-windows` job** runs the hook, installer, and validator suites on a real Windows host, pinned to Windows PowerShell 5.1 via a new `NEXUS_TEST_POWERSHELL` variable.

**Why the Windows leg, specifically.** Not symmetry. The Phase 3 ledger BOM defect (`Add-Content -Encoding utf8` emitting a UTF-8 BOM) is specific to Windows PowerShell 5.1 and does NOT reproduce under the ubuntu leg's pwsh 7. CI as previously configured would have run the `.ps1` parity tests, passed them, and shipped a ledger whose first field was unparseable on every Windows user's machine. The fixture otherwise prefers pwsh, hence the pin: the two legs now cover BOTH editions (ubuntu pwsh 7, windows 5.1) rather than testing pwsh twice. Cost is controlled the same way the existing Windows and macOS legs are: pushes only, never on pull requests.

## BG-5: the new gate found a hook dead since v3.11.0, on its first run

The AST gate failed immediately on `catalog/hooks/session-summary.ps1`, a file this plan never touched.

Root cause, line 139:

```powershell
$lines.Add("- Branch: `$branch`")
```

Inside a DOUBLE-quoted string the backtick is PowerShell's escape character, so this is broken twice over: `` `$branch `` emits the literal text `$branch` rather than the value, and the trailing backtick escapes the closing quote so the string never terminates. The parser runs on through the following lines and reports "string is missing the terminator" 23 lines later, nowhere near the actual fault, which is why it was never spotted by eye.

A parse error prevents a script from running at all, so that hook has been **completely non-functional for Windows users since it shipped in v3.11.0**, silently, because nothing parsed catalog `.ps1` files until this phase added the gate.

Fixed with single quotes plus concatenation so no escape rules apply, and verified to render byte-identically to the `.sh` sibling's `echo "- Branch: \`$BRANCH\`"`:

```powershell
$lines.Add('- Branch: `' + $branch + '`')
```

**On scope**: this is out-of-scope cleanup, included deliberately. The alternative was shipping either a red gate or an allowlisted permanent hole that leaves a known-broken hook broken. One line, root-caused rather than suppressed. It is also the strongest available argument for keeping the gate unconditional.
