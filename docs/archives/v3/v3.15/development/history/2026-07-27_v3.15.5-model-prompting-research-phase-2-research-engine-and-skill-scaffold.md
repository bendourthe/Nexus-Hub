### 2.2 - Research workflow template

- Added `assets/research-workflow.js`, a Dynamic-Workflow TEMPLATE to adapt (explicitly marked "NOT meant to run verbatim"), modeled on the canonical fan-out in `agent-orchestration-primitives`.
- Pipeline per model, with no barrier between stages: stage 1 searches for and FETCHES the vendor's own primary sources (official prompting docs, cookbook, model card or system card, changelog) and extracts discrete testable claims; stage 2 refutes each claim with three independent skeptics, each weighing a different angle (source authority, currency, actionability) and each instructed to default to refuted when uncertain.
- The verification bar: a claim survives only when a primary source supports it AND a majority of skeptics fail to refute it. `confidence` follows the margin (unanimous is high, two-of-three is medium, weaker is low), so a barely-surviving claim is not recorded with the weight of a unanimous one.
- **Scope may be tightened by a verifier but never loosened.** If any skeptic argues a claim is model-specific, it becomes model-specific. That asymmetry matters because loosening is the direction that makes a claim eligible for a shared body.
- The three mandatory rules are inline: graceful degradation (Dynamic Workflow, then isolated subagents, then a single sequential agent, plus an explicit OFFLINE rung that logs a no-op, writes nothing, and re-stamps nothing), scope-first token caution (calibrate on one model, review the plan on first trigger, confirm before full scale), and skill-native (no new outbound call, dependency, or credential; web access is the agent's own tools). Cross-links `[[agent-orchestration-primitives]]`, `[[ai-billing-safeguards]]`, and `[[adversarial-verifier]]`.

### 2.3 - Budget cap and kill switch

- `PER_MODEL_BUDGET` defaults to 60k output tokens per model branch, with a one-branch `RESERVE`.
- The kill switch checks the remaining turn budget BEFORE each new branch starts, so the run stops starting branches at the ceiling rather than dying mid-verification. It logs how many models were skipped and returns them in the result.
- Because writes happen per model as verification completes, a capped run leaves a VALID partial layer plus a logged shortfall, never a half-written index. This is asserted by `test_partial_write_leaves_a_valid_layer`.
- Documented in SKILL.md and the runbook, including how to raise the cap (a larger turn budget, or editing the constant after stating what the new ceiling costs) and the note that with no turn budget set, `budget.total` is null and `remaining()` is `Infinity`, so the per-model cap is the only bound. That is exactly why it exists.

### Deterministic planner and writer (in-spirit realization)

- Added the bundled `scripts/write_model_prompting_profile.py` with two modes.
- `plan` computes the research work-list: a model needs research when it has no profile, carries no claims, or carries only `unverified` claims. Run against the shipped layer it correctly returns all four rostered models, including the Phase 1 seed, which confirms NI-2 behaviorally. `--only` narrows for the scope-first calibration run; `--refresh-all` re-researches the roster.
- `write` validates every incoming claim, merges into the index, re-stamps the roster and its hash, and regenerates the Markdown mirror per written model. It refuses the ENTIRE write on any malformed claim, so a bad research result fails loudly instead of quietly degrading the layer. `--dry-run` validates without touching anything.
- The writer never invents, edits, or re-scopes a claim; it validates what it is handed. It also widens the recorded roster to cover anything just profiled, so the index can never claim a model it has no roster entry for.

## Defects found and fixed during stabilization

1. **The routing eval failed on the skill that shipped it.** The original `description` ended "SKIP picking a model (model-routing)". The scorer stems "picking" to the same token as "pick" in the near-miss prompt "pick the cheapest model that can carry this task", so the weakest positive scored 0.57 against a 0.50 strongest near-miss and missed the required 1.15x margin. The fence written to PREVENT mis-routing was pulling the look-alike closer. This is invisible on re-reading the prose because it lives in the scorer's token space, not in the meaning. Fixed by rewording to "SKIP choosing a model" and adding "conventions" as a real trigger word; the gate now passes across all 269 skills, and the description is 243/250 characters.
2. **The template documented the no-clock rule using the forbidden syntax.** A payload comment read "Date.now() is unavailable here", which tripped the test asserting the template contains no `Date.now(`. Reworded the template rather than weakening the test, since a strict literal check is what catches a real future call.
3. **A test helper bug**: `_payload(models, **over)` received `models` both positionally and via kwargs in the no-models parametrized case. Fixed by building the payload then updating it, and the case now also asserts nothing was written.
