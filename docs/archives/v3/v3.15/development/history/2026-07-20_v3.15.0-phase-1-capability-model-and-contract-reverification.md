## Overview

Phase 1 is the foundation for the platform-parity release: it gives the integration layer a single, real hook-capability signal and web-re-verifies the five parity-target platforms against their current official docs, so Phases 2-6 build on verified facts rather than assumptions. Two user decisions were taken up front (via a pre-flight question): run the release on a `feat/platform-parity-all-gaps` branch, and remove the dead `permissions_file` key rather than wire it up or reserve it.

## Sub-tasks completed

- **1.1 Resolve the dead capability keys.** Made `hooks_supported` the single load-bearing hook-capability signal. It was declared on every integration subclass config but never read; the real signal was implicit (an integration installs hooks iff it declares `hooks_subdir`). Gated the hook copy on `hooks_supported` in the base `SkillsIntegration._mirror_catalog` (a `cfg_key == "hooks_subdir" and not hooks_supported` skip) AND in the bespoke `Antigravity20Integration._mirror_surface` (wrapped `_install_hooks` in a `hooks_supported` check). Byte-identical for the live registry: the only three integrations declaring `hooks_subdir` (claude, nexus-ai, antigravity2) all set `hooks_supported: True`. Removed the dead `permissions_file` key from the 7 subclasses that declared it (claude, codex, copilot, gemini, gemini_cli, nexus_ai, antigravity) - never read by `base.py` / `runner.py` / `lifecycle.py` or any other code; the `configs/permissions/*.json` files are installed by a separate mechanism (`Install-Nexus-Hub-Permissions.ps1` + installer blocks) and are untouched.

## Deviations

- **`ruff format` not applied.** `ruff check` passes, but `ruff format` would rewrite pre-existing code across whole files (its diffs hit untouched functions like `_safe_resolve` / `print_config`), and the sibling test files are not format-clean either. The repo does not enforce `ruff format` (make lint = ShellCheck only; make validate = no ruff), so reformatting would be out-of-scope churn that violates the "every changed line traces to the request" rule. Matching the repo's hand-formatted style is correct.
- **`make validate` compression eval not run** (QG-1): `make` is unavailable in the dev environment (validators run individually) and the context-compressor accuracy eval is unrelated to Phase 1 (the extension is untouched). All other `make validate` steps pass.
