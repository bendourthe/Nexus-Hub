## Sub-tasks completed

### 2.1 - Measurable image-box and cropping rules

- `references/interactive-features.md` "Prominence preservation": added four measurable rules, each with an observable metric the Phase 5 QA gate can grade:
    - **Hero height cap** (~80vh): rendered image height / viewport height at or below ~0.8.
    - **Secondary cap** (inverse of the contact sheet): a low-`page_fraction` block renders no wider than its section's hero.
    - **Object-fit / crop policy**: `object-fit: contain` + matched background for content that `cover` would clip; `cover` only for decorative backdrops; cropping a chart axis / labeled region / face is a defect. Metric: rendered vs native aspect ratio within ~2 percent.
    - **No oversized tile**: every gallery tile within a single bounded range.
- "Spacing and density": added a **dead-space ceiling** (~30% whitespace within an image band). Metric: empty area / band area at or below ~0.3.
- Markdown style honored (ASCII-only, metrics phrased without clause-joining spaced hyphens).

### 2.2 - Confirm and guarantee extractor prominence signals (no code change)

- Confirmed `scripts/extract_content.py` already emits `page_fraction` + native `width`/`height` for every image block that has source geometry:
    - PPTX picture shapes: `_pptx_image_block` computes `page_fraction = shape area / slide area` (`origin: shape-picture`).
    - PDF embedded rasters: `page_fraction = bbox area / page area` (`origin: embedded-raster`); PDF rasterized-regions likewise.
    - Native dimensions come from `_image_dimensions` (Pillow) in `_image_block`.
- Confirmed `references/content-model.md` already documents the v3 `width` / `height` / `page_fraction` fields. Nothing was missing, so NO extractor or schema edit was made (per the plan's "add if missing" - it is not missing).
- Empirical confirmation (built and extracted): PPTX -> `shape-picture page_fraction=0.142 width=400 height=267`; reportlab text+image PDF -> `embedded-raster page_fraction=0.124 width=600 height=400`. A Pillow one-page image-only PDF is correctly classified `scanned-page` (no page geometry -> no `page_fraction`, by design), which is why a text-layer PDF fixture is required to exercise the embedded-raster path.

### 2.3 - Image caps in the baseline template

- `assets/presentation-template.html`: `figure img` now carries `max-height: 80vh` + `object-fit: contain` + `background: var(--ui-bg)` (aspect preserved by `height: auto` + `max-width`, so a tall image clamps proportionally with no crop or distortion).
- Added a token-driven `.gallery` grid (`repeat(auto-fit, minmax(min(220px, 100%), 1fr))`) with `.gallery img` capped at `max-height: 40vh` + `object-fit: contain`, so a set of comparable images renders as a legible, bounded gallery and no secondary balloons.
- Token-driven and offline: rebuild greps clean for external references and the builder self-check returns rc=0 at every layout.
