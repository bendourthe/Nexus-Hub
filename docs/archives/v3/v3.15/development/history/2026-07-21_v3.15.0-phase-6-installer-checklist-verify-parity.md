## Why no production change

- The installer checklist is rendered by both installers from `runner`'s `--summary-json` output; `_classify_surface` is path-shape-based (`skills`/`commands`/`agents`/`rules`/`hooks`/`instruction` by segment/basename/suffix), so any surface a Phase-2-4 integration writes is already grouped correctly.
- `_verify_checks` loads `install_verify` from `platform-read-contracts.json`; the Cursor/OpenCode/Qwen/Kimi rows were added when each integration's code landed (Phases 2-4), so verify already covers them.
- The installer smoke test (`test_installer_smoke.py`) is a parse/run smoke with no checklist-content assertions, so unit-level summary + verify tests are the correct home for this coverage.
