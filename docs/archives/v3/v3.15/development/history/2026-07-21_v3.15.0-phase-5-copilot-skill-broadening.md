## Overview

Phase 5 broadens Copilot's opt-in `.github/skills` seeding and fixes the pre-existing `test_init_subcommand` advisory that had ridden along since Phase 1. It acts within Phase 1's already-settled DF-5 read-contract - no fresh Copilot web re-verification was warranted, because the `.github/skills` path and Copilot's native default-on skill behavior were confirmed 2026-07-20 and Phase 5 changes only Nexus-Hub's selection breadth (a policy choice), not the platform's read paths.

## Sub-tasks completed

- **5.1 Broaden + make configurable.** Widened `CopilotIntegration`'s `.github/skills` seeding from a bare on/off toggle to a SELECTOR. `NEXUS_HUB_COPILOT_SKILLS` now resolves: unset/`0`/`false`/`no`/`off` -> nothing; `1`/`true`/`yes`/`on` -> the default `core-developer` bundle (backward-compatible with the v3.11.0 toggle); a bundle id (any of the 15 in `data/bundles.json`) -> that bundle; `all` -> the full catalog. An unknown bundle id falls back to the default with a logged note. Added `_copilot_skills_enabled` + `_copilot_skill_selection` helpers; split `_curated_skill_names` into `_bundle_skill_names` + `_all_catalog_skill_names`. Kept OFF-by-default + never-overwrite as the commit-visibility policy, and corrected the stale "opt-in because Copilot requires it" framing in the docstring to state it is a Nexus-Hub policy (Copilot reads skills natively default-on).
- **5.2 Advisory fix.** Resolved `test_init_subcommand.py::test_default_wire_project_surfaces_returns_none` by adding `copilot` to the test's `overrides` set (copilot has overridden `wire_project_surfaces` since v3.11.0, returning a `WriteResult`, never `None`).

## Design decisions

- **Backward-compatible selector**: bare-truthy still means the default `core-developer` bundle, so existing `NEXUS_HUB_COPILOT_SKILLS=1` installs are unchanged. The default was NOT broadened (still `core-developer`) to respect `.github/skills/` commit-visibility; broadening is opt-in per-bundle or `all`.
- **Kept OFF-by-default + never-overwrite**: `.github/skills/` is committed to the user's repo, so seeding stays a deliberate opt-in even though Copilot no longer technically requires it (DF-5).
- **Unknown bundle id -> default (not empty)**: an opted-in user always gets a sensible set; the fallback logs a note.
