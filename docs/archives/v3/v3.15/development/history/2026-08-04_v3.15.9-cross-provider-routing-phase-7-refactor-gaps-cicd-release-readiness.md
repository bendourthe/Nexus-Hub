### 2.5 7.5 - Terminal test run, defect, and fix

**What happened**: The full gate battery was executed. The first serial attempt at the five remaining pytest trees needed roughly 80 minutes and showed a failure at the 30% mark without naming it, so the trees were re-run as five parallel detached processes across the available 20 cores. Four came back green immediately; mapping the failure's progress-character index onto the collection order named the failing test before the slow tree finished.

The failure was `tests/integrations/test_copilot_hermes_native.py::test_hermes_skills_are_exactly_one_level_deep`, asserting `commit-sweep has no SKILL.md at depth 1`.

**Diagnosis**: seven `catalog/skills/<category>/<name>/` directories carry no `SKILL.md` (untracked parallel-session scaffolds; five created the same day). The defect was not the scaffolds but a contract disagreement between two gates:

- `flatten_skills` copied **all 277** `<category>/<name>/` directories to every platform.
- `validate_skills.py --bundles-only` **silently skipped** the 7 without a `SKILL.md` (hence its "Scanned 270 skills / PASS").

So a malformed directory passed every gate and surfaced only as an integration-test failure. Because git cannot represent an empty directory, the failure is working-tree-only and a clean CI checkout never reproduces it.

**Fix**: applied at the shared adapter, not per-platform.

- `flatten_skills` and `catalog_skill_names` now require a `SKILL.md`; skips are recorded in the manifest log. Because both live in `_catalog_adapters.py`, Hermes, Cursor, Codex, Antigravity, Qwen, Kimi, and OpenCode are corrected simultaneously.
- `validate_skills.py` gained `find_malformed_skill_dirs`, reporting the same directories in `--bundles-only` (the mode `make validate` and CI run) as a **warning**, not an error, so a work-in-progress scaffold still passes CI. This follows the orphan-bundle audit's precedent.
- The maintainer's seven scaffolds were **preserved**, not deleted.

**Key files**: `scripts/lib/integrations/_catalog_adapters.py`, `scripts/validate_skills.py`, `tests/integrations/test_catalog_adapters.py`, `tests/validators/test_validate_skills.py`

## 5. Deviations

Phase 7 was planned as a documentation, refactor, and CI gate that would touch no source file. It ended up changing two source files and two test files, because the terminal test run surfaced a real contract defect rather than a cosmetic one. The alternative -- deleting the seven empty scaffolds -- would have turned the gates green without fixing the disagreement that let a malformed directory pass validation and ship to every platform. The maintainer chose the root-cause fix explicitly. The earlier Phase 7 statements in `known-gaps.md` and `docs-cleanup-report.md` that "Phase 7 added no source file" were corrected in place rather than rewritten, with dated correction notices, so the record shows what was believed at each point.

A second, smaller deviation: the plan assumed `make` would drive the gates. It is absent on this host, so each target body was executed directly through `python -m`. The gates are identical; only the invocation differs.
