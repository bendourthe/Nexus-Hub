## Goal

Ship a deterministic, model-free, stdlib-only detector that flags any two skill descriptions sharing too much trigger vocabulary across the whole 267-skill catalog, warning-first and then promoted (in Phase 6) to a tuned CI gate with an intentional-neighbor allowlist.

## Sub-tasks completed

### 1.1 - Collision-detection script

- New `scripts/run_trigger_evals.py`: Python stdlib only (no third-party imports, no outbound call, no new dependency). The frontmatter parser is mirrored from `validate_skills.py` so the script is self-contained at its installed location.
- Tokenizer: lowercase, split on non-alphanumerics, drop a stopword set (standard function words plus the "pushy-description" scaffolding vocabulary) and tokens under 3 chars, light suffix stemmer (ing/es/ed/s) with a floor guard so stems never fall below 3 chars.
- Metric: containment `|A n B| / min(|A|, |B|)` (not Jaccard, so a smaller skill's vocabulary being subsumed by a larger one's still fires). Reports pairs at or above `--threshold` (default 0.5).
- CLI: `--path`, `--threshold`, `--allowlist`, `--json`, `--verbose`, and `--gate`/`--strict`. Default is warning-only (always exit 0); gate mode exits non-zero on un-allowlisted collisions.
- Attribution: generic descriptive names throughout; no external repository, product, author, or metric named (per the AGENTS.md reverse-engineering attribution rule).

### 1.2 - Warning-only triage over the catalog

- First run over all 267 skills surfaced 39 near-collisions.
- 38 are by-design category siblings (parallel `<lang>-cleanup` / `<lang>-expert` / `init-<lang>-project` / framework-expert / `*-generation` / mobile-platform / compliance-regulation pairs, plus the `oncall-runbook` / `runbook-writer` and `docs-layout-refactor` / `project-refactor` matched pairs that already carry mutual SKIP clauses). Each is routed apart by a domain noun that is the user's actual trigger.
- 1 genuine collision: `technical-documentation` (broad doc skill, advertised "ADRs", had NO SKIP clause) vs the single-artifact `architecture-decision-record` and `project-constitution` skills. FIXED by sharpening `technical-documentation`'s description to defer to both via an explicit SKIP clause (kept under the 250-char ceiling); `data/skills.json` `description` mirror updated to match. `summary_l0` and `SKILL_INDEX.md` were left untouched (the detector reads only `description`).

### 1.3 - Intentional-neighbor allowlist

- New `scripts/run_trigger_evals.allowlist.json` (modeled on `validate_skills.allowlist.json`): the 39 pairs, each with a one-line justification. The runner downgrades listed pairs to informational lines; `--gate` now reports zero un-allowlisted collisions.

### 1.4 - Registration (warning-first)

- `Makefile`: a `trigger-evals` target (warning-only `--verbose`) plus a warning-only step inside `validate`.
- `.github/workflows/ci.yml`: a warning-only step in the existing `validate` job (after the bundle-orphan audit).

## Deviations

- **CI per-path-filter granularity not implemented (DF-1)**: Phase 1.5 suggested path filters "so it only runs on `catalog/skills/**` and `scripts/run_trigger_evals*` changes". The repo runs all validators in a single `validate` job under the workflow-level `paths-ignore: docs/**`. The eval is a sub-second stdlib step; splitting it into a separately-path-filtered job would ADD checkout + setup minutes, defeating the optimization goal. Kept as a step in the existing optimized job (which already has concurrency cancel-in-progress, pip caching, and cost-gated matrix legs). Logged as DF-1.
- **Local dry-run install not run on the Windows dev host (WN-1)**: the bash installer cannot fully run here (WN-v36-1). The copy block mirrors the `generate_report.py` pattern exactly, is shellcheck-clean, and `scripts_dest` resolves to `~/.nexus-hub/scripts`. CI's `bootstrap` and `install-smoke` jobs exercise the installer end-to-end. Logged as WN-1.
