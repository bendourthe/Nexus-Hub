## Goal

Align `skill-eval-loop`'s behavioral `evals.json` to the interoperable behavioral-eval schema (or ship a converter) so Nexus-Hub's behavioral evals interoperate with external skill-eval tooling, without losing any existing eval-loop capability.

## Model-routing pre-flight

Phase 4's recorded recommendation is the strong reasoning tier at high effort (Opus 4.8) - a format migration with behavior-preservation risk. The session was already on Opus 4.8; proceeded without a switch.

## Sub-tasks completed

### 4.1 - Align-vs-adapter decision

- Compared the internal `evals.json` (bare list of `{id, query, should_trigger, assertions:[{text}], tags?, turns?, trigger_turn?, model?}`) against the interoperable schema `{skill_name, evals:[{id, prompt, expected_output, expectations[]}]}`.
- **Decision: ADAPTER, not native re-alignment.** The internal format is a strict superset (carries `should_trigger`, `turns`/`trigger_turn`, `model`, `tags` the interoperable schema cannot express). Native adoption would drop those capabilities and force a rewrite of the grader/aggregator/optimizer/viewer. A converter keeps every capability and changes nothing in the grading path.
- No committed sample `evals.json` exists (evals are authored per-workspace at runtime), so nothing to migrate.
- Documented in `references/schemas.md` (a new interop section) and the skill's SKILL.md. Generic naming; no external tool named.

### 4.2 - Converter

- Added `scripts/skill_eval_convert.py`: stdlib-only, bidirectional (`internal_to_interop` / `interop_to_internal` + entry mappers + CLI). Maps `query`<->`prompt` and `assertions[].text`<->`expectations[]`, preserves `expected_output`, and stashes every internal-only field (plus assertion keys beyond `text`) under an `x_nexus` extension key so both round-trips are lossless.
- CLI: `--to-interop` / `--to-internal` (mutually exclusive, required), `--skill-name`, `-o`, else stdout.
- Registered by explicit name in `scripts/installer.sh` and `scripts/installer.ps1` (sibling of the other eval-loop scripts). Cross-platform single .py, no .ps1 sibling (matches the sibling scripts).
- Documented the schema, field mapping, and decision in `references/schemas.md`; referenced from SKILL.md via a "Behavioral-eval schema interop" section.

### 4.3 - Testing and stabilization

- `tests/validators/test_skill_eval_convert.py` (18 cases): field mapping, extension-namespace behavior (incl. assertion-extra-key preservation and the no-extension minimal case), both lossless round-trips, an already-`x_nexus`-carrying interop round-trip, expected_output-only-when-present, error handling for wrong-shape inputs, and CLI + in-process `main()` surfaces. Converter line coverage 96%.
- Two test-fixture corrections during authoring (a fixture entry with `should_trigger: False` legitimately gets an `x_nexus` key; the no-extension case needs a truly minimal id/query/assertions entry). Implementation was correct.
- CI: no edit - the converter is a utility tested via the existing `pytest tests/validators` step, not a new gate.

## Behavior preservation

The converter is purely additive. The internal `evals.json` format and the grader/aggregator/optimizer/viewer are untouched, so grading is identical by construction. The lossless `internal -> interop -> internal == internal` round-trip test proves an export/import cycle yields byte-identical internal evals, so any grading over them is unchanged.

## Deviations

- **Converter placed at repo-level `scripts/` rather than the skill's `scripts/`** (the plan's 4.2 wording said "under the skill's scripts/"): the three existing eval-loop dispatcher scripts (skill_eval_viewer / aggregate_benchmark / optimize_skill_description) all live at repo-level `scripts/` and are installer-copied by explicit name; the converter matches that established layout for consistency and co-location. Also no `.ps1` sibling (the plan mentioned one): the `.ps1`-sibling rule applies to `.sh` scripts, and a stdlib Python script is inherently cross-platform (NI-v24-1 precedent). Reasoned, in service of consistency with the sibling scripts.
