## The constraint that shapes the whole phase

Models ship on the vendor's clock. A blocking freshness gate would mean a model released on a Tuesday wedges every Nexus-Hub release until someone runs a research swarm. So every design decision here points the same way: report, never enforce. That is the deliberate opposite of the platform read-contract check sitting immediately above it in the same list, which MUST hard-gate because the contract has to be re-verified for the release being cut. Both live in the same governance block, so the contrast is stated explicitly rather than left for a reader to infer.

## Sub-tasks completed

### 5.1 - Wire the staleness step into `/update release`

Added governance step 5 to `catalog/commands/update.md`, after step 4 (platform-contract-verification). It:

- **self-gates**, doing real work only in a repo that ships `assets/profiles-index.json` plus `model-routing`, and staying a silent no-op in any other project so the release flow remains generic;
- enumerates the live roster via `model-routing`'s `enumerate-models` helper and passes those ids to `check_model_prompting_freshness.py --advisory`;
- on DRIFTED prints a one-line note naming the added or removed models, plus an offer to run `/tune-prompting` before releasing.

The ADVISORY contract is stated as four explicit bullets rather than one adjective, because each is a distinct way the step could be broken:

1. never blocks the release (`--advisory` exits 0 on every path, including DRIFTED, a missing bundle, a corrupt index, and no live roster);
2. never re-stamps a freshness marker to force a pass (only a real research run may write `meta.last_verified`; re-stamping here would fake currency and make the check worthless);
3. is never wired into `make validate` or CI, unlike its structural sibling `verify_model_prompting_profiles.py`, which IS a hard gate on the layer's shape;
4. degrades to a logged no-op offline, where the verdict is UNKNOWN rather than a failure.

The entry closes with a direct warning that a future editor who "fixes" this into a blocking gate reintroduces the exact coupling the design avoids.

## What the new tests found, and one test I had to correct

**A gap they closed**: the check that each gate file documents WHY the checker is absent failed on the Makefile. Only `ci.yml` carried that note, so the Makefile's omission was indistinguishable from an oversight, and a future editor could reasonably "complete the set" by adding the missing gate. A five-line comment now records the reasoning inline. It sits at column 0 inside the recipe, which GNU make strips without terminating the recipe; verified structurally afterwards (38 recipe lines, 31 tab-prefixed commands, still ending in the compression gate and the "All catalogs valid" echo).

**A test I corrected rather than the code**: the first version of the not-wired check was a blunt substring search over the whole file, which flagged `ci.yml` for merely MENTIONING the script inside the Phase 1 comment that explains its absence. The fix was to strip comment-only lines and assert on the runnable surface. Deleting that comment to satisfy a crude test would have removed the very documentation the design depends on, and the correct move was to make the test precise about what it means.
