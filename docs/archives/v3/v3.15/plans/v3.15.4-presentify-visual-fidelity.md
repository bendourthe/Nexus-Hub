**Goal**: Make presentify's output visually faithful and self-correcting - honor full-width as a true edge-to-edge canvas, size and place images intelligently at 100% zoom, recreate source annotations (e.g. the regions on an annotated map) as interactive overlays instead of dropping them to side text, and reliably integrate relevant license-free stock imagery into image-starved sections - all enforced by a new iterative, multi-agent visual self-critique loop that grades each output segment against the source and a measurable quality rubric and rebuilds until the bar is met, degrading gracefully when a headless browser or the workflow runtime is absent.

## Overview

This plan operationalizes four concrete defects observed on a real run (a board-deck PDF turned into an interactive site): (1) selecting "full-width" still produced a centered column with large empty side margins, fixable only by a 200% browser zoom that breaks the rest of the page; (2) images extracted from the source were mis-sized (one secondary image ballooned to hero scale, others were cropped) and poorly placed, with dead space at 100% zoom; (3) an annotated coverage map lost its source-authored region overlays (the colored specialist zones and names), which were demoted to a textual list beside a flat base map; and (4) the "mix" imagery choice produced zero stock photos even though relevant, license-free ones exist.

The root cause is shared: presentify specifies the right behavior in prose (`references/interactive-features.md` defines full-width, prominence preservation, and the imagery tiers; `references/figure-reconstruction.md` defines map handling) but has no measurable, enforced feedback loop that renders the output, compares each segment to its source, grades it against concrete metrics, and rebuilds. Today's Step 9 renders once and looks for gross defects; it never measures an individual image box, never checks a segment against the source figure for lost annotations, and never verifies that a chosen imagery tier actually landed pixels.

Delivery is entirely inside the existing command and skill bundle: no new distribution channel and no `base-*.md` five-platform lockstep (like the model-routing precedent in AGENTS.md, this is command + skill + docs behavior, opt-in via the presentify pipeline, not always-loaded instruction text). Phases 1-4 each define one measurable contract and its gate: Phase 1 makes full-width a concrete, testable canvas across both the LLM-native path and the deterministic baseline builder; Phase 2 adds image sizing/cropping/dead-space discipline with measurable caps; Phase 3 adds an annotated-figure overlay-recreation pattern (keep the extracted base image, recreate its annotations as a registered interactive layer) with a confidence gate; Phase 4 makes stock/mix imagery reliably integrate by folding build-time-network consent into the opening round, detecting image-starved sections, running the keyless Openverse/Wikimedia fetch (Pexels when configured via `nexus-hub setup-media`), and gating on actual integration. Phase 5 is the centerpiece: a genuine iterative, multi-agent visual self-critique loop that fans per-segment graders out (Dynamic Workflows when available, isolated subagents or a single sequential pass otherwise), scores every segment against the source and the Phase 1-4 rubric, adversarially verifies, synthesizes fixes, and re-renders until clean - scope-first and budget-guarded. Phase 6 polishes the command/skill intake and docs and syncs the registry. Phase 7 is the mandatory architecture-refactor, known-gaps, and CI/CD close-out.

Success looks like: a full-width run whose top-level bands span the viewport (measured), with body prose still at a 45-85ch measure and no global zoom; images that never exceed their prominence-appropriate box, never crop meaningful content, and leave no dead space at 100%; the SUPPORT II specialist-coverage map rendered with its region overlays recreated as an interactive layer over the base image; a "mix" run that integrates at least one relevant, license-verified stock image into each image-starved section or records a per-section reason; and a visual-QA loop that proves all of the above by rendering and reading the page back, iterating until the rubric passes - with a clean degradation path and `make validate`, `make lint`, and `make test` green.

## Phase 1: Full-width canvas contract

**Goal**: Make "full-width" mean a true edge-to-edge canvas that fills the viewport natively (no global zoom), in both the LLM-native authoring path and the optional deterministic baseline builder, while body prose keeps its per-element 45-85ch measure.
**Prerequisites**: None.
**Stability Gate**: `references/interactive-features.md` defines a concrete full-width contract with a measurable target (top-level content bands span the viewport minus named gutter tokens; widest band >= ~95% of viewport width at a 1920px viewport); SKILL.md Step 6 forbids a page-wide centered column at full-width and cites the contract; `build_presentation.py` accepts `--layout {full|standard|portrait}` and the template maps it to a canvas CSS variable (replacing the hardcoded caps); a rendered full-width sample measurably fills the viewport; `make validate` and `make lint` green.
**Recommended model**: Strong reasoning tier, high effort (Claude Opus class, e.g. claude-opus-4-8). Rationale: this is the layout contract every later phase and the QA gate depend on; getting the per-element vs page-wide measure distinction concrete and testable is high-leverage.

## Phase 2: Image sizing and placement discipline

## Phase 3: Annotated-figure overlay recreation

**Goal**: When a source figure is a base image carrying author-added annotations (map regions, colored zones, callout labels, leader lines), recreate those annotations as a registered interactive overlay on the extracted base image (or a faithful SVG rebuild), instead of demoting them to a textual list beside a flat base map.

## Phase 4: Reliable stock/mix imagery integration

**Goal**: Make a stock/mix imagery choice reliably put relevant, license-verified images into image-starved sections - by folding build-time-network consent into the opening round, detecting sections that need imagery, running the keyless Openverse/Wikimedia fetch (Pexels when configured), and gating on actual integration - so "mix" never silently produces zero images.
**Prerequisites**: None (independent, but its output is graded by Phase 5).
**Stability Gate**: The consent for the build-time stock fetch is captured in the up-front batched question round when stock/mix is chosen (command + SKILL Step 2); an image-starved-section detection step is defined; `fetch_stock_media.py` is driven per-section with content-derived keywords; a verification gate fails a stock/mix run that integrated zero relevant assets into an image-starved section without a per-section reason; `nexus-hub setup-media` (Pexels key) is verified present or added installer-aware; the offline guarantee holds (assets base64-embedded); `make validate`/`make test` green.
**Recommended model**: Strong reasoning tier, medium-high effort (Claude Opus class). Rationale: pipeline wiring plus one "Ask first" cross-platform installer touch (setup-media), and a license-safety gate that must fail safe.
