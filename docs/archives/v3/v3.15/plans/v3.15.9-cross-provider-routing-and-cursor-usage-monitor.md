## Overview

`/plan` today routes each phase against the host platform's live model list. A plan authored in Claude Code therefore cites only Claude models; a plan authored in Codex cites only OpenAI models. Those concrete ids also go stale within weeks (for example v3.15.8 plans naming `gpt-5.5` while GPT-5.6 Sol/Terra/Luna are current, and v3.15.6 plans naming Opus 4.8 while Opus 5 and Fable 5 are current). This release redesigns plan routing so phases declare a generic **model tier** and **effort level**, and every generated plan carries a separate **tier-to-provider model map** refreshed by websearch at `/plan` time.

The same release adds `extensions/cursor-usage-monitor/`, a Cursor IDE extension modeled on the Claude and Codex usage monitors. It shows personal **Cursor Models** and **Other Models** included-usage percentages, plus personal on-demand spend when enabled, with progress bars in `#4682B4`. Live data may come from local Cursor credential reuse and/or HTML scraping of the Cursor spending/usage dashboard pages. The Nexus-Hub installer installs this extension only into Cursor when Cursor is present, and installs the Claude, Codex, and GitHub monitors only into VS Code (never into Cursor).

Success is observable: a plan written on any host shows identical tier/effort columns plus a fresh four-provider map; the Cursor monitor clean-installs beside Cursor only; VS Code monitors never land in Cursor; focused tests, live smoke, and CI E2E packaging into a throwaway Cursor profile pass before v3.15.9 is published.

## Goals First

**Target problem**: Plan recommendations are host-locked and stale, so implementers on another provider cannot follow them, and Cursor users have no Nexus-Hub status-bar usage monitor for included and on-demand consumption.

**Target persona**: Multi-platform Nexus-Hub users who plan in one assistant and implement in another, and Cursor IDE users who need live personal included-usage and on-demand spend visibility.

**Approach**: Decouple plan routing from host-platform enumeration; publish generic tiers plus a websearch-refreshed provider map. Build one Cursor-only monitor that reuses the proven Claude/Codex interaction model and installer packaging, with explicit VS Code vs Cursor host isolation.

**Definition of done**:

- `/plan` glance tables use **Recommended model tier** and **Recommended effort level** (generic only).
- Every new plan includes a **Current model map** table (`frontier` / `strong` / `standard` / `fast` x Anthropic / OpenAI / Google / Cursor) refreshed via websearch on each `/plan` invocation, with a documented offline fallback.
- Every phase records separate `**Recommended model tier**`, `**Recommended effort level**`, and `**Rationale**` fields without making a single-provider model id authoritative.
- `extensions/cursor-usage-monitor/` builds, tests, packages, and installs into Cursor only when Cursor is detected.
- The monitor displays personal Cursor Models %, Other Models %, and on-demand spend (when enabled), with reset/freshness context and `#4682B4` meter fills.
- Maintainer-supplied Cursor artwork owns the status-bar glyph and warning-panel logo; `icon.png` meets the 128x128 minimum (256x256 target).
- Claude, Codex, and GitHub monitors install only into VS Code and are never installed into Cursor.
- HTML scraping of Cursor usage/spending pages is permitted when needed for live personal meters; fail soft when auth or pages are unavailable.
- Testing bar: Vitest + skill/installer tests + documented live smoke + CI E2E package/install into a throwaway Cursor profile when feasible.
- CHANGELOG and known-gaps updated; usual Nexus-Hub lifecycle (local phase commits, final-only push, protected integration, `/update release`) completed.

## Scope

### In Scope

- Redesign `model-routing`, `/plan`, `/implement`, `/route`, and the `implementation-plan` template for generic tiers + effort columns + websearch-refreshed provider map.
- Tiers: `frontier`, `strong`, `standard`, `fast`. Effort: `low`, `medium`, `high`, `max` (mapped to each platform's native knob at implement/switch time).
- Providers in the map: Anthropic, OpenAI, Google, Cursor.
- Create `extensions/cursor-usage-monitor/` matching Claude/Codex form factor (status bar, hover, dashboard, settings, thresholds, warning panel, recommendations surface as appropriate).
- Personal-only meters: Cursor Models %, Other Models %, personal on-demand spend; team spend limit shown only as shared-pool context (not as a false per-member allocation).
- Seamless auth: prefer local Cursor credential/session reuse equivalent to Codex `auth.json` / Claude session; HTML scraping of `cursor.com/dashboard/spending` and `cursor.com/dashboard/usage` allowed when needed.
- Installer host isolation in both `scripts/installer.sh` and `scripts/installer.ps1`: Cursor monitor -> Cursor CLI only; Claude/Codex/GitHub -> VS Code CLI only.
- Brand color `#4682B4`; supplied Cursor PNG/SVG assets for status glyph and warning panel; compliant package icon.
- Focused CI, live smoke procedure, and E2E Cursor-profile install job when feasible.
- CHANGELOG under `## [Unreleased]` and known-gaps reconciliation.

### Out of Scope

- Rewriting existing v3.15.8 or older plan files to the new columns (only new `/plan` output changes).
- Auto-switching the user's live model mid-session across providers (recommend only; switch stays platform-native).
- Team-admin Cursor dashboards, spend-alert editing, or mutating Cursor billing settings.
- Claiming that a Teams `$N` spend limit is automatically divided into equal per-member hard caps (Cursor docs: Teams uses a shared team-level limit; Dynamic Spend Limits scale the team total with seat count; per-member hard limits are Enterprise).
- Replacing or deep-refactoring Claude / Codex / GitHub monitors beyond shared-pattern reuse and installer host targeting.
- Shipping unverified Cursor endpoints as "documented public API" without recording scrape-vs-API provenance.
- Releasing v3.15.9 during plan authoring; release mutation belongs to the final phase after green integration.

## Research and Architecture Decisions

| Decision | Resolution |
|----------|------------|
| Plan glance columns | Replace `Rec. model / effort` with `Recommended model tier` + `Recommended effort level`. |
| Tier labels | `frontier`, `strong`, `standard`, `fast` (generic; never Anthropic product names as tier ids). |
| Effort labels | `low`, `medium`, `high`, `max` (map to Claude `/effort`, Codex `model_reasoning_effort`, Cursor effort when present). |

| Freshness | Websearch (and official docs fetch) on every `/plan` invocation before writing the map; cache for the planning session only. |
| Offline fallback | If websearch/docs are unavailable, emit the last known map from a skill-bundled snapshot file with an explicit `stale as of <date>` note, or `assess at implementation time` cells - never invent silently. |
| Host enumeration | Remains for `/route` switch mechanics on the current platform; `/plan` recommendations no longer use host enumeration as the authoritative model list. |
| Cursor meters | Personal Cursor Models %, Other Models %, personal on-demand spend; team limit as shared-pool context only. |
| Cursor data path | Credential reuse first; HTML scrape of spending/usage dashboards allowed; typed provider isolates scrape fragility. |
| Brand | `#4682B4` meter fills; supplied Cursor artwork for status glyph and warning panel. |
| Installer | Dual-host resolution: `code`/`Code.exe` for VS Code monitors; `cursor`/`Cursor.exe` for Cursor monitor; never cross-install. |
| Testing | Vitest + skill/installer tests + live smoke + CI E2E into throwaway Cursor profile when feasible. |
