## Overview

The v3.15.7 release-time platform audit confirmed that every existing Nexus-Hub delivery path remained functional, but it found additive upstream capabilities that Nexus-Hub does not yet distribute. Codex now documents TOML custom agents and native hooks; Gemini CLI and Qwen expose native hooks; Kimi Code CLI exposes custom agents and TOML hook configuration; GitHub Copilot exposes custom agents and hooks; and Hermes documents category-nested skill directories in addition to the flattened layout Nexus-Hub already supplies. This plan resolves DF-9 through explicit ownership, merge, repair, teardown, contract, and cross-shell behavior instead of turning documentation findings into unsupported promises.

The release also adds one `extensions/github-usage-monitor/` VS Code extension modeled on the proven Claude and Codex monitor architecture. It displays current-month GitHub Copilot and GitHub Actions consumption in a status-bar hover, dashboard, and threshold-driven alert panel. The monitor uses documented GitHub billing APIs where the authenticated account and billing scope permit them, supports personal, organization, and enterprise contexts, stores an explicitly supplied token only through VS Code SecretStorage, and fails soft to cached or manual quota data when GitHub does not expose an included allowance. It never scrapes the billing website, reads browser cookies, or represents absolute consumption as a percentage without a verified denominator.

Success is observable: the GitHub monitor installs beside the existing monitors, shows Copilot AI-credit or premium-request usage plus Actions minutes and storage, uses `#008080` for usage-bar fills, uses the maintainer-supplied GitHub SVG for the status-bar glyph, and uses the supplied purple gradient GitHub artwork in the alert panel and a compliant 256x256 extension icon derived from the same artwork. Every new platform surface survives install, upgrade, repair, and teardown without overwriting user-owned configuration. Focused local tests, complete repository validation, protected integration checks, and release-only promotion all pass before v3.15.8 is published.

## Goals First

**Target problem**: Nexus-Hub leaves newly documented agent and hook capabilities unused on five supported platforms, and users have no unified, always-visible way to monitor their GitHub Copilot and Actions consumption before a monthly allowance or budget is exhausted.

**Target persona**: Developers who use Nexus-Hub across multiple coding assistants and rely on personal or managed GitHub Copilot plus GitHub Actions, with secondary support for organization and enterprise billing administrators authorized to read aggregated usage.

**Approach**: Extend each platform adapter only after its exact read and merge contract is proven, while building one local VS Code monitor that reuses the existing usage-monitor interaction model and consumes documented GitHub billing endpoints through least-privilege authentication.

**Definition of done**:

- Codex, Gemini CLI, Qwen, Kimi, and Copilot receive every approved v3.15.8 agent or hook surface at verified global and workspace locations.
- Installer, integration registry, repair, manifest, verify, and teardown behavior preserve shared-path and user-owned configuration boundaries.
- Hermes flattened skill delivery is re-proven against its recursive and category-nested discovery contract, with no unnecessary layout migration.
- `extensions/github-usage-monitor/` builds, tests, packages, and installs beside the Claude and Codex monitors.
- The monitor displays Copilot usage and Actions minutes/storage in its dashboard and status-bar hover, with reset context and data-source freshness.
- Usage progress bars use `#008080`; the supplied SVG owns the status-bar glyph; the alert panel uses the supplied gradient GitHub mark; and `icon.png` is a faithful 256x256 derivative.
- Threshold alerts, warning-panel behavior, dismissal, notification de-duplication, compact status-bar mode, cached-data behavior, and manual fallback match the existing monitor quality bar.
- Personal, organization, and enterprise scope failures are explicit; centrally managed Copilot usage is never inferred from a personal endpoint.
- No website scraping, browser-cookie access, plaintext token setting, hosted service, vendor MCP, or unapproved telemetry is introduced.
- All local and remote gates are green before the approved v3.15.8 release workflow promotes `develop` to `main` and publishes the tag and GitHub Release.

## Research and Architecture Decisions

| Decision | Resolution |
|----------|------------|
| Extension boundary | One `github-usage-monitor` extension with separate Copilot and Actions metrics. |
| Primary source | Documented GitHub REST billing endpoints using API version `2026-03-10`, isolated behind a typed provider. |
| Billing scopes | Personal first; optional organization or enterprise scope when configured and authorized. |
| Copilot units | Prefer AI credits on current plans and retain premium-request parsing for legacy or transitional plans. |
| Actions units | Aggregate current-month Actions minutes and storage by unit and SKU; preserve costs and discounts separately. |
| Allowance | Use a verified API value when available, otherwise an explicit user setting; show absolute usage when unknown. |
| Authentication | Probe an existing GitHub session only if proven compatible; otherwise store a fine-grained Plan-read token in SecretStorage. |
| Failure posture | Fall back to cache or manual data, show staleness and typed errors, and never show a false zero. |
| Status bar | One GitHub glyph; hover has independently labeled Copilot, Actions minutes, and Actions storage meters. |
| Alert metric | Configurable highest, Copilot, Actions minutes, or Actions storage metric. |
| Brand | `#008080` meter fills; supplied SVG for status glyph; supplied gradient mark for alert branding. Meter fills were `#651DA8` through Phase 3 and changed to teal on maintainer request during Phase 4; the supplied gradient artwork and package icon keep their original purple stops. |
| Config ownership | Folder copies use manifest ownership; shared JSON/TOML uses structured merge and removes only Nexus-Hub entries. |
| Hermes | Retain flattened delivery unless a live probe disproves it. |
| CI/CD | Reuse focused extension workflows and current repository gates while following the v3.19.0 lifecycle principles. |
| Dynamic workflows | Unavailable; use single-agent implementation and calibrate before any later fan-out. |
