## The CI fail-open this phase found

`ci.yml`'s changed-path classifier matched development contract documents with `^docs/[^/]+/[^/]+/development/[^/]+\.md$` - three segments before `development`. The canonical tree is one level deeper, so after the migration a contract-doc change fell through to "every changed path is ignorable documentation prose" and skipped CI entirely.

This is the second instance of the same shape in this plan, after the `presentify-extractor.yml` path filter in Phase 6. Neither turns CI red; both simply stop it running. Widened to accept both tree shapes, with three canonical-tree cases added to the classifier test and the new contract-doc case proven to fail against the un-widened pattern before the fix was restored.

## The Goal miss, and why it was fixed rather than shipped

The plan Goal says a consuming project should be able to reshape its docs tree "and prove nothing broke, rather than asserting it". The proving mechanism is `link-baseline diff`, and it was not move-aware: identity keyed on `source`, so a moved file's pre-existing broken links counted as newly broken. It read **873** where the true number of links broken by the move was **444**.

Recorded as BG-3, then fixed in the post-phase gaps pass before the single push, because a recorded hole in the Goal is not the same as meeting it. `--rename-map` now projects the before-baseline into post-move coordinates; the shipped tool reports `newly_broken: 0` and exits 0 against this release's own move.
