## 2. Chronological Steps

### 2.1 Fix the teaching scenario before coding

**Plan specification**: Choose one observable bug and one later feature, define the exact code shape and learner-visible results, and make the bug impossible to confuse with poor aim.

**What happened**: Added `docs/releases/v4/v4.4/development/asteroids-scenario.md`. The deterministic `wrap-boundary` fixture puts a size 2 asteroid at the left edge and a bullet at the corresponding visible right-edge silhouette. The buggy collision path measures flat-screen distance and misses; the fixed path uses minimum wrapped distance. The later `asteroid-splitting` feature replaces a registered size 2 hit with two fixed size 1 fragments whose IDs, radii, positions, and velocities are repeatable.

**Observable proof**: The buggy result retains the asteroid and score 0 while showing `WRAP HIT MISSED - visual contact, score unchanged`. The corrected result removes the parent and adds 100 points. With splitting enabled, the same hit produces `fragment-10` and `fragment-11` and announces `WRAP HIT COUNTED +100 - asteroid split`.

### 2.2 Build a self-contained playable game

**Plan specification**: Implement rotation, thrust, drift, firing, screen wrap, asteroid collision, score, lives, keyboard and touch input, delta-time integration, visibility pauses, reduced motion, and a small Phase 5 state API without a runtime library or network dependency.

**What happened**: Rebuilt Training's left work surface as a 640 by 360 logical Asteroids canvas with device-pixel-ratio scaling. Ship and asteroid movement wrap; bullets remain non-wrapping and expire. One update clamps elapsed time to 0.05 seconds and uses analytical acceleration integration so equivalent elapsed time produces equivalent motion across coarse and fine steps. The runtime pauses independently for offscreen, document-hidden, reduced-motion, manual, and canvas-unavailable reasons and resumes only the matching reason.

**Input contract**: Left Arrow or A rotates left, Right Arrow or D rotates right, Up Arrow or W thrusts, and Space fires. Equivalent named touch controls use pointer cancellation and release semantics. Modified shortcuts are ignored, native child buttons retain native keyboard activation, game keys do not scroll or change routes, and any pause or blur clears held movement.

### 2.3 Expose deterministic state and logic seams

**What happened**: Published frozen `window.NexusAsteroids` methods for `snapshot`, `reset`, `step`, `fire`, collision mode, splitting mode, pause, and resume. Its frozen `logic` object exposes `wrap`, `collides`, `fragmentsFor`, and `hitOutcome`. Snapshots are detached JSON-safe copies. Reset validates one of `wrap-boundary`, `ship-impact`, or `play`, restores the entity counter, and is idempotent.

**Lives correction**: The first `ship-impact` step loses one life and respawns at the deterministic safe point `(320, 270)`. Advancing beyond the 1.4-second invulnerability period without input leaves lives at 2, preventing the fixture from draining lives by respawning into the same asteroid.

### 2.4 Make every fallback and announcement truthful

**What happened**: The visible cue is visual-only, while a persistent `aria-live="polite"` and `aria-atomic="true"` status node announces cue changes. A change-only guard prevents one cue from mutating the live region on every animation frame. The game root has persistent keyboard and touch instructions. When canvas is unavailable, playable controls are hidden, the game root leaves the tab order, its accessible description switches to the dynamic fallback, and fallback text updates for buggy, fixed, splitting, ship-impact, and free-play states.

**Reduced motion**: Initial reduced-motion preference blocks autoplay and exposes `Advance one step`. Left, Right, and Thrust taps each advance one deterministic step. A live media-query change adds or removes only the `reduced-motion` pause reason while preserving the user's running intent.

### 2.5 Add behavioral and adversarial verification

**What happened**: Added `tests/guides/test_asteroids_game.py` and extended the existing guide structure tests. Browser coverage proves exact pure-logic results; baseline entity state; invalid inputs; detached snapshots; reset idempotence; buggy, fixed, and split outcomes; cue contrast in both themes; collision-free respawn; delta invariance; production wrap movement; keyboard and touch input; modifier non-interference; composed pause reasons; hidden and offscreen lifecycle; reduced-motion button outcomes and live preference changes; positive canvas pixels; one-mutation live status; and no-canvas fallback transitions. ## 5. Plan Discrepancies

## Plan delta

**Pure-logic placement**: The plan asked to extract the game's pure logic so it was testable without canvas. To retain the one-file offline artifact, pure functions remain in the guide runtime and are exposed through the frozen `logic` API rather than moved into a runtime module. Browser tests call those pure functions directly, and a separate no-canvas context proves the read-only API remains available.

**Input wording correction**: The draft prompt used the broad phrase `arrows or WASD`. The implementation exposes only the actions the game needs and names them exactly: Left/Right/Up arrows or A/D/W. It does not advertise Arrow Down or S.

**Review-expanded lifecycle contract**: The plan named offscreen, hidden, keyboard, touch, and reduced-motion coverage. Review demonstrated that those requirements also needed composed reasons, live preference changes, held-input release, pointer cancellation, and persistent live-region behavior. Those are now durable regressions rather than undocumented implementation details.

**Render destination**: The render helper retains a legacy v4.2 default, so the final command used an explicit v4.4 `--output-dir` and explicit 320/420/900/1440 widths. An accidental wrong-tree run was moved outside the repository to a recoverable temp location before staging; no v4.2 artifact is part of the phase diff.
