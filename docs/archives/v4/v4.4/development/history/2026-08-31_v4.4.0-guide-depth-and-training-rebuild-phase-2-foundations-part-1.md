### 2.2 Correct the model lifecycle and section structure

**Plan specification**: Show training first, platform integration second, then a later live request with context, model processing or reasoning, and output. Remove `Nothing else`, avoid visible chain-of-thought claims, and keep labels legible below 720 px.

**What happened**: Rebuilt the scene as `TRAIN FIRST -> THEN INTEGRATE -> LATER: ONE LIVE REQUEST -> REQUEST -> PROCESS -> OUTPUT`, separated training from live use with a visible time boundary, named context examples without assuming a coding project, and qualified output as a result rather than a transcript of internal reasoning. Added separate desktop and vertically stacked mobile SVGs, raised Phase 2 role and detail labels to a 13 px floor, capped the mobile variants at 22.5 rem, and centered them to avoid the former 720/721 height cliff.

**Verification**: Both responsive variants expose the same ordered `data-stage` contract, and the browser gate proves every marked label remains inside its associated shape at 320, 420, 720, 721, 900, and 1440 px in dark and light themes.

### 2.3 Teach tokens with verified text and honest image semantics

**Plan specification**: Show that text and images are encoded into tokens, use an actual text split, avoid universal ratio claims, and connect token count to context capacity, speed, and cost.

**What happened**: Verified `Freshly baked bread smells wonderful.` with the installed `tiktoken` 0.12.0 `cl100k_base` encoding and embedded the exact pieces `Fresh`, `ly`, ` baked`, ` bread`, ` smells`, ` wonderful`, and `.` as machine-testable attributes. The visible leading-space marker is explained, the copy states that tokenizers differ, and no tokens-per-word or image-token constant is claimed. Independent review caught that the first image illustration started at an abstract grid; it was replaced with a recognizable garden image, an animated encoding arrow, and a separate token grid with source-before-output ordering enforced by tests.

**Key files changed**: `guides/website/nexus-hub-guide.html`, `tests/guides/test_nexus_hub_guide.py`.

### 2.4 Teach prompt engineering without promising outcomes

**Plan specification**: Use one non-coding job, show weak first and strong second, name Goal, Material, Done, and Format, characterize the result difference, and connect the pattern to Nexus-Hub commands.

**What happened**: Built the lesson around a community garden welcome email using supplied Saturday, Oak Street, and RSVP facts. The weak side leaves the facts and finish line unstated; the stronger side supplies the four named ingredients. Independent review caught two gaps: the diagram omitted the stronger outcome and the first outcome wording implied a guarantee. The final copy and both responsive diagrams say the stronger request is more likely to produce a fact-bound, checkable draft while the weak result may be generic and invent missing details.

**Verification**: Structural tests require the same job, all four ingredients, explicit weak and qualified stronger outcomes, Nexus-Hub command linkage, responsive diagram variants, and project-generic vocabulary.

### 2.5 Make the detector measure Foundations rather than Home

**Plan specification**: Run the visual detector against Foundations at 320, 420, 900, and 1440 px in both themes.

**What happened**: Review proved that the detector always opened `path.resolve().as_uri()` without a fragment, so the earlier clean result measured Home. Added `--fragment`, restricted it to a local route identifier, appended it only to the resolved file URI, recorded it in JSON, and required the requested `id`, `page-<route>` id, or matching `data-page` target to exist and become visible after settlement. Added pass, routed-failure, malformed-fragment, and valid-typo regression tests. Updated the owning functional-verification skill with the hash-routed invocation.

**Troubleshooting**:

- **Problem**: A syntactically valid typo could initially leave no route active while the report still passed.
- **Root cause**: The first fragment implementation proved URI construction but not router activation.
- **Resolution**: Added a `fragment-target` gate finding when the named target is absent or hidden, plus a regression test for `foundatons`.
- **Problem**: The first truthful `--fragment foundations` run found overlapping inline `Weak prompt` and `Strong prompt` labels at 900 px in both themes.
- **Root cause**: Both emphasized labels shared one wrapped paragraph, producing overlapping semantic text boxes under the detector's geometry model.
- **Resolution**: Split the weak and strong examples into their own paragraphs; both detector sweeps then returned zero findings.

**Key files changed**: `catalog/skills/testing/functional-verification/scripts/detect_visual_defects.py`, `catalog/skills/testing/functional-verification/SKILL.md`, `tests/verification/test_visual_defect_detector.py`.
