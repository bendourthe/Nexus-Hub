## 2. Chronological Steps

### 2.1 Contrast chatbot handoff with agentic work

**Plan specification**: Show the same request ending as guidance a reader carries elsewhere or as work completed in the active work surface, while acknowledging that modern chatbots may also have tools.

**What happened**: Added `Chatbot or Agentic Platform?` as a title-plus-subtitle scene. Both lanes start from the same event-plan request. The chatbot lane ends with guidance to apply, while the agentic-platform lane reads relevant material, acts in the work surface, checks the result, and leaves a saved change. The copy defines the distinction by where work happens and what remains, not by claiming that a named product can never use tools.

**Verification**: Structural tests require the shared request, both outcomes, the capability qualification, without-then-with order, matching desktop/mobile node inventories, and no vendor-specific disparagement.

### 2.2 Rebuild context as a finite token budget

**Plan specification**: Explain that instructions, conversation, files, tool results, and other supplied material compete for one bounded context window, say what can happen when it fills, retain the noisy-versus-focused comparison, and connect the result to task-matched skill loading.

**What happened**: Replaced the earlier context comparison with a finite-window lesson and visible budget meters. The text qualifies overflow behavior as host-specific: older material can be omitted, compacted, summarized, replaced, or rejected. The focused lane demonstrates deliberate selection, and the closing claim connects that choice to progressive disclosure: load a matching skill for the current task instead of placing the whole catalog in context.

**Verification**: Tests require the competing-content inventory, host-specific full-window behaviors, both budget states, task-matched loading language, exact responsive nodes, and project-generic vocabulary.

### 2.3 Separate the platform harness from the portable Nexus-Hub layer

**Plan specification**: State that agentic platforms already ship a loop and harness, then map each Nexus-Hub claim to a real source artifact without accusing a named vendor of lacking a current capability.

**What happened**: Added a nested layer diagram with the model inside the platform loop and built-in harness, and Nexus-Hub's portable workflow layer outside it. Claims point to repository source artifacts: `catalog/` for the distributable source catalog, `catalog/skills` for matched procedures, `catalog/hooks/settings.json` for registered event hooks where a host exposes the event, `catalog/commands/implement.md` for written gates, and `docs/releases` for durable artifacts. A final practice scene says both a platform-only run and a Nexus-Hub-guided run can complete and save work; Nexus-Hub adds a portable procedure, written gate, and checkable evidence trail.

**Review correction**: The first diagram anchored `one-source-catalog` to generated `data/skills.json`. Independent review rejected that as a source-of-truth claim, so the marker now points to `catalog/`.

### 2.4 Correct Phase 3 geometry and motion contracts

**Plan specification**: Render connectors first, pulses second, and nodes last; enlarge labels and diagrams; attach arrowheads correctly; observer-gate continuous motion; and provide a complete reduced-motion state.

**What happened**: Each of the five Phase 3 diagram pairs declares explicit `connectors`, `pulses`, and `nodes` layers in that order where pulses are present. Desktop and mobile SVG variants switch at the 720/721 px boundary, use 14-15 px Phase 3 label sizes, and expose exact semantic node inventories. The observer adds `live` only while a scene is visible and removes it after scroll-away. Reduced motion reveals all scenes, removes pulse animation, and resolves pop, draw, and grow transitions into their final static states.

**Review correction**: The first reduced-motion probe looked for `.fx-grow` only inside the final practice scene, which contains no growth element. It now requires non-empty pop, draw, and grow inventories across all Phase 3 diagrams, preventing both false failures and vacuous passes.

### 2.5 Prove polygon labels against their actual shapes

**Plan specification**: Keep every label inside its shape at all release and breakpoint widths.

**What happened**: Labeled nodes expose their direct owning shape. Diamond gate labels use an inscribed `data-phase3-text-safe` rectangle because a polygon's rectangular bounding box includes space outside the diamond. The browser contract first proves all four safe-rectangle corners are inside the polygon with `isPointInFill`, then proves the label stays inside that safe rectangle.

**Review correction**: The mobile gate initially lived inside the broader `durable-trail-mobile` node, so the test measured `GATE` against the outer panel. It now has its own `written-gate-mobile` node. The stronger contract also found the desktop label 2.7 px above its first reduced safe rectangle; enlarging the diamond created a genuinely inscribed label-sized area. All six viewport cases passed after the geometry correction.

### 2.6 Preserve cold Training deep links

**Finding**: Independent review found that loading `#training/review?beat=1` cold could be overwritten by the default training state while Phase 3's Foundations work was present.

**Root cause**: The Training engine rendered its default scene before consuming the initial hash, and its hash synchronization could run while Training was inactive.

**Resolution**: Parse and apply the initial Training route before the first render, and prevent Training from rewriting unrelated active page hashes. A dedicated real-browser regression proves the cold URL, scene title, and requested beat survive initial load.

## 6. Assumptions Made

- **Agentic-platform boundary**: The lesson distinguishes where work happens and what is left behind; it does not claim chatbots categorically lack tools.
- **Context overflow**: The guide lists possible host behaviors and explicitly says the exact choice depends on the host; it does not invent one universal truncation rule.
- **Built-in harness baseline**: Every agentic platform is credited with its own loop and harness. Nexus-Hub's claim is limited to portable source artifacts present in this repository.
- **Hook scope**: Event hooks are described as firing where the host exposes and registers the relevant event, not as a universal guarantee across every host.
- **Local browser availability**: Browser-backed tests run fail-closed on this host through `NEXUS_REQUIRE_RENDER=1`; MT-1 records the remaining clean-runner gap.
- **Phase commit identity**: The Git commit containing this history file is the authoritative Phase 3 commit; no hash is fabricated inside the pre-commit transaction.
