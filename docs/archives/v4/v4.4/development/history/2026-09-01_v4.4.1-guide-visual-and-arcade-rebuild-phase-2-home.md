## Sub-tasks

### 2.1 -- Unify and float the Nexus Hub lockup

The hero title changed from the single hyphenated string `Nexus-Hub` to two spans, `<b>Nexus</b> <span>Hub</span>`, mirroring the nav wordmark's exact structure so both use the same roles, weights, and theme tokens (`--ink` at 700, `--teal-soft` at 600).

The mark and wordmark moved into an inner `.hero-lockup-float` wrapper. That separation is the point: the outer `.reveal` element already owns an entry transform, and stacking a continuous float on the same element would make two animations fight for one `transform`. The float is a 7s ease-in-out alternating translate to -9px, matching the historical cadence the plan names.

Rather than add a second observer, the lockup joined the existing `initSceneLiveness` observer by widening its selector from `.fx-scene` to `.fx-scene, .hero-lockup`. That mechanism already provides all three guarantees the plan requires: it toggles `.live` on visibility, it returns early under `REDUCE`, and it no-ops without `IntersectionObserver`. Reusing it means there is one liveness rule on this page, not two that can drift apart.

### 2.2 -- Integrate the five-platform compatibility rail

The six-item rail became exactly five in the accepted order, with OpenCode and its instruction-file note removed along with the `platform-mark-shell` opaque shell and the `platform-item--text` fallback, which had no remaining users.

**Each mark is inlined verbatim from its approved staged file, and that constrains the markup.** To keep the embedded bytes hash-identical to the ledger, no attribute could be added to the `<svg>` element itself. The `platform-mark` class and `aria-hidden="true"` therefore moved to a wrapper `<span>`, which hides the whole decorative subtree from assistive technology while the visible `.platform-name` supplies the accessible name. `focusable="false"` was deliberately NOT added: it would alter the approved bytes, and it only ever mattered for legacy IE, which this page does not target. The test extracts the raw `<svg>...</svg>` substring and compares its SHA-256 against the staged asset before any normalization, so a re-fetch or hand edit fails rather than ships.

Cursor's artwork is portrait (466x532) where the other four are square, so it and Gemini carry small per-mark optical scales rather than being sized by their bounding boxes.

The CC BY 4.0 obligation from Phase 1 is satisfied by a `<details class="platform-credits">` disclosure beside the rail naming Codicons and Microsoft Corporation, plus one nominative-use statement covering all five marks. It needed an explicit override of the global `details` panel styling, which had rendered the legal note as a heavy full-width card.

**The narrow layout needed a different structure, not a different column count.** Five items cannot divide into the existing 3-column mobile grid without leaving an orphan cell, which is precisely the "awkward orphan row" the plan forbids. Below 720 px the rail becomes a centred flex wrap, so a short final row centres instead of hanging left. A browser assertion now measures the final row's centre against the viewport centre at every width.

### 2.3 -- Reformat the workflow sequence as readable two-line pills

The `.loop-step` pills already contained a `<code>` and a `<span>` as separate children, so switching the pill to `flex-direction: column` produced the two rows with no markup churn. Command sizing rose to 15 px with `white-space: nowrap`, descriptions to 14 px, and the pill gained a 14 px radius appropriate to a two-line block. Semantic DOM order and focus order are untouched.

## Visual verification

```text
detect_visual_defects.py --fragment home --theme dark  --viewports 320 420 720 721 900 1440  -> PASS 0 finding(s), 60 allowlisted
detect_visual_defects.py --fragment home --theme light --viewports 320 420 720 721 900 1440  -> PASS 0 finding(s), 60 allowlisted
```

The detector found two things on the first run, and both were investigated rather than suppressed.

**The 60 allowlisted findings are one real construction, verified before being accepted.** Every one is `svg-viewbox-overflow` inside the Gemini mark, whose eleven Gaussian-blurred colour blobs are deliberately far larger than its 65x65 viewBox so the blur can fall off before a star-shaped alpha mask clips it. The temptation was to strip the filters and save 6,784 bytes. Doing that as an experiment produced a **completely blank mark**: the blurred layers ARE the artwork, not decoration behind it. The entry in `visual-allowlist.json` records that evidence, because an allowlist entry written without it is indistinguishable from silencing a true defect.

**The 12 remaining findings were a real fix.** `parent-padding-escape` fired on the two wordmark spans at 900 and 1440 px: `.hero-wordmark` used `line-height: 1`, so the h1's line box (68 px at 1440) was shorter than its inline children's content boxes (90 px). This condition pre-dated Phase 2 and was invisible to the detector only because the h1 previously held a bare text node with no child element to measure. A line box that cannot contain its own text is a latent clipping hazard for any future ancestor with `overflow: hidden`, so the line height was raised to 1.34 rather than allowlisted. Both themes then passed with zero findings.

## Plan delta

**Disposition: Incomplete** -- specifically, the Phase 1 superseded-assertion register was incomplete, and Phase 2 is what proved it.

Phase 2 broke four assertions the register had not anticipated:

1. `test_home_identity_is_centered_nonwrapping_and_observer_gated` pinned the exact hero markup string including `<h1 class="hero-wordmark">Nexus-Hub</h1>`.
2. `test_foundations_phase3_diagrams_animate_with_observer_and_static_fallback` pinned the literal selector text `document.querySelectorAll(".fx-scene")`.
3. `test_home_runtime_contract_across_themes_and_widths` counted platform items and visible names as 6, and measured wordmark line count as the number of client rects over a Range.
4. The same test collected marks via `svg.platform-mark[data-logo-source="official"]`, a selector invalidated by moving the class to the wrapper.

Items 1, 2, and 4 share a root cause worth naming: **an assertion that pins a literal implementation string is invisible to a requirements-level register.** The Phase 1 register was built by reading requirements and asking which behaviours change, which finds `six platforms` but never finds a hard-coded CSS selector inside a browser evaluation block.

Item 3's line-count measurement deserves a separate note because it was a false alarm, not a stale expectation. `Range.getClientRects()` returns one rect per inline fragment, so the two-span title produced five rects on a single visual line and the test reported a wrap that was not happening. The measurement was corrected to count distinct rounded `top` values, which is what "how many lines" actually means; the assertion itself was right to exist.

**Consequence for remaining phases**: Phases 3 through 6 all edit shared markup and shared script, so each must grep the suite for the literal strings it is about to change before trusting the register. The two structural rows and the generalized lesson were added to the Phase 1 contract's register when this surfaced. No phase scope, ordering, or acceptance criterion changes.
