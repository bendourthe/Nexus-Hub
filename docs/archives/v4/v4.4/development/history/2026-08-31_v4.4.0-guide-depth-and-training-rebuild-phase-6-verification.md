### 2.2 Correct visual-detector overlap geometry

**Problem**: Rule 3 used whole-element rectangles, so wrapped inline text and horizontally clipped command text could be reported as painted overlaps even when the visible glyph fragments did not overlap.

**Root cause**: Element bounding boxes include unpainted space and do not model clipping at scrolling, hidden, or clipped ancestors.

**Resolution**: The detector now compares direct text-node `Range.getClientRects()` fragments after clipping them to `overflow: auto|scroll|hidden|clip` ancestors that establish clipping boxes. Non-replaced inline and `display: contents` ancestors do not clip fragments, while zero-sized block clipping ancestors still do. Regression coverage retains the true absolute-position overlap case.

**Key files changed**: `catalog/skills/testing/functional-verification/scripts/detect_visual_defects.py`, `tests/verification/test_visual_defect_detector.py`.

### 2.3 Close four independent-review findings

The independent review found four proof gaps or incomplete contracts. Each was corrected before the final targeted rerun:

1. **Interaction contract coverage**: The browser test now proves explorer ArrowDown, ArrowUp, Home, and End focus movement; Enter and Space selection with the selected-file update; and a page-progress anchor reached by Tab and activated with Enter.
2. **Generated and non-text visual coverage**: The contrast collector now samples rendered nonempty `::before` and `::after` text without double-counting `none`, `normal`, empty, or URL content. It computes pseudo foreground, font, opacity, and composited background. The same review added explicit 24 x 24 px progress-target and at least 3:1 active/inactive dot assertions in both themes.

These corrections increased the authoritative contrast evidence from the earlier base-only run to 11,008 visible samples, including 552 generated pseudo-text samples, representing 265 unique computed styles. No further pseudo-text contrast failure remained.

### 2.4 Record the final audit, size, render, hallmark, and documentation evidence

**Contrast methodology**: A DOM TreeWalker selects each unique rendered parent of a nonblank text node under the header or active page, excludes hidden and `aria-hidden` content, and requires a nonempty text Range rectangle. Generated text is collected separately from nonempty rendered `::before` and `::after` content. Foregrounds use computed CSS color or SVG fill; backgrounds are walked to the painted ancestor and alpha-composited, including normalized `color(srgb ...)` values. WCAG AA thresholds are 4.5:1 for normal text and 3:1 for large text.

**Authoritative count**: 11,008 is the total visible-element sample count across the base matrix and every Training state. The 552 pseudo-text samples are included in that total. The 265 count is the union of unique computed styles across both themes, not an additional element count.

**Runtime and interaction evidence**: The browser matrix found zero outbound requests, console errors, page errors, unsupported computed colors, contrast failures, or horizontal-overflow cases. Keyboard contracts cover platform-mark semantics without Tab pollution, install tabs, progress navigation, page navigation, Asteroids controls, and the cumulative explorer. Reduced-motion runs found zero continuous animation, a static constellation, final Foundations states, immediate terminal output, and one exact Asteroids frame after `Advance one step` while the game remained paused.

**Size reckoning**: The literal Windows working HTML is 490,106 bytes, 9,894 bytes below the strict 500,000-byte gate. The normalized Git content is 487,893 bytes, up from the plan's 397,397-byte starting guide. The offline guarantee remains intact, no asset was externalized, and no budget increase or approval was required.

**Render evidence**: `docs/releases/v4/v4.4/development/guide-rebuild/renders/phase-6/` contains 32 PNG files totaling 12,449,986 bytes, one for every route/theme/width base case.

**Hallmark and docs**: The v4.4.0 hallmark audit passes the platform rail, new Foundations lessons, Asteroids chrome, terminal and evidence panels, cumulative explorer, progress navigation, install tabs, and disabled page ends. `guides/website/README.md` and the top-level `README.md` were refreshed for the shipped guide behavior without changing the documented v4.3.0 detector, rule, hook, and skill contract.

### 2.5 Raise the Claude Code effort default to high

**Plan specification**: T025 required the canonical Claude Code effort default to move from `medium` to `high` without changing Codex or other platform defaults, and required every generated or fallback artifact to remain synchronized.

**Resolution**: Updated `configs/platform-defaults.json` as the source of truth, including the dated rationale for the quality-over-rework choice. Regenerated or reconciled the installer template, Claude integration fallback, skill-catalog metadata, configuration documentation, prompt-effort guidance, and orchestration guidance. Codex remains explicitly at `medium`, so the change is scoped to Claude Code rather than silently broadening the cost policy.

**Verification**: `python scripts/sync_platform_defaults.py --check` reported 13 platforms with all derived artifacts in sync. `python scripts/check_registry_entries.py --check --strict` confirmed the strict registry and derived-value contracts.

**Installer upgrade correction**: Focused review found that both global installer implementations described the defaults as seed-if-absent but replaced existing `effortLevel`, `model`, and `env.CLAUDE_CODE_EFFORT_LEVEL` values on reinstall. That would have silently moved existing users to `high`. Both implementations now add only absent core settings and warn when a malformed user-owned `env` blocks fresh effort-pair seeding. The two precedence-linked effort levers are treated as one upgrade pair: if either already exists, the pair's exact shape is preserved; only a config with neither and an absent or object-shaped `env` receives both `high` keys. This prevents reinstall from introducing a higher-precedence env pin that bypasses the VS Code effort toggle.

**Regression coverage**: `tests/installer/test_core_settings_seeding.py` extracts and executes the real Bash and PowerShell functions. It covers complete existing choices, fresh seeding, missing env creation, partial configs, either effort key appearing alone without adding its missing partner, nested env siblings, malformed and null env, second-run idempotence, isolated core-merge byte identity, and the global-only call order. The current Windows host executes the PowerShell cases and skips the Bash counterparts because Git Bash has no `jq`; ShellCheck and `bash -n` cover the Bash source locally, while the final Linux CI leg remains the cross-host execution proof.
