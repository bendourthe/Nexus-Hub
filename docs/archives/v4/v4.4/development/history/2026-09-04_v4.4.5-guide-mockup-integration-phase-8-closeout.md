## Five rules for the README

Each one is something this plan learned, not a restatement of its diff:

1. **An assertion has to describe the FAILURE, not the intent.** Three defects here shipped past passing tests for exactly this reason: a mark asserted as an element rendered blank, a scene asserted for presence and order said everything twice, and a chain asserted as sorted offsets stacked one chip per line. Four identical offsets sort perfectly well.
2. **A rename is not finished until every sentence about the old name has been READ.** Not searched. The caveat under `9 TOKENS` described "the nine-square grid", a phrase containing none of the renamed words.
3. **One tag size, one token**, with the in-cell exception asserted in both directions so the smaller sizes read as a decision.
4. **An approved asset is copied, never shared, when sharing would rewrite it.** Three attempts at sharing the vendor marks failed, and the third failed against the ledger hash guard, which was right.
5. **A mockup is a source of teaching, not markup to paste.** What came across was structure. What did not: four tablists, two absolutely-positioned SVG maps, a ring in two coordinate systems, and every control.
