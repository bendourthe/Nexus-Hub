## Sub-tasks 5.2 + 5.3 -- The engine

`window.NexusShooter` replaces `window.NexusAsteroids` (699 lines removed, ~640 added): a mulberry32-seeded fixed-step accumulator engine whose snapshots are deep-frozen detached projections rounded to three decimals, sufficient for deep-equality. `setDamageMode` / `setVerticalMovementEnabled` replace the wrap and splitting setters; `reset`/`restart`/`start`/`step`/`pause`/`resume`/`input` complete the seam, plus pure `logic.collides` and `logic.damageOutcome` for unit-style assertions. `destroyed` is exclusively terminal: pause and resume can neither enter nor leave it, `step` is refused, and a generation counter keeps a stale frame or held key from mutating a reset world. Resize and DPR changes repaint through `setTransform`; the world never sees them.

## Sub-task 5.4 -- Art, controls, accessibility

The panel became a portrait 3:4 stage with procedural layered art: a gradient-hulled player ship with cockpit, wings, and animated engine trail; saucer-silhouette enemies with lit cockpits; irregular cratered asteroids drawn as wobbled polygons with radial shading; radial-glow projectiles; particle-burst explosions; and a falling starfield. A real `Click to start` overlay button gates activation; before it, ticks hold at zero and the page keeps its own arrow/Space behavior. The HUD (score, lives, lifecycle, mode tag) lives outside the canvas and renders authoritative state; the `aria-live` region announces lives and lifecycle CHANGES only, and is boot-silent because page load is not a change. Escape pauses, clears held keys, releases ownership, and focuses the visible Resume control; Ctrl/Alt/Meta-modified keys are never intercepted; five labelled touch controls mirror the keys; reduced motion stops autonomous ticks and `Advance one step` performs exactly one; a canvas-unavailable fallback states lives, damage, and feature state in text and removes unusable controls from the Tab order.

## Defects found while stabilizing (all fixed before the commit)

1. **Boot-order crash.** The reduced-motion probe and the intersection observer both call `pause()`, which snapshots, and both wired up BEFORE the first `reset()` created state, so the engine died on load with `Cannot read properties of null`. State creation moved above all wiring, with a comment recording why the position is load-bearing.
2. **The fixed-damage fixture could not demonstrate its own rule.** The seeded enemy never re-fired (`fireIn: Infinity`), so after the one pre-placed shot, fixed mode could never walk `3 -> 2 -> 1 -> 0`. The enemy now re-fires on a deterministic cadence timed to land after each invulnerability window; buggy mode's tick-75 first hit is unchanged. The scenario doc records the cadence.
3. **`reset()` created an unstartable game.** It returned the world to `idle` but never re-armed the start overlay, so any reset after the first start (including every route change through `configureGame`) left an idle game with no visible way to begin. Every reset now re-arms the overlay; `restart()` hides it again on its immediate start. The Phase 6 sweep caught this honestly by timing out on a game that could never reach `paused`.
4. **One test killed its own subject.** The bounds test parked the player at a wall for thirty simulated seconds inside the live `play` fixture, where seeded spawns correctly destroyed it before the firing assertion ran. Moved to the quiet fixture whose threats stay in one column.
