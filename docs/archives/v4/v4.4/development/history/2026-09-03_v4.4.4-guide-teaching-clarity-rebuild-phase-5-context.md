## Four changes, all from the review

1. **Copy first, full width.** The scene stacks now, so the three teaching paragraphs read across
   the whole column before any illustration appears.
2. **Request beside material.** They were stacked; the review asked for the prompt on the left and
   the material on the right, which is also how a reader thinks about attaching something to a
   request.
3. **Examples instead of drawings.** v4.4.3 put a picture under each kind name, which beat the
   dashed noun box it replaced. The review then asked for made-up examples, and it is right: under
   `Image`, `checkout-error.png` is more use than a drawing of a picture frame. The four kinds are
   unchanged, and the test now asserts drawings are ABSENT from that grid so the two cannot both
   creep back in.
4. **The cost, named.** The meters showed the budget filling but left the consequence implied. Under
   each meter there are now four items: more tokens, slower, costs more, and likelier to miss the one
   line that mattered, against fewer tokens, faster, costs less, and likelier to land. The crosses
   and ticks are drawn in CSS as rotated bars, because the guide is ASCII-only.

## The specificity trap, for the third time in this plan family

`.fx-ctx-row` is declared later in the stylesheet than the new `.cx-row`, so a lone class lost on
source order and the request and material stacked instead of sitting side by side. Fixed with a
compound selector, the same fix as `.fx-stack`, `.fx-subtitle`, and `.fx-mat--row` before it. It is
written as a rule in the README rather than as a comment in one place.
