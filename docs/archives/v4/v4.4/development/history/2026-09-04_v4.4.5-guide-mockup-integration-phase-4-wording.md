## The restyle was a defect fix

The review asked for the caption above the tokenized prompt to be renamed to `Prompt` and "styled like 'Vague'", and for `becomes 10 tokens` to be restyled the same way. Both were rendering as plain 16px sentence-case body text, and the reason is that `.fx-copy .fx-tokfig-cap` has matched nothing since the token figure moved into `.fx-diagram`.

So the review was asking for the styling the rule already describes and never applied. Renaming the caption without fixing the selector would have produced a caption called `Prompt` that still looked like a sentence.

**Three dead selectors were fixed, not two.** The caption, its mid variant, and the note below the chips are one defect in one figure. Fixing two thirds of it would have left a 16px body-text note under two 23px tags, for a reason nobody could reconstruct later.

## A caveat that stopped matching its own label

`NINE PIECES` became `9 TOKENS` on instruction. The sentence below it read "The nine-square grid illustrates the idea; it is not a literal token count", which describes a label the reader can no longer see. The caveat is the honest part and it stays, so the sentence now reads "Nine is the number in this picture, chosen to be countable; it is not a literal token count."

This is the second time in this plan that a rename left a nearby sentence describing the old version. It is worth naming as a habit rather than an incident: **a rename is not finished until every sentence that refers to the old name has been read.**

## An interaction the operator should see

It was 13px bold, so it did get bigger. But Phase 2 doubled the two budget tags below it to 23px, so the heading now reads QUIETER than the two labels it introduces.

Both instructions were followed exactly and they pull against each other. Flagged rather than silently resolved, because which one wins is the operator's call.
