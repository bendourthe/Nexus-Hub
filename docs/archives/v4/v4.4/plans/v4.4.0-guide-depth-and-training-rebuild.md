# Plan -- Visual Verification and Guide Depth

**Project**: Nexus-Hub
**Version**: v4.4.0
**Slug**: guide-depth-and-training-rebuild
**Plan Type**: Feature / Enhancement (guide rebuild + verification-discipline dogfood)
**Created**: 2026-08-29
**Goal**: The guide teaches and demonstrates rather than describes: Home opens on a centred animated identity with a selling tagline and six honest platform compatibility treatments using verified marks or explicit text fallbacks, and an Installation section that leads with the install command; Foundations teaches a non-technical reader what a model, a token, a prompt, a chatbot-versus-agent, a context window, and a harness actually are, with correct and legible animated diagrams; and Training drops the download entirely for a playable Asteroids game that starts broken, is fixed and extended through the eight-command loop, with a simulated terminal and an explorable tree of the files each command produces -- every phase gated by the v4.3.0 verification discipline so no visual or behavioural defect ships unexercised.

## Overview

This plan rebuilds the guide against the maintainer's third review. It is deliberately sequenced AFTER v4.3.0, which ships the verification discipline whose absence let the current defects through: building this guide with the process that produced those defects would repeat them. Every phase here runs under that discipline -- cheap deterministic checks including the visual-defect detector at each gate, and the fail-closed Tier 3 deep pass before release -- so this release is also the discipline's first real test case.

Home gets a centred animated mark and wordmark that never wraps, a short tagline that sells an outcome rather than listing contents, six honest platform compatibility treatments under generic names (Claude, ChatGPT, Gemini, Cursor, GitHub Copilot, OpenCode), an Installation section where the install command dominates rather than the verification step, a structured Troubleshooting disclosure, and a reframed pros-and-cons comparison saying the reader keeps the platform they prefer and gains the workflows.

Foundations is restructured into title-plus-subtitle sections, its model diagram corrected to the real sequence (trained first, then integrated into a platform, then a request arrives carrying context, then internal reasoning, then output), and extended with the five concepts it is missing: tokens for text and images, prompt engineering with worked examples, chatbot versus agentic platform, context engineering and the context window, and harness and loop engineering -- ending on an honest account of what Nexus-Hub adds above a platform's own built-in harness, since that is the section that justifies the product.

Training drops the download. A playable Asteroids game ships in the page with a seeded wrap-boundary collision bug, and the eight-command loop fixes it and adds asteroid splitting, with a simulated terminal and an explorable cumulative file tree showing what each command actually wrote.

Delivery constraints are unchanged: one self-contained offline HTML file, zero runtime network calls. The 500 KB budget is the live risk -- the file is at 397 KB and this plan adds a game, six compatibility treatments, five Foundations sections, and a file explorer. Phase 6 owns the budget reckoning and may raise the cap with justification rather than cut content silently.

#### 4.2 -- The game

Under `prefers-reduced-motion` the game does not autoplay and offers a static or step-through path so the walkthrough remains usable. If canvas is unavailable the section degrades to a described static state rather than a blank box. Game state is deterministic enough that the walkthrough can set a known situation.

**Build class**: load-bearing.

**Prompt**:
