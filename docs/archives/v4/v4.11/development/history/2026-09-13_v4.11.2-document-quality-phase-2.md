# Session History - v4.11.2 Phase 2

**Date**: 2026-09-13
**Plan**: [v4.11.2 document and deck quality](../../../../../releases/v4/v4.11/plans/v4.11.2-adoption-document-and-deck-quality.md)
**Phase**: 2 - Type roles and the SVG render ratio
**Branch**: `feat/v4.11.2-document-deck-quality`

## What this phase set out to do

Make type size a rendered property rather than an authored one, and close the
one-sided font gate that enforced floors but no ceilings.

## Steps

1. Read the existing font pass before changing it. It assigns a coarse role (heading / body / label / interactive) and enforces `FONT_FLOORS` only.
2. Added a named `typeRole` ALONGSIDE that coarse role rather than repurposing it. Floors and ceilings ask different questions, and merging them would have silently changed what the floor gate measures.
3. Measured the repository's own handbooks to get real per-role maxima BEFORE writing any ceiling.
4. Added ceilings and a role-coverage check.
5. Wrote six negative-controlled tests. Two of them failed, which drove the rest of the phase.
6. Wrote `responsive-typography.md` section 12.

## Troubleshooting

### The role-coverage gate could never fire

`test_an_unassignable_text_node_fails_with_its_text_and_selector` failed with
`assert []`. The cause was structural rather than a bug in the check: the
resolution ran inside the floor-gate loop, which iterates a fixed selector list,
and every element in that list maps to a role. `typeRole` could never be null.
A bare `<span>` - the exact case the test used - is not in the list and was
never visited.

So the check was vacuous. It would have reported clean forever and looked like
coverage.

Fixed by giving coverage its own walk over every element owning visible text,
kept deliberately separate from the floor pass so the floor gate's scope does
not change. Hoisting the resolver into a shared function meant both passes use
one definition rather than two that can drift.

### The new walk was too broad

The wider walk immediately reported 30 unresolved nodes per handbook. Inspecting
them rather than adjusting a threshold: all were `<strong>` and `<span>` inside
prose.

An inline element inherits the role of its block. A `<strong>` in a paragraph is
body text. Reporting 30 legitimate nodes per document would bury the one real
orphan, which is the same failure mode as the source project's 220-finding
audit.

A node now fails only when nothing in its ancestor chain resolves a role. Real
output returned to 0 while the orphan test still failed correctly - and checking
both directions is what distinguishes a fix from a suppression.

## What went right

Measuring real output before setting ceilings. Had I picked plausible-looking
numbers first, either they would have been too tight and failed the
repository's own 68.3px title, or too loose and never fired. The measurement
took one probe and removed the guesswork entirely.

Adding `typeRole` beside the existing role instead of replacing it. The floor
gate's 41 tests kept passing throughout, which is the evidence that the addition
was genuinely additive.
