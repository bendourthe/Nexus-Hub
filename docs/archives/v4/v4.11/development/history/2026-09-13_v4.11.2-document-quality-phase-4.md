# Session History - v4.11.2 Phase 4

**Date**: 2026-09-13
**Plan**: [v4.11.2 document and deck quality](../../../../../releases/v4/v4.11/plans/v4.11.2-adoption-document-and-deck-quality.md)
**Phase**: 4 - Deck integrity gates
**Branch**: `feat/v4.11.2-document-deck-quality`

## What this phase set out to do

Gate the deck defects that are invisible in markup and only appear while a slide
is current. The plan names this the highest-risk phase, because timing- and
state-dependent verification is the class that has most often produced false
results.

## Steps

1. Read the existing slide walk before adding to it. It already advances with `ArrowRight` and measures initial/mid/final per slide, which is exactly the discipline this phase needs, so the work was adding checks inside that loop rather than building a second walk.
2. Wrote `DECK_INTEGRITY` with three rules and wired it into the `final` state, after the animation window closes, so opacity is what the reader will actually see.
3. Built a four-slide fixture, one defect each.
4. Wrote the test asserting the plan's stated failure mode. It failed.
5. Measured what actually happens, rewrote the test around it, and corrected the reference accordingly.

## Troubleshooting

### The plan predicted the wrong failure, and the test caught it

The plan says a probe checking all slides at the end "reports everything
hidden". I encoded that and it failed with `assert 1 > 1`: only the genuinely
invisible slide was reported.

The reason is that the probe measures EFFECTIVE OPACITY, which `display:none`
does not change. A parent being undisplayed does not alter a child's computed
opacity, so that check is naturally immune to the timing trap.

Rather than delete the test or weaken it, I measured what the naive walk really
does differently. It misses `slide-overflow` entirely, because
`getBoundingClientRect` returns zeros inside a `display:none` slide. The
consequence is under-reporting, not over-reporting.

That is worse, and worth saying plainly: a false alarm gets investigated, a
silent miss ships. The test now asserts the measured difference, and its
docstring records that this is not the failure the plan predicted.

I kept the corollary as an assertion too: the opacity and reference checks agree
either way. If someone later makes one of them rect-dependent, that assertion
breaks rather than the check silently inheriting the trap.

## What went right

Writing the test from the plan's claim rather than from my implementation. Had I
written it to match what my code did, it would have passed and the plan's
incorrect premise would have propagated into the reference documentation as a
rule nobody had checked.

Reading the existing slide walk first. The per-slide discipline this phase is
about was already implemented for other checks; building a second walk would
have duplicated it and invited the two to drift.

## Next

Phase 5: attestation gates for the unmeasurable. It is the first phase where the
gate asserts that a decision was RECORDED rather than that it was correct, and
the risk the plan names is that it drifts into scoring taste.
