## What this phase set out to do

Make the loop mandatory repository-wide and wire the gates into the commands
that produce documents. Until this phase every gate built by this plan was
opt-in, which is the same state `check_handbooks.py` shipped in during v4.11.0 -
written, correct, and invoked by nothing.

## Steps

1. Wrote the global rule beside `responsive-layout.md`.
2. Added the `rendered-artifact-verified` gate with seven criteria.
3. Added the claim-to-evidence row and the reorder/fence rules.
4. Wired the gate into `presentify`, the skill pipeline, `/update docs`, `/update release`.
5. Wrote a test that asserts the wiring, and negative-controlled it.

## Troubleshooting

### An anchor matched twice, and the assertion caught it

The wiring script asserted `"## Gate: docs-complete"` appeared exactly once. It
appeared twice: `## Gate:` is a substring of `#### Gate:`, and the file carries
a section heading AND a fenced definition of each gate.

The assertion failed rather than inserting the new gate in the wrong place. That
is precisely the rule the new global file states - assert the anchor is present
and unique before replacing, because a replacement matching nothing does nothing
and reports success - and it demonstrated itself on the commit that introduced
it. I switched to the `#### Gate:` heading form and matched the surrounding
fenced format.

### The `/update docs` anchor did not exist

My first attempt anchored on a bullet I had read in the loaded `/update` skill
text rather than in `catalog/commands/update.md` itself. The two are not the
same file. The assertion failed, I grepped the real file, and anchored on a
bullet that is actually there.

Both failures were cheap because they were assertions rather than silent
replacements. A regex `sub` would have written nothing and reported success in
the first case and inserted into the wrong document in the second.

## What went right

Writing the wiring test as a surface-to-reference map. It makes the wiring a
checked property rather than a claim in an evidence file, which matters because
the specific failure this phase guards against is a gate that exists and is
never called.
