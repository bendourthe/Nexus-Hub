## Troubleshooting

### The full profile failed, and both failures were mine

`FAIL: 45 passed, 1 failed`, with two tests red inside `repo-tests`.

`check_attestation.py` was git mode `100644` while carrying a shebang, which
fails `ruff EXE001` on Linux. I had marked `geometric_audit.py` executable when
I created it and simply never did the same for the second script.

The other is the one worth recording. `test_update_md_stays_a_thin_dispatcher`
failed because Phase 6 had inlined a numbered procedure with sub-bullets into
`catalog/commands/update.md`, which is a dispatcher, not a runbook. The test's
own message named the fix: the procedure belongs in the skill.

A repository guard caught this plan violating the repository's own architecture,
during the phase whose job is to check exactly that. The substance already lived
in the skill from Phase 6, so the dispatcher now carries one line naming the gate
and its owner, and the guarded region is back to its prior count.

### Re-running the right scope

`tests/` rather than the whole 76-minute profile, and said so rather than
implying a full re-run. `5396 passed, 98 skipped, 0 failed`.
