# Phase 7 Stabilization Review

This independent read-only review covers the two test-only corrections and the fixture line-ending attribute following PR 190's first hosted verification failures. Scope: `tests/skills/test_safe_artifact.py`, `tests/skills/test_security_audit_benchmark_lifecycle.py`, the narrow `.gitattributes` addition, the retained hosted failure evidence, affected runtime guards, and the private deterministic perturbation/checkout probes. All corrections remain in the same uncommitted Cycle 3 stabilization scope at review time.

**Verdict**: PASS for the reviewed fixes. Zero findings. The original security assertions remain unchanged; no runtime correction is implied or required by these two failures.

## Failure roots and proving intent

| Test | Observed root cause | Applied correction and preserved assertion |
|---|---|---|
| `test_a_post_open_swap_is_detected` | Hosted Linux reported `ancestor_swap` instead of `post_open_swap`. The test's global `os.fstat` mock changed every inode, including POSIX directory descriptors checked by `_directory_guard` before the leaf reader. The guard rejected the simulated ancestor substitution before the intended leaf substitution was reached. | `stat.S_ISREG` limits the simulated identity change to regular-file descriptors; directory stats retain their original identity. The test still requires the exact `post_open_swap` error from the real safe reader. It does not weaken ancestor validation or broaden the accepted error set. |
| `test_post_ledger_substitution_rejected[fork]` | Hosted Linux selected a `0003` entry from unspecified `iterdir` order. Replacing `0000` left that filename unchanged, so `shutil.copyfile` raised `SameFileError` before the protected verification assertion ran. Replacing every substring also risked altering a coincidental hash substring. | Select the explicit `0000-` entry, then change only its first four sequence characters to `0001`. This guarantees a distinct duplicate-sequence artifact while retaining its type, attempt identity and hash suffix. The real ledger parser still sorts, checks sequence/content/hash/name consistency, and must reject the tampered candidate during rendering. |

## Independent verification

- The exact hosted log was inspected: these were the two reported failures in a group with 1,571 passes and 12 skips. The failure stack locations distinguish test setup from the runtime verification being asserted.
- The final two-file diff was inspected. It adds the regular-file guard and explicit sequence-entry selection without changing either security assertion.
- An independent run of both corrected tests with the private perturbation plugin passed: two passed, exit 0, in 8.15 seconds. The plugin reverses ledger-entry enumeration and checks that the leaf-swap injection preserves a sentinel directory stat. This independently exercises both formerly invalid assumptions on Windows.
- The parent separately reported the pre-fix perturbation run as two failures. This reviewer did not rerun that pre-fix tree and does not present the parent's RED result as an independent execution.

## Considered but rejected

| Candidate | Inspected evidence and reason |
|---|---|
| The hosted swap failure shows the runtime containment guard stopped working. | The recorded error is a successful ancestor-swap refusal. The test injected a different ancestor identity unintentionally; the regular-file restriction restores the intended leaf-only stimulus. |
| Production ledger parsing depends on filesystem enumeration order. | `ledger` explicitly sorts entries before checking sequence and hash-bound filenames. The unspecified-order dependency was in this test's construction of the fork. |
| The adjacent unsorted `next(iterdir())` in the `entry` case needs the same change. | That case intentionally corrupts any existing entry, then requires render rejection. Its success condition does not depend on the chosen sequence, so the same failure mechanism does not apply. |
| The revised fork test might copy an entry onto itself or corrupt its hash substring. | Selection requires `0000-`; the destination begins with `0001` and retains the suffix starting at character four. Source and destination necessarily differ, with no global substring replacement. |

No other global `fstat` mutation or `0000` replacement was found in the two reviewed files. This is a bounded assessment, not a repository-wide assumption audit.
