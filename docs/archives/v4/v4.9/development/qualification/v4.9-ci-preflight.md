## Proposed changes

### P1 - QG-1 Windows audit selection

Append one `_pytest` command to existing `WINDOWS_HOOKS` in `scripts/ci/profiles.py`. It runs only on Windows, has timeout 1200 seconds, and retains `NEXUS_TEST_POWERSHELL=powershell`. The existing tests-windows profile call selects it without a new job, context, dependency, or host/model/scanner invocation.

Select exactly these files under `tests/skills/`:

- `test_safe_artifact.py`.
- `test_target_manifest.py`.
- `test_strict_json.py`.
- `test_security_scanner_contract.py`.
- `test_graph_receipts.py`.
- `test_application_audit_envelope.py`.
- `test_security_review_sarif.py`.
- `test_security_audit_benchmark.py`.
- `test_security_audit_benchmark_lifecycle.py`.
- `test_security_audit_contract_e2e.py`.

The selection collected 424 tests during preflight. Cost: additional execution inside the existing Windows job, with no new startup. Hosted runtime remains unmeasured. Risk: real Windows path/handle/filesystem behavior or capability skips can fail or limit the gate; a 1200-second command timeout bounds the added work, and the existing job-level 60-minute timeout remains unchanged. The proposed profile regression proves selection, Windows-only execution, and the exact timeout.

Decision: PENDING explicit approval.

### P2 - Git long paths before Windows checkout

Add a step before actions/checkout in five Windows-capable jobs: ci.yml tests-windows, bootstrap-windows, install-smoke, installer-smoke, and nexus-memory.yml test-locking-matrix. The step has `if: runner.os == 'Windows'`, `shell: pwsh`, and `run: git config --global core.longpaths true`.

Cost: seconds and no dependency. Risk: changes Git configuration only on the disposable hosted runner; it does not promise every Windows shell or archive utility can manipulate arbitrary long paths. Setting this after checkout would not protect checkout itself. The proposed regression checks every Windows-capable workflow checkout and requires the setup earlier in its step sequence.

Decision: PENDING explicit approval.

### P3 - Select the existing interpreter gate before merge

Add interpreters to validate's existing full-profile group selection and to tests-windows' platform selection. No new group, job, required context, or probe implementation is introduced.

Cost: a small existing local interpreter probe, no dependency. Risk: correctly fails a runner whose declared interpreter cannot execute hooks. The proposed parametrized regression requires the interpreter profile selection in both pre-merge jobs.

Decision: PENDING explicit approval.

## Official Windows long-path evidence

The observed ledger filename reaches 298 repository-relative characters, approximately 323 characters under `D:/a/Nexus-Hub/Nexus-Hub/`. The schema requires its full candidate, attempt, and entry hashes, so shortening the checkout directory cannot alone solve the longest relative path.

Git for Windows documents core.longpaths as disabled by default and says it enables long-path support for builtin Git commands. The official runner image sets Windows LongPathsEnabled to 1, but its Git installation script does not set core.longpaths. GitHub code search for core.longpaths in actions/runner-images returned no matches. Therefore, official evidence does not establish that Git's separate setting is already enabled. The recommendation is an inference from image configuration and Git's documented default, not a live hosted-runner probe.
