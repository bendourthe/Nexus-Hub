Authored: 2026-09-29
Authoring cycle: v4.13.x (last tag `v4.13.5`, created 2026-09-29 on a base newer than the branch this report was written on)
Adoption target: v4.13.8

The user chose `v4.13.8`, immediately behind the just-prioritized `v4.13.7`. Consequence: this adoption edits `profiles-index.json` and `eval-pipeline-audit/SKILL.md` before `v4.17.6` and `v4.17.3` do, so those plans re-read both files (see Queued-plan impact). No renumber of existing plans.
Sources: four (one social-media post, one vendor blog, one GitHub repository, one web guide)
Skill: `cross-project-comparison`

The question in Source 1 is whether "think from first principles" should become part of key prompts, commands, and skills. The answer is no for the shared instruction surface and a bounded, measured yes for a handful of framing-heavy skills. The claim is one self-hedged anecdote about a different model family. The closest published evidence (step-back prompting) shows task-dependent gains on older models with a non-trivial rate of newly introduced errors. The vendor's own Sonnet 5.5 prompting guide reports a measured effect only for a narrow case (a "Think the problem through before you answer" line for reasoning tasks answered as structured JSON, where the model often skips thinking), and Nexus-Hub's profiles say to raise effort rather than prompt around shallow reasoning. A phrase added to the shared templates ships verbatim to roughly twenty platforms, so it has to earn its place with measurement first. The other three sources produce one clear correction (the catalog has no Sonnet 5.5 prompting profile even though every current plan's model map lists that model as the standard tier), one reusable reporting rule (a retrieval CLI's own benchmark restated its headline saving three times), and a guide whose recommendations Nexus-Hub already covers almost entirely.

- S2 is vendor-authored. The speed, cost, and benchmark figures are the vendor's own. The primary prompting guide adds measured claims of its own, each stated with its conditions (for example, a stop-and-report paragraph that cut session cost by about a third at `max` effort with no quality change). - S3 reports a ten-task, single-run SWE-bench comparison on tuned Python tasks. The README restates its own headline three times: 28.6% lower agent cost excluding the retrieval model's cost, then 25.8% lower total cost including it, then a later release whose combined cost was 2 to 3% higher. ## Step 7: Risks, conflicts, and items not recommended

**Conflicts to resolve during implementation:**

- **Reasoning-technique guidance against adaptive-thinking models.** `step-2-apply-reasoning-techniques.md` teaches written reasoning templates. The Sonnet 5.5 blog advises against asking the model to write out its reasoning, and the Sonnet 5 profile says to raise effort rather than prompt around shallow reasoning. A4 must state that any technique entry is conditional on the model and effort, and must not present it as a default.
- **A confound in A4.** Effort and thinking defaults change how much a model reasons regardless of any phrase, and the vendor's guide says a think-first line matters mainly where the model would otherwise skip thinking (low and medium effort, structured output). Runs must hold effort and thinking constant, and the control arm (M13) is what separates a general thinking nudge from the first-principles wording.
- **Newsletter claims against primary sources.** The newsletter's "rolls back changes that overfit" for `hillclimb` was not confirmed. A3 is justified on its own by the selection-bias gap in `skill-eval-loop`, so it does not depend on that claim.
- **Sequencing choice.** Placing this adoption at `v4.13.8` puts model-profile work ahead of the effort-allocation plan it informs. This is safe because A1 changes no shipped default, and the later plans read A1's output.
