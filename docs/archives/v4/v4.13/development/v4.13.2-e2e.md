# v4.13.2 End-to-End Evaluation

Design, runs, and verdict for the v4.13.2 Phase 8 evaluation: whether a full `/implement` run reaches `PLAN COMPLETE` with no unplanned stop on each enforcement layer. Read it to see what was measured, on which platforms, at what cost, and what the verdict licenses. The harness is `tests/e2e/implement_full/`.

## Status

**Complete (2026-09-26 to 2026-09-27).** Paid runs used only `NEXUS_PILOT_ANTHROPIC_API_KEY` and `NEXUS_PILOT_OPENAI_API_KEY`, each mapped into the child process alone; the harness never copies a user's credentials. The first pass closed at USD 38.12 (about USD 29.1 Anthropic, USD 9.0 OpenAI) under the USD 50 cap. Verdict below.

## Design (fixed before any paid run)

### Fixture

A two-phase plan (fix `add`, test `add`) plus a minimal final phase whose heavy duties self-gate, one open known gap (`BG-1`), a local bare remote with `main` and `develop`, and the stateful `gh` stand-in (`gh_e2e.py`) answering `pr create|view|checks|merge`, `release create|view`, `run list`, and `api`. The fixture has no designed blocker, so every blocker is an unplanned stop.

### Flow per run

1. A throwaway home with Nexus-Hub installed for the platform under test (`HOME`, `USERPROFILE`, `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, and `XDG_CONFIG_HOME` all point there; credentials come only from the environment).
2. A scripted first turn: `/implement <plan>` with the upfront approvals answered verbatim in the same prompt, never mid-run. It creates the run record.
3. `nexus-hub run-plan <plan> --platform <row>` resumes that session until the checker's verdict is terminal.
4. The checker's verdict is read back from the fixture.

### Conditions after the change

| Condition | Platform | Layers |
|---|---|---|
| A | Claude Code | native goal + hook + runner |
| B | Codex (`codex exec`) | hook + runner (the required real Codex run) |
| C | OpenCode (`opencode run`) | plugin + runner |
| D | Claude Code, hooks disabled, no runner | instructions only (measurement, not a gate) |

Baselines: one run per platform at the commit before this plan (`e8c34ef0`); the Codex baseline is `codex exec` without a runner, which did not exist.

### Measures

Per run: unplanned stops (any stop that is not a terminal verdict), deferrals, the final verdict, runner cycles, and spend per vendor (Claude Code through the harness's spend shim, which adds `--output-format json` and a per-call `--max-budget-usd`).

### Budget and rules

- A pilot run first, then the matrix sized to the USD 50 first-pass budget; fix-and-rerun cycles draw only on a separate USD 50 reserve; hard ceiling USD 100.
- Fixed only if every after-change run in conditions A, B, and C reaches `PLAN COMPLETE` with zero unplanned stops. Condition D is reported, not gated.
- Up to five fix-and-rerun cycles for a failing condition; if it still fails, the fallback slice ships (checker, gates, runner, and release path, with the previous one-phase default restored) and the miss is an owned known gap.
- Rule-of-three: zero failures in n runs bounds the per-run failure rate below 3/n at 95 percent confidence.
- No test asserts model output; prompts are not tuned between runs.

## Harness proof with a scripted agent (no model)

`python -m pytest tests/e2e/implement_full/test_harness.py -q` runs the full flow with `stub_agent.py` standing in for the CLI (one phase per cycle). Recorded 2026-09-25:

```text
runner_exit: 0
incomplete_cycles: 1
verdict: PLAN COMPLETE docs/releases/v0/v0.2/plans/v0.2.0-demo.md af55a97f... 61080b9b...
seconds: 10.1
```

All 14 completion predicates were satisfied through the real checker, the real runner, and the stateful `gh` stand-in: task commits after the record's start, the resolved gap, the evidence file, the merged pull request with green checks, the tag on the remote and in `main`, the published release, and the deleted branch. This proves the fixture is completable and the chain holds; it does not measure a model.

Building the proof found and fixed two defects before any paid run:

- **The runner launched a fresh session on its first cycle.** The run record exists only because the upfront round ran in a session; a fresh session carries a different session id, so the turn-end gate bound to the record would never fire there. Every cycle now resumes.
- **A bare `gh` in a subprocess reached the real GitHub CLI on Windows**, because CreateProcess ignores `PATHEXT` and skipped the stand-in's `gh.cmd`. The stand-in agent now resolves `gh` the way the checker does (`shutil.which`); the call it made failed against a nonexistent repository and changed nothing.

### Harness fixes (do not change the product)

- **Unattended permission profile, no bypass.** `run_plan.py` passes no bypass flag and refuses a platform whose own config bypasses approvals, so an unattended run can edit and run commands only where the platform's settings allow it. The harness grants exactly that inside the throwaway home and records it per run: Claude `permissions.defaultMode=acceptEdits` plus `Edit`, `Write`, `MultiEdit`, and `Bash(git|gh|python|python3|pytest|nexus-hub *)`; Codex `sandbox_mode="workspace-write"` with the fixture remote as a writable root; OpenCode `permission.edit` and `permission.bash` set to `allow`.
- **The harness runs from a virtual environment.** The Microsoft Store Python derives `sys.executable` from `USERPROFILE` and `LOCALAPPDATA`, so it cannot survive an isolated home. `LOCALAPPDATA` stays real and the venv's `Scripts` directory leads `PATH`.
- **Realistic `gh` not-found output.** Both `gh` stand-ins (`tests/fixtures/gh_stub/` and `gh_e2e.py`) now print real `gh`'s whole-line messages for a missing pull request or release, captured 2026-09-27 from read-only queries: `no pull requests found for branch "<branch>"` and `release not found`, each with exit 1; an unauthenticated call exits 1 with `HTTP 401: Bad credentials`.
- **A `gh` stand-in Git Bash can find.** An agent's Bash tool is Git Bash, which never resolves `gh.cmd`, so a bare `gh` there reached the real GitHub CLI (harmless only because the isolated environment carries no GitHub credentials). Each stand-in now also ships as an extensionless script; Python's `shutil.which` still resolves the `.cmd`.
- **Codex grants inside its installed profile.** The installed `default_permissions` profile overrides `sandbox_mode`, so writes are granted as absolute-path entries in `[permissions.default.filesystem]`: the run root, `work` itself (the workspace, which `":workspace_roots" = "read"` otherwise keeps read-only), `work/.git` (Codex keeps `.git` read-only inside a writable root), the remote, and read on the user-local Codex package, which the Linux sandbox re-executes.
- **Codex hook trust.** Codex skips every hook the user has not trusted through `/hooks`, so the spend shim adds `--dangerously-bypass-hook-trust` to Codex calls. It stands in for the one-time interactive trust and relaxes neither approvals nor the sandbox; the runner itself still refuses every bypass flag.
- **`PWD` and `nexus-hub` on PATH.** Git Bash exports `PWD`, which OpenCode trusts over the process directory, so every child gets `PWD` set to `work`; `~/.nexus-hub/bin` leads PATH, as the installer's shell-profile step would.
- **Stand-ins inside the run root, installs isolated from the real editors, and a pre-flight.** The stand-in scripts are copied into the run's `bin`, which the sandbox can see; the installer gets a throwaway `LOCALAPPDATA` so it cannot reach the user's VS Code or Cursor; and a run stops before any paid call unless the platform holds this tree's `implement-phase` skill byte for byte. Each run keeps its installer output as `install.log`.
- **Metering for every paid CLI.** The spend shim meters Claude (`total_cost_usd`), Codex (token usage at published rates), and OpenCode (`step_finish.cost`) into one ledger; Codex and OpenCode have no per-call budget flag, so their calls are bounded by a 30-minute timeout and the guard assumes the per-call cap.
- **The approval names the remote.** The fixture's approval now reads "for acme/demo, whose git remote origin is its local mirror: push to origin, ...", so the push destination is one the approval names. This corrects the fixture, not the prompt a model sees about the task.

### Product fixes

- **Installed script paths.** `/implement`, `/update release`, `[[implement-phase]]`, its runbook, the completion contract, and the mandatory final phase now run `python ~/.nexus-hub/scripts/<name>.py` for `check_plan_completion.py`, `plan_status.py`, and `check_release_preconditions.py`. The contract states that a missing installed copy is `BLOCKED: platform-unavailable`, never a reason to skip the record.
- **Installer copy bug (pre-existing, on `main`).** Both installers copied `plan_status.py` onto `generate_report.py`; each script is now copied under its own name, guarded by `test_installers_copy_every_script_to_its_own_name`.
- **Not-found is `unmet`.** `check_plan_completion.py` matches the whole `gh` stderr line; a not-found answer is `unmet` (the next step is to create it), while an unreachable, unauthenticated, or over-budget call stays `cannot-verify`. Guarded by `test_hosting_not_found_is_unmet_work_not_an_unreachable_platform` and `test_not_found_text_inside_another_error_still_cannot_verify`.
- **Windows install without Claude Code (BG-2).** `installer.ps1` passed the project name as a separate, empty argument that Windows PowerShell 5.1 drops, so every registry platform was skipped; it now travels as one `--project-name=<value>` token.
- **OpenCode agents (BG-3).** The `tools` line is dropped from agents installed for OpenCode; `opencode debug config` then loads all 23.
- **Linux install without `python3-venv` (BG-4).** `installer.sh` skips only the MCP servers instead of aborting under `set -e`.
- **Unrecorded approvals (BG-5).** The runbook and `/implement` now say approvals count only after `RECORDED`, and each push, merge, and release gate checks `record path <plan>`.
- **Codex Linux sandbox (BG-6, with the user's approval).** The shipped profile grants the documented `":minimal"` and `":workspace_roots"` read keys; commands run and writes stay gated.
- **The runner reads the verdict before its first launch.** Pilot 5's runner resumed a run already `BLOCKED` and spent USD 2.96 restating the blocker. Guarded by `test_terminal_verdict_before_the_first_cycle_launches_nothing`.

## Verdict

**Verified on Claude Code and Codex; not verified on OpenCode.** Shipped full-by-default on every platform by the user's decision of 2026-09-27, with the OpenCode behavior recorded as WN-7.

- **Condition A (Claude Code): pass.** Three of three runs reached `PLAN COMPLETE` in the first turn with zero unplanned stops, opening, merging, and releasing only through the pinned repository.
- **Condition B (Codex): pass, one run.** B7 reached `PLAN COMPLETE` in the first turn with zero unplanned stops; the second run was blocked by the OpenAI quota (MT-1).
- **Condition C (OpenCode): fail on the safe-stop criterion.** A headless OpenCode run cannot record approvals by design (WN-4), and in two runs the agent proceeded on the in-prompt approvals instead of stopping (WN-7).
- **Condition D (instructions only): measured.** Without the hooks and runner no record was created and hosting evidence could not be bound, so the run could not reach `PLAN COMPLETE`; the enforcement layers carry the result, not the instructions alone.
- **Baselines at `e8c34ef0`:** the Claude Code baseline left hosting and test evidence unmet, and the Codex (Linux) and OpenCode (Windows) baselines could not install because of BG-4 and BG-2, both fixed in this release.

The plan's literal rule (every A, B, and C run reaches `PLAN COMPLETE`) is not met, because condition C's criterion cannot be met headlessly by design; the fallback slice was declined by the user. What the evaluation licenses: a full `/implement` run completes end to end on Claude Code and Codex with the gates and runner in place. It does not license a reliability rate on any platform, or safe behavior on OpenCode without a record.
