## What this phase was for

The full skill table is about 81-84% of every rendered instruction file, and platforms that discover skills by themselves do not need it repeated. This phase adds an opt-in pointer that replaces the table only where that discovery is documented by the vendor and a skills tree is actually installed. The default stays the full index.

## Queue re-assessment (phase entry)

No drift. No queued plan edits `platform-read-contracts.json`'s new section, `skill_read_paths.py`, or `_effective_template_vars`.

## Steps taken

1. **T032, facts and eligibility.** Re-fetched the first-party skill-discovery pages for Claude Code, Copilot, Cursor, Codex, OpenCode, Antigravity, Gemini CLI, Qwen Code, Devin/Windsurf, and Hermes on 2026-09-25, and recorded a machine-readable `skill_read_paths` section in `docs/policy/platform-read-contracts.json`: per platform and scope, each path's `status`, `source`, and `verified` date. Also added a matching dated entry to `platform-read-contracts.md`.
    - `scripts/lib/integrations/skill_read_paths.py` loads the facts (a missing contract yields none), resolves paths, and validates the schema. The validation requires an https source and an ISO date on VERIFIED entries and checks agreement with the prose doc.
    - `scripts/verify_platform_contracts.py` now runs that validation.
    - `IntegrationBase.native_skill_enumeration(ctx)` is true only when a VERIFIED path for the platform and scope holds an installed `*/SKILL.md` tree, derived on every call and never stored.
2. **T033, mode.** The runner parses `NEXUS_HUB_SKILL_INDEX` once into `InstallContext.skill_index_mode` (`pointer` case-insensitively, otherwise `full`). In pointer mode with more than one integration, it re-runs each successful install after all of them finished. A shared path supplied by a later integration (Codex's `~/.agents/skills` for Copilot) is then judged from the final destinations, not caller order, and a provider that failed leaves no tree, so its consumers stay on the full index.
3. **T034, rendering.** `_effective_template_vars` substitutes the pointer for `{{SKILL_INDEX}}` only when the mode is `pointer` and the platform is eligible. The pointer keeps the `# Nexus-Hub Skill Index` heading (the `install_verify` needle), names the installed skills directory, and names `~/.nexus-hub/data/SKILL_INDEX.md` only if that file exists. It names no command or tool that some eligible platform lacks. Templates are untouched, so template parity holds.
4. **T035, tests.** `tests/integrations/test_skill_index_pointer.py` (30 tests) covers:
    - mode parsing and fallback;
    - the full mode being byte-identical to the default;
    - pointer rendering, the no-tree fallback, and every advertised path existing, at global and workspace scope;
    - eligibility for every registered integration in both scopes against the facts, with and without installed trees, UNVERIFIED paths never counting, and a missing contract failing closed;
    - `copilot,codex` in consumer-first order, and a failed provider keeping Copilot on the full index;
    - validator rejections and the contract verifier;
    - both installers passing the environment through.
    The file is registered in `repo-tests-integrations-install`.
5. **Capability usage draft.** `docs/releases/v4/v4.13/development/v4.13.3-capability-usage.md` holds the five-part release-notes entries for the pointer and for Phase 4's removal flag.

## Troubleshooting

### Copilot's `~/.claude/skills` claim did not survive the re-fetch

The 2026-09-21 pass recorded `~/.claude/skills` as a Copilot user-scope read path, and the plan's example relied on it. The page cited for Copilot personal skills now lists only `~/.copilot/skills` and `~/.agents/skills`, so the path is recorded UNVERIFIED and fails closed. The ordering tests use Codex as the shared-path provider instead.

### `native_skill_enumeration` first landed on the wrong class

It went onto `MarkdownIntegration` beside the render owner, so Hermes (not a Markdown integration) had no such method. It now lives on `IntegrationBase`, as the plan names it.

### Byte-identity looked broken until paths were normalized

The HEAD-versus-unset comparison flagged every file. The only difference was each throwaway home's own path and the `# <project>` heading derived from its directory name; after normalizing both, all eleven instruction files are byte-identical.
