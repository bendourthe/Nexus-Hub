## What this phase was for

`check_plan_completion.py` parsed `owner/repo` with a regex that accepted only a host literally named `github.com`. This repository's origin is `git@github-bendourthe:bendourthe/Nexus-Hub.git`, an SSH host alias, so the checker's default repository was empty and `integration.merged`, `integration.checks`, and `release.github` were `cannot-verify` on every shipped plan: a full `/implement` run could never reach `PLAN COMPLETE` here.

## Steps taken

1. **T001**: added `scripts/repo_host.py` (standard library only). `parse_remote` accepts `https://`, `ssh://`, and scp-like `git@host:owner/repo` forms, strips credentials and ports, and rejects anything with more or fewer than two path segments. `repo_from_url` accepts `github.com` or `GH_HOST` directly; any other host reached over ssh is treated as an alias and replaced by the `hostname` line of `ssh -G <alias>`, and an alias that looks like an option is refused before ssh runs. `resolve_repo` prefers a frozen record repository, else the verified origin URL, cross-checked with `gh repo view` when `gh` answers; a disagreement yields no repository. `absolute_tool` (moved from the checker) resolves executables on absolute PATH entries only and refuses one inside the working tree.
2. **T002-T003**: both installers copy `repo_host.py` beside `check_plan_completion.py` in `~/.nexus-hub/scripts/`.
3. **T004**: the checker imports `repo_host` as a sibling, uses `absolute_tool` for `git` and `gh`, and resolves its default repository lazily, only when no frozen repository exists, so the `ssh -G` and `gh repo view` calls cost nothing on a normal run. `approval.remote` keeps the WN-1 binding: the live push URL must equal the recorded `push_remote_url` byte for byte, and the repository that URL names (now alias-aware and host-verified) must equal the recorded `repo`. `record create` uses the same resolution. `REMOTE_RE` and the checker's own `_which_on_path`, `_tool`, and `_is_inside` are gone; a repository-wide test asserts no other script or hook parses GitHub remotes itself. `run_plan.py` keeps its local executable lookup by design and now names `repo_host` as the reference. The completion contract describes the resolution.
4. **T005**: `tests/validators/test_repo_host.py` (39 cases: every remote form, GitHub and non-GitHub aliases, an https look-alike host, failed or missing ssh, an option-shaped alias, `GH_HOST`, the `gh` cross-check agreeing, disagreeing, and unavailable, a missing remote, both installers, and the no-second-parser guard). `tests/validators/test_check_plan_completion.py` gains an `ssh` stand-in and three integration cases: an approved alias push remote reaches `PLAN COMPLETE` with `approval.remote met`; `record create` refuses an alias whose real host is gitlab.com; without a record, a gitlab alias yields `release.github cannot-verify` with no pinned hosting call, while a GitHub alias pins every call to `acme/tool`. The existing changed-push-remote regression gains an alias pointing at a different repository, still `unmet`.
