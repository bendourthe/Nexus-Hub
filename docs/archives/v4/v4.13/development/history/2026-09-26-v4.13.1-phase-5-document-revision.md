## What this phase was for

Stop the document skills from saving or copying straight onto an existing deliverable, which is how the incident's slide edit was lost.

## Steps taken

1. **T011**: an `## Existing-Deliverable Revision` section, placed before `## Common Rationalizations`, in `pptx-generation`, `docx-generation`, `xlsx-generation`, `pdf-document-generation`, `document-to-interactive-html` (with an extra item on builder rebuilds), and `deep-research-compilation`, plus a matching section before `## Output` in `catalog/commands/presentify.md`.
    - Once a deliverable exists, the agent opens and edits the current file and changes only the targeted slides or sections. If a rebuild is unavoidable, it builds to a working path, merges the user's edits from `edit_guard.py diff`, and asks before replacing the original.
    - Each section defines two helpers, `guard_existing(path)` (runs `edit_guard.py check` and stops on any nonzero exit when the file exists) and `record_saved(path)`, and names `user-edit-preservation` as the owner.
    - On a nonzero check, the agent runs `diff` and ends its turn with the owner skill's three-part reply, writing only after the user says yes.
2. **Save-call checklist**: every `.save(`, copy, `.build(`, and `write_pdf(` example in the six targets' references and scripts was walked and recorded in `docs/releases/v4/v4.13/development/v4.13.1-admission.md`. 16 call sites that overwrite a deliverable are now wrapped in `guard_existing()` before and `record_saved()` after. The other 40 are not deliverable overwrites (in-memory buffers, pytest temporary directories, a commented-out example, first-creation tutorials writing a new file), and each is labeled with its reason.
3. **Owner skill**: step 3 of `user-edit-preservation` is now a mandatory three-part reply template (what the user changed, suggestions not applied or "None", and the plan ending in a question).

## Troubleshooting

### A substring anchor matched two save lines

The first scripted insertion anchored on `doc.save`, which also matched an indented line inside a `with` block. The edit script now matches whole lines, and the checklist confirms each guard sits in front of the intended call.

### The PDF/A guard ran after the build

In `step-7-advanced-features.md` the guard was first placed before the pikepdf post-processing, after `doc.build` had already overwritten the file. It now runs before `doc.build`, and `record_saved()` runs after the `with pikepdf` block closes.

### The first paid run wrote without asking and listed no suggestions

The first fixture run kept both user edits and made both changes, but neither reply listed suggestions, and the docx agent wrote in the same turn. The fix was the three-part reply template in the owner skill and a revision-section step that says to end the turn after the reply. The rerun below passes.
