## What this phase was for

A VS Code or Cursor user sees Copilot usage in the status bar and dashboard with the Codex monitor's design, drawn only from the Phase 1 sources, and the extension writes the percentages-only state file the handoff guard reads. The maintainer's Copilot seat is on a work account while their projects are on a personal one, so the monitor follows the account pinned for the extension, never the open repository.

## Steps taken

1. **T005**: `extensions/copilot-usage-monitor/` scaffolded from the Codex monitor's tracked files with the maintainer's artwork: `icon.png` from `GitHub-Copilot-logo.png`, the `github-copilot-icon.svg` glyph as an icon font generated by a port of the Cursor monitor's generator (non-square view box handled, fill rule checked per contour).
2. **T006**: the personal provider reads `api.github.com/copilot_internal/user` through the VS Code GitHub session: background refreshes call `getSession("github", [], {createIfNone: false, silent: true})` so the pinned account decides, and only the explicit Sign in and Switch account commands prompt (with `read:user`). A quota gives a percentage only when limited with entitlement above 0; a Business seat (all quotas unlimited) shows credits used and no percentage.
3. **T007**: the organization provider uses a read-only fine-grained token stored only in VS Code secret storage and sent only to `api.github.com`, with redirects refused. Pool used is the unrounded sum of `discountQuantity` for the `Copilot AI Credits` sku in the requested month (negative or non-finite quantities skipped); the total is seats times 1,900 (Business) or 3,900 (Enterprise), marked approximate when a seat was added this cycle.
4. **T008**: status bar precedence is the organization pool when connected, then the personal quota, then credits used with no percent sign; teal progress bars (`#0E8A85`, at least 3.64:1 against seven default theme backgrounds). The dashboard carries a nonce Content-Security-Policy with no inline handlers, validates settings and webview messages, and the monitor's settings are application-scoped so a workspace cannot set them.
5. **T009**: the state file `~/.nexus-hub/state/usage-probe/copilot.json` is written atomically with percentages, reset times, source, and the approximate flag only; it is absent for the member state and removed on sign-out, and a transient fetch failure keeps the last figure marked stale until the probe's 30-minute rule retires it.
6. **T010**: 14 test files (254 tests), including the two-account acceptance test (work account pinned in a workspace whose remote and identity are personal shows the work seat; switching the pin switches the view), a static and runtime check that no git config, remote, `gh` state, or child process is read, a leak test over every 12-character window of each fake token, and a cross-check that the state file parses through the probe's `read_copilot`.

An independent review found a script-injection path through unescaped settings in a dashboard without a Content-Security-Policy, a second sku summed into the pool, a transient organization failure that silenced the guard, a leak test matching only whole tokens, a bypassable static check, unscoped settings, and a stale state file after sign-out. All seven were fixed; each fix was confirmed by reverting it and watching a test fail. The Codex and Claude monitors carry the same two dashboard defects (v4.13.7 WN-2, for sub-task 3.6).
