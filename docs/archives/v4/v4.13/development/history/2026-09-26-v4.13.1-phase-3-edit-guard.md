## What this phase was for

Build the component that decides whether a user edit is detected at all: a store of the agent's last-known state of every file it touches, across sessions and formats, and a helper that shows what changed and releases a block only after review.

## Steps taken

1. **T007**: `catalog/skills/workflow/user-edit-preservation/scripts/edit_guard.py`, standard library only, with lazy `python-pptx`, `python-docx`, and `openpyxl` imports that print an install hint.
    - **Store.** Default location `NEXUS_EDIT_GUARD_DIR` or `~/.nexus-hub/cache/edit-guard/`. There is one JSON record per canonical path, keyed by its SHA-256, with no session scoping.
    - **Store permissions.** Directories are 0700 and files 0600, plus an owner-rights-only DACL on Windows. It mirrors the installer's `_windows_owner_only`, because a skill script cannot import the repository.
    - **Store location rules.** It refuses a store inside the current workspace, inside a git repository, or inside a OneDrive, SharePoint, or Dropbox root.
    - **Canonical path.** Absolute, parent links and junctions resolved, 8.3 names expanded (`GetLongPathNameW`), `/` separators, case-folded on Windows and macOS. A link at the leaf itself is refused.
    - **Fingerprint.** Streamed SHA-256. Office files are hashed by content part, excluding `docProps/*`, so AutoSave metadata is not a change.
    - **Copies.** A copy of the file as the agent left it is kept, except for secret-looking paths (`.env*`, `*.pem`, `*.key`, `id_*`, `credentials*`, `*.kdbx`, `*.p12`, `*.pfx`) and files over 10 MB.
    - **Subcommands.** `record [--from read|write|command]`, `check` (0/3/4/5/2), `diff` (text diffs; per-slide pptx text with titles, body, notes, tables, groups, and unit count; per-paragraph docx; xlsx cells; "non-text change" with the changed parts), `accept`, `log`, and `purge [--path]`. Records older than 30 days are pruned on every run.
    - **Lock files and conflict copies.** An Office lock file (`~$name`) or a OneDrive conflict copy (`name-MACHINE.ext`) makes `check` report "open or conflicting copy". An online-only OneDrive placeholder is reported "cannot verify" without being read.
2. **Tests**: `tests/skills/test_edit_guard.py`, 25 cases:
    - the record/check/diff/accept cycle for text, pptx, and docx;
    - a cross-session change, a moved picture as a non-text change naming `ppt/slides/slide2.xml`, and metadata-only pptx and docx rewrites reported unchanged;
    - an 11 MB file fingerprinted without a copy, a lock file, and a OneDrive conflict copy;
    - accept refused without a diff, after a second change, and from another session;
    - `record --from read` refused on a changed file;
    - no record, a missing file, a corrupt archive, a symlink leaf, and an online-only placeholder;
    - secret paths keep no copy, the store is owner-only, and the store refuses git, OneDrive, and workspace locations;
    - purge, 30-day pruning, the accept log, and case folding.

## Design decisions not spelled out by the plan

- **Recording a read.** `record --from read` refuses when the file changed since the last record: otherwise merely reading a user-edited file would re-baseline it and launder the change. `--from write` and `--from command` re-baseline, because the caller attests the agent made that change and Phase 6's pre-write check runs before it.
- **Session identity.** An agent runs the helper through fresh shells that carry no session id, so `accept` uses the explicit `--session` or `NEXUS_EDIT_GUARD_SESSION` when either `diff` or `accept` has one. Otherwise it requires the diff within 30 minutes. In every case the file must still hash to exactly what `diff` showed, which is the property that matters: the reviewed bytes are the accepted bytes.

## Troubleshooting

### Tests ran from inside the store's parent

Every early call exited 2 because the test helper ran the script from the store's parent folder, which put the store inside the working directory, the case the guard refuses by design. The tests now run from a separate project folder, as an agent does.

### The stored copy was never parsed as Office

Copies are stored as `<key>.bin`, and the text extractor chose its parser from the suffix, so `diff` labeled a real title edit a "non-text change", and `check` could not recognize a genuine non-text change. The extractor now takes the original file's suffix.

### Nested-scope bug caught by lint

`lines += ...` inside the nested shape walker made `lines` local, which would crash on any slide with a table. It now uses `extend`.
