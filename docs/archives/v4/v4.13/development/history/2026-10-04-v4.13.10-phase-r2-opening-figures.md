## What this phase was for

The maintainer found the first opening figures geometrically poor, slow like dated slides, and not true to their pages; the Cheatsheets one illustrated a random command instead of how to use the page.

## Steps taken

1. **Rebuilt the figures in HTML and CSS** instead of scaled SVG, so text stays crisp and every figure reflows on a phone. Motion is continuous and quick (tokens highlight, a context gauge fills, rings turn, dots travel the pipes), never one item at a time.
2. **Foundations**: one request through every idea on the page. Tokens, prompt (request, context, goal, format), context window, and model, inside an agentic platform (tools, memory, permissions) with its loop, inside a harness (skills, commands, hooks, rules). All six parts link to their scenes.
3. **Cheatsheets**: a guided demo of reading the page. In an 8-second loop a cursor picks a group, finds the `/plan` card, chooses a scope, and copies the line, while four numbered steps light in turn. A few lines of script measure the real targets, so the cursor lands on them at any width.
4. **Training**: the journey as five illustrated stops (the buggy game, loop 1, playing again, loop 2, the reward). A highlight travels from stop to stop, and the scenes move: twinkling stars, a flickering engine, drifting enemies, a pulsing bug, a turning loop ring.
5. **Found by testing**:
    - Keyframes that set opacity only at the end left the prompt lines at 5 percent.
    - The guide's global code-chip style boxed every code element in the figures.
    - A figure class had no style rule.
