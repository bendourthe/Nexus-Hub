## Steps taken

1. **Gate core** (`scripts/completion_gate.py`). `stop` finds the run record bound to the payload's session, runs the INSTALLED checker (refused if inside the working tree), allows on `PLAN COMPLETE`, blocked, or paused, writes `record-tampered` on a malformed plan, keeps hook-owned progress state beside the record, writes `no-progress` after three refusals without a larger score or new `HEAD`, and otherwise emits the continuation. `capture` stores SHA-256 digests of the prompt and each line, with the raw session id, under `~/.nexus-hub/runs/prompts/`; Cursor gets its required `{"continue": true}`. A 30-second budget allows the stop when exceeded.
2. **Format resolution.** `NEXUS_GATE_FORMAT` when set, else the payload: `cursor_version` is Cursor, `AfterAgent` is Gemini CLI, `session_title` with `client_type` (Kimi's documented base fields) is Kimi's exit 2, and everything else gets the canonical `top-level-block`.
3. **Adapters.** `catalog/hooks/completion-gate.{sh,ps1}` and `approval-capture.{sh,ps1}`: honor both runtime controls, resolve the core from the home directory only, pass stdin through, and preserve the exit code.
4. **Registration.** Catalog `Stop` and `UserPromptSubmit`, which the native adapters carry to Codex, Gemini CLI (`AfterAgent`), Qwen, Kimi, Copilot, and Devin CLI (through Claude's settings). Cursor's own `hooks.json` gains `stop` and `beforeSubmitPrompt` entries; Antigravity 2.0's gains a `Stop` entry through its bridge. Windsurf/Devin Desktop is deliberately not registered: its `post_cascade_response` cannot refuse a stop.
5. **Bridge.** `_cascade_hook_compat.py` translates a `Stop` block for Antigravity (`decision: "continue"`) and Copilot (one object carrying both the CLI's top-level fields and VS Code's `hookSpecificOutput`, since both read `~/.copilot/hooks/`). A non-blocking or failing `Stop` child now yields empty output instead of Antigravity's `ask`.
6. **Ownership-scoped merge** (`scripts/lib/integrations/_hooks_json_merge.py`) for Cursor's flat schema and Antigravity's named sets: user entries survive, malformed files are kept, a backup precedes the first change, writes are atomic, and teardown prunes only Nexus-Hub entries, restoring the pre-merge bytes when nothing else changed. Both integrations now track `hooks.json` as shared and prune it before the base teardown, which would otherwise strip Markdown markers from it.
7. **Checker.** `record create --session auto` binds the run to the session whose captured prompts contain every approval text, which is also how an agent learns its session id on platforms that never expose it.
8. **Installers** copy `scripts/completion_gate.py`. **Counts**: 37 hooks in AGENTS.md and README. **CHANGELOG** `Added` entry under the capability usage gate.

## Troubleshooting

### Kimi could not be told its format

The plan says each transformer sets `NEXUS_GATE_FORMAT`. Kimi's schema allows only `event`, `matcher`, `command`, and `timeout`, and on Windows the command's shell is undocumented, so an environment prefix could be mis-quoted. Kimi's hooks page documents `session_title` and `client_type` in every payload, which no other supported host sends, so the gate infers Kimi from the payload instead and no command is modified.

### Uninstall rewrote a user's file with different line endings

The first teardown test failed on bytes, not data: the user's `hooks.json` used CRLF and the prune wrote LF. Teardown now restores the backup's exact bytes when the pruned object equals it, and otherwise keeps the file's line-ending style.

## Plan delta

**Disposition: Incomplete** (non-blocking).

Evidence:

- The plan asks to record every inserted entry in the install manifest "by exact identity (file, event, command, marker id)". The repository's established ownership signal is a command pointing into the installed hooks directory (`_hooks_common.handler_is_owned`), which every native adapter already uses for merge and teardown. This phase reuses it for Cursor and Antigravity rather than adding a second identity scheme; the tests prove the plan's two acceptance properties (idempotent registration, byte-identical user hook after uninstall).
- "Until [the merge] applies, report the gate as NEEDS SETUP and mark the run record as degraded enforcement": the merge applies everywhere except a malformed `hooks.json`, which is kept and logged. The installer cannot mark a run record that `/implement` creates later, so degraded enforcement is not recorded in the run record.
- The plan's per-platform format list assumed an environment variable per registration; payload inference covers every platform, and `NEXUS_GATE_FORMAT` remains available as an explicit override.

Consequences for remaining phases: Phase 5's plugins call the same core in `stop` mode. The terminal CI reconciliation must add `test_completion_gate_registration.py` to an integration group.
