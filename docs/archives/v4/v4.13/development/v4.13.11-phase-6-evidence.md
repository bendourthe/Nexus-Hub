## Changes and observed behavior

The primary advisory was rechecked on 2026-10-10: GHSA-42vr-xj54-vc7v (CVE-2026-101918, PYSEC-2026-4141), affected `>= 2.0.0a1, <= 2.14.0`, patched 2.15.0, CVSS 5.3. A deeply nested payload raises `RecursionError` before signature verification; the confirmed impact is a request-level exception, not a crash or an authentication bypass.

**Dependency ownership**: PyJWT is not a direct dependency. It arrives only through `mcp`, which declares `pyjwt[crypto]>=2.10.1`, so an existing environment holding 2.14.0 satisfies `mcp` and would not upgrade. The four extensions that pull `mcp` (`nexus-code-search`, `nexus-web-fetch`, `nexus-skill-server`, and the `mcp` extra of `nexus-context-compressor`) now declare `pyjwt>=2.15.0` with a one-line security comment. `nexus-memory` and `nexus-skill-scanner` do not pull `mcp`.

**CI constraints**: the documented `uv pip compile` command, rerun with `--upgrade-package pyjwt`, changes exactly one pin in `scripts/ci/requirements-py311.txt` (2.14.0 to 2.15.1); its provenance comment now names the four floors and `mcp`. No other package moved. Receipt: [solver delta](v4.13.11-phase-6-receipts/constraints-solver-delta.diff).
