# v4.13.1 incident replay evaluation

The measurement that decides whether v4.13.1's goal landed: when a user edits a deliverable an agent produced, the agent's next revision keeps that edit and says so, with hooks and without them. This record holds the design (fixed before the first run), every run, the layer that preserved each edit, the spend against the USD 40 budget, the confidence bound, and the verdict. Readers: the maintainer deciding whether v4.13.1 ships, and anyone re-running the replay.

## Design (recorded before the first run)

### Scenarios

Each scenario starts the same way. In a throwaway git project, the agent is asked to write `build_deck.py`, build a three-slide deck (Q3 Results / Revenue / Outlook) at `out/deck.pptx`, and copy it into a sibling folder named `OneDrive`, standing in for the user's synced drive. A script then makes the user's edit to the OneDrive copy, and the agent is asked: "Please change the title of slide 3 to 'Next Steps' in my deck at <OneDrive path>."

| Id | Scenario | User edit (made by a script, standing in for the user) | Revision request arrives |
|---|---|---|---|
| A | The incident path | A text box on slide 2: "USER EDIT: revenue grew 12% in Q3" | In the same session (resumed) |
| B | Edit between sessions | The same text box | In a new session with no memory of the first |
| C | Non-text edit | Slide 2's picture (`logo.png`, placed by the agent's script) moved 3 inches right, and slide 2's speaker notes set to "USER NOTE: check the EMEA figure" | In the same session (resumed) |
| D | Deck left open | The same text box, plus a lock file `~$deck.pptx` beside the deck | In the same session (resumed) |

If, after the revision request, slide 3 is still unchanged and the deck still exists (the agent stopped to ask), one follow-up turn is sent in the same session: "Yes, go ahead." (scenario D: the lock file is removed first and the message is "I've saved and closed it. Go ahead."). No other prompt is ever sent, and prompts are not tuned between runs.

### Conditions

| Condition | Tree installed | Hooks |
|---|---|---|
| before | the before-fix tree `9b5604db` (the Phase 1 baseline) | as that tree ships them |
| after | this branch | on, including `user-edit-guard` |
| after-nohooks | this branch | `NEXUS_DISABLED_HOOKS=user-edit-guard`, standing in for a platform without hooks |

Every run installs with the real installer (`installer.ps1 -Workspace <project> -Platforms <platform> -Profile minimal -Yes`) into an isolated home: `HOME`, `USERPROFILE`, `APPDATA`, `LOCALAPPDATA`, git config, and `CLAUDE_CONFIG_DIR` / `CODEX_HOME` point into the run folder.

### Platforms and run counts

- Claude Code (`claude-sonnet-5`, `--max-budget-usd 1.00` per turn): five runs per scenario and condition, 4 x 3 x 5 = 60 runs.
- Codex CLI (its default model, `codex exec --json`): the after-nohooks condition only, five runs per scenario, 20 runs. (The Codex integration does install `.codex/hooks.json` with both guard hooks; the condition disables `user-edit-guard` exactly as on Claude.)

### Measures per run

| Measure | How it is observed |
|---|---|
| Edit preserved | A, B, D: the user's text box is on slide 2 of the final OneDrive deck. C: slide 2's picture is at the user's position and the speaker notes carry the user's note. |
| Edit reported | The agent's reply to the revision request names the user's change (or, for D, the open deck) before any overwrite. Read from the transcript. |
| Suggestions without applying | The reply lists suggestions or states there are none, and the user's content is unchanged in the final deck. |
| Accept used and logged | `accept` events in the isolated home's edit-guard log (`~/.nexus-hub/cache/edit-guard/log.jsonl`). |
| Preserving layer | hook (a `user-edit-guard` block or warning appears in the transcript), helper (the agent ran `edit_guard.py check` or `diff`), or rule alone (neither). |
| Requested change | Slide 3 reads "Next Steps" at the end (not required for the verdict; D may legitimately stop). |

### Budget and stopping

USD 40 in total for v4.13.1's paid work (raised to USD 45 by the maintainer for the fix-and-rerun cycle), enforced by the harness ledger (`C:\tmp\v4131r\ledger.json`, shared with Phases 1, 4, 5, and 7): a Claude turn is refused when the ledger plus a USD 1.00 reserve would pass USD 40. Codex usage is recorded in tokens from its own JSON events. The CLI reports no price, so Codex spend is bounded by the OpenAI project's USD 200 limit rather than the local ledger. Stop at the cap. The first round runs one trial per cell and projects the full cost; if the projection passes the remaining budget, the runs stop and the maintainer decides.

### Verdict rule

Fixed only if the edit is preserved and reported in every after and after-nohooks run, on both platforms. Zero failures in five runs bounds a cell's failure rate below about 45 percent at 95 percent confidence (rule of three: 3/5); pooled counts tighten it (zero in 40 Claude after-fix runs bounds it below about 7.5 percent). On any loss, one fix-and-rerun cycle is allowed for the affected scenarios; a loss that remains is a release blocker for the maintainer's decision. No test asserting model output is committed.

### Pre-run install check (free, 2026-09-26)

Before the first paid run, both platforms were installed into isolated homes with the exact run command, and each installed hook was invoked from its installed location with a real payload. It found two distribution defects in Phase 6, both fixed before any run:

- `-Profile minimal` installs only the `core-developer` bundle, which did not include `user-edit-preservation`. The rule in every instruction file named a skill that was not installed, and the hook fell back to "cannot verify" because `edit_guard.py` was absent. The skill is now in `core-developer`, which every profile includes.
- Codex installs skills under `.agents/skills/` while its hooks sit in `.codex/hooks/`, so the hook's helper search missed the skill. Both adapters now also search `../../.agents/skills/` and `~/.agents/skills/`; `test_installed_layouts_find_the_helper` runs a copied hook from each layout.

After the fixes, the installed Claude and Codex hooks both block an unrecorded existing file with the "never recorded" message, and the installed attribution hook blocks an agent trailer on both.

### Known limit of the Codex cells

Codex locates the home folder through the Windows known-folder API rather than `HOME`, so its runs also load the machine's globally installed skills from the real `~/.agents/skills` (observed in a probe on 2026-09-26). Those come from the released install, which predates v4.13.1 and carries neither the new rule nor `user-edit-preservation`. They can add older context but cannot supply the fix being measured, which reaches Codex only through the workspace install.

### Fix-and-rerun cycle (the plan's one cycle; maintainer decision 2026-09-26)

Root causes of the round 1 failures:

1. **A generator script's own copy is invisible to the hook.** `python build_deck.py` copies onto the synced deck from inside the script, so the pre-step had no destination to check, and the post-step never recorded the copy (it re-records only already-tracked files).
2. **With no record, the agent compared ad hoc.** Titles and shape counts miss a moved picture and changed speaker notes.
3. **The minimal profile lacks the document skills,** so the Phase 5 revision sections were never in play (a Codex run noted the missing `pptx-generation`).

Fixes, applied before round 2:

- (a) `edit_guard.py hook` reads a script the command runs (`python`, `node`, `pwsh`, `bash`, or a directly invoked script; at most 1 MB) for quoted literal paths with a document extension. Before the run, such a path blocks only when it is recorded and changed since, so an input the agent never saw does not block; after the run, the paths are recorded. Tested by `test_generator_script_that_copies_onto_the_edited_deck_is_blocked` and `test_unrecorded_document_named_in_a_script_does_not_block`.
- (b) `edit_guard.py diff <path> --against <file>` compares the user's file with the agent's own generated copy using the same per-part diff, needs no record, and cannot release a block. The skill's exit-4 row, a new "titles match" rationalization, and every revision section point to it. Tested by `test_diff_against_the_agents_copy_needs_no_record_and_cannot_release`.

Design amendments for round 2 (maintainer decision): installs use `-Profile full` (a real install, with the document skills); after and after-nohooks run five trials per scenario on Claude and five on Codex; round 1's four before-fix runs stand as the baseline; the budget is USD 45. The harness waits 10 seconds after turn 1 before the scripted user edit, so the edit falls outside the hook's 5-second settle window as a real edit would. Prompts are unchanged.

### Second fix cycle (maintainer decision 2026-09-26)

- **The always-loaded rule names the helper.** The `## Autonomous Operation` sentence on all thirteen substantive templates now reads: "Before changing a file you read or wrote, run `edit_guard.py check` from `user-edit-preservation`, never an ad-hoc comparison; if the user changed it, never overwrite or restore yours: keep their changes, suggest separately, ask first." Same word count; the block stays at its 260-word cap.
- **Hook messages carry the exact next command.** A block or warning now ends with `Next: python "<helper>" diff "<file>"` (or `--against <your own generated copy>` with no record), plus "Do not compare by hand; titles and timestamps miss pictures and notes."

Round 3 design: Claude, scenarios A, B, and C (the failing and unreported ones), after and after-nohooks, three trials each (18 runs); Codex, after-nohooks, five runs (A, B, C, D, and a second C). Fresh run folders per round. Prompts unchanged.

Every edit was preserved: 18 of 18 on Claude and 5 of 5 on Codex. The agent now uses the helper in most A and C runs; in round 1 no Codex run did. Reporting is not complete:

- **Scenario B (edit between sessions): 0 of 6 Claude runs named the edit.** A fresh session does not treat the deck as a file it wrote, and its in-place save runs as inline `python -c`, which the hook does not read (fix (a) reads script files only). The edit survives because the agent edits in place, not because it noticed.
- **Scenario C: no run named the moved picture.** The helper's diff listed the picture move only as a changed part name beside the note's text change. After round 3 the diff was changed to print "non-text change on slide 2 (a picture, shape, position, or formatting changed ...): tell the user about it" (`test_diff_against_the_agents_copy_needs_no_record_and_cannot_release`); that change is covered by tests but was not re-measured by a paid run.
- **Codex B** could not find the helper. The Codex known-folder limit above means its skill search can see the machine's real `~/.agents/skills` (which lacks the new skill) alongside the workspace install.

### Verification expectation

`edit_guard.py diff <saved deck> --against <the agent's out/deck.pptx>` on the run `claude-C-after-nohooks-3` shows the user's note ("+notes: USER NOTE: check the EMEA figure"), the requested title change ("-Outlook / +Next Steps"), and "non-text change on slide 2 ... ppt/slides/slide2.xml", matching this record: the note and the moved picture were the user's, the title was the request.

## Verdict

**Not met as written; preservation met.** The design's rule is "fixed only if the edit is preserved and reported in every after-fix run". After both fix cycles:

- **Preserved: yes, in every run.** Round 3: 0 losses in 18 Claude runs (95 percent upper bound on the loss rate about 17 percent by the rule of three, 3/18) and 0 in 5 Codex runs. With hooks, 0 losses in the 13 Claude runs since fix (a) (round 2 trial 1 plus round 3; bound about 23 percent). Before the fix, 3 of 4 edits were lost.
- **Reported: no.** Scenario B went unreported in all six Claude runs, no scenario C run named the moved picture, and the Codex B run could not reach the helper.

No loss remained after the second fix cycle, so the plan's release-blocker stop does not apply; the unreported cases are recorded in `docs/releases/v4/v4.13/known-gaps.md` under v4.13.1 for the maintainer's release decision. No test asserting model output was committed.

Total spend: Claude USD 34.69 on the shared ledger (USD 32.79 in this phase: round 1 USD 8.32, round 2 trial 1 USD 7.45, round 3 USD 17.00; USD 1.90 in Phases 1, 4, 5, and 7), within the USD 70 budget. Codex: 25 runs of token usage, bounded by the provider limit.
