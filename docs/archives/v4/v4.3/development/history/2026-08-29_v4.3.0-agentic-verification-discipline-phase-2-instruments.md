## 2. Chronological Steps

### 2.1 Implement the renderer-backed detector and proving fixtures

**Plan specification**: Render local HTML at 420, 900, and 1440 pixels; detect seven gate classes with explicit measurements; exclude deliberate hidden states; deduplicate same-element findings; provide tolerance and recorded allowlists; emit JSON on stdout and a readable summary on stderr; fail visibly when rendering cannot run.

**What happened**: Added `detect_visual_defects.py` as a lazy-Playwright bundled script plus a committed clean page, seven isolated broken pages, a same-element dedup page, and 18 focused tests. The detector blocks network routes, loads only the local file, validates allowlist selectors, produces stable escaped selectors, distinguishes input errors from renderer-unavailable states, and returns exit 0 for a clean page, 1 for findings, 2 for invalid input, and 3 when Playwright or Chromium cannot run.

**Review finding and correction**: The first implementation classified every ancestor containing descendant text as text-bearing, which would have reported the rule's explicitly allowed primary responsive container. The final classifier mirrors the hook: direct media is exempt; semantic text tags, direct text, and text-name tokens are gated; text evidence wins over a container-like name; structural descendant-only wrappers are exempt. The clean fixture now contains `.page-container { width: 100%; max-width: 1200px; }`, while `p.copy-container` remains a finding.

**Key files changed**: `catalog/skills/testing/functional-verification/scripts/detect_visual_defects.py`, `tests/verification/test_visual_defect_detector.py`, and nine fixtures under `tests/verification/fixtures/visual/`.

**Verification**: The focused suite passed 18 tests in 16.43 seconds; Ruff and Python compilation passed; a real three-viewport clean invocation returned exit 0 with zero findings; a fixed-text page returned exit 1 with exactly `fixed-text-max-width` at `#fixed\:max`.

### 2.2 Add the responsive-layout rule and paired pre-write guard

**Plan specification**: Define the HTML responsive-layout policy, block fixed `px` or `ch` text caps in Write/Edit payloads, preserve breakpoint and bounded-container/media allowances, fail open on irrelevant or malformed input, honor the documented session escape, register only the Bash hook, and prove Bash/PowerShell parity.

**What happened**: Added the canonical rule, Bash hook, PowerShell sibling, Write/Edit registrations, 40 dedicated dual-shell behavior cases, and the explicit parity and Cursor-import list entries. The hook reads only JSON stdin, extracts `content` or `new_string`, strips CSS comments, distinguishes `@media (max-width: ...)` conditions from declarations, names the declaration, file, and rule on stderr, exits 2 on a block, and exits 0 for malformed, disabled, minimal-profile, absent, irrelevant, container, and media cases.

**Review finding and correction**: The first classifier allowed a target containing both text and container tokens because the container allowance ran first. The final classifier gives text evidence precedence, so `p.container` and `.copy-container` block while direct media such as `img.caption` remains allowed. A nested `@media` rule with a fixed text cap blocks; a breakpoint-only condition remains clean.

**Key files changed**: `catalog/rules/html/responsive-layout.md`, `catalog/hooks/html-responsive-guard.sh`, `catalog/hooks/html-responsive-guard.ps1`, `catalog/hooks/settings.json`, and the three affected hook test modules.

**Verification**: The retained independent hook run passed 363 tests in 198.93 seconds. Bash parse, PowerShell AST parse, settings JSON parsing, ShellCheck, executable-mode preservation, and diff checks passed.

## Plan delta

**No blocking delta**: implementation confirmed the plan's seven defect classes, false-positive controls, exit-code contract, hook parity requirement, and existing CI path coverage. The only durable clarification is that the detector and hook share the same text-evidence precedence so an allowed primary container cannot become a detector false positive while a text element named `container` cannot evade the rule.

## 6. Assumptions Made

- **Allowed primary container**: A structural wrapper with descendant-only text and a container/media name is the rule's allowed responsive container; semantic text tags, direct text, and text-name tokens remain gated even when their names also contain `container`.
- **Optional renderer in CI**: Browser-backed cases skip under the existing CI dependency set, while the detector's own missing-renderer path returns nonzero and an install hint. No CI browser download was added.
- **Make substitution**: The canonical CI profile is authoritative when GNU Make is unavailable because the Makefile itself delegates to the same repository-native command families and the profile adds the required local-source isolation.
