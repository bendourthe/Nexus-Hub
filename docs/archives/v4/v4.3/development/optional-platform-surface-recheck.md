# v4.3 WN-3 Optional Platform Surface Recheck

This is a targeted source recheck for the maintainer of the v4.3 optional-platform gap, completed 2026-09-24. It is not a full release-time platform-contract pass, a live Antigravity or Nexus-AI host test, or a re-stamp of the v4.13.0 read contract. The original v4.3 finding stays in the active known-gaps ledger.

| Surface | Current evidence | Bounded verdict |
|---|---|---|
| Antigravity CLI global and workspace hooks | [Google's hooks reference](https://antigravity.google/docs/hooks?tab=cli) names `~/.gemini/config/hooks.json` and `.agents/hooks.json` as CLI read paths. Nexus-Hub's `Antigravity20Integration` already writes that global config and workspace registration; its global dry-run test now asserts the shared config path. | Source-qualified path; no CLI runtime smoke was run. No separate CLI-only hook directory is needed or claimed. |
| Antigravity CLI loose workflows and agents | [Google's workflow-to-skills migration guide](https://antigravity.google/docs/migration/workflows-to-skills/) names legacy workflow paths, but does not establish that the `agy` CLI reads loose workflow files at the installer's proposed global location. Current CLI skills and shared instructions remain the delivered fallback. | UNVERIFIED; no new loose files emitted. |
| Cursor legacy commands | The old [commands URL](https://docs.cursor.com/en/agent/chat/commands) now redirects to the current [skills page](https://cursor.com/help/customization/skills), which describes migration of user and workspace commands but does not name the legacy command directories. Nexus-Hub emits command-skills through the verified skills path. | Both `~/.cursor/commands` and project `.cursor/commands` remain UNVERIFIED compatibility writes. |
| Gemini Code Assist IDE add-on surfaces | [Google's agent-mode guide](https://docs.cloud.google.com/gemini/docs/codeassist/use-agentic-chat-pair-programmer) documents the `GEMINI.md` context hierarchy, not IDE-specific discovery for the extra skills, workflows, agents, rules, or hooks mirrored by Nexus-Hub. This is distinct from Antigravity IDE and Gemini CLI. | Extra IDE destinations remain UNVERIFIED; `GEMINI.md` remains the verified instruction surface. |
| Nexus-AI global skills | At public main commit [`198ff9c8`](https://github.com/bendourthe/Nexus-AI/commit/198ff9c877f258c775092761e3c67a6bed56b1d2), [storage paths](https://github.com/bendourthe/Nexus-AI/blob/198ff9c877f258c775092761e3c67a6bed56b1d2/core/storage/paths.ts) define `~/.nexus-ai/catalog/`, the [CLI entry](https://github.com/bendourthe/Nexus-AI/blob/198ff9c877f258c775092761e3c67a6bed56b1d2/desktop/sidecar/src/cli/hubCatalogCli.ts) defaults to that root, and the [reader](https://github.com/bendourthe/Nexus-AI/blob/198ff9c877f258c775092761e3c67a6bed56b1d2/desktop/sidecar/src/skills/hubSkillReader.ts) resolves its `skills` subdirectory and `SKILL.md` files. Nexus-Hub's integration writes there. | Global skills read path is source-qualified. Project-local `.nexus-ai/catalog/` consumption and other mirrored surfaces were not traced; no live app smoke was run. |

The earlier assertion that Nexus-AI has no publicly auditable source is superseded only for the global skills path above. WN-3 stays open for every `UNVERIFIED` row. No installer destination or host setting changed in this recheck.
