## Subtasks

- **4.1 Present mode fills the viewport** (T015): rebuilt `.nht.is-present` as a full-height flex column - the bar and loop strip sized to content, the slide growing to consume the rest, the booth and terminal stretching inside it, and the takeaway and controls pinned at the bottom. Headings scale with the viewport. Measured live: the slide now occupies 823 px of a 900 px viewport, against a small centred block before.
- **4.2 Plain-language progress** (T016): the counter no longer reads "step 2 / 8 . beat 1 / 2". It reads `Understand . 1 of 8 . /describe full` - the stage name from the scene data, a simple position, and the command. The eight anonymous progress bars became labelled loop stages: each segment carries its command name, marks the current one with `aria-current="step"` plus a distinct treatment, dims completed ones, and is clickable to jump. The word "beat" no longer appears anywhere in the UI; it survives only as the underlying mechanism and in the `?beat=n` URL grammar, which is a compatibility contract.
- **4.3 Bottom-right icon controls** (T017): Previous, Next, and Restart moved out of the top bar into a right-aligned cluster below the takeaway, as icon buttons with `aria-label`, `title`, and a visible focus ring. Outline keeps a text label because a glyph does not carry its meaning. Verified after the DOM move that the icons still advance, that a loop segment jumps, and that Escape still exits present mode.
- **4.4 Graphics defects and illustration** (T018): the terminal command line adopts the shared invocation convention, so `/test` renders in accent and `unit` in plain ink while the copy payload stays the whole string. Three defects fixed: the terminal echoed the command a second time under a prompt line that already showed it (now a brief "working" line that yields to the reply); the reserved-but-empty output area now explains what will appear there and hides that placeholder once a command runs; and the booth stage in present mode was an over-tall empty box, now bounded by `clamp(180px, 30vh, 300px)`.

## Leftover width caps found and removed

Phase 1 removed the `--measure` token, but three `ch`-based caps survived it (`.nht-intent`, `.nht-takeaway`, `.fx-copy h2`) and were visible in present mode as a takeaway rule that stopped at 45% of the width. All three are gone; the headline one became `text-wrap: balance`, which shapes wrapping without imposing a measure. A new test now fails on any `max-width` in `px` or `ch` other than the present-mode stage bound.

That test needed one correction of its own: the first version matched `@media (max-width: 720px)` breakpoints and reported five false offenders. Tightened with a negative lookbehind so it only sees declarations.
