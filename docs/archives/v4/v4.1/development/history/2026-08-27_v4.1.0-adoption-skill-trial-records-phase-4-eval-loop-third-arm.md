## 2. Implementation

### 2.1 Optional third condition

`skill-eval-loop` accepts an optional eval-entry `raw_memory` path. A readable source creates `raw_memory/` beside `with_skill/` and `without_skill/`, reuses the same dispatcher, CLI, model, settings, query, and assertion grader, injects the notes verbatim, and records `skill_loaded: false` plus `memory_injected: true`. Missing or unreadable input creates no directory and requires `raw_memory: "not_run"`; the protocol forbids reconstructing notes or calling a hosted judge.

Terminal convergence review on 2026-08-28 found that the Phase 4 commit documented that dispatch but did not expose an executable creation path. Phase 6 corrected it by adding `--run-raw-memory --iteration-dir` to the existing optimizer executable. The command resolves sources relative to `evals.json`, dispatches without a skill overlay, and writes the response and metadata before the unchanged grader step.

### 2.2 Backward-compatible aggregation and review

`scripts/aggregate_benchmark.py` preserves every two-arm field and with-vs-without delta. Terminal review also found that directory presence alone was being treated as a completed run. Phase 6 now validates grading, flags, timing, tokens, exit status, and shared CLI identity; invalid artifacts are labeled and excluded. `scripts/skill_eval_viewer.py` keeps the existing two outputs and adds a responsive third column and summary only when raw memory is present.

### 2.3 Blind comparison

The comparator retains its exact A/B verdict contract for two-arm workspaces. Three-arm workspaces shuffle A/B/C outside the comparator's context, return a blinded ranking and best label, and unblind only after the verdict is written.
