## 2. Implementation

### 2.1 Outcome-annotated evidence

`continuous-learning` and `skill-create` now require every evidence item to carry an explicit `success` or `failure` label before it enters an instinct or skill draft. Mixed sets with an unlabeled item list the item and stop until the user labels or drops it. Git history is named as success-biased, and skill drafts require a real failure from a revert, follow-up fix, or user-supplied counterexample. All judgment stays in-session and local.

### 2.2 Bounded semantic confusability

`skill-stocktake` now uses trigger-noun buckets rather than a catalog-wide all-pairs scan. Quick Scan compares changed skills inside their category; Full Stocktake starts with low-scoring skills plus descriptions sharing two nouns. A named cross-category watchlist covers anti-slop, unknown/boundary, and cleanup vernacular. The report is advisory and proposes only description or `SKIP` repairs.

### 2.3 Two-level triggers

`skill-description-authoring` now requires Level 1 category/domain language plus a Level 2 strict observable, while retaining pushy synonyms, trigger nouns, confidence bands, and `SKIP` fences. It also requires nearby same-category skills to remain useful partial runbooks because exact intended invocation is neither sufficient nor necessary.
