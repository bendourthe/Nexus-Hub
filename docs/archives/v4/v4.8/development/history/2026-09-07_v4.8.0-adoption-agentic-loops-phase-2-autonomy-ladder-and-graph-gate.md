## Verification Expectation (functional smoke, gate 5)

### Functional exercise - the competitive-landscape example through Step 0 and the checklist

- **Revision**: `feat/v4.8.0-agentic-loops`, working tree after T007 to T010.
- **Artifact and boundary**: a decision procedure whose consumer is an agent or operator reading Step 0 and the checklist and landing a described task on a rung. The real boundary is that reading, so the exercise extracts the exact doctrine cells that decide the landing rather than paraphrasing them.
- **Command or action**: extract the Graph and Single-goal-loop "Fits when" cells from the Step 0 table, the Step 4 gate-condition sentence, and checklist item 1; then land the plan's example on a rung using only that text.
- **Input, case A**: the plan's competitive-landscape example, as stated: 12 research cycles, 6 parallel workers, a human gate on publication.
- **Input, case B**: the same example with one worker.
- **Expected contract**: case A reaches "graph" only after checklist item 1 is answered; case B lands on "single goal loop".
- **Observed doctrine text**: the Graph rung's cell reads `A single loop has a MEASURED limitation that multiple bounded nodes fix.`; Step 4 reads `the gate is passed only once [references/graph-readiness-checklist.md] is complete: all eight items true, with the first one (a measured single-loop failure mode) answered rather than predicted.`; checklist item 1 reads `A single loop has a **measured** failure mode that the graph fixes. Not a predicted one.`
- **Observed landing, case A**: not graph. The example supplies 6 workers as a design given, not as a measured single-loop limitation, so the Graph rung's own "Fits when" is unsatisfied and Step 4's gate cannot be passed. Minimum sufficient autonomy then selects the highest rung actually justified, which is single goal loop: an explicit verifier and budgets exist, and the publication gate is a `gates` entry the loop schema already supports without a graph. Once a measured single-loop limitation IS produced, Graph becomes reachable, subject to the remaining seven items.
- **Observed landing, case B**: single goal loop, reached directly. With one worker there is no parallel work package, so "multiple bounded nodes" has no referent and Graph is unreachable rather than merely ungated.
- **Comparison**: matches for both cases.
- **Environment**: Windows 11, CPython 3.12, Git Bash.
- **Delegates**: procedure owned by [[functional-verification]]; record handed to [[verification-before-completion]] and [[quality-gate-definitions]]. No finding, so nothing escalated.
- **NOT COVERED**: none.

The two properties this observation depends on are also held mechanically, so the exercise cannot silently stop being true: `test_checklist_first_item_requires_a_measured_not_predicted_failure` and `test_step_4_cites_the_checklist_as_the_gate_condition`.
