# v4.5 DF-2 Shared-Writable-Service Inventory

This is a bounded, read-only inventory of write-capable surfaces shared by the local agent sessions and this repository's GitHub Actions runs. It is for the maintainer deciding whether the isolation guidance can be applied to Nexus-Hub's own development environment. Observed at 2026-09-24 19:51 UTC; service counts can change. It is not an exhaustive host-wide write trace or proof of per-session isolation.

| Surface | Writers and readers in scope | Observed boundary | Result |
|---|---|---|---|
| Main repository checkout and its `.nexus/` state | Multiple Codex and Claude processes run under the same Windows user and can address the same checkout; another session's untracked `CONTEXT.md` is present. | No per-session filesystem boundary. Isolated Git worktrees reduce index collisions but do not prevent a session from reading or writing the shared checkout. | Shared writable channel; fails the skill's write-scoping and read-back-denial minimum. No file contents were read. |
| User-scoped `~/.nexus-hub/cache` | The installed cache directory exists. `nexus-skill-server` defaults there, and the context compressor defaults to a database under that cache. Multiple same-user local sessions can use the path. | No per-session cache root, write prefix, or cross-session read denial was observed. The audit did not inspect cache contents or trace individual writes. | Potential shared channel; isolation unverified. |
| User-scoped nexus-memory store | `nexus-memory` defaults to `~/.nexus-hub/memory` unless `NEXUS_MEMORY_ROOT` overrides it; the override is unset and the default directory is absent on this host. | Configured surface, not an observed live store. | Not counted as an active writable channel; recheck if enabled. |
| Repository code-search index | `nexus-code-search` defaults to `.nexus/code-index` under a target root; that directory is absent in the main checkout at this check. | Per-root path, but no session-specific namespace if two agents index the same root. | Latent shared channel; not observed active here. |
| GitHub Actions caches | The repository API returned 75 cache entries. `ci.yml` and `presentify-extractor.yml` use `actions/cache` for the Playwright browser download. | GitHub scopes pull-request writes to the PR merge ref, which prevents sibling PRs from restoring that entry, but PR runs can restore base/default-branch caches. This is branch scoping, not universal read-back denial between all runs. | Partly scoped; keep cache contents non-secret and treat restored bytes as untrusted. No cache payload was downloaded. |
| GitHub Actions artifacts | The repository API returned 411 artifacts. Several workflows upload report bundles to GitHub's artifact store. | Artifact names and runs separate writes; read access follows repository permissions, not a per-agent secret namespace. | Shared repository service; no cross-session confidentiality guarantee was established. No artifact payload was downloaded. |

The cache behavior above follows GitHub's [dependency caching reference](https://docs.github.com/en/actions/reference/workflows-and-actions/dependency-caching). Package registries are read-only dependencies in the inspected workflows, not observed shared write targets. This list deliberately excludes unknown host services and any remote runner service the repository configuration cannot enumerate. No service in this inventory was changed or deleted.

## Required disposition

DF-2 remains open. A complete service inventory needs an executor and credential boundary for each agent session, plus a write trace or administrator inventory of the local host and any CI runner services. For every shared service, the skill requires write-scoping and cross-session read-back denial, or removal of the shared write path. The current local checkout fails that test outright; a documentation-only closure would be false.
