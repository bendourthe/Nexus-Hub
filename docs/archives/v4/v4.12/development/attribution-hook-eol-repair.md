# Attribution hook source line-ending repair

**Purpose**: Record the v4.12 BG-3 follow-up found while removing the installer worktree. Read this with the original [hook lifetime repair](attribution-hook-lifetime-repair.md) before closing the shared-hook gap.

After PR #249 passed 24 hosted checks with one intentional skip and merged at `fcaab352`, post-merge run 35838028055 passed smoke and provenance. Its installer worktree was removed. The installed copy in the shared Git directory still passed its integrity check and rejected a forbidden attribution trailer. A second worktree rebased onto the merged code then failed `scripts/nexus_git_attribution.py check` with `Attribution guard version differs`. Git reported that source as `i/lf w/crlf`: it had the same repository content but a CRLF checkout, while the installed copy came from an LF checkout. Reinstalling from every worktree would merely move the mismatch.

The new regression parameterizes both LF-to-CRLF and CRLF-to-LF transitions after workspace installation. Both cases failed before the fix with the observed version error. The source freshness comparison now normalizes only CRLF line terminators before comparing the source to the installed copy. The installed copy is still checked byte-for-byte against the SHA-256 recorded at installation, so an altered executable cannot pass by changing line endings or content after installation. The pre-existing changed-source and tampered-copy regression remains in the focused control set.

The focused two-way and tamper/removal controls passed 4/4 after the fix. The complete attribution module passed 47 tests with one host skip in 549.40 seconds. Ruff passed for the changed script and tests; the fast profile passed 17/17 and docs passed 8/8. The distribution handbook rebuilt deterministically at SHA-256 `25ffd7b98de194f81f0a33035b4b184546c394214843318bec54573a2d22efb5`; Chromium measured all 200 reading and presentation states with zero errors, and the ownership views were visually checked at 1440 by 900 and 761 by 900. The read-only handbook freshness gate passed for both living handbooks. The repaired guard was installed into the shared Git directory and `check` passed from this worktree.

**Boundary**: This change does not accept a changed Python source program, bypass a hook, or alter commit and push policy. The distributed handbook's ownership explanation and its retained source now name the LF/CRLF behavior. Hosted, post-merge, and final worktree cleanup evidence will be recorded after publication; this document is not a completion claim.
