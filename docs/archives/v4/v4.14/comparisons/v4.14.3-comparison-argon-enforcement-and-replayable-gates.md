## Section 1: Executive Summary

**Argon is a records update first, then a recommendation update.** Nexus-Hub's routing snapshot (`catalog/skills/ai-development/model-routing/references/last-known-model-map.json`) still names `gemini-3.8-flash` as Google's frontier cell. Since a 2026-10-12 judgment it also names `gemini-3.8-flash` at strong, so both cells hold one model. `gemini-4-argon` is now listed as Stable on Google's model page. It belongs at frontier, which un-collapses the 2026-10-12 judgment. `model-prompting-research` has no `gemini-4-argon` profile. The Argon guidance differs materially from the Gemini 3.x family-level claims those profiles carry:

- `thinking_level` replaces `thinking_budget`; the levels are low, medium (the default), and high.
- Sampling parameters are ignored, and some penalty parameters return HTTP 400 on Cloud.
- Thinking tokens count against `max_output_tokens`.
- Caching is implicit only.

**The anti-slop article's thesis is "a lint rule beats a skill", and Nexus-Hub's own repository already proves it.** The repository runs dozens of validators. In the catalog it distributes, the promotion step is only half present. `review-trapdoors` Step 5 promotes a recurring blocker into a checklist line, and it proposes an automated check only "if the list grows past ~15 entries", for "the lowest-frequency ones". So promotion is triggered by list size, not by whether the blocker is mechanically detectable. It does not require the check to name the fix, and it does not retire the checklist line once the check is green. The adoption refines that existing rung; it is not a new skill.

**The decision toolkit's most valuable idea is a separate UNGATED result.** In S4, a run with no requirements is `UNGATED`, which is explicitly not a pass. `quality-gate-definitions` has no such result; only `verification-before-completion:78` names "missing evidence". A second, smaller adoption makes a gate verdict recomputable from what the record stores.

**wshobson/agents is mostly already covered or already queued.** Per-agent model pinning is v4.14.0 Phase 2, and the per-tool capability matrix is `docs/policy/platform-read-contracts.json`. One finding is new and was checked against the vendor's own source. Codex truncates skill prompts at 8,000 bytes (`MAX_SKILL_PROMPT_BYTES`, `openai/codex` `codex-rs/ext/skills/src/render.rs:21`). That truncation applies on the host path only to plugin skills (`host_prompt.rs:79`), and on the extension path to every skill (`extension.rs:473`). Nexus-Hub installs plain user skills to `~/.agents/skills`, so the host path does not truncate them today. 275 of 340 Nexus-Hub SKILL.md files exceed 8,000 bytes, so this is a contract item to record and re-verify, not a live defect.

**Recommended: five items. None adds an outbound call, a credential, a runtime dependency, or a third-party data processor.** Nine candidates are explicitly declined (Section 8). A sixth candidate, stale-approval detection for `/implement`, was dropped during planning: the run record already freezes the plan's hash (insight 4.9).

## Section 6: Risks and Conflicts (Step 7)

- **A, Argon in the frontier cell.** Changing the cell changes what every new `/plan` resolves for Google-hosted work, which is the intended effect. The risk is a profile that copies a Gemini-3.x claim ("keep sampling at defaults") onto Argon, where the guidance is "remove them". Scope each claim to its model.
- **B, overlap with v4.15.0 `instruction-necessity-review`.** That plan decides which AGENTS.md rules are still necessary; B gives such a review a "convert to a check" verdict. If v4.15.0 has not landed, B states only the skill rung and records the handoff gap. It does not define v4.15.0's verdict vocabulary.
- **C2 versus v4.14.2's `decision-policy-harness.md`.** v4.14.2 deliberately stores hashes, not raw tool inputs. C2 applies only to quality-gate verdicts, whose inputs are counts and thresholds, and must not extend recomputation to tool-call decisions.
- **D, hook logic change.** This is an AGENTS.md ask-first boundary. The flags have legitimate uses, so the hook asks for confirmation rather than blocking.
