# v4.14 Implementation Progress Reporting

Summary: v4.14 command-instruction addition for periodic implementation reports, read-only status requests and efficiency reviews. Release coordinators use this record to integrate the change and distinguish local contract verification from live editor delivery.

## Scope

The user approved hourly progress reports, on-demand status and efficiency reviews on 2026-10-26. The isolated branch is `feat/v4.14-progress-reports`, based on integration commit `017ec82a2`. This change does not advance any existing release-plan task marks or change signed run records.

The shared contract is [progress-reporting.md](../../../../../catalog/skills/workflow/implement-phase/references/progress-reporting.md). Both command dispatchers and the implementation skill/runbook link to it. It reuses `plan_status.py` for task counts and existing coordinator observations for worker activity and timing. No timer service, dependency, installer change or new task-state store is added.

## Usage

- `/implement v4.14` reports every member plan; a specific plan invocation reports every phase. The default consolidated cadence is 60 minutes plus significant transitions. A user may request a different interval in ordinary language.
- `/update status` reports the current run. `/update status v4.14` selects the minor; `/update status v4.14.2` selects a plan. Plan paths and slugs are also accepted.
- Status requests are read-only and never start/resume a run, spawn workers, run tests, change files or publish. Ambiguous or missing targets are surfaced rather than guessed.
- Each report shows checked/total tasks and percentage, active/waiting workers, wall time, remaining-time range, dependencies, progress since the previous report and next work. Unknown or stale observations are explicit. Task progress does not establish release completion.
- Active coordinators review safe parallel capacity and test timing. Existing admission, isolation, spend, focused-validation and final-validation gates remain authoritative. Status-only efficiency suggestions are advisory.

## Review

| Scenario | Required disposition |
|---|---|
| Minor run with completed and waiting members | Retain every member row; separate task progress and release state |
| Specific plan | Include every phase, including not started and completed |
| Zero-task phase | N/A percentage, never divide by zero or claim 100% |
| Unequal plan sizes | Aggregate checked/total counts, not mean percentages |
| Worker unavailable or old observation | Unknown/stale with timestamp, never infer liveness from a branch |
| No recorded start or resumed session | Unknown or observed-this-session-only elapsed |
| External dependency without duration | Unknown end-to-end ETA or explicitly conditional range |
| Inputs still changing | Defer broad checks with task IDs and final trigger; retain required focused checks |
| No timed host callback | Best-effort checkpoint report with actual timestamp and missed interval |
| On-demand request during implementation | Return observations without mutating or interrupting the active run |

These are inspected instruction dispositions, not measured model-compliance results. No separate test is added that merely asserts the new prose repeats itself.
