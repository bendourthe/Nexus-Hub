# v4.14.0 Native Hook Budget Proposal

The Windows PowerShell 5.1 hook corpus has an observed 1800.937-second timeout and a complete 2588-test pass in 1776.969 seconds. This proposal raises that command cap to 2400 seconds, retaining the same tests and the enclosing 60-minute job limit.

## Evidence

- The unfiltered Windows platform profile completed with 11 commands passed and one hook-command timeout. The timed-out capture has no final test verdict.

- A separate serial diagnostic completed all 2588 hook tests in 1773.58 seconds; canonical-runner duration was 1776.969 seconds. All 8259 source files were unchanged. Its private 2700-second diagnostic allowance does not establish a canonical platform profile pass.

- The candidate configuration passes all 205 existing CI engine tests in 55.88 seconds. Comparing all five loaded profile definitions finds exactly one changed field: `/platform/windows-hooks/commands/0/timeout`. These are bounded candidate checks; forks still read unchanged repository files.

## Decision

Keeping 1800 seconds retains an observed timeout and only 23.031 seconds of measured headroom in the complete serial pass. Raising the command cap to 2400 seconds supplies bounded timing margin for this corpus. A hung command can wait at most 600 additional seconds; the job remains capped at 60 minutes. No workflow trigger, job, permission, secret, package, required check or test selection changes.

Recommendation: approve the one-field 2400-second candidate. Application has not occurred. No new blocker or approval is implied by this document.
