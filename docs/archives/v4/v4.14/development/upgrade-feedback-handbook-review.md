# Distribution Handbook Claim Review - Upgrade Feedback

**Covers**: why the distribution handbook needs no content change when `nexus-hub upgrade` gains a short what's-new summary and visible bootstrap output, and the evidence behind refreshing its input digests for `scripts/nexus_hub_cli.py` and `scripts/nexus_process.py`.

The change has three parts. In `scripts/nexus_hub_cli.py`, `extract_changelog_section` is replaced by `summarize_changelog`, which prints one line per top-level changelog entry for every release newer than the installed one, and `run_bootstrap` now starts the install bootstrap through `run_in_current_console`. In `scripts/nexus_process.py`, `run_in_current_console` is added as the one sanctioned exception to the no-window default: it shares the current console only when the process owns a visible console window and both stdin and stdout are terminals, and otherwise falls back to a normal windowless launch. `install.ps1` and `install.sh` print the archive size and the downloaded size with elapsed time; neither file is a handbook input.

The handbook claim this touches is one sentence in `docs/handbooks/_sources/distribution/source.md`: both installers distribute `nexus_process.py` beside native commands, and its Windows subprocess default hides console children and preserves output. That sentence stays true. `install_no_window_default` is unchanged, and every launch that does not call `run_in_current_console` still receives `CREATE_NO_WINDOW`, with `DETACHED_PROCESS` and `CREATE_NEW_CONSOLE` still rejected. The new function is not a second default: it takes no stream, flag, or capture options, it runs only for the upgrade bootstrap, and it applies only on a host where the person is looking at the console. A hidden launch there would send the bootstrap's own output and any prompt to a console nobody can see. No other handbook sentence or composition fragment mentions the upgrade command, the what's-new text, or download progress, so no handbook text or rendered output changes.

Only the two input digests in `docs/handbooks/_sources/distribution/evidence.json` are refreshed, and this record becomes the content check's evidence. No new browser run is claimed because the handbook output is unchanged.
