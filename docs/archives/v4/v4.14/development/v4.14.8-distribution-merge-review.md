# Distribution Handbook Merge Review

This record covers the distribution handbook after `develop` (at `b4ba7209c`, with the usage-answer repair) was merged into the v4.14.8 candidate (final-phase commit `294a0a72a`). Each side had its own reviewed evidence for this handbook; the merge combines their inputs, so neither recorded snapshot matched. This review states which claims each earlier review covers and what the merge adds.

## Content

Only `develop` changed the handbook itself: `model.json`, `source.md`, `design.css`, the generated `distribution.html` and its build receipt, and the manifest entry that adds `catalog/hooks/usage-guard.py` as a reviewed code input. The merge takes those files unchanged from `develop`, so the [usage-answer review](usage-answer-handbook-review.md) still covers every handbook sentence and the rendered output.

The merged code inputs relate to the two reviews as follows:

- `scripts/nexus_git_attribution.py` is the v4.14.8 version; `develop` did not change it. The [v4.14.8 source review](v4.14.8-distribution-source-review.md) covers it: the change is limited to tagged diagnostics and escaped echoed values, and the identity, digest, history-scan and hook-preservation behavior the handbook describes is unchanged.
- `scripts/nexus_hub_cli.py` and `scripts/lib/integrations/cursor.py` are the `develop` versions; v4.14.8 did not change them. The usage-answer review covers them.
- `catalog/hooks/usage-guard.py` combines both sides. `develop` added submitted-answer capture and the `usage status` / `usage decide` recovery path, which the usage-answer review covers. v4.14.8 added the `[Nexus-Hub: usage-guard]` tag and the escaping of echoed values. Those are message-format changes only; they change no decision, file the guard reads or writes, or recovery command. The handbook names the recovery commands and the persistence check, not the message text, so no claim depends on the tag. One merge correction followed: the recovery path's error print, added by `develop` after v4.14.8 tagged the hook, now goes through the hook's tag emitter with escaping, as the hook-message decision requires. It still returns exit code 1 with the same error text after the tag; the source-label, usage-guard and integration tests pass on the merged file.
- The installers, `runner.py` and `catalog/style-guides/git-attribution.md` are identical on both sides.

## Build and rendered evidence

The handbook output is byte-identical to the `develop` output the usage-answer review built twice and verified in Chromium at eight viewports, so its build and rendered receipts remain valid and no new browser run was made. The snapshot in `docs/handbooks/_sources/distribution/evidence.json` is refreshed to the merged inputs with the checker's own `snapshot()` function, and the content check points at this review.
