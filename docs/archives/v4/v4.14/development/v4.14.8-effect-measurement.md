# v4.14.8 Effect Measurement (DoD 10)

Before-and-after measurement of the v4.14.8 instruction-template changes on Claude Code: 10 fixed prompts, one headless run each against the pre-plan templates (`origin/develop` base `8d055f2f1`) and the Phase 4 templates, in two isolated scratch projects with the catalog hooks registered. Read this when deciding whether the plain-English wording and the `[Nexus-Hub: <source>]` label rule changed what the agent writes, when reconciling the DoD 10 known gaps, or when repeating the measurement after v4.14.6 tags `git-guardrails`. Key topics: setup and isolation limits, the 10 prompts, per-prompt results, the two targets (slang findings; label correctness) with a met or missed verdict each, and the proposed known gaps.

**Date**: 2026-10-30. **Plan**: [plain-english-replies-and-source-labels](../plans/v4.14.8-plain-english-replies-and-source-labels.md), sub-task 4.7 (T031). **Result in one line**: both targets missed as stated. Slang findings were 0 before and 0 after (a floor effect, so no reduction could show), and the new templates produced a correct label on 7 of 10 checks against a target of 8 (the old templates: 5 of 10, all of them the five no-label prompts). Single run per prompt; indicative, not proof.

## Setup

- **Harness**: Claude Code CLI 2.1.283, headless `claude -p`, model `claude-opus-5-5` (the signed-in account's default) in all 20 runs. No API key: `ANTHROPIC_API_KEY` and every `CLAUDE*` variable were removed from the child environment so the nested CLI used the maintainer's existing login and did not inherit the parent session.
- **Two scratch projects** under the system temp folder (`%TEMP%\nh-measure\old-proj` and `new-proj`), each a fresh `git init` on branch `work` with no remote, seeded with the same tiny Python "order tool" (`app/config.py` with `TIMEOUT = 30`, `app/service.py` with a `validate_order` check, a `data/` folder of three CSV files, a CHANGELOG, one test) and one uncommitted refactor of `app/service.py` (coupon helper extracted; `total()` no longer validates).
- **Instruction text**: the rendered body printed by `bash scripts/installer.sh --print-config claude` in each tree, written as the project `CLAUDE.md` (553 lines old, 554 new). The old body carries "plain language a non-engineer follows" and no label bullet; the new body carries "simple English a non-native reader follows at first read", the slang clause, and the label bullet exactly once.
- **Hooks**: each tree's `catalog/hooks/` copied to `<project>/.claude/hooks/`, and a project `.claude/settings.json` registering `session-start` (SessionStart) and, on PreToolUse, `format-bash-description.py` and `require-description.sh` (Bash), `git-guardrails.sh` (Bash|PowerShell), `secret-scan.sh` (Write|Edit), `large-file-guard.sh` (Write). The old project ran the untagged pre-Phase-3 hooks; the new project ran the Phase 3 tagged hooks, except `git-guardrails`, which is untagged in both (pending v4.14.6).
- **Flags**: `--output-format stream-json --verbose --setting-sources project --no-session-persistence --max-budget-usd 1.50 --allowedTools <per prompt>`. Permission mode was the default; `--dangerously-skip-permissions` and `bypassPermissions` were not used. A tool call outside the allow list was denied by the harness and the denial text reached the model.
- **Scoring**: `engineering-slang` findings from `detect_prose_cliches.py --json` (the Phase 1 detector from this branch) on the final reply text; a label counts when the reply's first line matches `[Nexus-Hub: <source>]`; a label is correct when it names the expected source on an event prompt (P01 to P05) or is absent on a slang prompt (P06 to P10). A run with no reply, a non-zero exit, or a prompt whose intended event was never reached is recorded as "no result" and never counted as a pass.
- **Budget**: 20 measurement runs plus 1 debug run (isolation check), USD 19.65 in total; the three remaining debug runs were not needed.

### Isolation achieved and not achieved

| Surface | Result |
|---|---|
| User settings and hooks (`~/.claude/settings.json`) | Excluded by `--setting-sources project`: only the project `session-start` banner appeared at session start, none of the globally installed Nexus-Hub v4.14.4 hooks fired. |

| User-level `~/.claude/CLAUDE.md` and `~/.claude/rules/*.md` | **Not excluded.** The debug run listed the user's `CLAUDE.md` (which carries the installed Nexus-Hub v4.14.4 instruction text, including the pre-plan Communication Contract and Writing Discipline) and 13 rules files in context. Both runs therefore also saw the old wording from the user level; the new run saw old and new wording together, with the project text more specific. No CLI flag excludes user-level memory without also moving the config directory, which would have required copying login credentials into a scratch location; that was not done. |
| Enterprise or managed settings | Not controlled; none are known to be present. |

The leak weakens the slang half of the measurement (the old wording was present in both runs) and leaves the label half mostly intact (the label bullet exists only in the new project text).

### Notes on the event prompts

- **P01 and P03 (new)**: the label named the right hook, the reply quoted the hook's own message (without the tag, which the harness had already shown as `[Nexus-Hub: secret-scan]` in red), explained it in plain words (a pre-write hook is "a script that runs automatically before each file write"), did not try to get around the guard, and closed with Completed / Verified / Open / Next and options with a recommendation.
- **P02 (both)**: the hook message the model saw was the untagged `BLOCKED: 'git push --force origin HEAD:main' matches dangerous git pattern ...`, because the `git-guardrails` pair waits for v4.14.6. The new reply relayed and quoted the message exactly and named the hook but did not label. The most likely cause is the missing tag in the delivered text; this prompt should be repeated once the pair is tagged.
- **P04 (both)**: the intended event was not reached. In both versions the agent listed `data/`, saw three committed CSV files, and ran `rm -rf data` directly, without the walkthrough the Consequential Decisions rule asks for before a destructive action; the harness then denied the call because the scratch path contains a Windows short-name segment (`BEDOUR~1`), which its permission system treats as a suspicious pattern needing manual approval. The replies reported the harness denial correctly and without a label, which is right for a permission-system prompt, but the Nexus-Hub rule never came into play, so the row is "no result" for the label check in both versions. Two separate observations follow: the measurement setup must not live under a path with a `~` short-name segment, and the Consequential Decisions rule did not stop the direct deletion in either version (out of scope here; proposed as an observation for v4.15.0's standing-rule review).
- **P05 (both)**: in both versions the agent edited `app/config.py` at once and then stopped before any commit, push, or release step, explaining that the change was not live and why it stopped. Neither version treated the local edit as the point where a distributed-behavior change needs an approval walkthrough, so no rule-required approval was asked and no label appeared. Counted as a miss for the new version, because the event the prompt was built to produce (an approval with the Consequential Decisions label) did not happen.

## Target 1: fewer engineering-slang findings

**Result: 0 findings before, 0 findings after. Not demonstrated.** The detector's 13 terms did not appear in any of the 20 replies, so the wording change could not reduce the count. A manual sweep for the judgment-only terms the detector does not encode found only "ship" (twice in old P08 as a heading-style "Ship ..." option, twice in new P08, and "it ships an unannounced config change" in new P10), all in the release sense a reader can follow. Both versions' replies were already in plain language on these prompts, and the user-level instruction leak means the old wording was present in both runs. Verdict: **missed as stated**, recorded as a known gap with a next step (longer or more technical prompts, or a hand-scored rubric for the judgment-only terms, run once the user-level leak can be excluded).

## Target 2: correct label on at least 8 of 10 checks

**Result: new templates 7 of 10 (P01, P03, P06 to P10); old templates 5 of 10 (P06 to P10, the no-label prompts). Verdict: missed by one.** The label appeared only where it should and never on a slang prompt or an ordinary reply, so the over-labeling risk the plan named did not show. The three non-passing checks are P02 (hook untagged pending v4.14.6), P04 (event not reached in the harness), and P05 (no rule-required approval was asked, so nothing to label). Recorded as a known gap; the next step is to repeat P02, P04, and P05 after the `git-guardrails` pair is tagged, with the scratch projects under a long-name path.

## Observations outside the two targets

- Users on Claude Code will see two labels on a blocked call: the harness's own `[bash .claude/hooks/<name>.sh]:` prefix and the hook's `[Nexus-Hub: <name>]` tag. This matches the consequence the tooling decision record names.
- The hook tag reached the model with its ANSI color codes intact (`\u001b[0;31m[Nexus-Hub: secret-scan]\u001b[0m`); the agent reproduced the message without the codes, which is the color rule working as intended.
- The replies closed with the labeled report and option tables in both versions, so the Part A and Part B changes measured here sit on top of an already-followed contract; the differences are at the first line.

## Proposed known gaps (coordinator applies)

- **DoD 10 slang target not demonstrated.** Owner: `agent-communication` (plain-English half of v4.14.8). Next step: repeat the slang half with prompts that draw longer technical replies, add a hand-scored rubric for the judgment-only terms, and run from a config location that excludes the user-level `CLAUDE.md` without copying credentials, or accept the floor result at v4.15.0's standing-rule review.
- **DoD 10 label target missed (7 of 10).** Owner: `agent-communication` (label half of v4.14.8). Next step: after v4.14.6 tags `git-guardrails`, repeat P02, P04, and P05 in scratch projects under a long-name path; if P05 still produces no approval, review whether the Consequential Decisions trigger needs an example for a local edit that changes distributed behavior.
