## Verification

The commands and results are in the admission record (T030). Highlights:

- 191 extension tests pass with 99 percent statement and 92 percent branch coverage. Together with 612 Python tests (engine, installed-layout CLI, catalog validator, CI collection) and the fast profile (18 steps), all green.
- The panel agrees with `nexus-hub settings show --json` on all 18 records, proven three ways: a unit test against engine-generated fixtures, `test/agreement.test.ts` (the real controller driving the real Python CLI in a scratch home, including a byte-identical reset and the agent-marker refusal), and a live run of the packaged `.vsix` in an isolated VS Code extension host.
- The planted-binary test shows a `nexus-hub.cmd`, `nexus-hub.exe`, or `python.exe` in the workspace is never run, even with the workspace as current directory and first on PATH.
- The webview is tested for its content security policy, escaping of hostile values, label and heading structure, keyboard focus, and the exact messages it posts.

## CI impact

The package needs a path-filtered workflow and a profile group: Phase 5 (`.github/` was out of scope here). The extension's agreement test needs Python 3.11 or newer. No installer, hook, or required-check change, and no remote CI ran.

## Plan delta

- **Contract additions.** `show --json` gained `removable_override` and `explain --json` gained `control.per_tool`, `control.never_written`, and `claude_model_ids` (additive, `schema_version` 1). `scripts/nexus_hub_cli.py` did not change, so the handbook digest obligation does not apply.
- **Interpreter discovery.** Added the Microsoft Store Python location (the only Python on this host) and a `stat` fallback for app-execution aliases, which fail `stat` but run.
- **Panel layout.** The activity-bar view hosts the whole panel and the Open command focuses it. The model "picker" is a text box with the bundled Claude ids as suggestions.
- **The DoD 8 table is generated from the catalog**, so the Copilot CLI and VS Code Copilot Chat cells read "Not settable" with their reasons today.
- **No VS Code-host write is admitted yet**, so the CLI returns no `editor_writes` today and plan step 2 ("observe `claudeCode.initialPermissionMode`") has nothing to observe. The editor path is covered with the stub, with the real configuration API in an extension host, and with a catalog variant that admits a write.
- **VS Code's auto-approve dialog text** was not captured (proof matrix W23 is manual). The modal quotes the vendor's description of the setting.
- **The real VS Code modal** was not driven; the modal request is asserted in tests.
- **New test dependency**: `happy-dom` 21.0.4 (extension dev dependency, exact pin) for the webview script tests. `scripts/live-check.js` and `scripts/live-runner.js` repeat the isolated-VS-Code proof for the final phase.
