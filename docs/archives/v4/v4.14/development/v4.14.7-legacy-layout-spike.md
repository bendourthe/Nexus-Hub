# v4.14.7 Legacy Layout Spike

Summary: the time-boxed spike (task T034) that decided whether the obsolete `~/.agent` and home-root `~/.opencode` layouts can be recognized file by file, with the GO verdict and its evidence.
Read this when: changing `scripts/build_legacy_layout_fingerprints.py`, the legacy classifier in `scripts/lib/integrations/legacy.py`, or deciding whether another obsolete layout can be cleaned the same way.
Covers: the producing revision ranges, what each layout held, how each file kind is recognized, the size measurement, and the verdict.

Run on 2026-10-30 against the repository history at `feat/v4.14.7-installer-platform-detection`.

## What Each Layout Held

- `~/.agent`: `skills/` as a verbatim copy of `catalog/skills/` (category layout) and `workflows/` as a verbatim copy of `catalog/commands/`. No installer revision in the range wrote `AGENT.md`, `rules/`, or `subagents/` there. The maintainer's tree (removed by hand on 2026-10-29) held all three, so they came from something other than these installers, and an all-or-nothing match would correctly have kept that tree.
- `~/.opencode`: a rendered, marker-merged `AGENTS.md`; verbatim `commands/` and `rules/`; `skills/` in the category layout until `1e95d4e88` (2026-07-13) and flattened (`skills/<name>/`) from then on, plus a generated command-skill `skills/<command>/SKILL.md` per command. OpenCode itself adds `package.json`, `package-lock.json`, `.gitignore`, and `node_modules/` to its config folders when plugins are present; those are not Nexus-Hub output.

## Recognition

| File kind | Recognized by |
|---|---|
| Verbatim catalog copy | Relative install path plus sha256 of any historical blob of the source path in the producing range, in LF and CRLF forms (a Windows install from a git checkout with `autocrlf` copies CRLF files) |
| Flattened skill file | The same, with the category segment removed from the path |
| Generated command-skill | Replaying the range's own `_synthesize_skill` (with `_split_frontmatter` and `_yaml_double_quote`, extracted from `9b30ad29e^:scripts/lib/integrations/_catalog_adapters.py`; the generator did not change between `1e95d4e88` and `9b30ad29e^`) over every historical command blob, LF and CRLF |
| Rendered `AGENTS.md` | Every non-blank line's hash is in the existing `scripts/lib/installer/legacy_fingerprints.json` set |

## Measurement

Unique historical (path, content) pairs feeding `~/.agent`: 1,046 (573 distinct contents), estimated 131 KB as JSON before the layout mappings and CRLF variants. Built file, measured 2026-10-30: `scripts/lib/installer/legacy_layout_fingerprints.json`, 679,543 bytes, 552 `~/.agent` paths (2,047 hashes) and 1,280 `~/.opencode` paths (5,624 hashes); `--check` reproduces it byte for byte.

## Verdict

**GO.** Criterion 1 holds: every file kind the producing installers wrote into either layout has an exact recognizer (verbatim blobs, flattened paths, a deterministic replayed generator, and the existing line set). Criterion 2 holds: the estimate is an order of magnitude under the 2 MB bound, and the builder fails if the generated file exceeds it.

Expected real-world effect, stated plainly: removal is all-or-nothing per tree (decision D4), so a tree that also holds anything else (the maintainer's `~/.agent` with `AGENT.md`, `rules/`, and `subagents/`; an `~/.opencode` where OpenCode installed plugin dependencies) is kept and reported with its unrecognized entries. The command removes pristine legacy trees and explains the rest.
