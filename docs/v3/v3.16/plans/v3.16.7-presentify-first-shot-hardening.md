## Overview

`/presentify` had reached a state where the iterative visual-QA loop reliably repaired a page, but the FIRST rendered page still shipped a recurring family of defects that the loop then had to find. That distinction matters because each repair iteration costs a full render pass and because a defect that survives to delivery is one the reader sees. A real session produced five such defects, each invisible to the checks already in place: a CSS class collision that blanked the hero with zero console errors, a chart series flat-clamped at the axis maximum (fabricated data that looks like a value), a scrub ramp that loaded content dimmed before the reader had scrolled, a change-local re-render that verified the edited section while another section was silently broken, and a source placeholder (`xx subjects`) that an agent would rather estimate than surface.

The common shape is that all five pass every static check. The scorer reads bytes and structure, the console-error listener sees no errors, and the edited section renders clean. So the response is not another static rule: it is a set of BINARY authoring rules where a judgment call was previously implied, plus two new render-time probes that make the invisible classes deterministically visible.

This release is also where authoring stops fighting the scorer. `scripts/visual_qa_score.py` reads specific markup contracts, and a first authoring pass that does not know them earns a repair iteration for reasons unrelated to how the page looks. Phase 1 documents those contracts where the author reads them.

## Phase 1: First-shot hardening (COMPLETE - shipped in `0dbc170f`)

**Goal**: Give each of the five observed defect classes a named guard at the point where an author or the render loop would produce it.
**Outcome**: Shipped. Documented here for traceability; do not re-implement.

### What shipped, by defect class

1. **Component-CSS namespacing (BINARY)** - `SKILL.md` Step 6. Every class an authored component introduces carries a component prefix (`.map-pin`, `.chart-legend`), never a bare generic noun (`.pin`, `.card`, `.tip`, `.stage`). Origin: a map-pin `.pin{width:14px}` collided with the cinematic stage's `.pin` wrapper and squeezed every hero canvas into a 10px strip, with zero console errors. Paired Common Rationalizations row: "`.pin` / `.card` / `.tip` are obvious names for this component".
2. **Regression smoke-set** - `SKILL.md` Step 9. Every re-render pass, INCLUDING post-delivery edits, captures a fixed three-shot set: the hero at load, one divider mid-scroll, and one interactive chart. Origin: change-local rendering verified an edited map section while a class collision destroyed a section nobody re-looked at. Paired rationalization row: "I only touched the map section".
3. **Criterion 11, painted-surface integrity** - `references/visual-qa-rubric.md` plus the `SKILL.md` probe list. A render probe asserts every JS-painted canvas painted at its container's width AND that a pixel sample is not uniformly blank after settle. Origin: the same collision; a squeezed or unpainted canvas passes every static check and every console-error listener.
4. **Mixed-scale chart series (BINARY)** - `SKILL.md` Step 6 and `references/interactive-features.md`. A value is never drawn flat-clamped at the axis maximum; an out-of-range context series starts hidden and legend toggles auto-refit the axis. Framed as data integrity, not layout: a flat-topped bar at y-max is fabricated data. Paired rationalization row.
5. **First-paint legibility (BINARY)** - `SKILL.md` Step 6 and `references/scroll-scrub.md`. Scrub ramps fade content OUT on exit and never IN from a dimmed load state, because the reader has not scrolled yet at first paint. Paired rationalization row.

### Also shipped

- **"Author to the scorer contract" checklist** (`SKILL.md` Step 6): `data-aspect` on `<body>`, `--page-max` / `--gutter`, the parseable `placement:` line format, the literal hero-image caps, and the fg/bg custom-property NAME heuristics the contrast check pairs on. Purpose: pass the deterministic scorer on the first authoring pass rather than after a repair iteration.
- **Unfilled-placeholder detection** (`scripts/extract_content.py`, +73 lines): text blocks are scanned for author placeholders (`xx`, `[insert ...]`, `[TBD]`) into a `placeholders` model list surfaced at Round 2 intake. Never silently filled. Paired rationalization row: "the source says 'xx subjects' - I'll estimate from the other slides".
- **Geo-pin overlay path** (`references/figure-reconstruction.md` part 5, path 2b) with the bundled `scripts/fit_map_projection.py` (+150 lines): a landmark-anchor fitter for location maps whose labels were loose slide text. Quadratic fit by default because affine fits visibly fail on conic base maps; includes render-loop verification, per-site nudges, and collision relaxation.
- **Tests**: `tests/skills/test_presentify_first_shot_hardening.py` (+178 lines, 12 prose/behavior tests) and the two criteria-count contract tests in `test_presentify_intake.py` advanced to eleven. Presentify suite reported 199 passed.

### Sub-tasks

#### 2.1 - Strip the UTF-8 BOMs introduced by `0dbc170f`

**Objective**: Restore YAML-frontmatter parseability for the presentify skill.

**Prompt**:
> `0dbc170f` prepended a UTF-8 BOM (`EF BB BF`) to two files: `catalog/skills/specialized-domains/document-to-interactive-html/SKILL.md` and `tests/skills/test_presentify_intake.py`. Neither had one before that commit.
>
> The SKILL.md case is a hard release blocker, verified empirically rather than assumed: reading the file with `encoding="utf-8"` (which is what `scripts/validate_skills.py` line 258 does, NOT `utf-8-sig`), `content.startswith("---")` is False and the `^---\n(.*?)\n---` frontmatter regex does not match, so the validator's own `parse_frontmatter()` returns `None` and reports "no valid YAML frontmatter (must start with ---)" as a hard error. `make validate` and the CI `validate` job are therefore RED on this branch. Downstream, `AGENTS.md` records that the MCP skill server depends on parseable frontmatter, so skill discovery for the largest skill in the catalog is at risk too.
>
> Strip both BOMs and write the files back as UTF-8 without a BOM. On Windows this means `[System.IO.File]::WriteAllText($path, $text, (New-Object System.Text.UTF8Encoding($false)))` or a Python `write_text(..., encoding="utf-8")` - never `Set-Content -Encoding utf8`, which is what introduces the BOM on PowerShell 5.1 and is the exact trap `AGENTS.md` documents in its hook-authoring section.
>
> Then close the loop so this cannot recur silently: check whether `scripts/validate_unicode_safety.py` flags a BOM at all, and if it does not, add a BOM check to it (a leading `EF BB BF` on any tracked text file is an ERROR, not a warning). A repository that documents this trap twice and still ships it twice needs the guard, not a third mention.
>
> Acceptance criteria: neither file starts with `EF BB BF`; `python scripts/validate_skills.py --bundles-only` passes; `python scripts/validate_unicode_safety.py` reports 0 errors; a BOM re-introduced into any tracked text file is caught by a validator rather than by a reader.

### Intake protocol

Each incoming lesson becomes a numbered sub-task below and follows the same shape Phase 1 used, because that shape is what made Phase 1's guards enforceable rather than advisory:

1. **Name the defect as observed** - what the page did, in one sentence, from the real session.
2. **Name why the existing checks missed it** - static scorer, console errors, change-local render, or agent judgment. A lesson whose defect the existing checks WOULD have caught is a bug report, not a new guard.
3. **Choose the guard's kind**: a BINARY authoring rule in `SKILL.md` (when the correct behavior admits no judgment), a render-time probe plus a rubric criterion (when it is only visible in pixels), an extraction change (when the source content is at fault), or a reference-file pattern (when it is a technique, not a rule).
4. **Add the paired Common Rationalizations row** - the excuse an agent would use to skip it, with the concrete failure it caused. Every Phase 1 guard has one; a guard without one is a suggestion.
5. **Add the prose/behavior test** in `tests/skills/test_presentify_first_shot_hardening.py`, and advance the criteria-count contract tests if a rubric criterion was added.
