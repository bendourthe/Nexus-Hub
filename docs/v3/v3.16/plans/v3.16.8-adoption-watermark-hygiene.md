# Plan - Watermark Hygiene: Unicode Fix Mode + /plan and /update Wiring

**Project**: Nexus-Hub
**Version**: v3.16.8
**Slug**: adoption-watermark-hygiene
**Plan Type**: Feature (adoption, seeded from comparison)
**Created**: 2026-08-13
**Seeded from**: docs/v3/v3.16/comparisons/v3.16.8-comparison-watermark-hygiene-and-harness-engineering.md
**Goal**: Every plan file `/plan` writes and every release `/update release` ships is automatically free of invisible Unicode watermark characters and non-ASCII punctuation, enforced by the existing local validator extended with a fix mode, with zero new dependencies.

## Overview

This plan operationalizes the four P0 adoption items from the watermark-hygiene comparison (A2, A1, A3, A4, in RE-first order). Nexus-Hub already detects the core invisible-character set (zero-width characters, Trojan-Source bidi controls) and non-ASCII punctuation via `scripts/validate_unicode_safety.py`, wired into `make validate` and CI. What is missing is an auto-clean capability, a few character classes used for hidden-text smuggling, and the workflow wiring: `/plan` writes plan files without sanitizing them, and `/update release` has no explicit pre-commit hygiene gate.

Phase 1 extends the validator in place: new character coverage (exotic space homoglyphs, Unicode tag characters, soft hyphen, VS16) and an opt-in `--fix` mode with atomic writes, preserving the detect-only default, the 0/1/2 exit-code contract, the `.ps1` BOM exemption, and the non-English-content exemption. Phase 2 wires the workflow surfaces: the plan-writing step gains a mandatory closing sanitize pass (`--strict --fix` on the just-written file), and `/update` gains scope-appropriate gates (detect on docs/changelog scopes, fix-and-block on release artifacts in the release scope). Phase 3 is the mandatory refactor / known-gaps / CI/CD closing phase.

Success looks like: a plan file generated with a deliberately injected zero-width space comes out clean without manual intervention, `/update release` refuses to commit release artifacts carrying invisible characters, `make validate` and CI behavior are byte-for-byte unchanged for existing callers, and no new dependency, outbound call, or credential is introduced. The two upstream sources' other capabilities (statistical watermark defeat, C2PA/EXIF stripping) are explicitly NOT adopted, per the comparison's NOT-recommended list.

## Phase 1: Validator Coverage and Fix Mode

**Goal**: Extend `scripts/validate_unicode_safety.py` with the missing character classes and an opt-in `--fix` mode, without changing behavior for any existing caller.
**Prerequisites**: None.
**Stability Gate**: `pytest tests/validators/test_validate_unicode_safety.py` passes with new cases for every added character class and for fix-mode round-trips; `make validate` output on the current tree is unchanged versus the pre-change baseline (same findings, same exit code).
**Recommended model tier**: strong
**Recommended effort level**: high
**Rationale**: Small surface but contract-sensitive: the exit-code protocol, the `.ps1` BOM exemption, and the non-English exemption are load-bearing for `make validate`, CI, and both installers, and fix mode writes files.

### Sub-tasks

#### 1.1 - Extend the detection character set (adoption item A2)

**Objective**: Detect exotic space homoglyphs, Unicode tag characters, soft hyphen, and VS16 in English Markdown, closing the gap versus the upstream deterministic layer.

**Failure modes**: An undecodable (non-UTF-8) file is reported as an IO finding with exit 2, never a crash; an unreadable file (permissions) is likewise reported, not skipped silently; two concurrent validator runs are read-only in detect mode and cannot conflict.

**Prompt**:
> In `scripts/validate_unicode_safety.py`, extend detection coverage. Add to the hard-error set (`_UNSAFE_CODEPOINTS`): Unicode tag characters U+E0001 and U+E0020 through U+E007F (hidden-text smuggling channel). Add to the strict-mode punctuation/space set (`_NON_ASCII_PUNCT_CODEPOINTS`, replacement in parentheses): U+2000 through U+200A (space), U+1680 (space), U+202F narrow no-break space (space), U+205F (space), U+3000 ideographic space (space), U+00AD soft hyphen (delete or `-` per context: delete), and U+FE0F variation selector-16 (delete). Rationale for the split: tag characters are never legitimate in this repo's content, so they are errors like zero-width chars; space homoglyphs, soft hyphen, and VS16 can appear in legitimate non-English text, so they follow the existing warn-by-default / `--strict` promotion path and the existing natural-language exemption. Construct all new entries from codepoint integers like the existing sets, so the validator source stays self-detection-free. Do not change the `.ps1` BOM exemption, the exit-code contract (0 no errors / 1 errors / 2 usage-IO), the CLI surface, or the default targets. Update the module docstring's character inventory. Add pytest cases in `tests/validators/test_validate_unicode_safety.py` covering at least one character from each new class, both the error path and the strict-warning path, plus a case proving a `.ps1` leading BOM is still exempt. Acceptance: new tests pass; the full existing test file passes unchanged; `python scripts/validate_unicode_safety.py` on the current repo exits with the same code and finding count as before the change.

---

#### 1.2 - Add the opt-in fix mode (adoption item A1)

**Objective**: Give the validator a `--fix` flag that removes hard-error characters and applies the prescribed ASCII replacements for strict findings, then re-validates, so callers can clean files deterministically instead of looping on manual edits.

**Failure modes**: Malformed or undecodable input is never written back (fix skips the file, reports it, exits 2); a write failure mid-fix cannot corrupt the original because writes go to a temp file in the same directory followed by an atomic rename; two concurrent `--fix` runs on the same file each perform a whole-file atomic replace, so the result is one run's complete output, never an interleaved file.

**Build class**: load-bearing.

**Prompt**:
> In `scripts/validate_unicode_safety.py`, add an opt-in `--fix` flag. Behavior: for each file with findings, remove every hard-error character (zero-width set, bidi controls, tag characters) and, when `--strict` is also passed, apply the ASCII replacement already prescribed in the punctuation map (em dash to `--`, curly quotes to straight, ellipsis to `...`, NBSP and space homoglyphs to a regular space, soft hyphen and VS16 deleted). Without `--strict`, `--fix` repairs only hard errors. Hard constraints: (1) detect-only remains the default; no caller that omits `--fix` sees any behavior change; (2) the exit-code contract is unchanged, and after a fix pass the exit code reflects the POST-fix state (a fully repaired tree exits 0) while the report lists what was changed per file; (3) never touch files matching the existing exemptions: the leading BOM in `.ps1` files stays, and non-English natural-language content (the existing exemption path) is never rewritten; (4) write via temp-file-plus-atomic-rename in the same directory, preserving the file's original newline style (do not normalize LF/CRLF) and writing UTF-8 without adding a BOM; (5) after writing, re-scan the file and fail loudly (exit 1) if findings remain. Add pytest cases: fix removes an injected ZWSP and a bidi override; strict fix replaces an em dash and curly quotes; a `.ps1` BOM survives fix; CRLF files keep CRLF; a file with no findings is not rewritten (mtime unchanged); post-fix re-validation passes. Acceptance: all new and existing validator tests pass; `python -m py_compile scripts/validate_unicode_safety.py` is clean.

## Phase 2: Workflow Wiring - /plan Sanitize Step and /update Gates

**Goal**: Make the sanitize pass a default part of `/plan` output and a checked gate in `/update`, heaviest at release scope (adoption items A3 and A4).
**Prerequisites**: Phase 1 (the commands invoke `--fix`).
**Stability Gate**: A plan file generated with an injected zero-width space comes out clean; `/update release` documentation names the blocking gate and the exact command; `make validate` passes; the trigger-eval and placeholder lints pass on any touched skill files.
**Recommended model tier**: standard
**Recommended effort level**: medium
**Rationale**: Instruction-level edits to two command files and one skill body invoking an already-tested script; low blast radius, but the wording must be precise enough that agents execute the gate consistently.

### Sub-tasks

#### 2.1 - /plan closing sanitize step (adoption item A3)

**Objective**: Every plan file written by the planning flow is sanitized immediately after it is written, automatically.

**Prompt**:
> Wire a mandatory closing sanitize step into the plan-writing flow. Edit `catalog/skills/workflow/implementation-plan/SKILL.md` (Step 4, "Write the Plan") and `catalog/commands/plan.md` (a one-line surfaced guarantee, keeping the dispatcher thin): after the plan file is written, run `python scripts/validate_unicode_safety.py --strict --fix --path <plan-file>` (note: the script takes `--path`, not a positional argument), report what was cleaned in one line, and treat a non-zero post-fix exit as a blocker to fix before presenting the plan. Scope the auto-fix to the just-written plan file only, never the whole repo. Add the same step to the plan verification checklist in the skill. Follow the Markdown style guide (`catalog/style-guides/markdown.md`), keep the edits ASCII-clean, and respect the SKILL.md size norm. No registry updates are needed (no new skill); `catalog/commands/` and `catalog/skills/` are auto-copied by both installers. Acceptance: `make validate` passes (including the placeholder lint on the edited SKILL.md); a manual smoke test writing a scratch plan file with an injected U+200B then following the new instruction leaves the file clean.

#### 2.2 - /update gates, blocking at release scope (adoption item A4)

**Objective**: `/update docs` and `/update changelog` detect Unicode-hygiene findings on the Markdown they touch; `/update release` runs a fix-and-block gate on release artifacts before the release commit.

**Prompt**:
> Edit `catalog/commands/update.md`. (1) For the docs and changelog scopes: after writing or editing Markdown, run `python scripts/validate_unicode_safety.py --strict --path <file>` per touched file and fix findings before finishing (detect-first here; these scopes may touch hand-edited files). (2) For the release scope: add an explicit governance gate, positioned with the other pre-commit release checks, that runs `python scripts/validate_unicode_safety.py --strict --fix` with `--path` over the release-cycle artifacts only: CHANGELOG.md, README.md, any RELEASE_NOTES file, and the active `docs/v<MAJOR>/v<MAJOR>.<MINOR>/` tree for the version being released. A residual non-zero exit after fix BLOCKS the release commit. Explicitly scope the gate to release-cycle artifacts, not the whole repo, so grandfathered warnings in archived docs (the WN-v23-3 lineage) are not mass-rewritten; state that exclusion in the command text. Note the composition with CI: CI keeps its repo-wide detect pass; this gate is earlier (pre-commit) and stricter on the artifacts a release actually ships. Keep edits ASCII-clean per the Markdown style guide. Acceptance: `make validate` passes; the release-flow section reads as a numbered gate consistent with the existing governance steps (for example the capability-usage gate), and names the exact command an agent must run.
