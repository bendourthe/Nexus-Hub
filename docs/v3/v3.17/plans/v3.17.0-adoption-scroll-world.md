## Overview

This plan operationalizes the scroll-world comparison for presentify. [scroll-world](https://github.com/oso95/scroll-world) ships a paid Monid/Higgsfield generation pipeline plus a portable vanilla-JS scrub engine that plays a frame-locked dive/connector video chain as one continuous camera flight. Nexus-Hub already owns document-to-interactive-site authoring in `/presentify` / `document-to-interactive-html`, including a RICH scrollytelling catalog (pinned graphics, parallax, timelines) - but it has no scroll-scrubbed video/still stage, no seam-handoff protocol for chained local clips, and no size/cost gate for cinematic asset budgets.

The adoption is reverse-engineer-first and presentify-native: skill-native protocol and intake first, then a renamed offline scrub engine adapted for inlined `data:` / Blob sources, then command/skill wiring for `--interactivity cinematic` (with journey questions derived from the extracted content model). Monid, Higgsfield, Seedance, Kling, and any competing `/scroll-world` slash command are dropped under the MCP Registry Policy Hard-No (generation-as-service) and the presentify surface-ownership rule. Optional local background-knockout is included as a late, deferrable helper.

**Goals-first (from comparison + product framing):**

- **Target problem**: Users who want an Emons-/Apple-style scroll-through journey today must leave presentify for a vendor-paid skill that breaks Nexus-Hub's offline and generation-as-service policies.
- **Persona**: A Nexus-Hub user turning an existing deck, report, or brand kit into one shareable offline interactive site who optionally wants a cinematic hero journey without uploading prompts or frames to a hosted generator.
- **Definition of done**: A consented cinematic presentify run produces a single offline `.html` whose scroll position scrubs a stage (video when local/stock clips exist; stills-only crossfade otherwise), with size/cost disclosed before asset work, seam discipline documented for local clip chains, `prefers-reduced-motion` stills-only behavior, zero Monid/Higgsfield references in distributed artifacts, and `make validate` / presentify tests green.

**Prior known-gaps ingest (Step 0.6):** Checked `docs/v3/v3.15/known-gaps.md` (v3.15.4 presentify-visual-fidelity is finalized; open advisories are browser-skip and agent-side stock integration graded by visual-QA, not cinematic). Checked `docs/v3/v3.16/known-gaps.md` (no presentify/cinematic items). Nothing to pull forward into this plan beyond preserving those offline / visual-QA contracts.

**Grounding:** No `STRATEGY.md` or `docs/solutions/` hit for scroll-scrub; proceed from the comparison's RE ordering.

## Phase 1: Skill-native scroll-scrub foundation

**Goal**: Establish the cinematic protocol (when it applies, size/cost disclosure, seam/pacing rules, stills-only and reduced-motion fallbacks) as a Tier-3 reference every later phase cites.
**Prerequisites**: None.
**Stability Gate**: `catalog/skills/specialized-domains/document-to-interactive-html/references/scroll-scrub.md` exists and is referenced from SKILL.md; it forbids hosted generation vendors by name-class; stills-only and `prefers-reduced-motion` paths are specified with observable criteria; `make validate` orphan-bundle audit passes; SKILL.md stays within the soft size cap.
**Recommended model tier**: strong
**Recommended effort level**: high
**Rationale**: Authoring the load-bearing protocol that Phases 2-3 implement; high blast radius if the offline / Hard-No boundaries are written wrong, but mostly prose + reference structure.

### Sub-tasks

#### 1.1 - Author references/scroll-scrub.md (A6, A3, A7)

**Objective**: Write the canonical cinematic protocol reference.

**Prompt**:
> Create `catalog/skills/specialized-domains/document-to-interactive-html/references/scroll-scrub.md` for presentify's cinematic path. Follow `catalog/style-guides/markdown.md` (blank lines around lists/headings, ASCII-only). Cover, in order:
>
> 1. **When cinematic applies** - opt-in only (`--interactivity cinematic` or the cinematic choice in the up-front interactivity menu). It composes with existing RICH patterns; it does NOT replace interactive charts or the five-point interaction budget.
> 2. **Job fidelity** - section order and copy come from the extracted content model (deck/report/compile/project). Do not invent a parallel brand narrative. Camera/journey grammar is presentation over existing sections.
> 3. **Size / cost gate (A6)** - BEFORE generating or embedding cinematic assets, estimate and state: clip count, approximate base64/HTML size impact, stock-video key requirements if any, and QA-depth cost. Get go/no-go. Prefer short clips or stills-only when the estimate is large. Cross-link `[[ai-billing-safeguards]]`.
> 4. **Asset sources (Hard-No boundary)** - allowed: user-supplied local clips/stills; Tier 1 procedural stills; Tier 2 consent-gated stock (existing Pexels video path); Tier 3 LOCAL AI stills as posters only. Forbidden: any hosted image/video generation service, runtime hotlinks, multi-file sibling asset layouts that break the single-file offline guarantee.
> 5. **Seam and pacing protocol (A3)** - when chaining local clips: hand off actual rendered boundary frames (not original stills); short crossfade as insurance; per-section `scroll` (dwell) and `linger` (mid-scene settle) knobs; optional local ffmpeg encode notes (muted, small GOP, faststart) for scrub-friendly files the user already has.
> 6. **Stills-only fallback (A7)** - when no video exists or under `prefers-reduced-motion: reduce`, scroll drives still crossfade + gentle scale only; no video decode. Observable criterion: scrolling never produces vestibular video scrub for a reduced-motion user.
> 7. **Accessibility** - real section copy remains linearly readable; route/nav jumps work; reduced-motion path documented.
>
> Do NOT name external product/repos (scroll-world, Monid, Higgsfield, Seedance, Emons) in this distributed reference. Attribution belongs only in the reverse-engineering matrix (Phase 3).

## Phase 2: Offline scrub engine reverse-engineer

**Goal**: Ship a generic, zero-dependency scroll-scrub engine adapted for presentify's single-file offline output.
**Prerequisites**: Phase 1 (protocol and naming).
**Stability Gate**: `references/scroll-scrub-engine.js` (or equivalent generic name under the skill's `references/` or `assets/`) mounts a config-driven stage; loads clips from `data:` URIs or in-memory Blobs (no runtime network); implements seam crossfade, linger remap, seek-coalesce, iOS priming, and reduced-motion stills-only; is referenced from SKILL.md and `interactive-features.md`; a small fixture/demo or unit/smoke test proves offline seek without external URLs; no external product names in the distributed file.
**Recommended model tier**: frontier
**Recommended effort level**: high
**Rationale**: Novel integration of video scrubbing into the offline single-file contract; high structural complexity and regression risk against presentify's offline guarantee.

### Sub-tasks

#### 2.1 - Reverse-engineer the scrub engine (A2)

**Objective**: Produce the local engine artifact under a generic name.

**Prompt**:
> Add a portable vanilla-JS scroll-scrub engine to `catalog/skills/specialized-domains/document-to-interactive-html/` under a generic name (e.g. `references/scroll-scrub-engine.js` or `assets/scroll-scrub-engine.js`). Reverse-engineer from the comparison's described capabilities (blob/data-URI seek, dive/connector segment chain, seam crossfade, per-section scroll/linger, mobile seek-coalesce, iOS muted prime, atmosphere/particles optional and off under reduce/coarse, sticky route/nav). Requirements:
>
> - Zero dependencies; namespaced CSS injected into a caller-supplied container.
> - Clip loader MUST accept `data:` URIs and/or Blob object URLs so the authored `.html` can stay one file. Do NOT require HTTP byte-range serving of sibling files as the primary path.
> - Under `prefers-reduced-motion: reduce`, never attach/play video; stills cross-dissolve only (matches Phase 1).
> - No external product, vendor, or upstream repo names in comments or identifiers (use `scroll-scrub` / `ss-` prefixes).
> - Document the config shape in a short header comment and point to `references/scroll-scrub.md` for protocol.
