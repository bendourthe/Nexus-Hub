## 4.5 CI/CD and the MT-1 guard test

Taken before 4.3 so the test's outcome could feed the reconciliation.

### The guard test

`tests/skills/test_spec_artifact_agreement.py`, 21 cases. It asserts:

- the template carries every declared section and marks the mandatory ones `*(mandatory)*`;
- the skill's Verification checklist names each mandatory section (the assertion that would have caught the original defect, where the list named "Objective, Commands, Structure, Style, Testing, Boundaries");
- the skill declares exactly one canonical skeleton and no rival inline template has returned;
- the checklist's "Scope is clearly bounded" item names `## Non-Goals` **on its own line**, and a reason-per-entry item exists;
- `scope-guardian-reviewer` names the heading the template actually produces;
- the template still mandates a reason per Non-Goal.

### The first draft failed its own mutation test

Three mutations were applied and reverted:

1. Unbind `## Non-Goals` from the checklist's scope item.
2. Delete the reason-per-entry companion item.
3. Repoint the skill's Verification at the rival template's six areas.

Mutation 3 failed the suite correctly on the first draft (5 failures). **Mutation 1 passed**, which it must not. The assertion was `"Non-Goals" in checklist`, and the heading is also named in the Content Quality line, so the token survived while the binding did not. The test was checking that a word appeared somewhere in a document rather than that a relationship held, which is the most common way a guard test rots into decoration.

Rewritten to inspect the scope line itself and to require the reason item as a separate checklist entry. All three mutations now fail; the baseline passes 21. Without the mutation pass, MT-1 would have closed on a false guarantee, which is worse than leaving it open.

Mutations were run under a shell `trap` that restores on exit, after Phase 1's lesson: a `git stash && pytest && git stash pop` chain lost its `pop` to a tool timeout and stranded the working tree. A trap fires even when the command is killed. The tree was verified clean after each pass.

### CI

**Covered without a structural change.** Every surface this plan touched sits outside `docs/`, so `ci.yml`'s workflow-level `paths-ignore: docs/**` already fires the full job set for all of them. Adding a positive `paths:` filter restricted to `catalog/templates/**` and `catalog/skills/**`, as sub-task 1.5 literally suggested, would have **narrowed** coverage rather than optimizing it.

The four requested optimizations were verified present rather than assumed: `concurrency` with `cancel-in-progress`, pip caching keyed on `.pre-commit-config.yaml`, expensive Windows and matrix legs gated behind `if: github.event_name != 'pull_request'`, and SHA-pinned action references carrying version comments.

The new test needed no new job: the `Skills-script tests` step already runs `tests/skills` as a directory. Its descriptive label was updated to name the new coverage, which is the single CI edit in this phase.

## Lesson worth carrying forward

Two of this plan's factual assertions had gone stale between authoring and execution: the 269-skill catalog count (now 270) and the `actions/setup-node` tag pin (now SHA-pinned). Both were true when written. Neither was caught by transcription, and both would have shipped as wrong statements in a CHANGELOG and a gap ledger respectively.

A plan is a decision record, not a data source. Its reasoning is what survives; its measurements need re-taking at execution time. The same discipline applied to the guard test: a test that asserts a token appears somewhere is not a test that the relationship holds, and only mutation reveals the difference.
