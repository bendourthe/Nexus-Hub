## Goal

Make the Cursor monitor useful on install for a personal or Team plan, using only surfaces Cursor actually supports, without ever presenting a local observation as a billing fact.

v3.15.12 established what is *not* possible: there is no supported way to read personal server-side balances. Of 116 bundled extensions in Cursor 3.14.27, none declares a Cursor authentication provider and none contributes a usage or billing command; Cursor documents no personal-usage API; and its SDK explicitly does not auto-discover local credentials. The private dashboard route was probed to a closed negative.

What v3.15.12 also established is that a supported channel *does* exist and **Nexus-Hub already owns an entry in it**: `~/.cursor/hooks.json` is live on the maintainer's host (`version: 1`), and its registered `beforeShellExecution` command is our own `git-guardrails.sh` from the v3.15.0 parity work. This plan builds a local usage observer on that channel.

**Persona**: the maintainer on a Cursor Team plan who wants the panel to show something true and useful immediately after install, with no credential to manage, and who would rather see "23 requests observed on this machine since Aug 6" than a confidently wrong balance.

## Definition of Done (observable)

- Installing the extension enables a **consent-gated local usage monitor** with no credential. It reports model and request activity observed on the current machine and **labels its coverage explicitly**.
- The panel **never** displays a remaining allowance or an on-demand spend figure derived from local inference. Those fields are absent, not estimated.
- Every displayed figure carries a persistent authority badge (`Official` / `Local` / `Estimated` / `Unavailable`), and a local figure is never styled to resemble an official balance.
- An **Open official Spending** action links to the authoritative dashboard from both the panel and the empty state.
- The hook is installed under a Nexus-Hub ownership marker, is removable by a single command that also deletes local history, and **never rewrites the user's other `hooks.json` entries**.
- No prompt text, response text, source code, file name, shell command, repository URL, raw conversation id, token, or cookie is recorded. Enforced by test over the serialized record, not by comment.
- No hook event name or payload field is relied on unless it was **observed** on a real host in Phase 1 and version-gated.
- `make validate`, `make lint`, `make test` pass; every new `.sh` has a `.ps1` sibling with asserted exit-code parity.

## Non-goals

- Reading browser or Electron cookie stores, `Login Data`, keychains, or process memory. Unchanged from v3.15.12, and the README's no-cookie claim stays literally true.
- Re-probing the private dashboard route, guessing header forms, or scraping authenticated HTML. v3.15.12 closed that as `CURSOR_PRIVATE_DASHBOARD_CONTRACT = unsupported`, and Cursor's terms independently restrict probing and extraction.
- Opening `~/.cursor/ai-tracking/ai-code-tracking.db`. Undocumented schema, outside any allowlisted-key boundary, and its name suggests code attribution rather than billing.
- Inferring which pool a request drew on, or whether it was charged on demand. A model *selection* does not establish either, and with Auto or the router it may not even name the underlying model.
- Estimating remaining balances from observed counts. Absent beats wrong.

## Constitution Check

- **PASS - Local-first**: the observer reads only events Cursor hands it through its own documented hook channel, on this machine, after consent. The optional official adapter calls the user's own Cursor account with a key they paste.
- **PASS - No new dependency or credential broker**: the hook writes JSONL; the extension imports it with the `node:sqlite` already proven available in the extension host (Node 24.15.0 on the reference host). Any pasted key lives only in `ExtensionContext.secrets`.
- **PASS - Cross-platform parity**: any new `.sh` ships a `.ps1` sibling with asserted exit-code parity, per the v3.15.6 rule.
- **PASS - Installer-aware**: hook installation is an extension-runtime action into `~/.cursor/`, not an installer artifact, so it needs no installer copy step. The existing Cursor integration's `hooks_supported` gating and marker discipline are reused rather than duplicated.
- **PASS - Release discipline**: feature branch, integrates through `develop`, reaches `main` only via `/update release`.
- **CONDITIONAL - Honest sourcing**: this plan's entire value rests on never dressing a local observation as a billing fact. It passes only if authority and coverage are structural (in the type, asserted by test), not cosmetic. See Complexity Tracking.

**Prerequisites**: None.
**Stability Gate**: Every event name and field the later phases use appears in a captured, sanitized payload skeleton from this host; anything unobserved is recorded as unavailable rather than assumed.
**Recommended model tier**: frontier
**Recommended effort level**: max
**Rationale**: This is the HO-5 lesson applied before any code. v3.15.12 spent a phase discovering that a plausible-looking data source did not work; this phase spends a fraction of that verifying the source first. It is also the phase most likely to end the plan, which is a feature.

**Recommended model tier**: strong
**Recommended effort level**: high

- [ ] T006 Add the no-leak serialization test for the event record extensions/cursor-usage-monitor/test/observer-record.test.ts

**Prompt**:

Build the record field by field rather than by spread or payload passthrough, exactly as v3.15.12's `toSanitizedRecord` does, and assert by test that the serialized form contains none of a fixture payload's sensitive values and that its key set equals the approved set exactly. #### 2.2 - Install, ownership, and removal

## Phase 3: Authority and Coverage in the Data Model

**Goal**: Make it structurally impossible for a local observation to be presented as an official balance.
**Prerequisites**: Phase 2.
**Stability Gate**: A snapshot carries its authority and coverage; the remaining-allowance and on-demand fields are absent, not zero, on a local snapshot; tests assert a local snapshot cannot populate them.
**Recommended model tier**: frontier
**Recommended effort level**: high
**Rationale**: This is the phase that holds the plan's one conditional Constitution Check. Every other phase is mechanical once this type is right, and a cosmetic-only version of it would let the feature quietly become dishonest under later edits.

### Sub-tasks

#### 3.1 - The typed contract

- [ ] T011 Add authority and coverage to the usage snapshot type extensions/cursor-usage-monitor/src/types.ts
- [ ] T012 Make the unknowable fields unrepresentable on a local snapshot extensions/cursor-usage-monitor/src/types.ts

**Prompt**:
> Add `authority: "cursor-official" | "local-observed" | "estimated"` and a `coverage` describing which machines, which period, and which surfaces (main agent, subagents, tab, cloud agents, CLI). Then do the part that matters: use a discriminated union so a `local-observed` snapshot **cannot carry** `remainingCents` or on-demand spend at the type level. Do not settle for leaving them optional and documenting that they should be null; the compiler should reject the mistake. v3.15.12's `FreshUsageSnapshot` / `StaleUsageSnapshot` split is the precedent for making an illegal state unrepresentable rather than merely discouraged.

#### 3.2 - Provider abstraction

- [ ] T013 Define the provider interface and resolution order extensions/cursor-usage-monitor/src/providers/index.ts
- [ ] T014 Implement the hooks-backed provider extensions/cursor-usage-monitor/src/providers/localObserved.ts

**Prompt**:
> One interface, `{ id, authority, isAvailable(), connect?, refresh(), dispose() }`, with resolution preferring an official personal API when one exists, then an official team adapter when configured, then local hooks, then a dashboard link only. Retain the unused `CursorAccountApiProvider` seam from v3.15.12 for the first of those. The hooks provider reports counts by pool where the observed model id makes the pool determinable, and reports an explicit unresolved bucket where Auto or the router makes it not. Never guess a pool.

#### 3.3 - Tests

- [ ] T015 Assert the honesty invariants extensions/cursor-usage-monitor/test/authority.test.ts

**Prompt**:
> Assert: a local snapshot cannot express a remaining balance or an on-demand figure; an unresolved model lands in the unresolved bucket rather than being assigned a pool; coverage always names its machine scope and period; and no code path converts an observed count into a currency amount. Add a test that fails if a future edit widens the local variant to include the official-only fields, because that is the specific regression this phase exists to prevent.

### Phase 3 Exit Checklist

- [ ] `authority` and `coverage` present on every snapshot
- [ ] Official-only fields unrepresentable on a local snapshot at the type level
- [ ] Unresolved-pool bucket exists and is used rather than a guess
- [ ] A widening edit fails a test
- [ ] Local commit only, no push

## Complexity Tracking

| Violation | Why Needed | Simpler Alternative Rejected Because |
|-----------|------------|-------------------------------------|
| The extension writes into a file the user also owns (`~/.cursor/hooks.json`) | It is the only supported channel Cursor exposes for observing agent activity, and Nexus-Hub already writes there for `git-guardrails`, so the risk is already carried and the discipline already exists | Not installing a hook leaves the monitor with nothing true to show on a personal or Team plan, which is the status quo v3.15.12 proved cannot be improved by any unsupported route. ## Notes for Implementers

- **Phase 1 can end this plan, and that is a success condition.** If no hook event carries a model identifier, the honest outcome is the reduced scope in T004, not a monitor that counts undifferentiated events.
- **Reuse, do not rebuild.** `wireShape.ts` already summarizes payloads without leaking values; `consent.ts` already implements one-time consent with a scope guard; `authProbe.ts` already demonstrates the field-by-field sanitized record with an asserted key set. All three came out of v3.15.12 and all three apply directly.
- **The unresolved bucket is not a defect.** Auto and the router mean some requests cannot be attributed to a pool. Showing that honestly is the point; folding it into a pool to make the numbers look tidier is the failure.
- **Do not let the badge become cosmetic.** Phase 3 makes the type honest; Phase 4 has to make the screen honest. A badge a user does not notice is the same defect with extra steps.
- **`~/.cursor/hooks.json` on the reference host already contains a Nexus-Hub entry** (`git-guardrails.sh`, `beforeShellExecution`). Any registration test must use a fixture containing a foreign entry, because the real-world case is never an empty file.
- **Precedent to honor**: v3.15.12 Phase 4 shipped nothing until its premise was settled, and that turned out to be the right call twice over - once when the documentation conflicted, and once when the endpoint reference's silence would have produced a wrong default. Phase 1 and T021 exist for the same reason.
