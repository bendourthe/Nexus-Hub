# Plan - anti-slop-editing skill adoption

**Project**: Nexus-Hub
**Version**: v3.15.3
**Slug**: adoption-no-ai-slop
**Plan Type**: Feature
**Created**: 2026-07-23
**Seeded from**: docs/v3/v3.15/comparisons/v3.15.3-comparison-no-ai-slop.md
**Goal**: Ship a new `anti-slop-editing` skill that catches 20+ named AI-slop prose patterns and supports a detect-only audit mode, filling a catalog gap that `writing-editing` (generic) and `hallmark-design` (UI-only) do not cover.

## Overview

This plan operationalizes the `no-ai-slop` comparison. The catalog has no prose anti-slop capability: `writing-editing` is a thin generic skill with a single em-dash rule, and `hallmark-design` addresses only the visual "looks AI-generated" failure mode. The comparison recommends a new dedicated skill because the trigger surface is distinct ("is this AI slop?", "make this less AI-sounding") and folding the pattern catalog into `writing-editing` would muddy that skill's Tier-1 description.

Every adoption candidate is `skill-native` (MCP Registry Policy tier 2): pure prose instructions to the agent's own LLM, with zero new code, outbound calls, dependencies, or credentials. The work is therefore small and self-contained: author one SKILL.md carrying the named-pattern catalog and a dual Edit/Detect mode, ship two on-demand reference files (a banned-word list and a self-check rubric), register the skill in the three `data/` registry files by hand, add a reverse-engineering-matrix row, and validate.

Success looks like: a new triggerable skill that, given a draft, returns either an edited draft plus a What-changed section (Edit mode) or a list of named patterns with quoted lines and short fixes (Detect mode), routes cleanly against `writing-editing`, and passes `make validate` (JSON integrity, orphan-bundle audit, unfilled-placeholder lint) with the reverse-engineering provenance recorded in the matrix.

## Phase 1: Author the anti-slop-editing skill and bundle

**Goal**: Produce a conformant `anti-slop-editing` skill with its reference bundle and routing evals, passing every bundle-level check.
**Prerequisites**: None.
**Stability Gate**: `SKILL.md`, `references/slop-wordlist.md`, `references/self-check.md`, and `evals/trigger-cases.json` all exist under `catalog/skills/developer-experience/anti-slop-editing/`; `make validate` (bundle audit + unfilled-placeholder lint) reports no orphan bundle files and no unfilled placeholders for this skill; every reference file is linked from SKILL.md.
**Recommended model**: Strong reasoning tier, high effort (Opus 4.8, high). Rationale: the value is in faithful reproduction of the 20+ named patterns with before/after fixes and in a pushy-but-precise description that routes cleanly against `writing-editing`; both reward strong reasoning. Re-confirmed by /implement against the then-current model set.

### Sub-tasks

#### 1.1 - Author SKILL.md

**Objective**: Write the skill body with the named-pattern catalog, the dual Edit/Detect mode, voice-preservation discipline, Common Rationalizations, and Verification.

**Prompt**:
> Create `catalog/skills/developer-experience/anti-slop-editing/SKILL.md`. This is a new prose skill that removes AI-slop patterns from writing while preserving the writer's voice, and can also detect slop without rewriting. Requirements:
>
> - YAML frontmatter with `name: anti-slop-editing`, a pushy `description` per the AGENTS.md description-style rule (state the action first, then trigger phrases verbatim: "make this less AI-sounding", "does this read as AI", "de-slop this", "remove AI patterns", "audit this draft for slop"; then a SKIP clause fencing off general documentation writing, which belongs to `writing-editing`), `summary_l0` (<=15 words, quoted), and `overview_l1` (<=150 words, quoted). Keep Tier-1 fields tight.
> - Required body sections in order: title + intro; "When to Use This Skill" (include an explicit "When NOT to use" pointing generic writing to `writing-editing`); "Instructions"; "Common Rationalizations" (table, each row citing a concrete failure mode); "Verification" (binary, observable checklist); "Related Skills" (cross-link `[[writing-editing]]`, `[[hallmark-design]]`, `[[technical-writer]]`, `[[strategic-comments]]`).
> - The Instructions must encode a dual mode: Edit (default) makes the minimum effective edit and returns the edited draft plus a "What changed" section; Detect names each pattern found, quotes the line, and gives a short fix, and explicitly refuses to rewrite, score, or guess AI authorship.
> - The Instructions must include the named-pattern catalog with a quoted smell and a concrete before/after fix for each: binary contrasts, throat-clearing openers, faux-insight setups, colon reveals, superficial analysis (trailing -ing clauses), importance puffery, weasel attribution, fake-strong verbs, synonym cycling, negative listing, dramatic fragmentation, robotic rhythm, rhetorical setups, fake-profound kickers, summary-recap endings, formatting slop, and em-dash discipline.
> - Voice-preservation discipline: identify 3-5 voice signals to preserve, make the minimum effective edit, leave strong human sentences alone, keep useful edge and character.
> - Reconcile the em-dash guidance with the project's stronger conventions: adopt "no em-dashes; no clause-joining spaced hyphens" as the ceiling (per the project Communication Style rules and the user preference), NOT the source's "1-2 are fine in longer drafts". State this in the body.
> - Do NOT name any external repository, product, author, or course anywhere in the file (reverse-engineering attribution rule). The provenance is recorded only in the matrix row in Phase 2.
> - Keep the body at or under the 500-line size norm; push the long lists to the reference files in 1.2 and 1.3 and link to them.

#### 1.2 - Author references/slop-wordlist.md

**Objective**: Ship the banned-word and empty-phrase lists as a Tier-3 reference loaded on demand.

**Prompt**:
> Create `catalog/skills/developer-experience/anti-slop-editing/references/slop-wordlist.md`. It holds the banned-words list (delve, foster, leverage, utilize, facilitate, empower, streamline, robust, cutting-edge, and the rest), the often-empty adverbs list (just, literally, honestly, simply, actually, and the rest), and the often-empty phrases list (it's worth noting, at the end of the day, when it comes to, and the rest). Frame each list as guidance the editor applies with judgment (cut when empty, keep when the word carries emphasis, uncertainty, contrast, or the writer's spoken rhythm), NOT as a hard lint, so legitimate voice is not flattened. Reference this file from SKILL.md (for example "see `references/slop-wordlist.md` for the full banned-word and empty-phrase lists") so the orphan-bundle audit passes. Cross-link the project Communication Style rules. Use ASCII punctuation only.

#### 1.3 - Author references/self-check.md and wire the self-check loop

**Objective**: Adopt the self-check eval pattern - the skill grades its own output against a rubric before returning, then fixes and re-checks.

**Prompt**:
> Create `catalog/skills/developer-experience/anti-slop-editing/references/self-check.md` as a pass/fail content-quality rubric covering: does the edit preserve the writer's point and voice; is the cutting proportional to the actual slop; are the named patterns removed; are banned words and empty phrases removed unless quoted as examples; for detect requests, does the response name each pattern with a quoted line and a short fix without rewriting, scoring, or claiming AI authorship. Then edit SKILL.md's Workflow so that after making the edit the skill grades its own output against `references/self-check.md`, fixes any failing check, and re-checks until all pass, all within the single agent (no separate evaluator agent). Note in SKILL.md that this self-check is distinct from the binary Verification section (which checks observable artifacts) and from `evals/trigger-cases.json` (which checks routing). Reference the file from SKILL.md so the orphan-bundle audit passes.

---

#### 1.4 - Author evals/trigger-cases.json

**Objective**: Prove the skill routes correctly against the look-alike `writing-editing` skill.

**Prompt**:
> Create `catalog/skills/developer-experience/anti-slop-editing/evals/trigger-cases.json` following the v3.15.2 schema (keys lowercase: `skill`, `purpose`, `cases`). Include at least three positive cases (real phrasings such as "make this sound less like AI wrote it", "is this AI slop?", "de-slop this paragraph") each asserting it routes to `anti-slop-editing` first, and at least three near-miss negatives drawn from the SKIP clause (for example "write me a README for this library", "improve the structure of this technical doc", "proofread this report for grammar") each asserting it routes to `writing-editing` or `technical-writer`, not here. This directly addresses the comparison's trigger-overlap conflict note. The `evals/` subdir is consumed by `scripts/run_trigger_evals.py` and is exempt from the orphan-bundle audit.
