**Goal**: Close the highest-value gaps the comparison surfaced between Nexus-Hub and the "whole agentic setup" checklist, so the catalog distributes the same end-to-end discipline it already teaches. Every adopted item ships as a registered skill, hook, bundled script, or template that reaches every supported platform through the installer, is `skill-native` by default (the agent's own model does any LLM work; no new outbound call, dependency, or credential), passes `make validate` / `make lint` / `make test`, and is recorded in the CHANGELOG. The persona is AI coding agents consuming the catalog plus downstream Nexus-Hub users.

## Overview

The v3.12.1 comparison of Nexus-Hub against a widely-shared 18-point agentic-coding setup found that Nexus-Hub already implements the large majority of it: of the 19 numbered points, 7 are strong matches, 10 are partial, and 2 are clean gaps. This release adopts all 12 resulting candidates, ordered reverse-engineer-first per the comparison's Step 5.4 / Step 6 sequence: `skill-native` items lead, `re-full` local-artifact builds follow, and the one composition skill (the end-of-shift orchestrator) sequences last because it depends on the others existing.

Two candidates are net-new capabilities with no current home. A cross-commit sweep skill (point 10) reviews a window of recent commits at a higher altitude than per-diff review, catching partial refactors, convention drift, and cross-commit gotchas. A visual-regression discipline (point 15) adds baseline screenshots, a perceptual diff, and an agent visual-review gate on top of the existing screenshot capture in `demo-capture` and `browser-testing-with-devtools`.

The remaining ten are partials where a specific facet is missing: a false-confidence test audit that reads test bodies for tautological assertions and mocked-away subjects (point 14, distinct from the compute-heavy `mutation-testing`); a lint-repair loop that fixes rather than only flags (point 5); a committed-baseline performance-regression gate (point 16); a bundled profiler harness (point 17); a doc-header summary convention with a self-healing instruction (point 2); a first-class run-the-app verb in the base templates (point 3); a mid-task handoff worksheet with git-tag retrieval (point 7); a helper-script authoring skill (point 9); a persona-to-doc ownership binding for the review personas (point 6); and a composed end-of-shift full-validation orchestrator for autonomous runs (point 18).

One point is deliberately reframed rather than adopted as written. Point 5 recommends shelling lint failures out to a specific external model ("Composer 2.5") for auto-repair. Nexus-Hub's MCP Registry Policy rejects generation-as-service and mandates reverse-engineer-first, so the repair capability is kept but made `skill-native`: the agent's own session model performs the repair through a repair-loop skill, and only the deterministic native-formatter `--fix` pass is automated by an opt-in precommit hook. No second vendor, no credential, no outbound call.

The design principle throughout is minimum-new-surface: prefer augmenting an existing skill over minting a new one (point 17 augments `code-optimizer`; points 2, 6, 7 extend existing skills and templates), keep every LLM-driven step on the session's own model, and bundle deterministic helpers as per-skill tier-3 `scripts/` so they auto-distribute through the installer's recursive folder copy without an installer edit. The only installer-adjacent change is the opt-in precommit hook in Phase 2, which touches `catalog/hooks/settings.json` (an ask-first gate, see the Constitution Check).

Success is demonstrated end-to-end: the seven new skills are registered in all three catalog metadata files and pass `make validate`; the two bundled script sets run and diff correctly on fixtures; the opt-in autofix hook has a passing pytest and is registered in `settings.json`; the five base templates stay parity-clean under `check_base_template_parity.py`; the end-of-shift orchestrator composes the earlier phases' outputs into one green validation pass; and `make validate`, `make lint`, and `make test` are green with a throwaway dry-run install confirming every new artifact lands at its platform target.

## Phase 1: Skill-native quick wins - false-confidence test audit + commit sweep

**Goal**: Ship the two lowest-effort, highest-leverage `skill-native` items first: a skill that audits existing tests for false confidence, and a skill that sweeps a window of recent commits for higher-altitude problems. Neither ships a local artifact; both are pure catalog skills.
**Prerequisites**: None. These are independent and seed the safety net the later phases lean on.
**Stability Gate**: `catalog/skills/tests-generation/false-confidence-test-audit/SKILL.md` and `catalog/skills/workflow/commit-sweep/SKILL.md` exist with all required sections (When to Use with a "When NOT to use", Instructions, Common Rationalizations, Verification with binary items, Related Skills), a pushy `description` with a SKIP clause, and quoted `summary_l0` / `overview_l1`; both are registered in `data/SKILL_INDEX.md`, `data/skills.json`, and `data/marketplace.json`; `make validate` is green.
**Recommended model**: Strong reasoning tier (Opus-class), medium-high effort - a weak audit skill gives false assurance, and the sweep skill's altitude is easy to get wrong.

### Sub-tasks

#### 1.1 - Author the false-confidence test audit skill

**Objective**: A periodic audit skill that finds tests which pass regardless of the behavior they claim to cover.

**Prompt**:
> Create `catalog/skills/tests-generation/false-confidence-test-audit/SKILL.md`. It teaches the agent to audit an existing test suite for FALSE-CONFIDENCE tests: assertions that are tautological (assert true, assert a literal equals itself), tests that assert on a mock instead of the subject under test, tests where the subject is fully mocked away, tests with no assertion, tests that catch-and-pass on any exception, and snapshot tests rubber-stamped without review. Instructions: (1) enumerate the suite and, per test, identify the subject under test and the behavior claimed by its name; (2) read the assertions and classify each test as REAL, WEAK, or FALSE-CONFIDENCE with the specific reason; (3) for FALSE-CONFIDENCE tests, propose the corrected assertion or a real subject invocation, and optionally verify by mutating the subject and confirming the test now fails; (4) produce a short report and, when asked, apply fixes. Contrast it explicitly with `mutation-testing` (that skill DETECTS weak tests by mutation and is compute-heavy; this skill is a lighter, faster read-the-assertions audit run periodically). Write a pushy `description` listing triggers ("audit my tests", "are these tests actually testing anything", "false confidence", "tautological tests", "tests pass but code is broken") and a SKIP clause (SKIP: generating new tests - use `unit-tests` / `test-cases`; running a full mutation pass - use `mutation-testing`). Include Common Rationalizations (each citing a concrete failure mode), a binary Verification checklist, and a Related Skills block cross-linking `[[mutation-testing]]`, `[[testing-review]]`, `[[flaky-test-detector]]`. Keep the body under 500 lines. ASCII-only, style-guide compliant.

#### 1.2 - Author the commit-sweep skill

**Objective**: A higher-altitude periodic sweep across a window of recent commits.

**Prompt**:
> Create `catalog/skills/workflow/commit-sweep/SKILL.md`. It teaches the agent to sweep the last N commits (default 10, configurable) for problems that per-commit review misses: partial or abandoned refactors spread across commits, convention drift, TODO/FIXME debt introduced and not resolved, security-relevant deltas, dependency changes without lockfile or doc updates, and cross-cutting inconsistencies. Instructions: (1) read the window via `git log --stat` and `git diff <base>..<head>` (read-only; never mutate history); (2) cluster the changes by subsystem/file-area; (3) evaluate each cluster at the altitude of "what emerged across these commits that no single diff review would flag"; (4) emit a severity-tagged findings list with commit references, and offer to open follow-ups (cross-link `[[tasks-to-issues]]`). Distinguish it from per-diff `/review diff`, from `regression-root-cause-analyzer` (which explains one regression), and from `git-bisect-assistant` (which locates one bad commit). Pushy `description` with triggers ("sweep recent commits", "review the last N commits", "cross-commit review", "what did we miss across these commits", "periodic commit audit") and a SKIP clause (SKIP: reviewing a single diff - use `/review diff`; finding which commit broke something - use `git-bisect-assistant`). Include Common Rationalizations, a binary Verification checklist, and Related Skills cross-linking `[[regression-root-cause-analyzer]]`, `[[git-bisect-assistant]]`, `[[multi-agent-code-review]]`, `[[tasks-to-issues]]`. Under 500 lines, ASCII-only.

## Phase 2: Skill-native lint-repair loop + deterministic autofix hook

**Goal**: Adopt point 5's "repair, not just flag" idea in a policy-compliant form: a repair-loop skill that runs on the session's own model (never an external vendor), plus an opt-in precommit hook that runs available formatters' native `--fix` deterministically.
**Prerequisites**: None (independent of Phase 1).
**Stability Gate**: `catalog/skills/code-cleanup/lint-repair-loop/SKILL.md` exists and passes registration + `make validate`; `catalog/hooks/lint-autofix.sh` and `catalog/hooks/lint-autofix.ps1` exist, are fail-open (exit 0 on any internal failure), never edit unstaged files, and are registered in `catalog/hooks/settings.json` behind an opt-out env var; a pytest in `catalog/hooks/tests/test_lint_autofix.py` passes under `make test`; the two hook scripts are behavior-equivalent across OSes.
**Recommended model**: Strong tier (Opus-class), high effort - a repair hook that edits files has a larger blast radius than the advisory hooks, and the `.sh`/`.ps1` pair must stay in lockstep.

### Sub-tasks

#### 2.1 - Author the lint-repair-loop skill (session-model repair, policy-compliant)

**Objective**: A reusable discipline for repairing lint/type failures with the agent's own model.

**Prompt**:
> Create `catalog/skills/code-cleanup/lint-repair-loop/SKILL.md`. It teaches the agent a bounded repair loop: (1) run the project's linters/formatters/type-checkers; (2) apply their native `--fix`/`--write` autofix first (deterministic, cheapest); (3) re-run; (4) for residual failures the autofixers cannot handle, the agent reads each failure and edits the code to satisfy it - using its OWN session model, never an external service; (5) re-run until clean or a max-iteration cap is hit, then stop and surface the remaining failures rather than looping forever; (6) leave a reviewable diff and never force-push or bypass hooks. State explicitly, citing the AGENTS.md MCP Registry Policy (hard-no on generation-as-service; reverse-engineer-first), that this skill does NOT shell out to any external repair model - the reframe of the source's "Composer 2.5" recommendation into a `skill-native` loop. Pushy `description` with triggers ("fix the lint errors", "clean up the linter output", "repair type errors", "make lint pass", "auto-fix and repair") and a SKIP clause (SKIP: designing the lint config itself; large refactors - use `refactoring-expert`). Include Common Rationalizations (e.g. "just suppress the warning" -> rebuttal), a binary Verification checklist (lint command exits 0; diff exists; no hook bypass), and Related Skills cross-linking `[[pre-commit-checklist]]`, `[[code-simplification]]`, `[[refactoring-expert]]`. Register it (SKILL_INDEX, skills.json, marketplace.json `code-cleanup` count + total). Run `make validate`.

#### 2.2 - Author the opt-in deterministic autofix precommit hook (.sh + .ps1)

**Objective**: Automate the cheap, deterministic half (native formatter autofix) at precommit, fail-open and opt-out-able.

**Prompt**:
> Create `catalog/hooks/lint-autofix.sh` (`#!/usr/bin/env bash`, `set -euo pipefail`) and its behavior-equivalent sibling `catalog/hooks/lint-autofix.ps1`. On a `git commit` (wired as a `PreToolUse` matcher on `Bash` gating on `tool_input.command` containing `git commit`, following the workflow-phase-automation recipe in the settings reference), the hook detects which formatters are available (ruff, prettier/eslint --fix, gofmt, shfmt) and runs their native autofix on the STAGED files only, then re-stages the fixed files. It MUST be fail-open (exit 0 on any missing tool or internal error - never block a commit), MUST NOT touch unstaged changes, and MUST be a no-op when no supported formatter is present. Respect a per-session opt-out: skip entirely when `NEXUS_DISABLED_HOOKS` contains `lint-autofix` or `NEXUS_HOOK_PROFILE=minimal`, matching the `workflow-phase-notice` precedent. Write informational messages to stderr, keep stdout clean. Follow `catalog/rules/bash/{code-style,security}.md`. Do NOT invoke any LLM from the hook (the LLM-repair half is the Phase 2.1 skill, run by the agent).
